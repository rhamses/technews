Cloudflare Agents brings all of your deployed agent sessions into a single experience, surfacing key information and insights into how your agents perform at scale.</p><h2>First stop: agent tracing</h2><p>We are launching <a href=\"http://developers.cloudflare.com/agents/runtime/operations/observability/tracing/\" target=\"_blank\"><strong><u>agent tracing</u></strong></a> for more direct visibility and insight into agent behavior. With agent-aware traces, you can now understand exactly what your agent is doing and what it costs: every model call, tool execution, and token is measured and presented here. Agent tracing launches today with support for OpenTelemetry-compatible agent harnesses including <a href=\"https://developers.cloudflare.com/agents/harnesses/think/\" target=\"_blank\"><u>Think</u></a>, <a href=\"https://flueframework.com/docs/ecosystem/deploy/cloudflare/\" target=\"_blank\"><u>Flue</u></a>, and <a href=\"https://ai-sdk.dev/\" target=\"_blank\"><u>AI SDK</u></a>, and more.</p><p>Agent traces are just the beginning. Once you have observability into your agent’s thought process and real-world behavior, you can start to analyze this data and make real improvements. Plug this data into your <a href=\"http://blog.cloudflare.com/agent-development-lifecycle\" target=\"_blank\"><u>agent development lifecycle</u></a>, and you suddenly have autonomous, self-improving agents. This is the vision for Cloudflare Agents: one place to deploy, observe, and continuously improve every agent you run.</p><h2>Making agents observable</h2><p>An agent can return HTTP 200 and still fail. It may choose the wrong tool, pass stale context to a subagent, or spend tokens in a retry loop. Traditional application telemetry might show the API request or database query, but not the agent behavior that caused it.</p><p>Agent-level telemetry should answer questions such as:</p><ul><li>Where did the time go: the model, the tool, or the infrastructure?</li><li>Did the turn pause for approval?</li><li>Which model did the agent call, and how many tokens did the turn use?</li><li>Did the agent choose the right tool?</li><li>When the tool called an external API, did it receive a successful response or time out?</li><li>Which subagent performed the work, and how did that work affect the final response?</li></ul><p><a href=\"https://developers.cloudflare.com/workers/observability/traces/\" target=\"_blank\"><u>Workers tracing</u></a> already covers the infrastructure layer, including fetch calls, KV reads, and D1 queries, but until now, traces for agents running on Workers contained those infrastructure spans without the agent operations surrounding them. Agent tracing closes that gap, adding spans for agent invocations, model calls, tool execution, approval events, and supported subagent calls alongside the Workers data already captured. You also get context such as the model and token usage attached as metadata.&#160;</p><p>Starting today, agents built with <a href=\"https://developers.cloudflare.com/agents/harnesses/think/\" target=\"_blank\"><u>Think</u></a>, <a href=\"https://flueframework.com/docs/ecosystem/deploy/cloudflare/\" target=\"_blank\"><u>Flue</u></a>, and <a href=\"https://ai-sdk.dev/\" target=\"_blank\"><u>AI SDK</u></a> will send agent traces to Cloudflare, letting you visualize them in the dashboard or export them to a supported <a href=\"https://developers.cloudflare.com/workers/observability/exporting-opentelemetry-data/\" target=\"_blank\"><u>OpenTelemetry-compatible destination.</u></a></p><h2>All your agents in one This means traces aren’t just something you inspect when things break, but also a feedback loop for improving your agent’s quality, performance, and cost.</p><h2>Pricing</h2><p>Agent traces are built on Workers tracing, so pricing is straightforward.
