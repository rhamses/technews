contentHtml: "<p><a href=\"https://aws.amazon.com/glue/\" target=\"_blank\" rel=\"noopener\">AWS Glue</a> <a href=\"https://docs.aws.amazon.com/lake-formation/latest/dg/working-with-views.html\" target=\"_blank\" rel=\"noopener\">Data Catalog view</a> is a multi-dialect view that supports querying from multiple SQL query engines, such as <a href=\"https://aws.amazon.com/athena/\" target=\"_blank\" rel=\"noopener\">Amazon Athena</a>, <a href=\"https://aws.amazon.com/redshift/\" target=\"_blank\" rel=\"noopener\">Amazon Redshift</a> Spectrum, Apache Spark in <a href=\"https://aws.amazon.com/emr/\" target=\"_blank\" rel=\"noopener\">Amazon EMR</a> and AWS Glue. You can create a Data Catalog view in one account, using an <a href=\"https://aws.amazon.com/iam/\" target=\"_blank\" rel=\"noopener\">AWS Identity and Access Management</a> (IAM) definer role in the same or different account and use <a href=\"https://aws.amazon.com/lake-formation/\" target=\"_blank\" rel=\"noopener\">AWS Lake Formation</a> to share the view across multiple accounts.&nbsp;The <a href=\"https://docs.aws.amazon.com/lake-formation/latest/dg/views-prereqs.html\" target=\"_blank\" rel=\"noopener\">definer role</a> has the required full <code>SELECT</code> on the base tables to create the view and share it with other users for querying. The Data Catalog assumes the definer role and manages access of the base tables when the view is queried, thus allowing to share a subset of data without sharing the underlying base tables.</p> \n<p>AWS Glue now adds AWS SDK support for creating and updating the <code>ATHENA</code> dialect of Glue views. With this addition, you can now create <code>ATHENA</code> and <code>SPARK</code> dialects of Glue views simultaneously, using a cross account IAM definer role.&nbsp;This feature enhances the automation to create and update Glue views, like that of Data Catalog tables. In our earlier blog <a href=\"https://aws.amazon.com/blogs/big-data/create-aws-glue-data-catalog-views-using-cross-account-definer-roles/\" target=\"_blank\" rel=\"noopener\"><em>Create AWS Glue Data Catalog views using cross-account definer roles</em></a>, we had introduced IAM definer roles in a cross-account use case to create Data Catalog views with <code>SPARK</code> dialects using the APIs – <code>CreateTable()</code> and <code>UpdateTable()</code> – while creating and adding <code>ATHENA</code> dialects using Athena query editor. As a continuation to it, this post shows you how to use the Catalog objects API <code>CreateTable()</code> to programmatically create <code>ATHENA</code> and <code>SPARK</code> dialects using cross-account IAM definer roles, and how to add the <code>ATHENA</code> dialect programmatically for the views that were created earlier with only <code>SPARK</code> dialect.</p> \n<p>Cross account definer roles enable enterprise data mesh architectures where multiple accounts are interconnected in a central governance and multiple producers and consumers. The central governance account hosts the database, tables and permissions, while the producer accounts maintain CI/CD pipelines to create and manage those data assets. Having the definer role in producer accounts allows those CI/CD pipelines to be fully managed by IAM roles in the individual accounts.</p> \n<h3 id=\"key-points-on-creating-multi-dialect-views-using-cross-account-definer-roles\">Key points on creating multi-dialect views using cross-account definer roles</h3> \n<ul> \n <li><code>ATHENA</code> dialects are validated and asynchronously created. Hence, a cross-account Glue connection is required for validation for every producer account-central governance account pair. This is a one-time setup.</li> \n <li><code>SPARK</code> dialects are not validated. Hence <code>SPARK</code> dialect’s create syntax requires SubObjects list of the base tables and StorageDescriptor fields for the columns of the view.</li> \n <li>Though queries on cross account views can be run using database resource link names, the view definition SQL query for creating the view requires the original database and base table names from the central governance account.</li> \n <li>If a view has <code>SPARK</code> and <code>ATHENA</code> dialects available, we recommend updating both the dialects of the view simultaneously using <code>update_table()</code> API/SDK, for any changes in the SQL definition of the view or the base table. This will keep both the dialects queryable.</li> \n <li>Creating and updating both <code>SPARK</code> and <code>ATHENA</code> dialects using cross account definer role is supported using <a href=\"https://aws.amazon.com/cloudformation/\" target=\"_blank\" rel=\"noopener\">AWS CloudFormation</a>.</li> \n <li>The Data Catalog view that can be created using cross account IAM definer roles are available in <code>SPARK</code> and <code>ATHENA</code> dialects and currently not supported for Redshift Spectrum dialect.</li> \n</ul> \n<h3 id=\"prerequisites\">Prerequisites</h3> \n<p>We use the same setup used in <a href=\"https://aws.amazon.com/blogs/big-data/create-aws-glue-data-catalog-views-using-cross-account-definer-roles/\" target=\"_blank\" rel=\"noopener\"><em>Create AWS Glue Data Catalog views using cross-account definer roles</em></a> for the sample database, tables, definer role, resource link, IAM and Lake Formation permissions on those resources and principals between the two AWS accounts.
