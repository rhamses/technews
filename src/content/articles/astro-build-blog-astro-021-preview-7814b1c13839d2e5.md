At a high-level, it includes:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://astro.build/blog/astro-021-preview/#hello-vite\">A new build engine, powered by Vite</a></li>\n<li><a target=\"_blank\" href=\"https://astro.build/blog/astro-021-preview/#hello-wasm\">A new WASM compiler, written in Go</a></li>\n<li><a target=\"_blank\" href=\"https://astro.build/blog/astro-021-preview/#components-in-markdown\">Brand new features, like Components-in-Markdown</a></li>\n<li><a target=\"_blank\" href=\"https://astro.build/blog/astro-021-preview/#hmr-meet-html\">A new system for HTML live-updating via HMR</a></li>\n</ul>\n<p>You can try out our latest release today <a target=\"_blank\" href=\"https://gitpod.io/#snapshot/5e7cf2f1-8108-4fa5-99d3-ed8de70d8c23\">in the browser</a> or by running <code>npm install astro@next--compiler</code> in a new project directory on your machine.</p>\n<p>Astro is quickly becoming the production-ready framework for building faster, content-focused websites. To celebrate this milestone, here are some highlights and details on what you can expect in Astro v0.21.0 and beyond.</p>\n<h2 id=\"hello-vite\">Hello, Vite!</h2>\n<p>Astro 0.21 is getting an internal build engine upgrade, replacing Snowpack with <a target=\"_blank\" href=\"https://vitejs.dev/\">Vite</a> going forward.</p>\n<p>We ran some early experiments with Vite and came away extremely impressed. Vite is well-maintained, well-documented, a bit faster, has great error messages, and has been building clear community buy-in across multiple frameworks. SSR handling can be a bit flakey, but the Vite team is aware of this and actively working on it.</p>\n<p>So now, when Evan You tweets about <a target=\"_blank\" href=\"https://twitter.com/youyuxi/status/1440718351802646550\">some great performance optimization</a> that they’re making in Vite you can be certain that the same speed is coming to Astro as well.</p>\n<p>The reverse is also true: we can now contribute fixes and improvements back to the larger Vite community. Now, when we fix an SSR bug in Astro (like <a target=\"_blank\" href=\"https://github.com/vitejs/vite/pull/5197\">adding support for ESM-only npm packages</a>) we’re also fixing it for every other Vite user, including <a target=\"_blank\" href=\"https://kit.svelte.dev/docs#routing-endpoints\">SvelteKit</a>.</p>\n<p>There’s one other huge benefit to choosing Vite: Rollup plugins. Starting in v0.21.0, you’ll be able to connect the entire ecosystem of Rollup plugins to Astro. Enable new features like <a target=\"_blank\" href=\"https://github.com/JonasKruckenberg/imagetools/tree/main/packages/vite\">image optimizations</a> and <a target=\"_blank\" href=\"https://github.com/antfu/unplugin-icons\">icon loading</a> with just a few simple plugins. Magic!</p>\n<p>This switch from Snowpack to Vite might come as a surprise to some: Both Drew and myself are maintainers on both projects. This was <a target=\"_blank\" href=\"https://dev.to/fredkschott/5-more-things-i-learned-building-snowpack-to-20-000-stars-5dc9\">a hard decision</a> for us to make. But ultimately, after working with both tools I can confidently say that Vite will be a great choice for Astro’s future.</p>\n<h2 id=\"hello-wasm\">Hello, WASM!</h2>\n<p>Astro 0.21 features another huge low-level improvement: the brand new <a target=\"_blank\" href=\"https://github.com/withastro/astro-compiler-next\">@astrojs/compiler</a>. Astro’s new compiler is written in Go and distributed as WASM. You can run it right in your browser, or on the server in Node.js and Deno.</p>\n<p>The new <a target=\"_blank\" href=\"https://github.com/withastro/astro-compiler-next\">@astrojs/compiler</a> unlocks:</p>\n<ul>\n<li><strong>Flexibility:</strong> Run the compiler anywhere with WASM.</li>\n<li><strong>Speed:</strong> Build sites faster with Go’s compiled-language performance.</li>\n<li><strong>Stability:</strong> Writing our own compiler allowed us to fix some long-standing bugs.</li>\n</ul>\n<p>You can play with the new compiler today right in your browser at <a target=\"_blank\" href=\"https://astro.build/play\">https://astro.build/play</a>. This REPL is just one example of what is now possible when you have a fast, runs-anywhere compiler.</p>\n<p>Shout out to <span><a target=\"_blank\" href=\"https://bsky.app/profile/natemoo.re\" title=\"Follow Nate Moore on Bluesky\"><span>Nate Moore</span></a></span> who did an incredible job with this project.</p>\n<h2 id=\"components-in-markdown\">Components in Markdown</h2>\n<p>Our most requested feature <strong><em>by far</em></strong> has been the ability to use components directly in Markdown. After months of work, we’re excited to announce that this feature is finally coming to Astro.</p>\n<p>Starting in v0.21.0, you can import components inside of your Markdown frontmatter via an optional <code>setup</code> script. Once imported, your components can be used anywhere on the page:</p>\n<div><figure><pre><code><div><p><span>---</span></p></div><div><p><span>title</span><span>: </span><span>\"Astro 0.21 Early Preview\"</span></p></div><div><p><span>setup</span><span>: </span><span>|</span></p></div><div><p><span><span>  </span></span><span>import Logo from '../components/Logo.astro';</span></p></div><div><p><span><span>  </span></span><span>import ReactCounter from '../components/Counter.jsx';</span></p></div><div><p><span>---</span></p></div><div><p><span># Astro now supports components in Markdown!</span></p></div><div><p><span>&lt;</span><span>Logo</span><span> /&gt;</span></p></div><div><p><span>- Back to markdown here.</span></p></div><div><p><span>- Supports static Astro components.</span></p></div><div><p><span>- Supports dynamic React/Vue/Svelte components!</span></p></div><div><p><span>&lt;</span><span>ReactCounter</span><span> </span><span>start</span><span>=</span><span>{0}</span><span> </span><span>client:load</span><span> /&gt;</span></p></div></code></pre></figure></div>\n<p>This new <code>setup</code> script was designed for maximum flexibility. We’ll keep improving this API going forward with planned support for default components, default layouts, and markdown component overrides.</p>\n<h2 id=\"hmr-meet-html\">HMR, meet HTML</h2>\n<p>Starting in v0.21.0, Astro will support full HMR for Astro components and pages. Change any <code>.astro</code> file in your codebase, and watch the dev server update the page without a full refresh and without losing any client state.</p>\n<p>Astro has always supported powerful HMR updates for client-side JavaScript components like React, Preact, Svelte, Vue, and Solid.js. But adding this for Astro was a fun challenge because Astro components are just static HTML. Our “Zero JavaScript” approach meant that there was no “Astro runtime” to hook into for updates. We had to get creative.</p>\n<p>Now, Astro’s dev server sends HTML updates to the browser and then runs a small script to diff those updates against the current page. This creates a more granular, component-level HMR update that won’t impact the rest of the page.</p>\n<h2 id=\"try-it-today\">Try it today</h2>\n<p>If you’ve read this far, we’d love your help trying out the latest release before launch. You can try out our latest release today <a target=\"_blank\" href=\"https://gitpod.io/#snapshot/5e7cf2f1-8108-4fa5-99d3-ed8de70d8c23\">in the browser</a> or by running <code>npm install astro@next--compiler</code> in a new project directory. You can follow our progress and leave feedback in the <code>next</code> PR on GitHub: <a target=\"_blank\" href=\"https://github.com/withastro/astro/pull/1406\">https://github.com/withastro/astro/pull/1406</a></p>\n<p>Leave feedback, report bugs, and get involved with Astro’s development in our <a target=\"_blank\" href=\"https://astro.build/chat/\">Discord server</a>. You can also <a target=\"_blank\" href=\"https://twitter.com/astrodotbuild\">follow along</a> on Twitter.</p>\n</article>"
