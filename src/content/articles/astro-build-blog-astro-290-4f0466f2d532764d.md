You can now safely use redirects in your project. Check out <a target=\"_blank\" href=\"https://docs.astro.build/en/core-concepts/routing/#redirects\">the docs on redirects</a> to learn how to use this built-in feature.</p>\n<p>In your configuration, add a map of old and new paths to redirect from and to:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>'astro/config'</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>redirects</span><span>: {</span></p></div><div><p><span>    </span><span>'/old-page'</span><span>: </span><span>'/new-page'</span></p></div><div><p><span><span>  </span></span><span>}</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<h2 id=\"hoisted-script-optimization\">Hoisted script optimization</h2>\n<p>Astro’s static analysis to determine which <code>&lt;script&gt;</code> tags to bundle together just got a little smarter!</p>\n<p>Astro creates bundles that optimize script usage between pages and place them in the head of the document so that they are downloaded as early as possible. One limitation to Astro’s existing approach has been that you could not dynamically use hoisted scripts. When using libraries that re-exported components, each page received the same, all-inclusive bundle whether or not every script was needed on that page.</p>\n<p>Now, Astro has improved the static analysis to take into account the actual imports used.</p>\n<p>For example, Astro would previously bundle the <code>&lt;script&gt;</code>s from both the <code>&lt;Tab&gt;</code> and <code>&lt;Accordion&gt;</code> components for the following library that re-exports multiple components:</p>\n<p><strong>@matthewp/my-astro-lib</strong></p>\n<div><figure><pre><code><div><p><span>export</span><span> { </span><span>default</span><span> </span><span>as</span><span> </span><span>Tabs</span><span> } </span><span>from</span><span> </span><span>'./Tabs.astro'</span><span>;</span></p></div><div><p><span>export</span><span> { </span><span>default</span><span> </span><span>as</span><span> </span><span>Accordion</span><span> } </span><span>from</span><span> </span><span>'./Accordion.astro'</span><span>;</span></p></div></code></pre></figure></div>\n<p>Now, when an Astro page only uses a single component, Astro will send only the necessary script to the page. A page that only imports the <code>&lt;Accordion&gt;</code> component will not receive any <code>&lt;Tab&gt;</code> component’s scripts:</p>\n<div><figure><pre><code><div><p><span>---</span></p></div><div><p><span>import</span><span> { </span><span>Accordion</span><span> } </span><span>from</span><span> </span><span>'@matthewp/my-astro-lib'</span><span>;</span></p></div><div><p><span>---</span></p></div></code></pre></figure></div>\n<p>You should now see more efficient performance with Astro supporting this common library re-export pattern.</p>\n<p>Thanks to <a target=\"_blank\" href=\"https://ottomated.net/\">Ottomated</a>, a community contributor for working on this new feature.</p>\n<h2 id=\"more\">More</h2>\n<p>Additional bug fixes and integration features are included in this release.
