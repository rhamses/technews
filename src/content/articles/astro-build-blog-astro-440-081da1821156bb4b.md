Much like the accessibility audits currently available, performance audits will help you identify and fix performance issues in your Astro site. For example, the dev toolbar will now warn you when a lazy-loaded image is above the fold, recommending instead that you use eager loading for better performance.</p>\n<img src=\"https://astro.build/_image?href=%2F_astro%2Fperf-audit.YzxhGteG.webp&w=1536&h=854&f=webp\" srcset=\"https://astro.build/_image?href=%2F_astro%2Fperf-audit.YzxhGteG.webp&w=768&h=427&f=webp 768w, https://astro.build/_image?href=%2F_astro%2Fperf-audit.YzxhGteG.webp&w=1054&h=586&f=webp 1054w\" alt=\"Shows a tooltip telling the user to use loading='lazy' on an image below the fold.\">\n<h2 id=\"audit-list\">Audit list</h2>\n<p>Starting from Astro 4.4, the dev toolbar’s audit app includes a small UI showing the list of problems that have been detected. This list is a great way to quickly see what issues need to be addressed and to jump to the relevant part of the page to fix them. In the future, we’ll be expanding this UI to show more information about each issue, and to provide more guidance on how to fix them.</p>\n<h2 id=\"improved-streaming-performance\">Improved streaming performance</h2>\n<p>This release includes performance improvements for streaming. We discovered recently that <code>ReadableStream</code>s were slower than expected on Node.js, and migrated Astro to use <code>AsyncIterable</code> instead when running on Node.js. Notably, this change reduced the build time of Starlight websites with large sidebars by up to 47% in extreme cases. For more technical details, check out the <a target=\"_blank\" href=\"https://github.com/withastro/astro/pull/9614\">pull request</a> for this change.</p>\n<p>No changes are required to take advantage of these improvements, which benefit both static builds and runtime performance. You can have faster build times and improved runtime performance, as a treat.</p>\n<h2 id=\"automatically-infer-dimensions-of-remote-images\">Automatically infer dimensions of remote images</h2>\n<p>Thanks to <a target=\"_blank\" href=\"https://github.com/OliverSpeir\">Oliver Speir</a>, Astro 4.4 can now infer the dimensions of remote images. The new <code>inferSize</code> attribute can be used as a replacement for the previously required <code>width</code> and <code>height</code> attributes on remote images. This is especially useful when working with images from a CMS or other external sources where the dimensions of the image are not known at build time.</p>\n<p>To enable this feature, set the <code>inferSize</code> prop to <code>true</code> on the <code>Image</code> or <code>Picture</code> components:</p>\n<div><figure><pre><code><div><p><span>---</span></p></div><div><p><span>import</span><span> { </span><span>Image</span><span>, </span><span>Picture</span><span> } </span><span>from</span><span> </span><span>\"astro:assets\"</span><span>;</span></p></div><div><p><span>---</span></p></div><div><p><span>&lt;</span><span>Image</span><span> </span><span>src</span><span>=</span><span>\"https://example.com/image.jpg\"</span><span> </span><span>alt</span><span>=</span><span>\"A cool image\"</span><span> </span><span>inferSize</span><span> /&gt;</span></p></div><div><p><span>&lt;</span><span>Picture</span><span> </span><span>src</span><span>=</span><span>\"https://example.com/image.jpg\"</span><span> </span><span>alt</span><span>=</span><span>\"A cool image\"</span><span> </span><span>inferSize</span><span> /&gt;</span></p></div></code></pre></figure></div>\n<p>or as a parameter to <code>getImage()</code>:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>getImage</span><span> } </span><span>from</span><span> </span><span>\"astro:assets\"</span><span>;</span></p></div><div><p><span>const</span><span> </span><span>processedImage</span><span> = </span><span>await</span><span> </span><span>getImage</span><span>({ </span><span>src</span><span>: </span><span>\"https://example.com/image.jpg\"</span><span>, </span><span>inferSize</span><span>: </span><span>true</span><span> });</span></p></div></code></pre></figure></div>\n<p>Note that this feature comes with a performance cost, notably in SSR, as it requires a partial download of the image to infer its dimensions before the rest of the page can be rendered.
