id=\"performance-improvements\">Performance improvements</h2>\n<p>Thanks to the recent hard work from <a target=\"_blank\" href=\"https://github.com/bluwy\">@bluwy</a> both across the JavaScript ecosystem and in Astro itself, Astro is faster than ever! This release includes a number of performance improvements, cutting build and rendering times across the board.</p>\n<p>In our own benchmarks, we’ve observed build times improve by up to 20% in specific cases. No changes are needed to take advantage of these improvements—just upgrade to Astro 4.8 and enjoy the faster builds!</p>\n<h2 id=\"ability-to-define-multiple-routes-with-the-same-entrypoint\">Ability to define multiple routes with the same entrypoint</h2>\n<p>Astro integration authors discovered that trying to inject multiple routes with the same entrypoint using the <a target=\"_blank\" href=\"https://docs.astro.build/en/reference/integrations-reference/#injectroute-option\"><code>injectRoute</code></a> function would result in an unintended behavior at build time where the last injected route would override the previous ones.</p>\n<p>This issue has existed since the introduction of the <code>injectRoute</code> function, almost two years ago (in Astro 1.0), but thanks to a contribution by <a target=\"_blank\" href=\"https://github.com/goulvenclech\">@goulvenclech</a>, it is now finally fixed in Astro 4.8!</p>\n<p>With our thriving developer community and so many new integrations being built all the time, it’s important to us that Astro is a great platform to build for and we are pleased that this paves the way for even more integrations in the future!</p>\n<h2 id=\"bug-fixes\">Bug Fixes</h2>\n<p>You know it, Astro 4.8 includes more bug fixes and smaller improvements that couldn’t make it into this post!
