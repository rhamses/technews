This lets you serve static pages with personalized content injected later, providing the best of both worlds: fast, CDN-cached static pages, with personalized and dynamic content.</p>\n<p>Server islands build upon the existing islands architecture in Astro. Defining a server island is as simple as defining a client island, but using the <code>server:defer</code> directive instead:</p>\n<div><figure><pre><code><div><p><span>&lt;</span><span>UserButton</span><span> </span><span>server:defer</span><span> /&gt;</span></p></div></code></pre></figure></div>\n<p>This tells Astro to skip rendering this component in the initial response and “defer” its render to later. This lets you cache the static page behind a CDN with some initial placeholder content. When the dynamic HTML has loaded, a small inlined script replaces the server island on the page with the HTML result of the deferred render.</p>\n<p>This feature is notably useful for content-driven websites that mix dynamic and static content on the page. For instance, for an e-commerce site, you could defer the rendering of product recommendations until after the initial page load, providing a faster initial page load time while still delivering personalized content.</p>\n<p>For more details on using this feature, visit the <a target=\"_blank\" href=\"https://5-0-0-beta.docs.astro.build/en/guides/server-islands/\">server islands documentation in the 5.0 beta docs</a>.</p>\n<h2 id=\"merged-static-and-hybrid-output-modes\">Merged static and hybrid output modes</h2>\n<p>In Astro 5, it is now easier than ever to create a website with both static, cached, performant pages and rendered on-demand, dynamic pages.
