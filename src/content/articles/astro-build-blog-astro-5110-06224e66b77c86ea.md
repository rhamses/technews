contentHtml: "<article>\n<p><strong>More experimental Content Security Policy goodies, including serving the CSP using your preferred adapter!</strong></p>\n<p>Astro 5.11 is a small minor that ships with new CSP features and the ability to opt out of HTML streaming when using the Node.js adapter.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://astro.build/blog/astro-5110/#csp-with-adapters\"><strong>CSP with adapters</strong></a></li>\n<li><a target=\"_blank\" href=\"https://astro.build/blog/astro-5110/#disable-html-streaming\"><strong>Disable HTML streaming</strong></a></li>\n</ul>\n<p>To upgrade an existing project, use the automated <code>@astrojs/upgrade</code> CLI tool. Alternatively, upgrade manually by running the upgrade command for your package manager:</p>\n<div><figure><pre><code><div><p><span># Recommended:</span></p></div><div><p><span>npx</span><span> </span><span>@astrojs/upgrade</span></p></div><div><p><span># Manual:</span></p></div><div><p><span>npm</span><span> </span><span>install</span><span> </span><span>astro@latest</span></p></div><div><p><span>pnpm</span><span> </span><span>upgrade</span><span> </span><span>astro</span><span> </span><span>--latest</span></p></div><div><p><span>yarn</span><span> </span><span>upgrade</span><span> </span><span>astro</span><span> </span><span>--latest</span></p></div></code></pre></figure></div>\n<h2 id=\"csp-with-adapters\">CSP with adapters</h2>\n<p>Up until now, static pages could only serve the Content Security Policy (CSP) header via the <code>&lt;meta http-equiv=\"content-security-policy\"&gt;</code> element. This was an inconvenience for some users because some CSP directives such as <code>report-uri</code>, <code>frame-ancestors</code>, and <code>sandbox</code> are not supported in a <code>&lt;meta&gt;</code> element.</p>\n<p>Starting in Astro 5.11.0, the official <code>@astrojs/node</code>, <code>@astro/netlify</code>, and <code>@astro/vercel</code> adapters can specify custom headers for prerendered pages. This means that these adapters can now set the CSP header for static pages, allowing support for all directives, even on prerendered pages.</p>\n<p>This is an experimental feature available by enabling the new <code>experimentalStaticHeaders</code> adapter option:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>\"astro/config\"</span><span>;</span></p></div><div><p><span>import</span><span> </span><span>node</span><span> </span><span>from</span><span> </span><span>\"@astrojs/node\"</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>    </span><span>experimental</span><span>: {</span></p></div><div><p><span>        </span><span>csp</span><span>: </span><span>true</span></p></div><div><p><span><span>    </span></span><span>},</span></p></div><div><p><span>    </span><span>adapter</span><span>: </span><span>node</span><span>({</span></p></div><div><p><span>        </span><span>mode</span><span>: </span><span>\"standalone\"</span><span>,</span></p></div><div><p><span>        </span><span>experimentalStaticHeaders</span><span>: </span><span>true</span></p></div><div><p><span><span>    </span></span><span>})</span></p></div><div><p><span>})</span></p></div></code></pre></figure></div>\n<p>You can start using this feature today on Netlify, Vercel, and Node.js, with Cloudflare support coming soon.</p>\n<p>We will soon ship support for Cloudflare too, which will use the <a target=\"_blank\" href=\"https://developers.cloudflare.com/pages/configuration/headers/\"><code>_headers</code> file</a>.</p>\n<p>Under the hood, the adapters leverage a new Adapter API feature called <a target=\"_blank\" href=\"https://docs.astro.build/en/reference/adapter-reference/#experimentalstaticheaders\"><code>experimentalStaticHeaders</code></a>. If you’re an adapter developer, you can now provide full CSP capabilities to your users.</p>\n<h2 id=\"disable-html-streaming\">Disable HTML streaming</h2>\n<p>The <code>@astrojs/node</code> adapter can now be configured to disable <a target=\"_blank\" href=\"https://docs.astro.build/en/guides/on-demand-rendering/#html-streaming\">HTML streaming</a> for on-demand pages with the new <code>experimentalDisableStreaming</code> option.</p>\n<p>HTML streaming helps with performance and generally provides a better visitor experience. In most cases, disabling streaming is not recommended.</p>\n<p>However, when you need to disable HTML streaming (e.g. your host only supports non-streamed HTML caching at the CDN level), you can now opt out of the default behavior:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>'astro/config'</span><span>;</span></p></div><div><p><span>import</span><span> </span><span>node</span><span> </span><span>from</span><span> </span><span>'@astrojs/node'</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>adapter</span><span>: </span><span>node</span><span>({</span></p></div><div><p><span>    </span><span>mode</span><span>: </span><span>'standalone'</span><span>,</span></p></div><div><p><span>    </span><span>experimentalDisableStreaming</span><span>: </span><span>true</span></p></div><div><p><span><span>  </span></span><span>})</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<h2 id=\"bug-fixes\">Bug fixes</h2>\n<p>As always, we’ve been working hard on fixing issues since the <a target=\"_blank\" href=\"https://astro.build/blog/astro-5100\">5.10 release</a>.
