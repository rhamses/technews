experience</h2>\n<p>The <a target=\"_blank\" href=\"https://docs.astro.build/en/guides/integrations-guide/netlify/\">Netlify adapter</a> is now powered by Netlify’s very own <a target=\"_blank\" href=\"https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/#vite-plugin\">Vite plugin</a> during development, bringing Netlify’s entire platform and primitives to your local dev environment!</p>\n<h3 id=\"the-power-of-netlify-on-localhost\">The power of Netlify on localhost</h3>\n<p>Until now, using Netlify primitives with Astro during local development required running your project through the <a target=\"_blank\" href=\"https://docs.netlify.com/api-and-cli-guides/cli-guides/get-started-with-cli/\">Netlify CLI</a>. The new adapter embeds these capabilities directly into Astro’s dev server instead.</p>\n<p>After upgrading to the latest version of the adapter, running <code>astro dev</code> will provide:</p>\n<ul>\n<li>A local <a target=\"_blank\" href=\"https://docs.netlify.com/build/image-cdn/overview/#local-development\">Netlify Image CDN</a> server. This is used for <a target=\"_blank\" href=\"https://astro.build/blog/astro-5120/#netlify-image-cdn-support\">images</a> by default</li>\n<li>A local <a target=\"_blank\" href=\"https://docs.netlify.com/build/data-and-storage/netlify-blobs/\">Netlify Blobs</a> server. This is used for <a target=\"_blank\" href=\"https://astro.build/blog/astro-5120/#sessions\">sessions</a> by default</li>\n<li><a target=\"_blank\" href=\"https://docs.netlify.com/routing/redirects/\">Redirects, rewrites</a> and <a target=\"_blank\" href=\"https://docs.netlify.com/routing/headers/#app\">headers</a> from your Netlify config</li>\n<li>The <a target=\"_blank\" href=\"https://docs.astro.build/en/guides/integrations-guide/netlify/#accessing-edge-context-from-your-site\">Netlify Edge Context</a> in on-demand pages</li>\n<li><a target=\"_blank\" href=\"https://docs.netlify.com/environment-variables/overview/\">Environment variables</a> populated from your linked Netlify site</li>\n</ul>\n<h3 id=\"configuring-dev-features\">Configuring dev features</h3>\n<p>Along with these features comes a way to configure them. The Netlify adapter now accepts a <code>devFeatures</code> option in its configuration to customize which features are enabled during development. Currently, the features you can configure are:</p>\n<ul>\n<li><code>images</code>: Enables the local Netlify Image CDN for Astro images during dev. Defaults to <code>true</code>.</li>\n<li><code>environmentVariables</code>: Automatically populates your development server with environment variables from your linked Netlify site. Defaults to <code>false</code>.</li>\n</ul>\n<p>You pass this as an option to the Netlify adapter in your Astro configuration file:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>'astro/config'</span></p></div><div><p><span>import</span><span> </span><span>netlify</span><span> </span><span>from</span><span> </span><span>'@astrojs/netlify'</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>adapter</span><span>: </span><span>netlify</span><span>({</span></p></div><div><p><span>    </span><span>devFeatures</span><span>: {</span></p></div><div><p><span>      </span><span>environmentVariables</span><span>: </span><span>true</span><span>,</span></p></div><div><p><span>      </span><span>images</span><span>: </span><span>false</span><span>,</span></p></div><div><p><span><span>    </span></span><span>},</span></p></div><div><p><span><span>  </span></span><span>})</span></p></div><div><p><span>})</span></p></div></code></pre></figure></div>\n<p>Now you can enjoy the rich Netlify flavor in your own home!</p>\n<h2 id=\"experimental-raw-environment-values\">Experimental raw environment values</h2>\n<p>A new experimental configuration option allows you to opt out of Astro’s automatic type coercion for environment variable values in <code>import.meta.env</code>. By default, Astro converts string values like <code>\"true\"</code>, <code>\"false\"</code>, <code>\"1\"</code>, and <code>\"0\"</code> to their respective types, but this can be unexpected since environment variables are generally expected to be strings.</p>\n<p>This aligns Astro’s behavior with <a target=\"_blank\" href=\"https://vite.dev/guide/env-and-mode.html#env-variables\">Vite’s handling of environment variables</a>, and is likely to become the default in a future major release.</p>\n<p>To enable this feature, add the <code>rawEnvValues</code> flag to your Astro configuration:</p>\n<div><figure><pre><code><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>experimental</span><span>: {</span></p></div><div><p><span>    </span><span>rawEnvValues</span><span>: </span><span>true</span><span>,</span></p></div><div><p><span><span>  </span></span><span>},</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>This experimental option only affects the <code>import.meta.env</code> object and doesn’t impact the <code>astro:env</code> module that powers Astro’s <a target=\"_blank\" href=\"https://docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables\">type-safe environment variables</a>.</p>\n<p>Thanks to <a target=\"_blank\" href=\"https://github.com/adamhl8\">Adam Langbert</a> who contributed this feature.</p>\n<h2 id=\"bug-fixes\">Bug fixes</h2>\n<p>As always, we’ve been working hard on fixing issues since the <a target=\"_blank\" href=\"https://astro.build/blog/astro-5110\">5.11 release</a>.
