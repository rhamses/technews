This can cause subtle bugs and unexpected behavior that are hard to track down. With Netlify skew protection, this is now a thing of the past.</p>\n<p>When you deploy to Netlify, Astro automatically includes your deployment ID in all asset requests and API calls. This allows Netlify to detect and handle any version mismatches automatically—no configuration needed. Your site just works, even during rapid deployments or when users are on slow connections that might load assets across deployment boundaries.</p>\n<p>If you’re making custom fetch requests in your application, you can also access the deployment ID directly:</p>\n<div><figure><pre><code><div><p><span>const</span><span> </span><span>deployId</span><span> = Transitions, Server Islands, Prefetch, and Astro Actions, giving you peace of mind across your entire site.</p>\n<h2 id=\"new-adapter-apis-for-customizing-headers-and-assets\">New adapter APIs for customizing headers and assets</h2>\n<p>Behind the scenes, Netlify’s skew protection is powered by a new set of core APIs that allow adapters to customize both headers and asset query parameters across Astro’s systems.</p>\n<p>Astro now exposes a <code>client</code> configuration option in the <code>AstroAdapter</code> interface, allowing adapters to specify:</p>\n<ul>\n<li><strong><code>internalFetchHeaders</code></strong> - Custom headers that should be automatically included in all fetch calls made by Astro’s core systems (Actions, View Transitions, Server Islands, and Prefetch)</li>\n<li><strong><code>assetQueryParams</code></strong> - Query parameters that should be automatically appended to asset URLs</li>\n</ul>\n<p>This gives hosting platforms the hooks they need to implement sophisticated features like skew protection without requiring manual configuration from developers.</p>\n<p>Here’s how an adapter configures these benefits from these new APIs. Previously, Vercel’s skew protection had some limitations and bugs that prevented it from working correctly across all of Astro’s features. With this update, the Vercel adapter now uses the same new APIs to provide reliable skew protection when the <code>VERCEL_SKEW_PROTECTION_ENABLED</code> environment variable is enabled, bringing it to feature parity with Netlify.</p>\n<h2 id=\"granular-font-preload-filtering\">Granular font preload filtering</h2>\n<p>The experimental Fonts API now supports granular control over which font variants get preloaded. Previously, you could only choose to preload all variants of a font or none at all. Now you can specify exactly which weights, styles, and subsets should be preloaded, helping you optimize performance by downloading only what you actually use.</p>\n<p>When using the <code>&lt;Font&gt;</code> component, you can pass a <code>preload</code> array to filter variants:</p>\n<div><figure><pre><code><div><p><span>---</span></p></div><div><p><span>import</span><span> { </span><span>Font</span><span> } </span><span>from</span><span> </span><span>'astro:assets'</span><span>;</span></p></div><div><p><span>---</span></p></div><div><p><span>&lt;</span><span>Font</span></p></div><div><p><span>  </span><span>cssVariable</span><span>=</span><span>\"--font-roboto\"</span></p></div><div><p><span>  </span><span>preload</span><span>=</span><span>{</span><span>[</span></p></div><div><p><span><span>    </span></span><span>{ </span><span>subset</span><span>: </span><span>'latin'</span><span>, </span><span>style</span><span>: </span><span>'normal'</span><span> },</span></p></div><div><p><span><span>    </span></span><span>{ </span><span>weight</span><span>: </span><span>'400'</span><span> },</span></p></div><div><p><span><span>  </span></span><span>]</span><span>}</span></p></div><div><p><span>/&gt;</span></p></div></code></pre></figure></div>\n<p>This example will only preload the Latin subset in normal style and any font files with a weight of <code>400</code>. For variable weight fonts (which support a range like <code>100</code>–<code>900</code>), Astro intelligently matches them against your filter criteria. Requesting weight <code>400</code> will include a variable font that covers the <code>100</code>–<code>900</code> range, since it supports that weight.</p>\n<p>You can filter on any combination of:</p>\n<ul>\n<li><strong><code>weight</code></strong> - Specific font weight (e.g., <code>'400'</code>, <code>'700'</code>)</li>\n<li><strong><code>style</code></strong> - Font style (e.g., <code>'normal'</code>, <code>'italic'</code>)</li>\n<li><strong><code>subset</code></strong> - Font subset (e.g., <code>'latin'</code>, <code>'cyrillic'</code>)</li>\n</ul>\n<p>This gives you fine-grained control over your font loading strategy, reducing unnecessary downloads while maintaining design flexibility.</p>\n<h2 id=\"other-improvements\">Other improvements</h2>\n<ul>\n<li><strong>Copy button for stack traces</strong> – The error overlay now includes a copy button to easily share stack traces with LLMs and AI editors for faster debugging.
