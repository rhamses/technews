This meant every team member had to manually adjust the placement, and settings would be lost when clearing browser data. Individual developers can override the setting through the toolbar UI, if they desire.</p>\n<p>Read our guide on the <a target=\"_blank\" href=\"https://docs.astro.build/en/guides/dev-toolbar/\">Astro Sharp image service now supports configuring the resize kernel algorithm through a new <code>kernel</code> configuration option, giving you fine-grained control over image quality.</p>\n<p>By default, Sharp uses the <code>lanczos3</code> kernel for downsizing. Different kernels can produce noticeably different results depending on the characteristics of your source images: some excel at preserving sharp edges, while others produce smoother results.</p>\n<p>Set your preferred kernel in the image service config:</p>\n<div><figure><pre><code><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>image</span><span>: {</span></p></div><div><p><span>    </span><span>service</span><span>: {</span></p></div><div><p><span>      </span><span>entrypoint</span><span>: </span><span>'astro/assets/services/sharp'</span><span>,</span></p></div><div><p><span>      </span><span>config</span><span>: {</span></p></div><div><p><span>        </span><span>kernel</span><span>: </span><span>'mks2021'</span></p></div><div><p><span><span>      </span></span><span>}</span></p></div><div><p><span><span>    </span></span><span>}</span></p></div><div><p><span><span>  </span></span><span>}</span></p></div><div><p><span>})</span></p></div></code></pre></figure></div>\n<p>Note that this configuration applies to all images on your site and cannot currently be configured on a per-image basis.</p>\n<p>Each kernel offers different trade-offs between sharpness, smoothness, and performance. See <a target=\"_blank\" href=\"https://sharp.pixelplumbing.com/api-resize/#resize\">Sharp’s resize documentation</a> for detailed information on all the available kernel options.</p>\n<p>Thanks to <a target=\"_blank\" href=\"https://github.com/mark-ignacio\">Mark Ignacio</a> who contributed this feature!</p>\n<h2 id=\"retainbody-option-for-glob-loader\"><code>retainBody</code> option for <code>glob()</code> loader</h2>\n<p>The <code>glob()</code> loader now includes a <code>retainBody</code> option to help reduce the size of your data store, particularly beneficial for large content collections.</p>\n<p>By default, Astro stores the raw body of each content file in <code>entry.body</code> in addition to the rendered HTML. For sites with very large collections, this can significantly increase your deployed data store size.</p>\n<p>To prevent this, set the option <code>retainBody</code> to false in your <code>glob()</code> loader:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineCollection</span><span> } </span><span>from</span><span> </span><span>'astro:content'</span><span>;</span></p></div><div><p><span>import</span><span> { </span><span>glob</span><span> } </span><span>from</span><span> </span><span>'astro/loaders'</span><span>;</span></p></div><div><p><span>const</span><span> </span><span>blog</span><span> = </span><span>defineCollection</span><span>({</span></p></div><div><p><span>  </span><span>loader</span><span>: </span><span>glob</span><span>({</span></p></div><div><p><span>    </span><span>pattern</span><span>: </span><span>'**/*.md'</span><span>,</span></p></div><div><p><span>    </span><span>base</span><span>: </span><span>'./src/content/blog'</span><span>,</span></p></div><div><p><span>    </span><span>retainBody</span><span>: </span><span>false</span></p></div><div><p><span><span>  </span></span><span>}),</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>When <code>retainBody</code> is set to <code>false</code>:</p>\n<ul>\n<li><code>entry.body</code> will be <code>undefined</code> instead of containing the raw file contents</li>\n<li>The rendered HTML remains available in <code>entry.rendered.html</code> for Markdown files</li>\n<li>The <code>entry.filePath</code> property still points to the original file</li>\n<li>For MDX collections, this can dramatically reduce data store size</li>\n</ul>\n<p>This is particularly useful for very large sites that have encountered JSON string size limits or want to optimize their deployment size. The option defaults to <code>true</code> to maintain backward compatibility.</p>\n<h2 id=\"bug-fixes\">Bug fixes</h2>\n<p>As always, we’ve been working hard on fixing issues since the <a target=\"_blank\" href=\"https://astro.build/blog/astro-5160/\">5.16 release</a>.
