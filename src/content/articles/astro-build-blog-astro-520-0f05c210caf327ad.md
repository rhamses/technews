This simplifies the Tailwind experience in Astro and is now the recommended way to use Tailwind 4 in Astro.</p>\n<p>Astro 5.2 adds native support for this Vite plugin, and the <code>astro add tailwind</code> command will now add the plugin to your Astro config and create a default CSS file that imports Tailwind styles.</p>\n<p>As a result, the <code>@astrojs/tailwind</code> integration is now deprecated but will continue to work for older versions of Tailwind. To upgrade to Tailwind 4, please uninstall the integration and either use the updated <code>astro add tailwind</code> command or follow the <a target=\"_blank\" href=\"https://tailwindcss.com/docs/installation/framework-guides/astro\">Tailwind documentation for manual installation</a>.</p>\n<p>Thanks to <a target=\"_blank\" href=\"https://github.com/Eveeifyeve\">Eveeifyeve</a> who did the first work on supporting Tailwind 4 while it was in alpha, even though this ended up using a different implementation.</p>\n<h2 id=\"trailing-slash-redirects\">Trailing slash redirects</h2>\n<p>Whether or not a path should have a trailing slash is a common debate in web development. However, everyone agrees that it should be consistent. Duplicate content is bad for SEO and confusing for users.</p>\n<p>Astro has long allowed you to configure whether routes should be matched with or without trailing slash, but previously this has meant returning a “not found” page for the incorrect path or leaving it up to the host to handle conflicts. Astro 5.2 will automatically redirect your on-demand rendered routes to the correct path according to the <code>trailingSlash</code> option in your <code>astro.config.mjs</code>.</p>\n<p>Now, it doesn’t matter whether your visitor navigates to <code>/about/</code>, <code>/about</code>, or even <code>/about///</code>. In production, they’ll always end up on the correct page. For GET requests, the redirect will be a 301 (permanent) redirect, and for all other request methods, it will be a 308 (permanent, and preserve the request method) redirect.</p>\n<p>During development, Astro will display an error page instead of redirecting to help you catch any misconfigurations and bad links.</p>\n<p>To enable trailing slash redirects, set the <code>trailingSlash</code> option in your <code>astro.config.mjs</code>:</p>\n<div><figure><pre><code><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>adapter</span><span>: </span><span>node</span><span>({ </span><span>mode</span><span>: </span><span>'standalone'</span><span> }),</span></p></div><div><p><span>  </span><span>trailingSlash</span><span>: </span><span>'never'</span><span>, </span><span>// or 'always'</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>For more information, see the <a target=\"_blank\" href=\"https://docs.astro.build/en/reference/configuration-reference/#trailingslash\"><code>trailingSlash</code> documentation</a>.</p>\n<h2 id=\"external-redirects\">External redirects</h2>\n<p>Astro now supports defining external redirects to <code>http</code> or <code>https</code> destinations straight from the configuration.</p>\n<p>Just like with internal redirects available since Astro 2.9, with an adapter you can also provide an object as the value. This allows you to specify a <code>status</code> code in addition to the new <code>destination</code>.</p>\n<div><figure><pre><code><div><p><span>import</span><span> {</span><span>defineConfig</span><span>} </span><span>from</span><span> </span><span>\"astro/config\"</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>    </span><span>redirects</span><span>: {</span></p></div><div><p><span>        </span><span>\"/about\"</span><span>: </span><span>\"https://example.com/about\"</span><span>,</span></p></div><div><p><span>        </span><span>\"/news\"</span><span>: {</span></p></div><div><p><span>            </span><span>status</span><span>: </span><span>302</span><span>,</span></p></div><div><p><span>            </span><span>destination</span><span>: </span><span>\"https://example.com/news\"</span></p></div><div><p><span><span>        </span></span><span>}</span></p></div><div><p><span><span>    </span></span><span>}</span></p></div><div><p><span>})</span></p></div></code></pre></figure></div>\n<p>See the updated <a target=\"_blank\" href=\"https://docs.astro.build/en/reference/configuration-reference/#redirects\"><code>redirects</code> configuration docs</a> for more details.</p>\n<h2 id=\"toml-frontmatter-in-markdown\">TOML frontmatter in Markdown</h2>\n<p>Astro’s excellent support for Markdown and MDX has always included the YAML frontmatter, whether in file exports or content collections. With this release, Astro now also supports TOML frontmatter in both. This is useful for adding existing content files with TOML frontmatter to your project from another framework such as Hugo, or you may just prefer TOML over YAML!</p>\n<p>No configuration is required to use TOML frontmatter in your content files: just use <code>+++</code> to delimit the frontmatter and Astro will parse it as TOML.</p>\n<div><figure><pre><code><div><p><span>+++</span></p></div><div><p><span>date = 2025-01-30</span></p></div><div><p><span>title = 'Use TOML frontmatter in Astro!'</span></p></div><div><p><span>[</span><span>params</span><span>]</span></p></div><div><p><span><span>  </span></span><span>author = 'Houston'</span></p></div><div><p><span>+++</span></p></div><div><p><span># Support for TOML frontmatter is here!</span></p></div></code></pre></figure></div>\n<p>Thanks to <a target=\"_blank\" href=\"https://colinbate.com/\">Colin Bate</a> who contributed this feature.</p>\n<h2 id=\"experimental-astroconfig\">Experimental: <code>astro:config</code></h2>\n<p>Astro provides several ways to access your configuration settings from your project files: environment variables, the <code>Astro</code> global object in <code>.astro</code> files, and the <code>context</code> variable in middleware and endpoints.
