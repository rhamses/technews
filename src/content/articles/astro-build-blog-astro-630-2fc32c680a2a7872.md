href=\"https://docs.astro.build/en/reference/experimental-flags/advanced-routing/\">Experimental Advanced Routing docs</a>.</p>\n<h2 id=\"support-redirects-on-external-image-urls\">Support redirects on external image URLs</h2>\n<p>When optimizing remote images, Astro previously failed silently if the image URL returned a redirect. This was a problem for CDNs and image services that use redirects to route requests to the correct edge node or storage bucket. Your images would just disappear from the build without explanation.</p>\n<p>Astro 6.3 now follows up to 10 redirects when fetching remote images. Every URL in the redirect chain is validated against your <code>image.remotePatterns</code> and <code>image.domains</code> configuration, so you stay in control of which hosts Astro is allowed to fetch from. If a redirect leads to a host that isn’t in your allowlist, Astro will throw a helpful error instead of silently ignoring the image.</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>\"astro/config\"</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>image</span><span>: {</span></p></div><div><p><span>    </span><span>domains</span><span>: [</span><span>\"example.com\"</span><span>, </span><span>\"cdn.example.com\"</span><span>]</span></p></div><div><p><span><span>  </span></span><span>}</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<div><figure><pre><code><div><p><span>---</span></p></div><div><p><span>// Redirects to https://cdn.example.com/assets/image.png - However, this runs <code>librsvg</code> under the hood, and SVG files can contain embedded scripts and other active content. Processing untrusted SVGs this way is a potential security risk.</p>\n<p>Starting in Astro 6.3, SVG image processing is disabled by default. If you pass an SVG source to the image optimization pipeline, Astro will now throw a helpful error instead of silently processing it.</p>\n<p>If you trust your SVG sources and want to restore the previous behavior, set the new <code>image.dangerouslyProcessSVG</code> option:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>\"astro/config\"</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>image</span><span>: {</span></p></div><div><p><span>    </span><span>dangerouslyProcessSVG</span><span>: </span><span>true</span><span>,</span></p></div><div><p><span><span>  </span></span><span>}</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>This change does not affect importing SVGs as components. It only applies to rasterizing SVG sources through the image optimization pipeline (e.g. converting an SVG to PNG via <code>&lt;Image /&gt;</code>).</p>\n<h2 id=\"other-improvements\">Other improvements</h2>\n<ul>\n<li><strong>A new <code>consume()</code> method for <code>AstroCookies</code></strong>: this method marks cookies as consumed and returns the <code>Set-Cookie</code> header values. After consumption, any subsequent <code>set()</code> calls will log a warning since the headers have already been sent. This replaces the static <code>AstroCookies.consume(cookies)</code> method, which is now deprecated but kept for backward compatibility with existing adapters.</li>\n</ul>\n<p>For a complete list of
