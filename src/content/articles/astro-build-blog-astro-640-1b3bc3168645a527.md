Alternatively, upgrade manually by running the upgrade command for your package manager:</p>\n<div><figure><pre><code><div><p><span># Recommended:</span></p></div><div><p><span>npx</span><span> </span><span>@astrojs/upgrade</span></p></div><div><p><span># Manual:</span></p></div><div><p><span>npm</span><span> </span><span>install</span><span> </span><span>astro@latest</span></p></div><div><p><span>pnpm</span><span> </span><span>upgrade</span><span> </span><span>astro</span><span> </span><span>--latest</span></p></div><div><p><span>yarn</span><span> </span><span>upgrade</span><span> </span><span>astro</span><span> </span><span>--latest</span></p></div></code></pre></figure></div>\n<h2 id=\"new-markdownprocessor-api\">New <code>markdown.processor</code> API</h2>\n<p>Astro’s Markdown pipeline has always been built around <a target=\"_blank\" href=\"https://unifiedjs.com/\">unified</a> (remark, rehype, and friends). That ecosystem is powerful, having thousands of plugins available, but perhaps it’s not up to your taste. Astro 6.4 adds a new <code>markdown.processor</code> configuration option that lets you swap that pipeline out entirely.</p>\n<p>The default processor is still <code>unified()</code>, so existing projects keep working without any changes. Your remark and rehype plugins continue to behave the same, but they are now configured directly on the processor, instead of in the top-level <code>markdown</code> config:</p>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>'astro/config'</span><span>;</span></p></div><div><p><span>import</span><span> { </span><span>unified</span><span> } </span><span>from</span><span> </span><span>'@astrojs/markdown-remark'</span><span>;</span></p></div><div><p><span>import</span><span> </span><span>remarkToc</span><span> </span><span>from</span><span> </span><span>'remark-toc'</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>markdown</span><span>: {</span></p></div><div><p><span>    </span><span>processor</span><span>: </span><span>unified</span><span>({</span></p></div><div><p><span>      </span><span>remarkPlugins</span><span>: [</span><span>remarkToc</span><span>],</span></p></div><div><p><span><span>    </span></span><span>}),</span></p></div><div><p><span><span>  </span></span><span>},</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>The existing top-level <code>markdown.remarkPlugins</code>, <code>markdown.rehypePlugins</code>, <code>markdown.remarkRehype</code>, <code>markdown.gfm</code>, and <code>markdown.smartypants</code> options still work, but they’re now deprecated in favor of passing them to <code>unified({...})</code>, and will be removed in Astro 8.0.</p>\n<p>For more information, see the updated <a target=\"_blank\" href=\"https://docs.astro.build/en/guides/markdown-content/\">Markdown guide</a>.</p>\n<h2 id=\"faster-markdown-builds-with-sätteri\">Faster Markdown builds with Sätteri</h2>\n<p>A pluggable processor API also means Astro can ship other Markdown processors. Astro 6.4 introduces a new <code>@astrojs/markdown-satteri</code> package, with a new processor based on <a target=\"_blank\" href=\"https://satteri.bruits.org/\">Sätteri</a>, a Markdown and MDX pipeline written in Rust.</p>\n<p>Sätteri is much faster than the default unified-based pipeline, and it implements many Markdown features natively that previously required plugins. In our own testing, switching the Astro and Cloudflare docs site to Sätteri shaved over a minute off their respective build time. To try it out, install the package and set it as your processor:</p>\n<div><figure><pre><code><div><p><span>npm</span><span> </span><span>install</span><span> </span><span>@astrojs/markdown-satteri</span></p></div></code></pre></figure></div>\n<div><figure><pre><code><div><p><span>import</span><span> { </span><span>defineConfig</span><span> } </span><span>from</span><span> </span><span>'astro/config'</span><span>;</span></p></div><div><p><span>import</span><span> { </span><span>satteri</span><span> } </span><span>from</span><span> </span><span>'@astrojs/markdown-satteri'</span><span>;</span></p></div><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>markdown</span><span>: {</span></p></div><div><p><span>    </span><span>processor</span><span>: </span><span>satteri</span><span>({</span></p></div><div><p><span>      </span><span>features</span><span>: { </span><span>directive</span><span>: </span><span>true</span><span> },</span></p></div><div><p><span><span>    </span></span><span>}),</span></p></div><div><p><span><span>  </span></span><span>},</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>Sätteri doesn’t run remark or rehype plugins. If you depend on plugins from the unified ecosystem, you’ll need to either stay on <code>unified()</code> for now or port them to <a target=\"_blank\" href=\"https://satteri.bruits.org/docs/plugins/\">Sätteri MDAST or HAST plugins</a>.</p>\n<p>We hope to make Sätteri the default Markdown processor in a future major version of Astro.
