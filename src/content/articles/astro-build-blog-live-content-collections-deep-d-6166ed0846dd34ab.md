contentHtml: "<article>\n<p><strong>Live content collections represent the next evolution of content in Astro, bringing real-time data capabilities to the familiar content collections API you already know and love.</strong></p>\n<p>Content collections in Astro have been through several stages of evolution. They were first launched as an incredibly easy and powerful way to manage structured content from files on disk. Initially supporting Markdown, MDX and JSON files, they allow you to build blogs, documentation sites, and more with great developer experience and type-safe data.</p>\n<p>With Astro 5.0, content collections were expanded into a full-fledged Content Layer that supported pluggable loaders for all kinds of data sources, including APIs, CMSs, and more.</p>\n<p>In Astro 5.10, content collections take their next step, with experimental support for <strong>live content collections</strong>. With these, you can now fetch content at runtime instead of build time, opening up entirely new possibilities for dynamic, personalized, and real-time content experiences.</p>\n<p>Whether you’re building an e-commerce site with frequently changing inventory, a news site with breaking updates, or a dashboard with live metrics, Astro’s new live content collections provide the flexibility you need while maintaining the type safety and developer experience that makes Astro special.</p>\n<h2 id=\"the-foundations-of-live-content-collections\">The foundations of Live Content Collections</h2>\n<p>Before diving into live content collections, it’s worth understanding the foundation they’re built upon: <a target=\"_blank\" href=\"https://docs.astro.build/en/reference/content-loader-reference/\">loaders</a>. Astro content collections use loaders to manage structured data and content in your projects. Each content collection relies on its loader to define how entries are populated. During <code>astro build</code>, these loaders run to fetch data and populate a local data store. Your pages then query this immutable snapshot using the <code>getCollection()</code> and <code>getEntry()</code> functions.</p>\n<p>Live content collections take this concept one step further: instead of fetching data at build time, they fetch it at request time, giving you access to the freshest possible data. Sometimes you want the speed and reliability of static content, but other times you need the flexibility and dynamism of live data. Just as you can choose between static and on-demand rendered pages in Astro, you can now choose between build-time and live content collections.</p>\n<p>Whichever choice you make, you get the same, familiar API from your existing content collections. If you know how to use <code>getCollection()</code> and <code>getEntry()</code>, you already know most of what you need to use <code>getLiveCollection()</code> and <code>getLiveEntry()</code>.</p>\n<h2 id=\"the-architecture-of-live-collections\">The architecture of live collections</h2>\n<p>Unlike build-time content collections that populate a static data store during the build process, live content collections work fundamentally differently under the hood:</p>\n<p>When a page using live content collections is requested:</p>\n<ol>\n<li>The page calls <code>getLiveCollection()</code> or <code>getLiveEntry()</code> to fetch data.</li>\n<li>Data is fetched from the external source (API, database, etc.).</li>\n<li>Results are processed and validated against your schema.</li>\n<li>Data is returned to your page component.</li>\n</ol>\n<p>This architecture means you’re always working with fresh data, but it also means each request involves network calls to your data sources. This trade-off is perfect for use cases where data freshness is more important than absolute performance. You can mitigate performance concerns with page caching, and live collections help by providing cache hints that you can use to optimize this. As this experimental feature develops, Astro will eventually handle more of this for you. For now, you can use the <code>Cache-Control</code> and other headers to control how long the data is cached in the browser and on CDNs.</p>\n<h2 id=\"setting-up-live-content-collections\">Setting up Live Content Collections</h2>\n<p>Getting started with live content collections requires enabling the experimental flag and creating a live collection configuration:</p>\n<div><figure><pre><code><div><p><span>export</span><span> </span><span>default</span><span> </span><span>defineConfig</span><span>({</span></p></div><div><p><span>  </span><span>experimental</span><span>: {</span></p></div><div><p><span>    </span><span>liveContentCollections</span><span>: </span><span>true</span><span>,</span></p></div><div><p><span><span>  </span></span><span>},</span></p></div><div><p><span>  </span><span>// Live collections require an adapter for on-demand rendering</span></p></div><div><p><span>  </span><span>adapter</span><span>: </span><span>node</span><span>({</span></p></div><div><p><span>    </span><span>mode</span><span>: </span><span>'standalone'</span><span>,</span></p></div><div><p><span><span>  </span></span><span>}),</span></p></div><div><p><span>});</span></p></div></code></pre></figure></div>\n<p>Next, create a <code>src/live.config.ts</code> file to define your live collections, specifying <code>type: 'live'</code> and the collection’s <code>loader</code>.</p>\n<p>In this example I’m using <a target=\"_blank\" href=\"https://github.com/ascorbic/astro-loaders/\">two live loader packages that I created</a>, but you will probably need to <a target=\"_blank\" href=\"https://astro.build/blog/live-content-collections-deep-dive/#building-a-live-content-loader\">create your own loaders</a> for your own live data sources by following our documentation.
