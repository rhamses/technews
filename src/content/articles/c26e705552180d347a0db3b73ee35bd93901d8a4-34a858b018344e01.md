contentHtml: "<p>Customers running multiple <a href=\"https://aws.amazon.com/kinesis/data-streams/\" target=\"_blank\" rel=\"noopener\">Amazon Kinesis Data Streams</a> often struggle to estimate the cost impact of switching between capacity modes. As accounts grow to tens or hundreds of streams, manually reviewing Amazon CloudWatch metrics for each stream and comparing pricing across Provisioned, On-demand Standard, and On-demand Advantage becomes impractical. Teams often stay on their current mode, unsure whether switching would save money or cost more, leaving potential savings unquantified. <a href=\"https://docs.aws.amazon.com/streams/latest/dev/how-do-i-size-a-stream.html#ondemand-advantage-mode\" target=\"_blank\" rel=\"noopener\">On-demand Advantage</a> is an account-level setting that unlocks additional capabilities and a different pricing structure for on-demand streams in an AWS Region. However, without a clear, data-driven comparison, the decision to enable it remains difficult to justify.</p> \n<p>In this post, we show you how to deploy an AI-powered agent built on <a href=\"https://aws.amazon.com/bedrock/\" target=\"_blank\" rel=\"noopener\">Amazon Bedrock</a>. The agent automatically analyzes every Kinesis Data Stream in your account and compares costs across all <a href=\"https://docs.aws.amazon.com/streams/latest/dev/how-do-i-size-a-stream.html\" target=\"_blank\" rel=\"noopener\">three capacity modes</a>. It tells you exactly which streams to move to On-demand and whether your account qualifies for On-demand Advantage pricing, all on a daily or weekly schedule with zero manual intervention. As we showed in <a href=\"https://aws.amazon.com/blogs/big-data/kinesis-on-demand-advantage-saves-60-on-streaming-costs/\" target=\"_blank\" rel=\"noopener\">Kinesis On-demand Advantage saves 60%+ on streaming costs</a>, choosing the right mode can save over 60 percent on streaming costs. This agent automates that analysis for you.</p> \n<h2 id=\"what-is-the-kinesis-mode-optimizer-agent\">What is the Kinesis Mode Optimizer Agent?</h2> \n<p>The <a href=\"https://github.com/aws-samples/sample-kinesis-optimizer-agent\" target=\"_blank\" rel=\"noopener\">Kinesis Mode Optimizer Agent</a> is an open source, serverless solution that uses <a href=\"https://aws.amazon.com/bedrock/agentcore/\" target=\"_blank\" rel=\"noopener\">Amazon Bedrock AgentCore</a>, a platform to build, connect, and optimize agents at scale, with any framework or model. The agent autonomously analyzes your Kinesis Data Streams usage. It collects 7 days of Amazon CloudWatch metrics for every stream in the Region and discovers <a href=\"https://docs.aws.amazon.com/streams/latest/dev/enhanced-consumers.html\" target=\"_blank\" rel=\"noopener\">Enhanced Fan-Out (EFO)</a> consumers. It then computes a three-way cost comparison (On-demand Standard, On-demand Advantage, Provisioned) and generates per-stream recommendations along with an account-level On-demand Advantage assessment.</p> \n<p>The agent strongly prefers on-demand modes for their operational simplicity (automatic scaling, no capacity planning, and no throttling risk).</p> \n<p>Results are stored as both a visual HTML report and machine-readable JSON in Amazon Simple Storage Service (Amazon S3).</p> \n<h2 id=\"architecture\">Architecture</h2> \n<p>The solution uses the following architecture:</p> \n<div style=\"width: 810px\" class=\"wp-caption alignnone\">\n <img src=\"https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2026/08/05/BDB-6094-1.png\" alt=\"Architecture diagram of the Kinesis Mode Optimizer Agent showing Amazon EventBridge, a Scheduler Lambda, Amazon Bedrock AgentCore, a Tool Lambda, and downstream Kinesis Data Streams, CloudWatch, and Amazon S3\" width=\"800\">\n <p class=\"wp-caption-text\"><br>Figure 1: Architecture of the Kinesis Mode Optimizer Agent</p>\n</div> \n<p>The architecture flow includes the following steps:</p> \n<ol type=\"1\"> \n <li><strong>Amazon EventBridge Schedule</strong> triggers the Scheduler Lambda, an AWS Lambda function, on your configured cadence (daily, weekly, or custom cron).</li> \n <li><strong>Scheduler Lambda</strong> invokes the Amazon Bedrock AgentCore harness with the instruction to analyze streams and generate a report.</li> \n <li><strong>Amazon Bedrock AgentCore Gateway</strong>, a capability of Amazon Bedrock AgentCore powered by Claude Sonnet, interprets the request and routes it to the appropriate Model Context Protocol (MCP) tools exposed by the Tool Lambda.</li> \n <li><strong>Tool Lambda</strong> performs the heavy lifting, fanning out to three downstream services: \n  <ol type=\"a\"> \n   <li><strong>Kinesis Data Streams </strong>–&nbsp;Lists streams in the Region, describes each stream (shard count, mode, retention), and discovers Enhanced Fan-Out consumers per stream.</li> \n   <li><strong>CloudWatch</strong> – Pulls 7 days of metrics per stream (IncomingBytes, OutgoingBytes, throttle events) and computes three-way cost comparison.</li> \n   <li><strong>Amazon S3</strong> – Generates per-stream recommendations and an account-level Advantage assessment, then stores the final HTML and JSON reports.</li> \n  </ol> </li> \n <li><strong>Amazon Bedrock AgentCore harness</strong> summarizes the findings and returns them to the caller.</li> \n</ol> \n<p>The entire stack is deployed using AWS Cloud Development Kit (AWS CDK) with a single <code>cdk deploy</code> command.</p> \n<h2 id=\"prerequisites\">Prerequisites</h2> \n<p>Before you begin, verify that you have the following:</p> \n<ul> \n <li><strong>AWS CDK</strong> – <code>npm install -g aws-cdk</code>.</li> \n <li><strong>Python 3.12+</strong>.</li> \n <li><strong>aws-cdk-lib &gt;= 2.251.0</strong> – for AgentCore L2 constructs.</li> \n <li><strong>AWS Command Line Interface (AWS CLI)</strong> configured with credentials that have permissions to deploy the required resources.</li> \n <li><strong>Amazon Bedrock model access</strong> – verify you have access to <a href=\"https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html\" target=\"_blank\" rel=\"noopener\">Claude Sonnet 4.5</a> (or your chosen model) in the target Region. Check in the Amazon Bedrock console under Model access.</li> \n</ul> \n<h2 id=\"walkthrough\">Walkthrough</h2> \n<p>In the following sections, you deploy the Kinesis Data Streams Mode Optimizer Agent and test it against your Kinesis streams.</p> \n<h3 id=\"step-1-clone-the-repository\">Step 1: Clone the repository</h3> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">git clone https://github.com/aws-samples/sample-kinesis-optimizer-agent.git\ncd sample-kinesis-optimizer-agent</code></pre> \n</div> \n<h3 id=\"step-2-install-cdk-dependencies\">Step 2: Install CDK dependencies</h3> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">cd infra\npip install -r requirements.txt</code></pre> \n</div> \n<h3 id=\"step-3-set-your-target-region\">Step 3: Set your target Region</h3> \n<p>The stack deploys to whatever Region is set in <code>AWS_DEFAULT_REGION</code>. Set it before running any CDK commands:</p> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\"># Linux/macOS\nexport AWS_DEFAULT_REGION=us-east-1\n\n# Windows PowerShell\n$env:AWS_DEFAULT_REGION=\"us-east-1\"</code></pre> \n</div> \n<h3 id=\"step-4-bootstrap-cdk-first-time-per-accountregion\">Step 4: Bootstrap CDK (first time per account/Region)</h3> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">cdk bootstrap aws://&lt;ACCOUNT_ID&gt;/&lt;REGION&gt;</code></pre> \n</div> \n<h3 id=\"step-5-deploy\">Step 5: Deploy</h3> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">cdk deploy</code></pre> \n</div> \n<p>Optionally customize the schedule and bucket name:</p> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\"># Weekly instead of daily\ncdk deploy --parameters ReportSchedule=\"rate(7 days)\"\n\n# Custom bucket name\ncdk deploy --parameters ReportBucketName=amzn-s3-demo-bucket</code></pre> \n</div> \n<h3 id=\"step-6-test-the-agent\">Step 6: Test the agent</h3> \n<p>You can test the agent with the AWS CLI:</p> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">aws bedrock-agentcore invoke-harness \\\n    --harness-arn &lt;HARNESS_ARN&gt; \\\n    --runtime-session-id $(uuidgen) \\\n    --messages '[{\"role\":\"user\",\"content\":[{\"text\":\"Generate an optimization report\"}]}]' \\\n    --region us-east-1</code></pre> \n</div> \n<h3 id=\"step-7-view-reports\">Step 7: View reports</h3> \n<p>Reports are stored in Amazon S3 at:</p> \n<div class=\"hide-language\"> \n <pre><code class=\"language-plaintext\">s3:// amzn-s3-demo-bucket/kinesis-optimization-reports/YYYY/MM/DD/HHMMSS-&lt;report-id&gt;.html\ns3:// amzn-s3-demo-bucket/kinesis-optimization-reports/YYYY/MM/DD/HHMMSS-&lt;report-id&gt;.json</code></pre> \n</div> \n<p>The HTML report includes a per-stream action table with priority indicators, detailed cost breakdowns, and the account-level Advantage recommendation.</p> \n<div style=\"width: 810px\" class=\"wp-caption alignnone\">\n <img src=\"https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2026/08/05/BDB-6094-2.png\" alt=\"Sample HTML report showing the per-stream action table with priority indicators and cost breakdowns\" width=\"800\">\n <p class=\"wp-caption-text\"><br>Figure 2: Sample HTML report with the per-stream action table</p>\n</div> \n<div style=\"width: 810px\" class=\"wp-caption alignnone\">\n <img src=\"https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2026/08/05/BDB-6094-3.png\" alt=\"Sample report showing the account-level On-demand Advantage recommendation\" width=\"800\">\n <p class=\"wp-caption-text\"><br>Figure 3: Account-level On-demand Advantage recommendation in the sample report output</p>\n</div> \n<h2 id=\"multi-region-deployment\">Multi-Region deployment</h2> \n<p>The agent is Region-specific. When deployed to a Region, it analyzes only the streams in that Region. To cover multiple Regions, change the environment variable and repeat the deployment:</p> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">export AWS_DEFAULT_REGION=eu-west-1\ncdk bootstrap aws://&lt;ACCOUNT_ID&gt;/eu-west-1\ncdk deploy</code></pre> \n</div> \n<p>Each deployment is independent, with its own agent, Amazon S3 bucket, and schedule.</p> \n<h2 id=\"clean-up\">Clean up</h2> \n<p>To remove the stack from a Region:</p> \n<div class=\"hide-language\"> \n <pre><code class=\"language-bash\">cd infra\ncdk destroy</code></pre> \n</div> \n<p><strong>Note:</strong> The Amazon S3 bucket has a <code>RemovalPolicy.RETAIN</code> setting and isn’t deleted with the stack. Delete it manually if you no longer need the reports.</p> \n<h2 id=\"conclusion\">Conclusion</h2> \n<p>In this post, you deployed an AI-powered agent that autonomously analyzes your Amazon Kinesis Data Streams and recommends the optimal capacity mode for each stream. The agent alleviates the manual effort of reviewing CloudWatch metrics across dozens or hundreds of streams and produces actionable, cost-aware recommendations on a recurring schedule.</p> \n<p>By shifting from manual capacity reviews to autonomous, scheduled optimization, you gain three key benefits. First, you can reduce streaming costs by identifying streams that should switch modes. Second, you alleviate throttling risk by catching under-provisioned streams before they impact performance. Third, you free your team from repetitive operational work. All of this is achievable with a single <code>cdk deploy</code>.</p> \n<p>To get started, clone the <a href=\"https://github.com/aws-samples/sample-kinesis-optimizer-agent\" target=\"_blank\" rel=\"noopener\">sample-kinesis-optimizer-agent repository</a> and deploy it to your account today.</p> \n<hr> \n<h2>About the authors</h2> \n<footer> \n <div class=\"blog-author-box\"> \n  <div class=\"blog-author-image\"> \n   <p><img loading=\"lazy\" class=\"alignleft size-full\" src=\"https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2026/08/05/BDB-6094-4.jpeg\" alt=\"Masudur Rahaman Sayem\" width=\"100\" height=\"100\"></p> \n  </div> \n  <h3 class=\"lb-h4\">Masudur Rahaman Sayem</h3> \n  <p>Masudur is a Streaming Data Architect at AWS with over 25 years of experience in the IT industry.
