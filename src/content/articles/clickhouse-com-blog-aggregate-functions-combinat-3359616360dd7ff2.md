Along with aggregate functions, ClickHouse provides <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/\">aggregate combinators</a>, which are a powerful extension to the querying capabilities and can address a massive number of requirements.</p>\n<p>Combinators allow extending and mixing aggregations to address a wide range of data structures. This capability will enable us to adapt queries instead of tables to answer even the most complex questions.</p>\n<p>In this blog post, we explore Aggregate Combinators and how the can potentially simplify your queries and avoid the need to make structural changes to your data.</p>\n<h2 id=\"how-to-use-combinators\"></h2>\n<p>To use a combinator, we have to do two things. First, choose an aggregate function we want to use; let's say we want a <code>sum()</code> function. Second, pick a combinator needed for our case; let's say we need an <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-if\"><code>If</code></a> combinator. To use this in a query, we add the combinator to the function name:</p>\n<pre><p>\nSELECT sumIf(...)\n</p>\n</pre>\n<p>An even more useful feature is that we can combine any number of combinators in a single function:</p>\n<pre><p>\nSELECT sumArrayIf(...)\n</p>\n</pre>\n<p>Here, we've combined the <code>sum()</code> function with the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-array\"><code>Array</code></a>  and <code>If</code> combinators:</p>\n<p><span><img alt=\"sumArrayIf.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fsum_Array_If_2dbf550274.png&w=2048&q=75\"></span></p>\n<p>This particular example would allow us to conditionally sum the contents of an array column.</p>\n<p>Let's explore some practical cases where combinators can be used.</p>\n<h2 id=\"adding-conditions-to-aggregations\"></h2>\n<p>Sometimes, we need to aggregate data based on specific conditions.\nInstead of using a <code>WHERE</code> clause for this, we can use <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-if\"><code>If</code></a> combinator and specify conditions as a last argument of the combined function:</p>\n<p><span><img alt=\"how sumIf works\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F3_1a8fcdd660.png&w=2048&q=75\"></span></p>\n<p>Suppose we have a table with user payments of the following structure (populated with a <a target=\"_blank\" href=\"https://gist.github.com/gingerwizard/a24d0057367dbd9b7e4e36e26522a30a\">sample data</a>):</p>\n<pre><p>\nCREATE TABLE payments\n(\n    `total_amount` Float,\n    `status` ENUM('declined', 'confirmed'),\n    `create_time` DateTime,\n    `confirm_time` DateTime\n)\nENGINE = MergeTree\nORDER BY (status, create_time)\n</p>\n</pre>\n<p>Let's say we want to get the total amount spent, but only when the payment was confirmed i.e. <code>status=\"confirmed\"</code>:</p>\n<pre><p>\nSELECT sumIf(total_amount, status = 'confirmed') FROM payments\n┌─sumIf(total_amount, equals(status, 'declined'))─┐\n│                               10780.18000793457 │\n└─────────────────────────────────────────────────┘\n</p>\n</pre>\n<p>We can use the same syntax for the condition as for <code>WHERE</code> clauses.\nLet's get the total amount of confirmed payments, but when <code>confirm_time</code> is later than <code>create_time</code> by 1 minute:</p>\n<pre><p>\nSELECT sumIf(total_amount, (status = 'confirmed') AND (confirm_time &gt; (create_time + toIntervalMinute(1)))) AS confirmed_and_checked\nFROM payments\n┌─confirmed_and_checked─┐\n│     11195.98991394043 │\n└───────────────────────┘\n</p>\n</pre>\n<p>The principal advantage of using the conditional <code>If</code>, over a standard <code>WHERE</code> clause, is the ability to compute multiple sums for different clauses. We can also use any available <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/reference/\">aggregate function</a> with combinators, like <code>countIf()</code>, <code>avgIf()</code> or <code>quantileIf()</code> - any. Combing these capabilities we can aggregate on multiple conditions and functions within a single request:</p>\n<pre><p>\nSELECT\n    countIf((status = 'confirmed') AND (confirm_time &gt; (create_time + toIntervalMinute(1)))) AS num_confirmed_checked,\n    sumIf(total_amount, (status = 'confirmed') AND (confirm_time &gt; (create_time + toIntervalMinute(1)))) AS confirmed_checked_amount,\n    countIf(status = 'declined') AS num_declined,\n    sumIf(total_amount, status = 'declined') AS dec_amount,\n    avgIf(total_amount, status = 'declined') AS dec_average\nFROM payments\n┌─num_confirmed_checked─┬─confirmed_checked_amount─┬─num_declined─┬────────dec_amount─┬───────dec_average─┐\n│                    39 │        11195.98991394043 │           50 │ 10780.18000793457 │ 215.6036001586914 │\n└───────────────────────┴──────────────────────────┴──────────────┴───────────────────┴───────────────────┘\n</p>\n</pre>\n<h2 id=\"aggregating-on-unique-entries-only\"></h2>\n<p>It's a common case to calculate the number of unique entries. ClickHouse has several ways to do this using either <code>COUNT(DISTINCT col)</code> (the same as <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/reference/uniqexact/#agg_function-uniqexact\">uniqExact</a>) or  the<a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/reference/uniq/\"><code>uniq()</code></a> when an estimated (but faster) value is sufficient. Still, we might want to have unique values from a column used in different aggregate functions. The <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-distinct\"><code>Distinct</code></a> combinator can be used for this:</p>\n<p><span><img alt=\"Distinct combinator\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F4_39ec84f26a.png&w=2048&q=75\"></span></p>\n<p>Once we add <code>Distinct</code> to the aggregate function, it will ignore repeated values:</p>\n<pre><p>\nSELECT\n    countDistinct(toHour(create_time)) AS hours,\n    avgDistinct(toHour(create_time)) AS avg_hour,\n    avg(toHour(create_time)) AS avg_hour_all\nFROM payments\n┌─hours─┬─avg_hour─┬─avg_hour_all─┐\n│     2 │     13.5 │        13.74 │\n└───────┴──────────┴──────────────┘\n</p>\n</pre>\n<p>Here, <code>avg_hour</code> will be calculated based on the two distinct values only, while <code>avg_hour_all</code> will be calculated based on all <code>100</code> records in the table.</p>\n<h3 id=\"combining-distinct-and-if\"></h3>\n<p>As combinators can be combined together, we can use both previous combinators with an <code>avgDistinctIf</code> function to address more advanced logic:</p>\n<pre><p>\nSELECT avgDistinctIf(toHour(create_time), total_amount &gt; 400) AS avg_hour\nFROM payments\n┌─avg_hour─┐\n│       13 │\n└──────────┘\n</p>\n</pre>\n<p>This will calculate the average on distinct hour values for records with a <code>total_amount</code> value of more than <code>400</code>.</p>\n<h2 id=\"splitting-data-into-groups-before-aggregating\"></h2>\n<p>Instead of min/max analysis, we might want to split our data into groups and calculate figures for each group separately. This can be solved using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-resample\"><code>Resample</code></a> combinator.</p>\n<p>It takes a column, range (start/stop), and a step that you want to split data on. It then returns an aggregate value for each group:</p>\n<p><span><img alt=\"Resample combinator\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F5_37b846a84c.png&w=2048&q=75\"></span></p>\n<p>Suppose we want to split our <code>payments</code> table data based on the <code>total_amount</code> from <code>0</code> (which is the minimum) to <code>500</code> (which is the maximum) with a step of <code>100</code>. Then, we want to know how many entries there are in each group as well as the groups average total:</p>\n<pre><p>\nSELECT\n    countResample(0, 500, 100)(toInt16(total_amount)) AS group_entries,\n    avgResample(0, 500, 100)(total_amount, toInt16(total_amount)) AS group_totals\nFROM payments\nFORMAT Vertical\nRow 1:\n──────\ngroup_entries: [21,20,24,31,4]\ngroup_totals:  [50.21238123802912,157.32600135803222,246.1433334350586,356.2583834740423,415.2425003051758]\n</p>\n</pre>\n<p>Here,  the <code>countResample()</code> function counts the number of entries in each group, and an <code>avgResample()</code> function calculates an average of the <code>total_amount</code> for each group. <code>Resample</code> combinator accepts column name to split based on as a last argument to the combined function.</p>\n<p>Note that  the <code>countResample()</code> function has only one argument (since <code>count()</code> doesn't require arguments at all) and <code>avgResample()</code> has two arguments (the first one is the column to calculate average values for). Finally, we had to use <code>toInt16</code> to convert <code>total_amount</code> to an integer since a <code>Resample</code> combinator requires this.</p>\n<p>To get the <code>Resample()</code> combinators output in a table layout, we can use <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/#arrayzip\"><code>arrayZip()</code></a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-join/\"><code>arrayJoin()</code></a> functions:</p>\n<pre><p>\nSELECT\n    round(tp.2, 2) AS avg_total,\n    tp.1 AS entries\nFROM\n(\n    SELECT\n      arrayJoin(arrayZip(countResample(0, 500, 100)(toInt16(total_amount)),\n      avgResample(0, 500, 100)(total_amount, toInt16(total_amount)))) AS tp\n    FROM payments\n)\n┌─avg_total─┬─entries─┐\n│     50.21 │      21 │\n│    157.33 │      20 │\n│    246.14 │      24 │\n│    356.26 │      31 │\n│    415.24 │       4 │\n└───────────┴─────────┘\n</p>\n</pre>\n<p>Here, we combine corresponding values from 2 arrays into tuples and unfold the resulting array into a table using an <code>arrayJoin()</code> function:</p>\n<h2 id=\"controlling-aggregate-values-for-empty-results\"></h2>\n<p>Aggregate functions react differently to cases when the resulting set contains no data. For example, <code>count()</code> will return <code>0</code> while <code>avg()</code> will produce a <code>nan</code> value.</p>\n<p>We can control this behaviour using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-ordefault\"><code>OrDefault()</code></a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-ornull\"><code>OrNull()</code></a> combinators. Both changes a returned value of an aggregate function used in case of an empty dataset:</p>\n<ul>\n<li><code>OrDefault()</code> will return a default value of the function instead of <code>nan</code>,</li>\n<li><code>OrNull()</code> will return <code>NULL</code> (and will also change the return type to <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/nullable/\"><code>Nullable</code></a>).</li>\n</ul>\n<p>Consider the following example:</p>\n<pre><p>\nSELECT\n    count(),\n    countOrNull(),\n    avg(total_amount),\n    avgOrDefault(total_amount),\n    sumOrNull(total_amount)\nFROM payments\nWHERE total_amount &gt; 1000\n┌─count()─┬─countOrNull()─┬─avg(total_amount)─┬─avgOrDefault(total_amount)─┬─sumOrNull(total_amount)─┐\n│       0 │          ᴺᵁᴸᴸ │               nan │                          0 │                    ᴺᵁᴸᴸ │\n└─────────┴───────────────┴───────────────────┴────────────────────────────┴─────────────────────────┘\n</p>\n</pre>\n<p>As we can see in the first column, zero rows were returned.\nNote how <code>countOrNull()</code> will return <code>NULL</code> instead of <code>0</code>, and <code>avgOrDefault()</code> gives <code>0</code> instead of <code>nan</code>.</p>\n<h3 id=\"using-with-other-combinators\"></h3>\n<p>As well as all other combinators, <code>orNull()</code> and <code>orDefault()</code> can be used together with different combinators for a more advanced logic:</p>\n<pre><p>\nSELECT\n    sumIfOrNull(total_amount, status = 'declined') AS declined,\n    countIfDistinctOrNull(total_amount, status = 'confirmed') AS confirmed_distinct\nFROM payments\nWHERE total_amount &gt; 420\n┌─declined─┬─confirmed_distinct─┐\n│     ᴺᵁᴸᴸ │                  1 │\n└──────────┴────────────────────┘\n</p>\n</pre>\n<p>We've used the <code>sumIfOrNull()</code> combined function to calculate only declined payments and return <code>NULL</code> on an empty set.\nThe <code>countIfDistinctOrNull()</code> function counts distinct <code>total_amount</code> values but only for rows meeting the specified condition.</p>\n<h2 id=\"aggregating-arrays\"></h2>\n<p>ClickHouse's <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/array\">Array type</a> is popular among its users because it brings a lot of flexibility to table structures. To operate with <code>Array</code> columns efficiently, ClickHouse provides a set of <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/\">array functions</a>. To make aggregations on Array types easy, ClickHouse provides the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-array\"><code>Array()</code></a> combinators. 10 │ [24,11,23,9]                 │ [178,177,172,105]                    │     536 │\n...\n</p>\n</pre>\n<p>This table is used to store article reading data for each section of the article.\nWhen a user reads an article, we save the read sections to the <code>sections</code> array column and the associated reading times to the <code>times</code> column:</p>\n<p>Let's use the functions:</p>\n<pre><p>\nSELECT\n    minArray(times),\n    maxArray(times)\nFROM article_reads\n┌─minArray(times)─┬─maxArray(times)─┐\n│              30 │             300 function is <code>any()</code>, which returns any column value under aggregation, and can also be combined <code>Array</code>:</p>\n<pre><p>\nSELECT\n    article_id,\n    anyArray(sections)\nFROM               15 │\n│         20 │                  1 │\n│         16 │                 23 │\n│         12 │                 16 │\n│         11 │                  2 │\n│         10 │                 16 │\n│         13 │                  9 │\n│         17 │                 20 │\n└────────────┴────────────────────┘\n</p>\n</pre>\n<h3 id=\"using-array-with-other-combinators\"></h3>\n<p>The <code>Array</code> combinator can be used together with any other combinator:</p>\n<pre><p>\nSELECT\n    article_id,\n    sumArrayIfOrNull(times, length(sections) &gt; 8)\nFROM article_reads\nGROUP BY                    3001 │\n│         19 │                                                  NULL │\n...\n│         17 │                                                 14424 │\n└────────────┴───────────────────────────────────────────────────────┘\n</p>\n</pre>\n<p>We have used the <code>sumArrayIfOrNull()</code> function to calculate the total times for articles where more than eight sections were read. Note that <code>NULL</code> is returned for articles with zero cases of more than eight sections read because we've also used the <code>OrNull()</code> combinator.</p>\n<p>We can address even more advanced cases if we use array functions along with combinators:</p>\n<pre><p>\nSELECT\n    article_id,\n    countArray(arrayFilter(x -&gt; (x &gt; 120), times)) AS sections_engaged\nFROM article_reads\nGROUP BY article_id\n┌─article_id─┬─sections_engaged─┐\n│         14 │               26 │\n│         18 │               44 │\n...\n│         17 │               98 │\n└────────────┴──────────────────┘\n</p>\n</pre>\n<p>Here, we first filter the <code>times</code> array using an <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/#arrayfilterfunc-arr1-\"><code>arrayFilter</code></a> function to remove all values under 120 seconds. Then, we use <code>countArray</code> to calculate filtered times (which means engaged reads in our case) for each article.</p>\n<h3 id=\"aggregating-maps\"></h3>\n<p>Another powerful type available in ClickHouse is the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/map/\">Map</a>. Like arrays, we can use <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-map\"><code>Map()</code></a> combinator to apply aggregations to this type.</p>\n<p>Suppose we have the following table with a <code>Map</code> column type:</p>\n<pre><p>\nCREATE TABLE page_loads\n(\n    `time` DateTime,\n    `url` String,\n    `params` Map(String, UInt32)\n)\nENGINE = MergeTree\nORDER BY (url, time)\n┌────────────────time─┬─url─┬─params───────────────────────────────┐\n│ 2023-01-25 17:44:26 │ /   │ {'load_speed':100,'scroll_depth':59} │\n│ 2023-01-25 17:44:37 │ /   │ {'load_speed':400,'scroll_depth':12} │\n└─────────────────────┴─────┴──────────────────────────────────────┘\n</p>\n</pre>\n<p>We can use a <code>Map()</code> combinator for the <code>sum()</code> and <code>avg()</code> functions to get total loading times and average scroll depth:</p>\n<pre><p>\nSELECT\n    sumMap(params)['load_speed'] AS total_load_time,\n    avgMap(params)['scroll_depth'] AS average_scroll\nFROM page_loads\n┌─total_load_time─┬─average_scroll─┐\n│             500 │           35.5 │\n└─────────────────┴────────────────┘\n</p>\n</pre>\n<p>The <code>Map()</code> combinator can also be used with other combinators:</p>\n<pre><p>\nSELECT sumMapIf(params, url = '/404')['scroll_depth'] AS average_scroll FROM page_loads\n</p>\n</pre>\n<h2 id=\"aggregating-respective-array-values\"></h2>\n<p>Another way to work with array columns is to aggregate corresponding values from two arrays. This results in another array.\nThis can be used for vectorized data (like vectors or matrices) and is implemented via the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-foreach\"><code>ForEach()</code></a> combinator:</p>\n<p><span><img alt=\"ForEach combinator\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F7_b048be4d47.png&w=2048&q=75\"></span></p>\n<p>Suppose we have the following table with vectors:</p>\n<pre><p>\nSELECT * FROM vectors\n┌─title──┬─coordinates─┐\n│ first  │ [1,2,3]     │\n│ second │ [2,2,2]     │\n│ third  │ [0,2,1]     │\n└────────┴─────────────┘\n</p>\n</pre>\n<p>To calculate the average coordinates array (vector), we can use an <code>avgForEach()</code> combined function:</p>\n<pre><p>\nSELECT avgForEach(coordinates) FROM vectors\n┌─avgForEach(coordinates)─┐\n│ [1,2,2]                 │\n└─────────────────────────┘\n</p>\n</pre>\n<p>This will ask ClickHouse to calculate an average value for the first element of all <code>coordinates</code> arrays and put it into the first element of the resulting array. Then repeat the same for the second and third elements.</p>\n<p>And, of course, use with other combinators is also supported:</p>\n<pre><p>\nSELECT avgForEachIf(coordinates, title != 'second') FROM vectors\n┌─avgForEachIf(coordinates, notEquals(title, 'second'))─┐\n│ [0.5,2,2]                                             │\n└───────────────────────────────────────────────────────┘\n</p>\n</pre>\n<h2 id=\"working-with-aggregation-states\"></h2>\n<p>ClickHouse allows working with intermediate aggregation states instead of resulting values.\nLet's say we need to count unique values in our case, but we don't want to save the values themselves (because it takes space).\nIn this case, we can use a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-state\"><code>State()</code></a> combinator for the <code>uniq()</code> function to save the intermediate aggregation state and then use a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-merge\"><code>Merge()</code></a> combinator to calculate actual value:</p>\n<pre><p>\nSELECT uniqMerge(u)\nFROM\n(\n    SELECT uniqState(number) AS u FROM numbers(5)\n    UNION ALL\n    SELECT uniqState(number + 1) AS u FROM numbers(5)\n)\n┌─uniqMerge(u)─┐\n│            6 │\n└──────────────┘\n</p>\n</pre>\n<p>Here, the first nested query will return the state for the unique count of <code>1...5</code> numbers. The second nested query returns the same for <code>2...6</code> numbers. The parent query then uses the <code>uniqMerge()</code> function to merge our states and get a count of all unique numbers we saw:</p>\n<p><span><img alt=\"uniqState() and uniqMerge() examples\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F1_d266654aa7.png&w=2048&q=75\"></span></p>\n<p>Why do we want to do this? Simply because aggregate states take much less space than the original data. This is particulartly important when we want to store this state on disk. For example, <code>uniqState()</code> data takes 15 times less space than 1 million integer numbers:</p>\n<pre><p>\nSELECT\n    table,\n    formatReadableSize(total_bytes) AS size\nFROM system.tables\nWHERE table LIKE 'numbers%'\n┌─table─────────┬─size───────┐\n│ numbers       │ 3.82 MiB   │ &lt;- we saved 1 million ints here\n│ numbers_state │ 245.62 KiB │ &lt;- we save uniqState for 1m ints here\n└───────────────┴────────────┘\n</p>\n</pre>\n<p>ClickHouse provides an <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/engines/table-engines/mergetree-family/aggregatingmergetree/\"><code>AggregatingMergeTree</code></a> table engine for storing aggregation states and automatically merging them on the primary key. Let's create a table to store aggregated data for daily payments from our previous examples:</p>\n<pre><p>\nCREATE TABLE payments_totals\n(\n    `date` Date,\n    `total_amount` AggregateFunction(sum, Float)\n)\nENGINE = AggregatingMergeTree\nORDER BY date\n</p>\n</pre>\n<p>We've used the <code>AggregateFunction</code> type to let ClickHouse know we're going to store aggregated total states instead of scalar values. On insert, we need to use the <code>sumState</code> function to insert the aggregate state:</p>\n<pre><p>\nINSERT INTO payments_totals SELECT\n    date(create_time) AS date,\n    sumState(total_amount)\nFROM payments\nWHERE status = 'confirmed'\nGROUP BY date\n</p>\n</pre>\n<p>Finally, we need to use the <code>sumMerge()</code> function to fetch the resulting values:</p>\n<pre><p>\n┌─sumMerge(total_amount)─┐\n│     12033.219916582108 │\n└────────────────────────┘\n</p>\n</pre>\n<p><strong>Note</strong> that ClickHouse provides an easy way to use aggregated table engines based on <a target=\"_blank\" href=\"https://clickhouse.com/blog/using-materialized-views-in-clickhouse\">materialized views</a>. ClickHouse also provides a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-simplestate\">SimpleState</a> combinator as an optimized version that can be used with some aggregate functions (like 'sum' or 'min').</p>\n<h2 id=\"summary\"></h2>\n<p>Aggregation function combinators bring almost limitless possibilities to analytical querying on top of any data structure in ClickHouse. We can <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-if\">add conditions</a> to aggregations, apply functions to <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-array\">array elements</a> or get intermediate <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators/#-state\">states</a> to store data in aggregated form but still available for querying.</p></div></article>"
