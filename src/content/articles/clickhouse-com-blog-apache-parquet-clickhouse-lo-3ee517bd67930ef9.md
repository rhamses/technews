This adoption has led to it becoming the foundation for more recent data lake formats, e.g., <a target=\"_blank\" href=\"https://iceberg.apache.org/\">Apache Iceberg</a>. In this blog series, we explore how ClickHouse can be used to read and write this format before diving into the Parquet in more detail. For more experienced Parquet users, we also discuss some optimizations that users can make when writing Parquet files using ClickHouse to maximize compression, as well as some recent developments to optimize read performance using parallelization.</p>\n<p>For our examples, we utilize the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/uk-price-paid\">UK house price</a> dataset. This contains data about prices paid for real estate property in England and Wales, from 1995 to the time of writing. We distribute this in Parquet format in the public s3 bucket <code>s3://datasets-documentation/uk-house-prices/parquet/</code>.</p>\n<h3 id=\"clickhouse-local\"></h3>\n<p>For our examples, we use local and S3-hosted Parquet files, querying these with <a target=\"_blank\" href=\"https://clickhouse.com/blog/extracting-converting-querying-local-files-with-sql-clickhouse-local\">ClickHouse Local</a>. ClickHouse Local is an easy-to-use version of ClickHouse that is ideal for developers who need to perform fast processing on local and remote files using SQL without having to install a full database server. Designed and optimized for data analysis using the local compute resources on your laptop or workstation, users can query, filter, and transform data files in almost any format using only SQL and without having to write a single line of Python code. We recommend this recent blog post for an overview of this tool's capabilities. Most importantly, ClickHouse Local and ClickHouse Server share the same code for Parquet reading and writing, so any explanations apply to both.</p>\n<h2 id=\"what-is-parquet\"></h2>\n<p>The <a target=\"_blank\" href=\"https://parquet.apache.org/\">official description</a> for Apache Parquet provides an excellent summary of its design and properties: “Apache Parquet is an open source, <strong>column-oriented</strong> data file format designed for <strong>efficient data storage</strong> and <strong>retrieval</strong>”.</p>\n<p>Similar to ClickHouse’s <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/engines/table-engines/mergetree-family/mergetree\">MergeTree format</a>, data is stored <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/intro#why-column-oriented-databases-work-better-in-the-olap-scenario\">column-oriented</a>. This effectively means values of the same column are stored together, in contrast to row-oriented file formats (e.g., Avro), where row data is colocated.</p>\n<p>This data orientation, along with support for a number of <a target=\"_blank\" href=\"https://parquet.apache.org/docs/file-format/data-pages/encodings/\">encoding techniques</a> suited to the modern processors’ pipeline, allows for a high compression rate and efficient storage property. Column orientation additionally minimizes the amount of data read, as only the necessary columns are read from storage for analytical queries such as group bys. When coupled with high compression rates and internal statistics provided on each column (stored as metadata), Parquet also promises fast retrieval.</p>\n<p>This latter property largely depends on the full exploitation of the metadata, the level of parallelization in any query engine, and the decisions made when storing the data. We discuss these below in relation to ClickHouse.</p>\n<p>Before we dig into the internals of Parquet, we’ll cover how ClickHouse supports the writing and reading of this format.</p>\n<h2 id=\"querying-parquet-with-clickhouse\"></h2>\n<p>In the example below, we assume our house price data has been exported to a single <code>house_prices.parquet</code> file and the use of ClickHouse Local to query unless stated otherwise.</p>\n<h3 id=\"reading-schemas\"></h3>\n<p>Identifying the schema of any file can be achieved with the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/describe-table\">DESCRIBE statement</a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/files#file\">file table function</a>:</p>\n<div><pre><code><span><span>DESCRIBE</span> <span>TABLE</span> file(<span>'house_prices.parquet'</span>)</span>\n<span></span>\n<span>┌─name──────┬─type─────────────┬</span>\n<span>│ price \t│ Nullable(UInt32) │</span>\n<span>│ <span>date</span>  \t│ Nullable(UInt16) │</span>\n<span>│ postcode1 │ Nullable(String) │</span>\n<span>│ postcode2 │ Nullable(String) │</span>\n<span>│ type  \t│ Nullable(Int8)   │</span>\n<span>│ is_new\t│ Nullable(UInt8)  │</span>\n<span>│ duration  │ Nullable(Int8)   │</span>\n<span>│ addr1 \t│ Nullable(String) │</span>\n<span>│ addr2 \t│ Nullable(String) │</span>\n<span>│ street\t│ Nullable(String) │</span>\n<span>│ locality  │ Nullable(String) │</span>\n<span>│ town  \t│ Nullable(String) │</span>\n<span>│ district  │ Nullable(String) │</span>\n<span>│ county\t│ Nullable(String) <span>|</span></span>\n<span>└───────────┴──────────────────┴</span></code></pre></div>\n<h3 id=\"querying-local-files\"></h3>\n<p>This above file table function can be used as the input to a <code>SELECT</code> query, allowing us to execute queries over the Parquet file.
