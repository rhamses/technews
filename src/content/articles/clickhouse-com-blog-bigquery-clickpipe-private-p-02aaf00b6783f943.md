contentHtml: "<div><p>Running ClickHouse Cloud as a <em>speed-layer</em> on top of BigQuery is an increasingly common pattern: you let BigQuery handle batch processing and data warehousing, while ClickHouse powers <strong>interactive queries that need sub-second latency</strong>. As we onboard more customers with this architecture, it became clear that moving data over is a significant first hurdle in the onboarding experience. Teams would spend days iterating on export scripts, writing custom type conversion logic, and trial-and-error — before they could even start prototyping and testing their queries.</p>\n<blockquote>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/cloud/clickpipes/bigquery-connector\"><em>Join the waitlist</em></a> <em>today to try out the BigQuery connector for ClickPipes!</em></p>\n</blockquote>\n<p>Today, we’re announcing the first step towards making this integration a no-brainer: <strong>a new BigQuery connector for ClickPipes</strong>, in Private Preview! Whether you're evaluating ClickHouse Cloud for specific use cases where sub-second query latency matters, or exploring how BigQuery and ClickHouse can work together in your data architecture, the connector provides a straightforward path to get your data into ClickHouse Cloud for rapid prototyping and performance testing.</p>\n<h2 id=\"why-build-a-clickpipe\"></h2>\n<p><strong>Simpler than building your own pipeline.</strong> Previously, loading data from BigQuery into ClickHouse meant manually exporting tables to GCS, managing service account permissions across both platforms, writing custom SQL, and handling schema mapping yourself. The BigQuery ClickPipe handles all of this automatically: point it at your BigQuery dataset(s), configure your target tables, and the connector manages all those steps for you.</p>\n<p><strong>Built for continuous ingestion.</strong> The connector is built on <a target=\"_blank\" href=\"http://github.com/PeerDB-io/peerdb\">PeerDB</a>, an ✨open-source✨ data replication platform maintained by ClickHouse. Although BigQuery doesn't have a replication log for log-based CDC, PeerDB has the primitives to support query-based CDC for incremental syncs. We'll use this to add continuous ingestion capabilities in future releases as we evaluate the right cost-performance tradeoffs for BigQuery’s architecture.</p>\n<p><strong>Data movement is just the start.</strong> Loading your BigQuery tables into ClickHouse gets you far: you can prototype queries, validate performance, and build proof-of-concepts for the interactive workloads you want to migrate. But a successful, end-to-end workload migration also means translating SQL queries, optimizing schemas for ClickHouse's architecture, and validating results across (potentially thousands of) queries. As our teams make progress on AI-assisted migrations (see <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-build-agentic-cli-accelerate-postgres-clickhouse-apps\">clickhouse.build</a> for a recent example), we're exploring how to package this up for BigQuery and other connectors, too!</p>\n<h2 id=\"main-features\"></h2>\n<h4 id=\"efficient-bulk-loads\"></h4>\n<p>Private Preview supports <strong>bulk data loads</strong> from BigQuery tables. This is what most teams need as that first step: load a representative dataset, test some queries, and validate that ClickHouse performs the way you expect. The connector exports each table as compressed Avro files (auto-sharded at 1GB per file) to an intermediate GCS bucket, then loads them into ClickHouse Cloud in parallel. For very large datasets, it’s possible to adjust ingestion settings and sizing to speed up the initial load.</p>\n<h4 id=\"table--and-column-level-filtering\"></h4>\n<p>The connector automatically discovers all datasets and tables within your BigQuery project (that the associated service account is scoped to). From the ClickPipes UI, you have fine-grained control over what to load, whether that's a single table, an entire dataset, or even tables across different datasets.</p>\n<p><span><img alt=\"image2.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fimage2_4fd922a530.png&w=2048&q=75\"></span></p>\n<p>For each table, you can exclude specific columns, customize column mappings, and configure granular settings like how to handle <code>NULL</code> values. This eliminates the manual work of exporting tables one-by-one and gives you control over what data lands in ClickHouse without writing any code.</p>\n<h4 id=\"implicit-type-mapping\"></h4>\n<p>The connector handles BigQuery's type system automatically, including complex conversions that don't map directly to ClickHouse (<em>e.g.</em> <code>DATE</code> values stored as days-since-epoch become proper ClickHouse dates, <code>BYTES</code> columns get base64 decoded). With type mapping out of the way, you avoid writing error-prone conversion logic and investing time in debugging edge cases when data doesn't load correctly or queries return unexpected results.</p>\n<h4 id=\"terraform-and-open-api-support\"></h4>\n<p>Although you can only sync full tables in Private Preview, for smaller tables it can be useful to do full periodic reloads. To support workflow automation and managing the ClickPipe as code, a new <code>bigquery</code> source type is available in <a target=\"_blank\" href=\"https://clickhouse.com/docs/cloud/manage/api/swagger#tag/ClickPipes\">the ClickPipes OpenAPI specification</a>, as well as the ClickHouse Terraform Provider (<a target=\"_blank\" href=\"https://github.com/ClickHouse/terraform-provider-clickhouse/releases/tag/v3.8.3-alpha1\">3.8.3-alpha1</a>+).</p>\n<h2 id=\"how-does-it-work\"></h2>\n<p>Building a connector for a cloud data warehouse presents a unique challenge: moving (potentially very) large datasets efficiently while minimizing upstream costs. The new ClickPipes connector uses BigQuery's native export jobs (<strong>free!</strong>) to avoid incurring query processing charges.</p>\n<p><span><img alt=\"image1.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fimage1_a424ad43f3.jpg&w=2048&q=75\"></span></p>\n<p><em><strong>Bigquery ClickPipe:</strong> the user configures a ClickPipe to point to the desired tables in BigQuery, providing a service account key for authentication (1). A BigQuery job exports the data into an intermediate GCS bucket (2-3). ClickPipes reads from the staging bucket (4) and inserts data into ClickHouse Cloud tables (5). Authentication between services is managed via IAM.</em></p>\n<p><strong>Setup requirements:</strong></p>\n<ul>\n<li>A BigQuery project with the dataset(s) you want to export tables from, and a <a target=\"_blank\" href=\"https://clickhouse.com/cloud\">ClickHouse Cloud account</a>.</li>\n<li>A Google Cloud service account with BigQuery <code>dataViewer</code> and <code>jobUser</code> permissions, as well as GCS <code>objectAdmin</code> and bucketViewer permissions.</li>\n<li>A dedicated GCS bucket for intermediate staging. In Private Preview, this bucket must be provisioned in your GCP account. In the future, ClickPipes will provision and manage the staging bucket.</li>\n</ul>\n<h2 id=\"next-up-incremental-syncs\"></h2>\n<p>\nAfter a successful onboarding, the most common request we get from customers is performing incremental loads to keep BigQuery and ClickHouse in sync. Unlike databases with transaction logs, BigQuery requires querying tables to detect changes, or using advanced ($$) features like time travel — all of which drive up costs. 📈 We're evaluating strategies for query-based CDC like timestamp-based incremental loads for append-only tables, partition-aware sync for time-partitioned data, and metadata-driven triggers to minimize query costs. <strong>If incremental syncs are critical for your use case, we’d love to work with you as a design partner</strong>.\n</p>\n<p>In the meantime, we recommend <a target=\"_blank\" href=\"https://clickhouse.com/docs/integrations/clickpipes/object-storage/gcs/overview\">using the Google Cloud Storage ClickPipe</a> to continuously sync BigQuery data exports to ClickHouse Cloud, once the initial load via the BigQuery ClickPipes is completed. We’ll publish guides on how to implement this pattern in the next few weeks!</p>\n<h2 id=\"how-to-sign-up-for-private-preview\"></h2>\n<p>The BigQuery connector is in Private Preview and available upon request. Fill out <a target=\"_blank\" href=\"https://clickhouse.com/cloud/clickpipes/bigquery-connector\">this form</a> to join the waitlist, or reach out to your ClickHouse Cloud account manager! We'll work through requests as soon as possible, and expect to reach out to you, worst case, within a few days of signing up.</p>\n<p>We're actively looking for design partners to help shape this connector, in particular teams who need incremental syncs, or are planning large-scale BigQuery migrations. Your requirements and feedback will directly influence what we build next!</p></div>"
