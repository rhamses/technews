specificepithet LowCardinality(String),</span>\n<span>    scientificname LowCardinality(String),</span>\n<span>    vernacularname LowCardinality(String),</span>\n<span>    taxonremarks mortonEncode(mercator_x, mercator_y)</span></code></pre></div>\n<p>Most of the structure is the same as inferred from the CSV file.</p>\n<p>I removed <code>Nullable</code> because it is unneeded - I'd better use empty strings instead of NULLs, and it is generally good practice.</p>\n<p>I've replaced <code>year</code>, <code>month</code>, <code>day</code> with <code>EPHEMERAL</code> columns and added a <code>date</code> column, calculated from them: <code>date Date MATERIALIZED makeDate(year, month, day)</code>. <code>EPHEMERAL</code> columns are used in <code>INSERT</code> queries but are not stored in a table - they can be used to calculate expressions for other columns to apply transformations on the insertion time. In contrast, <code>MATERIALIZED</code> columns are columns that cannot be used in the INSERT query but are always calculated from their expressions.</p>\n<p>I've analyzed the number of distinct values in various columns and replaced many of the <code>String</code> data types with <code>LowCardinality(String)</code> to apply dictionary encoding. For example, the <code>country</code> column contains only 253 unique values.</p>\n<p>Additionally, I've created two materialized columns, <code>mercator_x</code> and <code>mercator_y</code> that map the lat/lon coordinates to the <a target=\"_blank\" href=\"https://en.wikipedia.org/wiki/Web_Mercator_projection\">Web Mercator</a> projection. The coordinates on the Mercator projection are represented by two UInt32 numbers for easier segmentation of the map into tiles. Additionally, I set up the order of the table by a <a target=\"_blank\" href=\"https://en.wikipedia.org/wiki/Space-filling_curve\">space-filling curve</a> on top of these numbers, and I created two <code>minmax</code> indices for faster search. ClickHouse has everything we need for real-time mapping applications!</p>\n<h3 id=\"data-loading\"></h3>\n<p>Then, I loaded the data with the following query:</p>\n<div><pre><code><span>ch --progress --query <span>\"</span></span>\n<span><span>    SELECT * FROM file('2023-eBird-dwca-1.0.zip :: eod.csv')</span></span>\n<span><span>    WHERE decimallatitude BETWEEN -89 AND 89</span></span>\n<span><span>      AND decimallongitude BETWEEN -180 AND 180</span></span>\n<span><span>    FORMAT Native\"</span> \\</span>\n<span>| clickhouse-client --host ... --query <span>\"INSERT INTO birds_mercator (basisofrecord, institutioncode, collectioncode, catalognumber, occurrenceid, recordedby, year, month, day, publishingcountry, country, stateprovince, county, decimallatitude, decimallongitude, locality, kingdom, phylum, class, order, family, genus, specificepithet, scientificname, vernacularname, taxonremarks, taxonconceptid, individualcount) FORMAT Native\"</span></span></code></pre></div>\n<p>Here, I use <code>clickhouse-local</code> (which is available under the <code>ch</code> alias after installation) to filter out of bound values of latitude and longitude (required by the Mercator projection) and convert the result to the <code>Native</code> format, which is optimal for insertion.
