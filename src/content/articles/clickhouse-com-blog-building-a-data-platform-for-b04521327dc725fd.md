contentHtml: "<article><div><p>One of the most important shifts in software right now is that <a target=\"_blank\" href=\"https://clickhouse.com/blog/agent-facing-analytics\">AI agents are becoming a new kind of database user</a>. Traditional analytics workflows are built around people. A business user asks a question, an analyst writes SQL, a dashboard gets built, and the answer arrives later. Agents change that loop. They inspect available tools, reason over schema, generate SQL, run queries, observe the results, and iterate in seconds.</p>\n<p><span><img alt=\"ai_march2026_3_69dc9fcbf2.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fai_march2026_3_69dc9fcbf2_31969e1512.jpg&w=2048&q=75\"></span></p>\n<p>This new user needs a data platform that can keep up: real-time ingestion, fast aggregation, flexible handling of semi-structured events, low-latency concurrency, and economics that still work at massive scale. ClickHouse already has this foundation. Not because we pivoted to AI, but because the things ClickHouse has always been good at happen to match the shape of modern AI workloads surprisingly well.</p>\n<p>What changes is <em>how</em> this new user interacts with the database. Agents need better discoverability, query patterns tuned for exploratory AI workflows, LLM-friendly documentation, stronger server-side state and memory patterns, and access control designed around short-lived, task-scoped permissions. There is a lot of iteration ahead. But the direction is clear.</p>\n<h2 id=\"the-agentic-data-stack\"></h2>\n<p>Building for this new user means rethinking the workflow. The old pattern, someone asks a question, an analyst writes SQL, a dashboard gets built, is too slow when the consumer is an agent that can reason and iterate in seconds. The Agentic Data Stack is our view of what replaces it.</p>\n<p>It has three layers: LibreChat as the chat interface, ClickHouse plus MCP as the data layer, and Langfuse for LLM observability. LibreChat gives teams a provider-agnostic, MCP-connected interface for conversational analytics. ClickHouse plus MCP makes the database queryable as part of an agent's reasoning loop. And Langfuse, which itself already runs on ClickHouse, adds tracing, prompt management, and cost and latency monitoring. Together they form a practical reference architecture for <a target=\"_blank\" href=\"https://clickhouse.com/blog/agent-facing-analytics\">agentic analytics</a>.</p>\n<p><span><img alt=\"AI_is_Redrawing_the_Database_Market_1409_eac7cc339d.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FAI_is_Redrawing_the_Database_Market_1409_eac7cc339d_90321404d6.jpg&w=2048&q=75\"></span></p>\n<p>We have written about this architecture in more detail in <a target=\"_blank\" href=\"https://clickhouse.com/blog/the-agentic-data-stack\">The Agentic Data Stack</a> and the <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-acquires-langfuse-open-source-llm-observability\">Langfuse acquisition announcement</a>.</p>\n<h3 id=\"we-are-using-this-stack-ourselves\"></h3>\n<p>Internally, we built DWAINE, the Data Warehouse AI Natural Expert, on this architecture. It connects LibreChat to our ClickHouse data warehouse through MCP, with a comprehensive business glossary to give the model context on our data model and business logic. It now serves more than 250 users, sees more than 200 daily messages, handles roughly 70% of data warehouse questions, and has reduced analyst workload by an estimated 50 to 70%. We wrote about the full build in <a target=\"_blank\" href=\"https://clickhouse.com/blog/ai-first-data-warehouse\">How we made our internal data warehouse AI-first</a>.</p>\n<p>We also made that experience public through <a target=\"_blank\" href=\"https://clickhouse.com/blog/agenthouse-demo-clickhouse-llm-mcp\">AgentHouse</a> at <a target=\"_blank\" href=\"https://llm.clickhouse.com/\"><code>llm.clickhouse.com</code></a>, where anyone can query dozens of public datasets in natural language and see ClickHouse plus MCP in action.</p>\n<h2 id=\"releases-for-agents-and-agentic-developers\"></h2>\n<p>Beyond the big-picture architecture, we have already shipped a concrete set of tools for agents and their teams building with ClickHouse.</p>\n<h3 id=\"agentic-data-stack-quickstart\"></h3>\n<p>We published the Agentic Data Stack as a one-command, composable Docker deployment. It bundles LibreChat, ClickHouse, and Langfuse into a setup that teams can run on their own infrastructure. The components are pre-wired, so LibreChat can talk to ClickHouse through MCP and Langfuse can trace interactions from the start.</p>\n<p>That local-first, open architecture matters. Teams can keep their data in their own ClickHouse deployment, choose any model provider they want, and avoid stitching together a stack from scratch just to begin experimenting.</p>\n<h3 id=\"clickhouse-mcp-servers\"></h3>\n<p>We ship both an open-source ClickHouse MCP server and a remote MCP server for ClickHouse Cloud.</p>\n<p>The open-source server gives agents the ability to list databases, inspect tables, and run queries through a standard MCP interface. It is read-only by default and designed to work with MCP-compatible clients such as Claude Desktop, Cursor, Windsurf, and custom agents. It also supports chDB for querying local files and URLs without a full ETL flow.</p>\n<p>The remote MCP server extends that model into ClickHouse Cloud, letting teams expose analytical data to AI tools without having to deploy and manage an MCP server themselves.</p>\n<h3 id=\"chdb-4\"></h3>\n<p>We also pushed ClickHouse into a more embedded, developer-friendly shape with chDB 4.</p>\n<p>chDB is the embedded ClickHouse engine, and version 4 introduced a Pandas-like DataStore API. That matters for AI because LLMs are already very good at generating Pandas-style code. chDB 4 lets developers keep that ergonomic surface while executing on the ClickHouse engine, with optimizations such as lazy execution, filter pushdown, and column pruning under the hood.</p>\n<p>In other words, it closes part of the gap between what language models naturally produce and what high-performance analytics systems want to execute.</p>\n<h3 id=\"clickhouse-assistant\"></h3>\n<p>We also built the agent experience directly into the product. ClickHouse Assistant is a co-pilot inside the ClickHouse Cloud SQL Console, designed for ad-hoc agentic analytics. It is loaded with ClickHouse Agent Skills so its recommendations follow ClickHouse best practices out of the box. It supports a context selector using <code>@</code> syntax, letting users scope conversations to specific databases, tables, or saved queries. It also supports <code>AGENTS.md</code> files, so teams can define domain-specific instructions that the assistant picks up automatically.</p>\n<p>Behind the scenes, we are also building a native RAG API and working on custom domain skills, both still in progress but aimed at the same goal: making the assistant context-aware enough to be genuinely useful for real analytical work, not just SQL generation.</p>\n<h3 id=\"clickhouse-agent-skills\"></h3>\n<p>General-purpose models can write SQL, but they can often struggle to get the best practices right across different databases. They can make predictable mistakes around schema design, partitioning, ordering keys, joins, materialized views, and ingestion patterns.</p>\n<p>To close that gap, we shipped ClickHouse Agent Skills: an open-source package of prioritized best practices that can be installed into your agent environments. The Skills significantly improve an agent's ability to get the most out of ClickHouse, and allow us to continually refresh knowledge as things change.</p>\n<h3 id=\"ide-integrations\"></h3>\n<p>We also moved this closer to where developers already work.</p>\n<p>The <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cursor-plugin\">ClickHouse Cursor plugin</a> packages ClickHouse agent guidance and MCP configuration directly into Cursor workflows. The <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-kiro-power\">ClickHouse Kiro Power</a> does the same in Kiro, exposing ClickHouse tools and best-practice guidance inside the IDE. Database interaction is becoming part of the coding agent loop, not a separate activity.</p>\n<h3 id=\"llm-accessible-content\"></h3>\n<p>We have also started making our written content directly consumable by agents. Every blog post and guide on clickhouse.com is available as clean Markdown, and we publish an llms.txt file so that agents and crawlers can discover and navigate our content programmatically. We are also investigating automatically serving Markdown to known LLM user-agents, so that when an agent fetches a ClickHouse page it gets structured text rather than a full HTML document.</p>\n<p>As agents are becoming a primary consumer of technical content, the content should be shaped to serve them well.</p>\n<h3 id=\"agent-friendly-docs\"></h3>\n<p>We have applied the same thinking to our documentation. The ClickHouse docs already serve an <code>llms.txt</code> file and a docs MCP server is behind our Ask AI feature.</p>\n<p>Soon, we will be adding one-click MCP server connections from docs pages, <code>llms-full.txt</code>, content negotiation to serve Markdown instead of HTML when an agent visits the site, the ability to append <code>.md</code> to any URL to view raw Markdown, a semantic search tool exposed to agents as a tool call so they can find information by intent rather than keyword, and per-page context menus that let users open conversations in popular AI chat interfaces with page context pre-filled.</p>\n<h3 id=\"clickhouse-build\"></h3>\n<p>We shipped an experimental agent, clickhouse.build, an agentic CLI that used multiple agents to inspect a Postgres-backed application, identify candidate analytical workloads, set up real-time syncing, and adapt the application code.</p>\n<p>It launched just before Anthropic introduced Agent Skills as a pattern for encoding reusable agent workflows. It has helped us to learn a lot about the boundaries of shipping custom agents, and perhaps that these migration and evaluation flows might now be better expressed as composable skills. The lessons from clickhouse.build are feeding directly into how we think about packaging ClickHouse guidance for agents going forward.</p>\n<h2 id=\"ai-runs-on-data-and-that-data-runs-on-clickhouse\"></h2>\n<p>Some of the most demanding AI companies in the world are already running core workloads on ClickHouse.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/why-openai-uses-clickhouse-for-petabyte-scale-observability\">OpenAI uses ClickHouse for petabyte-scale observability</a>. Their systems ingest petabytes of log data per day, growing more than 20% month over month. When GPT-4o image generation launched and log volume jumped 50% overnight, ClickHouse absorbed the spike. Their deployment runs across 90 shards with 2 replicas each, and even low-level optimizations paid off at that scale.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/how-anthropic-is-using-clickhouse-to-scale-observability-for-ai-era\">Anthropic has said ClickHouse \"played an instrumental role\" in helping them develop and ship Claude 4.</a> They run ClickHouse in custom air-gapped environments to satisfy stringent safety requirements, and a team of just three people managed the entire observability stack through rapid growth. Claude itself recommended ClickHouse when they were evaluating solutions.</p>\n<p><a target=\"_blank\" href=\"http://character.ai/\">Character.AI processes more than 450 petabytes of raw log data per month across thousands of GPUs</a>. After moving to ClickHouse, they were able to store 10x more data while cutting costs by 50%.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/lovable-ai-powered-observability\">Lovable</a> built its analytics pipeline with remarkable speed and now uses ClickHouse in its AI-native product. <a target=\"_blank\" href=\"https://clickhouse.com/blog/poolside-using-clickhouse-to-build-next-gen-ai-for-software-development\">Poolside</a> uses ClickHouse to work across billions of documents and code artifacts for next-generation code models. <a target=\"_blank\" href=\"https://clickhouse.com/blog/sierra-observability-analytics\">Sierra</a> uses ClickHouse to unify observability and analytics for customer-facing AI agents. <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-memorial-sloan-kettering-cancer-center-is-using-clickhouse-to-accelerate-cancer-research\">Memorial Sloan Kettering Cancer Center</a> uses ClickHouse to accelerate genomic research over billions of data points.</p>\n<p>These companies did not choose ClickHouse because it had an \"AI\" label on it. They chose it because AI workloads are, at their core, hard data workloads.</p>\n<h2 id=\"guides-and-further-reading\"></h2>\n<p>We have published detailed guides covering the ideas and tools in this post.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/the-agentic-data-stack\"><strong>The Agentic Data Stack</strong></a> explains the full architecture: why conversational analytics needs a chat layer, a data layer, and an observability layer, and how LibreChat, ClickHouse, and Langfuse fit together.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/agenthouse-demo-clickhouse-llm-mcp\"><strong>Introducing AgentHouse</strong></a> is the story behind <code>llm.clickhouse.com</code>, a public demo where anyone can query dozens of real datasets in natural language using ClickHouse and MCP.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/integrating-clickhouse-mcp\"><strong>Integrating with ClickHouse MCP</strong></a> walks through connecting the ClickHouse MCP server to clients like Claude Desktop, Cursor, and custom agents, with practical setup and usage examples.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/ai-first-data-warehouse\"><strong>How we made our internal data warehouse AI-first</strong></a> covers the full DWAINE build: architecture decisions, security model, what worked, and where traditional BI still wins.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/how-to-set-up-clickhouse-for-agentic-analytics\"><strong>How to set up ClickHouse for agentic analytics</strong></a> is the operational guide. The Agentic Data Stack is a practical implementation of that vision, an open, composable architecture where conversation, data access, and observability work together.</p>\n<p>But the impact of AI on databases goes well beyond conversational analytics. As we wrote in <a target=\"_blank\" href=\"https://clickhouse.com/blog/ai-redrawing-database-market\">AI is redrawing the database market</a>, AI is changing workload expectations across every major use case. In real-time analytics, AI-powered application features are tightening the feedback loop between transactional writes and analytical reads. In data warehousing, agent-facing analytics turns what used to be occasional batch queries into bursts of high-concurrency, low-latency requests that break the assumptions legacy platforms were built on. In observability, AI-driven investigation requires full-fidelity data at granularity levels that pre-aggregation and sampling cannot support.</p>\n<p>Across all three, the requirements converge: high concurrency, real-time query performance, and full-fidelity data at scale. Those are the same properties that ClickHouse was built around from the start.</p>\n<p>This is a fast-moving space. A lot of what we are doing is experimenting, listening to the market and our users, and discovering where AI adds real value and where it does not. That is why companies like OpenAI, Anthropic, Character.AI, Lovable, and Sierra choose to build on ClickHouse. Not because we put an AI label on it, but because the foundation was already right.</p></div></article>"
