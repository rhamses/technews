contentHtml: "<article><div><p>Financial data never stops moving. Prices tick up and down, trades execute in milliseconds, and quotes update thousands of times per second. Capturing that stream and turning it into something usable in real time is a tough engineering problem, but with the right tools, it becomes approachable.</p>\n<p>StockHouse is a complete demo showing how to build a streaming market analytics app using <a target=\"_blank\" href=\"https://clickhouse.com/\">ClickHouse</a>, <a target=\"_blank\" href=\"https://massive.com/\">Massive</a>, and <a target=\"_blank\" href=\"https://perspective.finos.org/\">Perspective</a>.</p>\n<p>You can explore the live version at <a target=\"_blank\" href=\"https://stockhouse.clickhouse.com/\">stockhouse.clickhouse.com</a>.</p>\n<p><span><img alt=\"stockhouse-landing.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fstockhouse_landing_3195032938.png&w=2048&q=75\"></span></p>\n<p>StockHouse ingests live market data from Massive's WebSocket APIs, stores it efficiently in ClickHouse, and visualizes it in a web dashboard that updates within milliseconds. The goal is to demonstrate how to handle high-frequency, high-volume data end-to-end: ingestion, storage, aggregation, and real-time visualization.</p>\n<h2 id=\"why-build-it\"></h2>\n<p>Market data is the perfect test case for real-time analytics. It's fast, continuous, and always changing. Traditional systems often fall behind when asked to process millions of tiny updates per second.</p>\n<p>ClickHouse was designed for that kind of load: fast ingestion, low-latency queries, and efficient compression for time-series data.</p>\n<p>StockHouse shows this in action:</p>\n<ul>\n<li><strong>Streaming ingestion</strong> from Massive's real-time stock and crypto feeds</li>\n<li><strong>Efficient time-series schema</strong> optimized for inserts and queries</li>\n<li><strong>Low-latency analytics</strong> with ClickHouse materialized views</li>\n<li><strong>Interactive visualizations</strong> that update as fast as the data arrives</li>\n</ul>\n<p>The system is simple enough to run locally but powerful enough to handle millions of events per second, which is a solid starting point for anyone building trading dashboards, analytics tools, or observability systems.</p>\n<h2 id=\"architecture-overview\"></h2>\n<p>StockHouse consists of five components that form a straightforward streaming pipeline:</p>\n<ol>\n<li><strong>Data Source</strong> -- Massive WebSocket APIs stream live stock and crypto market data.</li>\n<li><strong>Ingester</strong> -- A Go service that consumes the stream and writes to ClickHouse.</li>\n<li><strong>Database</strong> -- ClickHouse tables and materialized views optimized for real-time analytics.</li>\n<li><strong>Backend</strong> -- A Node.js API that connects the frontend to ClickHouse efficiently.</li>\n<li><strong>Frontend</strong> -- A Vue.js dashboard powered by Perspective for high-performance charts.</li>\n</ol>\n<p><span><img alt=\"stockhouse-diagram.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fstockhouse_diagram_e38424f51f.jpg&w=2048&q=75\"></span></p>\n<p>Let's look at some of the key technical decisions behind this setup.</p>\n<h2 id=\"ingester-in-go\"></h2>\n<p>The ingestion layer is written in Go to handle high event rates while keeping CPU and memory usage low. Go's concurrency model (goroutines and channels) allows the ingester to process multiple WebSocket streams in parallel without blocking.</p>\n<p>It uses ClickHouse's Native interface, which sends data in the database's binary columnar format. This reduces parsing overhead and achieves the highest throughput for inserts, confirmed in the <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-input-format-matchup-which-is-fastest-most-efficient#support-matrix\">ClickHouse input format benchmark</a>. Recently, Netflix <a target=\"_blank\" href=\"https://clickhouse.com/blog/netflix-petabyte-scale-logging#optimization-2-hub---serialization\">came to the same conclusion</a> while building its ingestion pipeline.</p>\n<p>In practice, this lets the ingester push millions of rows per second into ClickHouse while maintaining low latency and predictable resource usage.</p>\n<p>Each record (trade, quote, or crypto tick) is batched before insertion, balancing throughput and freshness. The result is a streaming pipeline that can sustain a constant firehose of updates without falling behind.</p>\n<h2 id=\"real-time-visualization-with-perspective\"></h2>\n<p>On the frontend, StockHouse uses <a target=\"_blank\" href=\"https://perspective.finos.org/\">Perspective</a>, an open-source visualization library originally developed at J.P. Morgan and open source through the FINOS community. It's designed for large, continuously updating datasets like financial ticks. This isn't our <a target=\"_blank\" href=\"https://clickhouse.com/blog/streaming-real-time-visualizations-clickhouse-apache-arrow-perpsective\">first time</a> featuring Perspective, it's no surprise we're drawn to tools built for performance.</p>\n<p>Perspective's core engine is written in C++ and compiled to WebAssembly, so most computations (aggregations, pivots, filtering) happen off the main thread. This keeps the UI responsive even when thousands of updates arrive each second.</p>\n<p>A key advantage is its native support for <a target=\"_blank\" href=\"https://perspective-dev.github.io/guide/explanation/table/loading_data.html?highlight=arrow#apache-arrow\">Apache Arrow</a>, a high-performance columnar format for in-memory data exchange.</p>\n<p>ClickHouse also supports <a target=\"_blank\" href=\"https://clickhouse.com/docs/interfaces/formats/Arrow\">Arrow as an output format</a>, which means query results can be streamed directly from ClickHouse to the browser in a binary, zero-copy format. This avoids JSON parsing overhead and makes transferring data between the database and the visualization layer extremely efficient.</p>\n<p>In practice, this allows the StockHouse dashboard to pull live data from ClickHouse, feed it straight into Perspective, and render updates immediately, all while keeping latency and CPU load low. The result is a smooth, interactive dashboard that stays in sync with the market in real time.</p>\n<h2 id=\"pool-connection-with-node-js\"></h2>\n<p>Between the frontend and ClickHouse sits a lightweight Node.js backend. This layer is small but crucial for performance.</p>\n<p>By managing a persistent connection pool to ClickHouse, the backend avoids the overhead of opening new database sessions for every query. It can reuse prepared contexts and execute requests with minimal latency.</p>\n<p>In a real-time dashboard, where queries run frequently and continuously, these savings add up as even a few milliseconds per query can make the difference between smooth streaming and lag.</p>\n<h2 id=\"pre-aggregation-with-materialized-views\"></h2>\n<p>ClickHouse can aggregate raw data quickly, but for live dashboards, every millisecond counts.&#160;</p>\n<p>To minimize query time, StockHouse uses materialized views to pre-aggregate data as it's ingested.</p>\n<p><span><img alt=\"blog-stockhouse.gif\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fblog_stockhouse_fbbce14048.gif&w=2048&q=75\"></span></p>\n<p>For example, the crypto live table keeps updating its content by querying ClickHouse for the latest daily price information for each crypto pair.</p>\n<p>To optimize query performance, it is a good idea to pre-aggregate the data at insert time therefore reducing the query operation complexity. See below the Materialized view SQL statement that aggregates the data at insert time.</p>\n<div><pre><code><span><span>-- Create table to store daily crypto price information</span></span>\n<span><span>CREATE TABLE</span> agg_crypto_trades_daily</span>\n<span>(</span>\n<span>    `event_date` <span>Date</span>,</span>\n<span>    `pair`    `volume_state` AggregateFunction(sum, Float64),</span>\n<span>    `latest_t_state` AggregateFunction(max, UInt64)</span>\n<span>)</span>\n<span><span>PARTITION</span> <span>BY</span> Float64, UInt64),</span>\n<span>    `volume_state` AggregateFunction(sum, Float64),</span>\n<span>    `latest_t_state` AggregateFunction(max, UInt64)</span>\n<span>)</span>\n<span><span>AS</span> <span>SELECT</span></span>\n<span>    toDate(fromUnixTimestamp64Milli(t, <span>'UTC'</span>)) <span>AS</span> event_date,</span>\n<span>    pair,</span>\n<span>    argMinState(p, t) <span>AS</span> to query the data, the SQL statement is very simple and can be executed in a few milliseconds.</p>\n<div><pre><code><span><span>WITH</span> toDate(now(<span>'UTC'</span>)) <span>AS</span> curr_day</span>\n<span>    <span>SELECT</span></span>\n<span>        t.pair <span>AS</span> pair,</span>\n<span>        argMaxMerge(t.last_price_state) <span>AS</span> <span>last</span>,</span>\n<span>        argMinMerge(t.open_price_state) <span>AS</span> <span>open</span>,</span>\n<span>        argMaxMerge(q.bid_state)        <span>AS</span> bid,</span>\n<span> a standard way to balance flexibility and speed in ClickHouse. The raw data remains available for historical or analytical queries, while the pre-aggregated tables keep the live UI fast.</p>\n<h2 id=\"putting-it-all-together\"></h2>\n<p>Here's how it flows:</p>\n<ol>\n<li>Massive streams live market data over WebSocket.</li>\n<li>The Go ingester parses and inserts events into ClickHouse via the native interface.</li>\n<li>Materialized views aggregate data in real time.<br>\nThe Node.js backend serves fast queries through pooled connections.</li>\n<li>The Vue + Perspective frontend visualizes updates within milliseconds.</li>\n</ol>\n<p>The result is a responsive dashboard that stays current with live market activity.</p>\n<h2 id=\"try-it-yourself\"></h2>\n<p>You can explore the running demo at <a target=\"_blank\" href=\"https://stockhouse.clickhouse.com/\">stockhouse.clickhouse.com</a> or deploy it locally using the setup instructions in the <a target=\"_blank\" href=\"https://github.com/ClickHouse/stockhouse\">GitHub repository</a>.</p>\n<p>All you need is Node.js, Docker, and a Massive API key to start streaming live data into your own ClickHouse instance. Massive has a free tier for basic use and paid plans that include unlimited API calls and full real-time data access.</p>\n<p>StockHouse raw data is also available on our <a target=\"_blank\" href=\"https://sql.clickhouse.com/?query_id=VTSFBTGQ8C51F15Z1HCZBK\">SQL playground</a> if you want to explore it using SQL.</p>\n<h2 id=\"final-thoughts\"></h2>\n<p>StockHouse isn't just a demo; it's a reference architecture for anyone building real-time analytics systems.</p>\n<p>By combining a streaming data source (Massive), a fast analytical database (ClickHouse), and a high-performance visualization layer (Perspective), you can handle massive event streams and deliver insights instantly.</p>\n<p>Whether you're tracking financial markets, monitoring infrastructure metrics, or analyzing sensor data, the same principles apply: ingest fast, store efficiently, and query faster.</p></div></article>"
