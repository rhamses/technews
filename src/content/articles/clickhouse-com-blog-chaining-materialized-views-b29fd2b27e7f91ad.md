They will operate on those rows, possibly transforming the data before writing to a destination table.\nThe diagram below gives a high-level view of how this works:</p>\n<p><span><img alt=\"mv-chain-1.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fmv_chain_1_38edba9eb7.png&w=2048&q=75\"></span></p>\n<p>Over the last couple of weeks, I’ve been learning about <a target=\"_blank\" href=\"https://clickhouse.com/blog/aggregate-functions-combinators-in-clickhouse-for-arrays-maps-and-states\">aggregation states</a>. I created a small demo with two materialized views reading from the same Kafka table engine. One stored raw event data and the other stored aggregation states.</p>\n<p>When I showed the example to <a target=\"_blank\" href=\"https://www.linkedin.com/in/schreibertom1/\">Tom</a>, he suggested that rather than have both materialized views read from the Kafka engine table, I could instead chain the materialized views together. We aren’t interested in the individual changes but rather want to track, on a minute-by-minute basis, the unique number of users making changes, the unique number of pages being changed, and the total changes made.</p>\n<p>We’ll start by creating and then using the <code>wiki</code> database:</p>\n<div><pre><code><span><span>CREATE</span> DATABASE wiki;</span></code></pre></div>\n<div><pre><code><span>USE wiki;</span></code></pre></div>\n<h2 id=\"create-kafka-table-engine\"></h2>\n<p>Next, let’s create a table called <code>wikiQueue</code> that will consume messages from Kafka. The broker is running locally on port 9092, and our topic is called <code>wiki_events</code>.</p>\n<blockquote>\n<p>Note that if you're using ClickHouse Cloud, you'll instead need to use <a target=\"_blank\" href=\"https://clickhouse.com/cloud/clickpipes\">ClickPipes</a> to handle ingestion of data from Kafka.</p>\n</blockquote>\n<div><pre><code><span><span>CREATE TABLE</span> wikiQueue(</span>\n<span>    id UInt32,</span>\n<span>    type String,</span>\n<span>    title String,</span>\n<span>    title_url String,</span>\n<span>    comment String,</span>\n<span>    <span>timestamp</span> UInt64,</span>\n<span>    <span>user</span> String,</span>\n<span>    bot <span>Boolean</span>,</span>\n<span>    server_url String,</span>\n<span>    server_name <span>'JSONEachRow'</span></span>\n<span>);</span></code></pre></div>\n<p>The <code>rawEvents</code> table stores the <code>dateTime</code>, <code>title_url</code>, <code>topic</code>, and <code>user</code>.</p>\n<div><pre><code><span><span>CREATE TABLE</span> rawEvents (</span>\n<span>    dateTime DateTime64(<span>3</span>, <span>'UTC'</span>),</span>\n<span>    title_url String,</span>\n<span>    topic String,</span>\n<span>    <span>user</span> String</span>\n<span>) </span>\n<span>ENGINE <span>=</span> MergeTree </span>\n<span><span>ORDER</span> <span>BY</span> <span>VIEW</span> rawEvents_mv <span>TO</span> rawEvents <span>AS</span> </span>\n<span><span>SELECT</span> toDateTime(<span>timestamp</span>) <span>AS</span> dateTime,</span>\n<span>       title_url, </span>\n<span>       tupleElement(meta, <span>'topic'</span>) <span>AS</span> topic, </span>\n<span>       <span>user</span></span>\n<span><span>FROM</span> wikiQueue</span>\n<span><span>WHERE</span> To keep a running total, which we need for total updates, we would use the <code>AggregateFunction(sum, UInt32</code>) type. The <code>UInt32</code> type gives us a maximum value of <code>4294967295</code>, which is way more than the number of updates we’ll receive in one minute.</p>\n<p>We’ll call this table <code>byMinute</code> and its definition is below:</p>\n<div><pre><code><span><span>CREATE TABLE</span> byMinute</span>\n<span>(</span>\n<span>    dateTime DateTime64(<span>3</span>, <span>'UTC'</span>) <span>NOT NULL</span>,</span>\n<span>    users AggregateFunction(uniq, String),</span>\n<span>    pages AggregateFunction(uniq, String),</span>\n<span>    updates AggregateFunction(sum, UInt32) </span>\n<span>)</span>\n<span>ENGINE <span>=</span> AggregatingMergeTree() </span>\n<span><span>ORDER</span> <span>BY</span> dateTime;</span></code></pre></div>\n<p>The materialized view that populates this table will read from <code>rawEvents</code> and use <code>-State</code> combinators to extract the intermediate state. We’ll use the <code>uniqState</code> function for users and pages and <code>sumState</code> for updates.</p>\n<div><pre><code><span><span>CREATE</span> MATERIALIZED <span>VIEW</span> byMinute_mv <span>TO</span> byMinute <span>AS</span> </span>\n<span><span>SELECT</span> toStartOfMinute(dateTime) <span>AS</span> dateTime,</span>\n<span>       uniqState(<span>user</span>) <span>as</span> users,</span>\n<span>       uniqState(title_url) <span>as</span> pages,</span>\n<span>       sumState(toUInt32(<span>1</span>)) <span>AS</span> updates</span>\n<span><span>FROM</span> rawEvents</span>\n<span><span>GROUP</span> <span>BY</span> dateTime;</span></code></pre></div>\n<p>The diagram below shows the chain of materialized views and tables that we’ve created so far:</p>\n<p><span><img alt=\"mv-chain-3.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fmv_chain_3_9e1060bbc4.png&w=2048&q=75\"></span></p>\n<p>We don’t have any data flowing into Kafka, so this table won’t have any data. Let’s fix that by running the following commands.</p>\n<div><pre><code><span>curl -N https://stream.wikimedia.org/v2/stream/recentchange  |</span>\n<span>awk <span>'/^data: /{gsub(/^data: /, \"\"); Let’s create that table:</p>\n<div><pre><code><span><span>CREATE TABLE</span> byTenMinutes</span>\n<span>(</span>\n<span>    dateTime DateTime64(<span>3</span>, <span>'UTC'</span>) <span>NOT NULL</span>,</span>\n<span>    users AggregateFunction(uniq, String),</span>\n<span>    pages AggregateFunction(uniq, String),</span>\n<span>    updates AggregateFunction(sum, UInt32) </span>\n<span>)</span>\n<span>ENGINE <span>=</span> AggregatingMergeTree() </span>\n<span><span>ORDER</span> <span>BY</span> dateTime;</span></code></pre></div>\n<p>Next, let’s create a materialized view to populate that table. <span>AS</span> updates</span>\n<span><span>FROM</span> byMinute</span>\n<span><span>GROUP</span> <span>BY</span> dateTime;</span></code></pre></div>\n<p>We can then write the following query against
