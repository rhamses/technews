If not, you can try it today. This latest release includes 2,140 new commits from 118 contributors, including 41 new contributors:</p>\n<p>Aaron Katz, Andre Marianiello, Andrew, Andrii Buriachevskyi, Brian Hunter, CoolT2, Federico Rodriguez, Filippov Denis, Gaurav Kumar, Geoff Genz, HarryLeeIBM, Heena Bansal, ILya Limarenko, Igor Nikonov, IlyaTsoi, Jake Liu, JaySon-Huang, Lemore, Leonid Krylov, Michail Safronov, Mikhail Fursov, Nikita, RogerYK, Roy Bellingan, Saad Ur Rahman, W, Yakov Olkhovskiy, alexeypavlenko, cnmade, grantovsky, hanqf-git, liuneng1994, mlkui, s-kat, tesw yew isal, vahid-sohrabloo, yakov-olkhovskiy, zhifeng, zkun, zxealous, 박동철.</p>\n<p>Let me tell you what is most interesting in 22.2…</p>\n<h2 id=\"projections-are-production-ready\"></h2>\n<p>Projections allow you to have multiple data representations in the same table. For example, you can have data aggregations along with the raw data. There are no restrictions on which aggregate functions can be used – you can have count distinct, quantiles, or whatever you want. You can have data in multiple different sorting orders. ClickHouse will automatically select the most suitable projection for your query, so the query will be automatically optimized.</p>\n<p>Projections are somewhat similar to Materialized Views, which also allow you to have incremental aggregation and multiple sorting orders. But unlike Materialized Views, projections are updated atomically and consistently with the main table. The data for projections is being stored in the same “data parts” of the table and is being merged in the same way as the main data.</p>\n<p>The feature was developed by <strong>Amos Bird</strong>, a prominent ClickHouse contributor. The <a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/20202\">prototype</a> has been available since Feb 2021, it has been merged in the main codebase by <strong>Nikolai Kochetov</strong> in May 2021 under experimental flag, and after 21 follow-up pull requests we ensured that it passed the full set of test suites and enabled it by default.</p>\n<p>Read an example of how to optimize queries with projections <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/uk-price-paid/#speedup-with-projections\">in our docs</a>.</p>\n<h2 id=\"control-of-file-creation-and-rewriting-on-data-export\"></h2>\n<p>When you export your data with an <code>INSERT INTO TABLE FUNCTION</code> statement into <code>file</code>, <code>s3</code> or <code>hdfs</code> and the target file already exists, you can now control how to deal with it: you can append new data into the file if it is possible, rewrite it with new data, or create another file with a similar name like ‘data.1.parquet.gz’.</p>\n<p>Some storage systems like <code>s3</code> and some formats like <code>Parquet</code> don’t support data appending. In previous ClickHouse versions, if you insert multiple times into a file with Parquet data format, you will end up with a file that is not recognized by other systems. Now you can choose between throwing exceptions on subsequent inserts or creating more files.</p>\n<p>So, new settings were introduced:</p>\n<div><pre><code><span>s3_truncate_on_insert</span>\n<span>s3_create_new_file_on_insert</span>\n<span>hdfs_truncate_on_insert</span>\n<span>hdfs_create_new_file_on_insert</span>\n<span>engine_file_allow_create_multiple_files</span></code></pre></div>\n<p>This feature <a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/33302\">was developed</a> by <strong>Pavel Kruglov</strong>.</p>\n<h2 id=\"custom-deduplication-token\"></h2>\n<p><code>ReplicatedMergeTree</code> and <code>MergeTree</code> types of tables implement block-level deduplication. When a block of data is inserted, its cryptographic hash is calculated and if the same block was already inserted before, then the duplicate is skipped and the insert query succeeds. This makes it possible to implement exactly-once semantics for inserts.</p>\n<p>In ClickHouse version 22.2 you can provide your own deduplication token instead of an automatically calculated hash. This makes sense if you already have batch identifiers from some other system and you want to reuse them. It also makes sense when blocks can be identical but they should actually be inserted multiple times. Or the opposite – when blocks contain some random data and you want to deduplicate only by significant columns.</p>\n<p>This is implemented by adding the setting <code>insert_deduplication_token</code>. The feature was contributed by <strong>Igor Nikonov</strong>.</p>\n<h2 id=\"default-keyword-for-insert\"></h2>\n<p>A small addition for SQL compatibility – now we allow using the <code>DEFAULT</code> keyword instead of a value in <code>INSERT INTO ... VALUES</code> statement. It looks like this:</p>\n<div><pre><code><span>INSERT INTO test VALUES (1, 'Hello', DEFAULT)</span></code></pre></div>\n<p>Thanks to <strong>Andrii Buriachevskyi</strong> for this feature.</p>\n<h2 id=\"ephemeral-columns\"></h2>\n<p>A column in a table can have a <code>DEFAULT</code> expression like <code>c INT DEFAULT a + b</code>. In ClickHouse you can also use <code>MATERIALIZED</code> instead of <code>DEFAULT</code> if you want the column to be always calculated with the provided expression instead of allowing a user to insert data. And you can use <code>ALIAS</code> if you don’t want the column to be stored at all but instead to be calculated on the fly if referenced.</p>\n<p>Since version 22.2 a new type of column is added: <code>EPHEMERAL</code> column. The user can insert data into this column but the column is not stored in a table, it’s ephemeral. The purpose of this column is to provide data to calculate other columns that can reference it with <code>DEFAULT</code> or <code>MATERIALIZED</code> expressions.</p>\n<p>This feature was made by <strong>Yakov Olkhovskiy</strong>.</p>\n<h2 id=\"improvements-for-multi-disk-configuration\"></h2>\n<p>You can configure multiple disks to store ClickHouse data instead of managing RAID and ClickHouse will automatically manage the data placement.</p>\n<p>Since version 22.2 ClickHouse can automatically repair broken disks without server restart by downloading the missing parts from replicas and placing them on the healthy disks.</p>\n<p>This feature was implemented by <strong>Amos Bird</strong> and is already being used for more than 1.5 years in production at Kuaishou.</p>\n<p>Another improvement is the option to specify TTL MOVE TO DISK/VOLUME <strong>IF EXISTS</strong>. It allows replicas with non-uniform disk configuration and to have one replica to move old data to cold storage while another replica has all the data on hot storage. Data will be moved only on replicas that have the specified disk or volume, hence <em>if exists</em>. This was developed by <strong>Anton Popov</strong>.</p>\n<h2 id=\"flexible-memory-limits\"></h2>\n<p>We split per-query and per-user memory limits into a pair of hard and soft limits. The settings <code>max_memory_usage</code> and <code>max_memory_usage_for_user</code> act as hard limits. When memory consumption is approaching the hard limit, an exception will be thrown. Two other settings: <code>max_guaranteed_memory_usage</code> and <code>max_guaranteed_memory_usage_for_user</code> act as soft limits.</p>\n<p>A query will be allowed to use more memory than a soft limit if there is available memory. But if there will be memory shortage (relative to the per-user hard limit or total per-server memory consumption), we calculate the “overcommit ratio” – how much more memory every query is consuming relative to the soft limit – and we will kill the most overcommitted query to let other queries run.</p>\n<p>In short, your query will not be limited to a few gigabytes of RAM if you have hundreds of gigabytes available.</p>\n<p>This experimental feature was implemented by <strong>Dmitry Novik</strong> and is continuing to be developed.</p>\n<p>Now we allow comments starting with <code># </code> or <code>#!</code>, similar to MySQL. The variant with <code>#!</code> allows using shell scripts with “shebang” interpreted by <code>clickhouse-local</code>.</p>\n<p>This feature was contributed by <strong>Aaron Katz</strong>. Very nice.</p>\n<h2 id=\"and-many-more\"></h2>\n<p>Maxim Kita, Danila Kutenin, Anton Popov, zhanglistar, Federico Rodriguez, Raúl Marín, Amos Bird and Alexey Milovidov have contributed a ton of performance optimizations for this release.
