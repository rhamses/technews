contentHtml: "<article><div><div><h2 id=\"introduction\"></h2>\n<p>Every December, the programming community gathers for a collective ritual: <a target=\"_blank\" href=\"https://adventofcode.com/\">Advent of Code</a>. Created by Eric Wastl, it is an Advent calendar of small programming puzzles that releases a new challenge every day from December 1st through the 12th.</p>\n<p>These aren't your typical \"fix the bug\" or \"build an API\" tasks. They are algorithmic challenges that require complex data structures, graph traversal, 3D geometry, cellular automata simulations, and pathfinding algorithms. Naturally, developers usually reach for general-purpose languages like Python, Rust, Go, or C++ to solve them.</p>\n<h3 id=\"why-not-sql\"></h3>\n<p>Asking a database to solve these problems is generally considered a mistake. Standard SQL is a declarative language designed for retrieving and aggregating relational data, not for imperative game loops or complex state management. It lacks native support for the data structures usually required for these puzzles (like stacks, queues, or trees), and attempting to solve them with standard JOINs usually leads to performance disasters or syntax errors. In short, solving Advent of Code in SQL is widely considered \"impossible\" - or at least, incredibly painful.</p>\n<h3 id=\"the-clickhouse-approach\"></h3>\n<p>At ClickHouse, we don't like the word \"impossible.\" We believe that with the right tools, <strong>everything</strong> is a data problem. ClickHouse isn't just a fast OLAP database; it is a vectorized query engine with a massive library of analytical functions that can be  bent to solve general-purpose computing problems.</p>\n<p>To prove it, we decided to complete the 2025 Advent of Code unconventionally: using <strong>pure ClickHouse SQL</strong>.</p>\n<h3 id=\"the-rules\"></h3>\n<p>To ensure we didn't take any shortcuts, we imposed three strict rules on our solutions:</p>\n<ol>\n<li>\n<p><strong>Pure ClickHouse SQL only</strong>: we allowed absolutely no User Defined Functions (UDFs), and specifically no <em>executable</em> UDFs that would allow us to \"cheat\" by shelling out to Python or Bash. If the query engine couldn't do it natively, we couldn't do it.</p>\n</li>\n<li>\n<p><strong>Raw inputs only</strong>: in Advent of Code, the input is often a messy text file.  Sometimes a list of numbers, sometimes an ASCII art map, or a block of cryptic instructions. We were not allowed to pre-process this data. The solution query must accept the raw puzzle input string exactly as provided by the AoC challenge and parse it within the query.</p>\n</li>\n<li>\n<p><strong>\"Single query\" constraint</strong>: this is the hardest rule of all. We were not allowed to create tables, materialized views, or temporary tables to store intermediate state. The entire puzzle—from parsing the input, to solving Part 1, to solving the (often substantially more complex) Part 2—must be executed as a <strong>single, atomic query</strong>. This required us to rely heavily on CTEs to chain our logic together in one uninterrupted execution.</p>\n</li>\n</ol>\n<p>Below are the solutions for all 12 days of Advent of Code 2025, demonstrating how we turned \"impossible\" algorithmic challenges into pure ClickHouse SQL queries.</p>\n<blockquote>\n<p>Note: in order to comply with Advent of Code's distribution policy, the queries below use a wrapper <code>URL()</code> table to fetch the raw puzzle inputs without exposing them.
