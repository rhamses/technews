If you are looking for Docker compose files for multi-server deployments or guides to go beyond the quick start and, for example, to separate compute and storage or replicate data across two data centers for fault tolerance, continue reading.</p>\n<h2 id=\"terminology\"></h2>\n<p>The terminology details are in the documentation, but here is the short form:</p>\n<p><strong>Replica</strong>: A replica is a copy of your data. You always have at least one. When you create a table, the initial instance of that table data is the first replica. To survive the loss of a server, a network outage, or other problems, you might want a second replica on a second server.</p>\n<p><strong>Shard</strong>: A shard is a portion of your table data. You also always have at least one shard. We recommend having only one shard until your server is not keeping up with the query load and you cannot scale vertically.</p>\n<p><strong>1S_2R</strong>: If you look at the diagram at the top of this post, you will see that the cluster is named <strong>cluster_1S_2R</strong>. This means that the cluster has one shard and two replicas. <strong>1S_2R</strong> is a common shorthand used within the ClickHouse community.</p>\n<h3 id=\"deployment-considerations\"></h3>\n<p>If you are setting up a ClickHouse server to import data for analysis, but the authoritative record is an OLTP database or a set of data files, then you probably only need one shard and one replica (so a single ClickHouse server).</p>\n<p>If your data only lives in ClickHouse, and the data can not be recreated or regenerated, then you probably need one shard and two replicas (so two ClickHouse Servers).</p>\n<p>The common question is, “How many shards do I need?”.  Our answer is, “One until you exceed the capacity of the current hardware and cannot scale your hardware vertically.”</p>\n<h2 id=\"details\"></h2>\n<p>The documentation for a single shard with two replicas and for two shards with one replica is at <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/architecture/introduction\">https://clickhouse.com/docs/en/architecture/introduction</a></p>\n<p>To separate storage and compute, see <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/integrations/s3#s3-multi-region\">using S3 object storage</a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/integrations/gcs#gcs-multi-region\">the same using GCS</a>.</p>\n<p>More examples are in the <a target=\"_blank\" href=\"https://github.com/ClickHouse/examples/blob/main/docker-compose-recipes/README.md\">ClickHouse/examples</a> GitHub repo with all of the configuration and Docker compose files.
