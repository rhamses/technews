Need a specific statistic, or are you curious about the queries being executed by your users and those that are failing? Or maybe you need to identify the currently applied settings. Look no further than system tables! In this post, we explore the system tables in ClickHouse and show how we in ClickHouse support use them to debug issues and understand your cluster usage with practical examples.</p>\n<h2 id=\"introduction-to-system-tables\"></h2>\n<p>System tables in ClickHouse are virtual tables that provide information about server states, processes, and the operating environment. These system tables are located in the system database and are only available for reading by the users. They cannot be dropped or altered, but their partition can be detached and old records can be removed using TTL. System tables offer great insight into the internal operations of ClickHouse and can be a valuable source of information when optimizing queries, monitoring system performance, or troubleshooting a system crash.</p>\n<p>In general, there are a few types of system tables in ClickHouse, and some useful ones contain system information related to your <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/databases\"><code>database</code></a>, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/tables\"><code>tables</code></a>, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/columns\"><code>columns</code></a>, and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/parts\"><code>parts</code></a>. There are also tables showing real-time information such as <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/metrics\"><code>metrics</code></a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/events\"><code>events</code></a>, providing a snapshot view of the current system events. Users may also find historical records in system log tables such as <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/metric_log\"><code>metric_log</code></a>, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/query_log\"><code>query_log</code></a>, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/part_log\"><code>part_log</code></a>, etc. In a cluster, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/distribution_queue\"><code>distribution_queue</code></a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/replication_queue\"><code>replication_queue</code></a> can be used to troubleshoot a distributed setup. Tables related to <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/settings\">settings</a>, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/users\">users</a>, and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/system-tables/roles\">roles</a> also provide information on the current configuration and user privileges.</p>\n<p>Most system tables store their data in memory, but system log tables such as <code>metric_log</code>, <code>query_log</code> and <code>part_log</code> use the MergeTree table engine and store their data in the filesystem by default. This persistent storage ensures that logs are still available for analysis after a server restart.</p>\n<h2 id=\"where-are-the-system-tables\"></h2>\n<p>The complete list of system tables is accessible via the <code>SHOW TABLES FROM system</code> statement.
