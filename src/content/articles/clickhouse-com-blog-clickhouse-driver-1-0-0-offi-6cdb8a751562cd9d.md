This has been a ground-up effort: new API design, full type coverage, package signing, and OpenTelemetry integration, all built on top of the community project we adopted last year. Starting with 1.0.0, the public API is stable. The package follows semver, and we won't break your code between minor versions.</p>\n<p>This release also comes bundled with a big <a target=\"_blank\" href=\"https://clickhouse.com/docs/integrations/csharp\">documentation</a> upgrade and 40+ <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cs/tree/main/examples\">practical usage examples</a>.</p>\n<h2 id=\"user-content-road_to_100\"></h2>\n<p>The 1.0.0 release builds on two major pre-releases:</p>\n<p><strong>0.8.0</strong> focused on packaging, configuration, and observability:</p>\n<ul>\n<li>Added support for .NET 10</li>\n<li>NuGet package signing and strong naming</li>\n<li><code>ClickHouseClientSettings</code> for structured configuration</li>\n<li>Logging and diagnostics support via <code>ILoggerFactory</code></li>\n<li><code>EnableDebugMode</code> for low-level network tracing</li>\n<li>Improved OpenTelemetry/ActivitySource integration</li>\n</ul>\n<p><strong>0.9.0</strong> focused on type support:</p>\n<ul>\n<li>Added support for BFloat16, Time/Time64, Geometry types (LineString, MultiLineString, Polygon)</li>\n<li>Reading Dynamic now supports all underlying types</li>\n<li>Improved JSON and FixedString support</li>\n</ul>\n<h2 id=\"user-content-the_new_clickhouseclient_api\"></h2>\n<p>1.0.0 introduces <code>ClickHouseClient</code>, a new primary API that replaces the <a target=\"_blank\" href=\"http://ado.net/\">ADO.NET</a> classes for most use cases. It's thread-safe, singleton-friendly, and a lot less ceremony than <code>ClickHouseConnection</code>.</p>\n<div><pre><code><span><span>using</span> <span>var</span> client = <span>new</span> ClickHouseClient(<span>\"Host=localhost\"</span>);</span>\n<span></span>\n<span><span>// DDL</span></span>\n<span><span>await</span> client.ExecuteNonQueryAsync(<span>\"CREATE TABLE logs (ts DateTime, msg String) ENGINE = MergeTree ORDER BY ts\"</span>);</span>\n<span></span>\n<span><span>// Binary bulk insert (replaces ClickHouseBulkCopy)</span></span>\n<span><span>await</span> client.InsertBinaryAsync(<span>\"logs\"</span>, [<span>\"ts\"</span>, <span>\"msg\"</span>], rows); <span>// rows: IEnumerable&lt;object[]&gt;</span></span>\n<span></span>\n<span><span>// Query</span></span>\n<span><span>var</span> parameters = <span>new</span> ClickHouseParameterCollection();</span>\n<span>parameters.AddParameter(<span>\"since\"</span>, DateTime.UtcNow.AddDays(<span>-7</span>));</span>\n<span><span>using</span> <span>var</span> reader = <span>await</span> client.ExecuteReaderAsync(<span>\"SELECT * FROM logs WHERE ts &gt; {since:DateTime}\"</span>, parameters);</span>\n<span></span>\n<span><span>// Scalar</span></span>\n<span><span>var</span> count = <span>await</span> client.ExecuteScalarAsync(<span>\"SELECT count() FROM logs\"</span>);</span></code></pre></div>\n<p><strong>Key methods:</strong></p>\n<div><table><thead><tr><th>Method</th><th>What it does</th></tr></thead><tbody><tr><td><code>ExecuteNonQueryAsync</code></td><td>DDL/DML (CREATE, INSERT, ALTER, DROP)</td></tr><tr><td><code>ExecuteScalarAsync</code></td><td>Returns a single result</td></tr><tr><td><code>ExecuteReaderAsync</code></td><td>Stream results via <code>ClickHouseDataReader</code></td></tr><tr><td><code>InsertBinaryAsync</code></td><td>High-performance bulk insert</td></tr><tr><td><code>ExecuteRawResultAsync</code></td><td>Raw result stream in arbitrary format (e.g. save Parquet directly to a file)</td></tr><tr><td><code>InsertRawStreamAsync</code></td><td>Insert from stream (CSV, JSON, Parquet, etc.)</td></tr><tr><td><code>PingAsync</code></td><td>Check server connectivity</td></tr><tr><td><code>CreateConnection()</code></td><td>Get a <code>ClickHouseConnection</code> for ORM compatibility</td></tr></tbody></table></div>\n<p>Per-query settings (query ID, custom server settings, roles, bearer token) are passed via the new <code>QueryOptions</code> and <code>InsertOptions</code> classes. The <a target=\"_blank\" href=\"http://ado.net/\">ADO.NET</a> layer (<code>ClickHouseConnection</code> / <code>ClickHouseCommand</code>) remains fully supported for ORM integration with Dapper and linq2db.</p>\n<p><strong>Note:</strong> <code>ClickHouseBulkCopy</code> is now deprecated. Use <code>client.InsertBinaryAsync(table, columns, rows)</code> instead.</p>\n<h2 id=\"user-content-what_else_is_new_in_100\"></h2>\n<h3 id=\"user-content-automatic_parameter_type_extraction_from_sql\"></h3>\n<p>No more specifying the type twice. The driver now extracts parameter types directly from your SQL:</p>\n<div><pre><code><span><span>// Before: type specified in both the SQL and the parameter</span></span>\n<span>command.CommandText = <span>\"SELECT {dt:DateTime('Europe/Amsterdam')}\"</span>;</span>\n<span>command.AddParameter(<span>\"dt\"</span>, <span>\"DateTime('Europe/Amsterdam')\"</span>, <span>value</span>);</span>\n<span></span>\n<span><span>// After: type extracted from SQL automatically</span></span>\n<span>command.CommandText = <span>\"SELECT {dt:DateTime('Europe/Amsterdam')}\"</span>;</span>\n<span>command.AddParameter(<span>\"dt\"</span>, <span>value</span>);</span></code></pre></div>\n<h3 id=\"user-content-jwt_authentication_roles_custom_http_headers\"></h3>\n<p>JWT authentication, ClickHouse roles, and custom HTTP headers are now supported at the client level, with per-query overrides via <code>QueryOptions</code>. Check out the examples on GitHub: <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cs/blob/main/examples/Core/Auth_001_JwtAuthentication.cs\">JWT example</a>, <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cs/blob/main/examples/Advanced/Advanced_006_Roles.cs\">roles example</a>, and <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cs/blob/main/examples/Advanced/Advanced_007_CustomHeaders.cs\">custom headers example</a>.</p>\n<h3 id=\"user-content-poco_serialization_for_json_columns\"></h3>\n<p>Write plain C# objects directly to typed JSON columns. Properties are serialized using the column's type hints, with automatic inference for unhinted properties:</p>\n<div><pre><code><span>client.RegisterJsonSerializationType&lt;UserEvent&gt;();</span>\n<span></span>\n<span><span>await</span> client.InsertBinaryAsync(<span>\"events\"</span>, [<span>\"data\"</span>], rows);</span></code></pre></div>\n<p>Control serialization using attributes: use <code>[ClickHouseJsonPath(\"custom.path\")]</code> for custom paths and <code>[ClickHouseJsonIgnore]</code> to exclude properties. The driver now detects these and throws a proper <code>ClickHouseServerException</code> with the error message, instead of a generic <code>EndOfStreamException</code>.</p>\n<h3 id=\"user-content-qbit_vector_type\"></h3>\n<p>QBit stores vectors in a compact transposed binary format; quantization granularity is chosen at query time rather than at insert time, letting you trade precision for speed without re-ingesting data. See the <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cs/blob/main/examples/DataTypes/Vector_001_QBitSimilaritySearch.cs\">QBit similarity search example</a>.</p>\n<h3 id=\"user-content-query_id_auto_generation\"></h3>\n<p>Every query now gets a unique ID automatically when one isn't explicitly set, making it easier to trace queries in server logs.</p>\n<h3 id=\"user-content-additional_improvements\"></h3>\n<ul>\n<li><strong>Binary data in String/FixedString columns</strong> — write <code>byte[]</code>, <code>ReadOnlyMemory&lt;byte&gt;</code>, or <code>Stream</code>; read back with the <code>ReadStringsAsByteArrays</code> setting.</li>\n<li>Full support for Dynamic type binary writing.</li>\n<li><strong><code>AddParameter()</code> convenience method</strong> on <code>ClickHouseParameterCollection</code>.</li>\n</ul>\n<h2 id=\"user-content-breaking_changes\"></h2>\n<p>1.0.0 includes breaking changes to clean up the API surface. Here's a summary:</p>\n<p><strong>Dropped .NET Framework / .NET Standard.</strong> The library now targets <code>net6.0</code>, <code>net8.0</code>, <code>net9.0</code>, and <code>net10.0</code> only. If you're on .NET Framework, stay on the previous version or migrate to .NET 6.0+.</p>\n<p><strong>DateTime behavior changed for columns without explicit timezone.</strong> Columns like <code>DateTime</code> (without a timezone parameter) now return <code>DateTime</code> with <code>Kind=Unspecified</code>, preserving the stored wall-clock time exactly. Writing also changed: <code>DateTime.Kind</code> is now respected. <code>Utc</code> and <code>Local</code> values maintain their instant, while <code>Unspecified</code> values are treated as wall-clock time.</p>\n<p><em>Migration:</em> Use explicit timezones in column definitions (<code>DateTime('UTC')</code>) or apply timezones after reading.</p>\n<p><strong>Removed <code>UseServerTimezone</code>.</strong> No longer needed since timezone-less columns return <code>Unspecified</code> values. <code>ServerTimezone</code> moved from <code>ClickHouseConnection</code> to <code>ClickHouseCommand</code> (extracted from response headers).</p>\n<p><strong>JSON write mode default changed from Binary to String.</strong> JSON data is now serialized via <code>System.Text.Json</code> and parsed server-side. This removes the need for the client to parse JSON structure into binary column format before sending. The server handles parsing directly from the JSON string. Binary writing now only works with POCOs.</p>\n<p><em>Migration:</em> JSON string or JsonNode writing still works, but the JSON string will be parsed on the server instead of the client. This could lead to subtle changes in paths without type hints, e.g., values previously parsed as Int32 may be parsed as Int64.</p>\n<p><strong>Other changes:</strong></p>\n<ul>\n<li>Removed feature discovery query from <code>OpenAsync</code> (no more <code>SELECT version()</code> on connect)</li>\n<li>Several helper/extension methods made internal</li>\n<li>See the full <a target=\"_blank\"
