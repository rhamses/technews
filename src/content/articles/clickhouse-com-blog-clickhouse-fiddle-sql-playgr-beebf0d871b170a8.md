Igor is studying for a Bachelor's degree in Computer Science at the Higher School of Economics in Moscow and planning to graduate in 2023. He works as a Golang SWE with a special interest in service meshes and telemetry.</p>\n</blockquote>\n<h2 id=\"introduction\"></h2>\n<p>Sometimes we want to run SQL queries online to validate them, to share them with other people, or just because we are too lazy to install a database locally. Online SQL playgrounds can help us with this.</p>\n<p>A playground allows running SQL queries from a browser without having a database instance on the user's side. In this article, we will talk about a new open-source SQL playground created specifically for ClickHouse — <a target=\"_blank\" href=\"https://fiddle.clickhouse.com/\">ClickHouse Fiddle</a>. We will cover the motivation and internal architecture of the platform.</p>\n<h2 id=\"motivation\"></h2>\n<p>If you have never used online playgrounds, a reasonable question might come to mind: what are the use cases of such platforms?</p>\n<p>Imagine you need to execute a few queries and see the execution result. For example, you want to know what your favorite database thinks about the truthfulness of the expression <code>0.1 + 0.2 == 0.3</code>. If you already have a running database instance, you can connect to it and execute a simple query there. Done. But what if you don't have a running instance? Or maybe the version of the instance you have is not what you want...</p>\n<p>Well, then you need to download a binary of the desired version, run it with proper options, and finally execute <code>SELECT (0.1 + 0.2) == 0.3</code>... In the modern world of clouds, we can even press a button in a control panel and get a managed instance of the database within minutes (or even seconds).</p>\n<p>But we all can agree, that for execution of such contextless queries it's much simpler and faster to open a webpage, type queries there, wait for several seconds and see the execution result. That's what playgrounds offer! A fast and easily accessible way to execute SQL queries from your browser:</p>\n<p><span><img alt=\"clickhouse-fiddle.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fclickhouse_fiddle_3339a19d73.png&w=2048&q=75\"></span>\n<em>Now we know, <code>0.1 + 0.2 != 0.3</code>. Floats...</em></p>\n<p>In general, an online SQL playground helps in the following cases:</p>\n<ul>\n<li>A database maintainer wants to check whether a bug is reproducible in a particular database version.</li>\n<li>An engineer reads about a new great SQL construct and is interested in whether it's supported in the database version they use (or planning to use).</li>\n<li>Your friend asked you how to do something in SQL and you want to share a snippet of SQL code with the execution result.</li>\n<li>And so on...</li>\n</ul>\n<p>Well, now we see the benefits of playgrounds. But why do we need another playground if we already have several of them, even for ClickHouse? The short answer is the limitations of the existing platforms.</p>\n<p>Most SQL playgrounds are intended for the emulation of OLTP databases. A transaction is created to execute a bunch of queries. After the execution, the transaction is rollbacked to return to the initial database state. Another way to provide mechanics of an online playground is to allow only read-queries over the existing dataset (that's how <a target=\"_blank\" href=\"https://sql.clickhouse.com/\">ClickHouse Play</a> is implemented). With such an approach, sometimes it's difficult (or even impossible) to get the desired logic of SQL queries.</p>\n<p>Furthermore, both of these approaches imply the presence of an always-on database instance for each supported database version.</p>\n<h2 id=\"possibilities\"></h2>\n<p>In short, ClickHouse Fiddle allows running several SQL queries in an arbitrary version of ClickHouse and provides a unique link to share the results of execution.</p>\n<p>Write and DDL queries are also allowed! It means you can create a table, insert some rows and execute a query over them. Data from one execution is not accessible in another run with isolation achieved via containerization (more on this in the design section).\n<span><img alt=\"fiddle-pros.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Ffiddle_pros_6a60e155a9.jpg&w=2048&q=75\"></span>\nThere are some rational limitations on the maximum execution duration and input/output size, but they are not too strict. Users can play with some basic executions to understand the logic of one or another SQL queryset.</p>\n<p>Keep in mind, playgrounds are not intended to measure the performance of databases. In case you want to understand how fast is a query, we suggest you run a benchmark in a production-ready instance.</p>\n<p>Execution of a simple query on a <em>hot</em> database version usually takes <strong>several seconds</strong> at the moment (p90 is ~2 seconds). We call a version <em>hot</em> if it has already been used recently for another query. Here you can see an example of the 90th percentile of run duration:</p>\n<p><span><img alt=\"fiddle-execution-time.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Ffiddle_execution_time_e300083f31.png&w=2048&q=75\"></span></p>\n<h2 id=\"clickhouse-fiddle-design\"></h2>\n<p>Let's discuss how the playground is implemented. The design of Fiddle fits into one picture:\n<span><img alt=\"clickhouse-fiddle-design.svg\" src=\"https://clickhouse.com/uploads/clickhouse_fiddle_design_cf5ff37109.svg\"></span>\nThe entry point for users is a simple web application available at <a target=\"_blank\" href=\"https://fiddle.clickhouse.com/\">fiddle.clickhouse.com</a>. Users interact with the platform using a HTTP API. All requests are sent to the main component of the system — playground core.</p>\n<p>For each user request a Docker container with the desired ClickHouse version is created. The core of Playground distributes incoming load over available machines and runs Docker containers on each of them.</p>\n<p>To optimize the latency of query execution, playground sends liveness probes to runners and collects information about already pulled images. Priority is given to runners with a pulled image when load balancing.\n<span><img alt=\"clickhouse-fiddle-coord-runner-communication.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fclickhouse_fiddle_coord_runner_communication_ee8888c23d.jpg&w=2048&q=75\"></span>\nLet's look more precisely at what happens when a user asks the platform to execute a query:</p>\n<ol>\n<li>Playground core picks an available machine using a load balancing algorithm.</li>\n<li>If there is no Docker image with the required ClickHouse version on the selected machine, pull it from the registry.</li>\n<li>Create and run a Docker container.</li>\n<li>Run provided SQL queries in the container.</li>\n<li>Wait for the execution of queries and kill the container.</li>\n<li>Save execution results in the query storage (to allow sharing them by link).</li>\n<li>Send a response with the fetched data to the user.</li>\n</ol>\n<p>Ephemeral containers help to isolate runs from each other via cgroups mechanism. If we compare this approach with always-on database instances, there is latency for image pulling and creating containers, but it requires significantly fewer resources for running the whole platform (1 runner is enough for non-frequent usage).</p>\n<p>But there are a lot of orchestration systems: Kubernetes, cloud services, etc. Why did you write yet another container manager? Existing orchestration services provide a huge number of things you can do with containers. And the price for this is their complexity and slowness (within purposes of playgrounds). The written coordinator is faster than orchestration systems because of its simplicity, and it requires fewer computing resources.</p>\n<h2 id=\"future-work-and-feedback\"></h2>\n<p>Fiddle has a lot of opportunities for improvement:</p>\n<ul>\n<li>frontend features, like SQL syntax highlight</li>\n<li>coordinator distribution algorithm</li>\n<li>database instances with preload datasets</li>\n<li>reducing latency by running containers in advance</li>\n<li>and many many others...</li>\n</ul>\n<p>If you want to suggest new improvements or share any other feedback, please create an issue in the <a target=\"_blank\" href=\"https://github.com/lodthe/clickhouse-playground\">Github repository</a>. Itis highly appreciated!</p>\n<p>And <a target=\"_blank\" href=\"https://fiddle.clickhouse.com/\">fiddle.clickhouse.com</a> is waiting for your queries :)</p></div></article>"
