contentHtml: "<article><div><p>At ClickHouse, our mission has always been to make real-time analytics accessible and lightning-fast. As more of our community moves toward cloud-native architectures, the need for a robust, automated way to manage Open Source ClickHouse distribution on Kubernetes has become clear.</p>\n<p>Today, we are thrilled to announce the release of the Official ClickHouse Kubernetes Operator - available now, open-source (under Apache-2.0 licence), and free for everyone.</p>\n<h2 id=\"why-a-kubernetes-operator\"></h2>\n<p>Running a stateful, high-performance database like ClickHouse on Kubernetes presents unique challenges: horizontal and vertical scaling, ensuring data persistence during pod restarts, and executing seamless upgrades.</p>\n<p>The ClickHouse Operator simplifies these tasks by extending the Kubernetes API. It allows you to manage complex ClickHouse clusters using convenient Custom Resource Definitions (CRDs). Instead of manually configuring Pods and Services, you simply describe your desired state, and the Operator handles the rest.</p>\n<h2 id=\"key-features\"></h2>\n<ul>\n<li><strong>Automated Cluster Provisioning:</strong> Deploy a production-ready, multi-node cluster with sharding and replication in minutes.</li>\n<li><strong>ClickHouse Keeper Support:</strong> Deploy and manage ClickHouse Keeper.</li>\n<li><strong>Vertical &amp; Horizontal Scaling:</strong> Easily adjust CPU / Memory resources or add new shards to your cluster with minimal downtime.</li>\n<li><strong>Configuration Management:</strong> Safely update your configuration and ClickHouse version in a single manifest change. The Operator manages the sequence, ensuring that new configuration parameters are rolled out only to updated pods, eliminating the risk of service disruptions caused by version-config mismatches.</li>\n<li><strong>Seamless Upgrades:</strong> Perform rolling updates to new ClickHouse versions without dropping queries.</li>\n</ul>\n<h2 id=\"design-choices\"></h2>\n<p>When implementing the operator, we wanted to reuse the ClickHouse Cloud production experience and build on bulletproof, reliable features. That's why we:</p>\n<ul>\n<li>We rely on ClickHouse Keeper for coordination — it’s built in, so you don’t need to run ZooKeeper separately, and there’s no “Keeper-less” mode to worry about. This <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-keeper-a-zookeeper-alternative-written-in-cpp\">post</a> covers the benefits.</li>\n<li>Make the Replicated a default database engine. DatabaseReplicated has been powering ClickHouse Cloud since the beginning of our business and has proved its reliability and convenience. That’s why it was an obvious choice for us to use it in the Operator as well. It eliminates the need to write the ON CLUSTER clause in every DDL query you issue to the database.</li>\n<li>Have a StatefulSet per replica. This key decision allows us to implement different upgrade strategies and have fine-grained control over each replica (e.g., the version they run, their configuration, etc.).</li>\n<li>TLS/SSL encryption for ClickHouse &lt;-&gt; Keeper and Client &lt;-&gt; ClickHouse communication.</li>\n<li>Configuration overrides for both ClickHouse and Keeper.</li>\n</ul>\n<p>In general, our key principle is keeping things simple. If something can be implemented on the ClickHouse side in C++, it has to be there. That made the Operator a very thin layer on top of what ClickHouse already can do.</p>\n<div><h3>Get started today</h3><p>Interested in seeing how ClickHouse works on your data? Get started with ClickHouse Cloud in minutes and receive $300 in free credits.</p><p><a target=\"_blank\" href=\"https://console.clickhouse.cloud/signUp?loc=blog-global-cta&utm_blogctaid=1\">Sign up</a></p></div>\n<h2 id=\"getting-started-your-first-cluster\"></h2>\n<p>Getting up and running is as simple as applying a few YAML files.</p>\n<p><strong>1. Install the cert-manager</strong></p>\n<p>The operator uses defaulting and validating webhooks to ensure the validity of Custom Resource (CR) objects. It requires cert-manager to issue a certificate.</p>\n<div><pre><code><span><span># Using kubectl</span></span>\n<span>kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.19.2/cert-manager.yaml</span></code></pre></div>\n<div><pre><code><span><span># Or using helmchart</span></span>\n<span>helm install cert-manager --create-namespace --namespace cert-manager oci://quay.io/jetstack/charts/cert-manager --<span>set</span> crds.enabled=<span>true</span> --version v1.19.2</span></code></pre></div>\n<p><strong>2. Install the Operator</strong></p>\n<div><pre><code><span><span># Using kubectl</span></span>\n<span>kubectl apply -f https://github.com/ClickHouse/clickhouse-operator/releases/latest/download/clickhouse-operator.yaml</span></code></pre></div>\n<div><pre><code><span><span># Or our helmchart</span></span>\n<span>helm install clickhouse-operator --create-namespace -n clickhouse-operator-system oci://ghcr.io/clickhouse/clickhouse-operator-helm</span></code></pre></div>     \n<p><strong>3. Deploy a Simple Cluster</strong> Below is a basic example of a Custom Resource (CR) to deploy a two-node cluster:</p>\n<p>YAML CR</p>\n<div><pre><code><span><span>apiVersion:</span> <span>clickhouse.com/v1alpha1</span></span>\n<span><span>kind:</span> <span>KeeperCluster</span></span>\n<span><span>metadata:</span></span>\n<span>  <span>name:</span> <span>sample</span></span>\n<span><span>spec:</span></span>\n<span>  <span>replicas:</span> <span>3</span></span>\n<span>  <span>dataVolumeClaimSpec:</span></span>\n<span>    <span>accessModes:</span></span>\n<span>      <span>-</span> <span>ReadWriteOnce</span></span>\n<span>    <span>resources:</span></span>\n<span>      <span>requests:</span></span>\n<span>        <span>storage:</span> <span>10Gi</span></span>\n<span><span>---</span></span>\n<span><span>apiVersion:</span> <span>clickhouse.com/v1alpha1</span></span>\n<span><span>kind:</span> <span>ClickHouseCluster</span></span>\n<span><span>metadata:</span></span>\n<span>  <span>name:</span> <span>sample</span></span>\n<span><span>spec:</span></span>\n<span>  <span>replicas:</span> <span>2</span></span>\n<span>  <span>dataVolumeClaimSpec:</span></span>\n<span>    <span>accessModes:</span></span>\n<span>      <span>-</span> <span>ReadWriteOnce</span></span>\n<span>    <span>resources:</span></span>\n<span>      <span>requests:</span></span>\n<span>        <span>storage:</span> <span>10Gi</span></span>\n<span>  <span>keeperClusterRef:</span></span>\n<span>    <span>name:</span> <span>sample</span></span></code></pre></div>\n<h2 id=\"our-commitment-to-open-source\"></h2>\n<p>We believe that the tools used to manage ClickHouse should be as open as the database itself.
