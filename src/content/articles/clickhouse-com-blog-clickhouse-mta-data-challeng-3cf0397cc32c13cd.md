We found a couple of major issues, which we’ll go through in turn.</p>\n<h3 id=\"challenge-1-cumulative-values-and-outliers\"></h3>\n<p>MTA provides a longer form<a target=\"_blank\" href=\"https://data.ny.gov/api/views/ug6q-shqc/files/29edbef3-268e-461d-95f1-374b1c8a6f9d?download=true&filename=MTA_SubwayTurnstileUsageData2015_Overview.pdf\"> description of the data</a>, which provides insight into some data quality issues and challenges. Not least, the <code>entries</code> and <code>exit</code> values are cumulative.</p>\n<p><em>&gt; Data is provided about every four hours for the cumulative register values for entries and exits for each turnstile, similar to odometer readings. The four-hour intervals will differ from other stations due to the need for staggering to prevent flooding the system with audit readings all at once. Systemwide, stations have been set to begin audit transmittal between 00 to 03 hours, then every four hours after the first audit of the day. The number of people who entered or exited a turnstile in a period can be obtained by comparing it to an earlier reading.</em></p>\n<p>These cumulative values are challenging to use and would require queries to compute time ordered derivatives for every turnstile.  We note that the 4 hour periodic delivery of data will make attributing usage of a station to specific periods still very imprecise. This is something we can't resolve, so counts below the granularity of this period are unlikely to be accurate.</p>\n<p>These values also have some clear data quality issues:</p>\n<p><em>&gt; Turnstile audits are often not available every four hours, turnstiles sometimes count down instead of up, exit and entry counters periodically get reset, and the timestamps for audits vary between turnstiles. In addition, the data is 10 digits long and will roll over to zero on overflow.</em></p>\n<p>Ideally we'd like to compute the number of entries and exits for each row based on the difference to the previous time value for the turnstile. This requires us to reliably be able to identify a turnstile.</p>\n<p>While turnstiles have an <code>scp</code> identifier, this is not unique across stations. Instead we can use a combination of the scp, ca (booth identifier at station) and unit(remote unit ID of the station) to identify a specific station.</p>\n<p>To compute the number of entries and exits for each turnstile, requires a<a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/window-functions\"> window function</a>. The following computes the columns <code>entries_change</code> and <code>exits_change</code> for each row.</p>\n<div><pre><code><span><span>WITH</span> <span>1000</span> <span>AS</span> threshold_per_hour</span>\n<span><span>SELECT</span></span>\n<span>    <span>*</span>,</span>\n<span>    <span>any</span>(date_time) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> ca, unit, scp <span>ORDER</span> <span>BY</span> date_time <span>ASC</span> <span>ROWS</span> <span>BETWEEN</span> <span>1</span> PRECEDING <span>AND</span> <span>CURRENT</span> <span>ROW</span>) <span>AS</span> p_date_time,</span>\n<span>    <span>any</span>(entries) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> ca, unit, scp <span>ORDER</span> <span>BY</span> date_time <span>-</span> p_exits) <span>/</span> if(hours <span>&gt;</span> <span>0</span>, hours, <span>1</span>)) <span>&gt;</span> threshold_per_hour), <span>0</span>, exits <span>-</span> p_exits) <span>AS</span> exits_change</span>\n<span><span>FROM</span> subway_transits_2014_2022_v1</span>\n<span><span>ORDER</span> <span>BY</span></span>\n<span>    ca <span>ASC</span>,</span>\n<span>    unit <span>ASC</span>,</span>\n<span>    scp <span>ASC</span>,</span>\n<span>    date_time <span>ASC</span></span></code></pre></div>\n<p>A few important points for the query:</p>\n<ul>\n<li>We order by <code>ca</code>, <code>unit</code>, <code>scp</code>, and <code>date_time</code> (ascending). This ensures the rows for each turnstile are processed together in increasing time order, allowing us to compute the delta.</li>\n<li>The function creates a window for each turnstile using <code>PARTITION BY ca, unit, scp</code>. Within each window the data is again ordered by increasing time. The <code>ROWS BETWEEN 1 PRECEDING AND CURRENT ROW</code> clause is used to add the columns <code>p_entries</code> and <code>p_exits</code>. These contain the previous entries and exit values for each row. The time from the previous row is captured in <code>p_date_time</code>.</li>\n<li>The columns <code>entries_change</code> and <code>exits_change</code> contain the delta between the previous and current values for the entries and exits, respectively. Importantly, if the change is negative, we return a value of 0, assuming this represents a rollover.
