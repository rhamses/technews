Below you will find new exciting features we released, recent meetup and webinar recordings, some neat queries using window functions and a few recommended reads.</p>\n<h2 id=\"clickhouse-v22-2\"></h2>\n<p>We released ClickHouse 22.2, the newest and greatest version of your favorite database. Highlights include:</p>\n<ul>\n<li><strong><a target=\"_blank\" href=\"https://clickhouse.com/docs/en/engines/table-engines/mergetree-family/mergetree/#projections\">Projections</a></strong> are production ready and enabled by default. They allow you to store part of a table in a subdirectory of the original table, often using a different sorting key or aggregating the original data – similar to materialized views but without all the overhead. Their usage is refreshingly simple: Queries will be automatically analyzed and redirected to the projection if less data has to be read there to produce the same result. Almost like magic!</li>\n<li><strong>Custom deduplication on insert</strong> – a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/settings/settings/#insert_deduplication_token\">new setting</a> <code>[insert_deduplication_token]</code> allows you to specify a custom token (any string) that is used to determine if a block has already been inserted. If it has, then any subsequent blocks with the same token are discarded. Any insert statement creates a block but large inserts are divided into multiple blocks of about 1 million rows (controlled by <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/settings/settings/#settings-max_insert_block_size\">max_insert_block_size</a>). This makes it easier to implement exactly-once semantics in ClickHouse. Note: By default, ClickHouse will already deduplicate inserted data blocks that are identical (consist of the same rows in the same order). This new setting gives you more control over the process if you need it.</li>\n<li><strong>Default table engine</strong> – You can now set a default table engine so you no longer have to specify one when creating a table. For example:</li>\n</ul>\n<div><pre><code><span>SET default_table_engine = 'MergeTree'</span>\n<span>CREATE TABLE table1 (x int PRIMAY KEY (x))</span></code></pre></div>\n<ul>\n<li><strong><a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/create/table/#ephemeral\">Ephemeral columns</a></strong> can be used at insert time to calculate other columns but are not stored themselves.</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/33314\">Text classification</a></strong> – Experimental functions for detecting language, character set, tonality and programming language were added. It’s a relatively recent (early 2021) feature but very powerful. Let’s go on a whirlwind tour of what’s possible that used to be much harder before. Note: We will use the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/uk-price-paid/\">UK Price Paid dataset</a> of all property transactions in the UK in the last few decades, so feel free to reproduce the queries!</p>\n<p><strong>Query 1: Compare with cohort average</strong></p>\n<div><pre><code><span><span>SELECT</span> <span>avg</span>(price) <span>OVER</span>(<span>PARTITION</span> <span>BY</span> postcode1) <span>AS</span> postcode_avg, <span>*</span></span>\n<span><span>FROM</span> uk_price_paid</span>\n<span><span>WHERE</span> type <span>=</span> <span>'flat'</span></span>\n<span><span>ORDER</span> <span>BY</span> price <span>DESC</span></span></code></pre></div>\n<p>This query will show the most expensive flats / apartments ever sold in the UK but in addition will show the average prices in their postcodes as the first column. So now we can see who’s really overpaying!</p>\n<p><strong>Query 2: When was this property sold previously?</strong></p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>lagInFrame(<span>date</span>) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> postcode1, postcode2, addr1, addr2 <span>ORDER</span> <span>BY</span> <span>date</span> <span>ASC</span>) <span>AS</span> previous_date,</span>\n<span>lagInFrame(price) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> postcode1, postcode2, addr1, addr2 <span>ORDER</span> <span>BY</span> <span>date</span> <span>ASC</span>) <span>AS</span> previous_price,</span>\n<span><span>*</span> <span>FROM</span> uk_price_paid</span></code></pre></div>\n<p>With a time series dataset like this we will often want to see the previous record for a particular entity. We can do this with <code>lagInFrame</code>. If we use <code>first_value</code> we would get the first time the property was sold instead (the dataset only goes back to 1995).</p>\n<p><strong>Query 3: Sorting with window functions</strong></p>\n<p>You can also sort by window functions. For example, this query shows the most expensive sub-postcodes within the most expensive postcode (in the UK, postcodes have two parts):</p>\n<div><pre><code><span><span>SELECT</span> <span>DISTINCT</span></span>\n<span>    postcode1,</span>\n<span>    postcode2,</span>\n<span>    <span>avg</span>(price) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> postcode1, postcode2) <span>AS</span> avg_price</span>\n<span><span>FROM</span> uk_price_paid</span>\n<span><span>WHERE</span> type <span>=</span> <span>'flat'</span></span>\n<span><span>ORDER</span> <span>BY</span></span>\n<span>    <span>avg</span>(price) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> postcode1) <span>DESC</span>,</span>\n<span>    avg_price <span>DESC</span></span></code></pre></div>\n<p>Note the two window functions used in the <code>ORDER BY</code> clause.
