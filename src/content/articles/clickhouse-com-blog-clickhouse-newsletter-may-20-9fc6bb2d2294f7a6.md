More to come here, stay tuned!</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/30325\">Keeper load balancing</a></strong> You can now specify how a ClickHouse instance chooses a (ClickHouse) Keeper or (Apache) ZooKeeper instance to connect to. The new <code>config.xml</code> setting is <code>&amp;lt;zookeeper_load_balancing&gt;</code> with possible values <code>random</code> (default), <code>in_order</code>, <code>nearest_hostname</code>, <code>first_or_random</code> and <code>round_robin</code>. This can help ensure low latency between ClickHouse and Keeper when you have different Keeper nodes that are far apart from each other.</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/32928\">Table metadata cache</a></strong> A new table setting <code>use_metadata_cache</code> uses the embedded RocksDB engine to cache table metadata. When ClickHouse starts up, it will try to read from this cache and fall back to the table files on disk if needed. This is useful when you have a very large number of data parts (usually caused by having a lot of databases, tables, and/or partitions, or by very high insert volume creating a lot of parts). In one extreme instance (700k parts), the metadata cache was able to reduce startup time from 75 minutes to 20 seconds.</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/35916\">Kafka metrics</a></strong> The Kafka table engine is now exposing some metrics, e.g. number of processed messages, number of errors, number of messages that failed to parse. You can find these in the <code>system.metrics</code> and <code>system.events</code> tables.</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/35349\">Gap filling</a></strong> You can now fill gaps in result sets using interpolation. For example, when you have minute-by-minute data but sometimes the value for a minute might be missing (completely missing, or maybe it’s stil making it’s way through the ingest pipeline and arriving late), you can have ClickHouse use the previous value instead using <code>ORDER BY toStartOfMinute(timestamp) WITH FILL INTERPOLATE (c AS c)</code>. More complex expressions are possible.</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/34394\">Last day of month</a></strong> So far, the ClickHouse date functions would round to the start of a time period (<code> toStartOf[Year|Month|Week|Day|Hour|Minute|etc.</code>). Now, we also have <code>toLastDayOfMonth</code> if you want to round to the last day of a month (useful for financial and accounting data).</li>\n<li><strong><a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/34568\">H3</a></strong> We’ve rounded out support for H3, the “hexagonal hierarchical geospatial indexing system” originally developed and open sourced by Uber. <span>│</span></span>\n<span><span>│</span> <span>ReadFromMergeTree</span>                     <span>│</span></span>\n<span><span>│</span> <span>ReadType:</span> <span>Default</span>                     <span>│</span></span>\n<span><span>│</span> <span>Parts:</span> <span>1</span>                              <span>│</span></span>\n<span><span>│</span> <span>Granules:</span> <span>1</span>
