This supports services such as data replication, distributed DDL query execution, leadership elections, and service discovery. ClickHouse Keeper is compatible with ZooKeeper, the legacy component used for this functionality in ClickHouse.</p>\n<p><strong>ClickHouse Keeper is production ready. ClickHouse Cloud is running clickhouse-keeper at large scale to support thousands of ClickHouse deployments in a multi-tenant environment.</strong></p>\n<p>Until now users would communicate with ClickHouse Keeper by sending commands directly over TCP using tools such as <code>nc</code> or <code>zkCli.sh</code>. While sufficient for basic debugging, this made administrative tasks a less than ideal user experience and were far from convenient.  To address this, in 23.5 we introduce <code>keeper-client</code> - a simple tool built into ClickHouse for introspecting your ClickHouse Keeper.</p>\n<p>To experiment with the client we can use our recently <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-architectures-with-docker-compose\">released docker compose files</a>, courtesy of our support team, to quickly start a multi-node ClickHouse cluster. These were the start of what we consider to be a journey in making ClickHouse the world’s fastest tool for querying Parquet files, either via <a target=\"_blank\" href=\"https://clickhouse.com/blog/extracting-converting-querying-local-files-with-sql-clickhouse-local\">ClickHouse Local</a> or ClickHouse Server. Unsatisfied with recent efforts to parallelise reading of Parquet, by exploiting row groups, 23.5 adds further improvements.</p>\n<p>Most of these improvements related to low level efforts to make parallel reading more efficient by <a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/49539\">avoiding mutex locks</a>. As noted in our blog, we also historically read Parquet rows in order which inherently limits reading speed. This limitation is now removed, with out of order reading the default. While this is not expected to impact most users (other than their queries being faster!), as analytical queries typically do not depend on read order, users can revert to the old behavior if required via the setting <code>input_format_parquet_preserve_order = true</code>.</p>\n<p>As an example of the improvements, consider the following case of executing the earlier query over a single Parquet file containing all of the rows from the earlier UK price paid dataset - this file can be downloaded from <a target=\"_blank\" href=\"https://datasets-documentation.s3.eu-west-3.amazonaws.com/uk-house-prices/parquet/house_prices.parquet\">here</a>.</p>\n<div><pre><code><span><span>--23.4</span></span>\n<span></span>\n<span><span>SELECT</span></span>\n<span>\ttoYear(toDate(<span>date</span>)) <span>AS</span> <span>year</span>,</span>\n<span>\tround(<span>avg</span>(price)) <span>AS</span> price,</span>\n<span>\tbar(price, <span>0</span>, <span>1000000</span>, <span>80</span>)</span>\n<span><span>FROM</span> file(<span>'house_prices.parquet'</span>)</span>\n<span><span>GROUP</span> <span>BY</span> <span>year</span></span>\n<span><span>ORDER</span> <span>BY</span> <span>year</span> <span>ASC</span></span>\n<span></span>\n<span><span>29</span> <span>rows</span> <span>in</span> set. Historically we <a target=\"_blank\" href=\"https://clickhouse.com/blog/apache-parquet-clickhouse-local-querying-writing-internals-row-groups\">have recommended users</a> utilize the latter of these two approaches, principally because <code>INTO OUTFILE</code> could <a target=\"_blank\" href=\"https://clickhouse.com/blog/apache-parquet-clickhouse-local-querying-writing-internals-row-groups#importance-of-row-groups\">reproduce very large row group</a> sizes due to some less than ideal<a target=\"_blank\" href=\"https://clickhouse.com/blog/apache-parquet-clickhouse-local-querying-writing-internals-row-groups#importance-of-row-groups\"> internal behaviors</a>. This would <a target=\"_blank\" href=\"https://clickhouse.com/blog/apache-parquet-clickhouse-local-querying-writing-internals-row-groups#importance-of-row-groups\">impact later read performance</a>. This could be a complex issue to debug and would require a deep understanding of Parquet. Fortunately, this issue is <a target=\"_blank\" href=\"https://github.com/ClickHouse/ClickHouse/pull/49325\">now addressed</a> - feel free to use <code>INTO OUTFILE</code> as you might for other formats!</p>\n<p>While the above all represent significant improvements, this journey is still not complete.
