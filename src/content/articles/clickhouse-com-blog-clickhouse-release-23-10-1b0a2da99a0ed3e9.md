One example of this ClickHouse <code>superset of SQL</code> is extensive support for arrays. Arrays are well-known to users of other programming languages like Python and JavaScript. They are generally useful for modeling and solving a wide range of problems in an elegant and simple way. ClickHouse <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions\">has</a> over 70 functions for processing arrays, with many of these functions being <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions#higher-order-functions---operator-and-lambdaparams-expr-function\">higher-order functions</a> providing a high level of abstraction, allowing you to express complex operations on arrays in a concise and declarative manner. We proudly announce that this family of array functions now has a new, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/github#git-blame\">long-awaited</a>, and most powerful member: <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions#arrayfold\">arrayFold</a>.</p>\n<p>arrayFold is equivalent to the <a target=\"_blank\" href=\"https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/reduce\">Array.reduce function</a> in JavaScript and is used to fold or reduce the elements in an array from left to right by applying a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions#higher-order-functions---operator-and-lambdaparams-expr-function\">lambda-function</a> to the array elements in a cumulative manner, starting from the leftmost element and accumulating a result as it processes each element. This cumulative process can be thought of as <code>folding</code> the elements of the array together.</p>\n<p>The following is a simple example where we use <code>arrayFold</code> for calculating the sum of all elements of the array <code>[10, 20, 30]</code>:</p>\n<div><pre><code><span><span>SELECT</span> arrayFold((acc, v) <span>-</span><span>&gt;</span> (acc <span>+</span> v), [<span>10</span>, <span>20</span>, <span>30</span>],  <span>0</span>::UInt64) <span>AS</span> sum</span>\n<span></span>\n<span>┌─sum─┐</span>\n<span>│  <span>60</span> │</span>\n<span>└─────┘</span></code></pre></div>\n<p>Note that we are passing both a lambda function <code>(acc, v) -&gt; (acc + v)</code> and an initial accumulator value <code>0</code> in the example call of <code>arrayFold</code> above.</p>\n<p>The lambda function is then called with <code>acc</code> set to the initial accumulator value <code>0</code> and <code>v</code> set to the first (most left) array element <code>10</code>. Next, the lambda function is called with <code>acc</code> set to the result of the previous step and <code>v</code>  set to the second array element <code>20</code>. This process continues, iteratively folding the array elements from left to right until the end of the array is reached, producing a final result, <code>60</code>.</p>\n<p>This diagram visualizes how the <code>+</code> operator from the body of our lambda function is cumulatively applied to the initial accumulator and all array elements from left to right:\n<span><img alt=\"arrayfold.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Farrayfold_b10298dc1d.png&w=2048&q=75\"></span></p>\n<p>We used the example above just as an introduction. We could have used <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions#arraysum\">arraySum</a> or <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions#arrayreduce\">arrayReduce(<code>sum</code>)</a>  for calculating the sum of all array elements. But <code>arrayFold</code> is far more capable. It is one of the most generic and flexible members of the ClickHouse array function family that can be used to perform a wide range of operations on arrays, such as aggregating, filtering, mapping, grouping, and more complex tasks.</p>\n<p>The possibility to (1) provide a custom folding function in the form of a lambda function, and to (2) hold, inspect, and shape the folding state (accumulator) on each iteration step is a powerful combination allowing complex data processing in a concise and composable way. We even mentioned:</p>\n<blockquote>\n<p>“Reconstructing this from a history of commits is particularly challenging - especially since ClickHouse doesn’t currently have an arrayFold function which As part of this, we loaded over 2 billion vectors from the <a target=\"_blank\" href=\"https://laion.ai/blog/laion-5b/\">LAION dataset</a> and their accompanying metadata into ClickHouse. This dataset contains vector embeddings for over 2 billion images and their captions, collected from a <a target=\"_blank\" href=\"https://laion.ai/blog/laion-5b/#distributed-processing-of-common-crawl\">distributed crawl</a>. These embeddings were generated using a multi-modal model, allowing users to search for images with text and vice versa.</p>\n<p>The vectors for this are distributed as Numpy arrays in<a target=\"_blank\" href=\"https://huggingface.co/datasets/laion/laion2b-en-vit-l-14-embeddings/tree/main/img_emb\"> <code>npy</code> format via the popular platform HuggingFace</a>. Each vector also has accompanying <a target=\"_blank\" href=\"https://huggingface.co/datasets/laion/laion2b-en-vit-l-14-embeddings/tree/main/metadata\">metadata in the format of Parquet files</a>, with properties such as the caption, height of width image, and a similarity score between the image and text.</p>\n<p>In order to insert this data into ClickHouse at the time, we were forced to <a target=\"_blank\" href=\"https://github.com/ClickHouse/laion/blob/main/process.py\">write Python code</a> to merge the <code>npy</code> files with the Parquet - with the aim of having a single table with all the columns. While ClickHouse had excellent support for Parquet, <code>npy</code> format was not supported. To make this more challenging, the <code>npy</code> files are designed only to contain floating point arrays. Joining the datasets, therefore, needs to be done based on row position. While the Python approach was sufficient and easily parallelized at a file level with over 2300 file sets to merge, we’re always frustrated when we can’t just solve something with clickhouse local! This particular problem is also common for other Hugging face datasets, which consist of embeddings and metadata.
