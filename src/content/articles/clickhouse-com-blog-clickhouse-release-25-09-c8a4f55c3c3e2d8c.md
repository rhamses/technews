<a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-fully-supports-joins-how-to-choose-the-right-algorithm-part5#imdb-large-join-runs\">fastest</a> join algorithms, including the This sequential process had several drawbacks:</p>\n<ul>\n<li><strong>Inefficient with LIMIT:</strong> Even if a query stopped early, ClickHouse still had to scan the entire index upfront.</li>\n<li><strong>Startup delay:</strong> Index analysis happened before query execution began.</li>\n<li><strong>Heavy index scans:</strong> In some cases, scanning the index cost more than processing the actual data.</li>\n</ul>\n<p>ClickHouse 25.9 eliminates these drawbacks by <strong>interleaving data reads with index checks</strong>. When ClickHouse is about to read a table data granule, it first checks the corresponding secondary index entry. If the index indicates the granule can be skipped, it's never read. Otherwise, the granule is read and processed while scanning continues on subsequent granules.</p>\n<p>This concurrent execution eliminates startup delay and avoids wasted work. For queries with LIMIT, ClickHouse halts index checks and granule reads as soon as the result is complete.</p>\n<p><strong>Results:</strong> In testing with a 1 billion row table and a 2+ GiB bloom filter index, a simple LIMIT 1 query was <strong>over 4× faster</strong> (2.4s vs 10s) with streaming indices enabled.</p>\n<p>This feature is controlled by the <a target=\"_blank\" href=\"https://clickhouse.com/docs/operations/settings/settings#use_skip_indexes_on_data_read\">use_skip_indexes_on_data_read</a> setting.</p>\n<p><strong><a target=\"_blank\" href=\"https://clickhouse.com/blog/streaming-secondary-indices\">Read the full deep-dive on streaming secondary indices →</a></strong></p>\n<h2 id=\"a-new-text-index\"></h2>\n<h3 id=\"contributed-by-anton-popov-elmi-ahmadov-jimmy-aguilar-mena\"></h3>\n<p>Since publishing <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-full-text-search\">our blog on reworking full-text search in August 2025</a>, we’ve learned even more from extended testing.
