duplicate values.</p>\n<p>When running JOIN queries (including those using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/sql-reference/functions/array-join\">arrayJoin</a> function), values from the input tables are often replicated in the result, especially when there are many matches for a given key.</p>\n<p>As an example, consider a hits table containing <a target=\"_blank\" <code>URL</code>:</p>\n<p><span><img alt=\"25.10-image1.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F25_10_image1_63adbec231.png&w=2048&q=75\"></span></p>\n<p>When we run a self-join:</p>\n<div><pre><code><span><span>SELECT</span> ...</span>\n<span><span>FROM</span></span>\n<span>    hits <span>AS</span> t1 <span>INNER</span> <span>JOIN</span> hits <span>AS</span> id=\"contributed-by-yarik-briukhovetskyi\"></h3>\n<p>ClickHouse can now <strong>push down complex OR conditions</strong> in JOIN queries to filter each table earlier, before the join actually happens.</p>\n<p>This optimization works when every branch of an OR condition includes at least one filter (predicate) for each table involved in the join.</p>\n<p>For example:</p>\n<div><pre><code><span>(t1.k <span>IN</span> (<span>1</span>,<span>2</span>) <span>AND</span> t2.x <span>=</span> <span>100</span>)</span>\n<span><span>OR</span></span>\n<span>(t1.k every branch.</p>\n<p>ClickHouse can therefore <strong>combine and push them down</strong> as:</p>\n<ul>\n<li>\n<p><code>t1.k IN (1,2,3,4)</code> for the left table</p>\n</li>\n<li>\n<p><code>t2.x IN (100,200)</code> for the right table</p>\n</li>\n</ul>\n<p>This allows both tables to be <strong>pre-filtered before the join</strong>, reducing the data read and improving performance.</p>\n<p>This optimization is available under the setting <a target=\"_blank\" href=\"https://clickhouse.com/docs/operations/settings/settings#use_join_disjunctions_push_down\">use_join_disjunctions_push_down</a>.</p>\n<p>To see how this optimization works in practice, we’ll
