contentHtml: "<div><p>One of my favorite features of ClickHouse 25.12 was the <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-release-25-12#hmac\"><code>HMAC</code> function</a> for message authentication using a shared key.</p>\n<p>ClickHouse has always been able to act as a webhook endpoint, but with the HMAC function we can now verify webhook requests, filtering out those that didn't come from the expected source.\nWe'll start by seeing how this works with a local example, before moving onto a real-life example using ClickHouse Cloud as a GitHub webhook endpoint.</p>\n<h2 id=\"the-webhook-pattern\"></h2>\n<p>One cool thing about ClickHouse is the ability to chain tables together using materialized views. Data gets ingested into one table, a materialized view acts as a SQL trigger, and the results are written to another table.</p>\n<p>This becomes especially powerful when combined with the Null table engine. Rather than storing data, the Null table engine forwards\neverything it receives to any connected materialized views — making it the perfect staging layer.</p>\n<p>The result is a clean three-step pattern:</p>\n<ol>\n<li>A staging table receives all incoming data</li>\n<li>A materialized view validates and transforms it</li>\n<li>A final table stores only the verified data</li>\n</ol>\n<p><span><img alt=\"Webhook Diagram Issue 1399.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FWebhook_Diagram_Issue_1399_0e9e53eb69.jpg&w=2048&q=75\"></span></p>\n<h2 id=\"create-the-tables\"></h2>\n<p>Let's have a look at how to set this all up in ClickHouse.\nIf you want to follow along, you'll need to have a ClickHouse server or ClickHouse Cloud service running.</p>\n<p>First, let's create the staging table:</p>\n<div><pre><code><span><span>CREATE TABLE</span> webhook_staging (</span>\n<span>    received_at DateTime <span>DEFAULT</span> now(),</span>\n<span>    raw_payload String,</span>\n<span>    signature String <span>DEFAULT</span> getClientHTTPHeader(<span>'X-Hub-Signature-256'</span>)</span>\n<span>) ENGINE <span>=</span> MergeTree()</span>\n<span><span>ORDER</span> <span>BY</span> received_at</span>\n<span>SETTINGS allow_get_client_http_header<span>=</span><span>1</span>;</span></code></pre></div>\n<p>The <code>allow_get_client_http_header</code> setting is required because reading client headers is disabled by default.</p>\n<blockquote>\n<p>We're creating the <code>webhook_staging</code> table with the <code>MergeTree</code> engine, so that we can debug incoming requests. In a production system we would use the <code>Null</code> engine and might also have a second materialized view that captures invalid requests.</p>\n</blockquote>\n<p>Next, we have a table that's going to store only verified rows:</p>\n<div><pre><code><span><span>CREATE TABLE</span> webhook_logs (</span>\n<span>    received_at DateTime,</span>\n<span>    payload JSON</span>\n<span>) ENGINE <span>=</span> MergeTree()</span>\n<span><span>ORDER</span> <span>BY</span> received_at;</span></code></pre></div>\n<p>And finally, we have a materialized view that validates the data:</p>\n<div><pre><code><span><span>CREATE</span> MATERIALIZED <span>VIEW</span> webhook_validator <span>TO</span> webhook_logs <span>AS</span></span>\n<span><span>SELECT</span></span>\n<span>    received_at,</span>\n<span>    raw_payload::JSON <span>as</span> payload</span>\n<span><span>FROM</span> webhook_staging</span>\n<span><span>WHERE</span> signature <span>=</span> <span>'sha256='</span> <span>||</span> <span>lower</span>(hex(HMAC(<span>'SHA256'</span>, raw_payload, <span>'my_secret_key'</span>)));</span></code></pre></div>\n<p>We're comparing the signature from the request header to the expected signature computed using the shared secret key.\nOur shared secret key is <code>my_secret_key</code>.</p>\n<p>If the incoming row doesn't match the expected signature, it won't be written to the <code>webhook_logs</code> table.</p>\n<h2 id=\"create-a-restricted-user\"></h2>\n<p>When experimenting on our own machine, we could use the default admin user, but for a production system it's safer to create a dedicated user with minimal permissions.\nThe user that we create will be used in the webhook URL that we construct later.</p>\n<p>First, let's create the user:</p>\n<div><pre><code><span><span>CREATE</span> <span>USER</span> webhook_receiver</span>\n<span>IDENTIFIED <span>WITH</span> sha256_hash</span>\n<span><span>BY</span> <span>'e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855'</span>;</span></code></pre></div>\n<p>The hash is the SHA256 of an empty string, so no password is needed when we construct the webhook URL.</p>\n<p>Next, let's grant the user the permissions it needs:</p>\n<div><pre><code><span><span>GRANT</span> <span>INSERT</span> <span>ON</span> default.webhook_staging <span>TO</span> webhook_receiver;</span>\n<span><span>GRANT</span> <span>SELECT</span> <span>ON</span> default.webhook_staging <span>TO</span> webhook_receiver;</span>\n<span><span>GRANT</span> <span>SHOW</span> TABLES <span>ON</span> default.webhook_staging <span>TO</span> webhook_receiver;</span>\n<span><span>GRANT</span> <span>SHOW</span> DATABASES <span>ON</span> default.<span>*</span> <span>TO</span> webhook_receiver;</span></code></pre></div>\n<p>If we want to be extra cautious, we could also apply rate limits to this user to guard against abuse.</p>\n<h2 id=\"construct-the-webhook-url\"></h2>\n<p>ClickHouse accepts inserts over HTTP, which means the whole webhook endpoint is a URL with the INSERT query embedded:</p>\n<div><pre><code><span>http://localhost:8123/?user=webhook_receiver&amp;query=INSERT+INTO+webhook_staging+(raw_payload)+FORMAT+RawBLOB</span></code></pre></div>\n<p>The key parts:</p>\n<ul>\n<li><code>user=webhook_receiver</code> -the restricted user we created</li>\n<li><code>query=INSERT INTO webhook_staging (raw_payload) FORMAT RawBLOB</code> -the URL-encoded query that inserts the raw request body</li>\n</ul>\n<p><code>FORMAT RawBLOB</code> tells ClickHouse to treat the entire request body as a single string value rather than trying to parse it.</p>\n<p>We can then test it out by sending a valid request i.e. one where the signature is computed with the correct key:</p>\n<div><pre><code><span>PAYLOAD=<span>'{\"event\":\"user_login\",\"user_id\":456}'</span></span>\n<span>SIGNATURE=$(<span>echo</span> -n <span>\"<span>$PAYLOAD</span>\"</span> | openssl dgst -sha256 -hmac <span>\"my_secret_key\"</span> | <span>cut</span> -d<span>' '</span> -f2)</span>\n<span></span>\n<span>curl -X POST <span>\"http://localhost:8123/?user=webhook_receiver&amp;allow_get_client_http_header=1&amp;query=INSERT%20INTO%20webhook_staging%20(raw_payload)%20FORMAT%20RawBLOB\"</span> \\</span>\n<span>  -H <span>\"X-Hub-Signature-256: sha256=<span>$SIGNATURE</span>\"</span> \\</span>\n<span>  -d <span>\"<span>$PAYLOAD</span>\"</span></span></code></pre></div>\n<p>Let's now connect to our ClickHouse Server using ClickHouse Client:</p>\n<div><pre><code><span>clienthouse client</span></code></pre></div>\n<p>And we can return the contents of <code>webhook_staging</code> and <code>webhook_logs</code>:</p>\n<div><pre><code><span><span>SELECT</span> <span>*</span> <span>FROM</span> webhook_staging;</span></code></pre></div>\n<div><pre><code><span>Row 1:</span>\n<span>──────</span>\n<span>received_at: 2026-02-20 15:42:22</span>\n<span>raw_payload: {<span>\"event\"</span>:<span>\"user_login\"</span>,<span>\"user_id\"</span>:456}</span>\n<span>signature:   sha256=5a23c796b6248c725a6ec7fc2cf0788117d69d376ee6241f411a8887297d3ca4</span>\n<span></span>\n<span>1 row <span>in</span> <span>set</span>. Elapsed: 0.001 sec.</span></code></pre></div>\n<div><pre><code><span><span>SELECT</span> <span>*</span> <span>FROM</span> webhook_logs;</span></code></pre></div>\n<div><pre><code><span>Row 1:</span>\n<span>──────</span>\n<span>received_at: 2026-02-20 15:42:22</span>\n<span>payload:     {</span>\n<span>    <span>\"event\"</span>: <span>\"user_login\"</span>,</span>\n<span>    <span>\"user_id\"</span>: 456</span>\n<span>}</span>\n<span></span>\n<span>1 row <span>in</span> <span>set</span>. Elapsed: 0.003 sec.</span></code></pre></div>\n<p>Both tables have the data. Now how about we send a request where we've computed the signature with a different key:</p>\n<div><pre><code><span>PAYLOAD=<span>'{\"event\":\"user_login\",\"user_id\":456}'</span></span>\n<span>SIGNATURE=$(<span>echo</span> -n <span>\"<span>$PAYLOAD</span>\"</span> | openssl dgst -sha256 -hmac <span>\"rogue_key\"</span> | <span>cut</span> -d<span>' '</span> -f2)</span>\n<span></span>\n<span>curl -X POST <span>\"http://localhost:8123/?user=webhook_receiver&amp;allow_get_client_http_header=1&amp;query=INSERT%20INTO%20webhook_staging%20(raw_payload)%20FORMAT%20RawBLOB\"</span> \\</span>\n<span>  -H <span>\"X-Hub-Signature-256: sha256=<span>$SIGNATURE</span>\"</span> \\</span>\n<span>  -d <span>\"<span>$PAYLOAD</span>\"</span></span></code></pre></div>\n<p>Let's run our queries against <code>webhook_staging</code>:</p>\n<div><pre><code><span>Row 1:</span>\n<span>──────</span>\n<span>received_at: 2026-02-20 15:43:21</span>\n<span>raw_payload: {<span>\"event\"</span>:<span>\"user_login\"</span>,<span>\"user_id\"</span>:456}</span>\n<span>signature:   sha256=01f65041f2505f2b245f3caff410913a22a0ff8c7e8414c9fe1e861359973a7a</span>\n<span></span>\n<span>Row 2:</span>\n<span>──────</span>\n<span>received_at: 2026-02-20 15:42:22</span>\n<span>raw_payload: {<span>\"event\"</span>:<span>\"user_login\"</span>,<span>\"user_id\"</span>:456}</span>\n<span>signature:   sha256=5a23c796b6248c725a6ec7fc2cf0788117d69d376ee6241f411a8887297d3ca4</span>\n<span></span>\n<span>2 rows <span>in</span> <span>set</span>. Elapsed: 0.002 sec.</span></code></pre></div>\n<p>And now, <code>webhook_logs</code>:</p>\n<div><pre><code><span>Row 1:</span>\n<span>──────</span>\n<span>received_at: 2026-02-20 15:42:22</span>\n<span>payload:     {</span>\n<span>    <span>\"event\"</span>: <span>\"user_login\"</span>,</span>\n<span>    <span>\"user_id\"</span>: 456</span>\n<span>}</span>\n<span></span>\n<span>1 row <span>in</span> <span>set</span>. Elapsed: 0.004 sec.</span></code></pre></div>\n<p><code>webhook_staging</code> gets a new row, <code>webhook_logs</code> doesn't  - the signatures didn't match so the materialized view dropped it.</p>\n<h2 id=\"github-webhook\"></h2>\n<p>With the pattern established locally, let's wire it up to a real GitHub repository using ClickHouse Cloud. The structure is almost identical, with just one difference - the staging table picks up an extra <code>event_type</code> column (from the <code>X-GitHub-Event</code> header GitHub sends) and <code>webhook_logs</code> picks an <code>event_type</code> column as well.</p>\n<p>The queries below create our tables and materialized view.</p>\n<div><pre><code><span><span>CREATE TABLE</span> webhook_staging (</span>\n<span>    received_at DateTime <span>DEFAULT</span> now(),</span>\n<span>    raw_payload String,</span>\n<span>    event_type String <span>DEFAULT</span> getClientHTTPHeader(<span>'X-GitHub-Event'</span>),</span>\n<span>    signature String <span>DEFAULT</span> getClientHTTPHeader(<span>'X-Hub-Signature-256'</span>)</span>\n<span>) ENGINE <span>=</span> MergeTree()</span>\n<span><span>ORDER</span> <span>BY</span> received_at</span>\n<span>SETTINGS allow_get_client_http_header<span>=</span><span>1</span>;</span></code></pre></div>\n<div><pre><code><span><span>CREATE TABLE</span> webhook_logs (</span>\n<span>    received_at DateTime,</span>\n<span>    event_type String,</span>\n<span>    payload JSON</span>\n<span>) ENGINE <span>=</span> MergeTree()</span>\n<span><span>ORDER</span> <span>BY</span> received_at;</span></code></pre></div>\n<div><pre><code><span><span>CREATE</span> MATERIALIZED <span>VIEW</span> webhook_validator <span>TO</span> webhook_logs <span>AS</span></span>\n<span><span>SELECT</span></span>\n<span>    received_at,</span>\n<span>    event_type,</span>\n<span>    raw_payload::JSON <span>as</span> payload</span>\n<span><span>FROM</span> webhook_staging</span>\n<span><span>WHERE</span> signature <span>=</span> <span>'sha256='</span> <span>||</span> <span>lower</span>(hex(HMAC(<span>'SHA256'</span>, raw_payload, <span>'my_secret_key'</span>)));</span></code></pre></div>\n<p>In ClickHouse Cloud, click <strong>Connect</strong> to get your cluster URL, then build the webhook URL the same way - just swap <code>localhost:8123</code> for your Cloud host and add <code>allow_get_client_http_header=1</code>:</p>\n<div><pre><code><span>https://&lt;host&gt;:8443/?user=webhook_receiver&amp;allow_get_client_http_header=1&amp;query=INSERT+INTO+webhook_staging+(raw_payload)+FORMAT+RawBLOB</span></code></pre></div>\n<h3 id=\"configure-the-github-webhook\"></h3>\n<p>In your GitHub repository, go to <strong>Settings → Webhooks → Add webhook</strong>:</p>\n<ol>\n<li>Paste your ClickHouse URL into <strong>Payload URL</strong></li>\n<li>Set <strong>Content type</strong> to <code>application/json</code></li>\n<li>Enter your secret key in the <strong>Secret</strong> field -this must match <code>my_secret_key</code> from the materialized view</li>\n<li>Choose which events to send (push events are fine to start)</li>\n<li>Click <strong>Add webhook</strong></li>\n</ol>\n<p><span><img alt=\"2026-02-20_15-48-01.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F2026_02_20_15_48_01_9837c2f742.png&w=2048&q=75\"></span></p>\n<p>GitHub will immediately send a <code>ping</code> event. Refresh the webhook page and you should see \"Last delivery was successful\".</p>\n<p><span><img alt=\"2026-02-20_15-48-31.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F2026_02_20_15_48_31_e808d6d9c3.png&w=2048&q=75\"></span></p>\n<h3 id=\"verify-it-s-working\"></h3>\n<p>We can then explore the contents of each table by clicking their name.</p>\n<p>You should see the <code>ping</code> event in both, which confirms the HMAC validation passed. Now make a change to your repository -commit to a branch, open a PR, merge it -and push events will appear in both tables.</p>\n<p><span><img alt=\"2026-02-20_16-11-08.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F2026_02_20_16_11_08_fbcc3df256.png&w=2048&q=75\"></span></p>\n<h3 id=\"testing-signature-validation\"></h3>\n<p>To confirm the validation is working, go back to GitHub, change the webhook secret to something different, then make another commit.</p>\n<p><code>webhook_staging</code> will have the new rows but <code>webhook_logs</code> won't - the materialized view computed a different HMAC and filtered them out.</p>\n<p><span><img alt=\"Webhook Diagram for Blog.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FWebhook_Diagram_for_Blog_ae59da5240.jpg&w=2048&q=75\"></span></p></div>"
