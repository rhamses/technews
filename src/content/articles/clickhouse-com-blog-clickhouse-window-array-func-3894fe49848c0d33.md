This query uses two powerful features of ClickHouse: window and array functions.</p>\n<p>Window functions have been available in ClickHouse since 21.5. <a target=\"_blank\" href=\"https://www.postgresql.org/docs/9.1/tutorial-window.html\">PostgreSQL's documentation</a> does a great job of summarizing this SQL capability:</p>\n<blockquote>\n  <p>A window function performs a calculation across a set of table rows that are somehow related to the current row. This is comparable to the type of calculation that can be done with an aggregate function. But unlike regular aggregate functions, the use of a window function does not cause rows to become grouped into a single output row - the rows retain their separate identities. The window function is able to access more than just the current row of the query result.</p>\n</blockquote>\n<p>We often find new users benefit from an example to fully comprehend the power of this capability and its core concepts.  In this post, we will use the solution for the question “Which author has made commits for the most number of consecutive days?” from our recent analysis of the ClickHouse Git repository to introduce window functions. This query also provides us with the opportunity to utilize <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/#arraycountfunc-arr1-\">array functions</a>: a powerful feature of ClickHouse that experienced users turn to when a specific operator is not available.</p>\n<p>All examples can be reproduced in our <a target=\"_blank\" href=\"https://sql.clickhouse.com/?query_id=DCQPNPAIMAQXRLHYURLKVJ\">play.clickhouse.com</a> environment (see the <code>git_clickhouse</code> database). The number of rows is controlled by a “window”, which is defined by either a number of <code>ROWS</code> or a <code>RANGE</code>. A separate window can also be created for each of the unique values of a column - similar to an aggregate function, via a <code>PARTITION BY</code> clause. A value can be computed for the row using a function across the window values.  The diagram below visualizes this window concept for some artificial data. In the example, we have three columns. The <code>country</code> column, is used to partition the data into multiple windows.</p>\n<p>An obvious example that might use these windows is a moving average per country - the following clause computes a moving average of the temperate over the last 5 points per country.</p>\n<div><pre><code><span><span>avg</span>(temperature) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> country <span>ORDER</span> <span>BY</span> <span>day</span> <span>ASC</span></span>\n<span><span>Rows</span> <span>BETWEEN</span> <span>5</span> PRECEDING <span>AND</span> <span>CURRENT</span> <span>ROW</span>) <span>AS</span> moving_avg_temp</span></code></pre></div>\n<p><span><img alt=\"window-function-example.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fwindow_function_example_e60ebbc235.png&w=2048&q=75\"></span></p>\n<p>They are a few key parts to the syntax:</p>\n<ul>\n<li>The <code>OVER</code> clause creates the window itself</li>\n<li>The <code>PARTITION BY</code> creates a window per value of country</li>\n<li>The <code>ORDER BY</code> controls the order of the peers of the current column. Without this, all of the other values in the result would be considered peers.</li>\n<li>The <code>ROWS</code> clause defines the number of rows to consider, known as a frame. We have a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/window-functions/#functions\">number of options</a> to define the range. Here we use <code>BETWEEN 5 PRECEDING AND CURRENT ROW</code> to specify a frame size starting from 5 rows preceding up to the current row (see the frames highlighted in orange in the drawing above). The <code>RANGE</code> clause is an alternative to this and defines the rows as a relationship to the current row, e.g., value difference.</li>\n</ul>\n<p>Now let's apply this functionality to our git commits and use this to solve our question. As you may recall from our <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-git-community-commits\">previous blog</a> and <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/github\">documentation</a>, the <code>git-import</code> tool generates a row for every commit in the repository. To answer our question, we only need two fields: <code>time</code> and <code>author</code>. Using these we need one row per author / day pair.  This is solved with a trivial <code>GROUP BY</code> using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/date-time-functions/#tostartofday\">toStartOfDay</a> function.</p>\n<pre><p>\nSELECT author, toStartOfDay(time) AS day\nFROM git.commits\nGROUP BY author, day\nORDER BY author ASC, day ASC\nLIMIT 10\n<span>\n┌─author──────────────────────┬─────────────────day─┐\n│ 1lann                       │ 2022-03-07 00:00:00 │\n│ 20018712                    │ 2020-09-17 00:00:00 │\n│ 243f6a8885a308d313198a2e037 │ 2020-12-10 00:00:00 │\n│ 3ldar-nasyrov               │ 2021-03-16 00:00:00 │\n│ 821008736@qq.com            │ 2019-04-26 00:00:00 │\n│ ANDREI STAROVEROV           │ 2021-05-09 00:00:00 │\n│ ANDREI STAROVEROV           │ 2021-05-10 00:00:00 │\n│ ANDREI STAROVEROV           │ 2021-05-11 00:00:00 │\n│ ANDREI STAROVEROV           │ 2021-05-13 00:00:00 │\n│ ANDREI STAROVEROV           │ 2021-05-14 00:00:00 │\n└─────────────────────────────┴─────────────────────┘\n</span>\n10 rows in set. For this, we need to create a window per author via a <code>PARTITION BY</code>, and simply grab the preceding row using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/reference/any/\">any</a> function i.e.,</p>\n<div><pre><code><span><span>any</span>(<span>day</span>) <span>OVER</span> (<span>PARTITION</span> <span>BY</span> author <span>ORDER</span> <span>BY</span> <span>day</span> <span>ASC</span> <span>ROWS</span> <span>BETWEEN</span> <span>1</span></span>\n<span>PRECEDING <span>AND</span> <span>CURRENT</span> <span>ROW</span>) <span>AS</span> previous_commit</span></code></pre></div>\n<p>We visualize this step below. Note the importance of the <code>ORDER BY</code>, which sorts the values within each partition’s window:</p>\n<p><span><img alt=\"window-function-example-2.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fwindow_function_example_2_9dd318d7f0.png&w=2048&q=75\"></span></p>\n<p>Now that we have the previous day as a column <code>previous_commit</code>, we can compute the difference in days with the current value using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/date-time-functions/#date_diff\">dateDiff</a> function. Finally, we add a <code>consecutive</code> column <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/conditional-functions/#if\">using a conditional </a>- set to 1 if the difference is 1, 0 otherwise.</p>\n<pre><p>\nSELECT\n    author,\n    toDate(day) as day,\n    any(day) OVER (PARTITION BY author ORDER BY day ASC ROWS BETWEEN 1 PRECEDING AND CURRENT ROW) AS previous_commit,\n    dateDiff('day', previous_commit, day) AS day_diff,\n    if(day_diff = 1, 1, 0) AS consecutive\nFROM\n(\n   SELECT author, toStartOfDay(time) AS day FROM git.commits GROUP BY author, day ORDER BY author ASC, day ASC\n)\nLIMIT 10\n</p> <a target=\"_blank\" href=\"https://sql.clickhouse.com/?query_id=1BSPOBWAT6PUOCYXYNPNML\">✎</a>\n</pre>\n<pre><p><span>\n┌─author──────────────────────┬────────day─┬─previous_commit─┬─day_diff─┬─consecutive─┐\n│ 1lann                       │ 2022-03-07 │      2022-03-07 │        0 │           0 │\n│ 20018712                    │ 2020-09-17 │      2020-09-17 │        0 │           0 │\n│ 243f6a8885a308d313198a2e037 │ 2020-12-10 │      2020-12-10 │        0 │           0 │\n│ 3ldar-nasyrov               │ 2021-03-16 │      2021-03-16 │        0 │           0 │\n│ 821008736@qq.com            │ 2019-04-26 │      2019-04-26 │        0 │           0 │\n│ ANDREI STAROVEROV           │ 2021-05-09 │      2021-05-09 │        0 │           0 │\n│ ANDREI STAROVEROV           │ 2021-05-10 │      2021-05-09 │        1 │           1 │\n│ ANDREI STAROVEROV           │ 2021-05-11 │      2021-05-10 │        1 │           1 │\n│ ANDREI STAROVEROV           │ 2021-05-13 │      2021-05-11 │        2 │           0 │\n│ ANDREI STAROVEROV           │ 2021-05-14 │      2021-05-13 │        1 │           1 │\n└─────────────────────────────┴────────────┴─────────────────┴──────────┴─────────────┘\n</span>\n10 rows in set. We simply need to identify the longest sequence of “1s” for the <code>consecutive</code> column for each author. To solve this, we turn to array functions.</p>\n<h2 id=\"counting-consecutive-values\"></h2>\n<p>Arrays in ClickHouse are a first-class citizen and can be processed with a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions\">wide range of functions</a>. These functions mean it can often be beneficial to orientate our data into an array to solve problems that otherwise appear pretty complex. Placing our earlier query in a CTE <code>commit_days</code>, we can find solve our consecutive 1s problem with a few lines:</p>\n<div><pre><code><span><span>WITH</span> commit_days <span>AS</span></span>\n<span>    (</span>\n<span>        <span>/</span><span>/</span> earlier query</span>\n<span>    )</span>\n<span><span>SELECT</span></span>\n<span>    author,</span>\n<span>    arrayMax(arrayMap(x <span>-</span><span>&gt;</span> length(x), arraySplit(x <span>-</span><span>&gt;</span> (x <span>=</span> <span>0</span>), groupArray(consecutive)))) <span>-</span> <span>1</span> <span>AS</span> max_consecutive_days</span>\n<span><span>FROM</span> commit_days <span>GROUP</span> <span>BY</span> author <span>ORDER</span> <span>BY</span> max_consecutive_days <span>DESC</span></span>\n<span>LIMIT <span>10</span></span></code></pre></div>\n<p>A lot is going on here, concealed by the fact that many array functions accept a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/#higher-order-functions\">high order function</a> (in this case another array function) as an input. Below, using <code>myrcc</code> as an example, we show how:</p>\n<ul>\n<li>\n<p>the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/reference/grouparray/\">groupArray</a> function is used to produce a row per author with the <code>consecutive</code> values as an array</p>\n</li>\n<li>\n<p>the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/#arraysplitfunc-arr1-\">arraySplit</a> function converts this into a list of sub-arrays using a lambda conditional which splits on 0s.</p>\n</li>\n<li>\n<p>Any consecutive sequences of 1s becomes a subarray with a leading 0</p>\n</li>\n<li>\n<p>An <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/#arraymapfunc-arr1-\">arrayMap</a> function next converts this into a list of the subarray lengths</p>\n</li>\n<li>\n<p>The largest number in this list (minus 1) is, in effect, the author's longest sequence of commits. The <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/array-functions/#arraymax\">arrayMax</a> function makes this trivial.</p>\n</li>\n</ul>\n<p><span><img alt=\"Bite-sized_git-array-functions_v2.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FBite_sized_git_array_functions_v2_4dec386f4a.png&w=2048&q=75\"></span></p>\n<p>Putting this all together, we need to sort by the largest consecutive count first. So who is the committer with the longest sequence of uninterrupted work?</p>\n<pre><p>\nWITH commit_days AS\n    (\n        SELECT\n            author,\n            toDate(day) AS day,\n            any(day) OVER (PARTITION BY author ORDER BY day ASC ROWS BETWEEN 1 PRECEDING AND CURRENT ROW) AS previous_commit,\n            dateDiff('day', previous_commit, day) AS days_since_last,\n            if(days_since_last = 1, 1, 0) AS consecutive\n        FROM\n        (\n            SELECT\n                author,\n                toStartOfDay(time) AS day\n            FROM git.commits\n            GROUP BY\n                author,\n                day\n            ORDER BY\n                author ASC,\n                day ASC\n        )\n    )\nSELECT\n    author,\n    arrayMax(arrayMap(x -&gt; length(x), arraySplit(x -&gt; (x = 0), groupArray(consecutive)))) - 1 AS max_consecutive_days\nFROM commit_days\nGROUP BY author\nORDER BY max_consecutive_days DESC\nLIMIT 5\n<span>\n┌─author───────────┬─max_consecutive_days─┐\n│ kssenii          │                   32 │\n│ Alexey Milovidov │                   30 │\n│ alesapin         │                   26 │\n│ Azat Khuzhin     │                   23 │\n│ Nikolai Kochetov │                   15 │\n└──────────────────┴──────────────────────┘\n</span>\n5 rows in set.
