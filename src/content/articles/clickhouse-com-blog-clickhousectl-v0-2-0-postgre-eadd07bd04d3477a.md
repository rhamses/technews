contentHtml: "<div><p>We're releasing <code>clickhousectl</code> v0.2.0. This release adds Postgres (local and ClickHouse Cloud managed), ClickPipes management for the full set of supported sources, SQL over HTTP against Cloud services, a few agent-friendly output tweaks, and a standalone Rust client library for the ClickHouse Cloud API.</p>\n<p>If you already have <code>clickhousectl</code> installed, update with:</p>\n<div><pre><code><span>clickhousectl update</span></code></pre></div>\n<p>If you don't, install it with:</p>\n<div><pre><code><span>curl https://clickhouse.com/cli | sh</span></code></pre></div>\n<h2 id=\"postgres\"></h2>\n<p><code>clickhousectl</code> now manages Postgres, too. Just like ClickHouse, you can use it locally (Docker-backed) and in ClickHouse Cloud (managed Postgres). Develop locally, and go to Cloud when you're ready for prod. Postgres managed by ClickHouse gives you the <a target=\"_blank\" href=\"https://postgresbench.clickhouse.com/\">fastest, enterprise-grade cloud Postgres</a>, backed by NVMes, with HA, read replicas, and point-in-time restore.</p>\n<p>Local Postgres runs as a Docker container, keyed on <code>(name, major version)</code>. Data lives under <code>.clickhouse/servers/&lt;name&gt;-pg&lt;major&gt;/data/</code>, so a single name can host multiple Postgres majors with isolated state. Supported versions are 16, 17, and 18.</p>\n<div><pre><code><span><span># Pre-pull an image (optional; start pulls on demand)</span></span>\n<span>clickhousectl <span>local</span> install postgres@16</span>\n<span></span>\n<span><span># Start a Postgres instance</span></span>\n<span>clickhousectl <span>local</span> postgres start --name dev --version 16 --port 5433</span>\n<span></span>\n<span><span># Connect with psql (host psql if installed, otherwise docker exec)</span></span>\n<span>clickhousectl <span>local</span> postgres client --name dev --query <span>\"SELECT 1\"</span></span>\n<span></span>\n<span><span># Write connection vars to .env</span></span>\n<span>clickhousectl <span>local</span> postgres dotenv --name dev</span>\n<span></span>\n<span><span># Stop / remove</span></span>\n<span>clickhousectl <span>local</span> postgres stop dev</span>\n<span>clickhousectl <span>local</span> postgres remove dev</span></code></pre></div>\n<p>ClickHouse and Postgres servers share <code>server list</code>, so you can see both engines side by side in a single command.</p>\n<p>Cloud-managed Postgres requires a <a target=\"_blank\" href=\"https://console.clickhouse.cloud/signUp\">ClickHouse Cloud</a> account, and the CLI must be authenticated with API Keys.</p>\n<div><pre><code><span><span># Create a managed Postgres service</span></span>\n<span>clickhousectl cloud postgres create \\</span>\n<span>  --name my-pg \\</span>\n<span>  --region us-east-1 \\</span>\n<span>  --size c6gd.large \\</span>\n<span>  --storage-gb 100 \\</span>\n<span>  --pg-version 17 \\</span>\n<span>  --ha-type <span>sync</span></span></code></pre></div>\n<h2 id=\"clickpipes\"></h2>\n<p><code>clickhousectl</code> now creates and manages <a target=\"_blank\" href=\"https://clickhouse.com/docs/integrations/clickpipes\">ClickPipes</a>, ClickHouse Cloud's managed connectors for streaming and batch ingest.</p>\n<p>Supported sources:</p>\n<div><table><thead><tr><th>Source</th><th>Mode</th><th>Subcommand</th></tr></thead><tbody><tr><td>S3 / GCP / Azure Blob</td><td>Batch</td><td><code>clickpipe create object-storage</code></td></tr><tr><td>Kafka / Redpanda / Confluent / MSK</td><td>Streaming</td><td><code>clickpipe create kafka</code></td></tr><tr><td>Amazon Kinesis</td><td>Streaming</td><td><code>clickpipe create kinesis</code></td></tr><tr><td>Postgres</td><td>CDC</td><td><code>clickpipe create postgres</code></td></tr><tr><td>MySQL</td><td>CDC</td><td><code>clickpipe create mysql</code></td></tr><tr><td>MongoDB</td><td>CDC</td><td><code>clickpipe create mongodb</code></td></tr><tr><td>BigQuery</td><td>Snapshot</td><td><code>clickpipe create bigquery</code></td></tr></tbody></table></div>\n<p>Creating a Kafka pipe:</p>\n<div><pre><code><span>clickhousectl cloud clickpipe create kafka &lt;service-id&gt; \\</span>\n<span>  --name my-kafka-pipe \\</span>\n<span>  --brokers <span>'broker:9092'</span> --topics events \\</span>\n<span>  --format JSONEachRow \\</span>\n<span>  --kafka-type redpanda \\</span>\n<span>  --auth SCRAM-SHA-256 --username user --password pass \\</span>\n<span>  --ca-certificate ./ca.crt \\</span>\n<span>  --database default --table events \\</span>\n<span>  --column <span>\"event_id:Int64\"</span> --column <span>\"name:String\"</span></span></code></pre></div>\n<p>Creating a Postgres CDC pipe:</p>\n<div><pre><code><span>clickhousectl cloud clickpipe create postgres &lt;service-id&gt; \\</span>\n<span>  --name my-pg-pipe \\</span>\n<span>  --host db.example.com --pg-database mydb \\</span>\n<span>  --username pguser --password pgpass \\</span>\n<span>  --table-mapping <span>\"public.users:public_users\"</span> \\</span>\n<span>  --table-mapping <span>\"public.orders:public_orders\"</span></span></code></pre></div>\n<p>Once a pipe is running, you can list, start, stop, scale, resync (for CDC pipes), and delete it:</p>\n<div><pre><code><span>clickhousectl cloud clickpipe list &lt;service-id&gt;</span>\n<span>clickhousectl cloud clickpipe scale &lt;service-id&gt; &lt;clickpipe-id&gt; \\</span>\n<span>  --replicas 2 --cpu-millicores 250 --memory-gb 1</span>\n<span>clickhousectl cloud clickpipe resync &lt;service-id&gt; &lt;clickpipe-id&gt;</span></code></pre></div></div><div><h2 id=\"improvements\"></h2>\n<h3 id=\"querying-clickhouse-services-in-clickhouse-cloud\"></h3>\n<p>Querying ClickHouse services in ClickHouse Cloud no longer requires a local ClickHouse binary to use as the client. The CLI now uses ClickHouse Cloud's Query Endpoints to send SQL over HTTP.</p>\n<p><code>cloud service create</code> provisions a Query Endpoint on new services by default. A new API Key is created that is scoped only to the new service (so it can't be used to go rogue), and the Query Endpoint itself is locked down to the new API Key. The CLI stores the new key alongside your existing API Key. <code>cloud service query</code> then runs SQL over HTTP using that key:</p>\n<div><pre><code><span>clickhousectl cloud service query --name my-service --query <span>\"SELECT 1\"</span></span>\n<span>clickhousectl cloud service query --<span>id</span> &lt;service-id&gt; \\</span>\n<span>  --query <span>\"SELECT count() FROM system.tables\"</span> \\</span>\n<span>  --format JSONEachRow</span>\n<span><span>echo</span> <span>\"SELECT 1+1\"</span> | clickhousectl cloud service query --name my-service</span></code></pre></div>\n<p>For existing services without a Query Endpoint or stored key, <code>cloud service query</code> provisions one lazily on first use. Pass <code>--no-auto-enable</code> to fail instead, or <code>--no-enable-query</code> on <code>service create</code> to skip the create-time hook.</p>\n<p>The query endpoint binding is created with role <code>sql_console_admin</code>, which grants read and write inside the bound service only. The API key itself has no org-level roles, so the binding is the only thing granting access: a stolen key can only hit the service it was minted for. <code>cloud service delete</code> removes the stored key from <code>credentials.json</code>.</p>\n<h3 id=\"experience\"></h3>\n<p>Two small changes that make a difference when an agent (or a human) is reading output.</p>\n<p><strong>Lighter tables.</strong> Tabular output now uses Markdown-style tables with ASCII separators instead of rounded Unicode box-drawing characters. The result is friendlier to copy into a markdown file, a PR description, or a chat with an LLM, and uses fewer tokens when an agent is reading it.</p>\n<p><strong><code>--debug</code> for credential resolution.</strong> Pass <code>--debug</code> to any <code>cloud</code> command to print the resolved credential source and the API URL to stderr before the command runs.</p>\n<div><pre><code><span>clickhousectl cloud --debug service list</span>\n<span><span># [debug] auth source: credentials file (.clickhouse/credentials.json)</span></span>\n<span><span># [debug] api url: https://api.clickhouse.cloud/v1</span></span>\n<span><span># ... normal output ...</span></span></code></pre></div>\n<h2 id=\"rust-clickhouse-cloud-api-client-library\"></h2>\n<p><code>clickhousectl</code> manages ClickHouse Cloud using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/cloud/manage/api/api-overview\">ClickHouse Cloud API</a>. The Cloud API code is now its own crate, <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhousectl/tree/main/crates/clickhouse-cloud-api\"><code>clickhouse-cloud-api</code></a>, a typed async Rust client.</p>\n<p>The CLI is now a consumer of this crate like any other downstream user.</p>\n<h2 id=\"new-contributors\"></h2>\n<p>Thanks to the new contributors who shipped code in this release:</p>\n<ul>\n<li>Kaushik Iska (<a target=\"_blank\" href=\"https://github.com/iskakaushik\">@iskakaushik</a>)</li>\n<li>Mark Dawson (<a target=\"_blank\" href=\"https://github.com/markdawson\">@markdawson</a>)</li>\n</ul>\n<h2 id=\"what-s-next\"></h2>\n<p><code>clickhousectl</code> is only 5 weeks old at the time of releasing v0.2.0, but already over 5000 ClickHouse developers are using it to build with ClickHouse locally and in Cloud.</p>\n<p>There's still lots of features to support: work is already underway for <a target=\"_blank\" href=\"https://clickhouse.com/cloud/clickstack\">ClickStack</a> (the ClickHouse observability stack), and we're looking into local PeerDB support to mirror the Postgres&lt;&gt;ClickHouse CDC capabilities that are already possible in Cloud.</p>\n<p>Outside of features, we're doing some exciting research into agentic experience (AX) and how we can better optimise the CLI, our APIs, MCP and other surface areas for agents. We're thinking about how we can improve an agent's ability to complete tasks, as well as their consistency, speed, tool calls, and cost. Expect some rapid iteration on the experience side.</p>\n<p><code>clickhousectl</code> is in beta, and we'd love to hear from you: please <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhousectl\">raise issues in the <code>clickhousectl</code> repo</a> and join us in the <a target=\"_blank\" href=\"https://clickhouse.com/slack\">community Slack</a>.</p></div>"
