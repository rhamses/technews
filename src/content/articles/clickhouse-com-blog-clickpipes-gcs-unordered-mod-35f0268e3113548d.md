contentHtml: "<div><blockquote>\n<p><em>Ingest data from Google Cloud Storage into ClickHouse Cloud in <strong>any</strong> <strong>order</strong> for event-driven, blazing-fast analytics. Files are no longer required to follow lexicographical order.</em></p>\n</blockquote>\n<p>A few months ago, we removed one of the biggest usability wrinkles in S3 ClickPipes by <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickpipes-s3-unordered-mode\">supporting ingesting files in any order</a> (<em>aka</em> unordered mode). We’re now extending that functionality to the Google Cloud Storage (GCS) connector, with a little help from <a target=\"_blank\" href=\"https://docs.cloud.google.com/storage/docs/pubsub-notifications\">Google Cloud Pub/Sub notifications for Cloud Storage</a>.</p>\n<p><span><img alt=\"gcs-unordered-mode.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fgcs_unordered_mode_fd4559c5df.png&w=2048&q=75\"></span></p>\n<p>This means that you no longer need to worry about ensuring files land in your bucket in lexicographical order: with unordered mode, we’ll simply listen to notifications for new files and ingest files as they land in the GCS bucket. Whether you’re dealing with backfills, retries, late-arriving data, or some other source of out-of-orderness — this is now covered.</p></div><div><h2 id=\"user-content-why-is-this-a-big-deal\"></h2>\n<p>By default, the GCS ClickPipe assumes files are added to a bucket in lexicographical order, and relies on this implicit order to ingest files sequentially. This means that any new file <em>must</em> be lexically greater than the last ingested file, which isn’t always true in the real world. For example, files named <code>events_2024-12-01.parquet</code>, <code>events_2024-12-02.parquet</code>, and <code>events_2024-12-03.parquet</code> will be ingested in order, but if a backfill named <code>events_2024-11-30.parquet</code> lands later in the bucket, it will be ignored.</p>\n<p>Not cool.</p>\n<p>With unordered mode, this limitation no longer applies: instead of polling the bucket every 30 seconds looking for the next file to process, the ClickPipe waits for new file notifications. When a notification arrives, ClickPipes just goes and processes that file regardless of its relative order to previously processed files. Although this requires a little extra configuration, it's a more robust and scalable approach when you’re dealing with millions of objects.</p>\n<h2 id=\"user-content-how-does-it-work\"></h2>\n<p>To configure a GCS ClickPipe to ingest files that don’t have an implicit order, you need to configure notifications from the bucket to a Pub/Sub topic. ClickPipes can then listen for <code>OBJECT_FINALIZE</code> events and ingest any new files regardless of the file naming convention.</p>\n<p><span><img alt=\"564927906-277a62f5-799d-4d30-951d-35ebc8b346f2.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F564927906_277a62f5_799d_4d30_951d_35ebc8b346f2_56abffa4ed.jpg&w=2048&q=75\"></span></p>\n<p><em><strong>Unordered mode:</strong> Files land in GCS in <strong>any order</strong> (A) and trigger Pub/Sub notifications (B-C). ClickPipes polls and processes files in the specified path, using a metadata store to track state (1-5). Data is inserted into the target tables with exactly-once guarantees (6).</em></p>\n<p><em><strong>“What about failures?”</strong></em> Since the steps above span multiple systems and don’t happen in a single transaction, failures can occur at any step — reading from GCS, marking files as processed, inserting data into ClickHouse, and so on. If a failure occurs, ClickPipes automatically reprocesses the batch. <em><strong>\"But what about duplicates?”</strong></em> Even if files are reprocessed multiple times, the GCS ClickPipe guarantees exactly-once semantics, so no duplicates make it into your target table.</p>\n<p>Let’s see it in action!</p>\n<h3 id=\"user-content-create-a-pubsub-topic\"></h3>\n<p><em>The following instructions assume you already have a GCS bucket with some data in it, as well as enough permissions to manage IAM roles and create new resources in your Google Cloud account.</em></p>\n<p><strong>1.</strong> In the Google Cloud Console, navigate to <strong>Pub/Sub &gt; Topics &gt; Create topic</strong>. Create a new topic with a default subscription and note the <strong>Topic Name</strong>.</p>\n<p><strong>2.</strong> Configure a <a target=\"_blank\" href=\"http://docs.cloud.google.com/iam/docs/keys-create-delete\">service account</a> with the minimum required set of permissions to allow ClickPipes to list and fetch objects in the specified bucket, as well as consume and monitor notifications from the Pub/Sub subscription.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fgcs_unordered_mar2026_image1_5969bf8711.png&w=2048&q=75\"></span></p>\n<p><strong>3.</strong> Configure your GCS bucket to send notifications to Pub/Sub when a new object lands in the bucket. This step cannot be performed in the Google Cloud Console, so you must use <code>gcloud</code> or your preferred programmatic interface.</p>\n<p><strong>3.1.</strong> Using <code>gcloud</code>, add a notification configuration to your GCS bucket that triggers notifications for the <code>OBJECT_FINALIZE</code> <a target=\"_blank\" href=\"https://docs.cloud.google.com/storage/docs/pubsub-notifications#events\">event type</a>:</p>\n<div><pre><code><span><span># Create a Pub/Sub notification for new objects in the bucket</span></span>\n<span>gcloud storage buckets notifications create <span>\"gs://<span>${YOUR_BUCKET_NAME}</span>\"</span> \\</span>\n<span>--topic=<span>\"projects/<span>${YOUR_PROJECT_ID}</span>/topics/<span>${YOUR_TOPIC_NAME}</span>\"</span> \\</span>\n<span>--event-types=<span>\"OBJECT_FINALIZE\"</span> \\</span>\n<span>--payload-format=<span>\"json\"</span></span>\n<span></span>\n<span><span># List the Pub/Sub notifications in the bucket</span></span>\n<span>gcloud storage buckets notifications describe</span></code></pre></div>\n<p>We strongly recommend configuring a <a target=\"_blank\" href=\"https://docs.cloud.google.com/pubsub/docs/dead-letter-topics\"><strong>Dead-Letter topic</strong></a>, too, so it's easier to debug and retry failed notifications. But that’s it — you’re ready to create a ClickPipe to continuously ingest data from your bucket whenever a new file lands!</p>\n<h3 id=\"user-content-create-a-clickpipe\"></h3>\n<p><strong>1.</strong> In the ClickHouse Cloud console, navigate to <strong>Data Sources &gt; Create ClickPipe</strong>, then choose <strong>Google Cloud Storage</strong>. Enter the details to connect to your GCS bucket, using <strong>Service account</strong> as the authentication method and providing the <code>.json</code> service account key.</p>\n<p><strong>2.</strong> Toggle on <strong>Continuous ingestion</strong>, then select the new <strong>Any order</strong> ingestion mode to enable unordered mode. Enter the path to your Pub/Sub subscription.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fgcs_unordered_mar2026_image5_01fc577707.png&w=2048&q=75\"></span></p>\n<p><strong>3.</strong> Click <strong>Incoming data</strong>. Define a <strong>Sorting key</strong> for the target table (very important) and make any necessary adjustments to the mapped schema. Finally, configure a role for the ClickPipes database user.</p>\n<p><span><img alt=\"cp-gcs-unordered.gif\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcp_gcs_unordered_26a91e8d0f.gif&w=2048&q=75\"></span></p>\n<p><strong>4.</strong> <strong>Sit back and relax.</strong> ClickPipes will now perform an initial scan of your bucket, then start processing files as new notification events arrive. 🚀</p>\n<p>If that seems like a lot of clicking, the good news is that ClickPipes is fully supported in the <a target=\"_blank\" href=\"https://registry.terraform.io/providers/ClickHouse/clickhouse/latest/docs\">ClickHouse Terraform provider</a>, so you can configure this setup as code from start to finish.</p>\n<h2 id=\"user-content-whats-next\"></h2>\n<p>We’re excited to enable more complex ingestion patterns from object storage into ClickHouse Cloud with the new unordered mode in GCS ClickPipes — you get the same fully-managed, full-speed experience with a little extra flexibility! This feature is also available for Amazon S3 as a data source. We plan to extend support to Azure Blob Storage in the near future, to ensure feature parity across <strong>all</strong> Object Storage ClickPipes.</p>\n<p>If you have any feedback or run into any snags while setting up ClickPipes, reach out to our team!
