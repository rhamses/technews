contentHtml: "<div><p>Migrating <a target=\"_blank\" href=\"https://www.postgresql.org/\">Postgres</a> between providers often involves more manual effort than users expect. This blog talks about the challenges with current migration paths, and how the new <strong>Postgres to Postgres ClickPipes</strong> in <a target=\"_blank\" href=\"https://clickhouse.com/cloud/postgres\">Postgres by ClickHouse</a> (now in <a target=\"_blank\" href=\"https://clickhouse.com/blog/postgres-managed-by-clickhouse-beta\">public beta</a>!) enables seamless, <strong>fully managed</strong> migrations with minimal downtime and operational overhead.</p>\n<h2 id=\"user-content-the-complexity-of-postgres-migrations-today\"></h2>\n<p>Achieving a true apples-to-apples migration experience is critical for Postgres-to-Postgres migrations. A Postgres database is far more than a collection of tables: indexes, constraints, sequences, triggers, and other database objects each play a role in running core business logic. Preserving these objects correctly is essential to ensuring applications behave identically after the migration.</p>\n<p>Despite this, most managed Postgres providers simply point users to documentation of various tools, and lack a purpose-built fully managed migration tooling.</p>\n<p>Stitching them together into a reliable migration workflow introduces several hassles:</p>\n<ul>\n<li><strong>Operational complexity becomes a barrier to adoption.</strong> Users are expected to install and manage command-line tools, generate schema dumps, restore them correctly, and coordinate the migration process themselves.</li>\n<li><strong>Migrations require expertise that many users don't have.</strong> While <a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/app-pgdump.html\"><code>pg_dump</code></a> and <a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/app-pgrestore.html\"><code>pg_restore</code></a> are powerful tools, they expose users to the intricacies of Postgres. This increases the risk of errors and makes migrations more intimidating.</li>\n<li><strong>Large migrations are slow and opaque.</strong> Standard <code>pg_dump</code> and <code>pg_restore</code> or native logical replication workflows can take hours for large datasets, while providing little visibility into progress or failures. Monitoring these long-running pipelines often becomes an operational burden in itself. <a target=\"_blank\" href=\"https://clickhouse.com/blog/practical-postgres-migrations-at-scale-peerdb#benchmarking-large-postgres-migrations\">This benchmark</a> goes into depth about this.</li>\n<li><strong>Online migrations require highly reliable CDC.</strong> Teams typically rely on Change Data Capture (CDC) to keep the destination continuously synchronized while preparing for a controlled cutover. Since restarting from scratch can be expensive, the CDC pipeline must be highly reliable.</li>\n</ul>\n<h2 id=\"user-content-introducing-postgres-to-postgres-clickpipes\"></h2>\n<p>To address the challenges discussed in the previous section, we built a fully managed Postgres migration service for Postgres by ClickHouse in <a target=\"_blank\" href=\"https://clickhouse.com/cloud\">ClickHouse Cloud</a>. Postgres to Postgres ClickPipes abstracts away much of the operational complexity involved in setting up and running a migration.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fpostgres_clickpipes_jun2026_image3_ef085baf50.jpg&w=2048&q=75\"></span></p>\n<h3 id=\"user-content-automated-schema-dump\"></h3>\n<p>One of its key features is <a target=\"_blank\" href=\"https://github.com/PeerDB-io/peerdb/pull/4283\"><strong>automated schema migration</strong></a>. Instead of requiring users to install and run tools such as <code>pg_dump</code> and <code>psql</code>, ClickPipes performs the schema dump and restore under the hood.</p>\n<p>Since we are abstracting this away from the user, we made sure to cover any corner cases that one might run into. Listing a few salient ones:</p>\n<ul>\n<li>Support for <strong>secure connections</strong> to source. This includes using TLS, certificates and even private links.</li>\n<li>Avoiding conflicts due to <strong>Postgres roles.</strong>  These roles can always be created during cutover and are not necessary for the data movement itself.</li>\n<li>Accounting for differences in source and target <strong>Postgres versions</strong>. pg_dump version and source server versions need to be compatible with one another.</li>\n<li><strong>Single round-trip</strong> connection to apply on destination, reducing latency. Running every statement in the dump file sequentially could be long-running otherwise and run into timeouts.</li>\n<li><strong>Transactional</strong> application of schema dump to allow for <strong>idempotent</strong> retries. This provides flexibility and room for making corrections and changes on the fly without having to recreate the ClickPipe.</li>\n<li>Dump errors immediately shown in ClickPipes UI and also via <strong>notifications</strong>.</li>\n</ul>\n<p>Running these operations inside ClickHouse Cloud also provides the benefit of <strong>colocation</strong> - schema dumps and initial loads are executed close to the source database making it faster than running it on your machine.</p>\n<p>For users with specialized requirements, ClickPipes <strong>also supports a manual mode</strong> that allows custom migration workflows with links to relevant documentation.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fpostgres_clickpipes_jun2026_image2_5477b13b51.png&w=2048&q=75\"></span></p>\n<h3 id=\"user-content-parallel-initial-loads-and-reliable-cdc\"></h3>\n<p>Postgres to Postgres ClickPipes is powered by PeerDB, which provides two key capabilities for online migrations: <strong>parallel initial loads</strong> to reduce the time required to move terabytes from days to hours, and <strong>reliable CDC</strong> always reading the replication slot on source, with support for features such as automatic <strong>column addition</strong> propagation and TOASTs to avoid costly resyncs during cutover.</p>\n<p>For a deeper dive, check out our earlier blog post <a target=\"_blank\" href=\"https://clickhouse.com/blog/practical-postgres-migrations-at-scale-peerdb#benchmarking-large-postgres-migrations\">here</a>.</p>\n<h3 id=\"user-content-retry-mechanisms-and-alerting\"></h3>\n<p>The Postgres to Postgres ClickPipe is resilient to transient errors on both pull and push, with both processes being independent of each other, and every activity being surrounded by retries.</p>\n<p>In addition to robustness, this also allows us to have a smarter <strong>notification system</strong> which can send out emails and UI bell notifications based on the number of failed retries.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fpostgres_clickpipes_jun2026_image1_710956fdde.png&w=2048&q=75\"></span></p>\n<h3 id=\"user-content-demo\"></h3>\n<p>The following demo showcases the onboarding experience where you will see a ClickPipe created with just a few clicks with a clean, step-by-step wizard.</p></div><div><h2 id=\"user-content-next-steps\"></h2>\n<p>With
