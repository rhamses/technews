contentHtml: "<div><p>When you’re on the receiving end of a data integration pipeline, you quickly learn that real-world data knows no rules. Sometimes it arrives, sometimes it doesn’t. Then it arrives twice, or maybe out-of-order. For object storage, in particular, this creates an interesting problem: how do you efficiently track what's new without scanning too many objects all the time?</p>\n<p>Like most tools out there, <a target=\"_blank\" href=\"https://clickhouse.com/cloud/clickpipes?utm_source=google.com&utm_medium=paid_search&utm_campaign=21862172336_181837693625&utm_content=764403839926&utm_term=clickpipes_g_c&gad_source=1&gad_campaignid=21862172336&gclid=CjwKCAjwisnGBhAXEiwA0zEOR3kM4ZBQO0_NpfRPpYU2YWG5onZqwF-Kf8m845Ol2IJeyN96r0k8DxoCit4QAvD_BwE\">ClickPipes</a> didn’t have a good solution for this problem, and simply expected you to ensure there were <em>some</em> rules to guarantee files landed in your bucket in lexicographical order. <strong>Not anymore!</strong></p>\n<p><span><img alt=\"image6.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fimage6_b5104fce2a.png&w=2048&q=75\"></span></p>\n<p>We’ve added a new mode to the S3 ClickPipe that allows ingesting files in any order using S3 Event Notifications via <a target=\"_blank\" href=\"https://aws.amazon.com/sqs/\">Amazon SQS</a>. Whether you’re dealing with backfills, retries, late-arriving data, or some other source of out-of-orderness — we handle it.</p></div><div><h2 id=\"why-is-this-a-big-deal\"></h2>\n<p>By default, the S3 ClickPipe assumes files are added to a bucket in lexicographical order, and relies on this implicit order to ingest files sequentially. Besides not rolling off the tongue, lexicographical order means that any new file <em>must</em> be lexically greater than the last ingested file. For example, files named <code>events_2024-12-01.parquet</code>, <code>events_2024-12-02.parquet</code>, and <code>events_2024-12-03.parquet</code> will be ingested in order, but if a backfill named <code>events_2024-11-30.parquet</code> lands later in the bucket, it will be ignored.</p>\n<p>This is not great.</p>\n<p>With unordered mode, this limitation no longer applies: instead of polling your bucket every 30 seconds looking for the next file to process, the ClickPipe waits to be notified that a new file has landed. When a notification arrives, ClickPipes just goes and processes that file regardless of its relative order to previously processed files. Although this requires you to configure event notifications, it's a more robust and performant alternative to the otherwise common approach of listing all objects in scope on every sync — which scales poorly and gets expensive fast when you have millions of objects.</p>\n<h2 id=\"how-does-it-work\"></h2>\n<p>To configure an S3 ClickPipe to ingest files that don’t have an implicit order, you need to set up an <a target=\"_blank\" href=\"https://aws.amazon.com/sqs/\">Amazon Simple Queue System (SQS)</a> queue connected to the bucket. ClickPipes can then listen for <code>ObjectCreated</code> events in the queue that match the specified path.</p>\n<p><span><img alt=\"ClickPipes S3 Blog Banner.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FClick_Pipes_S3_Blog_Banner_08474993cb.jpg&w=2048&q=75\"></span></p>\n<p><strong>Unordered mode:</strong> Files land in S3 in <strong>any order</strong> (A) and trigger SQS notifications (B-C). ClickPipes polls and processes files in the specified path, using a metadata store to track state (1-5). Data is inserted into the target tables with exactly-once guarantees (6).</p>\n<p><em><strong>“What about failures?”</strong></em> Since the steps above span multiple systems and don’t happen in one big transaction™️, failures can occur at any step — reading from S3, marking files as processed, inserting data into ClickHouse, and so on. If a failure occurs, ClickPipes automatically reprocesses the batch. <em>“<strong>But what about duplicates?”</strong></em> Even if files are reprocessed multiple times, the S3 ClickPipe guarantees exactly-once semantics, so no duplicates make it into your target table.</p>\n<p>Let’s see it working!</p>\n<h3 id=\"create-an-amazon-sqs-queue\"></h3>\n<p><em>The following instructions assume you already have an S3 bucket with some data in it, as well as enough permissions to manage IAM roles and create new resources in your AWS account.</em></p>\n<p><strong>1.</strong> In the AWS Console, navigate to <strong>Simple Queue Service &gt; Create queue</strong>.
