Charts need to automatically respond to dashboard time ranges, intervals, and filters, without users having to manually rewrite queries every time the dashboard changes.</p>\n<p>This is where query parameters and macros become critical.</p>\n<p>Query parameters expose dashboard state directly to the SQL query. These include values such as the dashboard start time, end time, and interval size. They use ClickHouse parameter syntax such as <code>{startDateMilliseconds:Int64}</code> and <code>{intervalSeconds:Int64}</code> and allow queries to dynamically adapt to the active dashboard context.</p>\n<p>Macros build on top of these parameters and provide shorthand expressions for common observability workflows. For example, macros such as <code>$__filters</code> and <code>$__sourceTable</code> automatically inject dashboard filters and source table references directly into the query. Time-filtering and bucketing macros further simplify the creation of dynamic time-series visualizations.</p>\n<p>One of our goals when building SQL-based visualizations was to make the experience feel immediately familiar to existing Grafana and ClickHouse users. As a result, many of the supported macros intentionally mirror the conventions used by the <a target=\"_blank\" href=\"https://github.com/grafana/clickhouse-datasource\">ClickHouse Grafana plugin</a>. In many cases, users can bring existing SQL queries directly from Grafana into ClickStack and have them work with minimal or no modification.</p>\n<p>This compatibility is an important design philosophy for us. Teams already invest significant time building operational queries, dashboards, and alerting logic, and we wanted SQL-based visualizations to integrate naturally into existing workflows rather than forcing users to rewrite everything from scratch.</p>\n<p>These macros also ensure that SQL charts remain fully interactive inside dashboards. When a user changes the dashboard time range, applies a filter, or switches the underlying source, the SQL query automatically adapts to reflect the new context.</p>\n<p>Considering the previous visualization and query, if we apply a dashboard time range and service-level filter, the macros automatically inject the corresponding SQL conditions into the query execution while preserving the visualization logic.</p></div><div><p>For users interested in the full list of supported macros and query parameters, see the SQL-based visualizations documentation:<a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/observability/clickstack/dashboards/sql-visualizations?utm_source=chatgpt.com\"> SQL-based visualizations documentation</a>.</p>\n<h3 id=\"charting-query-results\"></h3>\n<p>While SQL-based visualizations provide full flexibility over query logic, ClickStack still needs to understand how returned query columns should map onto visualization elements.
