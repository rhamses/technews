Below is a list with descriptions for each chart. They are grouped into three categories to help you navigate them.</p>\n<p><strong>ClickHouse specific</strong>:</p>\n<p>These metrics are tailored to monitor the health and performance of your ClickHouse instance.</p>\n<ul>\n<li>Queries Per Second: Tracks the rate of queries being processed.</li>\n<li>Selected Rows/Sec: Indicates the number of rows being read by queries.</li>\n<li>Inserted Rows/Sec: Measures the data ingestion rate.</li>\n<li>Total MergeTree Parts: Shows the number of active parts in MergeTree tables, helping identify unbatched inserts.</li>\n<li>Max Parts for Partition: Highlights the maximum number of parts in any partition.</li>\n<li>Queries Running: Displays the number of queries currently executing.</li>\n<li>Selected Bytes Per Second: Indicates the volume of data being read by queries.</li>\n</ul>\n<p><strong>System health specific</strong>:</p>\n<p>Monitoring the underlying system is just as important as watching ClickHouse itself.</p>\n<ul>\n<li>IO Wait: &#160;Tracks I/O wait times.</li>\n<li>CPU Wait: Measures delays caused by CPU resource contention</li>\n<li>Read From Disk: Tracks the number of bytes read from disks or block devices</li>\n<li>Read From Filesystem: Tracks the number of bytes read from the filesystem, including page cache.</li>\n<li>Memory (tracked, bytes): Shows memory usage for processes tracked by ClickHouse.</li>\n<li>Load Average (15 minutes): Report the current load average 15 from the system</li>\n<li>OS CPU Usage (Userspace): CPU Usage running userspace code</li>\n<li>OS CPU Usage (Kernel): CPU Usage running kernel code</li>\n</ul>\n<p><strong>ClickHouse Cloud specific</strong>:</p>\n<p>ClickHouse Cloud stores data using object storage (S3 type). Monitoring this interface can help detect issues.</p>\n<ul>\n<li>S3 Read wait: Measures the latency of read requests to S3.</li>\n<li>S3 read errors per second: Tracks the read errors rate.&#160;</li>\n<li>Read From S3 (bytes/sec): Tracks the rate data is read from S3 storage.</li>\n<li>Disk S3 write req/sec: &#160;Monitors the frequency of write operations to S3 storage.</li>\n<li>Disk S3 read req/sec: &#160;Monitors the frequency of read operations to S3 storage.</li>\n<li>Page cache hit rate: The hit rate of the page cache&#160;</li>\n<li>Filesystem cache hit rate: Hit rate of the filesystem cache</li>\n<li>Filesystem cache size: The current size of the filesystem cache</li>\n<li>Network send bytes/sec: Tracks the current speed of incoming network traffic</li>\n<li>Network receive bytes/sec: Tracks the current speed of outbound network traffic</li>\n<li>Concurrent network connections: Tracks the number of current concurrent network connections</li>\n</ul>\n<h2 id=\"customize-default-charts\"></h2>\n<p>Each visualization has a SQL query associated with it that populates it. id=\"identifying-issues-with-the-advanced-dashboard\"></h2>\n<p>Having this real-time view of the health of your ClickHouse service greatly helps mitigate issues before they impact your business or help solve them. Below are a few issues you can spot using the advanced dashboard.</p>\n<h3 id=\"unbatched-inserts\"></h3>\n<p>As described in the best practices documentation, it is recommended to always <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/cloud/bestpractices/bulk-inserts\">bulk insert</a> data into ClickHouse.</p>\n<p>A bulk insert with a reasonable batch size reduces the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/parts\">number of parts</a> created during ingestion, resulting in more efficient write-on disks and fewer merge operations.&#160;</p>\n<p>The key metrics to spot sub-optimized insert are <strong>Inserted Rows/sec</strong> and <strong>Max Parts for Partition.</strong></p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/uploads/advanced_dashboard_screen4_705b38951e.png\"><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fadvanced_dashboard_screen4_705b38951e.png&w=2048&q=75\"></span></a></p>\n<p>The example above shows two spikes in <strong>Inserted Rows/sec</strong> and <strong>Max Parts for Partition</strong> between 13h and 14h. This indicates that we ingest data at a reasonable speed.</p>\n<p>Then we see another big spike on <strong>Max Parts for Partition</strong> after 16h but a very slow <strong>Inserted Rows/sec</strong> speed. A lot of parts are being created with very little data generated, which indicates that the size of the parts is sub-optimal.</p>\n<h3 id=\"resource-intensive-query\"></h3>\n<p>It is common to run SQL queries that consume a large amount of resources, such as CPU or memory. However, it is important to monitor these queries and understand their impact on your deployment's overall performance.</p>\n<p>A sudden change in resource consumption without a change in query throughput can indicate more expensive queries being executed. Depending on the type of queries you are running, this can be expected, but spotting them from the advanced dashboard is good.&#160;</p>\n<p>Below is an example of CPU usage peaking without significantly changing the number of queries per second executed.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/uploads/advanced_dashboard_screen5_0af9049d66.png\"><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fadvanced_dashboard_screen5_0af9049d66.png&w=2048&q=75\"></span></a></p>\n<h3 id=\"bad-primary-key-design\"></h3>\n<p>Another issue you can spot using an advanced dashboard is bad primary key design. As described in the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/optimize/sparse-primary-indexes#a-table-with-a-primary-key\">documentation</a>, choosing the primary key to fit best your use case will greatly improve performance by reducing the number of rows ClickHouse needs to read to execute your query.</p>\n<p>One of the metrics you can follow to spot potential improvements in primary keys is <strong>Selected Rows per second</strong>. A sudden peak of number of selected rows can indicate both a  general increase in overall query throughput as well as  queries that select a very large number of rows to execute their query.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/uploads/advanced_dashboard_screen_6_70d24d6fd6.png\"><span><img alt=\"\"
