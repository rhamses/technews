contentHtml: "<div><blockquote>\n<p><strong>TL;DR</strong><br>\nCostBench is an open benchmark for cloud data warehouse cost-performance: performance-per-dollar, not just speed.<br><br>It helps teams choose the system that delivers the most performance per dollar for real-time analytical workloads.</p>\n</blockquote>\n<br>\n<h2 id=\"performance-alone-is-only-half-the-story\"></h2>\n<p>Most benchmarks tell you how fast a query runs. That is useful, but incomplete.</p>\n<blockquote>\n<p>In cloud data platforms, speed and cost are inseparable.</p>\n</blockquote>\n<p>If warehouse A is faster than warehouse B, A looks better on a performance chart. But if A costs three times more to run, the comparison changes. You might spend the same budget on a larger configuration of B, get more compute, and make B faster than A for less money overall.</p>\n<p>That comparison is hard because every platform exposes cost differently: credits, DBUs, slot-seconds, compute units, RPUs.</p>\n<p><span><img alt=\"Blog-Bench2Cost.001.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FBlog_Bench2_Cost_001_341b09cafb.png&w=2048&q=75\"></span></p>\n<p>The unit names differ, but the underlying question is the same:</p>\n<blockquote>\n<p>How much compute did the system need to finish the workload, and what did that compute cost?</p>\n</blockquote>\n<p>CostBench answers that question directly. It also exposes where cost-performance breaks: during ingest, while making data query-ready, or when serving reads.</p>\n<h2 id=\"why-this-matters-in-the-ai-era\"></h2>\n<p>Agentic analytics raises the pressure on every layer of the database.</p>\n<p>New data never stops: events, transactions, logs, traces, user activity, fraud signals, operational state. At the same time, users and agents expect fast answers over fresh data.</p>\n<blockquote>\n<p>If the database is slow, the agent is slow. If the database is expensive, teams start rationing what agents can do: fewer retries, smaller datasets, less context, stale data.</p>\n</blockquote>\n<p>In the AI era, fast and low-cost has to hold across the full analytics path: continuous ingest, query-ready preparation, and reads.</p>\n<p><span><img alt=\"Blog-Bench2Cost.002.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FBlog_Bench2_Cost_002_7f4af0a308.png&w=2048&q=75\"></span></p>\n<p><strong>Read-side pressure</strong> comes from query volume. A single user question can trigger many SQL queries: schema exploration, validation, retries, refinements, drilldowns, and follow-ups. Each extra query burns compute. At agentic scale, query volume turns directly into cost pressure.</p>\n<p><strong>Write-side pressure</strong> comes from real-time freshness: fresh data has to be continuously ingested, compressed, and organized so queries can skip more data. That work burns compute before the first query even runs, and determines how much compute those queries burn later.</p>\n<h2 id=\"what-costbench-measures\"></h2>\n<p>CostBench turns that pressure into a full-path cost-performance lens with two measurable dimensions:</p>\n<ul>\n<li><strong>Read-side cost-performance</strong>: how much query performance you get per dollar.</li>\n<li><strong>Write-side cost-performance</strong>: how efficiently each dollar turns fresh ingest into query-ready data.</li>\n</ul>\n<p>Together, they help answer the question that matters when choosing a platform:</p>\n<blockquote>\n<p>Which system gives you the most performance per dollar for real-time analytical workloads?</p>\n</blockquote>\n<p><span><img alt=\"Blog-Bench2Cost.003.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FBlog_Bench2_Cost_003_c9407dbe1a.png&w=2048&q=75\"></span></p>\n<p>The first release focuses on the read side: analytical queries over data that has already been loaded. We have also started measuring the write side, beginning with <a target=\"_blank\" href=\"https://clickhouse.com/blog/write-side-cost-performance-snowflake-clickhouse\">Snowflake as a contrast point for ClickHouse</a>. Broader write-side coverage will follow.</p>\n<p>This gives CostBench a simple roadmap: expose whether real-time cost-performance holds across the full analytics pipeline, from making fresh data query-ready to querying it efficiently.</p>\n<h2 id=\"the-first-results-read-side-cost-performance\"></h2>\n<p>The first CostBench release turns read-side performance into a comparable performance-per-dollar result across major cloud data warehouses.</p>\n<p>We compare ClickHouse Cloud, Snowflake, Databricks, BigQuery, and Redshift using 43 production-derived analytical queries on a real anonymized dataset, then apply <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-cloud-data-warehouses-bill-you\">each vendor’s actual compute billing model</a> to place every system on the same cost-performance plane: faster or slower, lower-cost or higher-cost.</p>\n<p><span><img alt=\"Blog-Bench2Cost.004.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2FBlog_Bench2_Cost_004_66900fe22f.png&w=2048&q=75\"></span></p>\n<p>ClickHouse Cloud is the only system that stays in the fast and low-cost zone as data scales. The nearest competitor is 23× worse in cost-performance.</p>\n<p>That is the value of CostBench: it turns vendor-specific runtimes and billing models into a result teams can use when choosing a platform.</p>\n<h2 id=\"open-and-reproducible-by-design\"></h2>\n<p>CostBench is open because cost-performance claims should be inspectable.</p>\n<p>The benchmark publishes the workload, scripts, configurations, pricing assumptions, raw JSON results, and methodology. If a result looks surprising, you can inspect the setup that produced it.</p>\n<h2 id=\"try-it-yourself\"></h2>\n<p>Explore the results on the <a target=\"_blank\" href=\"https://clickhouse.com/benchmarks\">ClickHouse benchmark hub</a>, inspect the raw data, or clone the <a target=\"_blank\" href=\"https://github.com/ClickHouse/CostBench\">CostBench repository</a> and run the benchmark yourself.</p>\n<p>Cost-performance should not be a black box.
