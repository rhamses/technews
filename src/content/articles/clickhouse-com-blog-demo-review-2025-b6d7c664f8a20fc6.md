contentHtml: "<article><div><div><p>As the year comes to an end and things slow down a bit, it feels like a good moment to zoom out and look back at the work we did as a team. I spend a lot of my time at ClickHouse working on demos, something I really enjoy, and I thought I would do a review of the most significant demos we built this year.</p>\n<p>That idea was reinforced by a conversation I had with my colleague Tom Schreiber before the holidays. He <a target=\"_blank\" href=\"https://clickhouse.com/blog/what-really-matters-for-performance-lessons-from-a-year-of-benchmarks\">spends a lot of his time benchmarking ClickHouse</a> and he shared a reflection that stuck with me:</p>\n<blockquote>\n<p>Benchmarks are great for measuring and understanding how fast ClickHouse is, but demos help people actually feel and experience that speed.</p>\n</blockquote>\n<p>That feels very true. Nothing beats a real-world example that shows how ClickHouse performance makes it possible to build impressive applications at scale. And it's not just us saying this. Customers like Tesla, which has ingested <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-tesla-built-quadrillion-scale-observability-platform-on-clickhouse\">over a quadrillion rows into ClickHouse</a>, or GitLab, <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-gitlab-uses-clickhouse-to-scale-analytical-workloads\">which serves sub-second queries to tens of millions of users</a>, would likely agree.</p>\n<p>That's a common theme across the demos featured in this post, and a good place to start looking at what we built this year.</p>\n<h2 id=\"stockhouse-real-time-market-analytics\"></h2>\n<p><a target=\"_blank\" href=\"https://stockhouse.clickhouse.com/\">StockHouse</a> is a real-time market analytics application built on live stock and crypto data from <a target=\"_blank\" href=\"https://massive.com/\">Massive APIs</a>. It streams ticks over WebSocket APIs, ingests them into ClickHouse, and renders a dashboard built using <a target=\"_blank\" href=\"https://perspective-dev.github.io/\">Perspective</a> that updates within milliseconds.</p></div><div><blockquote>\n<p>What I love about this demo is how tangible ClickHouse speed becomes. When prices move, charts move with them, without buffering or visible lag.</p>\n</blockquote>\n<p>From an engineering perspective, StockHouse shows how little configuration is needed to ingest real-time data into ClickHouse. <a target=\"_blank\" href=\"https://clickhouse.com/blog/building-stockhouse#ingester-in-go\">The Go ingester</a> connects directly to Massive's WebSocket APIs and writes batches using the native ClickHouse interface. There is no complex pipeline or external stream processor involved.</p>\n<p>On the query side, <a target=\"_blank\" href=\"https://clickhouse.com/blog/building-stockhouse#pre-aggregation-with-materialized-views\">the demo relies on materialized views</a>. Raw ticks are stored as-is, but the queries that feed the live UI read from pre-aggregated tables. Daily open, close, volume, and last update timestamps are computed at insert time, so dashboard queries stay simple and fast.</p>\n<p>The pattern is straightforward: raw events for flexibility, materialized views for speed, and queries that consistently run in a few milliseconds. This is a common ClickHouse design, but seeing it applied to live market data makes the tradeoffs very clear.</p>\n<p>StockHouse is a good reference for anyone building real-time dashboards, whether the data comes from financial markets, sensors, or observability pipelines. And it's <a target=\"_blank\" href=\"https://github.com/ClickHouse/stockhouse/\">open source</a>.</p>\n<h2 id=\"clickgems-open-analytics-for-the-rubygems-ecosystem\"></h2>\n<p><a target=\"_blank\" href=\"https://clickgems.clickhouse.com/\">ClickGems</a> started as a simple request from the <a target=\"_blank\" href=\"https://rubycentral.org/\">Ruby Central team</a>. They wanted an easier way for the community to explore RubyGems download statistics using SQL. <a target=\"_blank\" href=\"https://clickhouse.com/blog/announcing-ruby-gem-analytics-powered-by-clickhouse\">After loading the data</a> into our <a target=\"_blank\" href=\"https://sql.clickhouse.com/?query_id=HVMKR3JXFT4DA8NMAPGXKM\">SQL Playground</a>, it quickly became clear that it deserved a dedicated interface.</p></div><div><p><a target=\"_blank\" href=\"https://clickhouse.com/blog/announcing-clickgems\">ClickGems is essentially a RubyGems-focused version of ClickPy.</a> It uses the same codebase and the same approach: expose large public datasets, back them with ClickHouse, and let users explore them through fast, transparent SQL-powered visualizations. This approach has proven to scale well. <a target=\"_blank\" href=\"https://clickpy.clickhouse.com/\">ClickPy</a> crossed the <strong>two trillion row mark this year</strong>, and ClickGems benefits from the same design choices.</p>\n<blockquote>\n<p>What I love about this demo is the collaboration. Ruby Central helped with data ingestion and validation, Metabase enabled shareable charts, and together they made ClickGems useful in practice.</p>\n</blockquote>\n<p>From a technical standpoint, ClickGems reinforces a pattern we use across demos. Data is ingested in raw form, then materialized views aggregate it into shapes that match common queries. Each chart is backed by a SQL query that users can inspect and run themselves. There is no hidden logic between the visualization and the database.</p>\n<p>ClickGems is now a free analytics site for more than 200,000 gems, covering years of download history. It also serves as a <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickpy/tree/clickgems\">practical example</a> of how ClickHouse can power public, read-heavy analytics workloads at scale.</p>\n<h2 id=\"agenthouse-querying-data-with-natural-language\"></h2>\n<p><a target=\"_blank\" href=\"https://accounts.google.com/\">AgentHouse</a> explores a different angle. Instead of building another dashboard, we wanted to show how ClickHouse can act as a backend for <a target=\"_blank\" href=\"https://clickhouse.com/ai\">agentic applications</a>.</p></div><div><h3>Get started today</h3><p>Interested in seeing how ClickHouse works on your data? Get started with ClickHouse Cloud in minutes and receive $300 in free credits.</p><p><a target=\"_blank\" href=\"https://console.clickhouse.cloud/signUp?loc=blog-cta-29-get-started-today-sign-up&utm_blogctaid=29\">Sign up</a></p></div><div><p>AgentHouse is built on top of <a target=\"_blank\" href=\"https://www.librechat.ai/\">LibreChat</a> and ClickHouse, using <a target=\"_blank\" href=\"https://github.com/ClickHouse/mcp-clickhouse\">ClickHouse MCP server</a> to query real datasets hosted in ClickHouse Cloud. Users can ask questions using natural language, see the generated SQL, and get instant answers based on real data.</p>\n<blockquote>\n<p>What I love about this demo is how clearly it shows what agentic applications can look like in practice. There is no abstraction or mock setup. The LLM generates SQL, runs it against live data in ClickHouse, and reasons over real results, which makes the architecture easy to understand.</p>\n</blockquote>\n<p>AgentHouse uses the same datasets available in our <a target=\"_blank\" href=\"https://sql.clickhouse.com/\">SQL Playground</a>, including RubyGems, PyPI, GitHub, and Hacker News. This makes it a safe environment to explore how natural language interfaces behave on large, real-world datasets.</p>\n<p>For us, AgentHouse is less about replacing SQL and more about expanding how people interact with data. It shows how ClickHouse fits into LLM-driven systems without giving up transparency, performance, or control.</p>\n<h2 id=\"clickstack-demo-observability-on-clickhouse-end-to-end\"></h2>\n<p>We built the <a target=\"_blank\" href=\"https://play-clickstack.clickhouse.com/search\">ClickStack demo</a> to give users an easy way to experience what observability on top of ClickHouse actually looks like. The idea is to put yourself in the role of an SRE and use the stack to <a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/observability/clickstack/getting-started/remote-demo-data\">investigate a real application incident</a>, using the same workflows you would rely on in production.</p>\n<p>The demo <a target=\"_blank\" href=\"https://github.com/ClickHouse/opentelemetry-demo\">is based on the official OpenTelemetry demo</a>, which simulates a microservices-based e-commerce application with traffic generated by a load generator. All services are instrumented with OpenTelemetry and emit logs, traces, metrics, and session data through a standard OTel Collector into ClickHouse.</p></div><div><p>The dataset contains roughly 40 hours of telemetry and is replayed daily with timestamps shifted into the current time window. All signals are stored as wide events in ClickHouse and explored through HyperDX, without separate backends for logs, metrics, or traces.</p>\n<blockquote>\n<p>What I love about this demo is that it mirrors how an SRE actually works: starting from a vague symptom, narrowing it down through logs, confirming behavior with traces and metrics, and validating impact from the user’s perspective.</p>\n</blockquote>\n<h2 id=\"special-mention-to-alexey\"></h2>\n<p>Alexey Milovidov, ClickHouse CTO and co-founder, loves adopting new datasets and building demos to make it easy to explore them, using ClickHouse, always, obviously.</p>\n<p>This year, he extended a visualization tool he originally built for air traffic data and used it for several new demos. <a target=\"_blank\" href=\"https://clickhouse.com/blog/fsq\">One of the first </a>was based on Foursquare data, showing places such as shops, restaurants, parks, playgrounds, and monuments on a map.</p>\n<p><span><img alt=\"fsq-screenshot.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Ffsq_screenshot_f3955a7908.png&w=2048&q=75\"></span></p>\n<p>Later, Alexey explored an unusual dataset derived from airplane telemetry to infer weather conditions. A few weeks before the end of the year, Alexey <a target=\"_blank\" href=\"https://clickhouse.com/blog/velocity\">launched a new website</a> to track GitHub activity across the ClickHouse team.</p>\n<p><span><img alt=\"velocity-screenshot.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fvelocity_screenshot_ad779dfae3.png&w=2048&q=75\"></span></p>\n<p>Thanks, Alexey, for all the demos this year.</p>\n<h2 id=\"why-these-demos-matter\"></h2>\n<p>Looking back, these demos cover very different use cases, from real-time dashboards to public analytics sites to agent-driven interfaces. Store raw data, shape it with materialized views, keep queries explicit, and let performance simplify the rest of the system.</p>\n<p>All of these demos are built in the open. The code, schemas, and queries are there to be read, reused, and adapted. They are not reference architectures on slides, but working systems that developers can take apart and build on for their own applications.\nThat openness matters, especially when combined with real data and real scale. As I discussed with Tom in the introduction, demos make it possible to feel the speed and scale that ClickHouse allows us to operate at. You can see queries return in milliseconds, watch dashboards update live, and explore datasets that would be impractical to handle with many other systems.</p>\n<p>For me, this is where demos complement benchmarks.</p>\n<p>We will keep building more of them in 2026.</p></div></div></article>"
