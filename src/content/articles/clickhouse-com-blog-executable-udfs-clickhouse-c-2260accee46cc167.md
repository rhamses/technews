contentHtml: "<article><div><div><p>Today we're excited to announce that <strong>executable UDFs are now available\nin public beta on ClickHouse Cloud</strong>. You can write a function in Python, upload it as a zip to your cluster, and call it from\nSQL like any built-in. ClickHouse manages a pool of long-lived sandboxed\nprocesses and routes rows through them at query speed. The function is\ncallable anywhere SQL is: ad-hoc queries, joins, even materialized views\nthat fire on every insert.</p>\n<p>This isn't a brand-new idea. We've shipped executable UDFs in self-hosted\nClickHouse for a while. <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-open-ai-user-defined-functions-udfs\">Our 2023 post on calling OpenAI from\nSQL</a>\nwalked through the same mechanism. What's new today is that you don't\nneed to run your own server to use it. The model code lives where the\ndata is, runs in a managed sandbox, and the deployment surface is one\nupload screen in the Cloud console.</p>\n<p>To show what this unlocks, we built a demo. A small PyTorch autoencoder\nscores ~6 billion equity trade ticks for anomalousness, inline with\ningest. A Next.js front-end consumes the embeddings. Full source for the\nnotebook, UDF bundle, SQL, and webapp is in <a target=\"_blank\" href=\"https://github.com/ClickHouse/stock-anomaly-udf\">this repo</a>.</p>\n<p><span><img alt=\"Anomaly dashboard with packedbubble chart and S&P 500 leaderboard\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fhero_dashboard_5c8d3ce323.png&w=2048&q=75\"></span></p>\n<h2 id=\"the-problem-this-solves\"></h2>\n<p>You have a trained model. You have a stream of data in ClickHouse.\nGetting them into the same room used to mean one of three options.</p>\n<ol>\n<li>\n<p><strong>Stand up a separate scoring service.</strong> Now you maintain a model\nserver, an ingest pipeline that routes rows to it, and a way to write\nthe scores back into ClickHouse. The model is no longer near the data\nin any meaningful sense.</p>\n</li>\n<li>\n<p><strong>Translate the model into pure SQL.</strong> Workable for some tree-based\nmodels. Painful for anything with embeddings. Every retrain means\nregenerating thousands of lines of SQL by hand.</p>\n</li>\n<li>\n<p><strong>Batch score offline and join later.</strong> Loses freshness. The \"anomaly\"\non a trade that just hit is only useful if you can react to it now.</p>\n</li>\n</ol>\n<p>Executable UDFs collapse all three into one. Write the inference code as\na normal Python file. Point ClickHouse at it. Call it from SQL. The\nfunction runs inline with whatever query needs it, including inside a\nmaterialized view, which is exactly what we do here.</p>\n<h2 id=\"what-we-built\"></h2>\n<p>Last year we wrote <a target=\"_blank\" href=\"https://clickhouse.com/blog/building-stockhouse\">\"Building StockHouse\"</a>,\nshowing how ClickHouse handles a continuous firehose of stock trade ticks\nin real time. That post stopped at the ingest and query layer. The\nnatural next question is: what if you wanted to apply a learned model to\nevery trade as it lands?</p>\n<p>We picked an unsupervised anomaly-detection setup because it shows off\nthe shape of the problem cleanly.</p>\n<ul>\n<li>A small autoencoder (~270K parameters) is trained on 50M historical\ntrade ticks. Same end state, several more moving parts. Here it's\none DDL statement.</p>\n<p>The performance shape is unsurprising. Same UDF, same MV, same SQL.</p>\n<h2 id=\"making-anomalous-mean-something\"></h2>\n<p>The autoencoder gives us a raw <code>recon_score</code> per trade. That's a number\nbetween roughly 0.00002 and 1,000,000+ across the dataset. A naive\n\"trades above 0.062 are anomalous\" filter (using the global 99th\npercentile from the model's training distribution) sounds reasonable\nuntil you actually look at the data.</p>\n<p>A handful of symbols, like BRK.A and LLY, score every single trade above\nthat threshold because their share prices are unusually high. Their\nentire distribution sits in the right tail of the global one. A \"100%\nanomalous\" stat for those symbols is technically correct and practically\nuseless.</p>\n<p>So we redefine \"anomaly\" relative to each symbol's own history. For\nevery symbol, we maintain its <strong>lifetime p95 of <code>recon_score</code></strong>. A trade\nis anomalous <em>for that symbol</em> if it exceeds the symbol's own p95. About\n5% of trades qualify in a typical window, by construction. When that\nfraction spikes well above 5%, the symbol is having a genuinely unusual\nwindow.</p>\n<p>The per-symbol baseline lives in another ClickHouse table:</p></div><div><pre><code><span><span>CREATE TABLE</span> trades_baselines (</span>\n<span>    sym         LowCardinality(String),</span>\n<span>    p50         Float32,</span>\n<span>    p95         Float32,</span>\n<span>    p99         Float32,</span>\n<span>    <span>-- ...</span></span>\n<span>    computed_at DateTime</span>\n<span>)</span>\n<span>ENGINE <span>=</span> MergeTree</span>\n<span><span>ORDER</span> <span>BY</span> sym;</span></code></pre></div><p>A <strong>refreshable materialized view</strong> repopulates it every hour:</p><div><pre><code><span><span>CREATE</span> MATERIALIZED <span>VIEW</span> trades_baselines_mv</span>\n<span>REFRESH <span>EVERY</span> <span>1</span> <span>HOUR</span></span>\n<span><span>TO</span> trades_baselines</span>\n<span><span>AS</span></span>\n<span><span>SELECT</span></span>\n<span>    sym,</span>\n<span>    quantiles(<span>0.5</span>, <span>0.95</span>, <span>0.99</span>)(recon_score) <span>AS</span> qs,</span>\n<span>    qs[<span>1</span>] <span>AS</span> p50, qs[<span>2</span>] <span>AS</span> p95, qs[<span>3</span>] <span>AS</span> p99,</span>\n<span>    <span>-- ...</span></span>\n<span><span>FROM</span> trades_embeddings</span>\n<span><span>WHERE</span> <span>NOT</span> has(c, <span>15</span>) <span>AND</span> <span>NOT</span> has(c, <span>12</span>)   <span>-- exclude auction prints</span></span>\n<span><span>GROUP</span> <span>BY</span> sym;</span></code></pre></div><div><p>Refreshable MVs atomically truncate and replace the target table on each\nrefresh. No external calls anywhere on the read path. That's\nthe shape you want for the load-bearing pieces: cheap, predictable, no\nupstream that can disappear on you.</p>\n<p>But once a trade has been flagged as anomalous, the obvious next\nquestion is <em>why</em>.
