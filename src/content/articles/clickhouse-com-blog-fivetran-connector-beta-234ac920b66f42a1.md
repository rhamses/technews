A sync mode that preserves every version of each record from your source system. Instead of overwriting rows when data changes, History Mode inserts a new row for each change, giving you a complete audit trail of how your data has evolved over time. When enabled, Fivetran adds three system columns to your table:</p>\n<div><table><thead><tr><th><code>_fivetran_active</code></th><th><code>TRUE</code> if this is the current version of the record</th></tr></thead><tbody><tr><td><code>_fivetran_start</code></td><td>Timestamp of when this version of the record became active</td></tr><tr><td><code>_fivetran_end</code></td><td>Timestamp of when this record was superseded</td></tr></tbody></table></div>\n<p>Using History mode enables powerful analytics queries like:</p>\n<ul>\n<li>Point-in-time snapshots: “What did our customer data look like in January 2025?”</li>\n<li>Change tracking: “How many times did this account's status change last quarter?”</li>\n<li>Audit trails: “Who modified this record and when?”</li>\n</ul>\n<p>We also added support for <a target=\"_blank\" href=\"https://clickhouse.com/blog/introducing-warehouses-compute-compute-separation-in-clickhouse-cloud\">compute-compute separation</a>, so you can now use ClickHouse Cloud’s architecture for isolating Fivetran’s ingestion workloads from your other workloads.</p>\n<h2 id=\"ideal-use-cases-for-the-connector\"></h2>\n<p>The Fivetran destination for ClickHouse is excellent for getting business data from SaaS Applications like Salesforce, HubSpot, Stripe, and Zendesk, which have complex APIs that would require significant engineering effort to integrate directly. Fivetran handles the API, schema and incremental syncs. You can just point it to ClickHouse and start querying after it is loaded.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Ffivetran_feb2026_image4_5801363aaf.png&w=2048&q=75\"></span></p>\n<p><a target=\"_blank\" href=\"https://fivetran.com/docs/connectors/applications/salesforce#schema\">Salesforce ERD for Fivetran</a></p>\n<p>For high-volume streaming data (TB/PB) from sources like Kafka, Kinesis, or object storage, you can consider using <a target=\"_blank\" href=\"https://clickhouse.com/cloud/clickpipes\">ClickPipes</a>, ClickHouse Cloud’s native ingestion service optimised for continuous, high-throughput workloads from Object Storage, Message Queues and Databases.</p>\n<div><table><thead><tr><th>Source</th><th>Options</th></tr></thead><tbody><tr><td>SaaS Application (e.g. Salesforce)</td><td>Fivetran</td></tr><tr><td>Object Storage (e.g. S3 or GCS)</td><td>ClickPipes or Fivetran</td></tr><tr><td>Message Queue (e.g. Kafka or Kinesis)</td><td>ClickPipes or Fivetran</td></tr><tr><td>Databases with CDC (e.g. Postgres or MySQL)</td><td>ClickPipes or Fivetran</td></tr></tbody></table></div>\n<blockquote>\n<p>If your team doesn’t have dedicated data engineering, you will definitely benefit from Fivetran’s and ClickPipe's no-code user experience that gets you from source to ClickHouse in minutes.</p>\n</blockquote>\n<h2 id=\"how-does-the-fivetran-connector-work\"></h2>\n<p>The Fivetran destination is designed for ClickHouse to handle inserts, updates and deletes efficiently.</p>\n<h3 id=\"table-creation-and-primary-keys\"></h3>\n<p>When Fivetran creates a connection, the connector automatically creates a ClickHouse table using the source’s primary keys as the <code>ORDER BY</code>. If the source does not have a primary key, Fivetran will create <code>_fivetran_id</code> as a unique identifier as the table sorting key.</p>\n<h3 id=\"performance-considerations\"></h3>\n<p>When syncing from <a target=\"_blank\" href=\"https://fivetran.com/docs/destinations/clickhouse#destinationtables\">data sources without a nominal primary key</a> (like from a Google Sheet or SaaS API), Fivetran may use either a row identifier or generate an ID as the ordering key. This means queries filtering on business columns like <code>customer_name</code> or <code>status</code> could trigger a full table scan.</p>\n<h4 id=\"optimising-query-performance\"></h4>\n<p>There are several ideas that you can use for optimising your read query performance:</p>\n<div><table><thead><tr><th>Approach</th><th>Best for</th><th>Trade-offs</th></tr></thead><tbody><tr><td>Skip indexes</td><td>Filtering on ranges</td><td>A limited set of queries can be supported</td></tr><tr><td>Projections</td><td>Alternative sort orders for varied query patterns</td><td>Additional storage, but automatically maintained</td></tr><tr><td>Materialised Views</td><td>Schema changes and repeated query patterns</td><td>Requires managing a separate table with additional storage overhead</td></tr></tbody></table></div>\n<h5 id=\"option-1-skip-indexes\"></h5>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/docs/optimize/skipping-indexes\">Skip indexes</a> work at the granule level, allowing ClickHouse to skip blocks of data that don’t match your filter conditions. Skip indexes are most effective when you need point-in-time snapshots (“What did our customer data look like in January 2025”) or range-based filtering (“Show me records modified between two dates”). They offer faster queries by skipping irrelevant granules, add minimal storage overhead and are easy to add to existing tables. However, they only help when data has some natural ordering or clustering within granules and are limited to specific use cases like min/max ranges, set and bloom filters.</p>\n<div><pre><code><span><span>-- Add minmax index for date based filtering</span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table</span>\n<span><span>ADD</span> INDEX customer_idx (customer_idx) TYPE minmax GRANULARITY <span>4</span>;</span>\n<span></span>\n<span><span>-- Add bloom filter for string lookups</span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table</span>\n<span><span>ADD</span> INDEX customer_name (customer_name) TYPE bloom_filter GRANULARITY <span>4</span>;</span>\n<span></span>\n<span><span>-- index existing data</span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table MATERIALIZE INDEX synced_idx;</span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table MATERIALIZE INDEX customer_name;</span></code></pre></div>\n<p>There is a whole section within our ClickHouse documentation for <a target=\"_blank\" href=\"https://clickhouse.com/docs/optimize/skipping-indexes#skip-best-practices\">best practices</a> when using Skip Indexes that you can use to consider if this is the right approach for you.</p>\n<h5 id=\"option-2-1-projections\"></h5>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/docs/sql-reference/statements/alter/projection\">Projections</a> create an additional copy of your data with a different sort order. ClickHouse automatically selects the optimal projection at query time, making it ideal for point-in-time, change tracking (“How many times did this account’s status change last quarter?”) and audit trails (“Who modified this record and when?”).</p>\n<p>The primary advantage of projection is dramatically faster queries on non-primary key columns without needing to query a different table. You can also add projections to existing tables without rewriting the original data. The trade-off is additional storage for each projection, with the amount varying based on how well the data compresses with the new sort order. There’s also some insert overhead as data is written to both the main table and projections.</p>\n<div><pre><code><span><span>-- Add a projection for customer based queries</span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table_name</span>\n<span><span>ADD</span> PROJECTION customer_projection (</span>\n<span>\t<span>SELECT</span> <span>*</span> <span>ORDER</span> <span>BY</span> customer_name</span>\n<span>);</span>\n<span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table_name MATERIALIZE PRORJECTION customer_projection;</span></code></pre></div>\n<h5 id=\"option-2-2-projections-as-secondary-indexes\"></h5>\n<p>For a lighter-weight approach, you can use <a target=\"_blank\" href=\"https://clickhouse.com/blog/projections-secondary-indices\">Projections as secondary indexes</a>. Instead of storing all columns, you store only the ordering columns plus <code>_part_offset</code>, a virtual column indicating the row’s position within the part. This reduces storage while still enabling fast filtering, making it ideal when you need filtering performance but want to minimise storage.</p>\n<div><pre><code><span><span>-- Projection as a secondary index</span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table_name</span>\n<span><span>ADD</span> PROJECTION customer_idx_projection (</span>\n<span>\t<span>SELECT</span> customer_name, _part_offset <span>ORDER</span> <span>BY</span> customer_name</span>\n<span>);</span>\n<span></span>\n<span><span>ALTER TABLE</span> my_schema.fivetran_table_name MATERIALIZE PROJECTION customer_idx_projection;</span></code></pre></div>\n<p>When altering a table to add a projection, by default, it will throw the following exception:</p>\n<div><pre><code><span>ADD PROJECTION is not supported <span>in</span> SharedReplacingMergeTree with deduplicate_merge_projection_mode = throw. Please <span>set</span> setting <span>'deduplicate_merge_projection_mode'</span> to <span>'drop'</span> or <span>'rebuild'</span>.</span></code></pre></div>\n<p>As the error message suggests, we need to configure <a target=\"_blank\" href=\"https://clickhouse.com/docs/sql-reference/statements/alter/projection#control-projections-merges\"><code>deduplicate_merge_projection_mode</code></a> appropriately.\nYou can read more about <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-release-24-08#control-of-projections-during-merges\">controlling projections during merges in the 24.8 release blog post</a></p>\n<p>Check out Tom’s blog for <a target=\"_blank\" href=\"https://clickhouse.com/blog/projections-secondary-indices#example-combining-multiple-projection-indexes\">Projections as secondary indices</a> for more examples of combining multiple projection indices and Mark’s video explaining how you can use them.</p>\n<h5 id=\"option-3-materialised-views\"></h5>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/docs/materialized-view/incremental-materialized-view\">Materialized views</a> transform data at insert time and write it to a separate target table. You can transform, filter, or aggregate data during ingestion to create a table perfectly optimised for your specific query patterns. This gives you complete control over the target table’s schema, primary and ordering keys, and additional optimisations.</p>\n<div><pre><code><span><span>-- Create an optimised target table</span></span>\n<span><span>CREATE TABLE</span> my_schema.my_optimised_table (</span>\n<span></span>\n<span>) </span>\n<span><span>PRIMARY KEY</span> </span>\n<span><span>ORDER</span> <span>BY</span> ;</span>\n<span></span>\n<span><span>-- Create materialised view</span></span>\n<span><span>CREATE</span> MATERIALIZED <span>VIEW</span> my_schema.my_table_mv</span>\n<span><span>TO</span> my_schema.my_optimised_table</span>\n<span><span>AS</span> <span>SELECT</span>  <span>FROM</span> my_schema.fivetran_table_name</span></code></pre></div>\n<p>The trade-off is duplicated storage for all data, and schema changes to the source table are not automatically reflected in the target table, this requires manual management. You can get more information on <a target=\"_blank\" href=\"https://clickhouse.com/docs/managing-data/materialized-views-versus-projections\">Materialised views vs Projections</a> from the ClickHouse docs.</p>\n<h4 id=\"consider-a-medallion-architecture\"></h4>\n<p>Since you cannot modify a table’s primary key after creation, there are several strategies to optimise query performance. Consider implementing a Medallion Architect where Fivetran lands data in its raw data into a \"bronze\" layer, and you transform it into optimised \"silver\" and “gold” tables with the appropriate primary and ordering keys for your query patterns.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Ffivetran_feb2026_image5_f073b52273.png&w=2048&q=75\"></span></p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/building-a-medallion-architecture-with-clickhouse\">Blog post: Building a Medallion architecture with ClickHouse</a></p>\n<p>Using ClickHouse materialised views, you can automatically transform Fivetran synced data as it arrives.
