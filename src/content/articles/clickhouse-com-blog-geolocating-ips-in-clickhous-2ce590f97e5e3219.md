our <code>ip_trie</code> dictionary requires IP address ranges to be expressed in CIDR notation, we’ll need to transform <code>ip_range_start</code> and <code>ip_range_end</code>.  For reference, here’s a brief <a target=\"_blank\" href=\"https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing\">description of CIDR notation from Wikipedia</a>:</p>\n<blockquote>\n<p>These groups, commonly called CIDR blocks, share an initial sequence of bits in the binary representation of their IP addresses. IPv4 CIDR blocks are identified using a syntax similar to that of IPv4 addresses: a dotted-decimal address, followed by a slash, then a number from 0 to 32, i.e., a.b.c.d/n. The dotted decimal portion is the IPv4 address. The number following the slash is the prefix length, the number of shared initial bits, counting from the most-significant bit of the address. When emphasizing only the size of a network, the address portion of the notation is usually omitted. Thus, a /20 block is a CIDR block with an unspecified 20-bit prefix.</p>\n<p>\nAn IP address is part of a CIDR block and is said to match the CIDR prefix if the initial n bits of the address and the CIDR prefix are the same. An IPv4 address is 32 bits so an n-bit CIDR prefix leaves 32 − n bits unmatched, meaning that 232−n IPv4 addresses match a given n-bit CIDR prefix.\n</p>\n<p>\nAn IP address is part of a CIDR block and is said to match the CIDR prefix if the initial n bits of the address and the CIDR prefix are the same. An IPv4 address is 32 bits so an n-bit CIDR prefix leaves 32 − n bits unmatched, meaning that 232−n IPv4 addresses match a given n-bit CIDR prefix.\n</p>\n</blockquote>\n<p>In order to generate a CIDR expression for our IP ranges, we’ll need to compare each range to determine unmatched bits in each address and then determine the smallest possible CIDR range that encompasses the whole range. Here’s a diagram to demonstrate:</p>\n<p><span><img alt=\"cidr_range_calculation.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_range_calculation_398d9ddf49.png&w=2048&q=75\"></span></p>\n<p>In this diagram, we can see that our example IP address range (<code>161.123.218.0</code> → <code>161.123.220.255</code>) contains 768 possible addresses, spanning three /24 CIDR blocks, two /23 blocks, and two /22 blocks.  As a result, the smallest possible CIDR block that contains the range is a /21 block (containing 2048 addresses).  Amazingly, this entire calculation can be accomplished using a handful of bitwise and mathematical functions supported by ClickHouse.</p>\n<p><span><img alt=\"cidr_bitwise.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_bitwise_5c078aad31.png&w=2048&q=75\"></span></p>\n<p>To begin, we’ll use the <code>bitXor()</code> function in ClickHouse, which performs a bitwise XOR operation between two numbers and returns the result of the XOR operation.  The XOR operation compares each bit of the two numbers, outputting 1 if the two digits are different and 0 if they are the same.  For example, the expression <code>bitXor(5,3)</code> would evaluate to <code>6</code> since 5 is represented in binary as <code>101</code> and 3 is represented as <code>011</code>.  Comparing each bit produces <code>110</code> which is equivalent to <code>6</code> in decimal. Let’s see what happens when we use cast our IPs as Integers and apply the <code>bitXor()</code> function—note that ClickHouse automatically converts bitXor() outputs into decimal form, so we’ve added an additional column to demonstrate the underlying binary expression:</p>\n<div><pre><code><span><span>select</span></span>\n<span>    ip_range_start,</span>\n<span>    ip_range_end,</span>\n<span>    bitXor(ip_range_start, ip_range_end) <span>as</span> xor,</span>\n<span>    bin(xor) <span>as</span> xor_binary</span>\n<span><span>from</span></span>\n<span>    geoip_url</span>\n<span>limit</span>\n<span>    <span>20</span>;</span></code></pre></div>\n<p><span><img alt=\"bitXor_cidr.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fbit_Xor_cidr_d388198adf.png&w=2048&q=75\"></span></p>\n<p>From here, we can see that <code>bitXor()</code> will return the number of addresses in our range (for example 255 between <code>1.0.0.0</code> and <code>1.0.0.255</code>).</p>\n<p><span><img alt=\"cidr_unmatched_digits.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_unmatched_digits_ca3209c3d7.png&w=2048&q=75\"></span></p>\n<p>Next, we’ll use <code>log2()</code> and <code>ceil()</code> to count the number of binary digits beginning with the first unmatched bit.  We’ll also need to handle scenarios where the start and end of our IP range are equal (thereby yielding a xor output of 0) because <code>log2(0)</code> is undefined:</p>\n<div><pre><code><span><span>select</span></span>\n<span>    ip_range_start,</span>\n<span>    ip_range_end,</span>\n<span>    bitXor(ip_range_start, ip_range_end) <span>as</span> xor,</span>\n<span>    bin(xor) <span>as</span> xor_binary,</span>\n<span>    if(xor <span>!=</span> <span>0</span>, <span>ceil</span>(log2(xor)), <span>0</span>) <span>as</span> unmatched,</span>\n<span>    <span>32</span><span>-</span>unmatched <span>as</span> cidr_suffix</span>\n<span><span>from</span></span>\n<span>    geoip_url</span>\n<span>limit</span>\n<span>    <span>20</span>;</span></code></pre></div>\n<p><span><img alt=\"cidr_suffix_query.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_suffix_query_13217669e9.png&w=2048&q=75\"></span></p>\n<p>In the results above, we can see that the <code>unmatched</code> field is effectively calculating the position of the first <code>1</code> bit from our <code>bitXor()</code> output.  Subtracting this value from 32 yields our CIDR block size (suffix).</p>\n<p><span><img alt=\"cidr_bitwise_not_and.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_bitwise_not_and_29f829107b.png&w=2048&q=75\"></span></p>\n<p>Next, we’ll determine the address at which the CIDR block begins, as this will often differ from the address at the beginning of our range, especially for larger blocks.  To do this, we’ll need to perform a <a target=\"_blank\" href=\"https://docs.oracle.com/cd/E41183_01/DR/Bitnot.html\">bitwise NOT operation</a> <code>bitNot()</code> on the total number of addresses contained in our CIDR block, which can be expressed as <code>pow(2, n) - 1</code> where <code>n</code> is equal to the value of our <code>unmatched</code> field above.  Then, we’ll compare the result with the beginning of our IP range using a <a target=\"_blank\" href=\"https://support.apple.com/guide/functions/bitand-ffae6d40a070/web#:~:text=The%20BITAND%20function%20returns%20the%20bitwise%20AND%20of%20two%20numbers.&text=value%2D1%3A%20The%20first%20number,%2D2%3A%20The%20second%20number.\">bitwise AND operation</a> <code>bitAnd()</code> to determine which bits in both expressions are equal to 1. The result can then be converted back into an IPv4 address by first casting it to <code>UInt64</code> and then applying the <code>toIPv4()</code> function:</p>\n<div><pre><code><span><span>select</span></span>\n<span>    ip_range_start,</span>\n<span>    ip_range_end,</span>\n<span>    bitXor(ip_range_start, ip_range_end) <span>as</span> xor,</span>\n<span>    bin(xor) <span>as</span> xor_binary,</span>\n<span>    if(xor <span>!=</span> <span>0</span>, <span>ceil</span>(log2(xor)), <span>0</span>) <span>as</span> unmatched,</span>\n<span>    <span>32</span> <span>-</span> unmatched <span>as</span> cidr_suffix,</span>\n<span>    toIPv4(bitAnd(bitNot(pow(<span>2</span>, unmatched) <span>-</span> <span>1</span>), ip_range_start)::UInt64) <span>as</span> cidr_address</span>\n<span><span>from</span></span>\n<span>    geoip_url</span>\n<span>limit</span>\n<span>    <span>20</span>;</span></code></pre></div>\n<p><span><img alt=\"cidr_range_query.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_range_query_1c3caa65d1.png&w=2048&q=75\"></span></p>\n<p>Finally, we can concatenate our CIDR address and suffix into a single string.  To make this clean, we’ll also move all of our intermediary expressions into a <code>WITH</code> clause.</p>\n<div><pre><code><span><span>with</span> </span>\n<span>    bitXor(ip_range_start, ip_range_end) <span>as</span> xor,</span>\n<span>    if(xor <span>!=</span> <span>0</span>, <span>ceil</span>(log2(xor)), <span>0</span>) <span>as</span> unmatched,</span>\n<span>    <span>32</span> <span>-</span> unmatched <span>as</span> cidr_suffix,</span>\n<span>    toIPv4(bitAnd(bitNot(pow(<span>2</span>, unmatched) <span>-</span> <span>1</span>), ip_range_start)::UInt64) <span>as</span> cidr_address</span>\n<span><span>select</span></span>\n<span>    ip_range_start,</span>\n<span>    ip_range_end,</span>\n<span>    concat(toString(cidr_address),<span>'/'</span>,toString(cidr_suffix)) <span>as</span> cidr    </span>\n<span><span>from</span></span>\n<span>    geoip_url</span>\n<span>limit</span>\n<span>    <span>20</span>;</span></code></pre></div>\n<p><span><img alt=\"cidr_final_query.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcidr_final_query_f5a8fb03d9.png&w=2048&q=75\"></span></p>\n<h3
