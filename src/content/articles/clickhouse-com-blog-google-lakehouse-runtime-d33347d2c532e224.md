contentHtml: "<div><p>We're excited to announce a new integration between ClickHouse and Google's <a target=\"_blank\" href=\"https://docs.cloud.google.com/biglake/docs/blms-rest-catalog\">Lakehouse Runtime Catalog</a>, enabling direct querying of <a target=\"_blank\" href=\"https://docs.cloud.google.com/biglake/docs/biglake-iceberg-tables-in-bigquery\">Google Cloud Lakehouse Iceberg tables</a> in ClickHouse via <a target=\"_blank\" href=\"https://iceberg.apache.org/\">Apache Iceberg REST Catalog</a>.</p>\n<p>This integration debuts as a beta feature in ClickHouse 26.2 and will be available shortly after in ClickHouse Cloud.</p>\n<h2 id=\"user-content-why_iceberg_rest_catalog\"></h2>\n<p>A common challenge for data teams is making all their data accessible regardless of where it lives. Discovery, governance, and access control need to work across data lakes, warehouses, and operational stores.</p>\n<p>Lakehouse Runtime Catalog solves this by providing a centralized catalog for Apache Iceberg tables in Google Cloud. That enables interoperability with any Iceberg-compatible engine: BigQuery, Apache Spark, Trino, and now ClickHouse.</p>\n<p>By connecting to the REST Catalog, ClickHouse can discover and query Google Cloud Lakehouse Iceberg tables stored in Cloud Storage with no data movement, no proprietary connectors, and no metadata syncing required. Data engineers can write Google Cloud Lakehouse Iceberg tables with Spark or BigQuery, and analysts can immediately query that same data with ClickHouse for fast, complex analytics. Data can also be loaded into ClickHouse's native format in a single query using this integration!</p>\n<h2 id=\"user-content-how_does_the_integration_work\"></h2>\n<p>To use this integration, you need two things:</p>\n<ul>\n<li>A ClickHouse instance (ClickHouse and <a target=\"_blank\" href=\"https://clickhouse.com/docs/operations/utilities/clickhouse-local\">ClickHouse local</a> supported)</li>\n<li>A <a target=\"_blank\" href=\"https://cloud.google.com/\">Google Cloud project</a> with Lakehouse Runtime Catalog enabled</li>\n</ul>\n<p>Lakehouse Runtime Catalog tracks the Iceberg metadata for Iceberg tables and exposes it via the Iceberg REST Catalog API at <code>https://biglake.googleapis.com/iceberg/v1/restcatalog</code>. ClickHouse connects to this endpoint to discover and query the underlying tables directly.</p>\n<p>For authentication, ClickHouse integrates with Google's <a target=\"_blank\" href=\"https://docs.cloud.google.com/docs/authentication/provide-credentials-adc\">Application Default Credentials (ADC)</a> mechanism.</p>\n<h2 id=\"user-content-getting_started\"></h2>\n<p>Deploy ClickHouse on <a target=\"_blank\" href=\"https://clickhouse.com/partners/gcp\">Google Cloud</a> or use <a target=\"_blank\" href=\"https://clickhouse.com/docs/operations/utilities/clickhouse-local\">ClickHouse local</a>, ensuring you're on version 26.2 or later. Once your instance is ready, follow the steps below to connect to the Lakehouse Runtime Catalog. Read more in the <a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/data-lake/biglake-catalog\">ClickHouse documentation for Lakehouse Runtime Catalog</a>.</p>\n<h2 id=\"user-content-authentication_with_google_application_default_credentials\"></h2>\n<p>ClickHouse supports Google ADC natively, giving you two options to authenticate with the Lakehouse Runtime Catalog.</p>\n<h3 id=\"option-1-point-to-your-adc-credentials-file\"></h3>\n<p>If you already have Application Default Credentials configured on your machine (e.g. via <code>gcloud auth application-default login</code>), you can simply point ClickHouse to the JSON credentials file. This is the easiest approach for local development and testing:</p>\n<div><pre><code><span><span>SET</span> allow_database_iceberg <span>=</span> <span>1</span>;</span>\n<span></span>\n<span><span>CREATE</span> DATABASE Lakehouse_catalog</span>\n<span>ENGINE <span>=</span> DataLakeCatalog(<span>'https://biglake.googleapis.com/iceberg/v1/restcatalog'</span>)</span>\n<span>SETTINGS</span>\n<span>  catalog_type <span>=</span> <span>'biglake'</span>,</span>\n<span>  google_adc_credentials_file <span>=</span> <span>'/path/to/application_default_credentials.json'</span>,</span>\n<span>  warehouse <span>=</span> <span>'gs://&lt;bucket_name&gt;/&lt;optional-prefix&gt;'</span>;</span></code></pre></div>\n<p>ClickHouse reads the <code>client_id</code>, <code>client_secret</code>, <code>refresh_token</code>, and <code>quota_project_id</code> directly from the JSON file, so you don't need to specify them individually.</p>\n<h3 id=\"option-2-provide-credentials-inline\"></h3>\n<p>For production deployments or environments where a credentials file isn't available, you can provide the OAuth credentials directly in the query settings:</p>\n<div><pre><code><span><span>SET</span> allow_database_iceberg <span>=</span> <span>1</span>;</span>\n<span></span>\n<span><span>CREATE</span> DATABASE Lakehouse_catalog</span>\n<span>ENGINE <span>=</span> DataLakeCatalog(<span>'https://biglake.googleapis.com/iceberg/v1/restcatalog'</span>)</span>\n<span>SETTINGS</span>\n<span>  catalog_type <span>=</span> <span>'biglake'</span>,</span>\n<span>  google_adc_client_id <span>=</span> <span>'&lt;client-id&gt;'</span>,</span>\n<span>  google_adc_client_secret <span>=</span> <span>'&lt;client-secret&gt;'</span>,</span>\n<span>  google_adc_refresh_token <span>=</span> <span>'&lt;refresh-token&gt;'</span>,</span>\n<span>  google_adc_quota_project_id <span>=</span> <span>'&lt;gcp-project-id&gt;'</span>,</span>\n<span>  warehouse <span>=</span> <span>'gs://&lt;bucket_name&gt;/&lt;optional-prefix&gt;'</span>;</span></code></pre></div>\n<p>Both approaches use the same underlying OAuth flow to authenticate with the Iceberg REST Catalog endpoint and authorize access to the data in Cloud Storage.</p>\n<h2 id=\"user-content-querying_google_lakehouse_iceberg_tables_from_clickhouse\"></h2>\n<p>Once you've created a connection using either of the authentication methods above, querying your Google Lakehouse Iceberg tables is straightforward.</p>\n<h3 id=\"listing-available-tables\"></h3>\n<p>List all tables available in the catalog:</p>\n<div><pre><code><span><span>SHOW</span> TABLES <span>FROM</span> Lakehouse_catalog;</span></code></pre></div>\n<div><pre><code><span>┌─name─────────────────────────┐</span>\n<span>│ public_data.nyc_taxicab      │</span>\n<span>│ public_data.nyc_taxicab_2021 │</span>\n<span>└──────────────────────────────┘</span></code></pre></div>\n<h3 id=\"querying-tables\"></h3>\n<p>Query any Google Cloud Lakehouse Iceberg table directly:</p>\n<div><pre><code><span><span>SELECT</span> <span>count</span>(<span>*</span>)</span>\n<span><span>FROM</span> Lakehouse_catalog.`public_data.nyc_taxicab`</span>\n<span><span>WHERE</span> vendor_id <span>=</span> <span>1</span>;</span></code></pre></div>\n<p>You can also inspect the full schema:</p>\n<div><pre><code><span><span>SHOW</span> <span>CREATE TABLE</span> pickup_location_id, dropoff_location_id</span>\n<span><span>FROM</span> lakehouse_catalog.`public_data.nyc_taxicab`;</span></code></pre></div>\n<p>You can now query the local_taxi_data directly in ClickHouse native format for low query latency.</p>\n<h2 id=\"user-content-whats_next\"></h2>\n<p>This release is just the first step toward deeper integration with Google Cloud's data
