contentHtml: "<article><div><blockquote>\n<p><strong>TL;DR</strong><br><br>Building AI agents with MCP? There are now (at least) <strong>12 major agent SDKs</strong> with MCP support.<br><br>Each framework has different strengths: <strong>Claude Agent SDK</strong> for security-first production, <strong>OpenAI Agents SDK</strong> for delegation patterns, <strong>CrewAI</strong> for multi-agent workflows, <strong>LangChain</strong> for ecosystem breadth, <strong>Agno</strong> for minimal code, <strong>DSPy</strong> for prompt optimization, and more.<br><br><strong>We have a look at each of the frameworks and include code for interacting with a Model Context Protocol (MCP) Server for each of them.</strong></p>\n</blockquote>\n<p><a target=\"_blank\" href=\"https://modelcontextprotocol.io/docs/getting-started/intro\">Model Context Protocol</a> (MCP) is an open protocol that standardizes how applications interact with large language models (LLMs). Launched in late 2024, MCP has become the de facto standard for integrating systems and applications with LLMs, with support now available across major AI platforms, including <a target=\"_blank\" href=\"https://platform.openai.com/docs/guides/tools-connectors-mcp\">OpenAI</a>, <a target=\"_blank\" href=\"https://developers.googleblog.com/en/gemini-cli-fastmcp-simplifying-mcp-server-development/\">Gemini</a>, and <a target=\"_blank\" href=\"https://cloud.google.com/blog/products/ai-machine-learning/build-and-manage-multi-system-agents-with-vertex-ai\">Google's Vertex AI</a>.</p>\n<p>Platforms like <a target=\"_blank\" href=\"https://github.com/github/github-mcp-server\">GitHub</a>, <a target=\"_blank\" href=\"https://github.com/awslabs/mcp\">AWS</a> and <a target=\"_blank\" href=\"https://github.com/ClickHouse/mcp-clickhouse\">ClickHouse</a> build MCP servers, which define sets of tools and resources that LLMs can interact with. The LLM lists the tools available, and picks the most appropriate tool for the action it is trying to take.</p>\n<p>For example, the ClickHouse MCP server provides a tool called <code>run_select_query</code> that can be used to run a SQL SELECT statement against a ClickHouse database. The MCP server implements all of the logic needed to perform that action when the tool is used (creating a connection, authentication, etc.).</p>\n<p>MCP servers are conceptually very similar to REST APIs; in fact, before MCP was released, people were just using REST APIs to integrate with LLMs. REST APIs worked pretty well, but MCP provides clearer standardisation for developers and LLMs. MCP servers don’t replace REST APIs, they often live side-by-side providing functionality for different purposes.</p>\n<p>MCP servers originally ran locally as subprocesses, communicating through stdio or SSE (Server-Sent Events). However, there's been a recent shift toward platforms hosting remote MCP servers - similar to how REST APIs are deployed.</p>\n<p>With remote MCPs, users don't run the server themselves; their MCP client simply connects to an already-running service endpoint, often at a URL like <code>https://api.example.com/mcp</code>. This shift means MCP servers now need to handle concerns that were previously managed by the client environment: authentication, rate limiting, multi-tenancy, and authorization. Essentially, remote MCP servers are converging with REST APIs in terms of operational requirements, while maintaining MCP's standardized protocol for LLM tool usage.</p>\n<h2 id=\"agent-sdks\"></h2>\n<p>Agent SDKs are a building block used by developers to build agentic experiences in their applications, often providing much of the boilerplate needed to integrate with MCP servers (and much more). OpenAI function calling is model-specific, while MCP is model-agnostic. MCP provides standardization across different LLM providers and includes features like resource management and progress reporting that go beyond simple function calling. The real latency comes from tool execution. For a ClickHouse query, you're looking at the database query time plus MCP overhead. In practice, expect 50-200ms additional latency compared to direct API calls, though this is usually negligible compared to LLM inference time (2-5 seconds).</p>\n<h3 id=\"do-mcp-servers-work-with-local-llms\"></h3>\n<p>Yes, MCP is model-agnostic. You can use MCP servers with local models through frameworks like LangChain or LlamaIndex. Remote servers require more infrastructure but support production workloads.</p>\n<h3 id=\"can-mcp-servers-modify-data-or-only-read-it\"></h3>\n<p>MCP servers can provide any tools they want, including destructive operations. Always review which tools an MCP server exposes, especially in production. The Claude Agent SDK's allowlist approach is good practice here.</p>\n<h3 id=\"how-do-i-handle-mcp-server-authentication\"></h3>\n<p>Authentication is handled through environment variables passed to the MCP server on startup. Most will return the error to the LLM, which can then decide whether to retry, try a different approach, or report the failure. Some frameworks like Agno include automatic retry logic. You should implement timeout handling and consider circuit breakers for production deployments.</p>\n<h3 id=\"can-i-create-custom-mcp-servers\"></h3>\n<p>Yes, MCP is an open protocol. <a target=\"_blank\" href=\"https://modelcontextprotocol.io/docs/develop/build-server\">You can build MCP servers in Python</a>, TypeScript, or any language that can handle JSON-RPC over stdio or HTTP.
