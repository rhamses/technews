Here we will look at the more advanced use case of Kubernetes Logs. These changes will be used to formulate our Fluent Bit configuration. The Helm chart itself will deploy a <a target=\"_blank\" href=\"https://kubernetes.io/docs/concepts/workloads/controllers/daemonset/\">daemonset</a> on each node responsible for log collection.</p>\n<p>Under the <code>filters</code> key we are going to add the same <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/filters/nest\">nest filter</a> as our earlier post to move all fields under the <code>log</code> column.</p>\n<p>While the JSON type is great for the dynamic parts of the logs, we cannot currently use the columns it creates for primary keys. <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/guides/improving-query-performance/sparse-primary-indexes/sparse-primary-indexes-intro\">Primary keys</a> are a key component of accelerating query performance in ClickHouse and should broadly match those columns on which we are most likely to apply filters. For purposes of example, we will later create our table with a primary key on the <code>host</code>, <code>pod_name</code> and <code>timestamp</code> fields - filtering logs by the host, pod and timestamp seems like a reasonably common usage pattern for Kubernetes logs as a first pass. Obviously, this may vary depending on your use case and typical diagnosis paths, and we encourage users to read about optimizing and configuring primary keys <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/guides/improving-query-performance/sparse-primary-indexes/sparse-primary-indexes-design\">here</a>. To use these columns as primary keys we must therefore move them out of the JSON <code>log</code> field to the base of the message. To achieve this we use a <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/filters/lua\">lua filter</a>. This is currently necessary as the lift feature of the nest filter is not selective and the <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/filters/modify\">modify filter</a> is unfortunately <a target=\"_blank\" href=\"https://github.com/fluent/fluent-bit/issues/2152#issuecomment-1049615508\">not supported on nested fields</a>. file:</p>\n<div><pre><code><span><span>luaScripts:</span></span>\n<span>  <span>functions.lua:</span> <span>|</span></span>\n<span><span>    function set_fields(tag, timestamp, Any new fields which appear in the logs will automatically have new columns created for them within ClickHouse. We encourage users to use this capability for dynamic columns only. For fields which are expected to be on each message, and for which the type is known, we encourage users to lift these out of a JSON field to the root and explicitly define their type. Additionally, remove unused fields to minimize storage where possible and avoid column explosion. Your lua script may therefore be a lot longer in any production setting. As well as allowing more explicit typing e.g., lower precision integer, for better performance, users can also exploit codecs for compression.</p>\n<p><strong>Note: The JSON Object type is experimental and is undergoing improvements. Our advice with respect to this feature is evolving and may therefore change in later versions.</strong></p>\n<p>Finally, by default the Fluent Bit Helm chart configures a <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/administration/configuring-fluent-bit/classic-mode/configuration-file\">batch to be flushed</a> <a target=\"_blank\" href=\"https://github.com/fluent/helm-charts/blob/757f8e26184c6bb886950dae7bcda6e2a74a5526/charts/fluent-bit/values.yaml#L248\">every 1s</a>. ClickHouse prefers batches <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/about-us/performance/#performance-when-inserting-data\">of at least 1000 records</a>. You may wish to tune this flush time depending on the volume of logs generated by your Kubernetes cluster to <a target=\"_blank\" href=\"https://clickhouse.com/blog/common-getting-started-issues-with-clickhouse\">avoid common issues</a>.</p>\n<h2 id=\"conclusion\"></h2>\n<p>In this blog we set up Fluent Bit to route logs from a Kubernetes Environment to ClickHouse for expedited analysis.
