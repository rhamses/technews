By turning raw logs into structured columns, using optimized data types, and ordering similar values together, it’s possible to achieve over 170x compression.</p>\n</blockquote>\n<p>Storing logs at scale is difficult.</p>\n<p>They’re usually unstructured text that doesn’t compress efficiently. Yet, they hold important historical details about how applications and systems behave, information you don’t want to lose that is valuable for debugging during issues.</p>\n<p>In an observability system, logs sit alongside traces and metrics. Unlike logs, traces and metrics are already structured and repetitive, which makes them compress naturally in a columnar format. Fields such as Timestamp, ServiceName, and Latency fit well into column-based storage and compress effectively.</p>\n<p>But what if we could give logs a similar structure? Logs could achieve the same kind of efficient compression by identifying the variable parts of each message, extracting them into separate columns, using the most efficient data types, and storing similar data close together on disk.</p>\n<p>In this first post, we’ll experiment with this approach and transform raw logs into structured data, with the goal of reaching 170x compression. <strong>In a follow-up blog, we will explore how to leverage log clustering techniques to extend these ideas to any type of logs and automatically improve their compression ratio.</strong>&#160;</p>\n<h2 id=\"why-compression-is-important\"></h2>\n<p>Compression is not just about reduced storage; it also positively impacts performance and resource usage.&#160;</p>\n<p><strong>Reduced I/O and faster queries</strong></p>\n<p>Smaller data means less time to read from disk. In a columnar database, queries often scan large volumes of data, so reading compressed blocks significantly reduces I/O. This reduces stress on resources, such as disk bandwidth and network, and leads to faster query execution.</p>\n<p><strong>Lower storage requirements</strong></p>\n<p>Reducing how much data needs to be stored lowers storage costs. Even when using object storage like S3, where capacity is relatively cheap, compression still matters as more data can be cached locally in NVMEs for fast access.</p>\n<p><strong>Better caching efficiency</strong></p>\n<p>Compressed data fits more easily into memory and cache layers. This increases cache hit rates, reducing the need to fetch data from disks.</p>\n<h2 id=\"experiment-with-nginx-access-logs\"></h2>\n<p>Nginx access logs record every request handled by an Nginx server.
