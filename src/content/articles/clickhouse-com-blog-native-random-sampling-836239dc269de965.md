To do that, we need to specify a sample key when we create our table.</p>\n<p>A sample key is an expression that determines which rows get included when you sample your data. The key should be an unsigned integer (like a hash), have high cardinality, and distribute evenly across its range. One such function is <a target=\"_blank\" href=\"https://clickhouse.com/docs/sql-reference/functions/hash-functions#sipHash64\"><code>sipHash64</code></a>, a cryptographic hash function that returns a 64-bit value.</p>\n<p>We can verify this by checking how evenly it distributes <code>postcode1</code> and <code>postcode2</code>.\nThe following query uses <code>sipHash64</code> on <code>postcode1</code> and <code>postcode2</code> and then rounds down the hashes into 10 buckets, and each of them should hold around 10% of the values.</p>\n<div><pre><code><span><span>WITH</span> pow(<span>2</span>, <span>64</span>) <span>AS</span> maxUInt64, <span>10</span> <span>AS</span> numBuckets</span>\n<span><span>SELECT</span></span>\n<span>    <span>floor</span>(sipHash64(postcode1, postcode2) <span>/</span> (maxUInt64 <span>/</span> numBuckets)) <span>AS</span> bucket,</span>\n<span>    <span>count</span>() <span>AS</span> <span>rows</span>,</span>\n<span>    round(<span>count</span>() <span>/</span> (<span>SELECT</span> <span>count</span>() <span>FROM</span> uk_price_paid) <span>*</span> <span>100</span>, <span>2</span>) <span>AS</span> pct</span>\n<span><span>FROM</span> uk_price_paid</span>\n<span><span>GROUP</span> <span>BY</span> bucket</span>\n<span><span>ORDER</span> <span>BY</span> bucket;</span></code></pre></div>\n<p>If we run the query, we'll see the following output:</p>\n<div><pre><code><span>┌─bucket─┬────rows─┬───pct─┐</span>\n<span>│      0 │ 3106578 │  10.2 │</span>\n<span>│      1 │ 3025622 │  9.94 │</span>\n<span>│      2 │ 3043133 │  9.99 │</span>\n<span>│      3 │ 3033438 │  9.96 │</span>\n<span>│      4 │ 3063534 │ 10.06 │</span>\n<span>│      5 │ 3048884 │ 10.01 │</span>\n<span>│      6 │ 3005960 │  9.87 │</span>\n<span>│      7 │ 3053378 │ 10.03 │</span>\n<span>│      8 │ 3029517 │  9.95 │</span>\n<span>│      9 │ 3042419 │  9.99 │</span>\n<span>└────────┴─────────┴───────┘</span></code></pre></div>\n<p>Each bucket holds right around 10% - result of the same <code>SELECT .. SAMPLE</code> query is always the same.\nThe <code>SAMPLE</code> clause works in two modes.</p>\n<p>The first mode is <strong>by fraction</strong>, where we provide a value between 0 and 1 and the query will be executed on that fraction of the data.</p>\n<div><pre><code><span><span>SELECT</span> <span>count</span>() </span>\n<span><span>FROM</span> uk_price_paid_sample </span>\n<span>SAMPLE <span>0.1</span>;</span></code></pre></div>\n<p>This query takes the first 10% of the hash value range, effectively all rows where <code>sipHash64(postcode1, postcode2) &lt; 2^64 * 0.1</code>.\nThe result of running the query is shown below:</p>\n<div><pre><code><span>┌─count()─┐</span>\n<span>│ 3106578 │ -- 3.11 million</span>\n<span>└─────────┘</span>\n<span></span>\n<span>1 row <span>in</span> <span>set</span>. Elapsed: 0.043 sec.</span></code></pre></div>\n<p>There are 30.45 million rows in the table, so 10% of that is 3.045 million, which is reasonably close to the 3.11 million we got back.</p>\n<p>The second mode is <strong>by row count</strong>, where we specify a minimum number of rows to return:</p>\n<div><pre><code><span><span>SELECT</span> <span>count</span>() </span>\n<span><span>FROM</span> uk_price_paid_sample </span>\n<span>SAMPLE <span>100000</span>;</span></code></pre></div>\n<p>This returns <em>at least</em> 100,000 rows. ClickHouse computes a threshold of <code>(100000 / estimated_table_rows) * 2^64</code> and selects rows whose hash falls below it.\nThe output of running the query is shown below:</p>\n<div><pre><code><span>┌─count()─┐</span>\n<span>│  103347 │</span>\n<span>└─────────┘</span>\n<span></span>\n<span>1 row <span>in</span> <span>set</span>. Elapsed: 0.009 sec.</span></code></pre></div>\n<p>In both cases, because the hash is part of the primary index, ClickHouse can quickly skip granules whose hash values are above the threshold.</p>\n<h2 id=\"the-sample-factor-virtual-column\"></h2>\n<p>When using sampling, we can also use <code>_sample_factor</code>, a virtual column that tells you how many rows from the full dataset each sampled row represents.\nWhen there's no sampling, it's 1. For a 10% sample it's 10. For the row-count sample it's around 304.5.</p>\n<p>If we want to estimate the total number of rows, we can sum <code>_sample_factor</code>, as shown in the following query:</p>\n<div><pre><code><span><span>SELECT</span> <span>'None'</span> <span>AS</span> sampleType, <span>count</span>(), <span>sum</span>(_sample_factor)</span>\n<span><span>FROM</span> uk_price_paid_sample</span>\n<span></span>\n<span><span>UNION</span> <span>ALL</span></span>\n<span></span>\n<span><span>SELECT</span> <span>'Fraction (0.1)'</span> <span>AS</span> sampleType, <span>count</span>(), <span>sum</span>(_sample_factor)</span>\n<span><span>FROM</span> uk_price_paid_sample SAMPLE <span>0.1</span></span>\n<span></span>\n<span><span>UNION</span> <span>ALL</span></span>\n<span></span>\n<span><span>SELECT</span> <span>'Number (100,000)'</span> <span>AS</span> sampleType, <span>count</span>(), <span>sum</span>(_sample_factor)</span>\n<span><span>FROM</span> uk_price_paid_sample SAMPLE <span>100000</span>;</span></code></pre></div>\n<div><pre><code><span>┌─sampleType───────┬──count()─┬─<span>sum</span>(_sample_factor)─┐</span>\n<span>│ None             │ 30452463 │            30452463 │</span>\n<span>│ Fraction (0.1)   │  3106578 │            31065780 │</span>\n<span>│ Number (100,000) │   103347 │  31471706.936610293 │</span>\n<span>└──────────────────┴──────────┴─────────────────────┘</span></code></pre></div>\n<p>Both of the sampling techniques over estimate the total number of rows by 2-3%, which isn't too bad.</p>\n<p>The same principle applies to other aggregations.
