Maybe loading data takes longer than you’d like or perhaps a query is slower than your boss wants it to be. So you do some googling and in an answer to an old StackOverflow question you read about <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/operations/settings/settings/#settings-max_threads\">max_threads</a> and how it can be used to speed everything up.</p>\n<p>And yet, as so often in life and technology, it’s not that simple!</p>\n<p>By default, ClickHouse will try to determine the correct number of threads based on the number of available CPU cores. You can check what it is set to using <code>SELECT getSetting('max_threads')</code>. For example, on my MacBook Pro it returns 10, which is the number of cores in an Apple M1 chip (yes, ClickHouse works on ARM!).</p>\n<p>You can set it to use more threads, but it won’t always work well. For example, try this (after you create the right table structure <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/ontime/#creating-a-table\">see here</a>):</p>\n<div><pre><code><span>INSERT INTO ontime SELECT *</span>\n<span>FROM s3('https://clickhouse-public-datasets.s3.amazonaws.com/ontime/csv_by_year/*.csv.gz', CSVWithNames)</span>\n<span>SETTINGS max_threads = 100</span></code></pre></div>\n<p>Unless you have a really big machine, it will not complete – and use a lot of memory along the way. Effectively, every one of the 100 threads is a separate insert sub-query and requires its own memory to retrieve and write data.</p>\n<p>So should you set <code>max_threads = 1</code>? Well, maybe - for me, the query above will insert data at about 120k rows per second when limited to a single thread. Without <code>max_threads</code> it will insert 320k rows per second. However, the optimal insert speed for me is with 4 threads - 428k rows per second, some 33% faster than with thread autodetection. Sometimes it pays to experiment.</p>\n<p>Similarly, when reading data, more threads are not always better. Yes, more threads mean there are more CPU cycles available to a query. However, it also means there are more separate states that all need to be merged back together before the result can be returned. Most importantly, many threads per query will reduce the number of queries per second that can be run.</p>\n<p>For example, using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/getting-started/example-datasets/uk-price-paid\">UK Property Price Paid dataset</a>, we can check what the most popular street names are using:</p>\n<div><pre><code><span><span>SELECT</span> <span>count</span>(), street <span>FROM</span> uk_price_paid</span>\n<span><span>GROUP</span> <span>BY</span> street <span>ORDER</span> <span>BY</span> <span>count</span>() <span>DESC</span></span></code></pre></div>\n<p>The top 3: High Street, Station Road, London Road. In the next 7, there are Church Road, Church Street, and Church Lane - maybe not surprising in a monarchy where the King is both Head of State and Head of the Church.</p>\n<p>This above query takes 0.2 seconds on my machine. If I set <code>max_threads = 1</code> it takes 0.5 seconds. So more threads are better, right?</p>\n<p>In this case, yes - except if I want to run this query many times concurrently. I can execute 10 queries concurrently 10 times (100 queries in total) with <code>clickhouse-benchmark</code>:</p>\n<div><pre><code><span>clickhouse-benchmark -c 10 -i 100 -q \"&lt;query&gt;”</span></code></pre></div>\n<p>On my machine, it takes about 27 seconds to run all 100 queries, just under 4 queries a second (<code>QPS: 3.776</code> according to the result).</p>\n<p>With <code>max_threads = 1</code> it takes about 10 seconds,  or 13 queries per second (<code>QPS: 13.122</code>). Three times higher query throughput! And all we had to do was change the number of threads - but lower, not higher. Generally, if you expect a lot of concurrent queries you should consider explicitly lowering the thread count per query.</p>\n<h2 id=\"reading-corner\"></h2>\n<p>What we’ve been reading:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-cloud-public-beta\">ClickHouse Cloud is now in Public Beta</a> The launch blog post for the new and only official ClickHouse managed service by us, the creators of ClickHouse.</li>\n<li><a target=\"_blank\" href=\"https://clickhouse.com/blog/getting-data-into-clickhouse-part-3-s3\">Getting Data Into ClickHouse - Part 3 - Using S3</a> Part 3 of a series on how to get data into ClickHouse.
