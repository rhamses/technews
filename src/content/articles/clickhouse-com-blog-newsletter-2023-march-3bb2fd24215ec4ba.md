This represents an easy way to summarise a large dataset and identify columns that are either strongly or negatively correlated.</p>\n<h2 id=\"query-of-the-month---contributing-to-clickhouse\"></h2>\n<p>Real-time analytics is an important, and perhaps often misunderstood, concept. Real-time can imply at the point of ingestion, at the point of transformation, at the point of application interaction, or…importantly…at the point of interest. <br>\n<br>\nWe found ourselves interested, in the last week, about the number of contributors (over time) to the various ClickHouse repositories. And, also the number of unique users per month. The query itself turned out to be quite interesting.  <br>\n<br>\nThis is a little challenging as we want the cumulative unique users, not just the unique number per month. To achieve this, we first generate an array of the  unique contributors grouped by month (<code>uniq_users</code>)  via the aggregate function <code>groupArrayDistinct</code> (see our <a target=\"_blank\" href=\"https://clickhouse.com/blog/aggregate-functions-combinators-in-clickhouse-for-arrays-maps-and-states\">recent blog post</a> on aggregate functions). A window function in turn groups these monthly arrays and produces an array of the distinct contributors so far for each month. Finally an outer query identifies the unique number of values in each column.</p>\n<p>The query itself is fairly direct and shown below (and also available for perusing on <a target=\"_blank\" href=\"https://sql.clickhouse.com/?query_id=KIZPJXDYG1QB6DQDFSAVIE\">ClickHouse Play)</a>.</p>\n<pre><p>\nSELECT\n    month,\n    arrayUniq(cul_users) AS cul_users,\n    arrayUniq(uniq_users) AS uniq_users\nFROM\n(\n    SELECT\n        month,\n        groupArrayDistinctArray(uniq_users) OVER (ORDER BY month ASC) AS cul_users,\n        groupArrayDistinct(actor_login) AS uniq_users\n    FROM default.github_events\n    WHERE (repo_name LIKE 'ClickHouse%') AND (event_type = 'PullRequestEvent')\n    GROUP BY toStartOfMonth(created_at) AS month\n    ORDER BY month ASC\n)\n┌──────month─┬─cul_users─┬─uniq_users─┐\n│ 2018-08-01 │         2 │          2 │\n│ 2018-10-01 │         4 │          2 │\n│ 2018-11-01 │         4 │          2 │\n│ 2018-12-01 │         7 │          5 │\n│ 2019-02-01 │         8 │          2 │\n│ 2019-03-01 │         9 │          1 │\n│ 2019-05-01 │        10 │          2 │\n│ 2019-06-01 │        10 │          2 │\n│ 2019-07-01 │        12 │          3 │\n│ 2019-08-01 │        15 │          5 │\n│ 2019-09-01 │        38 │         31 │\n│ 2019-10-01 │        75 │         60 │\n│ 2019-11-01 │       114 │         77 │\n│ 2019-12-01 │       145 │         81 │\n…\n│ 2022-06-01 │      1118 │        122 │\n│ 2022-07-01 │      1157 │        121 │\n│ 2022-08-01 │      1208 │        120 │\n│ 2022-09-01 │      1239 │        118 │\n│ 2022-10-01 │      1280 │        131 │\n│ 2022-11-01 │      1317 │        133 │\n│ 2022-12-01 │      1344 │        119 │\n│ 2023-01-01 │      1374 │        123 │\n│ 2023-02-01 │      1405 │        142 │\n│ 2023-03-01 │      1441 │        124 │\n└────────────┴───────────┴────────────┘\n53 rows in set. After consulting and obtaining some enlightenment around state functions, we realised these could be used at query time for passing states from a subquery - not just for storing <a target=\"_blank\" href=\"https://clickhouse.com/blog/using-materialized-views-in-clickhouse\">intermediate states from materialized views</a>. The query below uses the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators#-state\"><code>uniqState</code></a> function to return “a sketch” of unique contributors per month. We then use a simple window function which performs a cumulative merge of these sketches using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/combinators#-state\"><code>uniqMerge</code></a> function.</p>\n<pre><p>\nWITH states AS\n    (\n        SELECT\n            month,\n            uniqState(actor_login) AS uniq_users\n        FROM default.github_events\n        WHERE (repo_name LIKE 'ClickHouse%') AND (event_type = 'PullRequestEvent')\n        GROUP BY toStartOfMonth(created_at) AS month\n        ORDER BY month ASC\n    )\nSELECT\n    month,\n    uniqMerge(uniq_users) OVER (ORDER BY month ASC) AS cul_users\nFROM states\n53 rows in set.
