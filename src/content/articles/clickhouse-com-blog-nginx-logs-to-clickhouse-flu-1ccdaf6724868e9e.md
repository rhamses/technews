contentHtml: "<article><div><p><span><img alt=\"calypia-blog.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fcalypia_blog_97dbedcd22.png&w=2048&q=75\"></span></p>\n<p>This blog post is part of a series:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://clickhouse.com/blog/kubernetes-logs-to-clickhouse-fluent-bit\">Sending Kubernetes logs To ClickHouse with Fluent Bit</a></li>\n</ul>\n<h2 id=\"introduction\"></h2>\n<p>ClickHouse has become a popular backend for receiving logs after users like <a target=\"_blank\" href=\"https://www.uber.com/en-PT/blog/logging/\">Uber incorporated the blazing-fast </a>database into their infrastructure. One common challenge with all data stores is how to ingest data from various sources. Thankfully this is a challenge that the Cloud Native Computing Foundation (CNCF) project Fluent Bit has solved for many backends, such as Amazon. Fluent Bit is a super fast, lightweight, and highly scalable logging and metrics processor and forwarder.</p>\n<p>In this blog, we walk through how to set up Fluent Bit to route logs to Clickhouse in under 5 minutes. In our next post, we will showcase an everyday observability use case of collecting and enriching logs from Kubernetes.</p>\n<h2 id=\"environment\"></h2>\n<ul>\n<li>Ubuntu 20.04 LTS running both Clickhouse and <a target=\"_blank\" href=\"https://calyptia.com/download/\">Calypita Fluent Bit </a>(LTS version of Fluent Bit provided by the creators)</li>\n<li>Fluent Bit v1.9.9</li>\n</ul>\n<p>For ClickHouse, we recommend trying our serverless <a target=\"_blank\" href=\"https://clickhouse.cloud/signUp\">ClickHouse Cloud</a>, which has a generous free trial that is more than sufficient to follow this blog post. Alternatively, all instructions should be compatible with self-managed versions greater than 22.6.</p>\n<h2 id=\"creating-the-clickhouse-database-and-tables\"></h2>\n<p>Our first step is to create a database within ClickHouse where we will store the logs. We can run the following command via the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/interfaces/cli/\">clickhouse-client</a> or via your ClickHouse Cloud console:</p>\n<pre><p>\nCREATE DATABASE fluentbit\n</p>\n</pre>\n<p>Note that the <strong><a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/json/\">JSON type</a> is currently experimental</strong> in ClickHouse core database and not enabled by default in <a target=\"_blank\" href=\"https://clickhouse.cloud/signUp\">ClickHouse Cloud</a>. Should users wish to use this capability in <a target=\"_blank\" href=\"https://clickhouse.cloud/signUp\">ClickHouse Cloud</a>, they can open a support case once they’ve started a service.</p>\n<p>After creating the database, we are required to enable the JSON object type via the  experimental flag <code>allow_experimental_object_type</code>:</p>\n<pre><p>\nSET allow_experimental_object_type = 1\n</p>\n</pre>\n<p>Once set, we can create the table with the provided structure. This creates a field <code>log</code> that contains all the JSON objects.</p>\n<pre><p>\nCREATE TABLE fluentbit.jsonlogs\n(\n    timestamp DateTime,\n    log JSON\n)\nEngine = MergeTree ORDER BY tuple()\n</p>\n</pre>\n<p>Once created, we can configure Fluent Bit to send data.</p>\n<h2 id=\"configuring-fluent-bit-on-ubuntu\"></h2>\n<p>The instructions below use the open source version of Fluent Bit. If you are interested in using an LTS version with additional premium features, you find more information on Calyptia’s offering <a target=\"_blank\" href=\"https://calyptia.com/products/\">here</a>.</p>\n<p>For example purposes, we send basic Nginx access logs and assume the user is using an Ubuntu system. For other systems, instructions are available <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/installation/getting-started-with-fluent-bit#install-on-linux-packages\">here</a>:</p>\n<div><pre><code><span>curl https://raw.githubusercontent.com/fluent/fluent-bit/master/install.sh | sh</span></code></pre></div>\n<p>This will install Fluent Bit to /opt/fluent-bit. If you need some test Nginx Access Logs, you can download a series of mock access logs from <a target=\"_blank\" href=\"https://gist.githubusercontent.com/agup006/b936d299c11b60283bdaf05a12e334eb/raw/b87905c7ea1e21745dba87233666135ee61d0087/apache-access.log\">here</a> and place them under <code>/var/log/access.log</code>.</p>\n<div><pre><code><span><span>sudo</span> wget -O /var/log/access.log https://gist.githubusercontent.com/agup006/b936d299c11b60283bdaf05a12e334eb/raw/b87905c7ea1e21745dba87233666135ee61d0087/apache-access.log</span>\n<span><span>sudo</span> <span>chmod</span> a+r /var/log/access.log</span></code></pre></div>\n<p>As a high-level intro to Fluent Bit configuration we designate a set of <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/inputs\">Inputs</a>, <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/filters\">Filters</a>, and <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/outputs\">Outputs</a>. On the Input side, we are going to specify the <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/inputs/tail\"><code>tail</code></a> plugin which will read the access logs and parse in with a well-known format.</p>\n<p>Once these logs are parsed, we will then use a Fluent Bit <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/filters/nest\">Nest Filter</a> to nest all fields under a field “log”, allowing ClickHouse to recognize the field where the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/guides/developer/working-with-json/json-intro\">JSON object </a>will be housed.</p>\n<p>Last but not least, we will use Fluent Bit’s <a target=\"_blank\" href=\"https://docs.fluentbit.io/manual/pipeline/outputs/http\">HTTP output</a> plugin to route these logs to ClickHouse with a few parameters.  You can see from the URI that we are using the database and table that we created earlier.</p>\n<h3 id=\"fluent-bit-configuration\"></h3>\n<p><strong>Note:</strong> We also need to specify the default user’s password for Fluent Bit to make use of HTTP Basic Authentication. For <a target=\"_blank\" href=\"https://clickhouse.cloud/signUp\">ClickHouse Cloud</a> we specify port 8443 and enable SSL via the <code>tls on</code> parameter. Users using self-managed ClickHouse may need to use the port 8143 if your cluster is not secure. You will also need to explicitly set the use of http, i.e. <code>tls off</code> parameter.</p>\n<p>Append the following configuration file to <code>/etc/fluent-bit/fluent-bit.conf</code>.</p>\n<pre><div><p>\n[INPUT]\n    name tail\n    path /var/log/access.log\n    read_from_head true\n    parser nginx_access\n[FILTER]\n    Name nest\n    Match *\n    Operation nest\n    Wildcard *\n    Nest_under log \n[OUTPUT]\n    name http\n    tls on\n    match *\n    host </p><!-- --><p>\n    port 8443\n    URI /?query=INSERT+INTO+fluentbit.jsonlogs+FORMAT+JSONEachRow\n    format json_stream\n    json_date_key timestamp\n    json_date_format epoch\n    http_user default\n    http_passwd </p><!-- -->\n</div>\n</pre>\n<p>If using <a target=\"_blank\" href=\"https://clickhouse.cloud/signUp\">ClickHouse Cloud</a>, your credentials will be available when you create your cluster i.e.</p>\n<p><span><img alt=\"connect_cloud.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fconnect_cloud_d46c740325.png&w=2048&q=75\"></span></p>\n<p>Run Fluent Bit, and send the logs to ClickHouse, with the following command:</p>\n<div><pre><code><span>/opt/fluent-bit/bin/fluent-bit -c /etc/fluent-bit/fluent-bit.conf</span></code></pre></div>\n<h2 id=\"searching-the-logs-in-clickhouse\"></h2>\n<p>Within ClickHouse we can run the following to see our logs in action. Without the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/select/format/#default-format\">FORMAT</a> option we only see the values of our JSON.</p>\n<pre><p>\nSET output_format_json_named_tuples_as_objects = 1\nSELECT * FROM fluentbit.jsonlogs FORMAT JSONEachRow\n</p>\n</pre>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/uploads/logs_9043688a6c.png\">\n         <span><img alt=\"logs.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Flogs_9043688a6c.png&w=2048&q=75\"></span>\n</a></p><p>A benefit with these logs now in ClickHouse is we can run adhoc queries for analysis without having to designate any schema.  Using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/describe-table/\">DESCRIBE</a> command, with the setting <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/guides/developer/working-with-json/json-semi-structured/#json-object-type\"><code>describe_extend_object_types</code></a>, we can discover the available fields in our jsonlogs table.</p>\n<pre><p>\nDESCRIBE TABLE fluentbit.jsonlogs\nFORMAT Vertical\nSETTINGS describe_extend_object_types = 1\nRow 1:\n──────\nname:               timestamp\ntype:               DateTime\ndefault_type:\ndefault_expression:\ncomment:\ncodec_expression:\nttl_expression:\nRow 2:\n──────\nname:               log\ntype:               Tuple(agent String, code String, host String, method String, path String, referer String, remote String, size String, user String)\ndefault_type:\ndefault_expression:\ncomment:\ncodec_expression:\nttl_expression:\n2 rows in set. Elapsed: 0.001 sec.\n</p>\n</pre>\n<p>We can run the following command to understand how many error codes are returned - note how we access the code field via its dot delimited json path.</p>\n<pre><p>\nSELECT\n    count(log.code) AS count,\n    log.code AS code\nFROM fluentbit.jsonlogs\nGROUP BY log.code\n┌─count─┬─code─┐\n│    26 │ 301  │\n│     9 │ 500  │\n│   397 │ 200  │\n│    17 │ 404  │\n└───────┴──────┘\n4 rows in set. Elapsed: 0.003 sec.\n</p>\n</pre>\n<p>For users interested in visualizing these logs, we recommend Grafana and the officially supported ClickHouse plugin. Further details can be found <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/connect-a-ui/grafana-and-clickhouse\">here</a> with an example of visualizing JSON logs at the end of this <a target=\"_blank\" href=\"https://clickhouse.com/blog/visualizing-data-with-grafana\">earlier post</a>. Below we show the above data in the Logs view of Grafana.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/uploads/grafana_logs_a00eb90de0.png\">\n         <span><img alt=\"grafana-logs.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fgrafana_logs_a00eb90de0.png&w=2048&q=75\"></span>\n</a></p><p>Note: ensure your Grafana instance has access to your <a target=\"_blank\" href=\"https://clickhouse.cloud/signUp\">ClickHouse Cloud</a> service with appropriate IP Access List rules.</p>\n<h2 id=\"summary\"></h2>\n<p>In this post we have loaded Nginx logs into ClickHouse using Fluent Bit and the JSON type.
