contentHtml: "<div><p>Dates come in all shapes and sizes - Unix timestamps from event streams, weird looking numeric dates from legacy database exports, ISO 8601 strings from APIs, and more. Lucky for us, ClickHouse has a rich set of functions to handle all of them and that's what we're going to explore in this blog post.</p>\n<p>We'll start with the most explicit approaches: converting Unix timestamps with <code>fromUnixTimestamp</code>, parsing packed numeric dates with <code>YYYYMMDDToDate</code>, and parsing known format strings with <code>parseDateTime</code>. Then we'll look at the <code>parseDateTimeBestEffort</code> family for when the format is unknown or mixed.</p>\n<p>Finally, we'll cover how casting dates with the <code>cast_string_to_date_time_mode</code> setting might be a better choice than explicit function calls for some use cases.</p>\n<h2 id=\"user-content-unix_timestamps\"></h2>\n<p>First up, Unix timestamps! Unix timestamps represent the number of seconds since January 1st, 1970. We can use the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/date-time-functions#fromUnixTimestamp\"><code>fromUnixTimestamp</code></a> function to convert them:</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    fromUnixTimestamp(<span>1704067295</span>) <span>AS</span> val1, toTypeName(val1);</span></code></pre></div>\n<p>This returns a <code>DateTime</code> type. If you have milliseconds since January 1st, 1970, there's a different function — <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#fromUnixTimestamp64Milli\"><code>fromUnixTimestamp64Milli</code></a> — and the type comes back as <code>DateTime64(3)</code>, where the <code>3</code> means precision up to milliseconds.</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    fromUnixTimestamp64Milli(<span>1704067295123</span>) <span>AS</span> val2, toTypeName(val2);</span></code></pre></div>\n<p>For microseconds, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#fromUnixTimestamp64Micro\"><code>fromUnixTimestamp64Micro</code></a> returns <code>DateTime64(6)</code>:</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    fromUnixTimestamp64Micro(<span>1704067295123456</span>) <span>AS</span> val3, toTypeName(val3);</span></code></pre></div>\n<h2 id=\"user-content-numeric_date_formats\"></h2>\n<p>Sometimes dates are represented as plain numbers encoding the year, month, and day — with no separators or formatting. This is common in legacy database exports or flat files from mainframes. The function <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/date-time-functions#YYYYMMDDToDate\"><code>YYYYMMDDToDate</code></a> handles this:</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    YYYYMMDDToDate(<span>20240115</span>) <span>AS</span> val1, toTypeName(val1);</span></code></pre></div>\n<p>If the number also includes time information, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/date-time-functions#YYYYMMDDhhmmssToDateTime\"><code>YYYYMMDDhhmmssToDateTime</code></a> handles that too:</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    YYYYMMDDhhmmssToDateTime(<span>20240115143022</span>) <span>AS</span> val2, toTypeName(val2);</span></code></pre></div>\n<h2 id=\"user-content-known_format_strings\"></h2>\n<p>APIs often return dates as strings. If you know the format, you can use <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#parseDateTime\"><code>parseDateTime</code></a> with a MySQL date format string:</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    parseDateTime(<span>'15/01/2024 14:30:22'</span>, <span>'%d/%m/%Y %H:%i:%s'</span>) <span>AS</span> val1,</span>\n<span>    toTypeName(val1);</span></code></pre></div>\n<p>This returns a <code>DateTime</code> including the timezone.</p>\n<p>If you prefer Joda date format strings, there's <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#parseDateTimeInJodaSyntax\"><code>parseDateTimeInJodaSyntax</code></a> which produces the same output:</p>\n<div><pre><code><span><span>SELECT</span></span>\n<span>    parseDateTimeInJodaSyntax(<span>'15/01/2024 14:30:22'</span>, <span>'dd/MM/yyyy HH:mm:ss'</span>) <span>AS</span> val2,</span>\n<span>    toTypeName(val2);</span></code></pre></div>\n<h2 id=\"user-content-best_effort_parsing\"></h2>\n<p>The previous three approaches all assumed we knew the exact date format. But what if we don't? That's where the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#parseDateTimeBestEffort\"><code>parseDateTimeBestEffort</code></a> family of functions comes in. Imagine we have dates in a mix of different formats:</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, parseDateTimeBestEffort(raw) <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates;</span></code></pre></div>\n<p>We can also convert to <code>DateTime64</code> using <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#parseDateTime64BestEffort\"><code>parseDateTimeBestEffort64</code></a>, like the earlier functions:</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, parseDateTime64BestEffort(raw) <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates;</span></code></pre></div>\n<p>What happens if we include a completely invalid date?</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'not a date'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, parseDateTime64BestEffort(raw) <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates;</span></code></pre></div>\n<p>ClickHouse throws an exception!</p>\n<p>We can work around this with the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#parseDateTime64BestEffortOrNull\"><code>parseDateTimeBestEffort64OrNull</code></a> variant, which returns <code>NULL</code> instead:</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'not a date'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, parseDateTime64BestEffortOrNull(raw) <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates;</span></code></pre></div>\n<p>Or if you'd rather get an actual datetime value, <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/functions/type-conversion-functions#parseDateTime64BestEffortOrZero\"><code>parseDateTimeBestEffort64OrZero</code></a> falls back to January 1st, 1970 at midnight:</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'not a date'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, parseDateTime64BestEffortOrZero(raw) <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates;</span></code></pre></div>\n<h2 id=\"user-content-casting\"></h2>\n<p>If you'd rather avoid calling explicit parse functions throughout your queries, you can cast string values directly to date types using <code>::DateTime</code>. However, there's an important setting to be aware of: <code>cast_string_to_date_time_mode</code>.</p>\n<p>By default it's set to <code>basic</code>, which handles standard formats like <code>YYYY-MM-DD</code> and <code>YYYY-MM-DD HH:MM:SS</code>, but anything else will fail. For broader format support, change it to <code>best_effort</code>. Note that this setting still throws an exception for completely invalid dates.</p>\n<p>You can pass the setting inline per query:</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, raw::DateTime <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates</span>\n<span>SETTINGS cast_string_to_date_time_mode <span>=</span> <span>'best_effort'</span>;</span></code></pre></div>\n<p>Or configure it at the session level so you don't need it in every query:</p>\n<div><pre><code><span><span>SET</span> cast_string_to_date_time_mode <span>=</span> <span>'best_effort'</span>;</span></code></pre></div>\n<p>Then the same query works without the <code>SETTINGS</code> clause:</p>\n<div><pre><code><span><span>WITH</span> dates <span>AS</span> (</span>\n<span>    <span>SELECT</span> <span>'2024-01-15T14:30:22.000Z'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'2024-01-15'</span> <span>AS</span> raw</span>\n<span>    <span>UNION</span> <span>ALL</span></span>\n<span>    <span>SELECT</span> <span>'1704067295'</span> <span>AS</span> raw</span>\n<span>)</span>\n<span><span>SELECT</span> raw, raw::DateTime <span>AS</span> val, toTypeName(val)</span>\n<span><span>FROM</span> dates;</span></code></pre></div>\n<p>Finally, imagine that we have the following file that contains a variety of dates:</p>\n<p><em>dates.csv</em></p>\n<div><pre><code><span>raw</span>\n<span>2024-01-15T14:30:22.000Z</span>\n<span>2024-01-15</span>\n<span>1704067295</span></code></pre></div>\n<p>We can parse the file(<span>'dates.csv'</span>, CSVWithNames);</span></code></pre></div>\n<div><pre><code><span>┌─raw──────────────────────┬─────────────────val─┬─toTypeName(val)─┐</span>\n<span>│ 2024-01-01 00:01:35 │ DateTime        │</span>\n<span>└──────────────────────────┴─────────────────────┴─────────────────┘</span></code></pre></div></div>"
