contentHtml: "<article><div><p>While building <a target=\"_blank\" title=\"pg_clickhouse on PGXN\" href=\"https://pgxn.org/dist/pg_clickhouse/\">pg_clickhouse</a>, I developed a PostgreSQL setting (or \"<a target=\"_blank\" title=\"PostgreSQL Source: GUC Implementation Notes\" href=\"https://github.com/postgres/postgres/blob/master/src/backend/utils/misc/README\">GUC</a>\")\nthat takes a list of key/value pairs and sets them as <a target=\"_blank\" title=\"ClickHouse Docs: Session Settings\" href=\"https://clickhouse.com/docs/operations/settings/settings\">session settings</a> in\nevery query sent to ClickHouse. The <a target=\"_blank\" title=\"pc_clickhouse Release v0.1.0\" href=\"https://github.com/ClickHouse/pg_clickhouse/releases/tag/v0.1.0\">v0.1.0</a> release kept the list of settings\nas a string, and parsed it for every query. We wanted to reduce that overhead\nby parsing them into a key/value data structure when the GUC is set.</p>\n<p>This post\ngoes into the implementation weeds for this work, released in <a target=\"_blank\" title=\"pc_clickhouse Release v0.1.1\" href=\"https://github.com/ClickHouse/pg_clickhouse/releases/tag/v0.1.1\">v0.1.1</a>,\ncovering the various attempts and ultimate solution. It will hopefully be\nhelpful to other PostgreSQL extension developers.</p>\n<p>Just want to try querying ClickHouse from PostgreSQL with <a target=\"_blank\" title=\"pg_clickhouse on PGXN\" href=\"https://pgxn.org/dist/pg_clickhouse/\">pg_clickhouse</a> and\ntune out all this C code and internals stuff? Check out <a target=\"_blank\" title=\"pg_clickhouse Tutorial on PGXN\" href=\"https://pgxn.org/dist/pg_clickhouse/doc/tutorial.html\">the tutorial</a>.</p>\n<h2 id=\"the-challenge\"></h2>\n<p>I wanted to optimize away parsing the key/value pairs from the <a target=\"_blank\" title=\"pg_clickhouse on PGXN\" href=\"https://pgxn.org/dist/pg_clickhouse/\">pg_clickhouse</a>\n<code>pg_clickhouse.session_settings</code> GUC for every query by pre-parsing it on\nassignment and assigning it to a separate variable. It took a few tries, as\nthe GUC API requires quite specific memory allocation for extra data to work\nproperly. It took me a few tries to land on a workable and correct solution.</p>\n<p>Here's the <code>pg_clickhouse.session_settings</code> setup:</p>\n<div><pre><code><span>DefineCustomStringVariable(</span>\n<span>    <span>\"pg_clickhouse.session_settings\"</span>,</span>\n<span>    <span>\"Sets the default ClickHouse session settings.\"</span>,</span>\n<span>    <span>NULL</span>,</span>\n<span>    &amp;ch_session_settings,</span>\n<span>    <span>\"join_use_nulls 1, group_by_use_nulls 1, final 1\"</span>,</span>\n<span>    PGC_USERSET,</span>\n<span>    <span>0</span>,</span>\n<span>    chfdw_check_settings_guc,</span>\n<span>    chfdw_settings_assign_hook,</span>\n<span>    <span>NULL</span></span>\n<span>);</span></code></pre></div>\n<p>So many arguments! Here's the <a target=\"_blank\" href=\"https://github.com/postgres/postgres/blob/bfe5c4b/src/include/utils/guc.h#L393-L402\">public declaration</a>:</p>\n<div><pre><code><span><span>extern</span> <span>void</span> <span>DefineCustomStringVariable</span><span>(</span></span>\n<span><span>    <span>const</span> <span>char</span> *name,</span></span>\n<span><span>    <span>const</span> <span>char</span> *short_desc,</span></span>\n<span><span>    <span>const</span> <span>char</span> *long_desc,</span></span>\n<span><span>    <span>char</span> **valueAddr,</span></span>\n<span><span>    <span>const</span> <span>char</span> *bootValue,</span></span>\n<span><span>    GucContext context,</span></span>\n<span><span>    <span>int</span> flags,</span></span>\n<span><span>    GucStringCheckHook check_hook,</span></span>\n<span><span>    GucStringAssignHook assign_hook,</span></span>\n<span><span>    GucShowHook show_hook</span></span>\n<span><span>)</span> <span>pg_attribute_nonnull</span><span>(<span>1</span>, <span>4</span>)</span>;</span></code></pre></div>\n<p>Quick explanations:</p>\n<ul>\n<li>\n<p><strong><code>name</code>:</strong> The name of the GUC, a used by <code>SET</code>. Extension GUCs should\nstart with a prefix and a dot; hence <code>pg_clickhouse.session_settings</code></p>\n</li>\n<li>\n<p><strong><code>short_desc</code>:</strong> A short description of the GUC.</p>\n</li>\n<li>\n<p><strong><code>long_desc</code>:</strong> A long description of the GUC.</p>\n</li>\n<li>\n<p><strong><code>valueAddr</code>:</strong> A pointer to the variable in which the GUC API stores\nthe value. The pg_clickhouse GUC uses a global <code>char *</code> variable.</p>\n</li>\n<li>\n<p><strong><code>bootValue</code>:</strong> The default value for the GUC when the extension loads.</p>\n</li>\n<li>\n<p><strong><code>context</code>:</strong> Determines who can set the GUC and when. We want to allow\nany users to set <code>pg_clickhouse.session_settings</code>, but there are a number\nof <a target=\"_blank\" href=\"https://github.com/postgres/postgres/blob/bfe5c4bec75091d5c91813ff9c6994a169ceb8ef/src/include/utils/guc.h#L39-L80\">other options</a>.</p>\n</li>\n<li>\n<p><strong><code>flags</code>:</strong> A bitmask of <a target=\"_blank\" href=\"https://github.com/postgres/postgres/blob/bfe5c4bec75091d5c91813ff9c6994a169ceb8ef/src/include/utils/guc.h#L210-L257\">GUC flags</a> that modify behavior, determine\nformatting and parsing.</p>\n</li>\n<li>\n<p><strong><code>check_hook</code>:</strong> A callback function that validates a value and\noptionally sets <code>extra</code> data to be passed to the assign hook. Our code\npoints to <code>chfdw_check_settings_guc</code>, which raises an error if a new value\nfails to parse as a valid key/value list.</p>\n</li>\n<li>\n<p><strong><code>assign_hook</code>:</strong> A callback function that assigns a GUC value to a\nvariable other than <code>valueAddr</code>. May use <code>extra</code> data set by the check\nhook.</p>\n</li>\n<li>\n<p><strong><code>show_hook</code>:</strong> A callback that reformats a GUC for display. Used by\nsome GUCs to normalize or canonicalize values, such as time zones.</p>\n</li>\n</ul>\n<p>The <code>check_hook</code> and <code>assign_hook</code> parameters allow the extra data parsing we\nneed. The idea is that the check hook can point <code>extra</code> at a data structure\nand that value is passed to the assign hook, which assigns it to a variable.</p>\n<h2 id=\"first-attempt\"></h2>\n<p>For my first attempt, I created a pointer to a list of key/value pairs,\nassuming that I could point <code>extra</code> at it in the check hook and then assign it\nin the assign hook. Something like:</p>\n<div><pre><code><span><span>static</span> <span>bool</span></span>\n<span><span>chfdw_check_settings_guc</span><span>(<span>char</span> **newval, <span>void</span> **extra, GucSource source)</span></span>\n<span>{</span>\n<span>    <span>if</span> (*newval == <span>NULL</span> || *newval[<span>0</span>] == <span>'\\0'</span>)</span>\n<span>        <span>return</span> <span>true</span>;</span>\n<span></span>\n<span>    kv_list * settings = parse_and_malloc_kv_list(*newval);</span>\n<span>    <span>if</span> (!settings)</span>\n<span>        <span>return</span> <span>false</span>;</span>\n<span></span>\n<span>    *extra = settings;</span>\n<span>    <span>return</span> <span>true</span>;</span>\n<span>}</span></code></pre></div>\n<p>Note that <code>parse_and_malloc_kv_list()</code> uses <code>malloc()</code> to allocate memory for\nthe list, each item in the list, and each key and value. It uses <code>malloc()</code>\nbecause we're going to store the value in a global, so it must not be cleaned\nup by the GUC memory context.</p>\n<p>Then, in the assign hook:</p>\n<div><pre><code><span><span>static</span> <span>void</span></span>\n<span><span>chfdw_settings_assign_hook</span><span>(<span>const</span> <span>char</span> *newval, <span>void</span> *extra)</span></span>\n<span>{</span>\n<span>    <span>if</span> (ch_session_settings_list)</span>\n<span>        kv_list_free(ch_session_settings_list);</span>\n<span>    ch_session_settings_list = (kv_list *) extra;</span>\n<span>}</span></code></pre></div>\n<p>Free the existing settings list, if it's set, then assign the new list from\n<code>extra</code>.</p>\n<p>Seems pretty simple, right? Alas, I could never get the assignment to work; I\nneed to better understand memory allocation, pointers, pointers to pointers,\netc.</p>\n<h2 id=\"second-attempt\"></h2>\n<p>So I tried just doing the assignment in the check hook and doing away with the\nassign hook. Something like:</p>\n<div><pre><code><span><span>static</span> <span>bool</span></span>\n<span><span>chfdw_check_settings_guc</span><span>(<span>char</span> **newval, <span>void</span> **extra, GucSource source)</span></span>\n<span>{</span>\n<span>    <span>if</span> (*newval == <span>NULL</span> || *newval[<span>0</span>] == <span>'\\0'</span>)</span>\n<span>        <span>return</span> <span>true</span>;</span>\n<span></span>\n<span>    kv_list * pairs = parse_and_malloc_kv_list(*newval);</span>\n<span>    <span>if</span> (!pairs)</span>\n<span>        <span>return</span> <span>false</span>;</span>\n<span></span>\n<span>   <span>if</span> (ch_session_settings_list)</span>\n<span>        kv_list_free(ch_session_settings_list);</span>\n<span>    ch_session_settings_list = pairs;</span>\n<span></span>\n<span>    <span>return</span> <span>true</span>;</span>\n<span>}</span></code></pre></div>\n<p>I asked about this approach on the Postgres Discord, where Tom Lane kindly\nresponded with:</p>\n<blockquote>\n<p>You absolutely must not change any session state in a check hook.  That's\ncalled when we're merely speculating about whether (eg) a proposed ALTER\nDATABASE SET command is okay; there is no guarantee that we are about to\napply the setting.</p>\n</blockquote>\n<p>I also noticed that <code>RESET</code> wouldn't work, as the check hook isn't called for\na reset. So much for that idea!</p>\n<h2 id=\"third-attempt\"></h2>\n<p>Next I switched to a double parse in order to avoid these issues. The check\nhook simplified to:</p>\n<div><pre><code><span><span>static</span> <span>bool</span></span>\n<span><span>chfdw_check_settings_guc</span><span>(<span>char</span> **newval, <span>void</span> **extra, GucSource source)</span></span>\n<span>{</span>\n<span>    <span>if</span> (*newval == <span>NULL</span> || *newval[<span>0</span>] == <span>'\\0'</span>)</span>\n<span>        <span>return</span> <span>true</span>;</span>\n<span></span>\n<span>    kv_list * settings = parse_and_malloc_kv_list(*newval);</span>\n<span>    <span>if</span> (!settings)</span>\n<span>        <span>return</span> <span>false</span></span>\n<span>    kv_list_free(ch_session_settings_list);</span>\n<span></span>\n<span>    <span>/* No errors, return true. */</span></span>\n<span>    <span>return</span> <span>true</span>;</span>\n<span>}</span></code></pre></div>\n<p>And the assign hook became:</p>\n<div><pre><code><span><span>static</span> <span>void</span></span>\n<span><span>chfdw_settings_assign_hook</span><span>(<span>const</span> <span>char</span> *newval, <span>void</span> *extra)</span></span>\n<span>{</span>\n<span>    <span>if</span> (ch_session_settings_list)</span>\n<span>        kv_list_free(ch_session_settings_list);</span>\n<span>    PG_TRY();</span>\n<span>    {</span>\n<span>        ch_session_settings_list = parse_and_malloc_kv_list(newval);</span>\n<span>    }</span>\n<span>    PG_CATCH();</span>\n<span>    {</span>\n<span>        ereport(LOG,</span>\n<span>                (errcode(ERRCODE_FDW_ERROR),</span>\n<span>                 errmsg(<span>\"unexpected error parsing \\\"%s\\\"\"</span>, newval)));</span>\n<span>    }</span>\n<span>    PG_END_TRY();</span>\n<span>}</span></code></pre></div>\n<p>Now both hooks execute <code>parse_and_malloc_kv_list()</code>. This double parsing\nseemed acceptable, given that it replaces parsing the settings for every\nquery. This solution became <a target=\"_blank\" title=\"ClickHouse/pg_clickhouse#95 Add kv_list and refactor session_settings with it\" href=\"https://github.com/ClickHouse/pg_clickhouse/issues/95\">pg_clickhouse#95</a>. I was, however, dissuaded from\napplying it because its memory management is more complicated than the\neventual solution, and also by this offhand Discord comment, again from Tom\nLane:</p>\n<blockquote>\n<p>I do not recommend doing new allocations inside the assign hook.  It is\nexpected to be incapable of failing.</p>\n</blockquote>\n<p>Which makes me think that the risk of actually raising an error that escapes\n<code>PG_TRY()</code>, while low, renders this approach suboptimal, to say the least.</p>\n<p>Back in my <a target=\"_blank\" href=\"https://clickhouse.com/blog/taming-postgres-guc-extra-data#first-attempt\">first attempt</a>, <code>parse_and_malloc_kv_list()</code> would\n<code>malloc()</code> memory for each bit of the structure it built: the <code>kv_list</code>, a\npointer to a list of key/value pairs, each of those pairs, plus the key and\nvalue strings themselves. The pattern still holds in <a target=\"_blank\" title=\"ClickHouse/pg_clickhouse#95 Add kv_list and refactor session_settings with it\" href=\"https://github.com/ClickHouse/pg_clickhouse/issues/95\">pg_clickhouse#95</a>'s\n<a target=\"_blank\" href=\"https://github.com/ClickHouse/pg_clickhouse/pull/95/files#diff-e6e6afea9fa95db0fb2d8a3afe3b757c1a5c66e54c071f0bf315ad862473a512R20-R70\"><code>kv_list.c</code></a>. But it made use of <code>extra</code> impossible --- or at least it\nsurpassed my C expertise. Tom educated me about how to properly use <code>extra</code>:</p>\n<blockquote>\n<p>You're supposed to use guc_malloc, and the extra data has to be a single\nmalloc block, not a list. <br><br>\nThe general principle with GUC extra data is that once your check_hook hands\nit back, it's guc.c's responsibility to free it when no longer needed. The\nsingle-chunk restriction is because guc.c wouldn't know about other\ncomponents of the data structure.</p>\n</blockquote>\n<p>This approach allows correct use of the <code>extra</code> data, does no other assignment\nin the check hook, and does nothing but assign in the assign hook, eliminating\nthe error risk. All I had to do was figure out how to do a single\n<code>guc_malloc()</code> with a list of key/value pairs.</p>\n<h2 id=\"fourth-attempt\"></h2>\n<p>The solution submitted in <a target=\"_blank\" title=\"ClickHouse/pg_clickhouse#94 Add kv_list and refactor session_settings with it\" href=\"https://github.com/ClickHouse/pg_clickhouse/issues/94\">pg_clickhouse#94</a> follows the example of\n<code>ConvertTimeZoneAbbrevs()</code> in PostgreSQL's <a target=\"_blank\" href=\"https://github.com/postgres/postgres/blob/84d5efa7e3ebcf04694d312b0f14ceb35dcdfb8e/src/backend/utils/adt/datetime.c#L4986-L5071\">datetime.c</a> to calculate the total\nmemory required for all the key/value pairs and allocate that memory as a\nsingle block. The struct's definition:</p>\n<div><pre><code><span><span>typedef</span> <span><span>struct</span> <span>kv_list</span></span></span>\n<span><span>{</span></span>\n<span>    <span>int</span>            length;</span>\n<span>    <span>char</span> data[];</span>\n<span>}            kv_list;</span></code></pre></div>\n<p>Note the use of a <a target=\"_blank\" title=\"Wikipedia: Flexible array member\" href=\"https://en.wikipedia.org/wiki/Flexible_array_member\">flexible array</a>, <code>data[]</code>. It serves as a pointer to the\nkeys and values, which the constructor simply writes from its address as a\nlist of null-terminated strings. It is not actually a C structure at all. Once the constructor sums up the memory required for\nall the keys and values like so:</p>\n<div><pre><code><span>kv_list * <span>list</span> = guc_malloc(ERROR, offsetof(kv_list, data) + summed_size);</span></code></pre></div>\n<p>It requires the size of the <code>kv_list</code> struct up to the <code>data</code> field, and adds\nthe total it summed for the key and value strings. <span>printf</span>(<span>\"%s =&gt; %s\\n\"</span>, iter.name, iter.value);</span>\n<span>}</span></code></pre></div>\n<p>This keeps things simple for the places in the code that need to process the\nsetting, namely setting them up for <a target=\"_blank\" href=\"https://github.com/ClickHouse/pg_clickhouse/blob/1ac05a319d94b41140ce7ce113646d308bdba997/src/binary.cpp#L179-L182\">binary</a> and <span>if</span> (*newval == <span>NULL</span> || *newval[<span>0</span>] == <span>'\\0'</span>)</span>\n<span>        <span>return</span> <span>true</span>;</span>\n<span></span>\n<span>    kv_list *
