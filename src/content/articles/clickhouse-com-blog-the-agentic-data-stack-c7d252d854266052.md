contentHtml: "<article><div><p>The <a target=\"_blank\" href=\"https://github.com/ClickHouse/agentic-data-stack\"><strong>Agentic Data Stack</strong></a> is an open-source, composable architecture for <a target=\"_blank\" href=\"https://clickhouse.com/blog/agent-facing-analytics\">agentic analytics</a>: connect AI agents directly to your data, wherever you store it.</p>\n<p>You can run the stack on your laptop with Docker and begin querying your data in less than a minute:</p>\n<div><pre><code><span>git <span>clone</span> https://github.com/ClickHouse/agentic-data-stack &amp;&amp; <span>cd</span> agentic-data-stack &amp;&amp; ./scripts/prepare-demo.sh &amp;&amp; docker compose up -d</span></code></pre></div>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/the-agentic-data-stack#getting-started\">Find more detail in the getting started section below.</a></p>\n<h2 id=\"why-the-agentic-data-stack\"></h2>\n<p>The traditional analytics workflow in the Enterprise requires multiple steps and handovers. A business user asks a question, a ticket gets raised, an analyst produces a dashboard, and the question gets answered a week later. AI allows the user to skip the process and answer their questions immediately.</p>\n<p>That's the promise of the <strong>Agentic Data Stack</strong> - an open-source, composable architecture that connects AI agents directly to your data. No dashboards. No ticket queues. No waiting around. Just a conversation with your data, grounded in real-time facts, with full observability into every interaction.</p>\n<p>A key design principle of the Open Source Agentic Data Stack is data sovereignty. You own everything:</p>\n<ul>\n<li><strong>Your data stays local</strong>: ClickHouse runs on your infrastructure, not a third-party service</li>\n<li><strong>Your conversations are private</strong>: LibreChat stores everything in your MongoDB instance</li>\n<li><strong>Your traces are yours</strong>: Langfuse writes to your ClickHouse instance, not an external SaaS</li>\n<li><strong>Your model choice</strong>: Frontier models are available from a wide variety of supported providers, gateways, and custom endpoints, as well as locally hosted models via tools like <a target=\"_blank\" href=\"https://www.librechat.ai/blog/2024-03-02_ollama\">Ollama</a> or <a target=\"_blank\" href=\"https://www.librechat.ai/docs/configuration/librechat_yaml/ai_endpoints/vllm\">vLLM</a></li>\n<li><strong>Your MCP servers:</strong> Connect to any MCP server you’d like, not just ClickHouse. LibreChat supports adding custom MCP servers via the <code>librechat.yaml</code> and on-the-fly from within the user interface</li>\n</ul>\n<h2 id=\"the-agentic-data-stack-architecture\"></h2>\n<p>The <a target=\"_blank\" href=\"https://clickhouse.ai/\">Agentic Data Stack</a> is an open-source reference architecture built on three pillars:</p>\n<div><table><thead><tr><th>Layer</th><th>Component</th><th>Role</th></tr></thead><tbody><tr><td><strong>Chat</strong></td><td><a target=\"_blank\" href=\"https://librechat.ai/\">LibreChat</a></td><td>A modern, provider-agnostic agentic chat interface</td></tr><tr><td><strong>Data</strong></td><td><a target=\"_blank\" href=\"https://clickhouse.com/\">ClickHouse</a> + <a target=\"_blank\" href=\"https://github.com/ClickHouse/mcp-clickhouse\">MCP</a></td><td>The world's fastest analytical database, exposed to agents via our open-source clickhouse-mcp server</td></tr><tr><td><strong>Observability</strong></td><td><a target=\"_blank\" href=\"https://langfuse.com/\">Langfuse</a></td><td>Full LLM tracing, evaluation, and prompt management to ensure your agents are effective in their roles and can be quantifiably improved over time</td></tr></tbody></table></div>\n<p>Each layer is best-in-class, fully open-source, and independently useful. Together, they form something greater than the sum of its parts: an end-to-end platform where AI agents can query billions of rows in just a couple of moments, automatically generate and tailor interactive visualizations to your specifications, provide useful, shareable insights into your data, and be continuously monitored for output quality - all without users having to write a single line of SQL.</p>\n<p><span><img alt=\"01-architecture.webp\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F01_architecture_2e43ef2a62.webp&w=2048&q=75\"></span></p>\n<h3 id=\"librechat\"></h3>\n<p>LibreChat is the front door. It provides a familiar, ChatGPT-style UI that supports multiple LLM providers simultaneously. Users can switch between providers and models mid-conversation, create specialized agents for different datasets or use cases, utilize modern agentic tools like web search and multimodal upload, tweak provider-specific model parameters for things like verbosity and effort, and share conversations and artifacts across their team.</p>\n<p>But LibreChat isn't just a chat window. It supports:</p>\n<ul>\n<li><strong>MCP server connections</strong>: agents can discover and use tools at runtime</li>\n<li><strong>Artifacts</strong>: charts, tables, and visualizations generated inline</li>\n<li><strong>RAG</strong>: retrieval-augmented generation backed by pgvector for document-grounded answers</li>\n<li><strong>Agent capabilities</strong>: code execution, web search, file search, OCR, and chaining</li>\n</ul>\n<p>In this stack, LibreChat is pre-configured to connect to the ClickHouse MCP server, so the moment you open a conversation, your agent already has access to your data.</p>\n<h3 id=\"clickhouse-mcp\"></h3>\n<p>The <a target=\"_blank\" href=\"https://github.com/ClickHouse/mcp-clickhouse\">ClickHouse MCP server</a> is the critical middleware that makes agentic analytics possible. In this setup, it implements the Model Context Protocol over HTTP, exposing ClickHouse's capabilities as tools that any LLM can invoke.<br>\nWhen an agent needs to answer a data question, the flow looks like this:</p>\n<ol>\n<li><strong>The User asks a question</strong> in LibreChat: <em>\"What were our top 10 customers by revenue last quarter?\"</em></li>\n<li><strong>The LLM reasons</strong> about the question and decides it needs to query the database</li>\n<li><strong>The LLM calls the MCP server’s <code>run_select_query</code> tool</strong>, which translates the request into a ClickHouse SQL query</li>\n<li><strong>ClickHouse executes the query</strong> at sub-second speed across billions of rows</li>\n<li><strong>The results flow back</strong> through MCP to the LLM, which formats them into a human-readable answer - optionally with a beautifully rendered chart or table if Artifacts are enabled for the conversation</li>\n</ol>\n<p><span><img alt=\"2.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F2_248aeed423.png&w=2048&q=75\"></span></p>\n<p>The MCP server runs as a lightweight HTTP service, authenticated via bearer token, and connects to ClickHouse over its native HTTP interface. In the Docker Compose setup, it's wired to the same ClickHouse instance that Langfuse uses by default, but you can point it at any ClickHouse deployment, including ClickHouse Cloud, either via the <code>librechat.yaml</code> configuration file or through the MCP Settings UI.</p>\n<h3 id=\"langfuse\"></h3>\n<p>Every LLM call LibreChat makes is traced in Langfuse. This gives you:</p>\n<ul>\n<li><strong>Full trace visualization</strong>: see the entire chain of prompts, tool calls, and responses for any conversation</li>\n<li><strong>Cost and latency monitoring</strong>: track spend across providers and models</li>\n<li><strong>Quality evaluation</strong>: score outputs with custom metrics, detect hallucinations, and run automated evals</li>\n<li><strong>Prompt management</strong>: version and test prompts before deploying them to production</li>\n</ul>\n<p><span><img alt=\"3.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F3_ced87ed6ae.png&w=2048&q=75\"></span>\n<span><img alt=\"4.png\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2F4_8d396949a5.png&w=2048&q=75\"></span></p>\n<p>Langfuse is pre-configured in this stack with auto-provisioned project keys, so tracing starts working the moment you boot up. Open Langfuse at localhost:3000 and you'll see every interaction flowing through in real time.</p>\n<h2 id=\"why-now\"></h2>\n<h3 id=\"1-llms-got-good-enough-to-write-sql\"></h3>\n<p>Modern foundation models can reliably translate natural language into complex analytical queries. They understand joins, window functions, CTEs, and time-series aggregations. When grounded with schema metadata, table comments, and a strong system prompt, they are able to reach an output quality that far exceeds that of the average non-technical business user.</p>\n<h3 id=\"2-the-proliferation-of-the-model-context-protocol\"></h3>\n<p>The <a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/AI/MCP\">Model Context Protocol</a> (MCP) gives LLMs a standardized way to interact with external systems. Instead of building custom integrations for every database, API, and tool, MCP provides a single interface in a format designed for agentic interaction. The ClickHouse MCP server lets any MCP-compatible client like LibreChat, Claude Desktop, Cursor, or your own application query ClickHouse through tool calls derived from natural language.</p>\n<p>This is a fundamental shift. MCP turns your database from a passive data store into an <a target=\"_blank\" href=\"https://clickhouse.com/blog/agent-facing-analytics\"><strong>agent-facing</strong> resource</a>: something AI agents can discover, explore, and query autonomously.</p>\n<h3 id=\"3-the-maturation-of-llm-observability-tooling\"></h3>\n<p>LLM-powered applications are non-deterministic. The same prompt can produce different responses. In production, anecdotal reports from your users as to the agent or model’s efficacy aren’t nearly robust enough data to make real business decisions. You need to trace every prompt, tool call, and response. You need to score outputs for quality, monitor costs and latency, and detect regressions before users do. ClickHouse's <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-acquires-langfuse-open-source-llm-observability\">acquisition of Langfuse</a> (January 2026) brought the leading open-source LLM observability platform into the stack. Langfuse itself runs on ClickHouse under the hood, handling the high-volume writes and fast analytical queries that AI observability demands.</p>\n<h2 id=\"who-s-using-it\"></h2>\n<p>Organizations are already using the Agentic Data Stack to transform how they work with data:</p>\n<p><strong>Shopify</strong> runs LibreChat internally with <a target=\"_blank\" href=\"https://clickhouse.com/blog/librechat-open-source-agentic-data-stack#shopify\">near-universal adoption and thousands of custom agents connected to 30+ internal MCP servers</a>. As CEO Tobi Lutke <a target=\"_blank\" href=\"https://twitter.com/tobi/status/1932846291794510241\">noted publicly</a>: <em>\"Shopify runs an internal fork of LibreChat, and we merge most everything back. Navigate to <a target=\"_blank\" href=\"http://localhost:3080/\">http://localhost:3080</a> for LibreChat, <a target=\"_blank\" href=\"http://localhost:3000/\">http://localhost:3000</a> for Langfuse, and start asking your data questions.</p>\n<p>The <a target=\"_blank\" href=\"https://github.com/ClickHouse/agentic-data-stack/blob/main/scripts/prepare-demo.sh\">prepare-demo.sh</a> script handles the tedious parts: ingesting LLM-provider API keys, generating random passwords, JWT secrets, encryption keys, MCP auth tokens, and wiring all the services together.
