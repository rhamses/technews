contentHtml: "<article><div><p>Around any good database sits the clients you import, the dashboards your team shares, the pipelines that feed it, the projects that build on top of it, and now the agents that query it. ClickHouse would not have <a target=\"_blank\" href=\"https://clickhouse.com/blog/what-a-difference-10-years-of-open-source-makes\">2,600+ contributors, 240k+ commits, and hundreds of millions of downloads</a> without the ecosystem that has flourished around it.</p>\n<h2 id=\"building-on-open-standards\"></h2>\n<p>ClickHouse is open source and built by a community of users. That shapes what the project reaches for when it connects to the rest of the world. ClickHouse gravitates to open standards that are themselves driven by their own communities, and over the years, it has adopted them across use cases: OpenTelemetry in observability, the Model Context Protocol in AI, Iceberg and Delta in the lakehouse. Much like ClickHouse is itself open, it integrates with an open ecosystem, where your data and your tooling stay yours, and you keep complete freedom over how you wire them together.</p>\n<h3 id=\"observability\"></h3>\n<p>OpenTelemetry is the open standard for instrumenting software, with one set of SDKs and one wire protocol for metrics, logs, and traces. You instrument once, and your telemetry can go anywhere, which means your instrumentation belongs to you.</p>\n<p>With ClickHouse rapidly becoming the database of choice for observability, it needed first-class support for OTel. The ClickHouse exporter lives upstream in the OpenTelemetry Collector's contrib repository, and OpenTelemetry is the spine of <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickstack-a-high-performance-oss-observability-stack-on-clickhouse\">ClickStack</a>, the open-source observability stack for ClickHouse.</p>\n<p>ClickHouse is learning to speak Prometheus, too, with <a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-1#promql-support\">PromQL support available experimentally</a>, so existing Prometheus queries and muscle memory carry over.</p>\n<h3 id=\"ai\"></h3>\n<p>When agents arrived, they needed a standard way to reach tools and data, and the Model Context Protocol became it: an open protocol any model or framework can implement. The <a target=\"_blank\" href=\"https://github.com/ClickHouse/mcp-clickhouse\">ClickHouse MCP server</a> is open source, and because MCP is an open protocol, it slots into whatever agent framework you already run. It's been shown <a target=\"_blank\" href=\"https://clickhouse.com/blog/integrating-clickhouse-mcp\">working with Agno, DSPy, LangChain, LlamaIndex, and PydanticAI</a>, and the list keeps growing. Any agent that speaks MCP can explore your tables, write queries, and read back results without anyone building a bespoke integration first.</p>\n<h3 id=\"open-table-formats-and-catalogs\"></h3>\n<p>Open table formats like Iceberg and Delta Lake let a dataset live in object storage, not tied to a single engine.</p>\n<p>ClickHouse <a target=\"_blank\" href=\"https://clickhouse.com/blog/climbing-the-iceberg-with-clickhouse\">reads Iceberg v2 in full</a>, including schema evolution, time travel, with Iceberg writes landing in 25.8. Delta Lake support is <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-is-data-lake-ready\">built on Delta Kernel</a>, and Apache Paimon arrived in <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-2025-roundup\">25.10</a>.</p>\n<p>A table format needs a catalog to track which files make up a table and hand that metadata to whatever engine asks. Here, too, ClickHouse leans on the open ones: it speaks the <a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/data-lake/rest-catalog\">Iceberg REST catalog</a> spec, <a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/data-lake/polaris-catalog\">Apache Polaris</a>, and <a target=\"_blank\" href=\"https://clickhouse.com/docs/use-cases/data-lake/unity-catalog\">Unity Catalog</a>, each an open project with its own community. Because the catalog API is a standard rather than a product, you pick whichever one fits your stack, and swap later, without re-platforming your data.</p>\n<h2 id=\"an-open-unified-data-stack\"></h2>\n<p>Postgres is another great open-source database. It has a different job, but the same spirit. It sets the standard for transactional, OLTP workloads, and it does it in the open, guided by a community. ClickHouse does the same for analytics. Put them side by side, and you can't find a more obvious <a target=\"_blank\" href=\"https://clickhouse.com/blog/postgres-managed-by-clickhouse-beta\">pair</a>. GitLab <a target=\"_blank\" href=\"https://about.gitlab.com/blog/two-sizes-fit-most-postgresql-and-clickhouse/\">wrote about this setup</a> a couple of years ago, and it has become common enough that the combination is turning into a standard in its own right.</p>\n<p>There are now several open-source tools that bring the two databases closer together:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://clickhouse.com/blog/postgres-cdc-year-in-review-2025\">PeerDB</a> is the open-source Postgres CDC project that became the engine for moving transactional data into analytical tables.</li>\n<li><a target=\"_blank\" href=\"https://clickhouse.com/blog/introducing-pg_clickhouse\">pg_clickhouse</a> is an open-source Postgres extension that makes ClickHouse tables queryable from standard Postgres, with filters, projections, and aggregations pushed down transparently. If a tool speaks Postgres, it now speaks ClickHouse.</li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/pg_stat_ch\">pg_stat_ch</a> is an open-source Postgres extension that turns every query execution into a compact event and streams it into ClickHouse, where you can slice query latency, errors, and behavior over months of history like an APM.</li>\n</ul>\n<h2 id=\"built-on-clickhouse\"></h2>\n<p>Some of the most interesting things in the ecosystem aren't just integrations. They're whole projects that chose ClickHouse as their engine and grew from there. A few have since become first-party, open-source projects alongside ClickHouse. Together, they mean ClickHouse can be more than a database: a full observability stack, or an LLM engineering platform, all without leaving open source.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/clickstack-a-high-performance-oss-observability-stack-on-clickhouse\">ClickStack</a> is a full open-source observability stack, ClickHouse for storage, the OpenTelemetry Collector for ingestion, and the HyperDX UI on top, launched in May 2025. A <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickstack-a-year-in-review-2025\">year in</a>, it's become one of the most active corners of the community.</p>\n<p><a target=\"_blank\" href=\"https://github.com/chdb-io/chdb\">chDB</a> started as a community project, embedding ClickHouse in-process for Python, before <a target=\"_blank\" href=\"https://clickhouse.com/blog/chdb-joins-clickhouse-family\">joining the family in 2024</a>. It's still Apache 2.0 and, as of June 2026, sits at around 24 million PyPI downloads, running about 2.3 million a month. <a target=\"_blank\" href=\"https://clickhouse.com/blog/chdb.4-0-pandas-hex\">chDB v4</a>, released in March 2026, added the DataStore API, which lets you write pandas-compatible code that lazily compiles to optimized SQL on the ClickHouse engine, falling back to real pandas automatically for operations ClickHouse can't do. <a target=\"_blank\" href=\"https://hex.tech/blog/announcing-clickhouse-partnership/\">Hex announced a partnership</a> that preinstalls chDB on every Hex notebook, with a one-click ClickHouse connection.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-1\">Langfuse</a> is the open-source LLM observability and engineering platform, tracing, evals, and prompt management for teams building on top of models. Its team joined ClickHouse in January 2026, with Langfuse remaining open source, OpenTelemetry-native, and self-hostable.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-2\">LibreChat</a> is the open-source agent and chat platform. It joined ClickHouse in October 2025 and continues as an active OSS project, shipping new releases every few weeks.</p>\n<h2 id=\"build-with-clickhouse\"></h2>\n<p>Every official client is open source, and between them they cover the languages you're most likely to be writing:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-go\">Go</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-java\">Java</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-js\">JavaScript and Node.js</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-connect\">Python</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cpp\">C++</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-cs\">.NET</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-rs\">Rust</a></li>\n</ul>\n<p>The official Rust client, <a target=\"_blank\" href=\"https://github.com/ClickHouse/clickhouse-rs\">clickhouse-rs</a>, didn't start official at all. Paul Loyd built and maintained it as a community project for years before it became the official client. Someone built the thing because they needed it, the community gathered around it, and eventually it became part of the family.</p>\n<p>The clients have had a busy year, and a lot of it shipped at <a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-2\">Open House</a>. The Python client, clickhouse-connect, hit v1.0 GA with native async and full sync parity, 4x faster cold starts, and first-class numpy, pandas, pyarrow, and polars support, plus a SQLAlchemy dialect with Alembic migrations. The .NET client reached v1.2.0 with Entity Framework Core, a Serilog sink, and Aspire and Semantic Kernel packages on NuGet. There's a Laravel driver with Eloquent models and artisan migrations for the PHP side of the house.</p>\n<p>And it's not just the clients. For teams running ClickHouse on Kubernetes, there's now an <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-kubernetes-operator\">official Apache 2.0 open-source Kubernetes operator</a>, shipped in January 2026. It automates the fiddly parts of running production clusters, sharding, replication, scaling, and safe rolling version upgrades, all driven through Kubernetes custom resources.</p>\n<h2 id=\"partners-and-integrations\"></h2>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-2#apache-airflow-native-provider\">Apache Airflow</a> is the open-source standard for orchestrating data pipelines, the scheduler running the jobs that feed analytical tables, so a first-class ClickHouse provider reaches a lot of teams. ClickHouse is now getting an official hook and operator in <a target=\"_blank\" href=\"https://github.com/apache/airflow/pull/67080\">upstream Airflow</a>; going upstream, rather than living in a side plugin, means anyone who installs Airflow gets ClickHouse support in the box. But that official provider didn't appear out of nowhere. For years, community members Ivan Klimenko and Anton Bryzgalov built and maintained their own ClickHouse providers for Airflow racking up hundreds of thousands of downloads and keeping teams unblocked long before anything official existed.</p>\n<p><a target=\"_blank\" href=\"https://www.getdbt.com/\">dbt</a> is the open-source tool analytics engineers use to transform data in the warehouse by writing plain SQL select statements, and the ClickHouse adapter itself <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-dbt-project-introduction-and-webinar\">started as a gift from the community</a>. ClickHouse is now the first partner co-developing a <a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-2#dbt-clickhouse-fusion-adapter\">dbt Fusion engine adapter</a>, now in alpha.</p>\n<blockquote>\n<p>\"ClickHouse has become one of the fastest-growing databases in the dbt community\" - Hope Watson, dbt Labs.</p>\n</blockquote>\n<p><a target=\"_blank\" href=\"https://grafana.com/\">Grafana</a> is the open-source dashboarding tool that a huge share of engineering teams already keep open on a second monitor, which makes its plugin one of the most common ways people see ClickHouse data. It's also one of the longest-running integrations anywhere, and the teams have published <a target=\"_blank\" href=\"https://clickhouse.com/blog/grafana-plugin-vision\">a shared vision for where it goes next</a>.</p>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-2#fivetran-generally-available\">Fivetran's ClickHouse Cloud destination went GA</a>, opening up more than 500 sources. <a target=\"_blank\" href=\"https://clickhouse.com/blog/open-house-2026-day-2#sigma-computing-connector-in-public-beta\">Sigma Computing's connector entered public beta</a>, Notion built a native ClickHouse MCP connector, and Google Cloud shipped a GA Dataflow template for Pub/Sub. Artie, Dreambase, Tavily, and Hightouch all shipped integrations of their own.</p>\n<h2 id=\"here-s-to-the-next-10-years\"></h2>\n<p>This open ecosystem has been building and flourishing for 10 years.</p>\n<p>ClickHouse is now becoming a default for AI-native companies, foundation labs, and the agents they build. You can see it threaded through this post: the MCP servers, agents querying ClickStack, chDB handing agents a pandas interface, and the <a target=\"_blank\" href=\"https://clickhouse.com/blog/introducing-clickhouse-agent-skills\">ClickHouse Agent Skills</a>. Given how fast that space is moving, this is surely only scratching the surface of what integrating with it will look like.</p>\n<p>That's the thing about an open ecosystem: nobody gets to script it. The ClickHouse story has always been written by the people using it. 200+ integrations and hundreds of millions of downloads, built by maintainers, by partners, and by a community that just keeps shipping. If you've built something that talks to ClickHouse, you're part of this story.</p>\n<p>We don't know what the next ten years of the ClickHouse ecosystem will look like. We can't wait to find out.</p></div></article>"
