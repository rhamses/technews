At SF10, it runs all 22 queries for less than one cent.</p>\n</blockquote>\n<br>\n<h2 id=\"clickhouse-cloud-joins-the-tpc-h-comparison\"></h2>\n<p>We ran the full <a target=\"_blank\" href=\"https://clickhouse.com/docs/getting-started/example-datasets/tpch\">TPC-H</a> workload on ClickHouse Cloud, Snowflake, Databricks, BigQuery, and Redshift.</p>\n<p>At SF100, that is 100 GB of data, 866M rows, and 22 join-heavy analytical queries.</p>\n<p>The result: ClickHouse Cloud was competitive on raw runtime and ranked first on cost-performance.</p>\n<p>At SF10, the full workload ran in 2.9 seconds for $0.009 in compute cost.</p>\n<p>Less than one cent.</p>\n<p>This post shows the benchmark results. The <a target=\"_blank\" href=\"https://clickhouse.com/blog/clickhouse-fast-joins\">companion post</a> explains the two years of join engineering behind them.</p>\n<h2 id=\"benchmark-setup\"></h2>\n<p>All benchmark scripts, queries, and result files are available in a public GitHub <a target=\"_blank\" href=\"https://github.com/ClickHouse/tpc-h-openhouse\">repository</a>, so the results can be reproduced and inspected.</p>\n<h3 id=\"dataset-and-runtime-measurement\"></h3>\n<p>The main comparison uses TPC-H SF100: 22 queries over 866M rows.</p>\n<p>For runtime measurements, we distinguish between cold and hot runs:</p>\n<p><strong>Cold runs</strong>: We did not systematically compare cold-start performance. Cloud warehouses exhibit different caching behavior, and most do not let users reliably reset OS-level page cache or restart compute on demand. Because cold conditions cannot be standardized, cold results would not be fair or reproducible.</p>\n<p><strong>Hot runs</strong>: Each query was run three times with result caching disabled. Charts use the fastest hot run. Result caching was disabled, so the benchmark measures query execution, not returning a previously cached result.</p>\n<h3 id=\"compared-systems\"></h3>\n<p>For <strong>ClickHouse Cloud</strong>, we used one fixed configuration: a single AWS compute node with 59 cores. For the other systems, we selected practical warehouse or serverless capacity configurations, and discuss the closest hardware comparisons later.</p>\n<ul>\n<li><strong>Snowflake</strong>: Small, Medium, Large, and 4X-Large Gen2 <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-cloud-data-warehouses-bill-you#snowflake\">warehouses</a></li>\n<li><strong>Databricks (SQL Serverless)</strong>: Small, Medium, Large, and 4X-Large <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-cloud-data-warehouses-bill-you#databricks-sql-serverless\">warehouses</a></li>\n<li><strong>BigQuery</strong>: 2,000 <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-cloud-data-warehouses-bill-you#bigquery\">slots</a></li>\n<li><strong>Redshift Serverless</strong>: 128 <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-cloud-data-warehouses-bill-you#redshift-serverless\">RPUs</a></li>\n</ul>\n<h3 id=\"cost-calculations\"></h3>\n<p>For cost calculations, we use the same methodology introduced in our earlier posts on cloud data warehouse <a target=\"_blank\" href=\"https://clickhouse.com/blog/how-cloud-data-warehouses-bill-you\">billing</a> and <a target=\"_blank\" href=\"https://clickhouse.com/blog/cloud-data-warehouses-cost-performance-comparison\">cost-performance</a>. We apply each vendor’s public billing model to the measured query runtimes, <a target=\"_blank\" href=\"https://clickhouse.com/blog/cloud-data-warehouses-cost-performance-comparison#a-note-on-metering-granularity\">assume perfect per-second compute billing</a> for all systems, and use Enterprise-tier pricing in comparable US East regions: AWS <code>us-east</code> for supported systems and GCP <code>us-east</code> for BigQuery.</p>\n<p>With that setup, we first look at raw hot runtime.</p>\n<h2 id=\"tpc-h-sf100-raw-hot-runtime\"></h2>\n<p><a target=\"_blank\" href=\"https://clickhouse.com/docs/getting-started/example-datasets/tpch\">TPC-H SF100</a> consists of <strong>100 GB of data</strong>, <strong>866M rows</strong>, and <strong>22 join-heavy analytical queries</strong>.</p>\n<p>In the diagram below, each bar sums the fastest of three runs for each of the 22 TPC-H queries.
