contentHtml: "<div><h2 id=\"problem\"></h2>\n<p>Our CI system is very good at catching bugs, and sometimes it catches crash logs during AST Fuzzing, Stress, and Functional tests. However, the crash reports are often very similar, and it is hard to understand which bugs are actually new and which ones are already known.</p>\n<p>Quoting the <a target=\"_blank\" href=\"https://arxiv.org/pdf/2009.12590\">TraceSim: A Method for Calculating Stack Trace Similarity</a> article:</p>\n<blockquote>\n<p>Many contemporary software products have subsystems for automatic crash reporting. However, it is well-known that the same bug can produce slightly different reports.</p>\n</blockquote>\n<p>This paper's methodology is based on the idea that similar stack traces are likely to be caused by the same bug. The authors propose a method for calculating stack trace similarity, which can be used to group similar crash stack traces together.</p>\n<p>The system to analyze and group traces from the ClickHouse Cloud was first built by our Infrastructure Engineer, Michael Stetsyuk. It groups crash reports by their stack traces and allows them to be tracked in the issue tracker.</p>\n<p>Similar to that system, we wanted to build a trace similarity system on top of ClickHouse to analyze crash stack traces from our CI. The system should be able to:</p>\n<ul>\n<li>Parse crash reports and extract stack frames.</li>\n<li>Calculate similarity between stack traces.</li>\n<li>Group similar new stack traces together with known.</li>\n<li>Create and update issues on GitHub to track the bugs.</li>\n</ul>\n<p>I'll describe below each step of the process in detail, so you can build a similar system for your own needs.</p>\n<h2 id=\"how-do-we-do-it\"></h2>\n<p>The high-level architecture of the system is as follows:</p>\n<p><span><img alt=\"trace-blog-diagram.jpg\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Ftrace_blog_diagram_4819d96174.jpg&w=2048&q=75\"></span></p>\n<h3 id=\"step-zero-collect-crash-reports-create-all-the-necessary-tables\"></h3>\n<p>We need to collect crash reports from our CI system. The traces contain a lot of noise that can affect the similarity calculation. The noise can come from, but is not limited to:</p>\n<ul>\n<li>Different compiler versions.</li>\n<li>Different build configurations (e.g., debug vs release).</li>\n<li>Different environments (e.g., different OS, different hardware).</li>\n<li>Different file names and line numbers in the stack traces.</li>\n</ul>\n<p>To clean the traces, we define two <a target=\"_blank\" href=\"https://clickhouse.com/docs/sql-reference/functions/udf#sql-user-defined-functions\">User Defined Functions</a>:</p>\n<div><pre><code><span><span>CREATE</span> <span>FUNCTION</span> cleanStackFrame <span>AS</span> frame <span>-</span><span>&gt;</span> replaceRegexpOne(</span>\n<span>  replaceRegexpAll(</span>\n<span>    splitByString(</span>\n<span>      <span>-- second, strip the file name and line number, keep the function name</span></span>\n<span>      <span>': '</span>, splitByString(</span>\n<span>        <span>-- first, strip the frame address, keep the frame number, file name, line number, and function name</span></span>\n<span>        <span>' @ '</span>, frame, <span>2</span></span>\n<span>      )[<span>1</span>], <span>2</span></span>\n<span>    )[<span>2</span>],</span>\n<span>    <span>-- third, replace all ABI specific information with a placeholder</span></span>\n<span>    <span>'\\\\[abi:[^]]+\\\\]'</span>, <span>'[$ABI]'</span>),</span>\n<span>  <span>-- finally, delete all LLVM specific information</span></span>\n<span>  <span>'(\\\\s+[(])*[.]llvm[.].+'</span>, <span>''</span></span>\n<span>);</span>\n<span></span>\n<span><span>CREATE</span> <span>FUNCTION</span> cleanStackTrace <span>AS</span> trace <span>-</span><span>&gt;</span> arrayFilter(</span>\n<span>  frame <span>-</span><span>&gt;</span> (</span>\n<span>    <span>-- second, keep only meaningful frames</span></span>\n<span>    frame <span>NOT</span> <span>IN</span> (<span>''</span>, <span>'?'</span>)), arrayMap(</span>\n<span>      <span>-- first, clean each frame of the stack trace</span></span>\n<span>      fr <span>-</span><span>&gt;</span> cleanStackFrame(fr), trace</span>\n<span>  )</span>\n<span>);</span></code></pre></div>\n<p>These functions will be used to clean the stack traces before calculating their similarity on the fly. The <code>cleanStackFrame</code> function removes the noise from each frame, and the <code>cleanStackTrace</code> function applies it to the whole stack trace.</p>\n<p>There's a possibility of using these UDFs to pre-process the data in the <code>stack_traces</code> table; however, we do it on the fly to avoid storing the pre-cleaned traces in the database. It provides us with more flexibility, enabling us to modify the cleaning logic without reprocessing all the data. It's handy for calculating the weights of frames at the similarity calculation step.</p>\n<h3 id=\"step-two-group-identical-traces-and-distinguish-the-significant-ones-among-them\"></h3>\n<p>Once the stack traces are cleaned, we can start analyzing them. The already processed traces are in the <code>crash_issues</code> table; we use these to find the existing issues.</p>\n<div><pre><code><span><span>WITH</span> known_hashes <span>AS</span></span>\n<span>    (</span>\n<span>        <span>SELECT</span></span>\n<span>            repo,</span>\n<span>            <span>-- Avoid default value of 'open' for state</span></span>\n<span>            toString(state) <span>AS</span> state,</span>\n<span>            updated_at,</span>\n<span>            closed_at,</span>\n<span>            arrayFlatten(groupArrayDistinct(stack_traces_hash)) <span>AS</span> known_hashes</span>\n<span>        <span>FROM</span> default.crash_issues <span>FINAL</span></span>\n<span>        <span>GROUP</span> <span>BY</span> <span>ALL</span></span>\n<span>    )</span>\n<span><span>SELECT</span></span>\n<span>    repo,</span>\n<span>    groupArrayDistinct((pull_request_number, commit_sha, check_name)) <span>AS</span> checks,</span>\n<span>    cleanStackTrace(trace_full) <span>AS</span> trace_full,</span>\n<span>    sipHash64(trace_full) <span>AS</span> trace_hash,</span>\n<span>    length(groupArrayDistinct(pull_request_number) <span>AS</span> PRs) <span>AS</span> trace_count,</span>\n<span>    has(PRs, <span>0</span>) <span>AS</span> is_in_master</span>\n<span><span>FROM</span> has(kh.known_hashes, trace_hash))</span>\n<span><span>WHERE</span> (st.event_time <span>&gt;=</span> (now() <span>-</span> toIntervalDay(<span>30</span>)))</span>\n<span>    <span>AND</span> (length(trace_full) <span>&gt;</span> <span>5</span>)</span>\n<span><span>GROUP</span> <span>BY</span></span>\n<span>    repo,</span>\n<span>    trace_full</span>\n<span><span>HAVING</span></span>\n<span>    groupArrayDistinct(kh.state) <span>=</span> [<span>''</span>] <span>-- new trace, no issues</span></span>\n<span>    <span>OR</span> (groupArrayDistinct(kh.state) <span>=</span> [<span>'closed'</span>] <span>AND</span> <span>max</span>(st.check_start_time) <span>&gt;</span> <span>max</span>(kh.closed_at)) <span>-- new event after the issue is closed</span></span>\n<span><span>ORDER</span> <span>BY</span> <span>max</span>(st.event_time)</span></code></pre></div>\n<p>This query groups the stack traces by their cleaned version and calculates the hash of the trace. The hashes are checked against the <code>crash_issues</code> table to find out if the trace is already known. If there is an open issue, or the trace is created before the existing issues were closed, it is considered a known trace.</p>\n<p>The query also counts the number of unique pull requests that contain the trace and checks if the trace is present in the master branch (pull request number 0). If the trace appears in fewer than three pull requests and wasn't seen in the master/release branches, it's considered insignificant. Such traces aren't used to create issues, but they can be added to existing issues if they are similar enough to the known traces.</p>\n<h3 id=\"step-three-calculate-similarity-between-traces\"></h3>\n<p>Now we have a list of new stack traces from step two. We need to compare them one by one to the known stack traces, linked to GitHub issues.</p>\n<p>The following query is the <a target=\"_blank\" href=\"https://arxiv.org/pdf/2009.12590\">TraceSim's paper</a> implementation of the similarity calculation. ClickHouse has <code>arraySimilarity</code> function since version <a target=\"_blank\" href=\"https://clickhouse.com/docs/whats-new/changelog#254\">25.4</a>, the weights are calculated on the fly. The <code>new_trace</code> is one of the new traces from step two.</p>\n<div><pre><code><span><span>WITH</span></span>\n<span>    <span>1.97</span> <span>AS</span> alpha,</span>\n<span>    <span>2.0</span> <span>AS</span> beta,</span>\n<span>    <span>3.7</span> <span>AS</span> gamma,</span>\n<span>    <span>0.68</span> <span>AS</span> threshold,</span>\n<span>    stack_frame_weights <span>AS</span> (</span>\n<span>        <span>WITH</span></span>\n<span>            (</span>\n<span>                <span>SELECT</span> <span>count</span>()</span>\n<span>                <span>FROM</span> default.stack_traces</span>\n<span>                <span>FINAL</span></span>\n<span>            ) <span>AS</span> total</span>\n<span>        <span>SELECT</span></span>\n<span>            arrayJoin(cleanStackTrace(trace_full)) <span>AS</span> frame,</span>\n<span>            countDistinct(trace_full) <span>AS</span> count,</span>\n<span>            <span>log</span>(total <span>/</span> count) <span>AS</span> IDF,</span>\n<span>            sigmoid(beta <span>*</span> (IDF <span>-</span> gamma)) <span>AS</span> weight</span>\n<span>        <span>FROM</span> default.stack_traces</span>\n<span>        <span>FINAL</span></span>\n<span>        <span>GROUP</span> <span>BY</span> frame</span>\n<span>    ),</span>\n<span>    (<span>SELECT</span>
