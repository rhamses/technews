id=\"adding-support-to-opentelemetry\"></h3>\n<p>Before we could add support to HyperDX, we first had to ensure each layer of the stack could handle JSON properly. Adding support to the ClickHouse OpenTelemetry exporter first required support for the JSON type in the <a target=\"_blank\" href=\"https://github.com/clickHouse/clickHouse-go\">clickhouse-go client</a> - used by the exporter for data insertion. This inserts JSON columns as a serialized JSON string. ClickHouse parses this and handles the identification of new columns and their types.</p>\n<p>Additionally, there were also some optimizations made to the insertion logic itself. The Go driver was updated to use ClickHouse’s native API for both TCP and HTTP connections. This improved performance when transforming the data from OpenTelemetry's structures to ClickHouse's native columnar format. We also used <code>pprof</code> to identify optimizations for the main insertion loops. Most of these were redundant calls to getters on OpenTelemetry structures.</p>\n<p>Support for JSON in the ClickHouse exporter was recently <a target=\"_blank\" href=\"https://github.com/open-telemetry/opentelemetry-collector-contrib/pull/40547\">merged behind a feature flag</a>. Furthermore, a few queries had to be rewritten to use the new JSON path notation, allowing us to access nested fields efficiently. At this stage, some operations still rely on casting JSON values to strings or floats, but over time we plan to implement smarter metadata caching.
