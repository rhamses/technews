Filters on these columns become queries like:</p>\n<div><pre><code><span>LogAttributes[<span>'http.status_code'</span>] <span>=</span> <span>'500'</span></span></code></pre></div>\n<p>or</p>\n<div><pre><code><span>ResourceAttributes[<span>'k8s.namespace.name'</span>] <span>=</span> <span>'payments'</span></span></code></pre></div>\n<p>This flexible schema design is one of the reasons OpenTelemetry works well across heterogeneous workloads, but it also creates a challenge for query execution. ClickHouse needs an efficient way to determine which <a target=\"_blank\" href=\"https://clickhouse.com/docs/guides/best-practices/sparse-primary-indexes#data-is-organized-into-granules-for-parallel-data-processing\">granules</a> may contain a given attribute key or value before reading and unpacking the underlying map data itself.</p>\n<p>Earlier versions of the schema relied mostly on a bloom filter over map keys and values. This helped avoid unnecessary reads, but search-heavy attribute queries still meant more I/O and slower queries.</p>\n<p>The new schema enables a new attribute-search path based on ClickHouse's text index. When enabled, values inside <code>ResourceAttributes</code>, <code>ScopeAttributes</code>, and <code>LogAttributes</code> are indexed using <code>text(tokenizer = 'array')</code>. This performs significantly better in our benchmarks for search-heavy attribute filtering workloads.</p>\n<p>One complication here is that the query shape does not directly match the indexed expression. The index is built over <code>mapValues(LogAttributes)</code>, while the filter itself is expressed as a keyed map lookup. That still gives ClickHouse useful pruning information, but not enough to fully resolve the predicate from the index alone.</p>\n<p>To avoid that mismatch, we added an alternate indexed representation for attribute maps. Each map is flattened into an array of <code>key=value</code> strings with a corresponding <code>text(tokenizer = 'array')</code> index.</p>\n<div><pre><code><span>LogAttributes[<span>'http.status_code'</span>] <span>=</span> <span>'500'</span></span></code></pre></div>\n<p>can be rewritten as:</p>\n<div><pre><code><span>has(LogAttributeItems, <span>'http.status_code=500'</span>)</span></code></pre></div>\n<p>This shape aligns exactly with the array tokenizer, allowing ClickHouse to evaluate the predicate from the index without unpacking the original map column. In our internal benchmarks, attribute filters that hit this path ran between 1.4 and 10 times faster than the equivalent map-subscript query.</p>\n<p><span><img alt=\"\" src=\"https://clickhouse.com/_next/image?url=%2Fuploads%2Fclickstack_apr2026_image4_3a6ff9ed6c.png&w=2048&q=75\"></span></p>\n<p><em>The green bar represents the performance of queries related to autocomplete for the previous implementation.
