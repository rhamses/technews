Depending on your use case, different types can be applied. Using the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/date\">Date</a> type for dates should be sufficient in most cases. This type only requires 2 bytes to store a date but limits the range to <code>[1970-01-01, 2149-06-06]</code>. The <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/datetime\">DateTime</a> allows storing dates and times up to the year 2106. For cases where more precision is required, the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/data-types/datetime64\">DateTime64</a> can be used. This allows storing time with up to nanoseconds precision:</p>\n<pre><p>\nCREATE TABLE dates\n(\n    `date` Date,\n    `datetime` DateTime,\n    `precise_datetime` DateTime64(3),\n    `very_precise_datetime` DateTime64(9)\n)\nENGINE = MergeTree\nORDER BY tuple()\n</p>\n</pre>\n<p>We can use the <code>now()</code> function to return the current time and <code>now64()</code> to get it in a specified precision via the first argument.</p>\n<pre><p>\nINSERT INTO dates SELECT NOW(), NOW(), NOW64(3), NOW64(9);\n</p>\n</pre>\n<p>This will populate our columns with time accordingly to the column type:</p>\n<pre><p>\nSELECT * FROM dates\nRow 1:\n──────\ndate:                  2022-12-27\ndatetime:              2022-12-27 12:51:15\nprecise_datetime:      2022-12-27 12:51:15.329\nvery_precise_datetime: 2022-12-27 12:51:15.329098089\n</p>\n</pre>\n<h3 id=\"timezones\"></h3>\n<p>Practical cases require having timezones stored as well in many cases. A popular example here is tracking website visitors.</li>\n<li>Gauges are used to set a metric value that tends to change over time. A good example here is tracking CPU load.</li>\n</ul>\n<p>Both metric types are easy to work with in ClickHouse and don’t require any additional configuration. Counters can be easily queried using <code>count()</code> or <code>sum()</code> functions, depending on the storage policy. To efficiently query for gauges, the <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/aggregate-functions/reference/any/\"><code>any()</code></a> aggregate function can be used together with <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/select/order-by/#order-by-expr-with-fill-modifier\">INTERPOLATE</a> modifier to fill any missing data points:</p>\n<pre><p>\nCREATE TABLE metrics\n( `time` DateTime, `name` String, `value` UInt32 )\nENGINE = MergeTree ORDER BY tuple();\nINSERT INTO metrics VALUES\n('2022-12-28 06:32:16', 'cpu', 7), ('2022-12-28 14:31:22', 'cpu', 50), ('2022-12-28 14:30:30', 'cpu', 25), ('2022-12-28 14:25:36', 'cpu', 10), ('2022-12-28 11:32:08', 'cpu', 5), ('2022-12-28 10:32:12', 'cpu', 5);\nSELECT\n    toStartOfHour(time) AS h,\n    any(value) AS v\nFROM metrics\nGROUP BY h\nORDER BY h ASC WITH FILL STEP toIntervalHour(1)\nINTERPOLATE ( v AS v )\n┌───────────────────h─┬──v─┐\n│ 2022-12-28 06:00:00 │  7 │\n│ 2022-12-28 07:00:00 │  7 │ &lt;- filled\n│ 2022-12-28 08:00:00 │  7 │ &lt;- filled\n│ 2022-12-28 09:00:00 │  7 │ &lt;- filled\n│ 2022-12-28 10:00:00 │  5 │\n│ 2022-12-28 11:00:00 │  5 │ &lt;- filled\n│ 2022-12-28 12:00:00 │  5 │ &lt;- filled\n│ 2022-12-28 13:00:00 │  5 │ &lt;- filled\n│ 2022-12-28 14:00:00 │ 50 │\n└─────────────────────┴────┘\n</p>\n</pre>\n<p>In this case, highlighted values were automatically filled by ClickHouse, to follow the gauge nature of the metric within a continuous time range.</p>\n<h3 id=\"histograms\"></h3>\n<p>A popular use case for time series data is to build histograms based on tracked events.
