One of the most notable being the performance gains; Fusion compiles and parses projects <strong>up to 30x faster</strong> than dbt Core, slashing development and iteration times from minutes to milliseconds. But on top of that, it also brings new features, like:</p><ul><li>State aware caching for cost reduction</li><li>A SQL-aware language server and improved IDE experience</li><li>Improved metadata management with tagging and column-level lineage</li></ul><p>By fusing <strong>dbt Fusion</strong> into Dagster’s dbt integration, you're getting:</p><ul><li>‍<strong>Hyper-fast iteration</strong> - Instant feedback loops make experimentation and debugging much more efficient.<strong>‍</strong></li><li><strong>Smarter editing experience</strong> - SQL authoring becomes proactive with insights baked right into your editor.<strong>‍</strong></li><li><strong>Efficient execution</strong> - Only changed models rerun, saving both time and compute costs.</li></ul><h2>Enabling Fusion support in the Dagster dbt integration</h2><p>If you’re ready to try Dagster’s dbt integration with Fusion, here’s all you need to do:</p><ol><li><strong>Install dbt Fusion</strong> dbt Fusion is distributed as a standalone Rust binary. Follow the <a target=\"_blank\" href=\"https://docs.getdbt.com/docs/fusion/about-fusion\">dbt installation docs</a> or use the provided install script to get the CLI on your PATH.</li></ol><ol><li><strong>Skip installing dbt-core</strong> If you want to test the pure Fusion flow, you don’t need dbt-core in your Python environment. Dagster will detect this and automatically switch to CLI-based methods.</li></ol><ol><li><strong>Point Dagster to your dbt project</strong> Use the standard DbtCliResource setup in your definitions:</li></ol><pre><code><span><span>1</span><span>from</span><span> dagster_dbt </span><span>import</span><span> DbtCliResource‍\n</span></span><span><span>2</span>\n</span><span><span>3</span><span>dbt_resource = DbtCliResource(project_dir=</span><span>\"path/to/your/dbt/project\"</span><span>)</span></span></code></pre><ol><li><strong>Pass the project to your @dbt_assets</strong>:</li></ol><pre><code><span><span>1</span><span>from</span><span> dagster_dbt </span><span>import</span><span> dbt_assets, DbtProject‍\n</span></span><span><span>2</span>\n</span><span><span>3</span><span>project = DbtProject(</span><span>\"path/to/your/dbt/project\"</span><span>)‍\n</span></span><span><span>4</span>\n</span><span><span>5</span><span></span><span>@dbt_assets(</span><span>manifest=project.manifest_path, project=project</span><span>)</span><span>\n</span></span><span><span>6</span><span></span><span>def</span><span> </span><span>my_assets</span><span>(</span><span>context, dbt: DbtCliResource</span><span>):</span><span>\n</span></span><span><span>7</span><span>&#160;&#160;&#160;&#160;</span><span>yield</span><span> </span><span>from</span><span> dbt.cli([</span><span>\"build\"</span><span>], context=context).stream()</span></span></code></pre><ol><li><strong>Run as usual</strong> Materialize your assets with Dagster’s orchestration, and enjoy the same asset materializations, checks, and metadata you get with dbt Core—now powered by dbt Fusion’s speed.</li></ol><h3>The technical details: How we added dbt Fusion support to Dagster</h3><p>Supporting the dbt Fusion engine in Dagster’s dagster-dbt library required <a target=\"_blank\" href=\"https://github.com/dagster-io/dagster/pull/31337\">rethinking our integration</a> interacts with dbt itself. Fusion is written in Rust and ships without the dbt-core Python package, so we needed to make the integration work both <strong>with</strong> and <strong>without</strong> the Python APIs.</p><p>Here’s what we changed under the hood:</p><ul><li><strong>Removed the hard dependency on dbt-core</strong> The integration now detects whether dbt-core is installed. If it is, we keep using the familiar Python methods for things like resolving selection strings. If it isn’t, we fall back to invoking dbt CLI commands directly, so Fusion users get full functionality without Python bindings.</li></ul><ul><li><strong>Compatibility shims for missing Python types</strong> When dbt-core isn’t installed we now provide internal stand-ins for these so Dagster can still interpret run results and surface rich asset events.</li></ul><ul><li><strong>Updated log parsing for Fusion’s event format</strong> dbt Fusion’s CLI output consolidates all model/test execution logs into a NodeFinished event type, whereas dbt Core uses multiple result event types. We created separate parser subclasses for each engine so asset materializations, checks, and metadata extraction remain consistent.</li></ul><ul><li><strong>Manifest differences handled transparently</strong> Fusion’s manifest output lacks a child_map field, so Dagster now builds that mapping dynamically to preserve lineage tracking and check associations.</li></ul><ul><li><strong>Engine-aware selection logic</strong> If Python APIs are unavailable, Dagster now resolves --select/--exclude/--selector arguments by calling dbt list --output json under the hood, ensuring selections behave identically in both environments.</li></ul><p>The result: whether you’re running dbt Core or dbt Fusion, Dagster gives you the same asset awareness, check integration, and orchestration experience, but if you opt to use the new Fusion engine, then you’ll get to see some pretty awesome performance improvements!</p></div></article></div><div><p><img
