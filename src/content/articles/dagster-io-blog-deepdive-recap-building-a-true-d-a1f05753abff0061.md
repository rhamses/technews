contentHtml: "<div><div><article><h3>Move past the MDS and build a data platform for observability, cost-efficiency, and top-tier orchestrating.</h3><div><p>As data engineering evolves, companies are running into problems with the modern data stack: observability, orchestration, and cost. To solve these problems, our recent <a target=\"_blank\" href=\"https://dagster.io/events/dagster-deep-dives\">Dagster Deep Dive</a>, led by [Pedram Navid] (https://www.linkedin.com/in/pedramnavid/), went into how to build a real data platform that goes beyond the modern data stack.</p><p>If you missed the live event, don’t worry. </p><p>We’ve embedded the video below so you can watch below.</p><figure><p></p><figcaption>&gt; &#160; &#160;Building a True Data Platform: Beyond the Modern Data Stack (A Dagster Deep Dive) &#160;</figcaption></figure><h2>Highlights</h2><p>We covered the following during the deep dive:</p><h3>The Unmet Promise of the Modern Data Stack</h3><p>While the modern data stack has improved upon previous tools, it has also introduced new problems:</p><ul><li>No observability across multiple tools</li><li>Limited orchestration beyond basic scheduling</li><li>High cost and vendor lock-in</li></ul><h3>The Data Platform Engineer</h3><p>We introduced the data platform engineer as the role that’s been created to solve these problems.</p><p>This role is about managing complex data infrastructure, with engineers building platforms that serve the needs of stakeholders. They enable consumers to build pipelines without having to learn complex languages, making data more accessible to a broader set of users.</p><p>And they’re moving from building individual pipelines to building frameworks and services that support the entire data ecosystem within an organization.</p><p>This is a big change and evolution in data engineering.</p><h3>What Makes a Good Data Platform?</h3><p>We went into how a real data platform is the foundation of modern data driven companies, and what characteristics a platform should have to meet the changing needs of companies and their data teams:</p><ul><li><strong>Scalability and Maintainability</strong>: It should grow with your company’s data maturity</li><li><strong>High-Quality Governance</strong>: Data testing, fact assertion, alerting</li><li><strong>Data Observability and Insights</strong>: Stakeholders should be able to see the state of the data and dependencies</li><li><strong>Software Development Lifecycle Integration</strong>: Testing, version control, branching</li><li><strong>Support for Heterogeneous Use Cases</strong>: Different languages and tools</li><li><strong>Declarative Workflows</strong>: Flexible, easy to understand process definitions</li></ul><h2>Takeaways</h2><p>Here's a recap of the main takeaways from the deep dive:</p><ul><li>The modern data stack is an improvement over legacy systems but has introduced new problems in data engineering: fragmented observability, limited orchestration, cost.</li><li>The data platform engineer role has emerged to solve these problems.</li><li>A good data platform should be scalable and maintainable, have high-quality governance and data observability and insights.</li><li>A data platform should also have:<ul><li>Software development lifecycle integration</li><li>Support for heterogeneous use cases</li><li>Different languages and tools</li><li>Declarative workflows</li></ul></li><li>Code-based solutions over no-code or low-code for complex data engineering tasks.</li><li><a target=\"_blank\" href=\"https://dagster.io/platform-overview\">Dagster</a> can help build such a unified data platform with features like code locations and asset checks for data quality and governance.</li></ul><h2>Q&amp;A</h2><p>Near the end of the deep dive, Pedram answered questions from our audience. Here are those questions and answers:</p><ol><li><strong>What are Dagster’s features for data governance, especially data access management?</strong><ul><li>The roadmap for data access management features isn’t set, but we’re considering role-based access control (RBAC). It’s possible for future development, but the timeline is unknown.</li></ul></li><li><strong>Are column-level lineage and data catalog in Dagster Plus or open source?</strong><ul><li>Column-level lineage is a Dagster+ feature, not open source.</li></ul></li><li><strong>How to schedule assets from multiple code locations?</strong><ul><li>Keep each code location separate as much as possible. For dependencies between code locations, you can use an asset sensor as input into the pipeline. You can also look into declarative automation, which allows you to specify asset materialization at a specific cadence without getting too granular about the details.</li></ul></li><li><strong>How to move from an existing Airflow setup to Dagster?</strong><ul><li>We’re working on a solution for this exact problem. Reach out on Slack and we’ll connect you with someone who can help.</li></ul></li><li><strong>What’s Dagster’s view on machine learning processes or LLM Ops?</strong><ul><li>We use Dagster internally for LLM Ops, basically as data ops. With LLMs, data quality and metadata become important. Dagster has built-in integrations like OpenAI, so you can observe token consumption through Dagster Insights. You can also emit custom metadata to track metrics like token count over time or LLM response quality.</li></ul></li><li><strong>Can I use Dagster Plus and then move to my own server with the open source option?</strong><ul><li>Yes, that’s possible. But if you become dependent on Dagster+ only features, you’ll need to remove those when you move. The core code itself isn’t locked in.</li></ul></li><li><strong>Can I access the data catalog programmatically and tag datasets for filtering?</strong><ul><li>Tagging and filtering by tags in the catalog is supported. For programmatic access to the data catalog, ask in the Slack channel for more info.</li></ul></li><li><strong>Can I use the Great Expectations plugin for data assets?</strong><ul><li>Yes, you can use Great Expectations or Dagster’s built-in asset checks. Depends if you need the more complex features Great Expectations offers.</li></ul></li><li><strong>What plugins or integrations would be helpful for a Financial Service Company?</strong><ul><li>Financial service companies face similar data engineering challenges as other industries. Data replication is key, so tools like Airbyte for replicating data across databases to your data warehouse are useful. Remember, Dagster is Python-based, so you can use any Python library, even without a specific built-in integration.</li></ul></li></ol><h2>Conclusion</h2><p>Building a real data platform is more than just using modern data stack tools. It’s thinking about scalability, governance and observability.
