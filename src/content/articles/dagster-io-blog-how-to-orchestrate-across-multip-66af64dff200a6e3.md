contentHtml: "<div><h2>Your First Workspace Was a Revelation. Your Thirtieth Is a Crisis.</h2><p>Somewhere between workspace five and workspace twenty, you lost the ability to answer a simple question: when Team A's pipeline fails at 3 AM, which downstream teams in which other workspaces are affected?</p><p>Lakeflow Jobs does not know. It cannot see across workspace boundaries. The \"Run Job\" task only triggers jobs within the same workspace.</p><p>So teams stitch together REST API polling scripts, Slack alerts, and a growing web of fragile dependencies.</p><h2>When Workspaces Become a System</h2><p>You start with one Databricks workspace. Within months, you have twelve.</p><p>This is how Databricks is designed to scale:&#160;split across environments, teams, and data products.</p><p>But once pipelines span multiple workspaces, you are no longer orchestrating inside a single system. You are coordinating a distributed one.</p><p>Dependencies exist across workspaces, but they are not defined anywhere.</p><h2>What Actually Breaks</h2><p>Consider a common scenario.</p><p>A finance team produces a curated dataset in one workspace. A machine learning team consumes that dataset in another to train a model.</p><p>If the upstream pipeline fails or runs late, nothing in Databricks prevents the downstream job from executing. There is no native way to express that dependency across workspaces, and no shared understanding of what is affected.</p><p>The result is predictable: stale data, inconsistent model outputs, and finance and ML engineers debugging the same failure from opposite ends of the platform.</p><h2>From Visibility to Coordination</h2><p>The first step is visibility.</p><p><a target=\"_blank\" href=\"https://docs.dagster.io/guides/labs/connections/databricks\">Connections</a> is the read-only entry point. It provides a view into Databricks jobs and pipelines across workspaces without requiring code changes, so you can see what exists and how it is structured.</p><p>The <a target=\"_blank\" href=\"https://docs.dagster.io/integrations/libraries/databricks/databricks-workspace-component\">DatabricksWorkspaceComponent</a> is the next step. It loads those jobs into Dagster as assets, bringing them into a single asset graph where dependencies can be defined across workspaces and execution coordinated accordingly.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/69e667c17b773d453ba380b1_Screenshot%202026-04-20%20at%201.51.38%E2%80%AFPM.png\"></p></figure><p>This is the shift: from observing pipelines to controlling how they relate.</p><h2>What This Looks Like in Practice</h2><p>Back to finance and ML.</p><p>With both workspaces connected, the curated finance dataset appears in the asset graph as an upstream dependency of the ML training job. That dependency is now declared, not implied:</p><pre><code><span><span>@asset(</span><span>deps=[finance_workspace.curated_revenue]</span><span>)</span><span>\n</span></span><span><span></span><span>def</span><span> </span><span>churn_model_training</span><span>(</span><span>context</span><span>):</span><span>\n</span></span><span>    ...</span></code></pre><p>When the finance pipeline fails or runs late, the ML job does not execute on stale inputs. A <a target=\"_blank\" href=\"https://docs.dagster.io/concepts/assets/freshness-policies\">freshness policy</a> on the curated dataset enforces the expectation explicitly, and both teams see the same lineage when something breaks.</p><p>The cross-workspace dependency that used to live in a Slack thread now lives in code.</p><h2>The Bottom Line</h2><p>Databricks scales by adding workspaces. As it scales, orchestration becomes a cross-workspace problem.</p><p>Dagster provides the missing layer by allowing you to observe, define, and orchestrate dependencies across your entire platform. This is what cross-workspace orchestration for Databricks actually requires.</p><p>If your pipelines already span multiple workspaces, this is not theoretical. It is already your reality.</p><p>For a hands-on walkthrough of connecting multiple workspaces, auto-discovering assets with the DatabricksWorkspaceComponent, and building a unified asset graph — <a target=\"_blank\" href=\"https://dagster.io/events/deep-dive-building-a-cross-workspace-control-plane-for-databricks\">watch the full deep dive</a>.</p><p>‍</p></div>"
