It provides practical examples, techniques, and best practices for setting up your Python environment, configuring paths to important tools, or defining variables for your scripts.</p><p>‍</p><h2>What are environment variables?</h2><p>Python provides a built-in module named <a target=\"_blank\" href=\"https://docs.python.org/3/library/os.html\"><strong><code>os</code></strong></a> as an interface to interact with the underlying operating system. This module provides a dictionary-like object, <strong><code>os.environ</code></strong>, that allows you to interact with environment variables.</p><p><strong><code>os.environ</code></strong> acts as a mapping between environment variable names and their values. It can access, modify, or create environment variables in a Python program. Let's break it down.</p><h3>Reading Python Environment Variables</h3><p>To read the value of an environment variable in Python, you treat <strong><code>os.environ</code></strong> as a dictionary and access the variable by its name. Here's an example:</p><pre><code><span><span>import</span><span> os\n</span></span><span>\n</span><span><span></span><span>### Accessing an environment variable</span><span>\n</span></span><span><span></span><span>print</span><span>(os.environ[</span><span>'HOME'</span><span>])\n</span></span><span></span></code></pre><p>This will print your default ‘home’ directory: <strong><code>/Users/username</code></strong> on a macOS system or <strong><code>/home/username</code></strong> on a Linux system:</p><pre><code><span><span>/Users/elliot</span></span></code></pre><p>Here, <strong><code>HOME</code></strong> is the name of the environment variable that typically stores the path to the current user's home directory. If the environment variable exists, its value will be printed to the console. If the environment variable does not exist, however, this will raise a <strong><code>KeyError</code></strong>.</p><p>To avoid this error, you might choose to use the <strong><code>get</code></strong> method, which allows you to provide a default value that will be returned if the environment variable is not found:</p><pre><code><span><span>import</span><span> os\n</span></span><span>\n</span><span><span></span><span>### Accessing an environment variable with a default value</span><span>\n</span></span><span><span></span><span>print</span><span>(os.environ.get(</span><span>'HOME'</span><span>, </span><span>'/home/default'</span><span>))\n</span></span><span></span></code></pre><p>In this case, if the <strong><code>HOME</code></strong> variable does not exist, the string <strong><code>/home/default</code></strong> will be returned instead.</p><p>You can print out and explore all environment variables with the following script:</p><pre><code><span><span>import</span><span> os\n</span></span><span>\n</span><span><span></span><span>for</span><span> name, value </span><span>in</span><span> value))\n</span></span><span></span></code></pre><h3>Modifying and Adding Environment Variables</h3><p>You can modify the value of an existing environment variable, or add a new one, by assigning a value to a key in the <strong><code>os.environ</code></strong> object:</p><pre><code><span><span>import</span><span> os\n</span></span><span>\n</span><span><span></span><span>### Setting an environment variable</span><span>\n</span></span><span><span>os.environ[</span><span>'MY_VARIABLE'</span><span>] = </span><span>'foo'</span><span>\n</span></span><span>\n</span><span><span></span><span>### Now, the new variable is accessible via os.environ</span><span>\n</span></span><span><span></span><span>print</span><span>(os.environ[</span><span>'MY_VARIABLE'</span><span>])  </span><span># Outputs: foo</span><span>\n</span></span><span></span></code></pre><p>In this example, the <strong>MY_VARIABLE</strong> environment variable is created and set to foo. However, this variable will be available only as long as the current process is running.</p><p>Changes made to the os.environ object are local to the process where they are made. If you set an environment variable in your Python script, it will be available to that script and any subprocesses it creates. However, it will not be visible in the broader environment or to other unrelated processes.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/686619d5dc6482e76ceafe50_6848255baaab6337076818f2_image.png\"></p></figure><p>The scope and lifecycle of environment variables set in this way are limited to the current process where they are assigned. As this might be a complicated point, consider our example above.</p><p>A Python script sets an environment variable named <strong>MY_VARIABLE</strong> to foo. If this script calls another Python script and creates a subprocess (Process 1), the second script will also access <strong>MY_VARIABLE</strong>. But if you try to access <strong>MY_VARIABLE</strong> from a different Python script that was not launched by the first script (Process 2), or from the command line after running the script, <strong>MY_VARIABLE</strong> will not be available—it is not part of the broader environment. Both processes, however, have access to any global variables like <strong>GLOBAL_VARIABLE</strong> in the example above.</p><h2>Scope and lifecycle of environment variables</h2><p>To persist environment variables across different sessions or processes, you'll need to set them in your operating system's environment outside of Python. The way to do this varies based on your operating system and shell but generally involves editing shell configuration files or using command-line utilities.</p><p>Let’s review what we mean when we talk about operating systems, shells, and command-line utilities.</p><h3>Operating systems, shells, and command-line utilities</h3><p><strong>Operating systems</strong> are the most fundamental piece of software that run on a computer. It acts as an intermediary between the user and the computer hardware, making it possible for users to execute programs, manage files, and interact with the device. Operating systems allow you to manage files, processes, memory, and security. Popular operating systems include Microsoft Windows, macOS, and Linux distributions (like Ubuntu, Fedora, etc.).</p><p><strong>Shells</strong> allow you to interact with your computer's operating system. As a data engineer, you'll primarily work with command-line shells, which let you issue commands to the operating system by typing them in as text.</p><p>When you open a terminal window (on Linux or Mac) or command prompt (on Windows), you interact with a shell. You might type a command like <strong><code>python my_script.py</code></strong> to run a Python script, or <strong><code>ls</code></strong> (on Linux or Mac) or <strong><code>dir</code></strong> (on Windows) to list the files in the current directory. These are all examples of interacting with a command-line shell.</p><p><strong>Shell configuration files</strong> are special files that the shell reads when it starts up. As a <a target=\"_blank\" href=\"https://docs.dagster.io/guides/build/projects/creating-a-new-project\">Dagster data engineer</a>, you will probably use them to set environment variables that should be available every time you open a new terminal window. This simplifies things since the shell automatically executes them every time it starts.</p><p><strong>Command-line utilities</strong> are programs designed for use from a text interface. Instead of clicking on buttons, you can run Python scripts from the command line (e.g., use pip to install Python packages or jupyter to start a Jupyter notebook server) or use Git from the command line for <a target=\"_blank\" href=\"https://dagster.io/blog/python-ci-cd-automation\">version control</a>. Other examples include Unix command-line utilities such as grep, awk, sed to search, filter, and transform text data; curl and wget to download files from the web; and ssh to connect with remote servers when working with <a target=\"_blank\" href=\"https://dagster.io/blog/python-high-performance\">distributed systems</a> or cloud-based resources.</p><h3>Process-level scope</h3><p>Environment variables set or modified via os.environ in your Python script are accessible within the same process. If your script starts another process (a subprocess), that subprocess inherits the environment of its parent, including any environment variables set by the parent. However, if two separate processes both set an <a target=\"_blank\" href=\"https://docs.dagster.io/guides/operate/configuration/run-configuration\">environment variable</a> with the same name, they will not interfere with each other; each process has its own independent copy of the environment.</p><h3>User-level and system-level scope:</h3><p>If you want to set environment variables that are accessible to all processes of a particular user, or to all processes on the system, you need to do this outside of Python, in the configuration files for your shell or operating system. These changes have a broader scope but are not immediate; they typically require you to start a new shell session or reboot the system.</p><h3>Persistence of changes</h3><p>Changes to <a target=\"_blank\" href=\"https://docs.dagster.io/guides/operate/configuration/using-environment-variables-and-secrets\">environment variables</a> made using os.environ in a Python script do not persist after the script finishes executing. This means that if you run a script that sets an environment variable and then run another script or return to your shell, the environment variable changes from the first script will not be visible.</p><p>This non-persistence can be an advantage. It allows your script to modify its environment as needed for its own purposes without affecting other processes or leaving lasting changes that could affect future shell sessions.</p><p>If you want to set an environment variable that persists across multiple shell sessions or is available to other applications, you must do so at the shell level or via the operating system's interfaces for setting environment variables. The exact method depends on your operating system and shell. However, you should do this carefully, as it can potentially have wide-ranging effects on your system's behavior.</p><p>‍</p><h2>Environment variables and configuration</h2><p>Using environment variables for <a target=\"_blank\" href=\"https://docs.dagster.io/api/dagster/config\">configuration</a> is considered a best practice in software development for two reasons.</p><p>First, they help avoid storing sensitive information, such as passwords, API keys, or <a target=\"_blank\" href=\"https://docs.dagster.io/guides/build/external-resources/configuring-resources\">database URIs</a>, directly in your code. This prevents such information from being inadvertently exposed, for example, by being included in version control repositories.</p><p>Second, they also make your code more portable. When different settings are needed for development, testing, and production environments, these can be controlled through environment variables without modifying the code. If a configuration value needs to change, it can be updated in the environment variable without requiring a change to the application's code and without needing to redeploy the application.</p><h3>Using environment variables for sensitive information</h3><p>To use environment variables for sensitive data like <a target=\"_blank\" href=\"https://docs.dagster.io/guides/operate/configuration/using-environment-variables-and-secrets\">API keys</a> or database URIs, ensure that the relevant environment variables are set in the environment where your Python code is running.</p><p>For example, you might have a Python script that connects to a database and uses an API. Instead of hardcoding the database URI and the API key in the script, use environment variables:</p><pre><code><span><span>import</span><span> os\n</span></span><span>\n</span><span><span></span><span>### Accessing sensitive data from environment variables</span><span>\n</span></span><span><span>db_uri = os.environ.get(</span><span>'DATABASE_URI'</span><span>)\n</span></span><span><span>api_key = os.environ.get(</span><span>'API_KEY'</span><span>)\n</span></span><span></span></code></pre><p>In this case, the <strong><code>DATABASE_URI</code></strong> and <strong><code>API_KEY</code></strong> environment variables would need to be set in the environment where the script is run. This could be done in the shell before starting the script, or in a configuration file that the shell reads when it starts.</p><h3>Don’t hardcode!</h3><p>Hardcoding sensitive information, such as directly embedding specific values or parameters into your code, like API keys or database URIs, poses a significant security risk. If your code is shared or made public, for example on GitHub, anyone who sees the code can access these sensitive details. This could allow unauthorized access to your database or misuse of your API keys.</p><p>Even if you do not plan to share your code, a risk remains. Hardcoded information stays in version control history, so anyone who later gains access to the repository could find sensitive data in old commits.</p><p>Hardcoding also makes your code less flexible. If you want to use a different database for testing or need to change API keys, you would need to change and redeploy your code. By contrast, using environment variables for such details allows you to simply change the environment variables when needed without touching your code.</p><h2>Best practices for managing environmental variables</h2><p>With \"dotenv\" files, you can store your configuration in a .env file that loads when your application starts. Raise an error if a critical variable is missing to prevent unexpected behavior.</li></ul><h3>Environment variables in production</h3><p>In development, it's often beneficial to have a simple and secure way to set environment variables that your application can use. between deployment environments and for sensitive data that should not be stored directly in the code.</p><p>You should consider using environment variables for:</p><ul><li><a target=\"_blank\" href=\"https://docs.dagster.io/guides/build/external-resources/configuring-resources\">Database URLs</a> and other related settings</li><li>API keys, tokens, or secrets</li><li>Hostnames or URLs for external services</li><li>Any kind of sensitive data that should not be exposed in the code</li></ul><p>However, environment variables may not be the best choice for:</p><ul><li>Fine-tuned configuration options that may need to be changed often</li><li>Large amounts of binary data</li><li>Data that would be better stored in a database or other storage service</li></ul><h3>Additional considerations for managing secrets and sensitive information</h3><p>Managing secrets and sensitive information is one of the key uses of environment variables. By storing this data in environment variables, you keep it out of your code.
