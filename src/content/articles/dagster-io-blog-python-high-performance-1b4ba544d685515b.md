Python code</h2><p>If you’re new to coding, thinking about how to improve Python performance may sound abstract. Multiply this by tens or hundreds of pipelines across the company, and it’s clear how these inefficiencies compound, too. </p><p>You could trim this processing time to just a few minutes with some relatively easy optimizations. Optimized code isn't just faster. It's also more cost-effective, making the most of every computational cycle and dollar spent. </p><h2>Python performance and data storage</h2><p>Before diving into technical examples, let’s discuss data storage and why better Python performance matters. </p><h3>Data storage 101</h3><p>Data can be stored in two primary places: in memory (RAM - Random Access Memory) or on disk (your computer's hard drive or an SSD - Solid State Drive).</p><ol><li>In-Memory Storage (RAM):</li></ol><p>When we talk about in-memory storage, we refer to storing in the computer's RAM. This is the memory your computer uses to hold data being used or processed at any given moment. It's like the desk you work on, holding the papers you are reading or writing on.</p><ol><li>On-Disk Storage (Hard Drive or SSD):</li></ol><p>On-disk storage saves data on your computer's hard drive or an SSD. This is where data is stored for the long term, even when your computer is turned off. It's like a filing cabinet where you store documents that you don't need right now but will need later.</p><h3>Performance trade-offs</h3><p>The choice between in-memory and on-disk storage can significantly impact the application's performance and the efficiency of your processing tasks.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/686619dd1d8b4b3c371e44f6_684b7a6ea2926e7ec01f6856_68493c0f337eaa5754c18ea4_Table7.png\"></p></figure><p>‍</p><p>Understanding the trade-offs and implications of each storage type becomes extremely relevant in many common data engineering scenarios. &#160;We’ll take a look at a common one in the next section. </p><p>Many practitioners use Python libraries like Pandas and NumPy because their built-in functions make handling data a breeze, but it can lead to performance issues and ramp up costs. </p><p>One typical trap many early data engineers fall into is using Pandas for everything. While Pandas makes it easy to <a target=\"_blank\" href=\"https://dagster.io/glossary/data-wrangling\">wrangle</a> and analyze data, using it for simpler tasks or very large datasets can lead to slower execution and higher RAM usage. It’s like using a sledgehammer to crack a nut—it gets the job done, but it's overkill and not the most efficient way to tackle the task at hand.</p><p>Let’s dive deeper into Pandas’ performance issues because it’ll help illustrate how you can apply the same principles to other libraries. Pandas isn’t the most efficient choice for two reasons.</p><ol><li>Pandas' overhead</li></ol><p>Pandas is designed to simplify complex data operations, but this ease of use comes with a trade-off in performance, especially for simple tasks or operations. Even the latest version of Pandas can introduce additional processing steps, which could lead to slower execution compared to using basic Python data structures like lists or dictionaries.</p><p>For example, a simple operation like summing a series of numbers (the list in square brackets) could be executed faster with native Python compared to Pandas, mainly when dealing with a small dataset:</p><div><pre><code>import pandas as pd\n### Data as a Python list\ndata_list = [1, 2, 3, 4, 5]\n### Summing using native Python\nsum_native = sum(data_list)\n### Data as a Pandas Series\ndata_series = pd.Series(data_list)\n### Summing using Pandas\nsum_pandas = data_series.sum()</code></pre></div><p>Summing the series of numbers using native Python with the <code>sum()</code> function is straightforward. On the other hand, to perform the same operation using Pandas, you need to first convert the list to a Pandas Series and then use the <code>sum()</code> method of the Series object. This additional step of converting the list to a Series introduces extra overhead, which, while not significant for this small dataset, can add up when performing many such simple operations. </p><p>If you only need to perform a basic operation on a dataset, using a Pandas DataFrame might be overkill and could make your code harder to understand compared to using a simple Python list or dictionary.</p><ol><li>Memory consumption</li></ol><p>Pandas often loads the entire dataset into RAM for fast data access and manipulation. While this is beneficial for medium-sized datasets, it can become a problem when dealing with very large ones that exceed the available RAM. </p><p>In such scenarios, using Pandas can lead to RAM exhaustion, causing your program to crash or run extremely slowly.</p><p>One way to get around this is to use libraries designed for out-of-core or distributed computing:</p><ul><li>Dask: Dask is similar to Pandas but can handle larger-than-memory datasets by breaking them down into smaller chunks, processing them in parallel, and even distributing them across multiple machines.</li><li>Vaex: Vaex is another library that can handle large datasets efficiently by performing operations lazily and utilizing memory-mapped files.</li></ul><p>Another option is to use on-disk storage solutions, especially when dealing with massive datasets or when persistence is required:</p><ul><li>SQL Databases: Utilize SQL databases like <a target=\"_blank\" href=\"https://dagster.io/blog/skip-kafka-use-postgres-message-queue\">PostgreSQL</a> or SQLite to manage and query your data on-disk</li><li>NoSQL Databases: For unstructured or semi-structured data, <a target=\"_blank\" href=\"https://dagster.io/glossary/nosql-in-data-engineering\">NoSQL</a> databases like MongoDB can be a good choice</li><li>Apache Parquet: It's a columnar storage file format optimized for use with <a target=\"_blank\" href=\"https://dagster.io/glossary/big-data-processing\">big data processing</a> frameworks. It's efficient for both storage and processing, especially when working with complex nested data structures</li></ul><p>It’s probably most likely that you’ll use a hybrid approach: use on-disk storage for long-term data retention and in-memory processing for active data manipulation and analysis.</p><h2>Python types and specialized structures</h2><p>Selecting the right data types in Python is crucial for writing high-performance code, especially in applications where speed and RAM efficiency are essential. Python, being a dynamically-typed language, allows for flexibility in choosing data types, but this flexibility can lead to inefficiencies if not used judiciously.</p><h3>Types in the Python standard library</h3><p>Furthermore, the appropriate choice of data type can affect the algorithmic complexity and, consequently, the performance of the code. For instance, choosing a Python dictionary (a hash table) for frequent lookup operations is much faster than using a list, as dictionaries have average-case constant time complexity for lookups, whereas lists have linear time complexity.</p><p>More advanced concepts like the Python generator object can further help you improve code performance. Generator objects and a special type of iterable, like a list or a tuple, but are particularly memory-efficient when dealing with large datasets or streams of data.</p><h3>Looking to specialized structures</h3><p>One key consideration is choosing between standard Python data structures like lists and specialized structures like NumPy arrays. Python lists are versatile and easy to use but inefficient for numerical operations on large data sets. They can store different types of objects, which adds overhead in terms of RAM and processing. For instance, when a list contains objects of different types, Python must store type information for each element and perform type checking during runtime, which can slow down computation.</p><p>On the other hand, NumPy arrays, often used for numerical computing in Python, and help improve performance of operations on large files of homogeneous data. These arrays use contiguous blocks of memory, making access and manipulation of array elements more efficient. They also support vectorized operations (which cannot be done with a standard library), allowing for complex computations to be executed on entire arrays without the need for explicit loops in Python. This not only leads to more concise and readable code but also significantly enhances performance due to optimized, low-level C implementations for mathematical operations.</p><p>In summary, the thoughtful selection of data types is vital in Python for optimizing both speed and memory usage. While Python's flexibility and ease of use are advantageous, leveraging specialized data types like NumPy arrays for numerical operations and making smart choices between different native data structures can significantly improve the performance of Python code. This is especially true in data-intensive and computationally demanding applications, such as scientific computing, data analysis, and machine learning.</p><h3>Python code optimization and global variables</h3><p>Global variables in Python are those defined outside of a function and which can be accessed from any part of the program, as<a target=\"_blank\" href=\"https://dagster.io/blog/python-environment-variables\"> explored earlier in the guide</a>. However, their use often sparks debate regarding best practices in coding, especially concerning code optimization and maintainability.</p><p>From a performance optimization perspective, global variables can sometimes offer benefits. They can be used to cache values that are expensive to compute and are required by multiple functions, potentially reducing the need for redundant calculations. This can lead to performance improvements in certain scenarios.</p><p>Nevertheless, there are many scenarios where we should avoid global variables:</p><ul><li>It can lead to code that is hard to debug and maintain as global variables can be modified by any part of the program.</li><li>Using global variables can lead to issues with code scalability and readability. They make it harder to understand the interactions between different parts of the code, and more challenging to test or implement changes without unintended side effects.</li><li>From a design perspective, overusing global variables often indicates a lack of encapsulation, affecting code modularity and reusability.</li></ul><p>So, while global variables can be used for optimizing performance in specific cases, they should be used sparingly and judiciously. It's often better to consider alternative approaches, such as function arguments or class attributes, which can provide a cleaner code that is easier to test.</p><h2>Towards more efficient in-memory Python pipelines</h2><p>Let's now turn to some practical advice on how Python code can be optimized to efficiently process data in-memory. </p><h3>Vectorized data transformations</h3><p>Always opt for vectorized operations over traditional loops. Vectorized operations refer to performing operations on entire arrays or collections of data at once rather than iterating through each element individually. </p><p>In Python, the NumPy library is well-known for providing vectorized operations. Here, we create a NumPy array <code>data_array</code> with some initial values and then perform a vectorized multiplication operation on the entire array.</p><div><pre><code>import numpy as np\ndata_array = np.array([1, 2, 3, 4, 5])\ndata_array *= 10  # Vectorized multiplication operation\n### Now data_array is array([10, 20, 30, 40, 50])</code></pre></div><h3>Efficient data loading</h3><p>For datasets that can fit into available RAM, Pandas provides efficient tools for data manipulation:</p><div><pre><code>import pandas as pd\n### Load data into a Pandas DataFrame\ndata = pd.read_csv('manageable_dataset.csv')\n### Use vectorized operations for efficient data transformations\ndata['new_column'] = data['old_column'] * 10</code></pre></div><h4>Chunking</h4><p>When dealing with large datasets, however, it can be impractical to <a target=\"_blank\" href=\"https://dagster.io/glossary/data-loading\">load</a> them into RAM all at once. As we discussed earlier about storage and performance trade-offs, loading these into RAM can be very slow or even cause your program to crash.</p><p>Instead, data engineers often use techniques like streaming, chunking, or using databases that allow for processing data in smaller, manageable pieces. Pandas provides a method to read data in chunks:</p><div><pre><code>import pandas as pd\nchunk_size = 50000  # This determines the number of rows per chunk; adjust based on your system's RAM\ncolumn_sum = 0\n### Using the 'chunksize' parameter with 'read_csv' allows us to process the file in chunks\nfor chunk in pd.read_csv('large_dataset.csv', chunksize=chunk_size):\n    column_sum += chunk['some_column'].sum()\nprint(f'Sum of some_column: {column_sum}')</code></pre></div><p>In this example, the <code>large_dataset.csv</code> file is read and processed in chunks. The size of each chunk is defined by the <code>chunk_size</code> variable. The sum of the <code>some_column</code> column is computed chunk by chunk, and the results are aggregated to get the total sum.</p><h4>Lazy evaluation</h4><p>Lazy evaluation is a programming concept where the execution of expressions is delayed until the value of the expression is actually needed. Instead of immediately performing computations when you define them, they're \"stored\" or \"remembered\" by the system. Only when you specifically ask for a result (like calling a function), the actual work is done. Pandas does eager evaluation: when you run an operation, the result is computed immediately.</p><p>Libraries like Vaex or Polars in Python are designed for the efficient processing of large datasets by performing operations lazily:</p><div><pre><code>import polars as pl\n### Load the data using Polars (the data is not immediately loaded into RAM)\ndf = pl.read_csv('large_dataset.csv')\n### Compute the sum of a particular column (data is loaded and processed as needed)\ncolumn_sum = df.select(pl.col(\"some_column\").sum()).collect()[0][0]\nprint(f'Sum of some_column: {column_sum}')</code></pre></div><p>Here, the <code>read_csv</code> function in Polars is used to create a DataFrame representing the data in the CSV file, but the data isn't loaded into RAM until processing is triggered.</p><p>We define a computation (sum of <code>some_column</code>), and only when we call <code>collect()</code>, the actual computation is executed.</p><p>The result of <code>collect()</code> is another DataFrame, from which we extract the value of the sum.</p><h3>Data structures</h3><p>The right data structure (e.g., lists, dictionaries, sets) can drastically improve an operation's memory and computational efficiency.</p><p>Suppose you are working on a data engineering task where you need to check whether certain items exist in a dataset. Let's assume you have a list of user IDs, and you need to check if specific user IDs exist in this list.</p><p>Using a list for this task is straightforward, but it's not efficient because checking for existence in a list requires scanning through the list, which can be very slow if the list is long:</p><div><pre><code>### Assume user_ids is a long list of user IDs\nuser_ids = [1, 2, 3, 4, 5, ...]\n### Checking for existence in a list (inefficient)\nif 12345 in user_ids:\n    print(\"User ID found\")\nelse:\n    print(\"User ID not found\")</code></pre></div><p>A more efficient approach would be to use a set, which is designed for fast membership tests. Converting the list to a set allows for much quicker lookups:</p><div><pre><code>### Convert the list to a set for faster lookups\nuser_ids_set = set(user_ids)\n### Checking for existence in a set (efficient)\nif 12345 in user_ids_set:\n    print(\"User ID found\")\nelse:\n    print(\"User ID not found\")</code></pre></div><p>‍</p><h3>List comprehension and generator expressions</h3><p>List comprehension in Python offers a concise and efficient way to create lists, improving execution speed and code readability. Unlike traditional for-loops, list comprehensions are generally faster because they are optimized for the Python interpreter to execute a predictable pattern of accessing and processing list elements. This optimization leads to quicker list creation and manipulation.</p><p>Moreover, list comprehensions reduce the overhead of repeatedly calling an append method in a loop, as the entire list is constructed in a single, readable line. This not only makes the code more elegant but also allows it to run more efficiently by minimizing function calls and RAM usage. By handling list operations in a more streamlined fashion, Python's comprehensions can lead to performance gains, especially in scenarios involving large datasets or complex list-processing tasks.</p><p>We can run a simple example to demonstrate:</p><pre><code><span><span>### Using a standard for-loop</span><span>\n</span></span><span>squares_loop = []\n</span><span><span></span><span>for</span><span> number </span><span>in</span><span> </span><span>range</span><span>(</span><span>1</span><span>, </span><span>1000001</span><span>):\n</span></span><span><span>    squares_loop.append(number ** </span><span>2</span><span>)\n</span></span><span>\n</span><span><span></span><span>### Using list comprehension</span><span>\n</span></span><span><span>squares_list_comp = [number ** </span><span>2</span><span> </span><span>for</span><span> number </span><span>in</span><span> </span><span>range</span><span>(</span><span>1</span><span>, </span><span>1000001</span><span>)]\n</span></span><span></span></code></pre><p>The performance difference between a for-loop and a list comprehension might appear minimal, especially in simple operations like the one in the example. However, for more complex list processing tasks, especially those involving multiple operations within each iteration, the performance improvement can be more noticeable.</p><h4>Generator object and expressions</h4><p>Python generator expressions are a concise way to generate values on the fly, similar to list comprehensions, but for generating iterators.</p><p>They provide RAM efficiency, lazy evaluation (they only compute the next value when it's needed), and are most useful when working with large data sets where you want to process items one at a time, or when you only need a part of the generated sequence, thus avoiding the overhead of generating the complete list.</p><p>Generator expressions can be easily used with built-in functions like <code>sum()</code>, <code>max()</code>, <code>min()</code>, etc., which take iterables as inputs.</p><p>A simple example would be:</p><pre><code><span><span>gen_exp = (x * </span><span>2</span><span> </span><span>for</span><span> x </span><span>in</span><span> </span><span>range</span><span>(</span><span>5</span><span>))\n</span></span><span>\n</span><span><span></span><span>for</span><span> value </span><span>in</span><span> gen_exp:\n</span></span><span><span>    </span><span>print</span><span>(value)</span></span></code></pre><p>which will print the doubled values of 0 through 4, one at a time, without ever creating a full list in memory.</p><h3>In-memory vs. compute engines</h3><p>Performing computations in-memory can be more efficient for smaller tasks, but leveraging a compute engine becomes essential for data-intensive tasks.</p><p>Suppose you are tasked with <a target=\"_blank\" href=\"https://dagster.io/glossary/data-aggregation\">aggregating</a> a large dataset to compute statistics like mean, sum, and count per group.</p><p>For smaller datasets, you might use a library like Pandas to perform these computations in-memory.</p><div><pre><code>import pandas as pd\n### Assume small_dataset.csv is a manageable-sized file\ndata = pd.read_csv('small_dataset.csv')\n### Performing aggregation using Pandas\naggregated_data = data.groupby('group_column').agg({\n    'value_column': ['mean', 'sum', 'count']\n})\n### Save or use the aggregated data\naggregated_data.to_csv('aggregated_data.csv')</code></pre></div><p>For larger datasets or more complex operations, you might leverage a compute engine like Apache Spark, which can handle distributed data processing across multiple machines.</p><div><pre><code>from pyspark.sql import SparkSession\nfrom pyspark.sql import functions as F\n### Initialize a Spark session\nspark = SparkSession.builder.appName('AggregationApp').getOrCreate()\n### Load the large dataset\nlarge_data = spark.read.csv('large_dataset.csv', header=True, inferSchema=True)\n### Performing aggregation using Spark (compute engine)\naggregated_data = (\n    large_data.groupBy('group_column')\n    .agg(\n        F.mean('value_column').alias('mean'),\n        F.sum('value_column').alias('sum'),\n        F.count('value_column').alias('count')\n    )\n)\n### Save or use the aggregated data\naggregated_data.write.csv('aggregated_data.csv', header=True)</code></pre></div><p>Beyond standalone compute engines like Apache Spark, databases and data warehouses also act as powerful compute engines. Modern data warehouses, such as Snowflake, BigQuery, or Redshift, are designed to run complex analytical queries directly on large datasets.</p><p>Instead of pulling data out into a separate compute environment, you can use the computational capabilities of these systems directly, which reduces the need to transfer data and have additional processing layers.</p><h3>In conclusion: optimizing data pipeline Python code</h3><p>At its core, data orchestration is about coordinating various data operations into cohesive workflows. Processes can become agonizingly slow or falter under the weight of poorly optimized Python code, crippling analytics and hampering critical decision-making.</p><p>As you progress in your programming career, aim to go beyond building pipelines that work and architect efficient and robust data solutions optimized for performance from day one.</p></div>"
