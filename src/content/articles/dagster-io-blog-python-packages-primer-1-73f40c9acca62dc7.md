Let’s dive in!</p><h2>Table of Contents</h2><ul><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">What are Python packages?</a></li><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">Starting with modules</a></li><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">From modules to packages</a></li><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">What is __init__.py?</a></li><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">How do you manage packages in Python?</a></li><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">How does pip work?</a></li><li><a target=\"_blank\" href=\"https://dagster.io/blog/python-packages-primer-1#\">What are relative vs. absolute imports?</a></li></ul><h2>What are Python packages?</h2><p>We put our Python code into packages as it makes it easy to share and reuse code in the Python community. A package is simply a collection of files and directories that include the code, documentation, and other necessary files that we will examine later.</p><p>We use Python packages instead of script files and Jupyter notebooks when we want to reuse complex code. With script files, code can become cluttered and difficult to maintain, while notebooks are often used for exploratory work but are not easily reusable.</p><p>You can think of a Python package as a standalone “project”. A project can contain multiple modules, each of which contains a specific set of related functions and variables. Hence, this makes it easier for you to embed tools from “projects” you need within your own code.</p><h2>Starting with modules</h2><p><strong>Modules</strong> are the building blocks of Python packages. A module is a single Python file that contains definitions and statements. They provide a way to structure your code into logical units and reuse code across multiple projects.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/68670666696eb97ed688144a_68483b6dbdb47be9fb356c78_image.png\"></p></figure><p>‍</p><p>To use a module in your code, you use the import statement. For example, if you have a module called <code>mymodule.py</code> , you can use its functions and variables in your code with the following import statement:</p><pre><code><span><span>import</span><span> mymodule</span></span></code></pre><p>Once you have imported a module, you can access its functions and variables using the dot (<code>.</code>) notation. For example, if the mymodule.py file has a function called <code>greet</code>, you can use it in your code as follows:</p><pre><code><span><span>import</span><span> mymodule\n</span></span><span><span>mymodule.greet(</span><span>\"John\"</span><span>)\n</span></span><span></span></code></pre><p>Let's create our own example module to illustrate the concept. Create a file called <code>examplemodule.py</code> and add the following code to it:</p><pre><code><span><span>def</span><span> </span><span>greet</span><span>(</span><span>name</span><span>):</span><span>\n</span></span><span><span>    </span><span>print</span><span>(</span><span>\"Hello, \"</span><span> + name + </span><span>\"!\"</span><span>)\n</span></span><span><span></span><span>def</span><span> </span><span>add</span><span>(</span><span>a, b</span><span>):</span><span>\n</span></span><span><span>    </span><span>return</span><span> a + b</span></span></code></pre><p>Here, we defined two functions, <code>greet</code> and <code>add</code> , in the <code>examplemodule.py</code> file. These functions can now be imported and used in other parts of your code.</p><h2>From modules to packages</h2><p>As your code grows, it can become difficult to manage and maintain all the code in a single module. <strong>Packages</strong> provide a way to organize and split your code into multiple modules, while still keeping everything organized and accessible.</p><p>To create a package, simply create a directory and place one or more modules in it. The directory should contain a special file called <code>__init__.py</code> , which tells Python that this directory is a package and should be treated as such. The <code>__init__.py</code> file can be left empty or it can contain code that will be executed when the package is imported. We explain <code>__init__.py</code> files in more detail below.</p><p>Let's refactor the example module from the previous section to be a package. Create a directory called <code>examplepackage</code> and move the <code>examplemodule.py</code> file into it. Then, create a file called <code>__init__.py</code> in the <code>examplepackage</code> directory.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/68670666696eb97ed6881447_68483b6dbdb47be9fb356c75_image.png\"></p></figure><p>‍</p><p>Your file structure should now look like this:</p><pre><code><span><span>examplepackage/\n</span></span><span>    __init__.py\n</span><span>    examplemodule.py</span></code></pre><p>You can now import the functions from the <strong><code>examplemodule.py</code></strong> file in your code as follows: &#160; &#160; &#160; &#160; </p><pre><code><span><span>import</span><span> examplepackage.examplemodule\n</span></span><span>\n</span><span><span>examplepackage.examplemodule.greet(</span><span>\"John\"</span><span>)\n</span></span><span><span>examplepackage.examplemodule.add(</span><span>1</span><span>, </span><span>2</span><span>)\n</span></span><span></span></code></pre><p>In this example, we have refactored the <code>examplemodule.py</code> file into a package called <code>examplepackage</code>. The functions from the <code>examplemodule.py</code> file can now be imported and used in your code as before, but with the added benefits of organization and modularity provided by packages.</p><h2>What is __init__.py?</h2><p><code>__init__.py</code> is a special file in Python packages that serves as an entry point for the package. It is executed when the package is imported, and its code can be used to initialize the package or set up any necessary components. The file is optional, but is often used to define the public interface of the package, making it easier for other developers to understand and use the package.</p><p>In previous versions of Python, <code>__init__.py</code> was required for a directory to be recognized as a package. However, as of Python 3.3, <code>__init__.py</code> is optional due to the introduction of PEP 420, which allows for packages to be defined without an <code>__init__.py</code> file.</p><p>Here's an example of how you could use <code>__init__.py</code> in a package:</p><pre><code><span><span>### examplepackage/__init__.py</span><span>\n</span></span><span>\n</span><span><span></span><span>from</span><span> .examplemodule </span><span>import</span><span> greet, add\n</span></span><span>__all__ = [\n</span><span><span>    </span><span>'greet'</span><span>,\n</span></span><span><span>    </span><span>'add'</span><span>,\n</span></span><span>]\n</span><span></span></code></pre><p>In this example, the <strong><code>__init__.py</code></strong> file imports the <strong><code>greet</code></strong> and <strong><code>add</code></strong> functions from the <strong><code>examplemodule.py</code></strong> file and makes them part of the public interface of the package. The <strong><code>__all__</code></strong> variable is used to define the public interface of the package, and makes it easier for other developers to understand and use the package.</p><p>With this setup, you can now import the <strong><code>greet</code></strong> and <strong><code>add</code></strong> functions from the <strong><code>examplepackage</code></strong> as follows:</p><pre><code><span><span>import</span><span> examplepackage\n</span></span><span><span>examplepackage.greet(</span><span>\"John\"</span><span>)\n</span></span><span><span>examplepackage.add(</span><span>1</span><span>, </span><span>2</span><span>)\n</span></span><span></span></code></pre><h2>How do you manage packages in Python?</h2><p>The most common way developers distribute their packages is by uploading them to a public repository called the <a target=\"_blank\" href=\"https://pypi.org/\">Python Package Index (PyPI)</a>. We use a system called <strong>pip</strong> which stands for \"Pip Installs Packages\". It is a command-line tool that allows users to install and manage packages from PyPI and other package indexes.</p><p>If you’ve used <code>pip install</code>, you have downloaded and installed a package through the Python Package Index (PyPI).</p><p>Package management systems like pip make it easy to install, update, and remove packages, as well as manage dependencies (packages that are required for other packages to function properly) in a project.</p><h2>How does pip work?</h2><p><code>pip install</code> is the command we use to download and install different packages from a library called PyPI or even from your own computer. When you run this command, it will check if the package is available on PyPI and if so, it will download and install it on your computer. In addition, it will check on - and if needed install - all the dependencies listed in the package metadata. Finally, pip will keep track of all the packages you install to help you upgrade or uninstall them later.</p><p>By default, <code>pip install</code> installs the latest version of the package, but you can choose to install a specific version if you need to by using <code>pip install &lt;PACKAGE&gt;==&lt;VERSION&gt;</code>, so for example you might use <code>pip install numpy==1.23.5</code>. This can be helpful if you're having trouble with your code and need to use a specific version of a package.</p><p>Have you ever noticed that when you use <code>pip install</code> to add a feature to your Python code, the name you use to install it is different from the name you use when you import it? This happens because there are two types of names:- the <em>distribution name</em>, which is the name you use to install the package using <code>pip install</code>- the <em>package name</em>, which is the name you use when you import the package in your code.</p><p>The distribution name is unique and guaranteed to be different from other package names by PyPI, the library where you get your packages from. On the other hand, the package name is chosen by the person who created the package, so it may not be unique.</p><p>This is why you might install a package called \"<em>dagster-dbt</em>\" using <code>pip install</code>, but import it in your code using the name \"<em>dagster_dbt</em>\". This is also why you might install a package called \"<em>scikit-learn</em>\" using <code>pip install</code>, but import it in your code using the name \"<em>sklearn</em>\".</p><h2>What are relative vs. absolute imports?</h2><p>When writing a package, there may be times when we want to use relative imports. <a target=\"_blank\" href=\"https://docs.python.org/3/reference/import.html#package-relative-imports\">Relative imports</a> consist of either explicit or implicit imports, but you really only need to know about explicit relative imports as implicit relative imports are not supported in Python 3.</p><p>Relative imports allow you to import modules relative to the current module. They use the keyword \"from\" followed by the name of the current package and the name of the module or package being imported. For example, if you have a package named <strong><code>examplepackage</code></strong> with two modules, <strong><code>module1.py</code></strong> and <strong><code>module2.py</code></strong>, you can import the code from <strong><code>module1.py</code></strong> into <strong><code>module2.py</code></strong> using a relative import as follows:&#160; &#160; &#160; &#160; </p><pre><code><span><span>### examplepackage/module2.py</span><span>\n</span></span><span>\n</span><span><span></span><span>from</span><span> .module1 </span><span>import</span><span> greeting\n</span></span><span><span></span><span>def</span><span> </span><span>greet</span><span>(</span><span>name</span><span>):</span><span>\n</span></span><span><span>    </span><span>print</span><span>(greeting + </span><span>\" \"</span><span> + name)\n</span></span><span></span></code></pre><p>Here, the relative import <strong><code>from .module1 import greeting</code></strong> is used to import the <strong><code>greeting</code></strong> variable from the <strong><code>module1.py</code></strong> file into the <strong><code>module2.py</code></strong> file. The <strong><code>.</code></strong> before <strong><code>module1</code></strong> indicates that the import should be relative to the current module.</p><p><strong>Absolute imports</strong> allow you to import modules using their full name, regardless of their location relative to the current module. They use the the full path of the module or package being imported. For example, you could use an absolute import to access the <strong><code>greeting</code></strong> variable from the <strong><code>module1.py</code></strong> file into the <strong><code>module2.py</code></strong> file as follows:</p><pre><code><span><span>### examplepackage/module2.py</span><span>\n</span></span><span>\n</span><span><span></span><span>from</span><span> examplepackage.module1 </span><span>import</span><span> greeting\n</span></span><span><span></span><span>def</span><span> </span><span>greet</span><span>(</span><span>name</span><span>):</span><span>\n</span></span><span><span>    </span><span>print</span><span>(greeting + </span><span>\" \"</span><span> + name)\n</span></span><span></span></code></pre><p>Here, the absolute import <strong><code>from examplepackage.module1 import greeting</code></strong> is used to import the greeting variable from the <strong><code>module1.py</code></strong> file into the <strong><code>module2.py</code></strong> file. The full name of the module, <strong><code>examplepackage.module1</code></strong>, is used to specify the location of the module.</p><p>In Python 3, relative imports must be <strong><em>explicit</em></strong> and the <strong><em>absolute</em></strong> imports are the default behavior.</p><p>‍</p><h3>Up next…</h3><p>We hope this blog post has provided a useful introduction to Python packages and how to manage dependencies effectively.
