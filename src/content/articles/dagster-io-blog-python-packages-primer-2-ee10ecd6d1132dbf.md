Keeping track of dependencies can be a challenge, but there are tools to help you manage them effectively.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/68670667d8586fe3ebe43909_681399f654933b29e12fbd1b_67eabbd37addc12b456af4c7_PyPI_logo.svg\"></p></figure><p>One of these tools is the <a target=\"_blank\" href=\"https://pypi.org/\"><strong>Python Package Index</strong></a> (PyPI), which is a central repository of open-source Python packages. You can use PyPI to search for packages that you can include in your project and to make your own packages available to others.</p><p>In the following sections, we'll look at two different ways to manage dependencies in your Python projects: the old way using <strong><code>setup.py</code></strong> , and the new way using <strong><code>pyproject.toml</code></strong>.</p><p>‍</p><h2>Managing Dependencies the Old Way: <strong><code>setup.py</code></strong></h2><p>Before the introduction of <strong><code>pyproject.toml</code></strong> , the recommended way was to use a <strong><code>setup.py</code></strong> file to manage dependencies in Python projects.</p><p><strong><code>setup.py</code></strong> is a file that you include in the root of your project, which contains information about your package and its dependencies. The file is used by <strong>pip</strong>, the package installer for Python, to install your package and its dependencies.</p><p>Here is an example of a <strong><code>setup.py</code></strong> file:</p><pre><code><span><span>from</span><span> setuptools </span><span>import</span><span> setup, find_packages\n</span></span><span>\n</span><span>setup(\n</span><span><span>    name=</span><span>'your-package-name'</span><span>,\n</span></span><span><span>    version=</span><span>'0.0.1'</span><span>,\n</span></span><span><span>    description=</span><span>'A brief description of your package'</span><span>,\n</span></span><span><span>    author=</span><span>'Your Name'</span><span>,\n</span></span><span><span>    author_email=</span><span>'your.email@example.com'</span><span>,\n</span></span><span>    packages=find_packages(),\n</span><span>    install_requires=[\n</span><span><span>        </span><span>'dependency1'</span><span>,\n</span></span><span><span>        </span><span>'dependency2'</span><span>,\n</span></span><span>    ],\n</span><span>)\n</span><span></span></code></pre><ul><li>The <strong><code>name</code></strong> and <strong><code>version</code></strong> are required fields that specify the name and version of your package.</li><li>The <strong><code>description</code></strong> field provides a brief description of your package.</li><li>The <strong><code>author</code></strong> and <strong><code>author_email</code></strong> fields specify the name and email address of the person responsible for the package.The <strong><code>packages</code></strong> field specifies the packages that are included in your project. The <strong><code>find_packages()</code></strong> function is used to automatically find all packages in your project.</li><li>The <strong><code>install_requires</code></strong> field is a list of dependencies that your package needs in order to run correctly. In this example, the package depends on two other packages, dependency1 and dependency2.</li></ul><p>To install the dependencies of your package, you can run the following command:</p><pre><code><span><span>pip install -e .</span></span></code></pre><p>The <strong><code>-e</code></strong> option tells pip to perform an \"editable\" install, which allows you to make changes to your package without having to reinstall it. The <strong><code>.</code></strong> at the end of the command specifies the current directory, which is the root of your package.</p><p>It is important to note that when you run the above command, pip will install the dependencies in the <strong>global</strong> environment which can create issues when you are working on multiple projects. This is addressed by <strong>virtual environments</strong>, which is covered later in this blog post.</p><h2>Managing Dependencies the New Way: <strong><code>pyproject.toml</code></strong></h2><p><strong><code>pyproject.toml</code></strong> is a new file format introduced to replace setup.py for managing dependencies in Python projects. It was introduced as part of PEP 518 and PEP 621.</p><p>It’s a configuration file that is used by pip to install your package and its dependencies. It has a simpler format compared to <strong><code>setup.py</code></strong> and is easier to read and maintain.</p><p>Here is an example of a pyproject.toml file:</p><pre><code><span><span>[project]\n</span></span><span><span>name = </span><span>\"your-package-name\"</span><span>\n</span></span><span><span>version = </span><span>\"0.0.1\"</span><span>\n</span></span><span><span>description = </span><span>\"A brief description of your package\"</span><span>\n</span></span><span><span>authors = [</span><span>\"Your Name &lt;your.email@example.com&gt;\"</span><span>]\n</span></span><span>\n</span><span>[project.dependencies]\n</span><span><span>dependency1 = </span><span>\"^1.0\"</span><span>\n</span></span><span><span>dependency2 = </span><span>\"^2.0\"</span><span>\n</span></span><span></span></code></pre><ul><li>The <strong><code>name</code></strong> and <strong><code>version</code></strong> fields are required, and specify the name and version of your package.</li><li>The <strong><code>description</code></strong> field provides a brief description of your package.</li><li>The <strong><code>authors</code></strong> field specifies the name and email address of the person responsible for the package.</li><li>The <strong><code>dependencies</code></strong> section specifies the dependencies that your package needs in order to run correctly. In this example, the package depends on two other packages, <strong><code>dependency1</code></strong> and <strong><code>dependency2</code></strong>.</li></ul><p>Like we discussed above, you can run the following command to perform an editable install:</p><pre><code><span><span>pip install -e .</span></span></code></pre><h2>Installing “extras”</h2><p>Let’s talk a bit about what happens when a package has optional features that require additional dependencies called \"extras\".</p><p>If you are using the <strong><code>setup.py</code></strong> file to manage your dependencies, you can specify the extras by including them in the <strong><code>extras_require</code></strong> argument of the <strong><code>setup()</code></strong> function. For example:</p><pre><code><span><span>setup(\n</span></span><span>    ...\n</span><span>    extras_require={\n</span><span><span>        </span><span>'extra_feature'</span><span>: [</span><span>'dependency3'</span><span>, </span><span>'dependency4'</span><span>]\n</span></span><span>    }\n</span><span>    ...\n</span><span>)\n</span><span></span></code></pre><p>To install the extra dependencies, you would run the following command:</p><pre><code><span><span>pip install -e .[extra_feature]</span></span></code></pre><p>If you are using the <strong><code>pyproject.toml</code></strong> file, you can specify the extras in the <strong><code>[project.extras]</code></strong> section of the file. For example:</p><pre><code><span><span>[project.extras]\n</span></span><span><span>extra_feature = [</span><span>\"dependency3\"</span><span>, </span><span>\"dependency4\"</span><span>]\n</span></span><span></span></code></pre><p>You can use the same command to install the extra dependencies as above:</p><pre><code><span><span>pip install -e .[extra_feature]</span></span></code></pre><p>As mentioned earlier, the <strong><code>-e</code></strong> flag stands for \"editable\" and it installs the package in \"developer mode\". You’ll use this if you want to test any changes before publishing a new version.</p><p>The <strong><code>-e .[dev]</code></strong> flag is similar to the <strong><code>-e</code></strong> flag, but it also specifies that the package should be installed with the \"dev\" extras. Any additional packages or dependencies that are specified as \"dev\" in the package's <strong><code>setup.py</code></strong> file will also be installed. This is useful for installing development-specific dependencies that are not needed for production use.</p><h4>Alternative Python Dependency Management Tools</h4><p>Aside from pip, there are alternative tools available for managing dependencies in Python projects. One such tool is <a target=\"_blank\" href=\"https://python-poetry.org/\"><strong>Poetry</strong></a>.</p><p>Poetry is a packaging and dependency management tool for Python projects. Poetry is designed to be more user-friendly than pip, with features like version constraint resolution and automatic virtual environment management.</p><p>One of the main advantages of using Poetry is its simplicity and ease of use. Poetry automatically manages your project's virtual environment, ensuring that each project has its own isolated environment with its dependencies. This reduces the risk of version conflicts between different projects. Additionally, Poetry provides a simple, concise syntax for specifying dependencies and version constraints in your <strong><code>pyproject.toml</code></strong> file.</p><p>However, there are also some disadvantages to using Poetry. For one, it is not as widely used as pip, and may not be as well-supported in the wider Python community. Some developers may prefer the more flexible and customizable approach offered by pip.</p><h2>Virtual environments (a.k.a. 'venvs')</h2><p><strong>Virtual environments</strong> in Python provide a solution to the problem of dependency conflicts. By default, all Python packages are installed into a single global namespace, which can cause compatibility issues between different projects on a single machine and make it difficult to resolve conflicts.</p><p>A virtual environment creates isolated Python environments to allow for different versions of Python and libraries to be used in separate projects, without interfering with each other.</p><p>This means that you can have multiple virtual environments on the same computer, each with its own set of packages, without them interfering with each other.</p><figure><p><img alt=\"\" src=\"https://cdn.prod.website-files.com/681399f654933b29e12fb8e4/68670667d8586fe3ebe4390c_68484413c250be6fe1b238e9_image.png\"></p></figure><p>To create a new virtual environment, you can use the <strong><code>python -m venv</code></strong> command. For example, to create an environment named \"myenv\", you would run:</p><pre><code><span><span>python -m venv myenv</span></span></code></pre><h4>Note: using <strong><code>python</code></strong> or <strong><code>python3</code></strong></h4><p>If you have multiple versions of Python installed, or if you’re working with legacy code that uses Python 2, you will need to use the command that explicitly refers to the Python version you’re using.</p><p>For example, if you’ve newly installed Python 3 on your computer, and thus you’re working in Python 3 by default, then you don’t need need to specify <strong><code>python3</code></strong> explicitly. You can use either <strong><code>python3</code></strong> or <strong><code>python</code></strong> as they both refer to Python 3.</p><p>But if you need to work with codebases in Python 2 but have Python 2 and 3 installed, using <strong><code>python</code></strong> will enable you to continue working without breaking any code.</p><p>The same logic applies for <strong><code>pip</code></strong> and <strong><code>pip3</code></strong> when you use pip to install packages.</p><p>To activate a virtual environment, you can use the <strong><code>source</code></strong> command followed by the path to the environment's <strong><code>activate</code></strong> script.</p><p>On Linux and macOS, you would run:</p><pre><code><span><span>source myenv/bin/activate</span></span></code></pre><p>On Windows, you would run:</p><pre><code><span><span>myenv\\Scripts\\activate</span></span></code></pre><p>When the environment is activated, any Python scripts or commands run will use the version of Python and libraries within the virtualenv, rather than the system's global version.</p><p>To deactivate a virtual environment, simply type <strong><code>deactivate</code></strong> in the terminal.</p><p>You will notice that when you activate a virtual environment, your command line prompt changes to indicate the active <em>venv</em>:</p><pre><code><span><span>myname@mymachine myProject % source myenv/bin/activate\n</span></span><span>(myenv) myname@mymachine myProject % deactivate\n</span><span>myname@mymachine myProject %</span></code></pre><p>It is best practice to create a specific virtual environment for each new project and to keep it in the same directory as the project. This makes it easy to manage and ensure that all dependencies are contained within the project folder.</p><p>If your virtual environment is in a Git repository, it is recommended to add it to your <strong><code>.gitignore</code></strong> file. This helps to keep your repository clean and ensures that each developer's virtual environment is isolated from the GitHub repository.</p><p>‍</p><h4>Up next…</h4><p>We hope this blog post has provided a useful introduction to effectively managing Python dependencies.
