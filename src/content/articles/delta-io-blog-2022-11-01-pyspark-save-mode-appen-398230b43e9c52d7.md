contentHtml: "<div>  <p>This post explains the <code>append</code> and <code>overwrite</code> PySpark <a target=\"_blank\" href=\"https://spark.apache.org/docs/latest/api/python/reference/pyspark.sql/api/pyspark.sql.DataFrameWriter.mode.html\">save mode</a> write operations and how they’re physically implemented in Delta tables. You’ll see how these operations are implemented differently for Parquet tables and learn why the Delta Lake implementation is superior. You’ll also learn about how the PySpark <code>errorifexists</code> and <code>ignore</code> save mode write operations are implemented with Delta Lake.</p>\n<p>Here’s the logical interpretation of the different <a target=\"_blank\" href=\"https://spark.apache.org/docs/latest/sql-data-sources-load-save-functions.html#save-modes\">save modes</a>:</p>\n<ul>\n<li><strong>Append</strong>: add additional data to an existing table</li>\n<li><strong>Overwrite</strong>: remove the existing data from the table and replace it with new data</li>\n<li><strong>Error</strong> (aka <code>errorifexists</code>): throw an error if the table exists and contains data</li>\n<li><strong>Ignore</strong>: don’t write if the table already exists, but don’t throw an error either</li>\n</ul>\n<p>The Delta Lake implementation of these different save modes allows for ACID transactions and a great developer experience.</p>\n<p>The limitations of Parquet tables make the developer experience less pleasant, especially for overwrite transactions. Let’s compare how the different write modes are implemented in Parquet and Delta Lake.</p>\n<p>All the code snippets covered in this post are in <a target=\"_blank\" href=\"https://github.com/MrPowers/delta-examples/blob/master/notebooks/pyspark/pyspark-append-overwrite.ipynb\">this notebook</a> if you’d like to reproduce these computations on your machine.</p>\n<h2 id=\"parquet-append-save-mode\">Parquet append save mode</h2>\n<p>Let’s start by showcasing how to create a DataFrame and add additional data with the <code>append</code> save mode.</p>\n<p>Here’s how to create a DataFrame with a row of data and write it out in the Parquet file format.</p>\n<pre><code><span><span>columns = [\"singer\", \"country\"]</span></span>\n<span><span>data1 = [(\"feid\", \"colombia\")]</span></span>\n<span><span>rdd1 = spark.sparkContext.parallelize(data1)</span></span>\n<span><span>df1 = rdd1.toDF(columns)</span></span>\n<span><span></span></span>\n<span><span>df1.repartition(1).write.format(\"parquet\").save(\"tmp/singers1\")</span></span></code></pre>\n<p>Take a look at the Parquet file written to disk.</p>\n<pre><code><span><span>tmp/singers1</span></span>\n<span><span>├── _SUCCESS</span></span>\n<span><span>└── part-00000-ffcc616b-4009-462a-a60d-9e2bd7130083-c000.snappy.parquet</span></span></code></pre>\n<p>We used <code>repartition(1)</code> so only one file is written and the intention of this example is clear. Here’s the code to create the DataFrame and overwrite the existing data.</p>\n<pre><code><span><span>data3 = [(\"rihanna\", \"barbados\")]</span></span>\n<span><span>rdd3 = spark.sparkContext.parallelize(data3)</span></span>\n<span><span>df3 = rdd3.toDF(columns)</span></span>\n<span><span></span></span>\n<span><span>df3.repartition(1).write.mode(\"overwrite\").format(\"parquet\").save(\"tmp/singers1\")</span></span></code></pre>\n<p>Here’s the content of the Parquet table after the overwrite operation:</p>\n<pre><code><span><span>+-------+--------+</span></span>\n<span><span>| singer| country|</span></span>\n<span><span>+-------+--------+</span></span>\n<span><span>|rihanna|barbados|</span></span>\n<span><span>+-------+--------+</span></span></code></pre>\n<p>Here are the new files on storage:</p>\n<pre><code><span><span>tmp/singers1</span></span>\n<span><span>├── _SUCCESS</span></span>\n<span><span>└── part-00000-63531918-401d-4983-8848-7b99fff39713-c000.snappy.parquet</span></span></code></pre>\n<p><img src=\"https://delta.io/_astro/image3.DKqd9O71_1FIbgj.webp\"></p>\n<p>When the save mode is set to <code>overwrite</code>, Parquet will write out the new files and delete all of the existing files. There are several downsides to this implementation:</p>\n<ul>\n<li>The old data is deleted, so there is no way to perform a rollback and undo a mistake if your storage format doesn’t support versioning or enable versioning. The changes are permanent.</li>\n<li>The Parquet table is in an unusable state for readers while the overwrite operation is being performed. For example, a concurrent reader may see a “mid-computation state”: file A gets deleted but file B still exists, which is not a valid table state.</li>\n<li>If the compute cluster performing the overwrite dies while the operation is being performed, your data lake is left in a “mid-computation state” and will likely be corrupted. The corruption type depends on how much the overwrite operation had completed when the error occurred.</li>\n</ul>\n<p>Let’s look at these same operations on a Delta table and see how they’re much more robust and user-friendly.</p>\n<h2 id=\"delta-lake-append-and-overwrite-save-modes\">Delta Lake append and overwrite save modes</h2>\n<p>Let’s perform the same operations with a Delta table with <code>df3</code>.</p>\n<pre><code><span><span>df3.repartition(1).write.mode(\"overwrite\").format(\"delta\").save(\"tmp/singers2\")</span></span></code></pre>\n<p>Here are the contents of the Delta files. It simply makes an entry in the transaction log to ignore the existing files (a logical delete). It doesn’t actually remove the files (a physical delete). Take a look at the following diagram to get some intuition about the three transaction log entries corresponding to the actions taken on this Delta Lake.</p>\n<p><img src=\"https://delta.io/_astro/image4.DW0MWd60_Z1CSiPO.webp\"></p>\n<p>The Delta Lake approach to overwriting data is almost always preferable!</p>\n<h2 id=\"why-delta-lake-is-safer\">Why Delta Lake is safer</h2>\n<p>A Delta Lake overwrite operation does not physically remove files from storage, so it can be undone. When you overwrite a Parquet table, the old files are physically removed from storage, so the operation can not be undone if your storage doesn’t support versioning or enable versioning. Performing an accidental overwrite on a Parquet table can still be a costly mistake even if you enable versioning on your storage.</p>\n<p>Delta Lake’s <a target=\"_blank\" href=\"https://github.com/delta-io/delta/blob/master/PROTOCOL.md\">design protocol</a> makes versioned data a built-in feature. Time travel and restoring to previous versions with the restore command are features that are easily allowed for by Delta Lake because versioned data is a core aspect of Delta Lake’s design. All of these features are extremely useful for data practitioners. Parquet tables don’t offer these features, so Delta Lake is almost always better.</p>\n<p>For completeness, let’s look at the other PySpark save modes and how they’re implemented with Delta Lake.</p>\n<h2 id=\"pyspark-error--errorifexists-save-modes-in-delta-lake\">PySpark error / errorifexists save modes in Delta Lake</h2>\n<p>The default PySpark save mode is error, also known as <code>errorifexists</code>. This will create a Delta table if one doesn’t exist already and error out if the Delta table already exists.</p>\n<p>Let’s use <code>df1</code> to create another Delta table and explicitly set the save mode to <code>error</code>.</p>\n<pre><code><span><span>df1.repartition(1).write.mode(\"error\").format(\"delta\").save(\"tmp/singers3\")</span></span></code></pre>\n<p>That works since <code>tmp/singers3</code> didn’t exist.</p>\n<p>Now let’s see what happens when we write <code>df2</code> to <code>tmp/singers3</code>, a Delta table that now exists.</p>\n<p>That operation errors out with the following message:</p>\n<pre><code><span><span>AnalysisException: Cannot write to already existent path file:/Users/…/tmp/singers3 without setting OVERWRITE = 'true'.</span></span></code></pre>\n<p>We’ve confirmed that PySpark will error when writing to an existing Delta table if the save mode is set to <code>error</code>.</p>\n<h2 id=\"pyspark-ignore-save-mode-with-delta-lake\">PySpark ignore save mode with Delta Lake</h2>\n<p>The PySpark <code>ignore</code> save mode will create the Delta table if it doesn’t exist yet. If the Delta table exists, the PySpark ignore save mode won’t do anything (it won’t write data or error out).</p>\n<p>Let’s write out the contents of <code>df1</code> to a new Delta table with save mode set to <code>ignore</code>.</p>\n<pre><code><span><span>df1.repartition(1).write.mode(\"ignore\").format(\"delta\").save(\"tmp/singers4\")</span></span></code></pre>\n<p>Here are the contents of the Delta table:</p>\n<pre><code><span><span>spark.read.format(\"delta\").load(\"tmp/singers4\").show()</span></span>\n<span><span></span></span>\n<span><span>+------+--------+</span></span>\n<span><span>|singer| country|</span></span>\n<span><span>+------+--------+</span></span>\n<span><span>|  feid|colombia|</span></span>\n<span><span>+------+--------+</span></span></code></pre>\n<p>Let’s append <code>df2</code> to this Delta table. Recall that <code>df2</code> contains the following data:</p>\n<pre><code><span><span>df2.show()</span></span>\n<span><span></span></span>\n<span><span>+------+-------+</span></span>\n<span><span>|singer|country|</span></span>\n<span><span>+------+-------+</span></span>\n<span><span>|annita| brasil|</span></span>\n<span><span>+------+-------+</span></span></code></pre>\n<p>Now let’s write out the contents of <code>df2</code> to a new Delta table with save mode set to <code>ignore</code>:</p>\n<pre><code><span><span>df2.repartition(1).write.mode(\"ignore\").format(\"delta\").save(\"tmp/singers4\")</span></span></code></pre>\n<p>Here are the contents of the Delta table after the write with save mode set to <code>ignore</code>:</p>\n<pre><code><span><span>+------+--------+</span></span>\n<span><span>|singer| country|</span></span>\n<span><span>+------+--------+</span></span>\n<span><span>|  feid|colombia|</span></span>\n<span><span>+------+--------+</span></span></code></pre>\n<p>When the save mode is set to <code>ignore</code>, the data in <code>df2</code> is not appended and an error is not thrown.</p>\n<p>Here’s the entry that’s made to the transaction log for the second write operation with save mode set to <code>ignore</code>:</p>\n<pre><code><span><span>{</span></span>\n<span><span>   \"commitInfo\":{</span></span>\n<span><span>      \"timestamp\":1664801261318,</span></span>\n<span><span>      \"operation\":\"WRITE\",</span></span>\n<span><span>      \"operationParameters\":{</span></span>\n<span><span>         \"mode\":\"Ignore\",</span></span>\n<span><span>         \"partitionBy\":\"[]\"</span></span>\n<span><span>      },</span></span>\n<span><span>      \"readVersion\":0,</span></span>\n<span><span>      \"isolationLevel\":\"SnapshotIsolation\",</span></span>\n<span><span>      \"isBlindAppend\":true,</span></span>\n<span><span>      \"operationMetrics\":{</span></span>\n<span><span></span></span>\n<span><span></span></span>\n<span><span>      },</span></span>\n<span><span>      \"engineInfo\":\"Apache-Spark/3.3.0 Delta-Lake/2.1.0\",</span></span>\n<span><span>      \"txnId\":\"dcb6992b-24cb-4f3e-bcd3-203837c7986e\"</span></span>\n<span><span>   }</span></span>\n<span><span>}</span></span></code></pre>\n<p>This transaction log entry doesn’t add or remove files. It’s a no-op.</p>\n<h2 id=\"conclusion\">Conclusion</h2>\n<p>PySpark’s save operations are implemented differently in Parquet tables and Delta Lake. In particular, Parquet overwrite operations physically delete files from storage, whereas Delta Lake overwrite operations only tombstone files in the transaction log.</p>\n<p>Delta Lake supports versioned data and time travel. It only physically removes files from disk when you run the <code>vacuum</code> command to remove unneeded old files to save your storage cost.</p>\n<p>PySpark operations on Parquet tables can be quite dangerous. Suppose you’d like to append a small DataFrame to an existing dataset and accidentally run <code>df.write.mode(\"overwrite\").format(\"parquet\").save(\"some/lake\")</code> instead of <code>df.write.mode(\"append\").format(\"parquet\").save(\"some/lake\")</code>. That relatively small mistake causes you to delete all your existing data. You’ll only be able to recover the data if it’s been backed up, but that could be a huge hassle as well.</p>\n<p>Delta Lake provides a much better user experience because you can easily undo an accidental overwrite command by <a target=\"_blank\" href=\"https://delta.io/blog/2022-10-03-rollback-delta-lake-restore/\">restoring to an earlier version of your Delta Lake</a>. Versioned data makes life a lot easier for data practitioners.</p>\n<p>It’s good to build up a basic intuition on how PySpark write operations are implemented in Delta Lake under the hood. Understanding how Delta Lake works at a high level makes it easier for you to optimize your lake and build better data pipelines.</p>  </div>"
