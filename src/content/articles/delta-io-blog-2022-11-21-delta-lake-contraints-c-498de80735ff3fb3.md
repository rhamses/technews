contentHtml: "<div>  <p>This post shows you how to add constraints to your Delta Lake that prevent bad data from getting added to your Delta table.</p>\n<p>Delta Lake allows you to append any data with matching data types to your Delta tables by default. For example, you can append any integer value to a column with an integer type. To limit the types of integers that can be appended to a certain column, you can add a constraint.</p>\n<p>For example, suppose you have a Delta table with an <code>age</code> column. You may want to add a constraint to the Delta table that prevents negative values from being added to the <code>age</code> column because they don’t make much sense.</p>\n<p>Let’s create a Delta table, add a constraint, and then see how it prevents us from appending bad data.</p>\n<p>All the code covered in this post is in <a target=\"_blank\" href=\"https://github.com/MrPowers/delta-examples/blob/master/notebooks/pyspark/constraints.ipynb\">this notebook</a> if you want to follow along.</p>\n<h2 id=\"delta-lake-check-constraint\">Delta Lake Check Constraint</h2>\n<p><a target=\"_blank\" href=\"https://delta.io/blog/2022-10-25-create-delta-lake-tables/\">Create a Delta table</a> with <code>age</code> and <code>word</code> columns and a couple of rows of data.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (1, \"foo\"),</span></span>\n<span><span>        (2, \"bar\"),</span></span>\n<span><span>    ],</span></span>\n<span><span>    [\"age\", \"word\"],</span></span>\n<span><span>)</span></span>\n<span><span></span></span>\n<span><span>df.write.format(\"delta\").saveAsTable(\"random1\")</span></span></code></pre>\n<p>Add a constraint that prevents negative values from being added to the <code>age</code> column.</p>\n<pre><code><span><span>spark.sql(\"ALTER TABLE default.random1 ADD CONSTRAINT ageIsPositive CHECK (age &gt;= 0)\")</span></span></code></pre>\n<p>Run <code>SHOW TBLPROPERTIES</code> to confirm that the constraint was added.</p>\n<pre><code><span><span>spark.sql(\"SHOW TBLPROPERTIES random1\").show(truncate=False)</span></span>\n<span><span></span></span>\n<span><span>+-------------------------------+--------+</span></span>\n<span><span>|key                            |value   |</span></span>\n<span><span>+-------------------------------+--------+</span></span>\n<span><span>|delta.constraints.ageispositive|age &gt;= 0|</span></span>\n<span><span>|delta.minReaderVersion         |1       |</span></span>\n<span><span>|delta.minWriterVersion         |3       |</span></span>\n<span><span>+-------------------------------+--------+</span></span></code></pre>\n<p>Now create a DataFrame with one row that has a negative age and one row that has a positive age. Try to append this DataFrame to the Delta table.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (-3, \"red\"),</span></span>\n<span><span>        (4, \"blue\"),</span></span>\n<span><span>    ],</span></span>\n<span><span>    [\"age\", \"word\"],</span></span>\n<span><span>)</span></span>\n<span><span></span></span>\n<span><span>df.write.format(\"delta\").mode(\"append\").saveAsTable(\"random1\")</span></span></code></pre>\n<p>Delta Lake won’t let you append this data to the Delta table because of the constraint. Here’s the error message:</p>\n<pre><code><span><span>org.apache.spark.sql.delta.schema.DeltaInvariantViolationException:</span></span>\n<span><span>CHECK constraint ageispositive (age &gt;= 0) violated by row with values:</span></span>\n<span><span> - age : -3</span></span></code></pre>\n<p>Read in the contents of the <code>random1</code> table and verify that no additional data was appended.</p>\n<pre><code><span><span>spark.table(\"random1\").show()</span></span>\n<span><span></span></span>\n<span><span>+---+----+</span></span>\n<span><span>|age|word|</span></span>\n<span><span>+---+----+</span></span>\n<span><span>|  1| foo|</span></span>\n<span><span>|  2| bar|</span></span>\n<span><span>+---+----+</span></span></code></pre>\n<p>The Delta table rejected the append operation because the DataFrame contains a row with a negative age, which fails the constraint. Notice that none of the data was appended. If there are any values that don’t satisfy the constraint, then none of the values are appended. Delta Lake supports ACID guarantees which means either all the data will be appended or none of it will be appended. These guarantees are critical in production data workloads.</p>\n<p>You’d have to filter out the values that don’t satisfy the constraint before appending if you’d like to add this data to the Delta table.</p>\n<pre><code><span><span>df.filter(F.col(\"age\") &gt;= 0).write.format(\"delta\").mode(\"append\").saveAsTable(\"random1\")</span></span>\n<span><span></span></span>\n<span><span>spark.table(\"random1\").show()</span></span>\n<span><span></span></span>\n<span><span>+---+----+</span></span>\n<span><span>|age|word|</span></span>\n<span><span>+---+----+</span></span>\n<span><span>|  4|blue|</span></span>\n<span><span>|  1| foo|</span></span>\n<span><span>|  2| bar|</span></span>\n<span><span>+---+----+</span></span></code></pre>\n<p>Let’s look at another type of constraint that’s often useful to add to your Delta tables.</p>\n<h2 id=\"delta-lake-not-null-constraint\">Delta Lake NOT NULL Constraint</h2>\n<p>You can add a <code>NOT NULL</code> constraint to Delta table columns to prevent null data from being appended. This constraint is often desirable as you’ll often have columns in your Delta table that you don’t want to contain any <code>NULL</code> data.</p>\n<p>Create a Delta table called <code>letters</code> with <code>letter1</code> and <code>letter2</code> columns.</p>\n<pre><code><span><span>spark.sql(\"\"\"</span></span>\n<span><span>CREATE TABLE default.letters (</span></span>\n<span><span>    letter1 STRING,</span></span>\n<span><span>    letter2 STRING NOT NULL</span></span>\n<span><span>  ) USING DELTA;</span></span>\n<span><span>\"\"\")</span></span></code></pre>\n<p>Append some data that doesn’t contain any NULL values and verify that good data can be appended.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (\"a\", \"aa\"),</span></span>\n<span><span>        (\"b\", \"bb\"),</span></span>\n<span><span>    ],</span></span>\n<span><span>    [\"letter1\", \"letter2\"],</span></span>\n<span><span>)</span></span>\n<span><span></span></span>\n<span><span>df.write.format(\"delta\").mode(\"append\").saveAsTable(\"letters\")</span></span>\n<span><span></span></span>\n<span><span>spark.table(\"letters\").show()</span></span>\n<span><span></span></span>\n<span><span>+-------+-------+</span></span>\n<span><span>|letter1|letter2|</span></span>\n<span><span>+-------+-------+</span></span>\n<span><span>|      b|     bb|</span></span>\n<span><span>|      a|     aa|</span></span>\n<span><span>+-------+-------+</span></span></code></pre>\n<p>Try to append some data that contains <code>NULL</code> in the <code>letter2</code> column and observe the error message.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (\"c\", None),</span></span>\n<span><span>        (\"d\", \"dd\"),</span></span>\n<span><span>    ],</span></span>\n<span><span>    [\"letter1\", \"letter2\"],</span></span>\n<span><span>)</span></span>\n<span><span></span></span>\n<span><span>df.write.format(\"delta\").mode(\"append\").saveAsTable(\"letters\")</span></span></code></pre>\n<p>Here’s the error message that’s raised:</p>\n<pre><code><span><span>org.apache.spark.sql.delta.schema.DeltaInvariantViolationException: NOT NULL constraint violated for column: letter2.</span></span></code></pre>\n<p>Delta Lake makes it easy for you to prevent adding <code>NULL</code> values to columns.</p>\n<h2 id=\"delta-lake-not-null-constraint-vs-dataframe-nullable-property\">Delta Lake NOT NULL constraint vs DataFrame nullable property</h2>\n<p>PySpark DataFrames have schemas that specify each column’s name, data type, and nullable property. The nullable property determines whether each column can take a null value.</p>\n<p>The nullable DataFrame property doesn’t provide the same guarantees that the <code>NOT NULL</code> constraint provides. For example, PySpark will automatically set the <code>nullable</code> property to <code>True</code> when reading a CSV file that contains null values, even if you try to explicitly set it to <code>False</code>.</p>\n<p>Suppose you have a CSV file with the following data:</p>\n<pre><code><span><span>col1,col2</span></span>\n<span><span>hi,bye</span></span>\n<span><span>hola,</span></span></code></pre>\n<p>Read this CSV file into a DataFrame and try to set the <code>col2</code> nullable property to <code>False</code>:</p>\n<pre><code><span><span>from pyspark.sql.types import StringType, StructType</span></span>\n<span><span></span></span>\n<span><span>schema = StructType().add(\"col1\", StringType(), True).add(\"col2\", StringType(), False)</span></span>\n<span><span></span></span>\n<span><span>df = (</span></span>\n<span><span>    spark.read.format(\"csv\")</span></span>\n<span><span>        .option(\"header\", True)</span></span>\n<span><span>       .schema(schema)</span></span>\n<span><span>       .load(\"../../data/small_file.csv\")</span></span>\n<span><span>)</span></span></code></pre>\n<p>View the contents of the DataFrame:</p>\n<pre><code><span><span>df.show()</span></span>\n<span><span></span></span>\n<span><span>+----+----+</span></span>\n<span><span>|col1|col2|</span></span>\n<span><span>+----+----+</span></span>\n<span><span>|  hi| bye|</span></span>\n<span><span>|hola|null|</span></span>\n<span><span>+----+----+</span></span></code></pre>\n<p>Now view the schema of the DataFrame:</p>\n<pre><code><span><span>df.printSchema()</span></span>\n<span><span></span></span>\n<span><span>root</span></span>\n<span><span> |-- col1: string (nullable = true)</span></span>\n<span><span> |-- col2: string (nullable = true)</span></span></code></pre>\n<p><code>col2</code> has a nullable property set to <code>True</code>, even though we tried to explicitly set it to <code>False</code> when reading the data.</p>\n<p>This blog post does not cover all the nullable property edge cases. For purposes of this post, you just need to understand that the nullable property does not provide you with the guarantees that the <code>NOT NULL</code> constraint provides.</p>\n<p>The <code>NOT NULL</code> constraint prevents data with null values from being appended to your Delta table.</p>\n<h2 id=\"adding-constraints-to-existing-delta-tables\">Adding constraints to existing Delta tables</h2>\n<p>Let’s see what happens when you add a check to a Delta table that already contains data.</p>\n<p>Create a Delta table named <code>random2</code> with <code>age</code> and <code>word</code> columns.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (-45, \"hi\"),</span></span>\n<span><span>        (2, \"bye\"),</span></span>\n<span><span>    ],</span></span>\n<span><span>    [\"age\", \"word\"],</span></span>\n<span><span>)</span></span>\n<span><span></span></span>\n<span><span>df.write.format(\"delta\").saveAsTable(\"random2\")</span></span></code></pre>\n<p>View the contents of the <code>random2</code> table.</p>\n<pre><code><span><span>spark.table(\"random2\").show()</span></span>\n<span><span></span></span>\n<span><span>+---+----+</span></span>\n<span><span>|age|word|</span></span>\n<span><span>+---+----+</span></span>\n<span><span>|  2| bye|</span></span>\n<span><span>|-45|  hi|</span></span>\n<span><span>+---+----+</span></span></code></pre>\n<p>One of the rows has a negative <code>age</code> value and the other has a positive <code>age</code> value. Let’s see what happens if you try to add a constraint that requires all rows of data in the Delta table to have positive <code>age</code> values.</p>\n<pre><code><span><span>spark.sql(\"ALTER TABLE default.random2 ADD CONSTRAINT ageIsPositive CHECK (age &gt;= 0)\")</span></span></code></pre>\n<p>This command will error out with the following message:</p>\n<pre><code><span><span>AnalysisException: 1 rows in default.random2 violate the new CHECK constraint (age &gt;= 0)</span></span></code></pre>\n<p>Delta Lake doesn’t let you apply a constraint if the existing table doesn’t satisfy the boolean check.</p>\n<h2 id=\"conclusion\">Conclusion</h2>\n<p>Constraints can be critical to make sure that bad data isn’t added to your Delta table. Sometimes you’ll want Delta tables that ingest all data (clean &amp; junk), but other times you’ll want Delta tables to be strict and only accept clean data.</p>\n<p>Delta Lake constraints make it easy for you to validate data before it’s appended to a Delta table. Make sure to use Delta Lake constraints whenever you want to prevent certain types of data from being added to a column.</p>\n<p>Remember that Delta Lake constraints are for row-level values. The schema-level checks for the column names and data types are performed separately via <a target=\"_blank\" href=\"https://delta.io/blog/2022-11-16-delta-lake-schema-enforcement/\">schema enforcement</a>.</p>  </div>"
