Delta Lake is a Lakehouse storage system that delivers reliability, security and performance for both streaming and batch operations.</p>\n<p>Polars has blazing fast performance and Delta Lake has amazing features like ACID transactions, time travel, schema enforcement, and many more, so they are a match made in heaven. Let’s dig into some code!</p>\n<h2 id=\"creating-delta-table\">Creating Delta Table</h2>\n<p>Let’s create a Delta table with three different versions. That will allow us to easily illustrate time travel between the different Delta table versions with Polars.</p>\n<p>Here’s the Delta table with three versions that we’ll create.</p>\n<p><img src=\"https://delta.io/_astro/image1.DDoRUTcN_Z1JORPh.webp\"></p>\n<p>Let’s start by creating version 0 of the Delta table with pandas.</p>\n<pre><code><span><span>from deltalake.writer import write_deltalake</span></span>\n<span><span>import pandas as pd</span></span>\n<span><span></span></span>\n<span><span>df = pd.DataFrame({\"x\": [1, 2, 3]})</span></span>\n<span><span></span></span>\n<span><span>write_deltalake(\"/tmp/bear_delta_lake\", df)</span></span></code></pre>\n<p>Now let’s append another DataFrame to the existing Delta table which will create version 1.</p>\n<pre><code><span><span>df2 = pd.DataFrame({\"x\": [9, 8, 10]})</span></span>\n<span><span></span></span>\n<span><span>write_deltalake(\"/tmp/bear_delta_lake\", df2, mode=\"append\")</span></span></code></pre>\n<p>Now let’s overwrite the Delta table which will remove the existing data and add new data. Now let’s use Polars to read the Delta table.</p>\n<h2 id=\"read-delta-table-with-polars\">Read Delta Table with Polars</h2>\n<p>Here’s how to read the latest version of the Delta table with Polars.</p>\n<pre><code><span><span>import polars as pl</span></span>\n<span><span></span></span>\n<span><span>print(pl.read_delta(\"/tmp/bear_delta_lake\"))</span></span></code></pre>\n<p>Here’s the DataFrame that’s printed:</p>\n<pre><code><span><span>+-----+</span></span>\n<span><span>| x   |</span></span>\n<span><span>| --- |</span></span>\n<span><span>| i64 |</span></span>\n<span><span>+=====+</span></span>\n<span><span>| 55  |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 66  |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 77  |</span></span>\n<span><span>+-----+</span></span></code></pre>\n<p>You can also read the DataFrame with <code>scan_delta</code> which will <strong>lazily</strong> read the Delta table. The <code>read_delta</code> method on the other hand immediately loads the Delta table into memory.</p>\n<pre><code><span><span>ldf = pl.scan_delta(\"/tmp/bear_delta_lake\")</span></span>\n<span><span></span></span>\n<span><span>print(ldf.collect())</span></span>\n<span><span></span></span>\n<span><span>+-----+</span></span>\n<span><span>| x   |</span></span>\n<span><span>| --- |</span></span>\n<span><span>| i64 |</span></span>\n<span><span>+=====+</span></span>\n<span><span>| 55  |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 66  |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 77  |</span></span>\n<span><span>+-----+</span></span></code></pre>\n<p>Polars will use the Delta table transaction log to only read the files that are required. Polars will optimize the computation before performing any work on a lazy DataFrame.</p>\n<h2 id=\"time-travel-to-different-versions-with-polars\">Time travel to different versions with Polars</h2>\n<p>The <code>scan_delta</code> and <code>read_delta</code> methods will read the latest version of the Delta table by default. Let’s look at how we can easily time travel across different versions of the Delta table using by setting the version parameter.</p>\n<p>Start by reading version 0 of the Delta table.</p>\n<pre><code><span><span>print(pl.read_delta(\"/tmp/bear_delta_lake\", version=0))</span></span>\n<span><span></span></span>\n<span><span>+-----+</span></span>\n<span><span>| x   |</span></span>\n<span><span>| --- |</span></span>\n<span><span>| i64 |</span></span>\n<span><span>+=====+</span></span>\n<span><span>| 1   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 2   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 3   |</span></span>\n<span><span>+-----+</span></span></code></pre>\n<p>Now read version 1 of the Delta table.</p>\n<pre><code><span><span>print(pl.read_delta(\"/tmp/bear_delta_lake\", version=1))</span></span>\n<span><span></span></span>\n<span><span>+-----+</span></span>\n<span><span>| x   |</span></span>\n<span><span>| --- |</span></span>\n<span><span>| i64 |</span></span>\n<span><span>+=====+</span></span>\n<span><span>| 1   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 2   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 3   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 9   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 8   |</span></span>\n<span><span>|-----|</span></span>\n<span><span>| 10  |</span></span>\n<span><span>+-----+</span></span></code></pre>\n<p>The Polars Delta Lake connector is intelligent about only reading the data files that are required for each version. Version 0 of the Delta table only requires a single data file, so that’s all Polars will read. Time travel is executed efficiently.</p>\n<h2 id=\"how-polars-executes-queries-on-delta-lake-tables\">How Polars executes queries on Delta Lake tables</h2>\n<p>Delta tables store data in Parquet files and metadata information in a transaction log. The following image shows the high level architecture of a Delta table.</p>\n<p><img src=\"https://delta.io/_astro/image2.CaRR2nxx_2mXfNC.webp\"></p>\n<p>Polars doesn’t run your queries naively but optimizes your query and ensures only the needed columns and rows are read from I/O. This works great with delta tables as Polars can query the transaction log to see what data files are needed.</p>\n<p>Querying the transaction log is a lot more efficient than reading the footer for each individual Parquet file, building up all the data table metadata, and then executing the query. This is especially true for nested directories on cloud object stores.</p>\n<h2 id=\"why-delta-lake-helps-polars-users\">Why Delta Lake helps Polars users</h2>\n<p>Delta Lake offers Polars users reliable ACID transaction guarantees on a variety of different storage systems, including the popular clouds. ACID transactions give users the guarantee that operations will complete fully or not at all. Users don’t want an operation to partially complete and then error out halfway through, thus corrupting their dataset.</p>\n<p>This blog demonstrates how users can efficiently time travel to different versions of an existing Delta Table, which is another great feature for production data workloads.</p>\n<p>Delta Lake will add even more value to Polars users as more features are added.</p>\n<h2 id=\"future-work\">Future work</h2>\n<p>The Polars Delta Lake connector depends on <a target=\"_blank\" href=\"https://github.com/delta-io/delta-rs/\">delta-rs</a>, a Rust implementation of the Delta Lake protocol.</p>\n<p>Delta Rust is under active development and new features like DML transactions, rollbacks, column mapping, Z ORDER, optimize and more.
