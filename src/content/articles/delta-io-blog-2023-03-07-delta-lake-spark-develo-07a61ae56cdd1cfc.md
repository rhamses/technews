You’ll learn how to retrieve and navigate the codebase, make changes, and package and debug custom builds of the Delta Lake Spark Connector.</p>\n<p>This post is for anyone who wants to start developing Delta Lake features or just wants to better understand the internals. If you’re working in other languages or with different systems, you can still learn a lot from the reference Spark connector because it’s currently the most mature and feature-rich connector available for Delta Lake.</p>\n<p>If you’re not a developer, you can still benefit from exploring the underlying implementation and running the Delta Lake Spark connector in debug mode when you encounter unexpected behavior in your daily usage. This is one of the main benefits of open source software!</p>\n<p>We’ll use git and IntelliJ, which is common for Java based projects, so you’ll be able to adapt these steps to many other related projects too.</p>\n<p>If you’re using a Mac, you can execute all the commands in this post in your terminal. You may need to make changes for other operating systems. If you run into any issues, please join our Slack channel #deltalake-questions or #contributing.</p>\n<p>Let’s get started.</p>\n<h2 id=\"how-to-get-the-delta-lake-spark-code\">How to get the Delta Lake Spark code</h2>\n<p>Let’s begin first by forking the Delta Lake Spark Connector repository. Go to <a target=\"_blank\" href=\"https://github.com/delta-io/delta\">https://github.com/delta-io/delta</a> and click <strong>+ Create a new fork</strong>.\nForking a repository creates a copy of it in our own Github account, which enables us to safely follow our git workflow on our own isolated copy.</p>\n<p><img src=\"https://delta.io/_astro/image1.Di5eDVDq_Z2iyNd0.webp\"></p>\n<p>Now that we have a copy of the Delta Spark connector repository in our own account, we can clone the code to our local environment.</p>\n<p>Clone the repository and open the new <code>delta</code> directory.</p>\n<pre><code><span><span>git clone https://github.com/nkarpov/delta</span></span>\n<span><span>cd delta</span></span></code></pre>\n<p>Now run <code>git remote -v</code> and observe the output. The <code>git remote</code> command is used to manage a set of tracked repositories.</p>\n<pre><code><span><span>➜  delta git:(dev) git remote -v</span></span>\n<span><span>origin\thttps://github.com/nkarpov/delta (fetch)</span></span>\n<span><span>origin\thttps://github.com/nkarpov/delta (push)</span></span></code></pre>\n<p>You can see here that our local repository tracks only one remote, <code>origin</code>, which points to our forked repository in GitHub.\nWe also want our local repository to track the original <code>delta-io/delta</code> repository.\nThis is critical to ensure we can synchronize our fork with any changes to the original repository.\nIt’s common to name the upstream remote, “upstream”, which we can do with the following command:</p>\n<pre><code><span><span>git remote add upstream https://github.com/delta-io/delta</span></span></code></pre>\n<p>Now let’s confirm that the new “upstream” remote has been added by running <code>git remote-v</code> again:</p>\n<pre><code><span><span>➜  delta git:(dev) git remote -v</span></span>\n<span><span>origin\thttps://github.com/nkarpov/delta (fetch)</span></span>\n<span><span>origin\thttps://github.com/nkarpov/delta (push)</span></span>\n<span><span>upstream https://github.com/delta-io/delta (fetch)</span></span>\n<span><span>upstream https://github.com/delta-io/delta (push)</span></span></code></pre>\n<p>Our local environment can now track both our fork, which we refer to as <code>origin</code> and the original Delta Lake Spark connector repo, which we refer to as <code>upstream</code>.\nYou can name your remotes anything you want, but “origin” and “upstream” are common naming conventions followed by many developers.</p>\n<p>Now let’s fetch all the tags with this command:</p>\n<pre><code><span><span>git fetch --all --tags</span></span></code></pre>\n<p>Tags are an easy way to point to a specific git commit.\nDelta Spark connector releases are tagged, like: <code>vX.X.X</code>, and we can reliably use these tags to get the exact code for a specific version, which we do by running the next command:</p>\n<pre><code><span><span>git checkout tags/v2.2.0 -b dev</span></span></code></pre>\n<p>This command checks out the commit referenced by the tag <code>v2.2.0</code> into a new local branch called “dev”.</p>\n<p>Our local repository is now set to version <code>2.2.0</code> of the Delta Lake Spark connector.</p>\n<p>We want to complete an entire development loop as fast as possible, so we’ll return to this code later.\nFor now, let’s move on to compiling and packaging our code base.</p>\n<h2 id=\"how-to-compile-and-package-delta-lake-spark\">How to compile and package Delta Lake Spark</h2>\n<p>The Delta Lake Spark connector build is managed by the <code>sbt</code> build tool, which is common for Scala and Java projects.\nA version of <code>sbt</code> comes bundled with the project, so we can easily compile and package current code with just one command from the local repository directory:</p>\n<pre><code><span><span>build/sbt package</span></span></code></pre>\n<p>The <code>package</code> command will both compile and package the code into JAR files you can use with Spark to work with Delta Lake tables.\nThis might take several minutes the first time you run it, but will be faster in the future.\nThe build tool has to resolve and download all the dependencies of the project, which you may or may not already have.</p>\n<p>When your package command completes, you should see a final message in your terminal like this:</p>\n<pre><code><span><span>[success] Total time: 22 s, completed Mar 2, 2023, 2:59:15 PM</span></span></code></pre>\n<p>If you haven’t worked with JVM based projects before, you may encounter errors with your Java installation and/or version.\nMake sure to have JDK 8 or JDK 11 installed and available on your machine.\nYou can start with <a target=\"_blank\" href=\"https://docs.oracle.com/en/java/javase/15/install/installation-jdk-macos.html\">this guide</a>, and see a list of vendors providing JDK distributions <a target=\"_blank\" href=\"https://sdkman.io/jdks\">here</a></p>\n<p>Assuming you ran the package command successfully, you should now have some new directories and files, which you can confirm using notice that <code>package</code> produced more than just one JAR file.\nThis is the first time we’re seeing that the Delta Spark connector consists of a handful of separate, but related modules.\nThe two modules we actually need for our work today are listed above: delta-core and delta-storage.</p>\n<p>Since we’re focused on getting our code to run, we’ll return to expand on these modules later.\nFor now you just need to know that the <code>delta-core</code> module contains both core Delta and Spark integration code, and the <code>delta-storage</code> module contains storage related code to make sure Delta works consistently across storage services like S3, Azure Data Lake, and Google Cloud Storage.</p>\n<h2 id=\"how-to-run-delta-lake-spark\">How to run Delta Lake We’ve stepped through the entire development loop: getting the code, compiling the code, and running the code.</p>\n<p>Let’s set up our project with an IDE, which will allow us to both navigate the code in a structured way, and easily run it with a debugger.</p>\n<h2 id=\"how-to-configure-intellij-with-delta-lake-spark\">How to configure IntelliJ with Delta Lake Spark</h2>\n<p>IntelliJ is the recommended IDE for working with the Delta Lake Spark connector.\nIf you don’t already have IntelliJ, you can <a target=\"_blank\" href=\"https://www.jetbrains.com/idea/\">download it here</a>.\nThe community edition is completely free.</p>\n<h3 id=\"createa-delta-lake-spark-intellij-project\">Createa Delta Lake Spark IntelliJ project</h3>\n<p>Create a new <em>Project from Existing Sources</em> and select the folder where you ran your build</p>\n<p><img src=\"https://delta.io/_astro/image2.B6epM4Z0_14sebR.webp\"></p>\n<p>Select <code>sbt</code> as the external model</p>\n<p><img src=\"https://delta.io/_astro/image3.Ch463nfD_1lVuBs.webp\"></p>\n<p>And make sure to select an appropriate <strong>Project JDK</strong> (JDK 1.8 or JDK 1.11):</p>\n<p><img src=\"https://delta.io/_astro/image4.CFOl9YXI_1kLfQh.webp\"></p>\n<p>Click finish, and IntelliJ will load the project using the project definition.\nWhen the loading process is complete you should see a screen like this, note the green checkmark in the bottom left panel showing that our sync was successful.</p>\n<p><img src=\"https://delta.io/_astro/image5.KoYGpOQ0_1HwkKi.webp\"></p>\n<h3 id=\"add-a-new-debug-configuration-in-intellij\">Add a new debug configuration in IntelliJ</h3>\n<p>Now let’s do the final configuration for debugging.</p>\n<p>On the top panel, click <strong>Add Configuration</strong></p>\n<p><img src=\"https://delta.io/_astro/image6.P9HZRBjD_Z1YzUA4.webp\"></p>\n<p>Click <strong>Add new &gt;
