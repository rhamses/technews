contentHtml: "<div>  <p>We are excited to announce that AWS Lambda with the latest release of AWS SDK for pandas (2.20) layer now supports the <code>deltalake</code> package for read and write access to Delta Lake tables.\nThe Delta Lake community has been working hard to make this a reality, and we are thrilled to share it with you.\nIn this blog post we’ll highlight the benefits of using Delta Lake from AWS Lambda and step through how to build your own Lambda layer with <code>deltalake</code>.</p>\n<h2 id=\"reading-and-writing-delta-lake-tables\">Reading and Writing Delta Lake tables</h2>\n<p>The code to read and write from and to Delta Lake tables from an AWS Lambda function is the same as it would be locally and in other environments.\nHere’s a minimal example of an AWS Lambda-compatible code block that demonstrates reading, transforming, and writing Delta Lake tables:</p>\n<pre><code><span><span>import json</span></span>\n<span><span>from deltalake import DeltaTable</span></span>\n<span><span>from deltalake.writer import write_deltalake</span></span>\n<span><span></span></span>\n<span><span>def lambda_handler(event, context):</span></span>\n<span><span>    # Read data from Delta Lake table</span></span>\n<span><span>    # Assume that `event` has value for the key `path`</span></span>\n<span><span>    path = event.get('path')</span></span>\n<span><span>    dt = DeltaTable(path)</span></span>\n<span><span>    df = dt.to_pandas()</span></span>\n<span><span></span></span>\n<span><span>    # Example: Add a new column with the length of the values in column 'A'</span></span>\n<span><span>    df['B'] = df['A'].apply(len)</span></span>\n<span><span></span></span>\n<span><span>    # Write the dataframe to a new Delta table on S3</span></span>\n<span><span>    new_path = 's3://your-bucket/new-delta-table'</span></span>\n<span><span>    write_deltalake(new_path, df, mode='append')</span></span>\n<span><span></span></span>\n<span><span>    return {</span></span>\n<span><span>        'statusCode': 200,</span></span>\n<span><span>        'body': json.dumps(f\"Data successfully written to: {new_path}\")</span></span>\n<span><span>    }</span></span></code></pre>\n<p>This Lambda function reads data from a Delta Lake table, adds a new column using Pandas, and writes the modified data to a new Delta table on S3.</p>\n<h2 id=\"benefits-of-delta-lake-tables-from-aws-lambda\">Benefits of Delta Lake Tables from AWS Lambda</h2>\n<p>With the new support for the Python <code>deltalake</code> package in AWS Lambda, users can now enjoy the following benefits:</p>\n<ul>\n<li>\n<p><strong>Scalability</strong>: AWS Lambda allows you to run code without provisioning or managing servers, enabling you to build applications that can easily scale with the number of requests. With Delta Lake table support, you can now build and scale data processing applications effortlessly.</p>\n</li>\n<li>\n<p><strong>Cost-effectiveness</strong>: AWS Lambda automatically scales your application in response to the number of requests, and you only pay for the compute time you consume. By leveraging the deltalake package in AWS Lambda, you can reduce spend on over provisioning large clusters for smaller use cases.</p>\n</li>\n<li>\n<p><strong>Ease of use</strong>: The integration of Delta Lake tables with AWS Lambda simplifies data processing workflows, allowing you to focus on your application logic rather than managing infrastructure.</p>\n</li>\n<li>\n<p><strong>Increased</strong> compatibility: By expanding the PyArrow build in the AWS pandas SDK, we have paved the way for other packages to benefit from this dependency, fostering a more extensive ecosystem of compatible applications and tools.</p>\n</li>\n</ul>\n<h2 id=\"installation\">Installation</h2>\n<p>You can configure deltalake with Lambda function by uploading a zip file archive as a Lambda Layer, or by creating a container image and uploading it to Amazon ECR.\nIn this post, we’ll focus on the easy to use <a target=\"_blank\" href=\"https://docs.aws.amazon.com/lambda/latest/dg/configuration-layers.html\">Lambda Layer</a> approach.</p>\n<h3 id=\"building-the-deltalake-package-as-an-aws-lambda-layer\">Building the deltalake package as an AWS Lambda Layer</h3>\n<p>First, create a new directory and a <code>python</code> subdirectory for the layer and navigate to it.\nThe subdirectory is required for AWS Lambda to correctly recognize dependencies.</p>\n<pre><code><span><span>mkdir -p deltalake_lambda_layer/python</span></span>\n<span><span>cd deltalake_lambda_layer</span></span></code></pre>\n<p>Second, install the deltalake package without its dependencies (<code>--no-deps</code>) into the python subdirectory.\nAll the necessary dependencies are included in the AWS SDK for pandas layer, which we’ll configure with our Lambda function in a later step.\nNote that we also specify <code>--platform</code> explicitly to make sure we get the compatible Linux-based build.</p>\n<pre><code><span><span>pip install -t ./python --no-deps --platform manylinux2014_x86_64 deltalake==0.8.0</span></span></code></pre>\n<p>Finally, package the installation up into a zip file and name it accordingly</p>\n<pre><code><span><span>zip -r deltalake_layer.zip .</span></span></code></pre>\n<p>You now have a <code>deltalake_layer.zip</code> file that you can upload as a layer to AWS Lambda.</p>\n<h3 id=\"uploading-the-deltalake-lambda-layer-zip-to-aws\">Uploading the deltalake Lambda layer zip to AWS</h3>\n<h4 id=\"using-the-aws-cli\">Using the AWS CLI</h4>\n<p>Install and configure the <a target=\"_blank\" href=\"https://aws.amazon.com/cli/\">AWS CLI</a> if you haven’t done so already, and then run the following command to upload the layer we built in the previous step.</p>\n<pre><code><span><span>aws lambda publish-layer-version \\</span></span>\n<span><span>--layer-name deltalake_layer \\</span></span>\n<span><span>--zip-file fileb://deltalake_layer.zip \\</span></span>\n<span><span>--compatible-runtimes python3.7 python3.8 python3.9</span></span></code></pre>\n<h4 id=\"using-the-aws-management-console\">Using the AWS Management Console</h4>\n<p>To upload the Lambda layer using the AWS Management Console, follow the steps below.\nYou can read more about configuring AWS Lambda Layers in the AWS documentation.</p>\n<ol>\n<li>Sign in to the AWS Management Console.</li>\n<li>Navigate to the Lambda service.</li>\n<li>Click on “Layers” in the left sidebar.</li>\n<li>Click the “Create layer” button.</li>\n<li>Provide a name for the layer, such as “deltalake_layer”.</li>\n<li>Click the “Upload” button and select the deltalake_layer.zip file.</li>\n<li>Choose the appropriate runtime, and click the “Create” button.</li>\n</ol>\n<p>Take note of the LayerVersionArn in the response, as you will need it when configuring your Lambda function.</p>\n<h3 id=\"configuring-the-aws-lambda-function\">Configuring the AWS Lambda function</h3>\n<p>There are a few more steps we need to configure before we can begin using <code>deltalake</code> in our lambda function.</p>\n<h4 id=\"adding-layers-to-lambda-function\">Adding layers to lambda function</h4>\n<p>As we noted before, we’re depending on AWS SDK for pandas to provide the dependencies that <code>deltalake</code> needs.\nThis means that we need to add both layers to our function.</p>\n<p>First, add the AWS SDK for pandas layer.\nAs the screenshot below shows, the layer is fully managed, and available directly in the AWS console, so we don’t need to package anything like we did the deltalake layer.\nYou can read more about this in the <a target=\"_blank\" href=\"https://aws-sdk-pandas.readthedocs.io/en/stable/install.html#aws-lambda-layer\">official documentation</a>.</p>\n<p><img src=\"https://delta.io/_astro/image1.CopeKe_w_ZkKfuY.webp\"></p>\n<h4 id=\"iam-roles\">IAM Roles</h4>\n<p>We need to make sure our function is able to read and write to S3.\nThe recommended approach is to use IAM Roles, so make sure that your execution role has the appropriate permissions.\nYou can read more about IAM role configuration with AWS Lambda in the <a target=\"_blank\" href=\"https://docs.aws.amazon.com/lambda/latest/dg/lambda-intro-execution-role.html\">official documentation</a>.</p>\n<h4 id=\"environment-variables\">Environment Variables</h4>\n<p>If you don’t plan to have multiple writers accessing a Delta Lake table at once you must set the following environment variable in the <a target=\"_blank\" href=\"https://docs.aws.amazon.com/lambda/latest/dg/configuration-envvars.html\">Lamda function environment variable configuration</a>.\nOtherwise, the function will throw an error to protect your data from unexpected writes.</p>\n<pre><code><span><span>AWS_S3_ALLOW_UNSAFE_RENAME\tfalse</span></span></code></pre>\n<p>If you do plan to have multiple writers, you must add the following environment variables to ensure that <code>deltalake</code> writers don’t overwrite each other.</p>\n<pre><code><span><span>AWS_S3_LOCKING_PROVIDER           dynamodb</span></span>\n<span><span>DYNAMO_LOCK_PARTITION_KEY_VALUE   key</span></span>\n<span><span>DYNAMO_LOCK_TABLE_NAME            delta_rs_lock_table</span></span></code></pre>\n<p>Note the values for the partition key value and table name above and make sure they are consistent with the DynamoDB table you provision in the next step!</p>\n<h4 id=\"dynamodb-multi-writer-support\">DynamoDB Multi Writer Support</h4>\n<p>If you’re planning to support multiple writers at once, you must provision a DynamoDB table and grant access using the IAM role.\nThis table is necessary to <a target=\"_blank\" href=\"https://delta.io/blog/2022-05-18-multi-cluster-writes-to-delta-lake-storage-in-s3/\">support concurrent writers in S3</a>.</p>\n<p>Here is the snippet to quickly create the DynamoDB table using the AWS CLI</p>\n<pre><code><span><span>aws dynamodb create-table --table-name delta_rs_lock_table \\</span></span>\n<span><span>    --attribute-definitions \\</span></span>\n<span><span>        AttributeName=key,AttributeType=S \\</span></span>\n<span><span>    --key-schema \\</span></span>\n<span><span>        AttributeName=key,KeyType=HASH \\</span></span>\n<span><span>    --provisioned-throughput \\</span></span>\n<span><span>        ReadCapacityUnits=10,WriteCapacityUnits=10</span></span>\n<span><span></span></span></code></pre>\n<h2 id=\"limitations-and-future-work\">Limitations and Future Work</h2>\n<p>The three leading multi-process writing solutions for Delta Lake, namely Databricks Runtime, Delta Lake Spark Connector with DynamoDB, and Delta Rust with DynamoDB, are continuously evolving to enhance compatibility.\nWhile reading tables concurrently is supported by all three connectors today, writing to the same table on AWS S3 simultaneously from different connectors is yet to be possible.\nUsers must use one connector at a time to ensure data correctness.\nToday’s limitation is due to the differing approaches to ensuring mutual exclusion on top of S3: Databricks Runtime uses a managed internal service, Delta Rust with DynamoDB employs a lease-based locking mechanism, and Delta Spark with DynamoDB relies on conditional writes.\nThe Delta community is actively working to develop a unified, compatible solution, ensuring that all connectors will support multi-process writes from all Delta connectors concurrently.</p>\n<h2 id=\"conclusion\">Conclusion</h2>\n<p>We are delighted to announce the support for the deltalake package in an AWS Lambda with the AWS SDK for pandas layer.\nWe believe this integration will empower users to build more scalable, cost-effective, and user-friendly data processing applications within the AWS ecosystem.\nWe would like to extend our gratitude to the AWS SDK for pandas team for their collaboration and willingness to adapt their AWS Lambda layer build, making this support possible!</p>\n<p>We encourage you to try out the deltalake package support in your AWS Lambda functions and experience the benefits firsthand.\nWe look forward to seeing the innovative solutions that our users will develop using this new integration.</p>\n<p>Happy coding, and enjoy the power of Delta Lake tables in AWS Lambda!</p>  </div>"
