contentHtml: "<div>  <p>This blog post describes how to create Delta Lake tables with generated columns, which are a great way to automatically populate columns based on other column values.</p>\n<p>You will learn about when generated columns are useful in your data workflows.</p>\n<p>All the computations in this post are in <a target=\"_blank\" href=\"https://github.com/delta-io/delta-examples/blob/master/notebooks/pyspark/generated-columns.ipynb\">this notebook</a> in case you’d like to follow along and run the code on your local machine.</p>\n<h2 id=\"create-delta-lake-table-with-generated-columns\">Create Delta Lake table with generated columns</h2>\n<p>In this section, we’ll create a Delta Lake table with <code>id</code>, <code>first_name</code>, <code>last_name</code>, <code>age</code>, and <code>full_name</code> columns.</p>\n<p>The <code>id</code>, <code>first_name</code>, <code>last_name</code> and <code>age</code> columns will be supplied by the user when they’re appending data to the table.</p>\n<p>The <code>full_name</code> column will be generated by Delta Lake when data is appended to the table. The <code>full_name</code> column will simply concatenate the <code>first_name</code> and <code>last_name</code> columns and separate them with a space.</p>\n<p>Here’s how we can create the empty Delta table with Python:</p>\n<pre><code><span><span>from delta import DeltaTable</span></span>\n<span><span></span></span>\n<span><span>(</span></span>\n<span><span>    DeltaTable.create(spark)</span></span>\n<span><span>    .tableName(\"default.some_people\")</span></span>\n<span><span>    .addColumn(\"id\", \"LONG\")</span></span>\n<span><span>    .addColumn(\"first_name\", \"STRING\")</span></span>\n<span><span>    .addColumn(\"last_name\", \"STRING\")</span></span>\n<span><span>    .addColumn(\"age\", \"LONG\")</span></span>\n<span><span>    .addColumn(</span></span>\n<span><span>        \"full_name\", \"STRING\", generatedAlwaysAs=\"concat(first_name, ' ', last_name)\"</span></span>\n<span><span>    )</span></span>\n<span><span>    .execute()</span></span>\n<span><span>)</span></span></code></pre>\n<p>Let’s show the Delta table and make sure it’s empty:</p>\n<pre><code><span><span>spark.sql(\"select * from some_people\").show()</span></span>\n<span><span></span></span>\n<span><span>+---+----------+---------+---+---------+</span></span>\n<span><span>| id|first_name|last_name|age|full_name|</span></span>\n<span><span>+---+----------+---------+---+---------+</span></span>\n<span><span>+---+----------+---------+---+---------+</span></span></code></pre>\n<p>Great, now let’s see how to append data to this table and take advantage of the generated column feature.</p>\n<h2 id=\"insert-into-delta-lake-table-with-generated-columns\">Insert into Delta Lake table with generated columns</h2>\n<p>Let’s append data to the Delta Lake table. We’ll append a DataFrame that has <code>id</code>, <code>first_name</code>, <code>last_name</code>, and <code>age</code> columns. This will let us observe how Delta Lake automatically generates the <code>full_name</code> column.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [(0, \"Bob\", \"Loblaw\", 23),(1, \"Sue\", \"Grafton\", None), (2, \"Jim\", \"Carrey\", 61)]</span></span>\n<span><span>).toDF(\"id\", \"first_name\", \"last_name\", \"age\")</span></span>\n<span><span></span></span>\n<span><span>df.write.mode(\"append\").format(\"delta\").saveAsTable(\"some_people\")</span></span></code></pre>\n<p>Now query the table and verify that the <code>full_name</code> column was populated by Delta Lake:</p>\n<pre><code><span><span>DeltaTable.forName(spark, \"some_people\").toDF().show()</span></span>\n<span><span></span></span>\n<span><span>+---+----------+---------+----+-----------+</span></span>\n<span><span>| id|first_name|last_name| age|  full_name|</span></span>\n<span><span>+---+----------+---------+----+-----------+</span></span>\n<span><span>|  2|       Jim|   Carrey|  61| Jim Carrey|</span></span>\n<span><span>|  0|       Bob|   Loblaw|  23| Bob Loblaw|</span></span>\n<span><span>|  1|       Sue|  Grafton|null|Sue Grafton|</span></span>\n<span><span>+---+----------+---------+----+-----------+</span></span></code></pre>\n<p>Let’s look at how Delta Lake stores the <code>full_name</code> column in Delta tables and the associated performance/storage implications.</p>\n<h2 id=\"how-delta-lake-stores-data-for-generated-columns\">How Delta Lake stores data for generated columns</h2>\n<p>Delta Lake persists the generated column data in storage. The column isn’t computed on the fly when the data is read. The data is computed and persisted when DataFrames are appended to storage.</p>\n<p>Let’s refresh our memory on the high-level structure of a Delta table:</p>\n<p><img src=\"https://delta.io/_astro/image1.DqmRt14i_Z1WEYOR.webp\"></p>\n<p>Delta tables consist of data stored in Parquet files and metadata stored in the transaction log.</p>\n<p>The generated column data is persisted in the underlying Parquet files, just like the data for the other columns.</p>\n<p>Persisting data in storage adds to storage costs. There is an extra column that’s persisted in your Delta table which you need to pay for.</p>\n<p>Persisting data generally saves on compute costs because you don’t need to compute the <code>full_name</code> value anymore when reading data. You can just read the value directly.</p>\n<p>Compute is generally more expensive than storage, so strategically generating columns and saving on compute should generally save you money overall.</p>\n<p>Let’s now turn our attention to how generated columns interact with Delta table schema evolution.</p>\n<h2 id=\"how-delta-lake-generated-columns-work-with-schema-evolution\">How Delta Lake generated columns work with schema evolution</h2>\n<p>When Delta Lake schema evolution is enabled, you can append DataFrames to Delta tables that have missing or extra columns, see <a target=\"_blank\" href=\"https://delta.io/blog/2023-02-08-delta-lake-schema-evolution/\">this blog post for more details</a>.</p>\n<p>Once column generation is enabled, certain columns become required and schema evolution doesn’t behave as usual. If you enable schema evolution on a Delta table without any generated columns, then the <code>first_name</code> and <code>last_name</code> columns would be optional. In this case, the <code>full_name</code> column depends on the <code>first_name</code> and <code>last_name</code> columns, so they’re required, even if schema evolution is enabled.</p>\n<p>Let’s see what happens when you try to append a DataFrame without the last_name column to the Delta table.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (8, \"Liam\", 66),</span></span>\n<span><span>        (9, \"Colin\", 77),</span></span>\n<span><span>    ]</span></span>\n<span><span>).toDF(\"id\", \"first_name\", \"age\")</span></span>\n<span><span></span></span>\n<span><span>df.write.option(\"mergeSchema\", \"true\").mode(\"append\").format(\"delta\").saveAsTable(</span></span>\n<span><span>    \"some_people\"</span></span>\n<span><span>)</span></span></code></pre>\n<p>Here’s the error message you’ll get:</p>\n<pre><code><span><span>AnalysisException: Column 'last_name' does not exist. Did you mean one of the following? [first_name, age, id]; line 1 pos 24;</span></span>\n<span><span>'Project [id#2335L AS id#2391L, first_name#2336 AS first_name#2392, age#2337L AS age#2393L, 'concat(first_name#2336,  , 'last_name) AS full_name#2394]</span></span>\n<span><span>+- Project [_1#2329L AS id#2335L, _2#2330 AS first_name#2336, _3#2331L AS age#2337L]</span></span>\n<span><span>   +- LogicalRDD [_1#2329L, _2#2330, _3#2331L], false</span></span></code></pre>\n<p>Now let’s see what happens if you try to append a DataFrame with values that should be generated.</p>\n<h2 id=\"what-happens-when-users-supply-columns-that-should-be-generated\">What happens when users supply columns that should be generated?</h2>\n<p>Delta Lake will reject the transaction if you try to append values that the Delta table should be generating for you. Let’s try to append a DataFrame that contains the <code>full_name</code> column to the Delta table.</p>\n<p>Start by creating the DataFrame:</p>\n<pre><code><span><span>df = spark.createDataFrame([</span></span>\n<span><span>    (21, \"Curtis\", \"Jackson\", 47, \"50 cent\"),</span></span>\n<span><span>    (22, \"Eric\", \"Wright\", None, \"easy-e\"),</span></span>\n<span><span>]).toDF(\"id\", \"first_name\", \"last_name\", \"age\", \"full_name\")</span></span></code></pre>\n<p>Now try to append it to the Delta table:</p>\n<pre><code><span><span>df.write.mode(\"append\").format(\"delta\").saveAsTable(\"some_people\")</span></span></code></pre>\n<p>Delta Lake rejects this transaction and provides the following error message:</p>\n<pre><code><span><span>Py4JJavaError: An error occurred while calling o234.saveAsTable.</span></span>\n<span><span>: org.apache.spark.sql.delta.schema.DeltaInvariantViolationException: CHECK constraint Generated Column (full_name &lt;=&gt; concat(first_name, ' ', last_name)) violated by row with values:</span></span>\n<span><span> - first_name : Eric</span></span>\n<span><span> - full_name : easy-e</span></span>\n<span><span> - last_name : Wright</span></span></code></pre>\n<p>Delta Lake rightfully rejects this transaction.</p>\n<h2 id=\"what-happens-when-generated-columns-depend-on-columns-will-null-values\">What happens when generated columns depend on columns will null values?</h2>\n<p>Let’s see what happens when you try to append a DataFrame with <code>first_name</code> or <code>last_name</code> columns that are <code>null</code> to the Delta table.</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [</span></span>\n<span><span>        (44, None, \"Perkins\", 20),</span></span>\n<span><span>        (55, \"Li\", None, 30),</span></span>\n<span><span>    ]</span></span>\n<span><span>).toDF(\"id\", \"first_name\", \"last_name\", \"age\")</span></span>\n<span><span></span></span>\n<span><span>df.write.mode(\"append\").format(\"delta\").saveAsTable(</span></span>\n<span><span>    \"some_people\"</span></span>\n<span><span>)</span></span></code></pre>\n<p>View the contents of the DataFrame:</p>\n<pre><code><span><span>spark.sql(\"select * from some_people\").show()</span></span>\n<span><span></span></span>\n<span><span>+---+----------+---------+----+-----------+</span></span>\n<span><span>| id|first_name|last_name| age|  full_name|</span></span>\n<span><span>+---+----------+---------+----+-----------+</span></span>\n<span><span>|  2|       Jim|   Carrey|  61| Jim Carrey|</span></span>\n<span><span>|  0|       Bob|   Loblaw|  23| Bob Loblaw|</span></span>\n<span><span>|  1|       Sue|  Grafton|null|Sue Grafton|</span></span>\n<span><span>| 44|      null|  Perkins|  20|       null|</span></span>\n<span><span>| 55|        Li|     null|  30|       null|</span></span>\n<span><span>+---+----------+---------+----+-----------+</span></span></code></pre>\n<p>In this case, the <code>full_name</code> is <code>null</code> whenever <code>first_name</code> or <code>last_name</code> is <code>null</code>. This behavior is consistent with the normal behavior of the PySpark concat function.</p>\n<h2 id=\"delta-lake-generated-columns-conclusion\">Delta Lake generated columns: Conclusion</h2>\n<p>Delta Lake allows you to create Delta tables with generated columns that are automatically computed based on other column values and are persisted in storage.</p>\n<p>Generated columns are a great way to automatically and consistently populate columns in your Delta table. You don’t need to manually append columns to your DataFrames before appending if generated columns are set up.</p>\n<p>Generated columns can only be added to Delta tables that are newly created or replaced. You can’t add a generated column to an existing Delta table.</p>\n<p>Persisting generated columns in storage can be a great way to save on compute and make your queries run faster. You don’t need to compute values when reading data if the computations have already been run beforehand and are persisted in storage.</p>\n<p>Take a look at <a target=\"_blank\" href=\"https://docs.delta.io/latest/delta-batch.html#-deltausegeneratedcolumns\">the documentation on generated columns</a> to learn more about the types of expressions that are supported by generated columns.</p>  </div>"
