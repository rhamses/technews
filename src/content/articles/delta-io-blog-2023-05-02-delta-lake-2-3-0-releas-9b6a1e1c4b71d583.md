contentHtml: "<div>  <p>Delta Lake continues to be the best open source storage format for the lakehouse. The Delta 2.0 release has been wildly successful with widespread adoption and we continue to build upon this success.</p>\n<p>With the release of 2.3, Delta now has even more capabilities that makes deploying Lakehouses super easy.</p>\n<p>This new release makes it easier to transition from Iceberg to Delta Lake, write advanced MERGE statement logic, query the change data feed, and much more. The features outlined below are just a few of the many features included in the release - see <a target=\"_blank\" href=\"https://github.com/delta-io/delta/releases/tag/v2.3.0\">the Delta Lake 2.3 Release Notes</a> for more.</p>\n<p>This post will show you why you should upgrade to Delta 2.3 and how to take advantage of these amazing features.</p>\n<h2 id=\"delta-lake-shallow-clone\">Delta Lake SHALLOW CLONE</h2>\n<p>The Delta Lake SHALLOW CLONE command creates a Delta table in a new location while leaving the existing data files in their current location.</p>\n<p>You can create a shallow clone of a Parquet table, a Delta table, or even an Iceberg table.</p>\n<p>Let’s look at the architecture of a Delta table to get a better understanding of how shallow clones work. Delta tables are normally constructed of Parquet files and a colocated transaction log, as illustrated in the following diagram:</p>\n<p><img src=\"https://delta.io/_astro/image1.DM18cjQZ_1kTlIJ.webp\"></p>\n<p>Let’s create a Delta Lake table and then clone it in another location. Start by creating a Delta Lake table with PySpark.</p>\n<pre><code><span><span>data </span><span>=</span><span> [(</span><span>0</span><span>, </span><span>\"Bob\"</span><span>, </span><span>23</span><span>), (</span><span>1</span><span>, </span><span>\"Sue\"</span><span>, </span><span>25</span><span>), (</span><span>2</span><span>, </span><span>\"Jim\"</span><span>, </span><span>27</span><span>)]</span></span>\n<span><span>df </span><span>=</span><span> spark.createDataFrame(data).toDF(</span><span>\"id\"</span><span>, </span><span>\"name\"</span><span>, </span><span>\"age\"</span><span>)</span></span>\n<span><span>df.write.format(</span><span>\"delta\"</span><span>).save(</span><span>\"/tmp/my_people\"</span><span>)</span></span></code></pre>\n<p>The Delta table contains metadata files and data stored in Parquet as follows:</p>\n<pre><code><span><span>/tmp/my_people</span></span>\n<span><span>├── _delta_log</span></span>\n<span><span>│   └── 00000000000000000000.json</span></span>\n<span><span>├── part-00000-b33f79ee-473d-4b98-ad79-a8b087ae5c50-c000.snappy.parquet</span></span>\n<span><span>├── part-00003-3de8e2cd-bb73-4ed6-af3c-2d61911670d0-c000.snappy.parquet</span></span>\n<span><span>├── part-00006-206bd2a6-bc3f-47d4-9b6c-e9fb8d317732-c000.snappy.parquet</span></span>\n<span><span>└── part-00009-1c687cd5-4515-4966-9aeb-27e03bc00818-c000.snappy.parquet</span></span></code></pre>\n<p>Now clone the table in another location.</p>\n<pre><code><span><span>spark.sql(\"CREATE TABLE right:</p>\n<pre><code><span><span>spark.read.format(\"delta\").load(\"/tmp/my_cloned_people\").show()</span></span>\n<span><span></span></span>\n<span><span>+---+----+---+</span></span>\n<span><span>| id|name|age|</span></span>\n<span><span>+---+----+---+</span></span>\n<span><span>|  2| Jim| 27|</span></span>\n<span><span>|  1| Sue| 25|</span></span>\n<span><span>|  0| Bob| 23|</span></span>\n<span><span>+---+----+---+</span></span></code></pre>\n<p>The cloned table only contains metadata files, it doesn’t contain any data files:</p>\n<pre><code><span><span>/tmp/my_cloned_people</span></span>\n<span><span>└── _delta_log</span></span>\n<span><span>    ├── 00000000000000000000.checkpoint.parquet</span></span>\n<span><span>    ├── 00000000000000000000.json</span></span>\n<span><span>    └── _last_checkpoint</span></span></code></pre>\n<p>Shallow clone is useful when you want to continue updating the source table but want to read or write to an independent copy of it. For example, shallow clone can be used to experiment and test on a production table. Creating a shallow clone means you can run arbitrary operations on the cloned table without corrupting the production table or disrupting any production workloads.</p>\n<p>We’ll dive into the details of cloning in a future blog post and how it can be used along with <code>CONVERT TO DELTA</code>.</p>\n<h2 id=\"convert-iceberg-to-delta-lake\">Convert Iceberg to Delta Lake</h2>\n<p>Companies are looking to migrate from Iceberg to Delta Lake to get access to better performance and reliability, as explained in the <a target=\"_blank\" href=\"https://www.cidrdb.org/cidr2023/papers/p92-jain.pdf\">Analyzing and Comparing Lakehouse Storage Systems</a> paper.</p>\n<p>In Delta 2.3 you can easily convert Iceberg tables to the Delta Lake format with <code>CONVERT TO DELTA</code>. It performs a one-time conversion to the Delta Lake format and also supports converting Parquet tables.</p>\n<p>Suppose you have an Iceberg table named <code>some_table</code> that’s stored at <code>/some/path/some_table</code>. You can convert it to a Delta table with the following command:</p>\n<pre><code><span><span>CONVERT TO DELTA iceberg.`/some/path/some_table`</span></span></code></pre>\n<p>Since both Iceberg tables and Delta tables consist of metadata transaction logs and data stored in Parquet files, converting from Iceberg to Delta Lake is an in-place operation. Converting an Iceberg table just creates a Delta transaction log and doesn’t rewrite any of the data files. After converting an Iceberg table to Delta Lake it will look something like this:</p>\n<p><img src=\"https://delta.io/_astro/image2.Eob5kP4g_69jei.webp\"></p>\n<p>After performing <code>CONVERT TO DELTA</code> the table is now a Delta table and can take advantage of all the awesome Delta Lake features. Note that any subsequent Delta operations could corrupt the Iceberg source table and will not update the Iceberg metadata. Convert to Delta is best used for one-time conversions when you don’t plan to update the source table in the source format anymore.</p>\n<h2 id=\"when-not-matched-by-source-clauses-for-the-merge-command\">“when not matched by source” clauses for the Merge command</h2>\n<p>The merge command enables updating an existing Delta table (target) with information in a source table. Previously only two clauses were supported; “when matched” which allows updating or deleting a target row, and “when not matched” which allows inserting a source row. “When not matched by source” enables you to <code>UPDATE</code> or <code>DELETE</code> rows in the target table that do not have corresponding records in the source table.</p>\n<p>Suppose you have the following target table with customers, their ages, the last time they were seen in your store, and an active flag. A customer will be considered active if they’ve gone to your store in the last month.</p>\n<p>Imagine you’re running this analysis on April 12th, 2023. Here’s the existing customer table.</p>\n<pre><code><span><span>+---+----+---+----------+--------+</span></span>\n<span><span>| id|name|age| last_seen|  status|</span></span>\n<span><span>+---+----+---+----------+--------+</span></span>\n<span><span>|  0| Bob| 23|2022-01-02|inactive|</span></span>\n<span><span>|  1| Sue| 25|2023-04-05|  active|</span></span>\n<span><span>|  2| Jim| 27|2023-02-07|  active| # should be inactive now</span></span>\n<span><span>+---+----+---+----------+--------+</span></span></code></pre>\n<p>You’d like to update the Delta table with the following information:</p>\n<pre><code><span><span>+---+-----+---+------------+</span></span>\n<span><span>| id| name|age|current_date|</span></span>\n<span><span>+---+-----+---+------------+</span></span>\n<span><span>|  0|  Bob| 23|  2023-04-12| # update existing row</span></span>\n<span><span>|  3|Sally| 30|  2023-04-12| # new row</span></span>\n<span><span>+---+-----+---+------------+</span></span></code></pre>\n<p>Here’s a summary of the changes that are needed:</p>\n<ul>\n<li>Bob needs <code>last_seen</code> updated and needs to become <code>active</code></li>\n<li>Sue shouldn’t change</li>\n<li>Jim should be made <code>inactive</code></li>\n<li>Sally should be added and made <code>active</code></li>\n</ul>\n<p>With the new “when not matched by source clause” here’s the Delta Lake code that will allow for this merge logic:</p>\n<pre><code><span><span>(</span></span>\n<span><span>    customers_table.alias(</span><span>\"target\"</span><span>)</span></span>\n<span><span>    .merge(new_df.alias(</span><span>\"source\"</span><span>), </span><span>\"target.id = source.id\"</span><span>)</span></span>\n<span><span>    .whenMatchedUpdate(</span></span>\n<span><span>        set</span><span>=</span><span>{</span><span>\"target.last_seen\"</span><span>: </span><span>\"source.current_date\"</span><span>, </span><span>\"target.status\"</span><span>: </span><span>\"'active'\"</span><span>}</span></span>\n<span><span>    )</span></span>\n<span><span>    .whenNotMatchedInsert(</span></span>\n<span><span>        values</span><span>=</span><span>{</span></span>\n<span><span>            \"target.id\"</span><span>: </span><span>\"source.id\"</span><span>,</span></span>\n<span><span>            \"target.name\"</span><span>: </span><span>\"source.name\"</span><span>,</span></span>\n<span><span>            \"target.age\"</span><span>: </span><span>\"source.age\"</span><span>,</span></span>\n<span><span>            \"target.last_seen\"</span><span>: </span><span>\"source.current_date\"</span><span>,</span></span>\n<span><span>            \"target.status\"</span><span>: </span><span>\"'active'\"</span><span>,</span></span>\n<span><span>        }</span></span>\n<span><span>    )</span></span>\n<span><span>    .whenNotMatchedBySourceUpdate(</span></span>\n<span><span>        condition</span><span>=</span><span>\"target.last_seen &lt;= (current_date() - INTERVAL '30' DAY)\"</span><span>,</span></span>\n<span><span>        set</span><span>=</span><span>{</span><span>\"target.status\"</span><span>: </span><span>\"'inactive'\"</span><span>},</span></span>\n<span><span>    )</span></span>\n<span><span>    .execute()</span></span>\n<span><span>)</span></span></code></pre>\n<p>Check to make sure the <code>MERGE</code> was properly performed:</p>\n<pre><code><span><span>DeltaTable.forPath(spark, \"tmp/customers\").toDF().show()</span></span>\n<span><span></span></span>\n<span><span>+---+-----+---+----------+--------+</span></span>\n<span><span>| id| name|age| last_seen|  status|</span></span>\n<span><span>+---+-----+---+----------+--------+</span></span>\n<span><span>|  0|  Bob| 23|2023-04-12|  active|</span></span>\n<span><span>|  1|  Sue| 25|2023-04-05|  active|</span></span>\n<span><span>|  2|  Jim| 27|2023-02-07|inactive|</span></span>\n<span><span>|  3|Sally| 30|2023-04-12| status of <code>inactive</code>. Without the “when not matched by source” clause this same operation would require two separate writes to the table: (1) a <code>MERGE</code> operation to update the table with the new information and (2) an <code>UPDATE</code> operation to set customer’s status to <code>inactive</code> if they haven’t been seen in 30 days.</p>\n<h2 id=\"create-table-like-to-create-empty-delta-tables\">CREATE TABLE LIKE to create empty Delta tables</h2>\n<p><code>CREATE TABLE LIKE</code> makes it easy to build a new table with the same columns and schema as an existing table.</p>\n<p>Let’s create a Delta table and then create another table with the same schema.</p>\n<p>Start by creating a Delta table:</p>\n<pre><code><span><span>df = spark.createDataFrame(</span></span>\n<span><span>    [(0, \"Bob\", \"Loblaw\", 23), (1, \"Sue\", \"Grafton\", None), (2, \"Jim\", \"Carrey\", 61)]</span></span>\n<span><span>).toDF(\"id\", \"first_name\", \"last_name\", \"age\")</span></span>\n<span><span></span></span>\n<span><span>df.write.format(\"delta\").saveAsTable(\"default.famous_people\")</span></span></code></pre>\n<p>Now use <code>CREATE TABLE LIKE</code> to create an empty table with the same columns and data types.</p>\n<pre><code><span><span>spark.sql(\"CREATE TABLE famous_people_duplicate LIKE famous_people\")</span></span></code></pre>\n<p>We can confirm that the table is empty:</p>\n<pre><code><span><span>spark.sql(\"select * from famous_people_duplicate\").show()</span></span></code></pre>\n<p><code>CREATE TABLE LIKE</code> is a handy feature whenever you want to replicate a table schema exactly without manually typing all the code for the column names and column types.</p>\n<h2 id=\"support-reading-change-data-feed-cdf-in-sql-queries\">Support reading Change Data Feed (CDF) in SQL queries</h2>\n<p>Delta Lake supports a Change Data Feed (CDF) which tracks row-level changes made to a Delta table over time.
