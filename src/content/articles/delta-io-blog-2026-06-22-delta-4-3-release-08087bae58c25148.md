contentHtml: "<div>  <p>With <a target=\"_blank\" href=\"https://delta.io/blog/2026-02-02-delta-catalog-managed-tables/\">catalog-managed tables</a> established as Delta’s new foundation, 4.3 turns to what’s built on top of it. Delta 4.3 integrates with the Unity Catalog Delta APIs, a new catalog integration layer that routes table operations through intent-based catalog APIs so the catalog can validate and apply every commit. Advancements in UniForm integration and streaming make catalog-managed tables the natural target for more workloads. The result is a more robust ecosystem, one where engines like Spark, DuckDB, and Flink can all operate on the same set of tables through the same catalog.</p>\n<h2 id=\"unity-catalog-delta-apis\">Unity Catalog Delta APIs</h2>\n<p>Every operation on a catalog-managed table now flows through the Unity Catalog Delta APIs: table <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6796\">loads</a>, <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6826\">CREATE and CTAS</a>, <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6859\">REPLACE, CREATE OR REPLACE, and RTAS</a>, and <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6840\">metadata-changing writes</a> such as DML schema evolution. Delta 4.2 makes commits catalog-coordinated while Delta 4.3 brings the rest of the operation surface under unified APIs.</p>\n<p>As a result, the catalog can provide stronger guarantees. Server-side commit validation rejects malformed or conflicting commits before they corrupt table state, and server-advertised table features let an engine know what features a new table should support, as defined by the catalog. Moreover, intent-based metadata updates let engines declare property and domain metadata changes that the catalog validates and applies. Together, these checks give every engine that connects to the catalog the same well-defined behavior, including Spark and every Kernel-based connector that adopts the UC Delta APIs.</p>\n<p>Here’s what this looks like in practice. Launch Spark 4.1 with Delta 4.3 and the Unity Catalog Spark connector 0.5, and point a catalog at your UC endpoint:</p>\n<pre><code><span><span>$SPARK_HOME/bin/spark-sql</span></span>\n<span><span>--packages</span><span> io.delta:delta-spark_4.1_2.13:4.3.0,io.unitycatalog:unitycatalog-spark_4.1_2.13:0.5.0</span></span>\n<span><span>--conf</span><span> spark.sql.extensions=io.delta.sql.DeltaSparkSessionExtension</span></span>\n<span><span>--conf</span><span> spark.sql.catalog.spark_catalog=org.apache.spark.sql.delta.catalog.DeltaCatalog</span></span>\n<span><span>--conf</span><span> spark.sql.catalog.</span><span>&lt;</span><span>catalog_nam</span><span>e</span><span>&gt;</span><span>=io.unitycatalog.spark.UCSingleCatalog</span></span>\n<span><span>--conf</span><span> spark.sql.catalog.</span><span>&lt;</span><span>catalog_nam</span><span>e</span><span>&gt;</span><span>.uri=</span><span>&lt;</span><span>uc_UR</span><span>L</span><span>&gt;</span><span> #Note: no /api suffix needed</span></span>\n<span><span>--conf</span><span> spark.sql.catalog.</span><span>&lt;</span><span>catalog_nam</span><span>e</span><span>&gt;</span><span>.token=</span><span>&lt;</span><span>uc_toke</span><span>n</span><span>&gt;</span></span>\n<span><span>--conf</span><span> spark.sql.defaultCatalog=</span><span>&lt;</span><span>catalog_nam</span><span>e</span><span>&gt;</span></span></code></pre>\n<p>From there, every operation routes through the catalog. We’ll land a <code>clickstream</code> table here:</p>\n<pre><code><span><span>CREATE</span><span> TABLE</span><span> prod</span><span>.</span><span>consumer</span><span>.</span><span>clickstream</span><span> (</span></span>\n<span><span>  event_date  </span><span>DATE</span><span>,</span></span>\n<span><span>  event_type  STRING,</span></span>\n<span><span>  user_id     STRING</span></span>\n<span><span>) </span><span>USING</span><span> DELTA CLUSTER </span><span>BY</span><span> (event_date);</span></span>\n<span></span>\n<span><span>INSERT INTO</span><span> prod</span><span>.</span><span>consumer</span><span>.clickstream </span><span>VALUES</span></span>\n<span><span>  (</span><span>'2026-06-01'</span><span>, </span><span>'click'</span><span>,    </span><span>'user_1'</span><span>),</span></span>\n<span><span>  (</span><span>'2026-06-01'</span><span>, </span><span>'purchase'</span><span>, </span><span>'user_2'</span><span>);</span></span>\n<span></span>\n<span><span>ALTER</span><span> TABLE</span><span> prod</span><span>.</span><span>consumer</span><span>.clickstream </span><span>ADD</span><span> COLUMNS (device_type STRING);</span></span></code></pre>\n<h2 id=\"delta-uniform-improvements\">Delta UniForm Improvements</h2>\n<p>UniForm keeps Apache Iceberg metadata in sync with Delta commits so Iceberg readers can query Delta tables without copying data. 4.3 advances UniForm on two fronts:</p>\n<p>First, conversion is now atomic and incremental: <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6717\">large commits convert to Iceberg metadata atomically within the Delta transaction</a>, and <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6834\">incremental conversion</a> regenerates only the changed log range instead of the full snapshot on every commit.</p>\n<p>Second, <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6783\">IcebergCompatV3 (experimental)</a> enables Delta tables that use deletion vectors (DVs) to also have UniForm enabled. With <code>delta.enableIcebergCompatV3=true</code>, DVs and UniForm coexist on the same table, and the new mode adds geometry/geography compatibility with the latest Iceberg writer protocol.</p>\n<p>To expose a table to Iceberg readers without copying data, we can create it with IcebergCompatV3, so UniForm and Deletion Vectors are enabled together from the start:</p>\n<pre><code><span><span>-- Create a clickstream table with UniForm and Deletion Vectors together</span></span>\n<span><span>CREATE</span><span> TABLE</span><span> prod</span><span>.</span><span>consumer</span><span>.</span><span>clickstream_v3</span><span> (</span></span>\n<span><span>  event_date </span><span>DATE</span><span>,</span></span>\n<span><span>  event_type STRING,</span></span>\n<span><span>  user_id    STRING</span></span>\n<span><span>)</span></span>\n<span><span>USING</span><span> DELTA</span></span>\n<span><span>TBLPROPERTIES (</span></span>\n<span><span>  'delta.enableIcebergCompatV3'</span><span>          =</span><span> 'true'</span><span>,</span></span>\n<span><span>  'delta.universalFormat.enabledFormats'</span><span> =</span><span> 'iceberg'</span><span>,</span></span>\n<span><span>  'delta.feature.catalogManaged'</span><span>         =</span><span> 'supported'</span><span>,</span></span>\n<span><span>  'delta.enableDeletionVectors'</span><span>          =</span><span> 'true'</span></span>\n<span><span>);</span></span></code></pre>\n<p>UniForm is now built against Iceberg-spark 1.11.0 and <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6858\">supports both Spark 4.0 and Spark 4.1</a>.</p>\n<h2 id=\"streaming-and-change-data-feed-cdf\">Streaming and Change Data Feed (CDF)</h2>\n<p>Delta 4.3 brings Structured Streaming and Change Data Feed to catalog-managed Delta tables from Apache Spark. Spark streaming sources now support all standard read options, and catalog-driven batch CDC lets an external engine both stream from and replay changes on catalog-managed Delta tables.</p>\n<p>As new events stream into <code>clickstream</code>, downstream consumers can replay what changed. <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6794\">Batch CDC</a> lands as <code>SELECT … CHANGES FROM VERSION/TIMESTAMP</code>, with <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6886\">deletion-vector awareness</a>, gated behind <code>spark.databricks.delta.changelogV2.enabled</code>:</p>\n<pre><code><span><span>SET</span><span> spark</span><span>.</span><span>databricks</span><span>.</span><span>delta</span><span>.</span><span>changelogV2</span><span>.</span><span>enabled</span><span> =</span><span> true;</span></span>\n<span></span>\n<span><span>-- Replay changes from a specific version</span></span>\n<span><span>SELECT</span><span> *</span><span> FROM</span><span> prod</span><span>.</span><span>consumer</span><span>.clickstream </span><span>CHANGES</span><span> FROM</span><span> VERSION</span><span> 0</span><span>;</span></span>\n<span></span>\n<span><span>-- Or from a point in time</span></span>\n<span><span>SELECT</span><span> *</span><span> FROM</span><span> prod</span><span>.</span><span>consumer</span><span>.clickstream </span><span>CHANGES</span><span> FROM</span><span> TIMESTAMP</span><span> '2026-06-01 00:00:00'</span><span>;</span></span></code></pre>\n<p>Change Data Feed also extends to Delta Sharing. Once <code>clickstream</code> is shared with a partner, streaming queries on shared Delta-format tables can now <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6627\">read the Change Data Feed</a> of a shared table and <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6549\">run backfill-then-stop pipelines via <code>Trigger.AvailableNow</code></a> (on top of the <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/6740\">delta-sharing-client 1.4.0 upgrade</a>).</p>\n<h2 id=\"conclusion\">Conclusion</h2>\n<p>Delta 4.3 strengthens catalog-managed Delta tables across the stack. The UC Delta APIs bring every table operation under a single, catalog-validated commit path. Streaming and CDF now work on catalog-managed Delta tables from Apache Spark. UniForm’s Iceberg conversion becomes atomic and incremental. Together these build directly on the <a target=\"_blank\" href=\"https://delta.io/blog/2026-02-02-delta-catalog-managed-tables/\">catalog-managed tables</a> foundation, toward an ecosystem where engines like Spark, DuckDB, Flink, and any client integrated with Delta-Kernel can all operate on the same tables through the same catalog.</p>\n<p>For the complete list of changes, fixes, and contributor acknowledgments, see the <a target=\"_blank\" href=\"https://github.com/delta-io/delta/releases/tag/v4.3.0\">Delta 4.3.0 release notes on GitHub</a>.</p>  </div>"
