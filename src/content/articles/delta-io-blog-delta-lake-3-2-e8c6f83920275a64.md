target=\"_blank\" href=\"https://spark.apache.org/releases/spark-release-3-5-0.html\">Apache Spark 3.5</a>, with features that improve the performance and interoperability of Delta Lake.</p>\n<p>This release includes many improvements and bug fixes, but we’d like to highlight the following:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/#liquid-clustering\">Liquid clustering</a>: A more performant, flexible table layout</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/#hudi-write-support-in-uniform\">Hudi write support in UniForm</a>: Expansion of the popular UniForm feature to Hudi</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/#type-widening\">Type widening</a>: An easier way to handle schema updates when data changes</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/#vacuum-inventory-support\">Vacuum inventory support</a>: Faster VACUUM operations for large tables</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/#delta-kernel-updates\">Delta Kernel updates</a>: Time travel support, metadata read improvements, additional protocol support for the connector ecosystem and preview version of APIs to create and append data to Delta tables.</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/#deletion-vectors-read-performance-improvements\">Deletion Vectors read performance improvements</a>: Faster Deletion Vectors read performance</li>\n</ul>\n<h2 id=\"whats-new-in-delta-lake-32\">What’s new in Delta Lake 3.2?</h2>\n<p>Building on the features released in Delta Lake 3.0 and 3.1, Delta Lake 3.2 introduces a host of performance enhancements and optimizations.</p>\n<h3 id=\"liquid-clustering\">Liquid clustering</h3>\n<p>We are pleased to announce the GA of <a target=\"_blank\" href=\"https://docs.delta.io/3.1.0/delta-clustering.html\">Liquid Clustering</a> in Delta Lake 3.2.0. The key changes are as follows:</p>\n<ul>\n<li>Support for ZCube-based incremental clustering: A ZCube is a group of files with Hilbert-clustered data produced by the same OPTIMIZE command. Already clustered files are tagged in the file metadata (that is, in the Delta log) by ZCube ID, and new <code>OPTIMIZE</code> commands will only rewrite unclustered files. This significantly limits the write amplification.</li>\n<li>Support for ALTER TABLE … CLUSTER BY to change clustering columns</li>\n<li>Support for DESCRIBE DETAIL to inspect the clustering columns</li>\n<li>Support for DeltaTable <a target=\"_blank\" href=\"https://docs.delta.io/3.2.0/api/scala/spark/io/delta/tables/DeltaTableBuilder.html#clusterBy(colNames:String*):io.delta.tables.DeltaTableBuilder\">clusterBy API</a> in Scala and Python.</li>\n</ul>\n<p>Liquid Clustering is fully pluggable in Delta Lake, allowing the open-source community to contribute to other clustering algorithms. The default technique in Liquid Clustering uses <a target=\"_blank\" href=\"https://en.wikipedia.org/wiki/Hilbert_curve\">Hilbert Curve</a>, a continuous fractal space-filling curve as a multi-dimensional clustering technique, which significantly improves data skipping over <code>ZORDER</code>. We encourage and are looking for contributions of different clustering techniques.</p>\n<h3 id=\"hudi-write-support-in-uniform\">Hudi write support in UniForm</h3>\n<p><a target=\"_blank\" href=\"https://docs.delta.io/latest/delta-uniform.html\">Delta Universal Format</a> enables you to write a single copy of your data and make it available to any engine that supports <a target=\"_blank\" href=\"https://delta.io/\">Delta Lake</a>, <a target=\"_blank\" href=\"https://iceberg.apache.org/\">Iceberg</a>, and now in Delta 3.2, <a target=\"_blank\" href=\"https://hudi.apache.org/\">Hudi</a>. Delta automatically generates metadata needed for Hudi clients, so users don’t have to manage manual conversions to work across ecosystems. Now with Hudi support, Delta is the universal format, unifying all three open table formats.</p>\n<h3 id=\"type-widening\">Type Widening</h3>\n<p>We are excited to introduce the Preview of <a target=\"_blank\" href=\"https://docs.delta.io/latest/delta-type-widening.html\">Type Widening</a> in Delta 3.2, which addresses one of the significant challenges in ETL processes—continuously evolving data schemas. This new feature allows the widening of data types, such as evolving a column from INT to LONG without rewriting data. Type changes can be applied manually using the ALTER TABLE CHANGE COLUMN TYPE command or automatically using schema evolution in INSERT and MERGE operations. By enabling this, Delta Lake not only supports <a target=\"_blank\" href=\"https://delta.io/blog/2023-02-08-delta-lake-schema-evolution/\">schema evolution</a> but also ensures seamless data ingestion and processing by automatically upcasting data types during reads.</p>\n<h3 id=\"vacuum-inventory-support\">Vacuum inventory support</h3>\n<p>Delta Lake 3.2 introduces <a target=\"_blank\" href=\"https://docs.delta.io/3.2.0/delta-utility.html#inventory-table\">vacuum inventory support</a>, a feature that allows users to specify an inventory table in a VACUUM command. By utilizing an inventory table, the VACUUM operation selectively processes only the files listed, bypassing the labor-intensive task of scanning the entire directory of a table. For large tables in particular, the difference in performance can be dramatic, making data management tasks both more efficient and cost-effective. Stay tuned for a deep dive blog post on the origin of this feature, coming soon.</p>\n<h3 id=\"delta-kernel-updates\">Delta Kernel updates</h3>\n<p>The Delta Kernel project is a set of Java libraries (<a target=\"_blank\" href=\"https://github.com/delta-incubator/delta-kernel-rs\">Rust</a> will be coming soon!) for building Delta connectors that can read (and, soon, write to) Delta tables without the need to understand the <a target=\"_blank\" href=\"https://github.com/delta-io/delta/blob/master/PROTOCOL.md\">Delta protocol details</a>). In this release, we improved the read support to make it production-ready by adding numerous performance improvements, additional functionality, improved protocol support, and fixing any rough edges.</p>\n<ul>\n<li>Support for time travel. Now you can read a table snapshot at a <a target=\"_blank\" href=\"https://docs.delta.io/3.2.0/api/java/kernel/io/delta/kernel/Table.html#getSnapshotAsOfVersion-io.delta.kernel.client.TableClient-long-\">version id</a> or snapshot at a <a target=\"_blank\" href=\"https://docs.delta.io/3.2.0/api/java/kernel/io/delta/kernel/Table.html#getSnapshotAsOfTimestamp-io.delta.kernel.client.TableClient-long-\">timestamp</a>.</li>\n<li>Improved Delta protocol support.\n<ul>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2826\">Support</a> for reading tables with <code><a target=\"_blank\" href=\"https://github.com/delta-io/delta/blob/master/PROTOCOL.md#v2-checkpoint-table-feature\">checkpoint v2</a></code>.</li>\n<li>Support for reading tables with <code>timestamp</code> partition type data column.</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2855\">Support</a> for reading tables with column data type <code><a target=\"_blank\" href=\"https://github.com/delta-io/delta/blob/master/PROTOCOL.md#timestamp-without-timezone-timestampntz\">timestamp_ntz</a></code>.</li>\n</ul>\n</li>\n<li>Improved table metadata read performance and reliability on very large tables with millions of files\n<ul>\n<li>Improved <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2872\">checkpoint reading latency</a> by pushing the partition predicate to the checkpoint Parquet reader to minimize reading number of checkpoint files read.</li>\n<li>Improved state reconstruction latency by <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2770\">using</a> <code>LogStore</code>s from <code><a target=\"_blank\" href=\"https://github.com/delta-io/delta/blob/master/storage/src/main/java/io/delta/storage/LogStore.java\">delta-storage</a></code> module for faster <code>listFrom</code> calls.</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2812\">Retry</a> loading the <code>_last_checkpoint</code> checkpoint in case of transient failures. Loading the last checkpoint info from this file helps construct the Delta table state faster.</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2817\">Optimization</a> to minimize the number of listing calls to object store when trying to find a last checkpoint at or before a version.</li>\n</ul>\n</li>\n</ul>\n<p>In this release, we also added a <strong><em>preview version</em></strong> of APIs that allows connectors to:</p>\n<ul>\n<li>Create Delta tables</li>\n<li>Insert data into Delta tables. Current support is for blind appends only.</li>\n<li>Idempotently update the Delta table.</li>\n</ul>\n<p>The above functionality is available both for the partitioned and unpartitioned tables. Refer to the <a target=\"_blank\" href=\"https://github.com/delta-io/delta/tree/branch-3.2/kernel/examples\">examples</a> for sample connector code to create and blind append data to the tables. We are still developing and evolving these APIs. Please give it a try and let us know your feedback.</p>\n<h3 id=\"deletion-vectors-read-performance-improvements\">Deletion Vectors read performance improvements</h3>\n<p>We continue to improve the performance of merge-on-read with Deletion Vectors (DV).</p>\n<ul>\n<li>We <a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/be7183bef85feaebfc928d5f291c5a90246cde87\">improved</a> stability by <a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/be7183bef85feaebfc928d5f291c5a90246cde87\">removing broadcasting of DV information to executors</a>, which reduces drivers’ memory consumption, and prevents potential Driver OOM for very large Delta tables like 1TB+. This work also improves performance by saving us fixed broadcasting overhead in reading small Delta Tables.</li>\n<li>We improved the performance of DV reads with filter queries by enabling <a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/2982\">predicate pushdown and file splitting</a>.</li>\n<li>We benchmarked these improvements using <a target=\"_blank\" href=\"https://www.brooklyndata.co/ideas/2022/11/28/benchmarking-open-table-formats\">a real world workload</a> that uses a combination.</li>\n</ul>\n<p><img alt=\"&quot;Performance chart linear scale&quot;\" src=\"https://delta.io/_astro/fg1.Cb3iU5mb_iOc3h.webp\"></p>\n<p><img alt=\"&quot;Performance chart log scale&quot;\" src=\"https://delta.io/_astro/fg2.C8uC0M1L_Z1WIetQ.webp\"></p>\n<h3 id=\"additional-features\">Additional features</h3>\n<p>This release includes even more features, including the improvements below. Please see the full release notes for more information on all the exciting features and instructions on how to use the release candidate artifacts.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/2e197f130765d91f201b6b649f30190a44304b29\">Support for Vacuum Writer Protocol Check</a>: Delta Spark can now support <code>vacuumProtocolCheck</code> ReaderWriter feature which ensures consistent application of reader and writer protocol checks during <code>VACUUM</code> operations, addressing potential protocol discrepancies and mitigating the risk of data corruption due to skipped writer checks.</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/b15a2c97432c8892f986c1526ceb2c3f63ed5d2c\">In-Commit Timestamp Preview</a>: When enabled, this <a target=\"_blank\" href=\"https://github.com/delta-io/delta/issues/2532\">preview feature</a> persists monotonically increasing timestamps within Delta commits, ensuring they are not affected by file operations. When enabled, time travel queries will yield consistent results, even if the table directory is relocated.</li>\n</ul>\n<h2 id=\"credits\">Credits</h2>\n<p>Thank you to everyone involved with the release of Delta Lake 3.2:</p>\n<p>Adam Binford, Ala Luszczak, Allison Portis, Ami Oka, Andreas Chatzistergiou, Arun Ravi M V, Babatunde Micheal Okutubo, Bo Gao, Carmen Kwan, Chirag Singh, Chloe Xia, Christos Stavrakakis, Cindy Jiang, Costas Zarifis, Daniel Tenedorio, Davin Tjong, Dhruv Arya, Felipe Pessoto, Fred Storage Liu, Fredrik Klauss, Gabriel Russo, Hao Jiang, Hyukjin Kwon, Ian Streeter, Jason Teoh, Jiaheng Tang, Jing Zhan, Jintian Liang, Johan Lasperas, Jonas Irgens Kylling, Juliusz Sompolski, Kaiqi Jin, Lars Kroll, Lin Zhou, Miles Cole, Nick Lanham, Ole Sasse, Paddy Xu, Prakhar Jain, Rachel Bushrian, Rajesh Parangi, Renan Tomazoni Pinzon, Sabir Akhadov, Scott Sandre, Simon Dahlbacka, Sumeet Varma, Tai Le, Tathagata Das, Terry Kim, Thang Long Vu, Tim Brown, Tom van Bussel, Venki Korukanti, Wei Luo, Wenchen Fan, Xupeng Li, Yousof Hosny, Gene Pang, Jintao Shen, Kam Cheung Ting, panbingkun, ram-seek, Sabir Akhadov, sokolat, tangjiafu</p>\n<p>We’d also like to extend special thanks to Scott Sandre for his contributions in making the release.</p>\n<p>And, as always, a huge thank you to the contributions from our open source <a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-2/delta.io/community\">community</a>.</p>\n<p>We are always excited to work with our current contributor community and welcome new members.
