contentHtml: "<div>  <p>We are pleased to announce the release of Delta Lake 3.3 (<a target=\"_blank\" href=\"https://github.com/delta-io/delta/releases/tag/v3.3.0\">release notes</a>) on Apache Spark 3.5.3,\nwith features that improve the performance and interoperability of Delta Lake. Whether you’re\nbuilding scalable pipelines, optimizing queries, or ensuring data governance, this release is\ndesigned to help you achieve more with less effort.</p>\n<p>Let’s dive into the highlights:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-3/#identity-columns\">Identity columns</a> assign unique values for each record inserted into a table</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-3/#vacuum-lite\">VACUUM LITE</a> uses the Delta transaction log to identify unreferenced files for faster table maintenance</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-3/#row-tracking-backfill\">Row Tracking Backfill</a> track row-level lineage in Delta Spark on existing tables</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-3/#version-checksums\">Version Checksums</a> provide stronger consistency guarantees, enhanced performance, and easier debugging</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-3/#Enable-UniForm-on-ALTER\">UniForm ALTER</a> supports enabling UniForm on existing Delta Lake tables without rewriting data</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-3-3/#type-widening-for-delta-kernel\">Type Widening</a> is now supported in Delta Kernel Java and Rust</li>\n</ul>\n<h2 id=\"whats-new-in-delta-lake-33\">What’s new in Delta Lake 3.3?</h2>\n<p>Building on the features released in Delta Lake 3.0+, Delta Lake 3.3 introduces a host of\nperformance enhancements and optimizations.</p>\n<h3 id=\"identity-columns\">Identity Columns</h3>\n<p>Identity Columns are columns in a table that automatically generate a unique ID for each\nnew row. A long-time staple of data warehousing workloads, they commonly serve as primary\nand foreign keys when modeling data. Delta Lake 3.3 supports creating identity columns with unique,\nauto-incrementing ID numbers for each new row. This dramatically simplifies data modeling and\navoids the need to roll manual, brittle solutions. See the documentation for more information.</p>\n<h3 id=\"vacuum-lite\">VACUUM LITE</h3>\n<p>Table maintenance just got easier and faster. With VACUUM LITE, you can clean up unreferenced files\nfaster than ever before. This feature uses the Delta transaction log to identify and remove\noutdated files, delivering 5-10x performance improvements for periodic cleanup tasks. Save time and\nreduce costs with this optimized approach to table maintenance. See github for more information.</p>\n<h3 id=\"row-tracking-backfill\">Row Tracking Backfill</h3>\n<p>Row Tracking is a feature to track row-level lineage in Delta Spark, introduced in Delta 3.2\nfor new tables. With Backfill support, you can now enable Row Tracking on existing tables.\nWhen enabled, users can identify rows across multiple versions of the table and can access this\ntracking information using the two metadata fields Row Id and Row Commit Version. Refer to the\ndocumentation on Row Tracking for more information and examples.</p>\n<h3 id=\"version-checksums\">Version Checksums</h3>\n<p>Delta Lake now includes version checksums for every table commit, bringing stronger consistency\nguarantees and better debugging tools to your data ecosystem. Detailed metrics like file counts,\ntable size, and data distribution histograms enable automatic detection of potential state\ninconsistencies. State validation is performed at every checkpoint, which helps maintain table\nintegrity in distributed environments. The Checksum is also used to bypass the initial Spark\nquery that retrieves the Protocol and Metadata actions, resulting in a decreased snapshot\ninitialization latency. See github for more information.</p>\n<h3 id=\"enable-uniform-on-alter\">Enable UniForm on ALTER</h3>\n<p>Delta Lake now supports enabling UniForm Iceberg on existing tables, without having to rewrite\ndata. This means you can seamlessly read and share tables across Iceberg clients, enhancing\ncompatibility and flexibility for diverse workflows. See the documentation for more details.</p>\n<h3 id=\"type-widening-for-delta-kernel\">Type widening for Delta Kernel</h3>\n<p>The Delta Kernel project is a set of Java and Rust libraries for building Delta connectors\nthat can read and write to Delta tables without needing to understand the Delta protocol\ndetails. Type widening is a feature that allows you to change the type of certain columns\nin a Delta table to a wider type, to accommodate data expansion, without rewriting any\nexisting data. When tables are enabled with type widening, you can manually enable type\nchanges using the ALTER TABLE ALTER COLUMN command. Automatic type migration with schema\nevolution is also enabled for INSERT and MERGE INTO commands.</p>\n<p>In this release, both Kernel implementations now support reading tables with type widening enabled,\nensuring better compatibility and smooth handling of schema changes. Any connectors developed using\neither of the Kernel implementations can now read tables that include any data types eligible\nfor type widening.</p>\n<h2 id=\"additional-features\">Additional features</h2>\n<p>These are just a few highlights. Additional features include:</p>\n<ul>\n<li>\n<p>Liquid Clustering convenience and performance features:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/3793\">OPTIMIZE FULL</a>: Recluster all records in a table for peak performance.</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/3174\">Unpartitioned Tables</a>: Enable clustering on an existing, unpartitioned table.</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/pull/3251\">External Locations</a>: Create clustered tables from external storage.</li>\n</ul>\n</li>\n<li>\n<p>UniForm performance optimizations and functionality:</p>\n<ul>\n<li>Support for <a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/7a0db43df1ef8236e4db8a57837734b83ed15153\">timestamp-type partition columns</a> for UniForm Iceberg</li>\n<li>Automatic manifest cleanups via <a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/7bb979205d7eb4cd8aaa04da8fd960f3862b53b7\">expireSnapshot</a> whenever OPTIMIZE is run on the Delta table</li>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/dd39415912f6009fb9e5d2f4057288bb1e9fd117\">List and map</a> data types for UniForm Hudi</li>\n</ul>\n</li>\n<li>\n<p>Expanded support in Delta Kernel:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/d467f520d\">Expired log file cleanup</a> as part of checkpointing</li>\n<li>Support for <a target=\"_blank\" href=\"https://github.com/delta-io/delta/commit/3cebe546a\">data skipping</a> on timestamp and timestamp_ntz type columns</li>\n</ul>\n</li>\n</ul>\n<p>All these and many more features and bug fixes are outlined in the Delta 3.3 <a target=\"_blank\" href=\"https://github.com/delta-io/delta/releases/tag/v3.3.0\">release notes</a>.\nReady to get started? Explore the <a target=\"_blank\" href=\"https://delta.io/\">Delta Lake Documentation</a> for all the details,\nand upgrade to Delta Lake 3.3.0 today.</p>\n<h2 id=\"credits\">Credits</h2>\n<p>Thank you
