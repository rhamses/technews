contentHtml: "<div>  <p>This post shows you how to use Delta Lake without Spark.</p>\n<p>You might want to use Delta Lake without Spark because:</p>\n<ul>\n<li>You don’t want to learn Spark</li>\n<li>Your team doesn’t use Spark</li>\n<li>You don’t want to use the Java Virtual Machine (JVM)</li>\n<li>You are working with relatively small datasets</li>\n</ul>\n<p>You can use Delta Lake without Spark using many other languages, like SQL, Python, and Rust. This post will show you examples of the most popular ways of using Delta Lake without Spark.</p>\n<p>Let’s jump in! 🪂</p>\n<h2 id=\"how-to-use-delta-lake-without-spark\">How to use Delta Lake without Spark</h2>\n<p>There are many ways to use Delta Lake without Spark.</p>\n<p>Let’s group them into two categories for clarity:</p>\n<ul>\n<li>dedicated <strong>Delta Connectors</strong> let you use Delta Lake from engines like Flink, Hive, Trino, PrestoDB, and many others</li>\n<li>the <a target=\"_blank\" href=\"https://delta-io.github.io/delta-rs/\"><strong>delta-rs</strong></a> package lets you use Delta Lake in Rust or Python, e.g. with pandas, polars, Dask, Daft, DuckDB and many others</li>\n</ul>\n<p>This post will show you a brief code example for each of these options to use Delta Lake without Spark. You can also find <a target=\"_blank\" href=\"https://delta.io/integrations\">the full list of integrations</a> on the Delta Lake website.</p>\n<h2 id=\"delta-lake-without-spark-dedicated-connectors\">Delta Lake without Spark: Dedicated Connectors</h2>\n<p>Many non-Spark query engines have dedicated connectors to use Delta Lake. These are all based on <a target=\"_blank\" href=\"https://docs.delta.io/latest/delta-standalone.html\">Delta Standalone</a>: a JVM library for Java / Scala that can be used to read from and write to Delta tables. You can use Delta Standalone to build your own Delta connector for services that are not listed on the Integrations page.</p>\n<p><em>Note: if you want to avoid the JVM entirely, refer to the <a target=\"_blank\" href=\"https://delta.io/blog/delta-lake-without-spark/#delta-lake-without-spark-with-delta-rs\">delta-rs</a> section below</em></p>\n<p>You can use Delta Lake without Spark with a dedicated Delta connector from:</p>\n<ul>\n<li>Apache Flink</li>\n<li>Apache Hive</li>\n<li>PrestoDB</li>\n<li>Trino</li>\n<li>Amazon Athena</li>\n<li>Snowflake</li>\n<li>Google BigQuery</li>\n<li>Microsoft Fabric</li>\n</ul>\n<p>Some of these connectors support limited Delta Lake functionality. Make sure to check the “Known Limitations” section for each connector to learn more.</p>\n<h3 id=\"delta-lake-without-spark-apache-flink\">Delta Lake without Spark: Apache Flink</h3>\n<p><img src=\"https://delta.io/_astro/image1.C4NhKdGk_19xr2U.webp\"></p>\n<p>You can use the <a target=\"_blank\" href=\"https://github.com/delta-io/delta/tree/master/connectors/flink/\">Flink/Delta connector</a> to use Delta Lake from Apache Flink. The connector supports data writes in both batch and streaming mode.</p>\n<p>The connector includes:</p>\n<ul>\n<li><code>DeltaSink</code> for writing data from Apache Flink to a Delta table.</li>\n<li><code>DeltaSource</code> for reading Delta tables using Apache Flink.</li>\n</ul>\n<p>You can use Delta Lake with the Flink Python or SQL API.</p>\n<h4 id=\"delta-lake-with-flink-python\">Delta Lake with Flink: Python</h4>\n<p>The code below is an example of how you can write data to a partitioned table using one partitioning column <code>surname</code>.</p>\n<pre><code><span><span>    import io.delta.flink.sink.DeltaBucketAssigner;</span></span>\n<span><span>    import io.delta.flink.sink.DeltaSinkBuilder;</span></span>\n<span><span></span></span>\n<span><span>    public DataStream&lt;RowData&gt; createDeltaSink(</span></span>\n<span><span>            DataStream&lt;RowData&gt; stream,</span></span>\n<span><span>            String deltaTablePath) {</span></span>\n<span><span>        String[] partitionCols = { \"surname\" };</span></span>\n<span><span>        DeltaSink&lt;RowData&gt; deltaSink = DeltaSink</span></span>\n<span><span>            .forRowData(</span></span>\n<span><span>                new Path(deltaTablePath),</span></span>\n<span><span>                new Configuration(),</span></span>\n<span><span>                rowType)</span></span>\n<span><span>            .withPartitionColumns(partitionCols)</span></span>\n<span><span>            .build();</span></span>\n<span><span>        stream.sinkTo(deltaSink);</span></span>\n<span><span>        return stream;</span></span>\n<span><span>    }</span></span></code></pre>\n<p>You can also use Delta Lake’s time-travel functionality from Apache Flink. For example like this:</p>\n<pre><code><span><span>    public DataStream&lt;RowData&gt; createBoundedDeltaSourceWithTimeTravel(</span></span>\n<span><span>            StreamExecutionEnvironment env,</span></span>\n<span><span>            String deltaTablePath) {</span></span>\n<span><span></span></span>\n<span><span>        DeltaSource&lt;RowData&gt; deltaSource = DeltaSource</span></span>\n<span><span>            .forBoundedRowData(</span></span>\n<span><span>                new Path(deltaTablePath),</span></span>\n<span><span>                new Configuration())</span></span>\n<span><span>            // could also use `.versionAsOf(314159)`</span></span>\n<span><span>            .timestampAsOf(\"2022-06-28 04:55:00\")</span></span>\n<span><span>            .build();</span></span>\n<span><span></span></span>\n<span><span>        return env.fromSource(deltaSource, WatermarkStrategy.noWatermarks(), \"delta-source\");</span></span>\n<span><span>    }</span></span></code></pre>\n<h4 id=\"delta-lake-with-flink-sql\">Delta Lake with Flink: SQL</h4>\n<p>Starting from Flink version 3.0.0, the Delta connector can be used for Flink SQL jobs. Both Delta Source and Delta Sink can be used as Flink Tables for SELECT and INSERT queries.</p>\n<p>For example, you can load an entire Delta table into another Delta table using:</p>\n<pre><code><span><span>    INSERT INTO sinkTable SELECT * FROM sourceTable;</span></span></code></pre>\n<p>In the SQL query above, <code>sourceTable</code> and <code>sinkTable</code> both refer to Delta tables configured using the Delta/Flink connector. The table schema’s must match.</p>\n<p>Or to create a new, partitioned table:</p>\n<pre><code><span><span>    CREATE TABLE testTable (</span></span>\n<span><span>        id BIGINT,</span></span>\n<span><span>        data STRING,</span></span>\n<span><span>        part_a STRING,</span></span>\n<span><span>        part_b STRING</span></span>\n<span><span>      )</span></span>\n<span><span>      PARTITIONED BY (part_a, part_b);</span></span>\n<span><span>      WITH (</span></span>\n<span><span>        'connector' = 'delta',</span></span>\n<span><span>        'table-path' = '&lt;path-to-table&gt;',</span></span>\n<span><span>        '&lt;arbitrary-user-define-table-property' = '&lt;value&gt;',</span></span>\n<span><span>        '&lt;delta.*-properties&gt;' = '&lt;value'&gt;</span></span>\n<span><span>    );</span></span></code></pre>\n<p>You do not need to write any Spark to use Delta Lake with Apache Flink.</p>\n<p>Note that the Flink/Delta SQL connector must be used together with a Delta Catalog. Trying to execute SQL queries on Delta table using Flink API without Delta Catalog configured will cause the SQL job to fail.</p>\n<h4 id=\"known-limitations\">Known Limitations</h4>\n<ul>\n<li>Only <code>append</code> write operations are currently supported; no <code>overwrite</code> or <code>upsert</code>.</li>\n<li>Azure Blob Storage currently only supports reading. The Metadata and Computed columns are currently not supported. You can use this connector to query data from Delta tables in Hive. You cannot use it to write data from Hive to Delta tables.</p>\n<p>To work with Delta Lake, you will need to define an external Hive table pointing to a Delta table, for example on S3 like this:</p>\n<pre><code><span><span>    CREATE EXTERNAL TABLE deltaTable(col1 INT, col2 STRING)</span></span>\n<span><span>    STORED BY 'io.delta.hive.DeltaStorageHandler'</span></span>\n<span><span>    LOCATION '/delta/table/path'</span></span></code></pre>\n<p>The table schema in the CREATE TABLE statement should match the schema of the Delta table you are reading.</p>\n<p>Once you have defined your external Hive table, you can then query it as follows:</p>\n<pre><code><span><span>    select * from deltaTable;</span></span></code></pre>\n<p>You do not need to write any Spark to use Delta Lake with Apache Hive.</p>\n<h4 id=\"known-limitations-1\">Known Limitations</h4>\n<ul>\n<li>This connector is READ ONLY. This connector is based on the Hive connector and shares a lot of the same configuration options.</p>\n<p>Your Delta table will need to be registered in a Hive metastore.</p>\n<p>You can create a Presto table from an existing Delta table on S3 as follows:</p>\n<pre><code><span><span>    CREATE TABLE sales.apac.sales_data_new (sampleColumn INT)</span></span>\n<span><span>    WITH (external_location = 's3://db-sa-datasets/presto/sales_data_new');</span></span></code></pre>\n<p>To register a table in the Hive metastore, you don’t need to pass the full schema of the table as the Delta Lake connector gets the schema from the metadata located at the Delta Lake table location. To get around the <code>no columns error</code> in Hive metastore, provide a sample column as schema of the Delta table being registered.</p>\n<p>To access a Delta table <code>sales_data</code> that is already registered in the Hive metastore as part of the <code>apac</code> database and <code>sales</code> Catalog, you can simply run:</p>\n<pre><code><span><span>    SELECT * FROM sales.apac.sales_data LIMIT 200;</span></span></code></pre>\n<p>You can also query the Delta table directly from S3 by passing the <code>path</code>:</p>\n<pre><code><span><span>    SELECT * FROM sales.\"$path$\".\"s3://db-sa-datasets/presto/sales_data\" LIMIT 200;</span></span></code></pre>\n<p>You can travel back to specific versions of your Delta table by adding the version to the table name as follows:</p>\n<pre><code><span><span>    SELECT * FROM sales.apac.\"sales_data@v4\" LIMIT 200;</span></span></code></pre>\n<h4 id=\"known-limitations-2\">Known Limitations</h4>\n<ul>\n<li>This connector is READ ONLY. You can then use SQL to query and transform your Delta tables. Note that your Delta tables must be registered with a metastore, e.g. Hive metastore or AWS Glue.</p>\n<p>The Trino connector supports reading and writing operations. You can <a target=\"_blank\" href=\"https://trino.io/docs/current/connector/delta-lake.html#data-management\">append, overwrite and merge</a> your Delta tables.</p>\n<p>For example, you can create a Delta Lake table, add some data, modify some data and add more data like this:</p>\n<pre><code><span><span>    CREATE TABLE users(id int, name varchar) WITH (column_mapping_mode = 'name');</span></span>\n<span><span>    INSERT INTO users VALUES (1, 'Alice'), (2, 'Bob'), (3, 'Mallory');</span></span>\n<span><span>    ALTER TABLE users DROP COLUMN name;</span></span>\n<span><span>    INSERT INTO users VALUES 4;</span></span></code></pre>\n<p>Use the following statement to look at all data in the table:</p>\n<pre><code><span><span>    &gt; Trino detects write collisions on these storage systems when writing from multiple Trino clusters, or from other query engines.</li>\n<li>Writes to <a target=\"_blank\" href=\"https://trino.io/docs/current/object-storage/legacy-s3.html\">Amazon S3</a> and S3-compatible storage must be enabled with the <code>delta.enable-non-concurrent-writes</code> property. Writes to S3 can safely be made from multiple Trino clusters; however, write collisions are not detected when writing concurrently from other Delta Lake engines. You must make sure that no concurrent data modifications are run to avoid data corruption.</li>\n</ul>\n<h4 id=\"data-type-mapping\">Data Type Mapping</h4>\n<ul>\n<li>Trino and Delta Lake each support data types that the other does not.
