contentHtml: "<div>  <p>Delta Lake provides a robust foundation for managing data with ACID compliance, schema evolution,\nand transactional consistency. It enables organizations to create a unified analytics platform with\na single source of truth, improving governance, and reducing operational overhead.</p>\n<p>However, some workloads are particularly challenging to port to a data lake environment due to their\ndemanding performance requirements. <strong>Customer-facing analytics</strong> is one such workload, requiring\nsub-second query responses and high concurrency. In this blog, we’ll explore how to leverage Delta Kernel\nand the open-source query engine StarRocks to quickly integrate with Delta Lake and make customer-facing\nanalytics directly on open data formats possible.</p>\n<h2 id=\"the-challenge-integrating-with-delta-lake\">The Challenge: Integrating With Delta Lake</h2>\n<p>Delta Lake is powerful, but integrating with it with a query engine presents significant challenges:</p>\n<h3 id=\"complex-protocols\">Complex Protocols</h3>\n<p>Delta Lake’s transaction log and metadata format are intricate. A query engine must interpret\nthe Delta log to read or write data correctly, which tracks changes, schema, and partition\ninformation. With new features like <strong>Deletion Vectors</strong> or <strong>Column Mapping</strong>, keeping up with\nprotocol updates becomes increasingly complex.</p>\n<h3 id=\"optimizing-performance\">Optimizing Performance</h3>\n<p>Efficiently querying Delta Lake requires more than just reading Parquet files. The integration\nmust optimize I/O operations, handle metadata caching, and leverage partition pruning to minimize\ndata scans. Without these optimizations, query performance can degrade significantly, especially at scale.</p>\n<h3 id=\"connector-fragmentation\">Connector Fragmentation</h3>\n<p>Delta Lake’s rapid innovation and introduction of features like\n<a target=\"_blank\" href=\"https://delta.io/blog/2023-07-05-deletion-vectors/\"><strong>Deletion Vectors</strong></a>\nand <a target=\"_blank\" href=\"https://delta.io/blog/liquid-clustering/\"><strong>Liquid Clustering</strong></a> have significantly\nenhanced performance and flexibility. However, this pace of innovation presents challenges for connectors.</p>\n<p>Each new feature requires connectors to update their implementations, leading to fragmentation.\nIt becomes less predictable for customers to know which features are supported by which connectors,\ncreating inconsistencies in the user experience. This delay in adoption can hinder customers’ ability\nto fully leverage Delta Lake’s latest advancements across their ecosystem.</p>\n<h2 id=\"enter-delta-kernel\">Enter Delta Kernel</h2>\n<p><strong>Delta Kernel</strong> is a game-changer. Built as a lightweight library, it abstracts the complexities of\ninteracting with Delta Lake, providing APIs for metadata handling, schema reading, and transaction\nlog processing. Delta Kernel provides <strong>stable APIs</strong> that streamline essential operations such as:</p>\n<ul>\n<li><strong>Metadata Handling</strong>: Access and interpret table schema, partitions, and protocol details seamlessly.</li>\n<li><strong>Statistics Collection:</strong> Extract file-level statistics, enabling query optimizers to make informed decisions for efficient query planning.</li>\n<li><strong>Transaction Log Processing</strong>: Replay Delta’s atomic transaction logs to compute the latest snapshot of the table for consistency and correctness.</li>\n</ul>\n<h2 id=\"how-starrocks-integrates-delta-lake-through-delta-kernel\">How StarRocks Integrates Delta Lake Through Delta Kernel</h2>\n<p>If you’re not yet familiar with StarRocks, here’s what you need to know. Designed with a distributed\narchitecture optimized for running customer-facing workloads on open data lakehouses, StarRocks’ core components include:</p>\n<ul>\n<li>\n<p><strong>Frontend (FE)</strong>:</p>\n<ul>\n<li>Responsible for query parsing, plan generation, and metadata management.\nIt acts as the brain, orchestrating query execution across multiple nodes.</li>\n</ul>\n</li>\n<li>\n<p><strong>Compute Node (CN):</strong></p>\n<ul>\n<li>Handles data caching, retrieval, and execution of distributed query plans.\nIt is the muscle that delivers fast and scalable data processing.</li>\n</ul>\n</li>\n</ul>\n<p><img src=\"https://delta.io/_astro/figure1.Cucw6Sd9_ZySoyX.webp\"></p>\n<p>This <strong>FE + CN MPP</strong> architecture is simple yet effective, allowing StarRocks\nto scale easily while delivering high performance, ideal for analytics on large data volumes.</p>\n<h3 id=\"core-functions-of-delta-kernel-in-starrocks-fe\">Core Functions of Delta Kernel in StarRocks FE</h3>\n<p>StarRocks integrates with Delta Lake primarily through its <strong>Frontend (FE)</strong>,\nwhere <strong>Delta Kernel</strong> plays a critical role in handling metadata, optimizing queries, and managing scan ranges.</p>\n<p><img src=\"https://delta.io/_astro/figure2.4JvpX6Ou_CuMws.webp\"></p>\n<h4 id=\"metadata-and-protocol-retrieval\">Metadata and Protocol Retrieval</h4>\n<p>Delta Kernel retrieves the table’s <strong>metadata</strong>, including schema, partition columns, and configurations,\nand ensures compatibility with Delta Lake’s evolving feature set. As part of this process, it reads the Delta Lake protocol to determine:</p>\n<ul>\n<li><code>minReaderVersion</code>: The minimum reader version required to correctly interpret the table.</li>\n<li><code>readerFeatures</code>: The specific features that must be supported for proper data processing.</li>\n</ul>\n<h4 id=\"statistics-retrieval-for-query-optimization\">Statistics Retrieval for Query Optimization</h4>\n<p>Delta Kernel provides file-level statistics, which help StarRocks’ <strong>Cost-Based Optimizer (CBO)</strong> select the most efficient query execution plan.</p>\n<h4 id=\"scan-range-management\">Scan Range Management</h4>\n<p>Delta Kernel is key to simplifying scan range generation in StarRocks’ FE,\neffectively abstracting the complexities of Delta Lake’s table format.</p>\n<ul>\n<li><strong>Partition Pruning</strong>: Using partition predicates to exclude unnecessary partitions.</li>\n<li><strong>Data Skipping</strong>: Leveraging file-level metadata to skip irrelevant data files.</li>\n<li><strong>Incremental Scheduling</strong>: The scheduler in FE uses Delta Kernel’s iterator to\nfetch scan ranges in batches and incrementally distribute them to CN nodes for execution.</li>\n</ul>\n<p>This design means that the downstream Compute Nodes (CNs) do not need to be aware of the table format or its specific implementation.</p>\n<h3 id=\"optimizations-for-customer-facing-analytics\"><strong>Optimizations for Customer-Facing Analytics</strong></h3>\n<p>Delta Kernel provides a set of <strong>Engine APIs</strong> to facilitate data access and support custom functionality.\nThese APIs include default implementations for:</p>\n<ul>\n<li>Reading <strong>JSON</strong> and <strong>Parquet</strong> files.</li>\n<li>Evaluating expressions over the data read by these APIs.</li>\n</ul>\n<p>StarRocks builds on these defaults to better serve <strong>customer-facing analytics</strong>,\nintroducing caching mechanisms that minimize redundant file reads:</p>\n<p><img src=\"https://delta.io/_astro/figure3.C0F6I2An_12VbeP.webp\"></p>\n<h4 id=\"custom-handlers-for-cached-reads\">Custom Handlers for exists in the cache, its data is returned directly, avoiding the need to access and reprocess the file.</li>\n<li>If the file is not in the cache, it is fetched from the Delta log, processed, and stored in the cache for future queries.</li>\n</ul>\n</li>\n<li>The cache operates with an eviction policy based on timeout settings and FE memory constraints,\nensuring efficient use of resources while keeping frequently accessed data readily available.</li>\n</ul>\n<p>These optimizations reduce query latency by avoiding redundant reads of Parquet/JSON files and\nminimize metadata-related overhead in the FE, ensuring responsiveness for high-concurrency workloads.</p>\n<h2 id=\"current-capabilities\">Current Capabilities</h2>\n<p>Today, StarRocks’ Delta Lake connector
