Delta Lake provides lots of data management techniques that are useful for streaming use cases. Delta Lake also allows for fast downstream queries with a variety of engines.</p>\n<p>Let’s start by showing how to read a Kafka stream and write to a Delta Lake table</p>\n<p><img src=\"https://delta.io/_astro/image1.RnGJQQ3L_okgOm.webp\"></p>\n<h2 id=\"read-kafka-stream-and-write-to-a-delta-lake-table-periodically\">Read Kafka stream and write to a Delta Lake table periodically</h2>\n<p>Suppose you have a Kafka stream that’s outputting data in the following JSON format:</p>\n<pre><code><span><span>{\"student_name\":\"someXXperson\", \"graduation_year\":\"2023\", \"major\":\"math\"}</span></span>\n<span><span>{\"student_name\":\"liXXyao\", \"graduation_year\":\"2025\", \"major\":\"physics\"}</span></span></code></pre>\n<p>The <code>student_name</code> field contains the first name and last name delimited by <code>XX</code>. We want to ingest this Kafka stream into a Delta table and split the <code>student_name</code> field into <code>first_name</code> and <code>last_name</code> fields.</p>\n<p>Here’s how to read a Kafka stream into a Spark DataFrame:</p>\n<pre><code><span><span>df = (</span></span>\n<span><span>    spark.readStream.format(\"kafka\")</span></span>\n<span><span>    .option(\"kafka.bootstrap.servers\", \"host1:port1,host2:port2\")</span></span>\n<span><span>    .option(\"subscribe\", subscribeTopic)</span></span>\n<span><span>    .load()</span></span>\n<span><span>)</span></span></code></pre>\n<p>We need to manually define the schema of the Kafka stream to ingest it:</p>\n<pre><code><span><span>schema </span><span>=</span><span> StructType([</span></span>\n<span><span> StructField(</span><span>\"student_name\"</span><span>, StringType()),</span></span>\n<span><span> StructField(</span><span>\"graduation_year\"</span><span>, StringType()),</span></span>\n<span><span> StructField(</span><span>\"major\"</span><span>, StringType()),</span></span>\n<span><span>])</span></span></code></pre>\n<p>Create a function that will process the JSON input data and return a properly formatted Spark DataFrame that can be output to the Delta table:</p>\n<pre><code><span><span>def with_normalized_names(df, schema):</span></span>\n<span><span>    parsed_df = (</span></span>\n<span><span>        df.withColumn(\"json_data\", from_json(col(\"value\").cast(\"string\"), schema))</span></span>\n<span><span>        .withColumn(\"student_name\", col(\"json_data.student_name\"))</span></span>\n<span><span>        .withColumn(\"graduation_year\", col(\"json_data.graduation_year\"))</span></span>\n<span><span>        .withColumn(\"major\", col(\"json_data.major\"))</span></span>\n<span><span>        .drop(col(\"json_data\"))</span></span>\n<span><span>        .drop(col(\"value\"))</span></span>\n<span><span>    )</span></span>\n<span><span>    split_col = split(parsed_df[\"student_name\"], \"XX\")</span></span>\n<span><span>    return (</span></span>\n<span><span>        parsed_df.withColumn(\"first_name\", split_col.getItem(0))</span></span>\n<span><span>        .withColumn(\"last_name\", split_col.getItem(1))</span></span>\n<span><span>        .drop(\"student_name\")</span></span>\n<span><span> <code>perform_available_now_update()</code> function whenever we’d like to update the Delta table with the latest data in the Kafka stream. You can run this function every 10 minutes, every hour, or every day depending on the latency needs of your business.</p>\n<p>The <code>checkpointPath</code> tracks the Kafka data that’s already been processed, so you don’t need to manually track the data that’s already been ingested into the Delta table. Spark Structured Streaming makes these incremental updates quite easy.</p>\n<h2 id=\"read-kafka-stream-and-write-to-a-delta-lake-table-continuously\">Read Kafka stream and write to a Delta Lake table continuously</h2>\n<p>In the previous example, we showed how to read the Kafka stream with the trigger to <code>availableNow</code> which allows for periodic processing. Now let’s see how to use Spark Structured Streaming to continuously process new data from the Kafka stream.</p>\n<p>Here is a function that reads the latest data from Kafka and continuously process it every 10 seconds:</p>\n<pre><code><span><span>def perform_trigger_fixed_interval_update():</span></span>\n<span><span>    checkpointPath = \"data/tmp_students_checkpoint/\"</span></span>\n<span><span>    deltaPath = \"data/tmp_students_delta\"</span></span>\n<span><span>    return df.transform(lambda df: with_normalized_names(df)).writeStream.trigger(</span></span>\n<span><span>        processingTime='10 seconds'</span></span>\n<span><span>    ).format(\"delta\").option(\"checkpointLocation\", checkpointPath).start(deltaPath)</span></span></code></pre>\n<p>For continuous streaming, you need a cluster that’s always running. That is usually more expensive than periodically provisioning a new cluster and incrementally processing the new data.</p>\n<p>Continuous streaming is good for low-latency data processing pipelines. Incremental processing is good when the latency requirements are higher.</p>\n<p>For a continuous streaming query, you can also skip manually setting a trigger and rely on the default trigger. This could have lower latency compared to the processing time trigger if the data can be processed within the pre-defined processing time.</p>\n<p>Let’s now turn our attention to how ingesting Kafka streams into Delta tables can create lots of small files.</p>\n<h2 id=\"why-streaming-can-cause-the-small-file-problem\">Why streaming can cause the small file problem</h2>\n<p>Query engines perform best when Lakehouse storage systems contain files that are not too big or too small. A Delta table with an excessive number of small files has the small file problem which causes queries to run slowly.</p>\n<p>Streaming data from Kafka to Delta tables can cause lots of small files, especially when the latency is low and/or the Delta table uses a Hive-style partition key that’s not conducive for streaming.</p>\n<p>If you’re streaming to a Delta table every 5 seconds, then lots of small files are likely to be created. Delta tables that are partitioned by a key like <code>ingestion_date</code> shouldn’t create an excessive number of small files. But Delta tables that are partitioned by a high cardinality column, like <code>medical_code</code> could also create a lot of small files. See this blog post on <a target=\"_blank\" href=\"https://delta.io/blog/pros-cons-hive-style-partionining/\">the pros and cons of Hive-style partitioning</a> for more details.</p>\n<p>You should design your Kafka data ingestion pipelines to generate the minimal number of small files possible. Luckily Delta Lake has a built-in solution to fix the small file problem.</p>\n<h2 id=\"small-file-compaction\">Small file compaction</h2>\n<p>Delta Lake makes it easy to compact small files and fix the small file problem.</p>\n<p>Whenever a Delta table accumulates a lot of small files, you can run a single-line command to rearrange the small files into properly sized files.</p>\n<p>You can also use predicates to only compact a subset of the Delta table, so the operation is relatively lightweight. You can run a job on a daily basis that compacts all the files ingested in the previous day for example.</p>\n<p>See this blog post on <a target=\"_blank\" href=\"https://delta.io/blog/2023-01-25-delta-lake-small-file-compaction-optimize/\">Delta Lake small file compaction with OPTIMIZE</a> to learn more.</p>\n<p>Delta Lake also offers several other benefits for Kafka workloads.</p>\n<h2 id=\"advantages-of-delta-lake-for-kafka-streaming-data\">Advantages of Delta Lake for Kafka streaming data</h2>\n<p>There are several other advantages of Delta Lakes for Kafka workflows.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/2022-11-16-delta-lake-schema-enforcement/\">Schema enforcement</a>: Delta tables enable schema enforcement by default, so if the schema of the Kafka streaming data changes, mismatched data won’t corrupt your table</li>\n<li><a target=\"_blank\" href=\"https://delta.io/blog/2023-02-08-delta-lake-schema-evolution/\">Schema evolution</a>: You can optionally enable schema evolution so the schema of your table can change over time.</li>\n<li><a target=\"_blank\" href=\"https://docs.delta.io/latest/concurrency-control.html\">Concurrency control</a>: Delta Lake offers different types of concurrency control so simultaneous commands will not corrupt the table.</li>\n<li>DML operations: Delta Lake makes it easy to run delete, update, and merge commands.</li>\n<li>Large connector ecosystem: Many engines can read and write to Delta tables. Ingesting a Kafta stream into a Delta table allows the data to be easily read by Spark, pandas, Polars, Trino, and many other query engines, see <a target=\"_blank\" href=\"https://delta.io/integrations\">the full list of integrations here</a>.</li>\n</ul>\n<p><img src=\"https://delta.io/_astro/image2.D-1UYCC-_1xvL8y.webp\"></p>\n<p>There are many good reasons to write Kafka stream data to a Delta table for better downstream processing.</p>\n<h2 id=\"conclusion\">Conclusion</h2>\n<p>This blog post has shown you that it’s easy to read a Kafka stream and write it out to a Delta table with Spark Structured Streaming.
