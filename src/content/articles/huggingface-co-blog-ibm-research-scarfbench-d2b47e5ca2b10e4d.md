</p>\n<!--]--><!--]--><p>Modernizing enterprise applications is one of the largest and most expensive software engineering activities organizations undertake. Teams migrate applications across frameworks to improve maintainability, cloud readiness, developer productivity, and access to modern capabilities.</p>\n<p>Recent advances in coding agents have sparked excitement around AI-assisted modernization. But an important question remains:</p>\n<p><strong>Can AI agents reliably modernize real-world enterprise applications?</strong></p>\n<p>Existing software engineering benchmarks have demonstrated impressive progress in bug fixing and code generation, but framework migration presents a fundamentally different challenge. Success requires not only translating code, but also preserving behavior, adapting build systems, and navigating runtime dependencies.</p>\n<p>To address this gap, we introduce <strong>ScarfBench (Self-Contained Application Refactoring Benchmark)</strong>, an open benchmark for evaluating AI agents on cross-framework migration tasks in Enterprise Java.</p>\n<p>ScarfBench focuses on migrations across three major Java ecosystems:</p>\n<ul>\n<li>Spring</li>\n<li>Jakarta EE</li>\n<li>Quarkus</li>\n</ul>\n<p>Unlike traditional benchmarks that compare generated code against reference implementations, ScarfBench evaluates whether migrated applications actually build, deploy, and preserve behavior.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#why-migration-is-hard\">\n\t</a>\n\t<span>\n\t\tWhy Migration Is Hard\n\t</span>\n</h2>\n<p>Framework migration is much more than replacing annotations.</p>\n<p>A simple repository migration can require changes across dependency injection, persistence configuration, queries, and framework descriptors. Small mistakes in any of these pieces can prevent successful deployment.</p>\n<p><a target=\"_blank\" href=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/3LDxVMx4nf_WEqEN2AQ7W.png\"><img src=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/3LDxVMx4nf_WEqEN2AQ7W.png\" alt=\"scarf-intro-anatomy\"></a></p>\n<p><b>Figure: Spring → Jakarta Migration Example</b></p>\n<p>Framework migration requires translating framework semantics, not just source code.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#introducing-scarfbench\">\n\t</a>\n\t<span>\n\t\tIntroducing ScarfBench\n\t</span>\n</h2>\n<p><a target=\"_blank\" href=\"https://huggingface.co/spaces/ibm-research/ScarfBench\">ScarfBench</a> provides a systematic way to evaluate AI agents on enterprise Java framework migration tasks.</p>\n<p>Applications are required to:</p>\n<ol>\n<li>Build successfully.</li>\n<li>Deploy correctly.</li>\n<li>Pass behavioral validation.</li>\n</ol>\n<p>This provides a much more realistic measure of modernization quality.</p>\n<h2>Benchmark at a Glance</h2>\n<table>\n  <thead>\n    <tr>\n      <th>Metric</th>\n      <th>Value</th>\n    </tr>\n  </thead>\n  <tbody>\n code</td><td>~151K</td></tr>\n    <tr><td>Source and test files</td><td>~2,000</td></tr>\n    <tr><td>Expert-written tests</td><td>1,331</td></tr>\n  </tbody>\n</table>\n<p>ScarfBench includes both focused migration tasks and whole-application migrations.</p>\n<p><a target=\"_blank\" Pipeline</b></p>\n<p>Starting from a JSR-based enterprise Java taxonomy, expert migrations create verified implementations across Spring, Jakarta EE, and Quarkus.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#how-do-frontier-agents-perform\">\n\t</a>\n\t<span>\n\t\tHow Do Frontier Agents Perform?\n\t</span>\n</h2>\n<p>We evaluated several state-of-the-art coding agents on ScarfBench.</p>\n<p>Despite strong performance on traditional software engineering benchmarks, framework migration remains difficult. Success rates vary considerably across framework pairs and whole-application migrations remain particularly challenging.</p>\n<p><a target=\"_blank\" href=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/MrcQ5trSi8oKtfD2UEhm9.png\"><img src=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/MrcQ5trSi8oKtfD2UEhm9.png\" alt=\"leaderboard\"></a></p>\n<p><b>Figure: Current Leaderboard</b></p>\n<p>\nEven the strongest current agents achieve less than 10% behavioral success, illustrating the gap between generating compilable code and preserving application behavior.\n</p><p><a target=\"_blank\" href=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/j7rihRrFe-Eo9oSxNFQS1.png\"><img src=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/j7rihRrFe-Eo9oSxNFQS1.png\" alt=\"scarf_aggregate_progression\"></a></p>\n<p><b>Figure: Compile → Deploy → Test Progression</b></p>\n<p>Compile success consistently exceeds deploy success, which in turn exceeds behavioral success. Build success alone significantly overestimates migration quality.</p>\n<p><a target=\"_blank\" Framework</b></p>\n<p>Migration difficulty depends strongly on the target framework, with Jakarta EE proving particularly challenging.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#what-we-learned-about-ai-agents-for-java-modernization\">\n\t</a>\n\t<span>\n\t\tWhat We Learned About AI Agents for Java Modernization\n\t</span>\n</h2>\n<p>Beyond measuring success rates, ScarfBench helps us understand how agents behave during modernization.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#can-agents-reliably-tell-when-a-migration-is-complete\">\n\t</a>\n\t<span>\n\t\tCan Agents Reliably Tell When a Migration Is Complete?\n\t</span>\n</h3>\n<p>A migrated application is only useful if it actually builds and runs.</p>\n<p>We therefore compared agent-reported outcomes against independent build verification.</p>\n<h4>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#finding-agents-are-overconfident\">\n\t</a>\n\t<span>\n\t\tFinding: Agents Are Overconfident\n\t</span>\n</h4>\n<p>Claude Code reported successful builds for 29 out of 30 whole applications.</p>\n<p>Only 22 of those applications actually built successfully.</p>\n<p>Meanwhile, the single application classified as failed by the agent ultimately built correctly.</p>\n<p>This suggests that agent self-assessment should not be treated as a reliable signal of migration completion.</p>\n<p>Independent build and test validation remains essential.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#how-do-agents-navigate-application-dependencies\">\n\t</a>\n\t<span>\n\t\tHow Do Agents Navigate Application Dependencies?\n\t</span>\n</h3>\n<p>Framework migrations rarely affect a single file or layer.</p>\n<p>Changes in configuration, services, databases, and web components often cascade across the application.</p>\n<h4>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#finding-migration-is-iterative-rather-than-linear\">\n\t</a>\n\t<span>\n\t\tFinding: Migration Is Iterative Rather Than Linear\n\t</span>\n</h4>\n<p>The most frequently visited layers were:</p>\n<ul>\n<li>Configuration</li>\n<li>Web</li>\n<li>Database</li>\n<li>Service</li>\n</ul>\n<p>Common transitions included:</p>\n<ul>\n<li>Configuration ↔ Web</li>\n<li>Service ↔ Database</li>\n</ul>\n<p>This suggests that migration is an iterative dependency-resolution process rather than a simple source-to-source transformation.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#where-do-agents-spend-most-of-their-effort\">\n\t</a>\n\t<span>\n\t\tWhere Do Agents Spend Most of Their Effort?\n\t</span>\n</h3>\n<p>We used layer revisit frequency as a proxy for migration effort. Layers that required repeated visits typically involved debugging, dependency resolution, or framework adaptation.</p>\n<h4>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#finding-configuration-dominates-migration-effort\">\n\t</a>\n\t<span>\n\t\tFinding: Configuration Dominates Migration Effort\n\t</span>\n</h4>\n<p>Rather than proceeding linearly, agents repeatedly returned to configuration-related artifacts while resolving framework differences and dependency issues.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#what-challenges-are-not-about-code-transformation\">\n\t</a>\n\t<span>\n\t\tWhat Challenges Are Not About Code Transformation?\n\t</span>\n</h3>\n<p>Not every migration issue originates from source code.</p>\n<h4>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#finding-environment-and-tooling-matter\">\n\t</a>\n\t<span>\n\t\tFinding: Environment and Tooling Matter\n\t</span>\n</h4>\n<p>Agents frequently struggled with environmental issues, including:</p>\n<ul>\n<li>Docker cache inconsistencies</li>\n<li>Port connectivity problems</li>\n<li>Maven wrapper and build tooling issues</li>\n</ul>\n<p>These operational concerns often delayed validation even when the source-code migration itself was largely complete.</p>\n<p><a target=\"_blank\" href=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/BtWLPGsif0O4VoQfVppIC.png\"><img src=\"https://cdn-uploads.huggingface.co/production/uploads/649c1276a83f996b4191a8f1/BtWLPGsif0O4VoQfVppIC.png\" alt=\"failure-distribution\"></a></p>\n<p><b>Figure: Failure Mode Distribution</b></p>\n<p>Modernization failures span build systems, deployment environments, dependency injection, databases, endpoints, assertions, and infrastructure.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#key-takeaway\">\n\t</a>\n\t<span>\n\t\tKey Takeaway\n\t</span>\n</h2>\n<p>The biggest challenge in framework modernization is not translating Java code.</p>\n<p>It is managing the web of dependencies across configuration, infrastructure, and runtime environments.</p>\n<p>While frontier agents can automate substantial portions of the migration process, reliable validation and architectural reasoning remain critical for achieving successful outcomes.</p>\n<p>ScarfBench helps expose these challenges and provides a standardized way to measure progress toward truly autonomous application modernization.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#explore-scarfbench\">\n\t</a>\n\t<span>\n\t\tExplore ScarfBench\n\t</span>\n</h2>\n<p>ScarfBench is designed as an open resource for researchers and practitioners.</p>\n<p>Resources include:</p>\n<ul>\n<li>Benchmark dataset</li>\n<li>Evaluation infrastructure</li>\n<li>Public leaderboard</li>\n<li>Documentation</li>\n<li>Open-source code</li>\n</ul>\n<p>Researchers can compare agent architectures and techniques. Practitioners can use ScarfBench to evaluate modernization solutions before deploying them in production environments.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#website\">\n\t</a>\n\t<span>\n\t\tWebsite\n\t</span>\n</h3>\n<p><a target=\"_blank\" href=\"https://scarfbench.info/\">https://scarfbench.info</a></p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#dataset\">\n\t</a>\n\t<span>\n\t\tDataset\n\t</span>\n</h3>\n<p><a target=\"_blank\" href=\"https://huggingface.co/datasets/ibm-research/ScarfBench\">https://huggingface.co/datasets/ibm-research/ScarfBench</a></p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#space\">\n\t</a>\n\t<span>\n\t\tSpace\n\t</span>\n</h3>\n<p><a target=\"_blank\" href=\"https://huggingface.co/spaces/ibm-research/ScarfBench\">https://huggingface.co/spaces/ibm-research/ScarfBench</a></p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#github-repository\">\n\t</a>\n\t<span>\n\t\tGitHub Repository\n\t</span>\n</h3>\n<p><a target=\"_blank\" href=\"https://github.com/scarfbench/scarfbench\">https://github.com/scarfbench/scarfbench</a></p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#leaderboard\">\n\t</a>\n\t<span>\n\t\tLeaderboard\n\t</span>\n</h3>\n<p><a target=\"_blank\" href=\"https://scarfbench.info/leaderboard\">https://scarfbench.info/leaderboard</a></p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ibm-research/scarfbench#paper\">\n\t</a>\n\t<span>\n\t\tPaper\n\t</span>\n</h3>\n<p><a target=\"_blank\" href=\"https://arxiv.org/abs/2605.06754\">https://arxiv.org/abs/2605.06754</a></p>\n<p>Framework migration remains one of the largest unsolved problems in AI-assisted software engineering.
