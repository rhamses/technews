authentication</li>\n<li>The same observability</li>\n<li>A single bill</li>\n</ul>\n<p>Open-source models integrate with Foundry Agents the same way frontier models do, so you can mix model types in Hugging Face, by itself, is not an enterprise serving platform. <strong>Hugging Face models on Foundry is that operational layer, run by Microsoft.</strong></p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/microsoft/foundry-managed-compute#hugging-face-models-on-foundry\">\n\t</a>\n\t<span>\n\t\tHugging Face Models on Foundry\n\t</span>\n</h2>\n<p>The Hugging Face Collection brings a curated subset of models directly into the Foundry Model Catalog:</p>\n<ul>\n<li><strong>Refreshed weekly</strong> — trending models from the Hugging Face ecosystem are added continuously as the community publishes them.</li>\n<li><strong>Every modality</strong> — text, vision, audio, and multimodal: LLMs and VLMs for chat and agents, ASR and speech translation, embeddings, segmentation, image generation.</li>\n<li><strong>Safetensors only, no untrusted code</strong> — every model in the Collection is security-screened and ships in the SafeTensors weight where applicable, TEI for embeddings, llama.cpp for CPU — Foundry picks the engine that matches the model.</li>\n</ul>\n<p>From your side, an open-weight model in the Hugging Face Collection looks and behaves like any other model in the Foundry Model Catalog, and every model in the Collection has been put through a multi-stage publishing pipeline before it ever shows up there.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/microsoft/foundry-managed-compute#the-curation-pipeline\">\n\t</a>\n\t<span>\n\t\tThe Curation Pipeline\n\t</span>\n</h3>\n<p>Hugging Face and Microsoft work together to bring the most popular open-weight models from the Hugging Face ecosystem to Microsoft Foundry — production-ready for enterprise environments — through a systematic curation process:</p>\n<ol>\n<li><strong>Identify trending models</strong> in the Hugging Face ecosystem — based on community signals, partner requests, and customer demand — and select candidates for enterprise readiness.</li>\n<li><strong>Screen for compliance and security</strong> — model licenses are reviewed against Microsoft's enterprise distribution policy (with license metadata captured and preserved on the catalog model card), and repositories are inspected for <code>trust_remote_code</code> patterns and custom executable code; any model that would require executing third-party Python at load time is either remediated or excluded.</li>\n<li><strong>Build, scan, and publish runtimes</strong> — Microsoft builds inference container images on supported runtimes (vLLM, SGLang, TensorRT-LLM, NIM, TEI, llama.cpp), scans them for CVEs, and signs and publishes them to a Microsoft-managed container registry.</li>\n<li><strong>Upload weights to secure Azure storage</strong> — model weights are pulled from Hugging Face once, validated against the published model card, and stored in Microsoft-managed Azure storage in the regions where the model is served.</li>\n<li><strong>Validate and publish to the catalog</strong> — every model + runtime + accelerator combination is tested for API conformance (chat completions, embeddings, rerank, etc.) and performance (latency, throughput, time-to-first-token, inter-token decode time), then the validated model — with its templates, runtime images, and weights — is published to the Foundry Model Catalog with a one-click deploy path onto Managed Compute.</li>\n</ol>\n<p>Because weights are pre-staged in Azure storage and runtime images live in a Microsoft-managed registry, your deployments won't need outbound network access to Hugging Face Hub — you can deploy to production inside a private network.</p>\n<h2>\n\t<a target=\"_blank\" versatile collection of community-built, open-source inference runtimes — each selected and tuned for Foundry Managed Compute, and matched to the model architectures it serves best. Hugging Face and the SGLang team have built a Transformers backend integration for SGLang, so any model in the Transformers library runs on SGLang out of the box — and reaches Foundry the same day it lands on Hugging Face.</p>\n</li>\n<li><p><strong>Text Embeddings Inference (TEI)</strong> — the runtime for embedding, reranker, and sequence-classification models. Accelerator-specific images ship with kernels compiled for each GPU and CPU family Foundry supports, keeping the embedding hot path lean for RAG and semantic-search workloads.</p>\n</li>\n<li><p><strong>llama.cpp</strong> — the CPU and small-GPU path for GGUF-quantized models. Useful for cost-optimized deployments, smaller models, and CPU-only regions, with the same OpenAI-compatible API as vLLM and SGLang.</p>\n</li>\n<li><p><strong>TensorRT-LLM and NIM</strong> — used on NVIDIA hardware where NVIDIA's optimized kernels and Triton-based serving deliver meaningfully better latency or throughput for specific model families.</p>\n</li>\n<li><p><strong>hf-serve</strong> — Hugging Face's own multi-model inference server, used for model architectures outside the LLM and embedding fast paths (vision, audio, segmentation, and other Transformers-native pipelines) so the Collection can cover every modality with a consistent serving layer.</p>\n</li>\n</ul>\n<h2>\n\t<a target=\"_blank\"
