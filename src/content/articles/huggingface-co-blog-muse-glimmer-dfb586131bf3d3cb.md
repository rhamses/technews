href=\"https://huggingface.co/blog/muse-glimmer#architecture\">\n\t</a>\n\t<span>\n\t\tArchitecture\n\t</span>\n</h2>\n<p>Muse Glimmer is a dense 30B parameter model consisting of:</p>\n<ul>\n<li>2B ViT-style encoder for vision (Perception Encoder)  </li>\n<li>28B parameter text decoder</li>\n</ul>\n<p>In addition to the main VLM, there’s also a speculative decoding drafter implemented on DFlash. Usage of this module is optional, and it can provide much faster generation in exchange for some memory cost. We found this drafter to be particularly well suited to structured content generation such as coding.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/muse-glimmer#text-decoder\">\n\t</a>\n\t<span>\n\t\tText Decoder\n\t</span>\n</h3>\n<p>The language model uses the following architecture components:</p>\n<ul>\n<li><strong>Hybrid attention:</strong> Alternating between three sliding window layers (of 2,048 tokens) using rotary position embedding, followed by a fourth layer that uses full attention and NoPE (no positional embedding). The pattern is therefore (SWA, SWA, SWA, Full), repeated 13 times to a total of 52 layers. This allows the model to retain relative order and distance information with RoPE and preserve information globally with NoPE.  </li>\n<li><strong>Gated Grouped-Query Attention:</strong> Each key-value head is shared by 16 query heads, which reduces KV-cache memory by 16x and makes generation faster and cheaper.  </li>\n<li><strong>Q-K normalization with extra query scaling:</strong> Before computing attention, Muse Glimmer applies RMS normalization to every query and key head to keep attention logits stable. After this, queries are multiplied by a scale factor to set the target logit scale after normalization. The extra query scaling behaves like an inverse temperature at the softmax level.</li>\n</ul>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/muse-glimmer#perception-encoder\">\n\t</a>\n\t<span>\n\t\tPerception Encoder\n\t</span>\n</h3>\n<p>Muse Glimmer uses one image encoder to handle both images and videos. Unlike the relatively small vision encoders used in other VLMs, this is a sizable 2B ViT-like model designed after the Perception Encoder architecture. Perception Encoder was previously introduced by Meta <a target=\"_blank\" href=\"https://huggingface.co/papers/2504.13181\">as a backbone for various downstream spatial and multimodal tasks</a>.<br>The encoder patchifies images to a shape of 2 frames x 3 channels x 14 x 14, and passes them through a linear layer for projection. An interpolated absolute position embedding from a learned position table is then added to these embeddings. These are then sent to the vision tower which consist of 50 layers and GELU MLPs. Similar to the language model, the attention pattern consists of three window attention layers followed by one full attention layer. Inside the attention layers, 2D RoPE is applied to the queries and keys.</p>\n<p>After transformer, pixel shuffle concatenates 2x2 groups of neighboring spatial tokens which reduces the number of image tokens 4x without discarding their channels. The merged features are then projected to the shared embedding space of the text decoder.</p>\n<p>Videos go through the same encoder frame by frame, where each frame is converted into patches (of shape [batch, temporal groups, grid height, grid width, 2 frames, 3 channels, 14, 14]). The processor targets 2 frames per second and caps the clip at 96 frames sampled evenly across video. The processor creates timestamped video placeholders, interleaving text with frame e.g. “Time: 0.0s &lt;|video|&gt; x N” in which the final video embeddings are replaced before the final projection layer.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/muse-glimmer#transformers\">\n\t</a>\n\t<span>\n\t\tTransformers\n\t</span>\n</h3>\n<p>Upgrade transformers to the latest version to be able to use Muse Glimmer.</p>\n<pre><code>pip install --upgrade transformers accelerate\n</code></pre>\n<p>Muse Glimmer comes with day-0 support in transformers, both for the main model and the speculative decoding drafter.
