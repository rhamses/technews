In a real retrieval system, these near-misses are exactly the documents that cause bad answers. Hard negative mining finds these confusing passages so the model can learn to tell them apart.</p>\n<pre><code>nemotron embed prep -c default\n</code></pre>\n<p>The above command runs three sub-steps automatically:</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/nvidia/domain-specific-embedding-finetune#2a-train--validation--test-split\">\n\t</a>\n\t<span>\n\t\t2a. Train / Validation / Test Split\n\t</span>\n</h3>\n<p>The generated QA pairs are split into training (80%) and test (20%) sets. The test set is formatted as a <a target=\"_blank\" href=\"https://github.com/beir-cellar/beir\">BEIR</a>-compatible benchmark for standardized evaluation in Step 5.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/nvidia/domain-specific-embedding-finetune#2b-hard-negative-mining\">\n\t</a>\n\t<span>\n\t\t2b. Hard Negative Mining\n\t</span>\n</h3>\n<p>Using the base embedding model, the pipeline:</p>\n<ol>\n<li>Embeds every query and every passage in the corpus.  </li>\n<li>Computes similarity between each query and all passages.  </li>\n<li>Masks out each query's labeled positive documents.  </li>\n<li>Applies a margin filter: any non-positive document scoring <em>above</em> 95% of the minimum positive score is eliminated. This exclusion zone guards against false negatives — unlabeled passages that are so close to the positive they may actually be relevant.  </li>\n<li>From the surviving candidates, selects the top-k highest-scoring documents as hard negatives (5 per query by default).</li>\n</ol>\n<p>The result: hard negatives are the most similar non-positive passages that still fall safely below the positive-score ceiling. They are passages the current model considers highly relevant but that are not the labeled answer.</p>\n<p><strong>Why this works</strong>: Training on easy negatives (completely unrelated passages) teaches the model nothing new. Training on hard negatives forces it to learn the subtle distinctions that matter in your domain. For example, in a medical corpus, a question about \"metformin dosage for Type 2 diabetes\" might have hard negatives about \"metformin side effects\" or \"insulin dosage for Type 1 diabetes\" — close but critically different. The 95% margin ceiling prevents the miner from selecting passages that are too close to the positive, which could actually be correct answers that simply weren't labeled during SDG.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/nvidia/domain-specific-embedding-finetune#2c-multi-hop-unrolling\">\n\t</a>\n\t<span>\n\t\t2c. For example, a question like <em>\"How does the thermal management system in Section 3.2 relate to the power constraints described in Section 5.1?\"</em> has two positive passages.</p>\n<p>Unrolling creates one training example per (query, positive document) pair, so the contrastive loss sees each positive independently. A question with 2 positive documents becomes 2 training examples, each with the same hard negatives but a different positive.</p>\n<p>The final output is a training-ready JSON Understand Multi-Hop Questions and Why They Improve Retrieval\n\t</span>\n</h2>\n<p>Standard embedding fine-tuning generates one question per passage and trains the model to match them. This works for simple factual lookups, but real users ask complex questions that span multiple documents or sections. If the model has only seen single-hop training data, it will struggle to retrieve <em>all</em> the relevant passages for these complex queries.</p>\n<p>The SDG pipeline generates questions at 1 to 3 hops by default:</p>\n<ul>\n<li><strong>1-hop:</strong> \"What is the TDP of the H100 SXM?\" — answered by a single passage.  </li>\n<li><strong>2-hop:</strong> \"How does the H100's TDP relate to cooling requirements in dense deployments?\" — requires connecting information from two passages.  </li>\n<li><strong>3-hop:</strong> \"Given the TDP, cooling constraints, and rack density limits, what is the maximum number of H100 GPUs deployable in a standard data center row?\" — synthesizes three passages.</li>\n</ul>\n<p>Each hop is tracked with its own context summary and segment IDs, so the training data preserves the full reasoning chain. The final two stages convert the model and serve it behind an API.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/nvidia/domain-specific-embedding-finetune#export-to-onnx--tensorrt\">\n\t</a>\n\t<span>\n\t\tExport to ONNX / TensorRT\n\t</span>\n</h3>\n<pre><code>nemotron embed export -c default\n</code></pre>\n<p>This exports the fine-tuned checkpoint to ONNX (opset 17).
