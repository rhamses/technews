href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#why-finetune\">\n\t</a>\n\t<span>\n\t\tWhy Finetune?\n\t</span>\n</h2>\n<p>General-purpose multimodal embedding models like <a target=\"_blank\" href=\"https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B\"><code>Qwen/Qwen3-VL-Embedding-2B</code></a> are trained on diverse data to perform well across a wide range of languages and tasks: image-text matching, visual question answering, document understanding, and more. But this generality means the model is rarely the best choice for any specific task.</p>\n<p>Consider Visual Document Retrieval: given a text query like \"What was the company's Q3 revenue?\", the model must find the most relevant document screenshot from a corpus of thousands. This requires understanding document layouts, charts, tables, and text, which is a very different skill from e.g. matching pictures of shoes with product descriptions.</p>\n<p>By finetuning on domain-specific data, the model can learn these specialized patterns. In my experiment, finetuning improved NDCG@10 from 0.888 to 0.947, ahead of every recent multimodal model I tested, including ones up to 4x larger.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#training-components\">\n\t</a>\n\t<span>\n\t\tTraining Components\n\t</span>\n</h2>\n<p>Training multimodal Sentence Transformer models involves the same components as training text-only models:</p>\n<ol>\n<li><a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#model\"><strong>Model</strong></a>: The multimodal model to train or finetune.</li>\n<li><a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#dataset\"><strong>Dataset</strong></a>: The data used for training and evaluation.</li>\n<li><a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#loss-function\"><strong>Loss Function</strong></a>: A function that quantifies the model's performance and guides the optimization process.</li>\n<li><a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#training-arguments\"><strong>Training Arguments</strong></a> (optional): Parameters that influence training performance and tracking/debugging.</li>\n<li><a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#evaluator\"><strong>Evaluator</strong></a> (optional): A tool for evaluating the model before, during, or after training.</li>\n<li><a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#trainer\"><strong>Trainer</strong></a>: Brings together the model, dataset, loss function, and other components for training.</li>\n</ol>\n<p>The multimodal training pipeline uses the same <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/trainer.html#sentence_transformers.sentence_transformer.trainer.SentenceTransformerTrainer\"><code>SentenceTransformerTrainer</code></a> as text-only training. The key difference is that your datasets contain images (or other modalities) alongside text, and the model's processor handles the image preprocessing automatically.</p>\n<p>Let's walk through each component, using Visual Document Retrieval (matching text queries to document screenshots) as a running example.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#model\">\n\t</a>\n\t<span>\n\t\tModel\n\t</span>\n</h2>\n<p>The most common approach is to finetune an existing multimodal embedding model, or to start from a Vision-Language Model (VLM) checkpoint. The <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Transformer\"><code>Transformer</code></a> module automatically detects supported modalities from the model's processor.</p>\n<p>To finetune an existing multimodal embedding model (e.g. one that already has a <code>modules.json</code> file), you can pass <code>processor_kwargs</code> and <code>model_kwargs</code> to control preprocessing and model loading respectively. <code>processor_kwargs</code> are passed directly to <a target=\"_blank\" href=\"https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoProcessor.from_pretrained\"><code>AutoProcessor.from_pretrained(...)</code></a> (e.g., image resolution bounds: higher <code>max_pixels</code> means higher quality but more memory), while <code>model_kwargs</code> are passed to the appropriate <a target=\"_blank\" href=\"https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoModel.from_pretrained\"><code>AutoModel.from_pretrained(...)</code></a> call (e.g., precision, attention implementation):</p>\n<pre><code><span>from</span> sentence_transformers <span>import</span> SentenceTransformer\nmodel = SentenceTransformer(\n    <span>\"Qwen/Qwen3-VL-Embedding-2B\"</span>,\n    model_kwargs={<span>\"attn_implementation\"</span>: <span>\"flash_attention_2\"</span>, <span>\"torch_dtype\"</span>: <span>\"bfloat16\"</span>},\n    processor_kwargs={<span>\"min_pixels\"</span>: <span>28</span> * <span>28</span>, <span>\"max_pixels\"</span>: <span>600</span> * <span>600</span>},\n)\n</code></pre>\n<p>You can also start from a fresh VLM checkpoint that hasn't been trained for embeddings yet. Sentence Transformers will attempt to recognize the architecture, infer the supported modalities from the processor, and set up the appropriate forward method and pooling. If the automatic detection doesn't work perfectly for a particular model, the configuration in the saved <code>sentence_bert_config.json</code> can be edited to adjust modality settings, forward methods, and output handling:</p>\n<pre><code><span>from</span> sentence_transformers <span>import</span> SentenceTransformer\nmodel = SentenceTransformer(<span>\"Qwen/Qwen3-VL-2B\"</span>)\n</code></pre>\n<p>In both cases, the <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Transformer\"><code>Transformer</code></a> module inspects the processor to determine which modalities are available, and <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/modules.html#sentence_transformers.sentence_transformer.modules.Pooling\"><code>Pooling</code></a> is added automatically if needed. You can verify the supported modalities:</p>\n<pre><code><span>print</span>(model.modalities)\n<span># ['text', 'image', 'video', 'message']</span>\n<span>print</span>(model.supports(<span>\"image\"</span>))\n<span># True</span>\n</code></pre>\n<details>\n<summary>Alternative: Building multimodal models with Router</summary>\n<p>Instead of using a single VLM backbone, you can compose separate encoders for different modalities using the <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Router\"><code>Router</code></a> module. This lets you combine any existing encoders and route inputs to the appropriate one based on detected modality:</p>\n<pre><code><span>from</span> sentence_transformers <span>import</span> SentenceTransformer\n<span>from</span> sentence_transformers.sentence_transformer.modules <span>import</span> Dense, Pooling, Router, Transformer\n<span># Create separate encoders for different modalities</span>\ntext_encoder = Transformer(<span>\"sentence-transformers/all-MiniLM-L6-v2\"</span>)\ntext_pooling = Pooling(text_encoder.get_embedding_dimension(), pooling_mode=<span>\"mean\"</span>)\ntext_projection = Dense(text_encoder.get_embedding_dimension(), <span>768</span>)\n<span># SigLIP outputs pooled embeddings directly, so no separate Pooling module is needed</span>\nimage_encoder = Transformer(<span>\"google/siglip2-base-patch16-224\"</span>)\n<span># Route inputs based on modality</span>\nrouter = Router(\n    sub_modules={\n        <span>\"text\"</span>: [text_encoder, text_pooling, text_projection],\n        <span>\"image\"</span>: [image_encoder],\n    },\n)\nmodel = SentenceTransformer(modules=[router])\n</code></pre>\n<blockquote>\n<p>Since Router-based multimodal models use separate encoders per modality, their embedding spaces are initially unaligned. Training is required to align the spaces for meaningful cross-modal similarity. The <code>Dense</code> projection layer shown above helps map embeddings from different encoders into a shared space.</p>\n</blockquote>\n<p>This approach is useful when you want to use lightweight, specialized encoders rather than a large VLM. You can also combine Router-based multimodality with task-based routing (e.g. different encoders for queries vs. documents) using <code>route_mappings</code>. See the <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Router\"><code>Router</code></a> documentation for advanced routing scenarios.</p>\n</details>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#dataset\">\n\t</a>\n\t<span>\n\t\tDataset\n\t</span>\n</h2>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#visual-document-retrieval-dataset\">\n\t</a>\n\t<span>\n\t\tVisual Document Retrieval Dataset\n\t</span>\n</h3>\n<p>For this example, I use the <a target=\"_blank\" href=\"https://huggingface.co/datasets/tomaarsen/llamaindex-vdr-en-train-preprocessed\"><code>tomaarsen/llamaindex-vdr-en-train-preprocessed</code></a> dataset, a preprocessed English subset of <a target=\"_blank\" href=\"https://huggingface.co/datasets/llamaindex/vdr-multilingual-train\"><code>llamaindex/vdr-multilingual-train</code></a>. The source dataset was released alongside the <a target=\"_blank\" href=\"https://huggingface.co/blog/vdr-2b-multilingual\">Visual Document Retrieval Goes Multilingual</a> blogpost by LlamaIndex, and consists of ~500k multilingual query-image samples collected from public internet PDFs, with queries synthetically generated using VLMs (gemini-1.5-pro and Qwen2-VL-72B). \nMy preprocessed version filters to the 53,512 English samples and resolves 4 of the 16 ID-based hard negatives per sample into actual document screenshot images, so it can be used directly for training without further preprocessing:</p>\n<pre><code><span>from</span> datasets <span>import</span> load_dataset\ntrain_dataset = load_dataset(<span>\"tomaarsen/llamaindex-vdr-en-train-preprocessed\"</span>, <span>\"train\"</span>, split=<span>\"train\"</span>)\ntrain_dataset = train_dataset.select_columns([<span>\"query\"</span>, <span>\"image\"</span>, <span>\"negative_0\"</span>])\neval_dataset = load_dataset(<span>\"tomaarsen/llamaindex-vdr-en-train-preprocessed\"</span>, <span>\"eval\"</span>, split=<span>\"train\"</span>)\n</code></pre>\n<p>The <code>train</code> config contains the first 10,000 samples, and the <code>eval</code> config contains the next 300 samples (a <code>full</code> config with all 53,512 samples is also available). For training, I select <code>query</code>, <code>image</code>, and <code>negative_0</code> to form (anchor, positive, hard negative) triplets. Including additional hard negatives would likely improve the training signal, but each extra negative also increases memory usage and training time, so I stick with one. For evaluation, I keep all four hard negatives per query to build a more challenging retrieval corpus (more on that in the <a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#evaluator\">Evaluator</a> section).</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#dataset-format\">\n\t</a>\n\t<span>\n\t\tDataset Format\n\t</span>\n</h3>\n<p>Just like text-only training, the dataset format must match your chosen <a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#loss-function\">loss function</a>. The rules are the same:</p>\n<ol>\n<li>If your loss function requires a <em>Label</em>, your dataset must have a column named <strong>\"label\"</strong> or <strong>\"score\"</strong>.</li>\n<li>All columns other than <strong>\"label\"</strong> or <strong>\"score\"</strong> are considered <em>Inputs</em>. The number of these columns must match the number of valid inputs for your chosen loss function. Beyond the label column, the column names don't matter, only the order does.</li>\n</ol>\n<p>For multimodal datasets, the inputs can contain:</p>\n<ul>\n<li><strong>Text</strong>: strings.</li>\n<li><strong>Image</strong>: PIL images, file paths, URLs, or numpy/torch arrays.</li>\n<li><strong>Audio</strong>: file paths, numpy/torch arrays, dicts with <code>\"array\"</code> and <code>\"sampling_rate\"</code> keys, or (if <code>torchcodec</code> is installed) <code>torchcodec.AudioDecoder</code> instances.</li>\n<li><strong>Video</strong>: file paths, numpy/torch arrays, dicts with <code>\"array\"</code> and <code>\"video_metadata\"</code> keys, or (if <code>torchcodec</code> is installed) <code>torchcodec.VideoDecoder</code> instances.</li>\n<li><strong>Multimodal dicts</strong>: a dict mapping modality names to values, e.g. <code>{\"text\": ..., \"image\": ...}</code>. The keys must be <code>\"text\"</code>, <code>\"image\"</code>, <code>\"audio\"</code>, or <code>\"video\"</code>.</li>\n</ul>\n<p>The data collator automatically calls <code>model.preprocess()</code>, which detects the modality of each input and applies the appropriate preprocessing. No manual tokenization or image processing is needed.</p>\n<blockquote>\n<p>Many Hugging Face datasets that work out of the box with Sentence Transformers have been tagged with <code>sentence-transformers</code>, allowing you to easily find them at <a target=\"_blank\" href=\"https://huggingface.co/datasets?other=sentence-transformers\">https://huggingface.co/datasets?other=sentence-transformers</a>.</p>\n</blockquote>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#loss-function\">\n\t</a>\n\t<span>\n\t\tLoss Function\n\t</span>\n</h2>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#cachedmultiplenegativesrankingloss\">\n\t</a>\n\t<span>\n\t\tCachedMultipleNegativesRankingLoss\n\t</span>\n</h3>\n<p>For this training, I use <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/losses.html#cachedmultiplenegativesrankingloss\"><code>CachedMultipleNegativesRankingLoss</code></a>, a common choice for retrieval tasks. It accepts (query, positive) pairs with any number of additional hard negative columns, from 0 up to n, as long as each sample has the same number of negatives.\nDuring training, the loss pushes each query's similarity to its positive <em>up</em> and its similarity to every negative <em>down</em>. The negatives come from two sources:</p>\n<ol>\n<li><strong>Hard negatives</strong>: the negative column(s) explicitly supplied in the dataset (just <code>negative_0</code> in our triplet setup).</li>\n<li><strong>In-batch negatives</strong>: the positives and hard negatives from every <em>other</em> sample in the same batch, reused as additional negatives for this query at no extra cost.</li>\n</ol>\n<p>More negatives per query means a stronger training signal, so a larger batch size directly improves training quality. Beyond that, the \"cached\" variant of the loss uses gradient caching to make large effective batch sizes feasible even when GPU memory is limited.</p>\n<p>The <code>mini_batch_size</code> parameter controls how many samples are processed at once during the cached forward passes. For large multimodal models, setting this to a small value (e.g., 1) is important to avoid out-of-memory errors without sacrificing the benefits of large effective batch sizes:</p>\n<pre><code><span>from</span> sentence_transformers.sentence_transformer.losses <span>import</span> CachedMultipleNegativesRankingLoss\nloss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=<span>1</span>)\n</code></pre>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#matryoshkaloss\">\n\t</a>\n\t<span>\n\t\tMatryoshkaLoss\n\t</span>\n</h3>\n<p>To produce embeddings that work well at multiple dimensionalities, I wrap the base loss with <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/losses.html#matryoshkaloss\"><code>MatryoshkaLoss</code></a>. This trains the model so that truncating the embedding to a smaller number of dimensions still yields good performance:</p>\n<pre><code><span>from</span> sentence_transformers.sentence_transformer.losses <span>import</span> CachedMultipleNegativesRankingLoss, MatryoshkaLoss\nloss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=<span>1</span>)\nloss = MatryoshkaLoss(model, loss, matryoshka_dims=[<span>2048</span>, <span>1536</span>, <span>1024</span>, <span>512</span>, <span>256</span>, <span>128</span>, <span>64</span>])\n</code></pre>\n<p>This is especially useful for multimodal models, where embeddings can be large (2048 dimensions for Qwen3-VL). With Matryoshka training, you can use truncated embeddings (e.g., 256 or 128 dimensions) at deployment time for faster search with minimal quality loss. As I'll show in the <a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#results\">Results</a> section, the finetuned model achieves near-peak performance even at 512 dimensions.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#training-arguments\">\n\t</a>\n\t<span>\n\t\tTraining Arguments\n\t</span>\n</h2>\n<p>The <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/training_args.html#sentencetransformertrainingarguments\"><code>SentenceTransformerTrainingArguments</code></a> class lets you control training hyperparameters. Here's the configuration used for the VDR finetuning:</p>\n<pre><code><span>from</span> sentence_transformers.sentence_transformer.training_args <span>import</span> SentenceTransformerTrainingArguments, BatchSamplers\nrun_name = <span>\"Qwen3-VL-Embedding-2B-vdr\"</span>\nargs = SentenceTransformerTrainingArguments(\n    <span># Required parameter:</span>\n    output_dir=<span>f\"models/<span>{run_name}</span>\"</span>,\n    <span># Optional training parameters:</span>\n    num_train_epochs=<span>1</span>,\n    per_device_train_batch_size=<span>64</span>,\n    per_device_eval_batch_size=<span>64</span>,\n    learning_rate=<span>2e-5</span>,\n    warmup_ratio=<span>0.1</span>,\n    fp16=<span>False</span>,\n    bf16=<span>True</span>,\n    batch_sampler=BatchSamplers.NO_DUPLICATES,\n    <span># Optional tracking/debugging parameters:</span>\n    eval_strategy=<span>\"steps\"</span>,\n    eval_steps=<span>0.1</span>,\n    save_strategy=<span>\"steps\"</span>,\n    save_steps=<span>0.1</span>,\n    save_total_limit=<span>2</span>,\n    logging_steps=<span>0.05</span>,\n    run_name=run_name,\n)\n</code></pre>\n<p>A few things to note for (multimodal) training:</p>\n<ul>\n<li><code>bf16=True</code>: bfloat16 is generally preferred over float16 due to better numerical stability.</li>\n<li><code>batch_sampler=BatchSamplers.NO_DUPLICATES</code>: When using <code>MultipleNegativesRankingLoss</code> or its cached variant, having no duplicate samples in a batch ensures that every in-batch negative is a truly different sample.</li>\n<li><code>per_device_train_batch_size=64</code>: This may seem large for a 2B parameter VLM, but <code>CachedMultipleNegativesRankingLoss</code> with <code>mini_batch_size=1</code> handles the memory constraints through gradient caching.</li>\n<li><code>eval_steps</code>, <code>save_steps</code>, and <code>logging_steps</code>: Setting these to a fraction (e.g., 0.1) means evaluation, saving, and logging will happen every 10% of an epoch, which is useful for monitoring training progress.</li>\n</ul>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#evaluator\">\n\t</a>\n\t<span>\n\t\tEvaluator\n\t</span>\n</h2>\n<p>To track retrieval performance before, during, and after training, I use the <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/evaluation.html#informationretrievalevaluator\"><code>InformationRetrievalEvaluator</code></a>. It computes standard retrieval metrics like NDCG@10, MAP, and Recall@k:</p>\n<pre><code><span>from</span> sentence_transformers.sentence_transformer.evaluation <span>import</span> InformationRetrievalEvaluator\n<span># Build the evaluation data from the eval dataset.</span>\n<span># Queries and corpus use integer IDs: query 0's relevant document is corpus 0.</span>\neval_queries = {qid: sample[<span>\"query\"</span>] <span>for</span> qid, sample <span>in</span> <span>enumerate</span>(eval_dataset)}\neval_corpus = {did: sample[<span>\"image\"</span>] <span>for</span> did, sample <span>in</span> <span>enumerate</span>(eval_dataset)}\nnum_eval = <span>len</span>(eval_dataset)\n<span># Add hard negatives to the corpus with offset IDs (num_eval, 2*num_eval, ...)</span>\n<span># so they don't collide with the positive document IDs (0..num_eval-1).</span>\nnegative_columns = [<span>\"negative_0\"</span>, <span>\"negative_1\"</span>, <span>\"negative_2\"</span>, <span>\"negative_3\"</span>]\n<span>for</span> neg_idx, neg_col <span>in</span> <span>enumerate</span>(negative_columns):\n    <span>for</span> did, sample <span>in</span> <span>enumerate</span>(eval_dataset):\n        eval_corpus[num_eval * (neg_idx + <span>1</span>) + did] = sample[neg_col]\n<span># Each query's relevant document is the positive at the same index</span>\neval_relevant_docs = {idx: [idx] <span>for</span> idx <span>in</span> <span>range</span>(<span>len</span>(eval_dataset))}\neval_evaluator = InformationRetrievalEvaluator(\n    queries=eval_queries,\n    corpus=eval_corpus,\n    relevant_docs=eval_relevant_docs,\n    batch_size=<span>1</span>,\n    show_progress_bar=<span>True</span>,\n    name=<span>\"vdr-eval-hard\"</span>,\n)\n</code></pre>\n<p>The evaluator takes text queries, a corpus of images (including hard negatives), and a mapping of which documents are relevant to which queries. Note that the corpus contains a mix of positive and hard negative document screenshots, making this a challenging evaluation. Using <code>batch_size=1</code> prevents out-of-memory issues during evaluation of the large VLM.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/train-multimodal-sentence-transformers#trainer\">\n\t</a>\n\t<span>\n\t\tTrainer\n\t</span>\n</h2>\n<p>The <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/sentence_transformer/trainer.html#sentence_transformers.sentence_transformer.trainer.SentenceTransformerTrainer\"><code>SentenceTransformerTrainer</code></a> brings everything together. Here's the complete training script:</p>\n<pre><code><span>from</span> datasets <span>import</span> load_dataset\n<span>from</span> sentence_transformers <span>import</span> SentenceTransformer\n<span>from</span> sentence_transformers.sentence_transformer.evaluation <span>import</span> InformationRetrievalEvaluator\n<span>from</span> sentence_transformers.sentence_transformer.losses <span>import</span> CachedMultipleNegativesRankingLoss, MatryoshkaLoss\n<span>from</span> sentence_transformers.sentence_transformer.model_card <span>import</span> SentenceTransformerModelCardData\n<span>from</span> sentence_transformers.sentence_transformer.trainer <span>import</span> SentenceTransformerTrainer\n<span>from</span> sentence_transformers.sentence_transformer.training_args <span>import</span> (\n    BatchSamplers,\n    SentenceTransformerTrainingArguments,\n)\n<span># 1. Define a loss function</span>\nloss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=<span>1</span>)\nloss = MatryoshkaLoss(model, loss, matryoshka_dims=[<span>2048</span>, <span>1536</span>, <span>1024</span>, <span>512</span>, <span>256</span>, <span>128</span>, <span>64</span>])\n<span># 4. The key difference is using <a target=\"_blank\" href=\"https://sbert.net/docs/package_reference/cross_encoder/trainer.html#sentence_transformers.cross_encoder.trainer.CrossEncoderTrainer\"><code>CrossEncoderTrainer</code></a> and Cross Encoder-specific loss functions. This section provides a brief overview; see the <a target=\"_blank\" href=\"https://github.com/huggingface/sentence-transformers/tree/main/examples/cross_encoder/training/multimodal\">full training examples</a> for complete, runnable scripts with dataset preparation and evaluation.</p>\n<p>Here's a simplified example based on the <a target=\"_blank\" href=\"https://github.com/huggingface/sentence-transformers/blob/main/examples/cross_encoder/training/multimodal/training_doodles_any_to_any.py\">doodles training script</a>, which trains a reranker to match images with text captions:</p>\n<pre><code><span>from</span> sentence_transformers.cross_encoder <span>import</span> CrossEncoder\n<span>from</span> sentence_transformers.cross_encoder.losses <span>import</span> BinaryCrossEntropyLoss\n<span>from</span> sentence_transformers.cross_encoder.modules <span>import</span> LogitScore, Transformer\n<span>from</span> sentence_transformers.cross_encoder.trainer <span>import</span> CrossEncoderTrainer\n<span>from</span> sentence_transformers.cross_encoder.training_args <span>import</span> CrossEncoderTrainingArguments\n<span># 1. Build the model from modules</span>\ntransformer = Transformer(\n    <span>\"Qwen/Qwen3.5-0.8B\"</span>,\n    transformer_task=<span>\"any-to-any\"</span>,\n    model_kwargs={<span>\"torch_dtype\"</span>: <span>\"bfloat16\"</span>, <span>\"device_map\"</span>: <span>\"auto\"</span>, <span>\"attn_implementation\"</span>: <span>\"flash_attention_2\"</span>},\n    processing_kwargs={<span>\"chat_template\"</span>: {<span>\"add_generation_prompt\"</span>: <span>True</span>}},\n)\n<span># Extend chat template to support \"query\" and \"document\" roles</span>\ntransformer.processor.chat_template = transformer.processor.chat_template.replace(\n    <span>'message.role == \"user\"'</span>, <span>'message.role in [\"user\", \"query\", \"document\"]'</span>\n)\n<span># LogitScore: score = log(P(\"1\")) - log(P(\"0\"))</span>\nscore_head = LogitScore(\n    true_token_id=transformer.tokenizer.convert_tokens_to_ids(<span>\"1\"</span>),\n    false_token_id=transformer.tokenizer.convert_tokens_to_ids(<span>\"0\"</span>),\n)\nmodel = CrossEncoder(\n    modules=[transformer, score_head],\n    num_labels=<span>1</span>,\n    prompts={\n        <span>\"image_to_text\"</span>: <span>\"Given the image, judge whether the text matches it. Respond with 1 if they match, 0 if they don't.\"</span>,\n        <span>\"text_to_image\"</span>: <span>\"Given the text, judge whether the image matches it.
