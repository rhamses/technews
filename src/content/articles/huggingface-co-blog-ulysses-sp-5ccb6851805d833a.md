As models are increasingly used for tasks like document analysis, code understanding, complex reasoning, and RAG workloads, the need to process sequences of hundreds of thousands—or even millions—of tokens has grown dramatically. To put this in perspective, an average book is roughly 250k tokens, so training on multi-document contexts or book-length inputs requires handling sequences well beyond what fits on a single GPU. For a sequence of length  <span><span></span></span>, standard attention requires  <span><span></span></span> FLOPs and  <span><span></span></span> memory to compute and store the attention score matrix. Optimized implementations like <a target=\"_blank\" href=\"https://huggingface.co/papers/2205.14135\">FlashAttention</a> reduce the <strong>memory</strong> to  <span><span></span></span> by tiling the computation and never materializing the full attention matrix—but the  <span><span></span></span> compute remains. For very long sequences (32k+ tokens), even with FlashAttention, training still pushes the limits of single-GPU memory.</p>\n<p>Consider these scenarios where long-context training is essential:</p>\n<ul>\n<li><strong>Document understanding</strong>: Processing entire books, legal documents, or research papers</li>\n<li><strong>Code analysis</strong>: Understanding large codebases with multiple interconnected files</li>\n<li><strong>Reasoning tasks</strong>: Models that \"think\" step-by-step may generate thousands of tokens during inference</li>\n<li><strong>Retrieval-augmented generation</strong>: Incorporating many retrieved passages into the context</li>\n</ul>\n<p>Traditional data parallelism doesn't help here—each GPU still needs to process the full sequence inside the attention block. We need a way to split the sequence itself across multiple devices.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#how-ulysses-works\">\n\t</a>\n\t<span>\n\t\tHow Ulysses Works\n\t</span>\n</h2>\n<p>Ulysses Sequence Parallelism (SP), introduced in the <a target=\"_blank\" href=\"https://huggingface.co/papers/2309.14509\">DeepSpeed Ulysses paper</a>, takes a clever approach: in addition to splitting on the sequence dimension, it also partitions the attention heads across GPUs.</p>\n<figure>\n  <img src=\"https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ulysses/ulysses_overview.png\" alt=\"Ulysses Sequence Parallelism Overview\">\n  <figcaption>Ulysses splits input sequences along the sequence dimension and uses all-to-all communication to exchange key-value pairs, enabling each GPU to compute a subset of attention heads. (<b><i>Source: <a target=\"_blank\" href=\"https://www.snowflake.com/en/engineering-blog/ulysses-low-latency-llm-inference/\">Snowflake Engineering Blog</a></i></b>)</figcaption>\n</figure>\n<p>Here's how it works:</p>\n<ol>\n<li><p><strong>Sequence Sharding</strong>: The input sequence is split along the sequence dimension across  <span><span></span></span> GPUs. Each GPU  <span><span></span></span> holds tokens  <span><span></span></span>.</p>\n</li>\n<li><p><strong>QKV Projection</strong>: Each GPU computes the query, key, and value projections for its local sequence chunk.</p>\n</li>\n<li><p><strong>All-to-All Communication</strong>: An all-to-all collective operation redistributes the data so that each GPU holds <em>all</em> sequence positions after the projections, but only for a subset of attention heads.</p>\n</li>\n<li><p><strong>Local Attention</strong>: Each GPU computes attention for its assigned heads using standard attention mechanisms (FlashAttention or SDPA).</p>\n</li>\n<li><p><strong>All-to-All Communication</strong>: Another all-to-all operation reverses the redistribution, returning to sequence-sharded format.</p>\n</li>\n<li><p><strong>Output Projection</strong>: Each GPU computes the output projection for its local sequence chunk.</p>\n</li>\n</ol>\n<p>The key insight is that attention heads are independent—each head can be computed separately. By trading sequence locality for head locality, Ulysses enables efficient parallelization with relatively low communication overhead.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#communication-complexity\">\n\t</a>\n\t<span>\n\t\tCommunication Complexity\n\t</span>\n</h3>\n<p>Ulysses requires two all-to-all operations per attention layer, with total communication volume of <span><span></span></span> per GPU, where:</p>\n<ul>\n<li><span><span></span></span> is the sequence length</li>\n<li><span><span></span></span> is the hidden dimension</li>\n<li><span><span></span></span> is the parallelism degree</li>\n</ul>\n<p>Ring Attention communicates <span><span></span></span> per GPU — a factor of <span><span></span></span> more — via <span><span></span></span> sequential point-to-point transfers around the ring. Ulysses also benefits from lower latency because all-to-all can exploit full bisectional bandwidth in a single collective step, whereas Ring Attention serializes over <span><span></span></span> hops.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#integration-with-accelerate\">\n\t</a>\n\t<span>\n\t\tIntegration with Accelerate\n\t</span>\n</h2>\n<p>Accelerate The main constraint is that Ulysses requires <code>num_heads &gt;= sp_size</code>, while Ring Attention has no such limitation.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#best-practices\">\n\t</a>\n\t<span>\n\t\tBest Practices\n\t</span>\n</h2>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#1-sequence-length-divisibility\">\n\t</a>\n\t<span>\n\t\t1. Sequence Length Divisibility\n\t</span>\n</h3>\n<p>Always ensure your sequence length is divisible by <code>sp_size</code>:</p>\n<pre><code>training_args = SFTConfig(\n    pad_to_multiple_of=<span>4</span>,  <span># For sp_size=4</span>\n    max_length=<span>32768</span>,  <span># Must be divisible by 4</span>\n)\n</code></pre>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#2-use-flash-attention\">\n\t</a>\n\t<span>\n\t\t2. Use Flash Attention\n\t</span>\n</h3>\n<p>Flash Attention 2 provides cleaner output and better performance than SDPA:</p>\n<pre><code>parallelism_config = ParallelismConfig(\n    sp_handler=DeepSpeedSequenceParallelConfig(\n        sp_attn_implementation=<span>\"flash_attention_2\"</span>,\n    ),\n)\n</code></pre>\n<p>Use Flash Attention 3 for Hopper and look out for Flash Attention 4 release for Blackwell (FA2 on Blackwell is quite slow).</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#3-combine-with-deepspeed-zero\">\n\t</a>\n\t<span>\n\t\t3. Combine with DeepSpeed ZeRO\n\t</span>\n</h3>\n<p>For very large models, combine Ulysses with ZeRO Stage 3:</p>\n<pre><code><span>deepspeed_config:</span>\n  <span>zero_stage:</span> <span>3</span>\n  <span>offload_optimizer:</span>\n    <span>device:</span> <span>cpu</span>\n</code></pre>\n<p>If the model is huge, you can offload the params as well by adding to the above:</p>\n<pre><code>  <span>offload_param:</span>\n    <span>device:</span> <span>cpu</span>\n</code></pre>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#5-use-memory-fragmentation-friendly-pytorch-allocator\">\n\t</a>\n\t<span>\n\t\t5. Use memory fragmentation-friendly PyTorch allocator\n\t</span>\n</h3>\n<p>This environment variable will allow for a longer sequence length:</p>\n<pre><code><span>export</span> PYTORCH_ALLOC_CONF=expandable_segments:True\n</code></pre>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#6-2d-parallelism-configuration\">\n\t</a>\n\t<span>\n\t\t6. 2D Parallelism Configuration\n\t</span>\n</h3>\n<p>Balance SP and DP for your GPU count:</p>\n<div>\n\t<table>\n\t\t<thead><tr>\n<th>GPUs</th>\n<th><code>sp_size</code></th>\n<th><code>dp_shard_size</code></th>\n<th>Use Case</th>\n</tr>\n\t\t</thead><tbody><tr>\n<td>4</td>\n<td>2</td>\n<td>2</td>\n<td>Balanced throughput and sequence length</td>\n</tr>\n<tr>\n<td>4</td>\n<td>4</td>\n<td>1</td>\n<td>Maximum sequence length</td>\n</tr>\n<tr>\n<td>8</td>\n<td>2</td>\n<td>4</td>\n<td>Higher throughput with moderate sequence length</td>\n</tr>\n<tr>\n<td>8</td>\n<td>4</td>\n<td>2</td>\n<td>Longer sequences with moderate throughput</td>\n</tr>\n</tbody>\n\t</table>\n</div>\n<p>Remember: <code>dp_replicate_size × dp_shard_size × sp_size = num_processes</code></p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#7-liger-kernel\">\n\t</a>\n\t<span>\n\t\t7. Liger-Kernel\n\t</span>\n</h3>\n<p>If your desired model architecture is supported by <a target=\"_blank\" href=\"https://github.com/linkedin/Liger-Kernel\">Liger-Kernel</a>, it is fully compatible with Ulysses SP and can be enabled with a single flag:</p>\n<pre><code>training_args = SFTConfig(\n    use_liger_kernel=<span>True</span>,\n)\n</code></pre>\n<p>The main memory saving comes from <code>FusedLinearCrossEntropy</code> which avoids materializing the full logits tensor during loss calculation. The savings grow with longer sequences where the logits tensor is larger.</p>\n<p>Additionally, you can enable <a target=\"_blank\" href=\"https://www.deepspeed.ai/tutorials/ulysses-alst-sequence-parallelism/#tiled-mlp-computation\"><code>TiledMLP</code></a> to further extend sequence length — like <code>FusedLinearCrossEntropy</code>, it saves working memory by tiling large matrix operations.</p>\n<h3>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#8-token-distribution-across-ranks\">\n\t</a>\n\t<span>\n\t\t8. Token Distribution Across Ranks\n\t</span>\n</h3>\n<p>You don't need to worry about manually balancing tokens across SP ranks—the loss aggregation code handles uneven distributions gracefully (including ranks with zero valid tokens). With random batching over a reasonably sized dataset, the distribution evens out statistically over training.</p>\n<h2>\n\t<a target=\"_blank\" href=\"https://huggingface.co/blog/ulysses-sp#benchmarks\">\n\t</a>\n\t<span>\n\t\tBenchmarks\n\t</span>\n</h2>\n<p>To quantify the benefits of Ulysses SP, we trained <a target=\"_blank\" href=\"https://huggingface.co/Qwen/Qwen3-4B\">Qwen3-4B</a> on the <a target=\"_blank\" href=\"https://huggingface.co/datasets/sedthh/gutenberg_english\">Gutenberg English</a> streaming dataset using TRL's SFTTrainer.
