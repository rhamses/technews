contentHtml: "<article><div>\n<p>Today we're launching <strong>Supabase Analytics Buckets</strong> in private alpha. These are a new kind of storage bucket optimized for analytics, with built-in support for the <a target=\"_blank\" href=\"https://iceberg.apache.org/\">Apache Iceberg</a> table format.</p>\n<p>Analytics buckets are integrated into Supabase Studio, power table-level views instead of raw files, and can be queried using the new <strong>Supabase Iceberg Wrapper</strong>, also launching in alpha.</p>\n<p></p>\n<p>Apache Iceberg is a high-performance, open table format for large-scale analytics on object storage. It brings the performance and features of a database to the flexibility of flat files.</p>\n<p>We chose Iceberg for its bottomless data model (append-only, immutable history), built-in snapshotting and versioning (time travel), and support for schema evolution. Iceberg is also an open standard widely supported across the ecosystem. Supabase is committed to <a target=\"_blank\" href=\"https://supabase.com/blog/open-data-standards-postgres-otel-iceberg\"><strong>open standards and portability</strong></a>, and Iceberg aligns with that goal by enabling users to move data in and out without being locked into proprietary formats.</p>\n<p>Once your project has been accepted into the alpha release program, Analytics buckets can be created via Studio and the API. To create an analytics bucket, visit <code>Storage &gt; New bucket</code> in Studio.</p>\n<!-- -->\n<p>Analytics buckets are a separate bucket type from standard Supabase Storage buckets. You can't mix file types between the two.</p>\n<p>They're stored in a new system table: <code>storage.buckets_iceberg</code>. These buckets are not included in the <code>storage.buckets</code> table and objects inside them are not shown in <code>storage.objects</code>. However, the <code>listBuckets()</code> endpoint returns a merged list of standard and analytics buckets for consistency with Studio and API consumers.</p>\n<!-- -->\n<p>After creating the bucket, we're met with connection details. Copy the <code>WAREHOUSE</code>, <code>VAULT_TOKEN</code>, and <code>CATALOG_URI</code> values and and create an Iceberg namespace and table using your preferred method. For now, populate Analytics Buckets with your own ingestion pipeline or Iceberg-compatible tooling. This will complete the workflow of <strong>write → store → query</strong>, all inside Supabase.</p>\n<p>Once live, this gives you analytical storage using open formats. As a bonus, Iceberg gets us time travel for free.</p>\n<p>Analytics Buckets are launching in private alpha with the following constraints:</p>\n<ul>\n<li>Two analytics buckets per project</li>\n<li>Up to five namespaces per bucket</li>\n<li>Ten tables per namespace</li>\n<li>Pricing will be announced in a few weeks</li>\n<li>You cannot store standard objects in analytics buckets</li>\n</ul>\n<p>This launch marks the first step toward full analytical capabilities in Supabase. Our goal is to make Supabase a full-featured HTAP backend, where you can write, store, and query analytical data seamlessly.</p>\n<p><a target=\"_blank\" href=\"https://forms.supabase.com/analytics-buckets\">Join the waitlist here</a> to get early access and start working with bottomless, time-travel-capable analytics data inside Supabase.</p></div></article>"
