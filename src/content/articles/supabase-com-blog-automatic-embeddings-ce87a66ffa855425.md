contentHtml: "<article><div>\n<p>Today we’re releasing&#160;<a target=\"_blank\" href=\"https://supabase.com/docs/guides/ai/automatic-embeddings\">automatic embeddings</a> - automate embedding generation and updates using Supabase <a target=\"_blank\" href=\"https://supabase.com/modules/vector\">Vector</a>, <a target=\"_blank\" href=\"https://supabase.com/modules/queues\">Queues</a>, <a target=\"_blank\" href=\"https://supabase.com/modules/cron\">Cron</a>, and <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/pg_net\">pg_net</a> extension, and <a target=\"_blank\" href=\"https://supabase.com/edge-functions\">Edge Functions</a>.</p>\n<p>Embeddings power features like semantic search, recommendations, and retrieval-augmented generation (RAG). They represent text or other content as high-dimensional vectors. At query time, you convert the input into a vector and compare it to stored vectors to find similar items.</p>\n<p>Postgres with&#160;<a target=\"_blank\" href=\"https://github.com/pgvector/pgvector\"><code>pgvector</code></a>&#160;already supports storing and searching over vectors. But generating and maintaining those embeddings has been left to the application. This often means building a separate pipeline just to keep vector data in sync.</p>\n<p>Automatic embeddings bring that pipeline into the database. You can manage embedding generation using SQL, triggers, and extensions like&#160;<code>pgmq</code>, <code>pg_cron</code>, and <code>pg_net</code>. No new runtimes or services are required.</p>\n<p>Most teams implementing semantic features in Postgres end up building their own pipeline. The general pattern looks like this:</p>\n<ol>\n<li>Store source content (e.g. documents, tickets, articles)</li>\n<li>Generate an embedding using an external model</li>\n<li>Store the result in a vector column</li>\n<li>Re-run the embedding job if the content changes</li>\n<li>Handle retries if the model fails or times out</li>\n</ol>\n<p>This pipeline is easy to describe but hard to implement. It introduces inconsistency between your source of truth (Postgres) and derived data (the embeddings). It also requires background workers, queues, observability, and external coordination.</p>\n<p>Here are some ways this pipeline can fall apart:</p>\n<ul>\n<li><strong>Drift</strong>. If you update the content but forget to re-embed it, your search quality drops.</li>\n<li><strong>Latency</strong>. Some embedding APIs are slow or rate-limited. If you call them synchronously on write, you add latency to the write path.</li>\n<li><strong>Lack of resilience</strong>. If your background worker dies or the queue fails, you may not notice until things break.</li>\n<li><strong>Schema duplication</strong>. Your application ends up duplicating logic that could live in the schema.</li>\n</ul>\n<p>Automatic embeddings move the vector generation step into Postgres. Not literally. Inference still happens via an external model, but the responsibility for coordinating that process becomes part of your database.</p>\n<p>When a row is inserted or updated, Postgres can automatically enqueue a job to generate or refresh its embedding. That job runs in the background, retries if it fails, and stores the result back into the vector column.</p>\n<p>This approach has a few benefits:</p>\n<ul>\n<li><strong>No drift</strong>. Embeddings stay in sync with content updates.</li>\n<li><strong>Bring your own model</strong>. You can point to any API that returns a vector.</li>\n<li><strong>All SQL</strong>. You can enqueue, inspect, and retry embedding jobs without leaving Postgres.</li>\n</ul>\n<p>A number of use cases get easier when embeddings are automatically managed:</p>\n<ul>\n<li>Build semantic search without leaving SQL</li>\n<li>Keep embeddings fresh as data changes</li>\n<li>Use vector search for deduplication or anomaly detection</li>\n<li>Combine structured and semantic filters in a single query</li>\n<li>Enrich or classify rows using embedding-based inheritance</li>\n</ul>\n<p>There are two approaches to automatic embeddings today:</p>\n<h3 id=\"generated-columns\">Generated columns<a target=\"_blank\" href=\"https://supabase.com/blog/automatic-embeddings#generated-columns\">#</a></h3>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>create table documents (</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  id uuid primary key,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  content text,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  embedding vector(1536) generated always as (embed(content)) stored</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>);</span></p></div><br></code></p></div>\n<p>This uses a generated column to call an embedding function on write. It only works if your model is local and fast. In practice, this approach with the <code>embed()</code> function blocks the write path and doesn’t scale well.</p>\n<h3 id=\"trigger-based-asynchronous-embeddings\">Trigger-based asynchronous embeddings<a target=\"_blank\" href=\"https://supabase.com/blog/automatic-embeddings#trigger-based-asynchronous-embeddings\">#</a></h3>\n<p>This is the pattern we use at Supabase. It uses a few common extensions:</p>\n<ul>\n<li>SQL triggers to enqueue work when rows are inserted or updates</li>\n<li><code>pgmq</code> to enqueue embedding jobs inside a transactional message queue</li>\n<li><code>pg_net</code> to send async HTTP requests to an Edge Function (and in turn, embedding provider like OpenAI)</li>\n<li><code>pg_cron</code> to run workers that process the queue</li>\n<li><code>pgvector</code> for storing and searching over embeddings</li>\n</ul>\n<p>You can inspect the queue, retry failed jobs, and customize the Edge Function used to generate embeddings. You can find the complete reference implementation in the&#160;<a target=\"_blank\" href=\"https://supabase.com/docs/guides/ai/automatic-embeddings\">Supabase Automatic Embeddings Guide</a>.</p>\n<p>After applying the implementation from the guide, it is as easy as adding two triggers to a table.</p>\n<h3 id=\"set-up-the-table\">Set up the table<a target=\"_blank\"
