contentHtml: "<article><div><p>tl;dr: Supabase Branching is now in open beta! You can enable it on any project that's Pro Plan or above.</p>\n<p>Branching is a seamless integration of Git with your development workflow, extending beyond your local environment to a remote database. Leveraging Git, particularly focusing on GitHub initially, each time a Pull Request is opened, a corresponding \"Preview Environment\" is spawned.</p>\n<!-- -->\n<p>Preview Branches are essentially full Supabase instances. Every push triggers migrations from the <code>./supabase/migrations</code> folder, ensuring team synchronization and a shared source of truth. When you merge a Pull Request, your migrations are applied to the Production database.</p>\n<p>We <a target=\"_blank\" href=\"https://supabase.com/blog/supabase-branching\">announced Branching</a> a few months ago in our previous Launch Week, with a deep dive on a few of the features like data seeding, integrations with Vercel, and seamless handling of environment variables. Since launching Branching for early-access we've worked with early users of all sizes. Today we're making Branching available to everyone.</p>\n<p>Our open Beta introduces a number of requested features:</p>\n<h3 id=\"edge-function-support\">Edge Function support<a target=\"_blank\" href=\"https://supabase.com/blog/branching-publicly-available#edge-function-support\">#</a></h3>\n<p>Branching now deploys your Edge Functions along with your migrations. Any Functions added or changed in your <code>./supabase/functions</code> will automatically be deployed without any extra configuration.</p>\n<h3 id=\"monorepo-support\">Monorepo support<a target=\"_blank\" href=\"https://supabase.com/blog/branching-publicly-available#monorepo-support\">#</a></h3>\n<p>You can now set a custom Supabase directory path which allows for monorepo support. You can also choose to only spin up new branches when there are changes inside your Supabase directory. See all the configuration settings in your projects <a target=\"_blank\" href=\"https://supabase.com/dashboard/project/_/settings/integrations\">here</a>.</p>\n<h3 id=\"persistent-branches\">Persistent branches<a target=\"_blank\" href=\"https://supabase.com/blog/branching-publicly-available#persistent-branches\">#</a></h3>\n<!-- -->\n<p>We had quite a few users of branching request for long-running branches so we added the concept of persistent branches. In persistent mode, a branch will remain active even after the underlying PR merges or closes.</p>\n<p>Please note that branches should still be treated as replaceable at any time. Persistent or ephemeral Branches should not be used for production data.</p>\n<p>A special thank you to all our early-access branching users who provided lots of actionable feedback. Our feature development was largely driven by the direct feedback from our users.</p>\n<p>We still have many features to add to branching before 1.0, so please continue <a target=\"_blank\" href=\"https://github.com/orgs/supabase/discussions/18937\">sending us your feedback</a>!</p>\n<p>You can easily get started with Branching by following our <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/branching#how-to-use-supabase-branching\">Getting Started Guide</a>.</p></div></article>"
