contentHtml: "<article><div><p>Branching without Git is now the default for all Supabase projects.</p>\n<p>Supabase has supported database branching through a git-based workflow since <a target=\"_blank\" href=\"https://supabase.com/blog/supabase-branching\">Launch Week X</a>. That workflow connects your GitHub repo to Supabase, tracks migrations in version control, and creates preview branches automatically when you open a pull request. It works well for teams that manage their database schema as code. But it requires a GitHub connection, which rules out anyone who doesn't work that way.</p>\n<p><a target=\"_blank\" href=\"https://supabase.com/blog/branching-2-0\">Branching 2.0</a> removed that requirement. You create a branch from the dashboard, make changes using the SQL Editor or Table Editor, review a schema diff, and merge. No git configuration required. It shipped behind a feature preview. Today, that preview is gone.</p>\n<p>Branching without Git is on by default for every project. It adds a second path for developers who want to iterate on their schema without setting up a Git integration. Both approaches are fully supported, and you can switch between them or use them together. If you're already using git-based branching, nothing changes.</p>\n<p><strong>Branching without Git</strong></p>\n<p>Create branches directly from the Supabase Dashboard. Your branch gets its own Postgres instance with your current production schema. Make changes, preview the diff, and merge. The whole workflow stays inside Supabase.</p>\n<p>Choose this when:</p>\n<ul>\n<li>You're prototyping schema changes and want fast iteration</li>\n<li>Your team manages the database primarily through the dashboard</li>\n<li>You're working with AI tools that create and manage branches programmatically</li>\n<li>You want to try branching without any upfront configuration</li>\n</ul>\n<p><strong>Git-based branching</strong></p>\n<p>Connect a GitHub repo to your Supabase project. Migrations live in version control. Branches are created automatically when you open a pull request and cleaned up when the PR is closed.</p>\n<p>Choose this when:</p>\n<ul>\n<li>Your team already manages database migrations in git</li>\n<li>You want schema changes reviewed as part of your pull request workflow</li>\n<li>You need an audit trail of every migration in version control</li>\n<li>You prefer an infrastructure-as-code approach to database management</li>\n</ul>\n<p>You can start with dashboard branching and add a git integration later when your workflow demands it. The two approaches use the same underlying infrastructure.</p>\n<p><strong>1. Create a branch</strong></p>\n<p>Open your project in the Supabase Dashboard and click \"Create Branch.\" Pick a name. Your branch spins up with your current production schema.</p>\n<!-- -->\n<p><strong>2. Make changes</strong></p>\n<p>Use the branch like any Supabase project. Add tables, modify columns, update RLS policies, change functions. Every schema change you make in the SQL Editor or Table Editor is tracked.</p>\n<p><strong>3. Review the diff</strong></p>\n<p>When you're ready to merge, Supabase generates a migration diff showing exactly what changed between your branch and production. This diff is powered by pg-delta, our new schema diffing engine.</p>\n<!-- -->\n<p><strong>4. Merge</strong></p>\n<p>Review the generated migration, confirm, and merge. Your schema changes are applied to production.</p>\n<!-- -->\n<p>The merge experience depends on accurate schema diffs. We built pg-delta from scratch inside <a target=\"_blank\" href=\"https://github.com/supabase/pg-toolbelt\">pg-toolbelt</a> to handle the full range of Postgres objects: tables, columns, RLS policies, functions, triggers, indexes, and extensions.</p>\n<p>When you merge a branch, pg-delta compares the two schemas and generates the correct migration statements. It replaces migra as the default diffing engine for dashboard branching, with better coverage of Postgres-specific DDL.</p>\n<p>pg-delta is also available in the Supabase CLI behind a flag for the <code>diff</code> command if you want to try it locally.</p>\n<p>Every branch created through the Supabase MCP server uses dashboard branching automatically. When an AI tool needs to iterate on your database schema, it can create a branch, make changes, and merge, all without touching git. The branch exists for as long as the agent needs it and gets cleaned up when the work is done.</p>\n<p>Branching is available now in your dashboard.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://supabase.com/dashboard\">Dashboard</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/deployment/branching\">Branching documentation</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/supabase/pg-toolbelt\">pg-delta on GitHub</a></li>\n</ul>\n<p>If you're using the git-based workflow today, nothing changes. Your existing setup continues to work. Dashboard branching is the new default for new projects and for users who haven't configured a git integration.</p></div></article>"
