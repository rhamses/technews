You can directly import millions of popular, commonly used npm modules into your Edge Functions.</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>import { drizzle } from 'npm:drizzle-orm/node-postgres'</span></p></div><br></code></p></div>\n<p>You can migrate your existing Node apps to Supabase Edge Functions with minimal changes.</p>\n<p>We created a demo to show how to migrate a Node app that uses Express, Node Postgres, and Drizzle. This custom version helps us keep Edge Functions working the same way no matter where it is deployed - on our hosted platform, in local development, or in your self-hosted environment.</p>\n<p>The biggest challenge when adding npm support was finding an approach that would work across all environments. We wanted to keep the workflow close to the Deno CLI experience. It should be possible to import npm modules directly in your source code without an extra build step.</p>\n<p>When deploying a Function, we serialize its module graph into a single file format (an <a target=\"_blank\" href=\"https://github.com/denoland/eszip\">eszip</a>). In the hosted environment, all module references are then loaded from the eszip. This prevents any extra latency in fetching modules and potential conflicts between module dependencies.</p>\n<p>We used the eszip module loader in the local and self-hosted environments too, so we only need to implement one module-loading strategy for all environments. As an additional benefit for local development, this approach avoids potential conflicts with npm modules installed in the user's system since the Edge Function's npm modules are self-contained within the eszip.</p>\n<p><a target=\"_blank\" href=\"https://github.com/supabase/edge-runtime/pull/223\">Refactoring the module loader</a> fixes a few other bugs, such <a target=\"_blank\" href=\"https://github.com/supabase/cli/issues/1584#issuecomment-1848799355\">edge functions erroring out</a> when an <code>deno.lock</code> file is already present in the project.</p>\n<h3 id=\"regional-invocations\">Regional Invocations<a target=\"_blank\" href=\"https://supabase.com/blog/edge-functions-node-npm#regional-invocations\">#</a></h3>\n<p>You now have the option to specify a region when running an Edge Function (perhaps we should change the name in the future). Usually, Edge Functions run in the region closest to the user invoking the Function. However, sometimes you want to run it closer to your Postgres database or another 3rd party API for optimal performance.</p>\n<p>Functions are still deployed to all regions.
