contentHtml: "<article><div><p>Over the past 3 months, the team has been focused on <strong>security</strong>, <strong>performance</strong>, and <strong>stability</strong>. This is always part of our mandate, but for this period we have been <em>exclusively</em> focused on this task.</p>\n<p>And we haven't been alone with security. <a target=\"_blank\" href=\"https://x.com/xyz3va/\">@xyzeva</a> (Eva), a rising star in the world of security, has been instrumental in the past 3 months - everything from discovering misconfigured projects to collaborating on fixes and features.</p>\n<p>This post outlines the key initiatives that we have collaborated on and a few more in the pipeline.</p>\n<p>Eva and her colleagues are the authors of <a target=\"_blank\" href=\"https://env.fail/posts/firewreck-1/\">Firewreck</a>, which exposed the misconfiguration of Firebase instances. This <a target=\"_blank\" href=\"https://news.ycombinator.com/item?id=39743225\">HN comment</a> highlights the key challenges for Firebase (paraphrased):</p>\n<blockquote>\n<p>.. First, security rules as implemented by Firebase are still a novel concept.</p>\n</blockquote>\n<blockquote>\n<p>.. Second, without the security of obscurity created by random in-house implementations of backends, scanning en masse becomes easier.</p>\n</blockquote>\n<blockquote>\n<p>.. Finally, security rules are just hard.</p>\n</blockquote>\n<blockquote>\n</blockquote>\n<p>And then an important technical distinction:</p>\n<blockquote>\n<p>Technically there is nothing wrong with the Firebase approach but ... it opens itself up to misunderstanding, improper use, and issues like this.</p>\n</blockquote>\n<p>Security is a <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/shared-responsibility-model\">Shared Responsibility Model</a>. The more control you are given with a technology, the more opportunity you have to make a mistake.</p>\n<p>We believe that we can give developers full control of their tools, while <em>also</em> being the most secure platform to develop with. How?</p>\n<ul>\n<li>By providing security tooling, baked deeply into our platform.</li>\n<li>By leaning into existing standards like Postgres Row Level Security (RLS), instead of using custom systems.</li>\n</ul>\n<p>This post consolidates the tools and guides that we have available for the community.</p>\n<h3 id=\"lunchcat\">Lunchcat<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#lunchcat\">#</a></h3>\n<p>Eva has added support for Supabase in <a target=\"_blank\" href=\"https://lunchcat.dev/\">Lunchcat</a>, the AI-Powered security company she works for. Parts of this tooling is available for <a target=\"_blank\" href=\"https://github.com/lunchcat/sif\">self-hosting</a> today, and will be available as an integration once their platform is publicly available.</p>\n<h3 id=\"security-advisor\">Security Advisor<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#security-advisor\">#</a></h3>\n<p>We launched our <a target=\"_blank\" href=\"https://supabase.com/blog/security-performance-advisor\">Security Advisor</a> in the last Launch Week. Eva was a big contributor to this, helping to set up a robust set of <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/database-advisors\">security rules</a>. These rules are available in <a target=\"_blank\" href=\"https://supabase.com/dashboard/project/_/advisors/security\">the Dashboard</a>, many with one-click solutions.</p>\n<h3 id=\"security-emails-and-notifications\">Security emails and notifications<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#security-emails-and-notifications\">#</a></h3>\n<p>The security rules in our Security Advisor are run against all of your projects and project owners now receive weekly emails with a list of security issues that need to be solved. Since all of the advisories are <a target=\"_blank\" href=\"https://github.com/supabase/splinter\">open source</a>, you can also use them inside your CI/CD pipeline.</p>\n<h3 id=\"disabling-the-default-data-api\">Disabling the default Data API<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#disabling-the-default-data-api\">#</a></h3>\n<p>We have made it even easier to turn off the Data API if you don’t plan to use it. When you launch a project you can choose whether you want to create it with <em>only</em> Postgres connections, or if you also want the Data API. You can also turn off the Data API at any time in your <a target=\"_blank\" href=\"https://supabase.com/dashboard/project/_/settings/api\">project settings</a>.</p>\n<h3 id=\"api-hardening\">API hardening<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#api-hardening\">#</a></h3>\n<p>We have made it simple to switch the default schema from <code>public</code> to <code>api</code> in the <a target=\"_blank\" href=\"https://supabase.com/dashboard/project/_/settings/api\">API Settings page</a>. We have also released a guide for <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/hardening-data-api\">Hardening the Data API</a>, outlining various approaches for using the Data API. It’s very likely that we will make this the default set up in the future to align with PostgREST’s <a target=\"_blank\" href=\"https://docs.postgrest.org/en/v12/explanations/schema_isolation.html\">Schema Isolation</a> guide.</p>\n<h3 id=\"column-level-security\">Column level security<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#column-level-security\">#</a></h3>\n<p>We’ve added <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/postgres/column-level-security\">guides</a> and a <a target=\"_blank\" href=\"https://supabase.com/dashboard/project/_/database/column-privileges\">simple-to-use dashboard</a> for column-level grants. This allows you to manage Postgres <a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/sql-grant.html\">grants</a> for every role (including the default Supabase <code>anon</code> and <code>service_role</code>). Combining this with RLS gives you extremely fine-grained control of your database.</p>\n<h3 id=\"user-impersonation\">User impersonation<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#user-impersonation\">#</a></h3>\n<p>We have added <a target=\"_blank\" href=\"https://supabase.com/blog/studio-introducing-assistant\">User/Role impersonation</a> to the Dashboard. You can use this to switch between anonymous and authenticated roles, or even go as deep as selecting an individual user (if you use Supabase Auth) to see the level of data that they use.</p>\n<h3 id=\"rls-ai-assistant\">RLS AI Assistant<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#rls-ai-assistant\">#</a></h3>\n<p>RLS policies are even easier with our new GPT-4o powered <a target=\"_blank\" href=\"https://github.com/orgs/supabase/discussions/21882\">AI Assistant</a>. We want Row Level Security to be easier than any other security tool on the market. We have added a ton of <a target=\"_blank\" href=\"https://github.com/supabase/supabase/blob/master/packages/ai-commands/src/sql/rls.test.ts\">tests</a> to ensure that we have the most accurate Postgres RLS assistant available, for free.</p>\n<h3 id=\"network-restrictions\">Network Restrictions<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#network-restrictions\">#</a></h3>\n<p>You can <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/network-restrictions\">restrict access</a> to your database at the network level for any direct access to your database. This is especially useful when you’re getting started and only want to give direct access to your own IP address.</p>\n<h3 id=\"and-more\">And more<a target=\"_blank\" href=\"https://supabase.com/blog/hardening-supabase#and-more\">#</a></h3>\n<p>Our docs are full of best practices and useful info:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/going-into-prod\">Production Checklist</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/shared-responsibility-model\">Shared responsibility model</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/maturity-model\">Maturity model</a></li>\n</ul>\n<p>Since we see a few common complaints about Row Level Security, we figured we would address them.</p>\n<ul>\n<li>\n<p><em>“It’s unsafe to communicate from the browser directly to the database.”</em></p>\n<p>The Database-centric approach is a three-tier architecture, the same as any other tool like NodeJs, Django, or RoR. The key difference is that you write your security rules in the SQL. It is also a different “workflow” from a three-tier approach, where traditionally you write authorization rules as part of your middleware rather than when you are setting up your database.</p>\n<p>Supabase is <strong>agnostic</strong> which approach you take. If SQL makes you uncomfortable, you can use the Postgres server we provide just like any other Postgres service.</p>\n</li>\n</ul>\n<ul>\n<li>\n<p><em>“I turned off RLS while prototyping.”</em></p>\n<p>By default, Supabase enables RLS for all tables created via the dashboard. Some developers disable this while they are prototyping which is not recommended. The best way to solve this is to use our <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli\">CLI for Local Development</a>. The CLI provides the entire Supabase stack, directly on your local development machine.</p>\n</li>\n<li>\n<p><em>\"I forgot to enable RLS.\"</em></p>\n<p>Our dashboard has copious warnings when you have disabled RLS for any table. We also surface this in the Security Advisor, warnings via email and dashboard notifications.</p>\n</li>\n</ul>\n<p>That said, there are some legitimate difficulties with RLS - it’s not a silver bullet by any means. We are planning a lot more tooling to make this easier for Postgres and Supabase developers.</p>\n<p>This is just the beginning of our tooling efforts, with many more ideas in the pipeline. We have hired dedicated security engineers to continue working on these initiatives, including:</p>\n<ul>\n<li>\n<p><em>Improved Security Advisor</em></p>\n<p>As we continue to discover misconfigurations and potential vulnerabilities we will continue to improve the suite of security <a target=\"_blank\" href=\"https://github.com/supabase/splinter\">rules</a> that we enable across our entire fleet of database.</p>\n</li>\n<li>\n<p><em>Network restrictions 2.0</em></p>\n<p>Networking should be as easy as using the database in Supabase. We’ve got a tonne of plans for this: network peering, <a target=\"_blank\" href=\"https://tailscale.com/\">Tailscale</a> integration, better API Key management, fine-grained restrictions for each service and project scoped roles.</p>\n</li>\n<li>\n<p><em>OpenAPI management</em></p>\n<p>We will be giving developers the ability to control the visibility of the OpenAPI spec based on the Postgres roles and grants. This provides some level of security through obscurity.</p>\n</li>\n<li>\n<p><em>Development on \"Hard mode\"</em></p>\n<p>Not all projects are alike. While some require extremely strict levels of access, others can be a bit more relaxed. This is explained in our <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/maturity-model\">Maturity Models</a> framework. We are brainstorming ways to codify this, so that developers can “turn up” the enforced security levels on their projects, restricting what developers can and cannot do.</p>\n</li>\n<li>\n<p><em>CI/CD warnings</em></p>\n<p>We will be adding the <a target=\"_blank\" href=\"https://github.com/supabase/splinter\">Security Advisories</a> into our CLI for first-class support within GitHub Actions and CI/CD pipelines. Combined with <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/branching\">Branching</a>, this prevents security misconfigurations before they ever reach production.</p>\n</li>\n<li>\n<p><em>Revamped API keys</em></p>\n<p>Soon we will be replacing the <code>anon</code> and <code>service_role</code> API keys with a simpler <code>public</code> and <code>admin</code> key. This new setup will be conceptually similar, but will allow developers to create more fine-grained authorization rules and allow them to roll individual keys in case of a leak.</p>\n</li>\n</ul>\n<p>Eva approached us during our last Launch Week. While she was helping us with the Security Advisor she discovered a misconfiguration in one of our own applications using Supabase with <a target=\"_blank\" href=\"https://lunchcat.dev/\">Lunchcat</a>. We were able to solve this quickly by toggling off read access to the <code>anon</code> role and scanning the <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/logs\">access logs</a> to ensure no malicious actors had accessed the data.</p>\n<p>At the time, we didn’t have the Security Advisor to help the developer discover the misconfiguration before publishing. The Supabase Security suite is being developed to prevent this ever occurring again - for us and for our customers.</p>\n<p>But no platform is infallible: when tooling doesn’t work, we rely on our community to help discover and responsibly disclose any vulnerabilities. We are launching a private Vulnerability Disclosure Program today with HackerOne. We commit to transitioning to a public disclosure program in a month, once we iron out the initial kinks. If you cannot wait till then, use our <a target=\"_blank\" href=\"https://hackerone.com/ca63b563-9661-4ac3-8d23-7581582ef451/embedded_submissions/new\">secret link</a> submit a report.</p>\n<p>If you find any misconfigured projects, please let us know. We will work with those customers to ensure that they know about the issue and can solve it. If you are a security professional, we welcome your help to secure the Supabase community.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/going-into-prod\">Production Checklist</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/shared-responsibility-model\">Shared responsibility model</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/maturity-model\">Maturity Model</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/postgres/row-level-security\">Row Level Security</a> &amp; <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/postgres/column-level-security\">Column Level Security</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/api/securing-your-api\">Securing the Data API</a> &amp; <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/hardening-data-api\">Hardening the Data API</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/postgres/custom-claims-and-role-based-access-control-rbac\">Custom Claims &amp; RBAC</a></li>\n</ul></div></article>"
