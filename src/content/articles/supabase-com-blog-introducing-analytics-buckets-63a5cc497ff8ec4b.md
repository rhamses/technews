Postgres is great for your app. But Postgres isn't designed for analytical workloads.</p>\n<p>Analytics Buckets are a specialized storage type in Supabase designed for analytical workloads and built on <a target=\"_blank\" href=\"https://iceberg.apache.org/\">Apache Iceberg</a> and Amazon S3. They store data in columnar Parquet format, which is optimized for scans, aggregations, and time-series queries.</p>\n<p>Think of them as cold storage for your data, with a query engine attached.</p>\n<p>Your hot transactional data stays in Postgres. Your historical data and analytical workloads live in Analytics Buckets. You query both using familiar tools.</p>\n<p>Analytics Buckets give you:</p>\n<ul>\n<li>\n<p><strong>Cost-effective storage.</strong> S3 pricing instead of database storage. Documented savings of 30-90% on storage costs for large datasets.</p>\n</li>\n<li>\n<p><strong>Open table format.</strong> Apache Iceberg means no vendor lock-in. Query your data from any compatible tool.</p>\n</li>\n<li>\n<p><strong>Schema evolution.</strong> Change your table schema without rewriting data.</p>\n</li>\n<li>\n<p><strong>Time travel.</strong> Query historical snapshots of your data. See what a table looked like at any point in time.</p>\n</li>\n<li>\n<p><strong>Full audit history.</strong> Every change is preserved. Track what changed, when, and how.</p>\n</li>\n</ul>\n<h2 id=\"when-to-use-analytics-buckets-vs-postgres\">When to use Analytics Buckets vs Postgres<a target=\"_blank\" href=\"https://supabase.com/blog/introducing-analytics-buckets#when-to-use-analytics-buckets-vs-postgres\">#</a></h2>\n<p>Analytics Buckets and Postgres are complementary. They serve different workloads.</p>\n<h3 id=\"keep-data-in-postgres-when\">Keep data in Postgres when:<a target=\"_blank\" href=\"https://supabase.com/blog/introducing-analytics-buckets#keep-data-in-postgres-when\">#</a></h3>\n<ul>\n<li>\n<p>You need low-latency reads for your application</p>\n</li>\n<li>\n<p>Data changes frequently and consistency matters</p>\n</li>\n<li>\n<p>Your dataset is small to medium size</p>\n</li>\n<li>\n<p>You need real-time access from your app</p>\n</li>\n</ul>\n<h3 id=\"use-analytics-buckets-when\">Use Analytics Buckets when:<a target=\"_blank\" href=\"https://supabase.com/blog/introducing-analytics-buckets#use-analytics-buckets-when\">#</a></h3>\n<ul>\n<li>\n<p>You are storing millions or billions of rows</p>\n</li>\n<li>\n<p>You run heavy analytical queries that scan large tables</p>\n</li>\n<li>\n<p>You need long-term retention at low cost</p>\n</li>\n<li>\n<p>You want to query data from multiple tools</p>\n</li>\n<li>\n<p>You need complete audit history and time travel</p>\n</li>\n</ul>\n<p>Many teams use both. Keep the last 90 days in Postgres. Archive everything to Analytics Buckets. Query historical data when needed.</p>\n<p>Analytics Buckets use <a target=\"_blank\" href=\"https://iceberg.apache.org/\">Apache Iceberg</a>, an open table format created for large analytical datasets.
