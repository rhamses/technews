contentHtml: "<article><div>\n<p>Today we are releasing <a target=\"_blank\" href=\"https://github.com/supabase/iceberg-js\"><code>iceberg-js</code></a>, a minimal, vendor-agnostic JavaScript client for the Apache Iceberg REST Catalog API.</p>\n<p><a target=\"_blank\" href=\"https://iceberg.apache.org/\">Apache Iceberg</a> is becoming the standard for large-scale analytics workloads. But until now, JavaScript and TypeScript developers have lacked a simple way to interact with Iceberg REST Catalogs.</p>\n<p>We recently launched <a target=\"_blank\" href=\"https://supabase.com/blog/introducing-analytics-buckets\">Analytics Buckets</a> in the Supabase Dashboard. This feature lets you create and manage Iceberg tables directly from the Supabase UI. To power this experience, we needed a JavaScript library that could talk to Iceberg REST Catalogs.</p>\n<p>We looked around and did not find what we needed. Most Iceberg tooling is built for JVM languages like Java and Scala. The JavaScript ecosystem had nothing lightweight and focused. So we built iceberg-js.</p>\n<p>We care about supporting open-source tools and communities, and creating developer-friendly libraries is one of the ways we contribute.</p>\n<p><code>iceberg-js</code> is a thin HTTP wrapper that mirrors the official Iceberg REST API. It provides a 1:1 mapping to the API, making it easy to manage namespaces and tables from any JavaScript or TypeScript environment.</p>\n<p>The library is designed around a few core principles:</p>\n<p>First, it is generic. It works with any Iceberg REST Catalog implementation. It is not tied to any specific vendor.</p>\n<p>Second, it is minimal. There is no engine-specific logic and no heavy dependencies. It uses the native fetch API with support for custom implementations.</p>\n<p>Third, it is type-safe. It provides full TypeScript support with strongly-typed request and response models.</p>\n<p>We were deliberate about what <code>iceberg-js</code> should not do. Keeping the scope narrow is what makes the library maintainable.</p>\n<ul>\n<li>\n<p><code>iceberg-js</code> does not support data operations. It cannot read or write Parquet files. For that, use a query engine like DuckDB, Spark, or Trino.</p>\n</li>\n<li>\n<p>It does not support query execution. It is purely a catalog management tool.</p>\n</li>\n<li>\n<p>It does not include engine-specific integrations. No Spark, Flink, or other engine code.</p>\n</li>\n<li>\n<p>It does not support advanced features like branching, tagging, or time travel queries beyond basic metadata operations.</p>\n</li>\n</ul>\n<p>These boundaries exist on purpose. For data operations, pair <code>iceberg-js</code> with a query engine that supports Iceberg.</p>\n<p>Install the package:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>npm install iceberg-js</span></p></div><br></code></p></div>\n<p>Create a catalog client and start managing namespaces and tables:</p>\n<div><p><code><br><div><p><span>_<!-- -->15</span></p><p><span>import { IcebergRestCatalog } from 'iceberg-js'</span></p></div><div><p><span>_<!-- -->15</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>const catalog = new IcebergRestCatalog({</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>  baseUrl: 'https://my-catalog.example.com/iceberg/v1',</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>  auth: {</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>    type: 'bearer',</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>    token: process.env.ICEBERG_TOKEN,</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>  },</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>})</span></p></div><div><p><span>_<!-- -->15</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>// Create a namespace</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>await catalog.createNamespace({ namespace: ['analytics'] })</span></p></div><div><p><span>_<!-- -->15</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>// List tables</span></p></div><div><p><span>_<!-- -->15</span></p><p><span>const tables = await catalog.listTables({ namespace: ['analytics'] })</span></p></div><br></code></p></div>\n<p>The library supports multiple authentication methods including bearer tokens, custom headers, and custom functions for dynamic authentication.</p>\n<p><code>iceberg-js</code> works everywhere JavaScript runs. It supports Node.js (ESM and CommonJS), TypeScript, modern browsers, Deno, and all major bundlers like Webpack, Vite, and Rollup.</p>\n<p>All compatibility scenarios are tested in CI on Node.js 20 and 22.</p>\n<p><code>iceberg-js</code> is MIT licensed and <a target=\"_blank\" href=\"https://github.com/supabase/iceberg-js\">available on GitHub</a>. We welcome contributions that align with the library's goals. Note, as mentioned above, the library is intentionally focused. We plan to keep it that way. If you need features outside the scope of catalog management, we recommend pairing <code>iceberg-js</code> with a query engine.</p>\n<p>You can start using <code>iceberg-js</code> today.</p>\n<ul>\n<li>\n<p>GitHub: <a target=\"_blank\" href=\"https://github.com/supabase/iceberg-js\">github.com/supabase/iceberg-js</a></p>\n</li>\n<li>\n<p>API Documentation: <a target=\"_blank\" href=\"https://supabase.github.io/iceberg-js/\">supabase.github.io/iceberg-js/</a></p>\n</li>\n<li>\n<p>npm: <a target=\"_blank\" href=\"https://www.npmjs.com/package/iceberg-js\">npmjs.com/package/iceberg-js</a></p>\n</li>\n</ul></div></article>"
