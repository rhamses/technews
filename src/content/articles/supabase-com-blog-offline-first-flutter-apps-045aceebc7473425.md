contentHtml: "<article><div>\n<p>Brick is an&#160;<a target=\"_blank\" href=\"https://www.youtube.com/watch?v=2noLcro9iIw\">all-in-one</a> data manager for Flutter that handles querying and uploading between Supabase and local caches like SQLite. Using Brick, developers can focus on implementing the application without&#160;<a target=\"_blank\" href=\"https://www.youtube.com/watch?v=jm5i7e_BQq0\">worrying about translating or storing their data</a>.</p>\n<p>Most significantly, Brick focuses on offline-first data parity: an app should function the same with or without connectivity.</p>\n<h3 id=\"why-offline\">Why Offline?<a target=\"_blank\" href=\"https://supabase.com/blog/offline-first-flutter-apps#why-offline\">#</a></h3>\n<p>The worst version of your app is always the unusable one. People use their phones on subways, airplanes, and on sub-3G connections. Building for offline-first provides the best user experience when you can’t guarantee steady bandwidth.</p>\n<p>Even if you’re online-only, Brick’s round trip time is drastically shorter because all data <a target=\"_blank\" href=\"https://getdutchie.github.io/brick/#/offline_first/offline_first_with_supabase_repository\">from Supabase is stored in a local cache</a>. When you query the same data again, your app retrieves the local copy, reducing the time and expense of a round trip. And, if SQLite isn’t performant enough, Brick also offers a third cache in memory. When requests are made while the app is offline, they’ll be <a target=\"_blank\" href=\"https://getdutchie.github.io/brick/#/offline_first/offline_queue\">continually retried until the app comes online</a>, ensuring that your local state syncs up to your remote state.</p>\n<p>Of course, you can <a target=\"_blank\" href=\"https://getdutchie.github.io/brick/#/offline_first/policies\">always opt-out of the cache</a> on a request-by-request basis for sensitive or must-be-fresh data.</p>\n<h3 id=\"getting-started\">Getting Started<a target=\"_blank\" href=\"https://supabase.com/blog/offline-first-flutter-apps#getting-started\">#</a></h3>\n<p>Create a Flutter app:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>flutter create my_app</span></p></div><br></code></p></div>\n<p>Add the Brick dependencies to your <code>pubspec.yaml</code>:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>dependencies:</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  brick_offline_first_with_supabase: ^1.0.0</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  sqflite: ^2.3.0</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  brick_sqlite: ^3.1.0</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  uuid: ^3.0.4</span></p></div><div><p><span>_<!-- -->10</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>dev_dependencies:</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  brick_offline_first_with_supabase_build: ^1.0.0</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  build_runner: ^2.4.0</span></p></div><br></code></p></div>\n<p>Set up directories for Brick’s generated code:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>mkdir -p lib/brick/adapters lib/brick/db;</span></p></div><br></code></p></div>\n<p>Brick synthesizes your remote data to your local data through code generation.
