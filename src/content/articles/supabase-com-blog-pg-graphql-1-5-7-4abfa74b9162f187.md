A quick roundup of the key differences includes:</p>\n<ul>\n<li>Pagination via First/Offset</li>\n<li>Schema based multi-tenancy</li>\n<li>Filtering on array typed columns with <code>contains</code>, <code>containedBy</code> and <code>overlaps</code></li>\n</ul>\n<p>Since the earliest days of pg_graphql, <a target=\"_blank\" href=\"https://supabase.github.io/pg_graphql/api/#keyset-pagination\">keyset pagination</a> has been supported. Keyset pagination allows for paging forwards and backwards through a collection by specifying a number of records and the unique id of a record within the collection. For example:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>{</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  blogCollection(</span></p></div><div><p><span>_<!-- <code>offset</code> number of records before returning the results.</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>{</span></p></div><div><p><span>_<!-- -->10</span></p><p><span> values increase, the performance of the query will decrease. For that reason its important to use keyset pagination where possible.</p>\n<p>pg_graphql caches the database schema on first query and rebuilds that cache any time the schema changes. The cache key is a combination of the postgres role and the database schema's version number. Initially, the structure of all schemas was loaded for all roles, and table/column visibility was filtered down within <code>pg_graphql</code>.</p>\n<p>In multi-tenant environments with 1 schema per tenant, that meant every time a tenant updated their schema, all tenants had to rebuild the cache. When the number of tenants gets large, that burdens the database if its under heavy load.</p>\n<p>Following version <code>1.5.2</code> each tenant's cache only loads the schemas that they have <code>usage</code> permission for, which greatly reduces the query time in multi-tenant environments and the size of the schema cache. At time of writing this solution powers a project with &gt;2200 tenants.</p>\n<p>From <code>1.5.6</code> pg_graphql has added <code>contains</code>, <code>containedBy</code>, <code>overlaps</code>
