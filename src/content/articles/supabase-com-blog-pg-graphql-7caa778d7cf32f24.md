contentHtml: "<article><div>\n<p>Today we're open sourcing <a target=\"_blank\" href=\"https://github.com/supabase/pg_graphql\"><code>pg_graphql</code></a>, a native PostgreSQL extension adding GraphQL support. The extension keeps schema generation, query parsing, and resolvers all neatly contained on your database server requiring no external services.</p>\n<p><code>pg_graphql</code> inspects an existing PostgreSQL schema and reflects a GraphQL schema with resolvers that are:</p>\n<ul>\n<li>performant</li>\n<li>always up-to-date</li>\n<li>compliant with best practices</li>\n<li>serverless</li>\n<li>open source</li>\n</ul>\n<p>Interested? You're <a target=\"_blank\" href=\"https://supabase.github.io/pg_graphql/quickstart/\">3 commands away</a> from a live <a target=\"_blank\" href=\"https://graphql-dotnet.github.io/docs/getting-started/graphiql/\">GraphiQL</a> demo.</p>\n<p>The Supabase stack is centered around PostgreSQL as the single source of truth. All data, configuration, and security are housed in the database so any GraphQL solution needed to be equivalently SQL-centric.</p>\n<p>With that in mind, we took a look at the landscape and considered two excellent technologies, <a target=\"_blank\" href=\"https://www.graphile.org/postgraphile/\">Graphile</a>, and <a target=\"_blank\" href=\"https://hasura.io/\">Hasura</a>.</p>\n<table><thead><tr><th>Requirements</th><th>Graphile</th><th>Hasura</th></tr></thead><tbody><tr><td>Open Source</td><td>✅</td><td>✅</td></tr><tr><td>Reflected GraphQL Schema</td><td>✅</td><td>✅</td></tr><tr><td>Reflected Resolvers</td><td>✅</td><td>✅</td></tr><tr><td>Always up-to-date</td><td>✅</td><td>✅</td></tr><tr><td>Performant</td><td>✅</td><td>✅</td></tr></tbody></table>\n<p>We found both options to be largely viable for the core feature set.</p>\n<p>Which left us with one final hang-up: we host free-tier projects on VMs with 1 GB of memory. After tallying the resources reserved for PostgreSQL, PostgREST, Kong, GoTrue, and a handful of smaller services, we were left with a total memory budget of ... 0 MB 😬. Unsurprisingly, our pathological memory target disqualified any option that required launching another process in those VMs.</p>\n<p>For that reason, we decided to invest in a lightweight alternative that runs in the database, and can be exposed over HTTP using the existing <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/api\">PostgREST</a> deployments' <a target=\"_blank\" href=\"https://postgrest.org/en/v8.0/api.html#stored-procedures\">RPC functionality.</a></p>\n<p>By our most conservative estimate, that reduces the platform's memory requirements by 525 TB/hours every month, saving 💰 and 🌳.</p>\n<p>As a native PostgreSQL extension, <code>pg_graphl</code> is written in a combination of C and SQL. Each GraphQL query is parsed, validated, and transpiled to SQL, all within the database.</p>\n<p>Each GraphQL request is resolved by a single SQL statement. That SQL statement aggregates requested data as a JSON document to return to the caller. This approach results in blazing fast response times, avoids the <a target=\"_blank\" href=\"https://medium.com/the-marcy-lab-school/what-is-the-n-1-problem-in-graphql-dd4921cb3c1a\">N+1 query problem</a>, and hits the theoretical minimum achievable network IO overhead of any GraphQL to SQL resolver. No special permissions are required for the PostgreSQL role executing queries, so <code>pg_graphql</code> is fully compatible with your existing <a target=\"_blank\" href=\"https://supabase.com/docs/guides/auth/row-level-security\">row level security policies</a>.</p>\n<p>Embedding the GraphQL server directly in the database allows us to leverage PostgreSQL's built-in solutions for common challenges:</p>\n<p>Caching → <code>PREPARE STATEMENT</code></p>\n<p>Errors → <code>RAISE EXCEPTION</code></p>\n<p>Bad Data → <code>ROLLBACK</code></p>\n<p>Authorization → <code>CREATE POLICY</code></p>\n<p>Similarly, <code>pg_graphql</code> benefits from PostgreSQL's strong <a target=\"_blank\" href=\"https://database.guide/what-is-acid-in-databases/\">ACID</a> guarantees and can expose them through its API.</p>\n<p>Ever wanted to execute multiple operations in a single transaction? Each request is managed in a single transaction so with a multi-operation GraphQL request and <code>pg_graphql</code>, that behavior falls out for free!</p>\n<h3 id=\"schema-reflection\">Schema
