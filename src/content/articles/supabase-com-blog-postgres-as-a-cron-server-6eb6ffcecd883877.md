contentHtml: "<article><div>\n<p>A Supabase user asked recently if they can trigger a webhook periodically. We haven't yet released Functions yet, so we checked whether it's possible with Postgres.</p>\n<p>It is. Here's how.</p>\n<h3 id=\"whats-cron\">What's cron?<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#whats-cron\">#</a></h3>\n<p>A \"cron job\" is a script<sup><a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#user-content-fn-1\">1</a></sup> that runs periodically at fixed times, dates, or intervals. Traditionally you'd set it up on a Linux server. An example might be an hourly script that downloads emails to your computer.</p>\n<p>These days, cron jobs are set up on a remote servers and in the cloud to run internet-related tasks. Like checking an endpoint every hour, or scraping a website every day.</p>\n<h3 id=\"postgres--cron\">Postgres + cron<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#postgres--cron\">#</a></h3>\n<p>Postgres has \"extensions\" which allow you to, well, extend the database with \"non-core\" features. Extensions essentially turn Postgres into an application server.</p>\n<p>The team at <a target=\"_blank\" href=\"https://github.com/citusdata\">Citus</a> created <a target=\"_blank\" href=\"https://github.com/citusdata/pg_cron\"><code>pg_cron</code></a> to run periodic jobs within your Postgres database.</p>\n<h4 id=\"enabling-the-extension\">Enabling the extension<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#enabling-the-extension\">#</a></h4>\n<p>If you're using a cloud-hosted Postgres database, make sure that <code>pg_cron</code> is installed first. The easiest way to do this is to run this command:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select name, comment, default_version, installed_version</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from pg_available_extensions</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>where name = 'pg_cron';</span></p></div><br></code></p></div>\n<p>If it returns a result then the extension is supported and you can turn it on by running:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>create extension if not exists pg_cron;</span></p></div><br></code></p></div>\n<p>If you're using Supabase you can also enable it in the Dashboard.</p>\n<h4 id=\"granting-access-to-the-extension\">Granting access to the extension<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#granting-access-to-the-extension\">#</a></h4>\n<p>If you're planning to use a <code>non-superuser</code> role to schedule jobs, ensure that they are granted access to the <code>cron</code> schema and its underlying objects beforehand.</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>grant usage on schema cron to {{DB user}};</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>grant all privileges on all tables in schema cron to {{DB user}};</span></p></div><br></code></p></div>\n<p>Failure to do so would result in jobs by these roles to not run at all.</p>\n<h3 id=\"postgres--webhooks\">Postgres + webhooks<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#postgres--webhooks\">#</a></h3>\n<p>The Supabase customer wanted to call external endpoints every day. How would we do this? Another extension of course. This time we're going to use <a target=\"_blank\" href=\"https://github.com/pramsey/pgsql-http\">pgsql-http</a> by <a target=\"_blank\" href=\"https://github.com/pramsey\">@pramsey</a>. Using the same technique, we can enable the extension (if it exists in your cloud provider).</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>create extension if not exists http;</span></p></div><br></code></p></div>\n<p>This extension can now be used for <a target=\"_blank\" href=\"https://github.com/pramsey/pgsql-http#functions\">sending</a> <code>GET</code>, <code>POST</code>, <code>PATCH</code>, and <code>DELETE</code> requests.</p>\n<p>For example, this function would get all the people in Star Wars (using the <a target=\"_blank\" href=\"https://swapi.dev/\">Star Wars API</a>):</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select content::json-&gt;'results'</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from http_get('https://swapi.dev/api/people');</span></p></div><br></code></p></div>\n<h3 id=\"postgres--cron--webhooks\">Postgres + cron + webhooks<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#postgres--cron--webhooks\">#</a></h3>\n<p>Now the fun stuff. For this example we're going to call <a target=\"_blank\" href=\"https://webhook.site/\">webhook.site</a> every minute with the payload <code>{ \"hello\": \"world\" }</code>.</p>\n<p>Here's the code (with comments <code>--like this</code>).</p>\n<div><p><code><br><div><p><span>_<!-- -->14</span></p><p><span>select</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>  cron.schedule(</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>    'webhook-every-minute', -- name of the cron job</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>    '* * * * *', -- every minute</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>    $$</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>    select status</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>    from</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>      http_post(</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>        'https://webhook.site/223c8a43-725b-4cbd-b1fe-d0da73353a6b', -- webhook URL, replace the ID(223c8..) with your own</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>        '{\"hello\": \"world\"}', -- payload</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>        'application/json'</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>      )</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>    $$</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>  );</span></p></div><br></code></p></div>\n<p>Now when we see that the payload is sent every minute, exactly on the minute.</p>\n<p>And that's it! We've built a cron webhook. Breaking down the code example above we have 2 key parts:</p>\n<h4 id=\"posting-data\">POSTing data<a target=\"_blank\" -->10</span></p><p><span>select status</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  http_post(</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    'https://webhook.site/223c8a43-725b-4cbd-b1fe-d0da73353a6b', -- webhook URL</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    '{\"hello\": \"world\"}', -- payload</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    'application/json'</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  );</span></p></div><br></code></p></div>\n<h4 id=\"scheduling-the-job\">Scheduling the job<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#scheduling-the-job\">#</a></h4>\n<p>The HTTP function is wrapped with the CRON scheduler:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  cron.schedule(</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    'cron-name', -- name of the cron job</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    '* * * * *', -- every minute</span></p></div><div><p><span>_<!-- -->10</span></p><p><span> $$</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  );</span></p></div><br></code></p></div>\n<p>The second parameter uses cron syntax:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span> ┌───────────── min (0 - 59)</span></p></div><div><p><span>_<!-- -->10</span></p><p><span> │ ┌────────────── hour (0 - 23)</span></p></div><div><p><span>_<!-- href=\"https://supabase.com/blog/postgres-as-a-cron-server#what-can-i-do-with-this\">#</a></h3>\n<p>There are plenty use-cases for this. For example:</p>\n<ul>\n<li><strong>Sending welcome emails.</strong> If you use an email provider with an HTTP API, then you batch emails to that service. Write a function that <code>selects</code> all your signups yesterday, then sends them to your favorite transactional email service. Schedule it every day to run at midnight.</li>\n<li><strong>Aggregating data.</strong> If you're providing analytical data, you might want to aggregate it into time periods for faster querying (which serves a similar purpose as a <a target=\"_blank\" href=\"https://supabase.com/blog/postgresql-views#materialized-views-vs-conventional-views\">Materialized View</a>).</li>\n<li><strong>Deleting old data.</strong> Need to free up space? Run a scheduled job to delete data you no longer need.</li>\n</ul>\n<p>See a detailed list in the <a target=\"_blank\" href=\"https://github.com/citusdata/pg_cron#example-use-cases\"><code>pg_cron</code> README</a>.</p>\n<h3 id=\"postgres-background-workers\">Postgres background workers<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#postgres-background-workers\">#</a></h3>\n<p>You might have noticed <a target=\"_blank\" href=\"https://github.com/pramsey/pgsql-http#why-this-is-a-bad-idea\">this</a> notice the warning at the bottom of the <code>http</code> readme:</p>\n<blockquote>\n<p>\"What happens if the web page takes a long time to return?\" Your SQL call will just wait there until it does. Make sure your web service fails fast.</p>\n</blockquote>\n<p>Luckily pg_cron implements <a target=\"_blank\" href=\"https://paquier.xyz/postgresql-2/postgres-9-3-feature-highlight-custom-background-workers/\">Background Workers</a>:</p>\n<blockquote>\n<p>Care is taken that these extra processes do not interfere with other postmaster tasks: only one such process is started on each ServerLoop iteration. This means a large number of them could be waiting to be started up and postmaster is still able to quickly service external connection requests.</p>\n</blockquote>\n<p>This means that even if your endpoint takes a long time to return, it's not going to be blocking your core Postgres functions. Either way, you should probably only call endpoints that will return a response quickly, or set the http extension to fail fast (<code>http.timeout_msec = 300</code>).</p>\n<p>If you're familiar with <code>C</code>, you could also help <code>@pramsey</code> to implement async functions: <a target=\"_blank\" href=\"https://github.com/pramsey/pgsql-http/issues/105\">https://github.com/pramsey/pgsql-http/issues/105</a></p>\n<h3 id=\"should-i-use-postgres-as-a-cron-server\">Should I use Postgres as a cron server?<a target=\"_blank\" href=\"https://supabase.com/blog/postgres-as-a-cron-server#should-i-use-postgres-as-a-cron-server\">#</a></h3>\n<p>There are plenty of ways to run cron jobs these days. You can trigger them from your local machine. You can install them on a VPS. You can schedule Serverless functions. You can use a paid service. You can use GitHub Actions.</p>\n<p>Is Postgres the best place to put your cron jobs? <code>¯\\_(ツ)_/¯</code>.
