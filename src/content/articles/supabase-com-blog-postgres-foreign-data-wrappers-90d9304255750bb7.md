contentHtml: "<article><div>\n<p>Foreign Data Wrappers (FDWs) allow Postgres to interact with externally hosted data. To operate a FDW, the user creates a foreign table. When queried, the foreign table reaches out to the 3rd party service, collects the requested data, and returns it to the query in the shape defined by the foreign table. This allows seamless querying and data manipulation across different tools as if they were local tables from within Postgres.</p>\n<p><a target=\"_blank\" href=\"https://github.com/supabase/wrappers\">Wrappers</a> is a Rust framework for creating Postgres Foreign Data Wrappers. Today we're releasing support for <a target=\"_blank\" href=\"https://webassembly.org/\">Wasm (WebAssembly)</a> wrappers.</p>\n<p>With this feature, anyone can create a Wasm wrapper to an external service and run it directly from e.g. GitHub:</p>\n<div><p><code><br><div><p><span>_<!-- -->14</span></p><p><span>-- An Example Google Sheets Wasm Wrapper:</span></p></div><div><p><span>_<!-- Provide custom options</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>\tbase_url 'https://docs.google.com/spreadsheets/d'</span></p></div><div><p><span>_<!-- -->14</span></p><p><span>  );</span></p></div><br></code></p></div>\n<p>This feature is available today in public alpha for all new projects.</p>\n<p></p>\n<p><a target=\"_blank\" href=\"https://wiki.postgresql.org/wiki/Foreign_data_wrappers\">Foreign Data Wrappers (FDW)</a> are a powerful feature of Postgres that allows you to connect to and query external data sources as if they were regular tables.</p>\n<p><a target=\"_blank\" href=\"https://github.com/supabase/wrappers\">Wrappers</a> is an open source project that simplifies the creation of Postgres Foreign Data Wrappers using <a target=\"_blank\" href=\"https://www.rust-lang.org/\">Rust</a>.</p>\n<p><a target=\"_blank\" href=\"https://webassembly.org/\">WebAssembly (Wasm)</a> is a binary instruction format that enables secure and high-performance execution of code on the web. It is originally designed for web browsers, but now can also be used in server-side environments like Postgres.</p>\n<p>Here's how the Wasm FDW benefits us:</p>\n<ul>\n<li><strong>Improved Security:</strong> Wasm's sandboxed execution runtime with minimum interfaces enhances the security of FDW.</li>\n<li><strong>Simplified Development:</strong> Developers can use <a target=\"_blank\" href=\"https://www.rust-lang.org/\">Rust</a> to create complex FDWs without diving deep into Postgres internal API.</li>\n<li><strong>Simplified Distribution:</strong> Easily distribute your Wasm FDW through any URL-accessible storage (such as GitHub or S3).</li>\n<li><strong>Enhanced Performance:</strong> Wasm's near-native speed ensures FDWs operate with minimal overhead.</li>\n<li><strong>Increased Modularity:</strong> Each Wasm FDW is an isolated package which is dynamically loaded and executed by Wrappers individually.</li>\n</ul>\n<p>To better understand how the Wasm FDW works, let's take a look at the architecture:</p>\n<p>The above diagram illustrates the key components and how they interact:</p>\n<ol>\n<li><strong>Supabase Wrappers Extension (Host):</strong> This is the core component that runs within Postgres. It includes below modules:<!-- -->\n<ul>\n<li><strong>Wasm Runtime:</strong> Provides runtime environment to executes the Wasm FDW package.</li>\n<li><strong>HTTP Interface:</strong> Manages communication with external data sources through HTTP.</li>\n<li><strong>Utilities:</strong> Helper tools and functions to support FDW operations.</li>\n<li>Other modules providing specific functionalities, such like JWT, stats and etc.</li>\n</ul>\n</li>\n<li><strong>Wasm FDWs (Guests):</strong> Isolated, dynamically-loaded Wasm packages that perform data fetching and processing. They execute in a sandboxed environment to ensure security and performance. For example:<!-- -->\n<ul>\n<li><strong>Snowflake Wasm FDW:</strong> A foreign data wrapper specifically designed to interact with <a target=\"_blank\" href=\"https://www.snowflake.com/\">Snowflake</a>.</li>\n<li><strong>Paddle Wasm FDW:</strong> Another FDW example, tailored for <a target=\"_blank\" href=\"https://www.paddle.com/\">Paddle</a> integration.</li>\n</ul>\n</li>\n<li><strong>Web Storage:</strong> Represents external storage services like <a target=\"_blank\" href=\"https://github.com/\">GitHub</a> or <a target=\"_blank\" href=\"https://aws.amazon.com/s3/\">S3</a>, where Wasm packages can be publicly stored and downloaded from.</li>\n<li><strong>External Data Source:</strong> Various external systems which data is fetched from or pushed to, such as <a target=\"_blank\" href=\"https://www.snowflake.com/\">Snowflake</a> and <a target=\"_blank\" href=\"https://www.paddle.com/\">Paddle</a>. Data is accessed using RESTful APIs.</li>\n</ol>\n<p>Wasm FDWs are loaded dynamically when the first request is made. The interaction flow is:</p>\n<ol>\n<li><strong>Wasm download:</strong> The Wasm FDWs are dynamically downloaded from web storage services, like GitHub or S3, and cached locally. This happens the first time the <code>SELECT</code> statement is initiated.</li>\n<li><strong>Initialization and Execution:</strong> Once downloaded, the Wasm FDWs are initialized and executed within the embedded Wasm runtime environment. This provides a secure, sandboxed execution environment that isolates the packages from the main Postgres system.</li>\n<li><strong>Data Fetching via RESTful API:</strong> The Wasm FDWs interact with their respective external data sources via RESTful APIs.</li>\n<li><strong>Query Handling and Data Integration:</strong> When a query is executed against a foreign table in Postgres, the Supabase Wrappers extension invokes the appropriate Wasm FDW, fetches data from the external source, processes it, and returns it to the Supabase Wrappers, which integrates it back into the Postgres query execution pipeline.</li>\n</ol>\n<p>The Wasm FDW currently only supports data sources which have HTTP(s) based JSON API, other sources such like TCP/IP based DBMS or local files are not supported yet.</p>\n<p>A major benefit of Wasm FDW is that you can build your own FDW and use it on Supabase. To get started, clone the <a target=\"_blank\" href=\"https://github.com/supabase-community/postgres-wasm-fdw\">Postgres Wasm FDW [Template]</a>. Building your own Wasm FDWs opens up a world of possibilities for integrating diverse data sources into Postgres.</p>\n<p>Visit <a target=\"_blank\" href=\"https://fdw.dev/guides/create-wasm-wrapper/\">Wrappers docs and guides</a> to learn more about how to develop a Wasm FDW.</p>\n<p>The Wasm FDW feature is available today on the Supabase platform. We have 2 new built-in Wasm FDWs: <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/snowflake\">Snowflake</a> and <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/paddle\">Paddle</a>.</p>\n<p>To get started, follow below steps:</p>\n<ol>\n<li>Create a new Supabase project: <a target=\"_blank\" href=\"http://database.new/\">database.new</a></li>\n<li>Navigate to the <a target=\"_blank\" href=\"https://supabase.com/dashboard/project/_/database/wrappers\">Database -&gt; Wrappers</a> section and enable Wrappers.</li>\n<li>Add <code>Snowflake</code> or <code>Paddle</code> wrapper, follow the instructions and create foreign tables.</li>\n</ol>\n<p>We can also use SQL.
