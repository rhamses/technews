contentHtml: "<article><div>\n<p><a target=\"_blank\" href=\"https://github.com/PostgREST/postgrest/releases/tag/v12.2.0\">PostgREST 12.2</a> is out! It comes with Observability and API improvements. In this post, we'll see what's new.</p>\n<p>Version 12.2 ships with Prometheus-compatible metrics for PostgREST's schema cache and connection pool. These are useful for troubleshooting, for example, when PostgREST's pool is starved for connections.</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>curl localhost:3001/metrics</span></p></div><div><p><span>_<!-- -->10</span></p></div><div><p><span>_<!-- -->10</span></p><p><span># HELP pgrst_db_pool_timeouts_total The total number of pool connection timeouts</span></p></div><div><p><span>_<!-- -->10</span></p><p><span># TYPE pgrst_db_pool_timeouts_total counter</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>pgrst_db_pool_timeouts_total 7.0</span></p></div><div><p><span>_<!-- -->10</span></p></div><div><p><span>_<!-- -->10</span></p><p><span># ....</span></p></div><br></code></p></div>\n<p>A full list of supported metrics is available in the <a target=\"_blank\" href=\"https://postgrest.org/en/latest/references/observability.html#metrics\">PostgREST documentation</a>.</p>\n<p>Sometimes it's handy to set a custom timeout per function. You can now do this on 12.2 projects with:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>create or replace function special_function()</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>returns void as $$</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  select pg_sleep(3); -- simulating some long-running process</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>$$</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>language sql</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>set statement_timeout to '4s';</span></p></div><br></code></p></div>\n<p>And calling the function with the <a target=\"_blank\" href=\"https://supabase.com/docs/reference/javascript/rpc\">RPC interface</a>.</p>\n<p>When doing <code>set statement_timeout</code>on the function, the <code>statement_timeout</code> will be “hoisted” and applied per transaction.</p>\n<p>By default this also works for other settings, namely <code>plan_filter.statement_cost_limit</code> and <code>default_transaction_isolation</code>. The list of hoisted settings can be extended by modifying the <a target=\"_blank\" href=\"https://postgrest.org/en/latest/references/configuration.html#db-hoisted-tx-settings\">db-hoisted-tx-settings</a> configuration.</p>\n<p>Before 12.2, this could be done by setting a <code>statement_timeout</code> on the API roles, but this affected all the SQL statements executed by those roles.</p>\n<p>In prior versions of PostgREST, users could limit the number of records impacted by mutations (insert/update/delete) to 1 row using vendor media type <code>application/vnd.pgrst.object+json</code>. That supports a common use case but is not flexible enough to support user defined values.</p>\n<p>12.2 introduces the <code>max-affected</code> preference to limit the affected rows up to a custom value.</p>\n<p>For example:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>curl -i \"http://localhost:3000/items?id=lt.15\" -X DELETE \\</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  -H \"Content-Type: application/json\" \\</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  -H \"Prefer: handling=strict, max-affected=10\"</span></p></div><br></code></p></div>\n<p>If the number of affected records exceeds <code>max-affected</code> , an error is returned:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>HTTP/1.1 400 Bad Request</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>{</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    \"code\": \"PGRST124\",</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    \"message\": \"Query result exceeds max-affected preference constraint\",</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    \"details\": \"The query affects 14 rows\",</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>    \"hint\": null</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>}</span></p></div><br></code></p></div>\n<p>PostgREST v12.2 is already available on the Supabase platform on its latest patch version (<a target=\"_blank\" href=\"https://github.com/PostgREST/postgrest/releases/tag/v12.2.3\">v12.2.3</a>) for new projects. Spin up a new project or upgrade your existing project to try it out!</p></div></article>"
