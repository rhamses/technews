contentHtml: "<article><div><p>Startups are hard. One of our favorite startups, Snaplet, is <a target=\"_blank\" href=\"https://www.snaplet.dev/post/snaplet-is-shutting-down\">shutting down</a>. Despite that, they built an amazing team (some who now work at Supabase) and some incredible products.</p>\n<p>One way to ensure that your products out-live your business is to open source what you've built. I'm a huge fan of what Snaplet built so I reached out to <a target=\"_blank\" href=\"https://x.com/appfactory/\">Peter</a> to see if Snaplet were interested in open sourcing. He said yes:</p>\n<blockquote><p>I built Snaplet because I believe developers write better software when they have access to\nproduction-like data. Although the company is closing, my belief remains strong, so we are\nopen-sourcing the tools we've built.</p><div><p><img alt=\"Peter Pistorius, Founder of Snaplet avatar\" src=\"https://supabase.com/_next/image?url=%2Fimages%2Fblog%2Favatars%2Fpeter-snaplet.webp&w=64&q=75\"></p><figcaption><p>Peter Pistorius, Founder of Snaplet</p></figcaption></div></blockquote>\n<p>There are 3 main tools that they are releasing under the MIT license:</p>\n<h3 id=\"copycat\">Copycat<a target=\"_blank\" href=\"https://supabase.com/blog/snaplet-is-now-open-source#copycat\">#</a></h3>\n<p>Copycat generates fake data. It's like faker.js, but deterministic: for any given input it'll always produce the same output. For example, if you generate an email with the user ID <code>user_1234</code>, the next time you generate an email with that email it will be the same, <em>guaranteed:</em></p>\n<ul>\n<li>Repo: <a target=\"_blank\" href=\"https://github.com/snaplet/copycat\">github.com/snaplet/copycat</a></li>\n</ul>\n<h3 id=\"snaplet-seed\">Snaplet Seed<a target=\"_blank\" href=\"https://supabase.com/blog/snaplet-is-now-open-source#snaplet-seed\">#</a></h3>\n<p>Seed generates realistic synthetic data based off a database schema. It automatically determines the values in your database so you don't have to define each value. For example, if you want to generate a 3 <code>comments</code> for one of your <code>posts</code> you simply point it at your schema and let it handle the rest:</p>\n<ul>\n<li>Repo: <a target=\"_blank\" href=\"https://github.com/snaplet/seed\">github.com/snaplet/seed</a></li>\n<li>Docs: <a target=\"_blank\" href=\"https://snaplet-seed.netlify.app/seed\">docs.snaplet.dev/seed</a></li>\n</ul>\n<h3 id=\"snapshot\">Snapshot<a target=\"_blank\" href=\"https://supabase.com/blog/snaplet-is-now-open-source#snapshot\">#</a></h3>\n<p>Snapshot is for capturing, transforming, and restoring snapshots of your database. It's like an advanced version of pg_dump/pg_restore. It has a particularly neat feature called “subsetting”. Point it at a database table and it tell it how much data you need. To maintain referential integrity, subsetting traverses tables, selecting all the rows that are connected to the target table through foreign key relationships:</p>\n<ul>\n<li>Repo: <a target=\"_blank\" href=\"https://github.com/snaplet/snapshot\">github.com/snaplet/snapshot</a></li>\n<li>Docs: <a target=\"_blank\" href=\"https://snaplet-snapshot.netlify.app/snapshot\">docs.snaplet.dev/snapshot</a></li>\n</ul>\n<p>The Snaplet team who joined Supabase have been helping Peter to migrate these projects to open source. Over the next few weeks we'll move these into the Supabase GitHub org and pick up the ongoing maintenance.</p>\n<p>We prefer to keep products decoupled (it's one of our <a target=\"_blank\" href=\"https://supabase.com/docs/guides/getting-started/architecture#everything-works-in-isolation\">Principles</a>), so you'll always be able to use these tools independently from Supabase. We can also see a lot of value providing a deep integration, so we've already started adding their <a target=\"_blank\" href=\"https://supabase.com/docs/guides/local-development/seeding-your-database#generating-seed-data\">Snaplet Seed</a> to our official docs. This is just a start, watch this space!</p>\n<p>Peter is back at <a target=\"_blank\" href=\"https://redwoodjs.com/\">RedwoodJS</a>, which he co-founded before Snaplet. He's been working on React Server Components, coming soon to Redwood.</p></div></article>"
