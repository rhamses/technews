contentHtml: "<article><div>\n<p>Today we're releasing Supabase Agent Skills, an open-source set of instructions that teach AI coding agents how to build on Supabase correctly. If you use Claude Code, Codex, GitHub Copilot, Cursor, or any of the agents that support <a target=\"_blank\" href=\"https://agentskills.io/\">Agent Skills Open Standard</a>, you can install the skill in one command and get better results on every Supabase task.</p>\n<p>AI agents already know a lot about Supabase. We hit <a target=\"_blank\" href=\"https://supabase.com/blog/100000-github-stars\">100k stars on GitHub</a>, and most models have seen plenty of Supabase code in their training data. But knowing about Supabase and using it correctly are two different things. We kept seeing agents skip RLS policies on exposed schemas, hallucinate CLI commands that don't exist (like <code>supabase db execute</code>), create views without <code>security_invoker = true</code> (which silently bypasses RLS), and ignore the docs entirely, relying on training data that may be months out of date.</p>\n<p>This is a follow-up to our earlier work on <a target=\"_blank\" href=\"https://supabase.com/blog/postgres-best-practices-for-ai-agents\">Postgres best practices for AI agents</a>. That release focused on general Postgres patterns. Supabase Agent Skills goes further: it covers all Supabase products, encodes security requirements inline, and teaches agents to check the docs before implementing anything.</p>\n<p>Install it with one command:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>npx skills add supabase/agent-skills</span></p></div><br></code></p></div>\n<p>Or install as a Claude Code plugin:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span># 1. Install supabase/agent-skill marketplace</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>claude plugin marketplace add supabase/agent-skills</span></p></div><div><p><span>_<!-- -->10</span></p></div><div><p><span>_<!-- -->10</span></p><p><span># 2. Install the supabase plugin</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>claude plugin install supabase@supabase-agent-skills</span></p></div><br></code></p></div>\n<p>The skill covers four areas: documentation access, security, tooling workflow, and schema management. Everything critical lives directly inside <code>SKILL.md</code>, about 100 lines total. We put it there on purpose.</p>\n<h3 id=\"docs-and-product-knowledge\">Docs and product knowledge<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-agent-skills#docs-and-product-knowledge\">#</a></h3>\n<p>The core principle: verify against current docs before implementing.</p>\n<p>Supabase moves fast. Config options, product documentation and API conventions are examples of things that will change over time. An agent working from training data alone is essentially working from a snapshot — one that could be months or years old.</p>\n<p>The skill instructs agents to look up documentation before writing any Supabase-specific code, using three methods in priority order:</p>\n<ol>\n<li><strong>MCP <code>search_docs</code> tool</strong>: returns relevant snippets ordered by relevance</li>\n<li><strong>Fetch docs as markdown</strong>: use bash tools like <code>curl</code> to fetch Supabase docs as markdown files. Supabase docs pages can be fetched as markdown by appending <code>.md</code> to its URL</li>\n<li><strong>Native web search tools</strong>: freely search the web whenever the other two options are not available</li>\n</ol>\n<p>The skill doesn't tell agents what the current API looks like. It tells them how to find out. This keeps the skill small, maintainable, and always accurate — the docs are the source of truth, and they're already maintained. There's no value in replicating them inside the skill.</p>\n<h3 id=\"security-and-rls\">Security and RLS<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-agent-skills#security-and-rls\">#</a></h3>\n<p>Supabase has specific security configurations that the agent might miss. These instructions are described in detail in our documentation. The skill instructs agents to check the Supabase docs before implementing anything, but agents are lazy about it: even with <code>search_docs</code> available, they can choose to keep it offline and go with what they already know from training data rather than making an extra round-trip. That means security configurations and patterns might get missed even when the correct guidance exists in the docs.</p>\n<p>To ensure agents never skip these, the skill includes an inline checklist of security requirements that apply to every Supabase project. These aren't pulled from docs on demand — they're loaded with the skill, so the agent has no excuse to miss them:</p>\n<ul>\n<li><strong>Never use <code>user_metadata</code> for authorization.</strong> It's user-editable. Use <code>app_metadata</code> instead.</li>\n<li><strong>Never expose the <code>service_role</code> key on the frontend.</strong> In Next.js, any <code>NEXT_PUBLIC_</code> env var is sent to the browser.</li>\n<li><strong>Views bypass RLS by default.</strong> Use <code>security_invoker = true</code>.</li>\n<li><strong>UPDATE requires a SELECT policy.</strong> Without one, updates silently return 0 rows. No error, just no change.</li>\n<li><strong>Storage upsert requires INSERT + SELECT + UPDATE.</strong> Granting only INSERT makes file replacement silently fail.</li>\n<li><strong>Deleting a user doesn't invalidate their JWT.</strong> You must revoke sessions first.</li>\n</ul>\n<p>We originally put security guidance in separate reference files. Agents sometimes skipped them. So we moved everything critical into <code>SKILL.md</code> itself, where the agent reads it the moment the skill loads.</p>\n<h3 id=\"tooling\">Tooling<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-agent-skills#tooling\">#</a></h3>\n<p>Agents have two main ways to work with Supabase: through the Supabase MCP server, or through the Supabase CLI when they have access to a bash environment.</p>\n<p>For humans, the command line is still the most common way to interact with a service from the terminal. CLIs expose functionality through shell commands, and well-designed commands typically document themselves through the <code>--help</code> flag. That makes the interface discoverable and self-documenting. For an agent, this is especially useful: instead of guessing how a command works, it can inspect <code>--help</code>, follow the documented options, and use that information to troubleshoot when something goes wrong.</p>\n<p>MCP, by contrast, is designed specifically for agents. An MCP server exposes a service through structured tools that an agent can call directly, without needing terminal access. This makes the interface more natural for agentic workflows. However, an MCP server still has to be configured by a human before the agent can use it. To bridge that gap, the skill includes a short troubleshooting guide that helps the agent assist with common Supabase MCP server connection issues.</p>\n<p>In practice, the skill provides targeted guidance for both interfaces:</p>\n<ul>\n<li><strong>CLI</strong>: always discover commands through <code>--help</code>; never guess. The skill also documents known gotchas, such as the <code>supabase db query</code> command requiring CLI version 2.79.0 or later.</li>\n<li><strong>MCP server</strong>: step-by-step guidance for diagnosing and resolving connection issues.</li>\n</ul>\n<h3 id=\"schema-management\">Schema management<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-agent-skills#schema-management\">#</a></h3>\n<p>Agents are becoming increasingly autonomous, and we're growing more comfortable giving them direct access to our databases—whether to ship new features or troubleshoot issues. For example, Replit has previously described how its agents autonomously <a target=\"_blank\" href=\"https://blog.replit.com/production-databases-automated-migrations\">manage database schema</a> changes in development environments.</p>\n<p>Supabase enables agents to access databases through both the MCP server and the CLI. While this gives agents the necessary access, it doesn't by itself provide a clear or efficient workflow for managing schema changes.</p>\n<p>To address this, the skill introduces an opinionated approach to schema management. Instead of relying on migration-based workflows for every change, agents are encouraged to modify the schema directly using the <code>execute_sql</code> MCP tool or the <code>supabase db query</code> CLI command. This avoids creating a new migration entry for every DDL operation and enables faster iteration during development.</p>\n<p>Once the agent determines that the schema has stabilized, it should run the <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/database-advisors\">Supabase database advisors</a> to catch potential security or performance issues early. Only after passing these checks should the agent formalize the changes by committing a migration.</p>\n<p>We tried different formats and reference file structures before landing on the current approach.</p>\n<p>We learned that agents are lazy about reading reference files. When they do read one, they tend not to read more. Problems that require knowledge from multiple areas get missed.</p>\n<p>So we moved all critical information into <code>SKILL.md</code> itself. About 100 lines. The agent gets everything it needs the moment the skill loads. Only one reference file remains: <code>skill-feedback.md</code>, a meta-workflow for users to report issues on the <a target=\"_blank\" href=\"https://github.com/supabase/agent-skills\">GitHub repo</a>.</p>\n<p>The skill teaches agents <em>how</em> to find current information, not <em>what</em> the current information is. This keeps the skill maintainable and always accurate.</p>\n<p>We followed OpenAI's <a target=\"_blank\" href=\"https://developers.openai.com/blog/eval-skills\">framework for evaluating agent skills</a>: define success criteria, manually test, then advance to automated evaluation. As the skill matured, we moved to testing it systematically with an internal tool that runs evaluations automatically across agents and conditions.</p>\n<h3 id=\"what-we-measure\">What we measure<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-agent-skills#what-we-measure\">#</a></h3>\n<ul>\n<li><strong>Skill loading</strong>: does the agent discover and load the skill? This tests whether the name and description work as triggers.</li>\n<li><strong>Task completeness</strong>: does the agent finish the task? An LLM judge reviews the full transcript and generated files, separating requirements into primary (the core deliverable) and secondary (verification steps, workflow compliance). The judge checks for concrete evidence: actual tool calls, SQL statements, and valid outputs. Not just the agent saying it will do something.</li>\n</ul>\n<p>For example, in Postgres, views execute as their creator by default, which means they can bypass Row Level Security (RLS) policies defined on the underlying tables. This can lead to subtle security issues if a view is exposed without the correct configuration.</p>\n<p>In this case, the agent is expected to create the view with <code>security_invoker = true</code> so that it respects the RLS policies of the querying user.</p>\n<p>A typical prompt for the agent might look like:</p>\n<blockquote>\n<p>Create a view called <code>reports_view</code> that returns all reports from the reports table.</p>\n</blockquote>\n<p>When evaluating the agent's performance in this scenario, we use an LLM as a judge to determine whether the task was completed according to the defined success criteria. In this case, the success criteria is that the agent creates the view with <code>security_invoker = true</code>.</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>-- expected They knew how to implement it. They just didn't know when.</li>\n</ol>\n<p>If you're building skills for your own product, here's what we learned:</p>\n<ul>\n<li><strong>Fetch the docs, don't replicate them.</strong> Your docs already exist and are maintained. Put critical knowledge where they can't miss it.</li>\n<li><strong>Be opinionated.</strong> You know your product best. The skill encodes the judgment calls that training data can't.</li>\n<li><strong>Test across agents and conditions.</strong> What helps one model might not help another.
