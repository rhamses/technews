While both are databases, they serve different use-cases:</p>\n<ul>\n<li><strong>Postgres:</strong> Ideal for storing and querying application data, powering critical transactional and web app use cases.</li>\n<li><strong>ClickHouse:</strong> Optimized for analytics and reporting, supporting both customer-facing and internal applications</li>\n</ul>\n<p>Postgres is a row-oriented database, ClickHouse is column-oriented. The ClickHouse team have a <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/intro#row-oriented-vs-column-oriented-storage\">great write up about the difference</a> between the two formats.</p>\n<!-- -->\n<p>To provide an interface between these, Supabase customers generally use:</p>\n<ol>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/clickhouse\">clickhouse_fdw</a> to query their ClickHouse data from their Postgres database.</li>\n<li><a target=\"_blank\" href=\"https://www.peerdb.io/\">PeerDB</a> to replicate their data from Postgres to ClickHouse.</li>\n</ol>\n<!-- -->\n<p>We're making a number of changes to our platform based on the feedback we've had from customers.</p>\n<h3 id=\"updated-clickhouse-foreign-data-wrapper\">Updated ClickHouse Foreign Data Wrapper<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-clickhouse-partnership#updated-clickhouse-foreign-data-wrapper\">#</a></h3>\n<p>Using the <a target=\"_blank\" href=\"https://fdw.dev/catalog/clickhouse/\">ClickHouse FDW</a>, you can directly query your ClickHouse database from Postgres:</p>\n<div><p><code><br><div><p><span>_<!-- -->11</span></p><p><span>-- Connect Postgres to your ClickHouse database:</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>create foreign table user_analytics (</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  id bigint,</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  user_id bigint,</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  event text</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>)</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>server clickhouse_server</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>options ( table 'UserAnalytics' );</span></p></div><div><p><span>_<!-- -->11</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>-- Query your ClickHouse instance from Postgres:</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>select * from user_analytics where user_id = 1;</span></p></div><br></code></p></div>\n<p>This means you can query your ClickHouse data using the Postgres tooling that you're familiar with.</p>\n<p>The Wrapper now has support for ClickHouse <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/create/view#parameterized-view\">Parameterized Views</a>. With this update, you can pass query parameters directly to ClickHouse, taking full advantage of its analytical engine::</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>create foreign table user_analytics (</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  id bigint,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  user_id bigint,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  _event text,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>)</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>server clickhouse_server</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>options ( table '(select * from UserAnalytics(event=${_event}))' );</span></p></div><div><p><span>_<!-- -->10</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>select * from user_analytics where _event='button_click';</span></p></div><br></code></p></div>\n<h3 id=\"more-granular-replication-control\">More granular replication control<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-clickhouse-partnership#more-granular-replication-control\">#</a></h3>\n<p>Many of our customers use <a target=\"_blank\" href=\"https://www.peerdb.io/\">PeerDB</a> to replicate data from Postgres to ClickHouse. This has occasionally presented challenges, particularly with Postgres's default 1GB WAL size, which, for large data volumes, can result in data loss if the WAL exceeds this size.</p>\n<p>To resolve this, we've added 13 <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/custom-postgres-config\">configurable Postgres parameters</a>, enabling you to adjust replication settings through the CLI. For example, you can increase the default WAL size to 2GB:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>supabase --experimental --project-ref xxxx-yyy \\</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>postgres-config update --config max_slot_wal_keep_size=2GB</span></p></div><br></code></p></div>\n<p>The new CLI config includes the following Postgres parameters:</p>\n<ol>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-resource.html#GUC-LOGICAL-DECODING-WORK-MEM\">logical_decoding_work_mem</a>: Controls memory used during logical decoding.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-connection.html#GUC-MAX-CONNECTIONS\">max_connections</a>: Limits total connections to the Postgres server.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-locks.html#GUC-MAX-LOCKS-PER-TRANSACTION\">max_locks_per_transaction</a>: Sets the maximum locks allowed in a single transaction.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-MAX-REPLICATION-SLOTS\">max_replication_slots</a>: Defines the number of replication slots for data streaming.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-MAX-SLOT-WAL-KEEP-SIZE\">max_slot_wal_keep_size</a>: Limits disk space for WAL in replication slots.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-MAX-STANDBY-ARCHIVE-DELAY\">max_standby_archive_delay</a>: Sets how long standby servers can wait for archive recovery.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-MAX-STANDBY-STREAMING-DELAY\">max_standby_streaming_delay</a>: Controls delay on standby servers for streaming replication.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-wal.html#GUC-MAX-WAL-SIZE\">max_wal_size</a>: Specifies the maximum size of the Write Ahead Log.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-MAX-WAL-SENDERS\">max_wal_senders</a>: Sets the maximum number of processes sending WAL data.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-resource.html#GUC-MAX-WORKER-PROCESSES\">max_worker_processes</a>: Defines the number of background worker processes.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-resource.html#GUC-SHARED-BUFFERS\">shared_buffers</a>: Determines the amount of memory for shared buffers.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-WAL-KEEP-SIZE\">wal_keep_size</a>: Sets minimum WAL size to keep for standby servers.</li>\n<li><a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/runtime-config-replication.html#GUC-WAL-SENDER-TIMEOUT\">wal_sender_timeout</a>: Specifies the timeout for inactive WAL sender processes.</li>\n</ol>\n<h3 id=\"improved-disk-management\">Improved Disk Management<a target=\"_blank\"
