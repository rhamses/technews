Due to our commitment with OSS,\nall of our improvements are upstreamed, so you can fully use them on your own self-hosted projects.</p>\n<h3 id=\"highlights\">Highlights<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-community-day#highlights\">#</a></h3>\n<p><strong>Improved Performance</strong>: Due to Supabase's high throughput requirements, PostgREST 8.0 handles up to 50% more throughput on\nGET requests, according to our benchmarks. We converted all SELECT queries to use prepared statements and reduced logging\nverbosity to make this possible.</p>\n<p><strong>Reduced downtime</strong>: we need PostgREST to be more \"set it and forget it\", so reloading schema cache now has zero downtime.</p>\n<p><strong>Dynamic Configuration</strong>: we've made it easier to handle PostgREST configuration at scale (we manage thousands of PostgREST instances).\nThis new version includes the ability to use an in-database configuration that is reloadable through a <code>NOTIFY</code> command.</p>\n<p><strong>Less admin burden</strong>: PostgREST previously required the <code>pg_listen</code> utility to reload its schema cache. This is no longer needed.\nThe schema cache is reloadable with a simple <code>NOTIFY</code> command.</p>\n<p><strong>Better diagnostic information</strong>: in the rare cases where PostgREST fails, we want to find the exact root cause quickly.\nFor this we've improved its logging by adding logging levels and timestamps to all server errors.</p>\n<p><strong>Simpler OpenAPI</strong>: showing a complete OpenAPI output used to require a highly-privileged <code>anon</code> role. With the new <code>openapi-mode</code>,\nthis is no longer needed and <code>anon</code> can be kept with minimal privileges.</p>\n<p>The community has made many more enhancements and bug fixes for the new version.
