contentHtml: "<article><div>\n<p>One of our goals at Supabase is to make Postgres development delightful. To do this, we need to simplify the experience between our CLI, your code editor, and the remote Postgres database powering your applications.</p>\n<p>We received feedback recently about our local development experience, encouraging us to improve. This iteration introduces many new features to address that feedback. Let’s jump into a few of the features we’re launching today.</p>\n<p></p>\n<h2 id=\"postgres-language-server\">Postgres Language Server<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-local-dev#postgres-language-server\">#</a></h2>\n<p>One of the unique features of Supabase is the ability to access your Postgres database directly from a browser or mobile app through our <a target=\"_blank\" href=\"https://supabase.com/docs/guides/api\">Serverless APIs</a>. This means that developers are writing more <a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/plpgsql.html\">PL/pgSQL</a>.</p>\n<p>While code editors have great support for most programming languages, SQL support is underwhelming. We want to make Postgres as simple as Python. Our recently announced <a target=\"_blank\" href=\"https://github.com/supabase/postgres_lsp\">Postgres Language Server</a> takes us a step in that direction - eventually it will provide first-class support for Postgres in your favorite code editor including Linting, Syntax Highlighting, Migrations Parsing, SQL Auto-complete, and Intellisense.</p>\n<p>The Postgres Language Server is not ready for Production just yet. The majority of work is still ahead, but we've verified that the technical approach works and we're making it public now so that we can develop it in the open with input from the community. We’re already receiving amazing <a target=\"_blank\" href=\"https://github.com/supabase/postgres_lsp/discussions\">feedback</a> and <a target=\"_blank\" href=\"https://news.ycombinator.com/item?id=37020610\">support</a>.</p>\n<p>Follow the progress of the <a target=\"_blank\" href=\"https://github.com/supabase/postgres_lsp\">Postgres Language Server on GitHub</a>.</p>\n<h2 id=\"observability-tools-for-postgres\">Observability tools for Postgres<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-local-dev#observability-tools-for-postgres\">#</a></h2>\n<p>We’ve added <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/inspect\">debugging utilities</a> to our CLI to identify production issues via the <code>supabase inspect db</code> command. This interface includes 19 different commands to help you solve everything from slow queries to redundant indexes.</p>\n<p>A lot of the credit for this belongs to <a target=\"_blank\" href=\"https://github.com/heroku/heroku-pg-extras\">Heroku’s pg-extras</a> feature, an amazingly useful set of functionality. We’ve adapted the work they started, added a few additional commands, and made it available for any Postgres database. Simply append the <code>--db-url</code> param to use these commands with your own Postgres database.</p>\n<p>This is just a starting point for the Supabase inspector. We’ll grow this feature to become an essential part of your Postgres toolkit.</p>\n<p>We’ve made it even easier to backup and migrate your database, using <code>supabase db dump</code>. Under the hood, this simply uses <a target=\"_blank\" href=\"https://www.postgresql.org/docs/current/app-pgdump.html\">pg_dump</a> (it's just Postgres, after all). However we also handle a few of the hairy issues that you might need to navigate on your own, like object permissions.</p>\n<p>We’ve extended the CLI migration feature and added Dashboard support. Database migrations give you a way to update your database using version-controlled SQL files. We’ve built a lot of tooling around our migrations, including <a target=\"_blank\" href=\"https://supabase.com/docs/reference/cli/supabase-migration-repair\">reparation</a>, migration cleanup using the <a target=\"_blank\" href=\"https://supabase.com/docs/reference/cli/supabase-migration-squash\">squash</a> command, and <a target=\"_blank\" href=\"https://supabase.com/docs/reference/cli/supabase-db-diff\">diffing</a> (using <a target=\"_blank\" href=\"https://github.com/djrobstep/migra\">migra</a>) to generate a new migration or to detect schema drift.</p>\n<p>With the new Postgres Language Server, we hope to make it as easy to write Postgres migrations as it is to develop applications in TypeScript, Go, Python, or Rust.</p>\n<p>Finally, we’ve added a Migrations view <a target=\"_blank\" href=\"https://app.supabase.com/project/_/database/migrations\">in the dashboard</a> to track your migration history to improve the discoverability of migrations.</p>\n<p>We’ve simplified the database testing experience, with <code>supabase test</code>. Running <code>supabase test new</code> stubs out a <a target=\"_blank\" href=\"https://pgtap.org/\">pgTAP test</a> for you to fill with testing logic. The CLI includes <a target=\"_blank\" href=\"https://pgtap.org/pg_prove\">pg_prove and the TAP harness</a>, so all you need to do is run <code>supabase test db</code>.</p>\n<p>To make life even easier, our friends at <a target=\"_blank\" href=\"https://usebasejump.com/\">Basejump</a> have created an entire suite of <a target=\"_blank\" href=\"https://github.com/usebasejump/supabase-test-helpers\">Supabase Test Helpers</a> which make it simple to create users, run tests as an <a target=\"_blank\" href=\"https://usebasejump.com/blog/testing-on-supabase-with-pgtap#testing-authenticated\">authenticated user</a>, and test your <a target=\"_blank\" href=\"https://usebasejump.com/blog/testing-on-supabase-with-pgtap#rls-testing\">RLS policies</a>.</p>\n<p>Finally, while you wait for us to make progress on the Language Server, we’ve added <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli/testing-and-linting#linting-your-database\">support for linting</a> through the excellent <a target=\"_blank\" href=\"https://github.com/okbob/plpgsql_check\">plpgsql_check</a> extension.</p>\n<p>Seeding is the process of populating a database with initial data, typically used to provide sample or default records for testing and development purposes. This gives you a reproducible development environment across your entire team.</p>\n<p>We’ve added <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli/seeding-your-database\">support for seeding</a> to populate your local databases with data whenever you run <code>supabase start</code> or <code>supabase db reset</code>.</p>\n<p>We’ve also worked with our friends at Snaplet to <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli/seeding-your-database#generating-seed-data\">generate seed data</a> directly from your database:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>npx snaplet generate --sql &gt; supabase/seed.sql</span></p></div><br></code></p></div>\n<p>Type generators introspect a PostgreSQL schema and automatically generate TypeScript definitions. This gives you <a target=\"_blank\" href=\"https://www.youtube.com/watch?v=VSNgAIObBdw\">end-to-end type safety</a> from the database to the browser.</p>\n<p>In the past month, we've added relationship detection in supabase-js. Foreign keys are now included in the generated types so that supabase-js can detect whether a referenced table should be an array (one-to-many) or an object (many-to-one). We've also added Helper Types to improve the developer experience for common scenarios, like short-hand accessors:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>// Before</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>let movie: Database['public']['Tables']['movies']['Row'] = // ...</span></p></div><div><p><span>_<!-- -->10</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>// After</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>let movie: Tables&lt;'movies'&gt; = // ...</span></p></div><br></code></p></div>\n<p>We’ve developed an official <a target=\"_blank\" href=\"https://github.com/marketplace/actions/supabase-cli-action\">GitHub Action</a> which leverages the CLI. You can <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli/github-action/generating-types\">generate types on every PR</a>, or run <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli/github-action/testing\">your tests on every commit</a>.</p>\n<p>Logs are now accessible locally in the Dashboard. Last launch week we released an open source logging server, with support for BigQuery. In the past few months we’ve added Postgres support to this server. This means that all of your local logs are accessible with no additional config - simply run supabase start and then visit the local dashboard to start debugging.</p>\n<p>We’ve moved the Supabase CLI to a fortnightly stable-release cycle. Every 2 weeks, we will update the <a target=\"_blank\" href=\"https://www.npmjs.com/package/supabase?activeTab=versions\"><code>latest</code></a> tag on npm, the <a target=\"_blank\" href=\"https://github.com/supabase/homebrew-tap/blob/main/supabase.rb\"><code>supabase/tap</code></a> for homebrew, and the <a target=\"_blank\" href=\"https://github.com/supabase/homebrew-tap/blob/main/supabase.rb\"><code>supabase</code></a> scoop bucket. You can find the binary downloads in our GitHub <a target=\"_blank\" href=\"https://github.com/supabase/cli/releases/latest\">latest release</a>.</p>\n<p>For the adventurous feature hunters, we’ve added a <code>beta</code> release channel for the CLI, with new releases on every PR merged. You can follow <a target=\"_blank\" href=\"https://github.com/supabase/cli#install-the-cli\">this guide</a> to install Supabase CLI (beta).</p>\n<p>And finally, probably our most anticipated feature - branching:</p>\n<p>We’ve made major improvements to our local development with the features above - but we have bigger ambitions. For several months we’ve been developing Supabase branching and today we're opening it up for alpha testers.</p>\n<p>Supabase isn’t simply a database, it’s an entire backend - everything from your Postgres database to your <a target=\"_blank\" href=\"https://supabase.com/blog/storage-v3-resumable-uploads\">50GB videos</a>. Branching improves the experience of managing environments so that developers and teams spend less time on DevOps and more time building.</p>\n<h3 id=\"supabase-branching-is-hard\">Supabase branching is hard<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-local-dev#supabase-branching-is-hard\">#</a></h3>\n<p>Every project is a Postgres database, wrapped in a suite of tools like <a target=\"_blank\" href=\"https://supabase.com/auth\">Auth</a>, <a target=\"_blank\" href=\"https://supabase.com/storage\">Storage</a>, <a target=\"_blank\" href=\"https://supabase.com/edge-functions\">Edge Functions</a>, <a target=\"_blank\" href=\"https://supabase.com/realtime\">Realtime</a> and <a target=\"_blank\" href=\"https://supabase.com/modules/vector\">Vectors</a>, and encompassed by <a target=\"_blank\" href=\"https://supabase.com/docs/guides/api\">API middleware</a> and <a target=\"_blank\" href=\"https://supabase.com/blog/supabase-logs-self-hosted\">logs</a>.</p>\n<p>A good branching solution requires each tool to provide multi-tenancy support so that:</p>\n<ol>\n<li>Data can be isolated from production for security.</li>\n<li>Compute can be isolated from each other to avoid noisy-neighbors.</li>\n</ol>\n<h3 id=\"how-does-branching-work\">How does branching work?<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-local-dev#how-does-branching-work\">#</a></h3>\n<p>We use Git to bridge the gap between your local development environment and your hosted database. For now, we’ve focused on GitHub.</p>\n<p>Every time you open a new Pull Request on GitHub, a corresponding “Preview Environment” is created. Each preview branch is an isolated Firecracker instance that pauses automatically after a period of inactivity. Every time a change is pushed to GitHub, the migrations within the <code>./supabase/migrations</code> folder are run against the Preview Branch so that your entire team is working from the same source of truth.</p>\n<p>When you hit merge on your Pull Request we run the migrations on your Production database.</p>\n<h3 id=\"what-about-data\">What about data?<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-local-dev#what-about-data\">#</a></h3>\n<p>We’re starting with seed data. Any SQL with <code>./supabase/seed.sql</code> will populate your Preview Branch. This provides your entire team with an isolated and reproducible environment, safe from any data privacy concerns.</p>\n<p>Importantly, we <em>aren’t</em> cloning production data until we find something appropriate for data security. We know that copy-on-write is an available option, and with the appropriate anonymization techniques it seems like a promising way to provide a “production-like” test environment.</p>\n<p>We’ll also need to figure out what this means for large files in Supabase Storage. Do you need to anonymize your photos and videos? This is a work in progress and we’re open to feedback.</p>\n<p>Either way, we want to support <em>both</em> seed data and anonymized production data, so that teams can choose their preference based on their risk profile. It makes sense to start with a seed.</p>\n<h3 id=\"is-it-available-yet\">Is it available yet?<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-local-dev#is-it-available-yet\">#</a></h3>\n<p>Jump into our updated <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli\">Local Development documentation</a> to get started with the CLI.</p>\n<p>If you’re an existing user simply <a target=\"_blank\" href=\"https://supabase.com/docs/guides/cli/getting-started#updating-the-supabase-cli\">update your CLI</a> and check out the <a target=\"_blank\" href=\"https://supabase.com/docs/reference/cli/introduction\">full command reference</a> for all the latest commands.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://supabase.com/blog/hugging-face-supabase\">Hugging Face is now supported in Supabase</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/launch-week\">Launch Week 8</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/blog/interactive-constellation-threejs-react-three-fiber\">Coding the stars - an interactive constellation with Three.js and React Three Fiber</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/blog/why-supabase-remote\">Why we'll stay remote</a></li>\n<li><a target=\"_blank\" href=\"https://github.com/supabase/postgres_lsp\">Postgres Language Server</a></li>\n</ul></div></article>"
