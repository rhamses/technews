contentHtml: "<article><div><p>Today we're launching Supabase PrivateLink, a new capability that lets you connect your database to AWS cloud resources over private networks. When enabled, your database connections stay entirely within the AWS network. No public internet exposure. No additional attack surface.</p>\n<p>If you work in a regulated industry or handle sensitive data, you've had this conversation with your security team: \"Can we connect to the database without going over the public internet?\" Until now, the answer was complicated. You could use IP allowlists and SSL, but traffic still flowed over public networks. For some organizations, that's a non-starter.</p>\n<p>Supabase PrivateLink solves this. Traffic never leaves private networks. From a network perspective, your Supabase database behaves like it's inside your own VPC.</p>\n<p>This matters for compliance. Many regulatory frameworks require private network connectivity for sensitive data. It also matters for security. Fewer public endpoints mean fewer attack vectors. You can disable public database access entirely once PrivateLink is configured.</p>\n<p>Our AWS PrivateLink implementation uses AWS VPC Lattice under the hood. When you enable PrivateLink, we share a VPC Lattice Resource Configuration with your AWS account. You accept the share and create an endpoint in your VPC.</p>\n<p>Your applications connect to the endpoint using a private DNS name. Traffic flows through AWS infrastructure to your Supabase database. The connection supports both direct Postgres connections and PgBouncer for connection pooling.</p>\n<p>Latency is typically lower than public connections because traffic takes a more direct path through AWS networks.</p>\n<p>Supabase PrivateLink makes sense when:</p>\n<ul>\n<li><strong>You have compliance requirements.</strong> Highly compliant industries such as healthcare, finance, and public sector often require private network connectivity. PrivateLink satisfies these requirements without needing to do configurations on your own.</li>\n<li><strong>You want to minimize your attack surface.</strong> Every public endpoint is a potential target. PrivateLink lets you disable public database access entirely.</li>\n<li><strong>Your workloads already run on AWS.</strong> If your applications are in AWS, setting up PrivateLink is straightforward. Traffic stays within the same cloud provider.</li>\n</ul>\n<p>PrivateLink is not necessary for every use case. If you're building a side project or your security requirements are satisfied by SSL and IP allowlists, the standard public connection works fine.</p>\n<p>Supabase PrivateLink is in Beta with some constraints:</p>\n<ul>\n<li><strong>AWS environments required.</strong> This initial release supports connections to AWS VPCs via PrivateLink. Your workloads need to run in AWS to use PrivateLink.</li>\n<li><strong>Database connections only.</strong> PrivateLink works for Postgres and PgBouncer connections. It does not cover the Supabase API, Storage, Auth, or Realtime services. Those still use public endpoints. To establish PrivateLink with a Read Replica, reach out to your account rep.</li>\n<li><strong>Same region required.</strong> Your AWS VPC must be in the same region as your Supabase project.</li>\n<li><strong>Team or Enterprise plan required.</strong> PrivateLink is available on Team and Enterprise plans.</li>\n</ul>\n<p>If you're familiar with AWS networking, setup is straightforward. Here's the overview:</p>\n<ol>\n<li>Go to Settings &gt; Integrations in your Supabase dashboard and add your AWS account ID</li>\n<li>Accept the resource share in your AWS RAM console</li>\n<li>Create a PrivateLink endpoint in your VPC (or attach to an existing VPC Lattice Service Network)</li>\n<li>Configure your security group to allow TCP port 5432</li>\n<li>Update your application connection string to use the private endpoint</li>\n<li>Test the connection with psql</li>\n<li>Optionally disable public database access</li>\n</ol>\n<p>The full walkthrough with screenshots is in <a target=\"_blank\" href=\"https://supabase.com/docs/guides/platform/privatelink\">our documentation</a>.</p>\n<p>Supabase PrivateLink is available today for Team and Enterprise customers. Head to Settings &gt; Integrations in your dashboard to get started.</p>\n<p>If you run into issues or have questions, open <a target=\"_blank\" href=\"https://www.supabase.com/support\">a support ticket</a> or <a target=\"_blank\" href=\"https://discord.supabase.com/\">ask in our Discord</a>. We're collecting feedback during the Beta to improve the experience.</p></div></article>"
