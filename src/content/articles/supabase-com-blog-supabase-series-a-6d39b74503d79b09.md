Supabase has smuggled scalability into the product, perhaps without you noticing.\nEvery Supabase project is a <em>full</em> Postgres database. It's not \"Postgres compatible\", it's not \"built on top of\",\nand we don't abstract it. If we did, your applications would face the same scalability issues as Firebase.</p>\n<p>Supabase simply makes Postgres easy to use - hopefully easier than any other database platform you've ever used.</p>\n<p>We plan to make Postgres the default database for every developer in the world. How do we do that? By making Postgres both easy\n(Phase 2: tooling) and scalable (Phase 3: Cloud-Native Postgres).</p>\n<h3 id=\"phase-2-postgres-tooling\">Phase 2: Postgres Tooling<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-series-a#phase-2-postgres-tooling\">#</a></h3>\n<p>User-facing applications usually require tools beyond just a database and frontend framework:</p>\n<ul>\n<li><strong>APIs:</strong> to provide access to your database from untrusted systems.</li>\n<li><strong>Authentication:</strong> for users sign ups.</li>\n<li><strong>File Storage:</strong> for large images and media.</li>\n</ul>\n<p>Supabase makes all of this easy. Beyond the database we offer <a target=\"_blank\" href=\"https://supabase.com/docs/guides/auth\">Auth</a>,\nRESTful and Realtime <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/api\">APIs</a>, a <a target=\"_blank\" href=\"https://supabase.com/docs/guides/storage\">Storage</a>\nsystem for large files, and a bunch of other tools - all wrapped up into a simple-to-use Dashboard.</p>\n<p>And this is where Supabase really differentiates itself: by doing less. All of these features build on top of PostgreSQL's\nexisting functionality.</p>\n<ul>\n<li><strong>Row Level Security:</strong> restrict user access to data and files using Postgres Policies.</li>\n<li><strong>Realtime data streams:</strong> subscribe to database changes using the logical replication stream.</li>\n<li><strong>Database Webhooks (previously called \"Function Hooks\"):</strong> trigger external systems using Postgres triggers and our <a target=\"_blank\" href=\"https://github.com/supabase/pg_net/\">async request extension</a>.</li>\n<li><strong>RESTful APIs:</strong> query your database <a target=\"_blank\" href=\"https://supabase.com/docs/reference/javascript/select\">tables</a> and <a target=\"_blank\" href=\"https://supabase.com/docs/reference/javascript/rpc\">functions</a> over HTTP, using <a target=\"_blank\" href=\"https://postgrest.org/\">PostgREST</a>.</li>\n</ul>\n<h3 id=\"phase-3-cloud-native-postgresql\">Phase 3: Cloud-native PostgreSQL<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-series-a#phase-3-cloud-native-postgresql\">#</a></h3>\n<p>PostgreSQL was created over 30 years ago, and it's one of the safest and most reliable databases in the world.</p>\n<p>But modern developers are becoming accustomed to cloud-native services with several characteristics:</p>\n<ul>\n<li>Automatic scaling.</li>\n<li>Low latency anywhere in the world.</li>\n<li>Billing based on usage.</li>\n</ul>\n<p>PostgreSQL is still catching up to the modern cloud environment in some areas. What does a Cloud-native PostgreSQL look like?</p>\n<ul>\n<li><strong>Branching:</strong> developers should be able to \"fork\" a database at any point. This is particularly important for Jamstack developers who run deployments for every Git branch.</li>\n<li><strong>Scalable storage:</strong> storage should grow and shrink without the user needing to provision more space themselves.</li>\n<li><strong>Distributed:</strong> An entire fleet of databases, distributed around the world, should feel like a single database (and even better if all nodes can accept read/write workloads).</li>\n<li><strong>Ephemeral compute:</strong> developers don't want to be charged for a database which isn't doing anything. Likewise - if they are running huge computation then the database should scale up seamlessly, and scale down to zero when it's unused.</li>\n<li><strong>Snapshots and time-travel:</strong> developers should be able to roll back to any point in time, or take a copy of their database with just a click of a button.</li>\n</ul>\n<p>This is the future of Supabase - a platform to power your transactional workloads: no matter how big or small; no matter the use-case.\nWe're building a cloud-native Postgres platform.</p>\n<p>We have a track record of hiring open source maintainers, PostgREST is maintained by a\n<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-steve-chavez\">Supabase developer</a>, one of our first hires over a year ago.\nWe've recently added <a target=\"_blank\" href=\"https://www.postgresql.org/message-id/CABwTF4UZzYoHcaEGe2cESVn-e9dc3wzg%3Dmvx7Tz8qbKJ7p3UKA%40mail.gmail.com\">another developer</a>\nwith the explicit goal of working within the PostgreSQL community.</p>\n<p>If you want to help us build the future of cloud-native Postgres, join us:\n<a target=\"_blank\" href=\"https://about.supabase.com/careers/postgres-experts\">https://about.supabase.com/careers/postgres-experts</a></p>\n<ul>\n<li>Start using Supabase today:&#160;<strong><a target=\"_blank\" href=\"https://supabase.com/dashboard/\">supabase.com/dashboard</a></strong></li>\n<li>Make sure to&#160;<strong><a target=\"_blank\" href=\"https://github.com/supabase/supabase\">star us on GitHub</a></strong></li>\n<li>Follow us&#160;<strong><a target=\"_blank\" href=\"https://twitter.com/supabase\">on Twitter</a></strong></li>\n<li>Subscribe to our&#160;<strong><a target=\"_blank\" href=\"https://www.youtube.com/c/supabase\">YouTube channel</a></strong></li>\n<li>Become a&#160;<strong><a target=\"_blank\" href=\"https://github.com/sponsors/supabase\">sponsor</a></strong></li>\n</ul></div></article>"
