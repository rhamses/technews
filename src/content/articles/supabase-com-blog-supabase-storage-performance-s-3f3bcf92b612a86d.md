contentHtml: "<article><div><p>Today, we're shipping a large set of updates to Supabase Storage that improve performance at scale, close security vulnerabilities, and reduce the most common causes of support issues. These changes affect every project using Storage, and they are live in all regions now.</p>\n<p>Storage has grown a lot. Projects now hold tens of millions of objects, and that scale exposed real problems: write performance degraded under concurrent uploads, certain SQL patterns could accidentally orphan objects, and a path traversal vulnerability existed in the file backend. We knew about these problems from support tickets and our own benchmarks. This release fixes all of them.</p>\n<p>The biggest change is a full rewrite of how Storage lists objects. The old system used a prefixes table with six triggers and twelve helper functions to keep folder structure in sync. On large buckets, those triggers slowed down every write. We replaced the entire system with a hybrid skip-scan algorithm that derives folder structure on-the-fly from the objects table. We also replaced OFFSET-based pagination with cursor-based pagination, which runs in constant time regardless of how deep you page. On a table with 60 million rows, deep pagination is up to 14.8 times faster. There is no write penalty. The prefixes table, level column, and two indexes have been dropped entirely.</p>\n<p>These changes are already live. The Storage API handles everything automatically. If you are not using the listV2 endpoint, we recommend that you switch to it to get even more performance benefits!</p>\n<h3 id=\"path-traversal-prevention\">Path traversal prevention<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#path-traversal-prevention\">#</a></h3>\n<p>The file backend can no longer read or write files outside the configured storage path. Previously, a crafted path could escape the storage root. This is now closed. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/818\">GitHub</a></p>\n<h3 id=\"preventing-accidental-deletes-via-direct-sql\">Preventing accidental deletes via direct SQL<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#preventing-accidental-deletes-via-direct-sql\">#</a></h3>\n<p>Running <code>DELETE FROM storage.objects</code> directly in SQL was the most common cause of orphan objects, where the database row was removed but the file in S3 or the file backend was not. A new statement-level trigger now rejects <code>DELETE</code> on Storage schema tables unless the session variable <code>storage.allow_delete_query</code> is set to <code>true</code>. The Storage API sets this flag automatically, so normal operations are unaffected. Direct SQL deletes are blocked by default. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/817\">GitHub</a></p>\n<h3 id=\"object-listing-rewrite\">Object listing rewrite<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#object-listing-rewrite\">#</a></h3>\n<p>The old prefixes table required a write on every object insert, update, and delete to keep folder structure in sync. At high concurrency and large object counts, this became a bottleneck. Enterprise customers with 60 million or more objects were hitting real limits on write throughput.</p>\n<p>The new skip-scan algorithm removes all of that. Folder structure is computed at read time from the objects table. Pagination uses a cursor instead of OFFSET, so page 1,000 is just as fast as page 1.</p>\n<p>Benchmark on 60 million rows: up to 14.8x faster for deep pagination.</p>\n<h3 id=\"query-cancellation-and-statement-timeouts\">Query cancellation and statement timeouts<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#query-cancellation-and-statement-timeouts\">#</a></h3>\n<p>When a client disconnects, in-flight Postgres queries are now cancelled using the native Postgres cancel protocol. This works with pgBouncer. A configurable 30-second query statement timeout has also been added via the <code>DB_STATEMENT_TIMEOUT</code> environment variable. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/841\">GitHub</a></p>\n<h3 id=\"idempotent-migrations\">Idempotent migrations<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#idempotent-migrations\">#</a></h3>\n<p>All Storage migrations are now fully idempotent. You can clear the <code>storage.migrations</code> table and safely replay the entire chain without errors. CI now runs the full migration suite twice and compares <code>pg_dump</code> output to verify. This should eliminate the class of support tickets around stuck migrations. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/805\">GitHub</a></p>\n<h3 id=\"tus-zombie-lock-fix\">TUS zombie lock fix<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#tus-zombie-lock-fix\">#</a></h3>\n<p>A race condition in the S3 locker for TUS resumable uploads could leave an orphaned lock that never expired. This happened when a lock was released during a renewal cycle, between the S3 GET and PUT. The renewal now checks whether the lock was already released before completing. This race condition is now closed. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/812\">GitHub</a></p>\n<h3 id=\"orphan-object-scanner-improvements\">Orphan object scanner improvements<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#orphan-object-scanner-improvements\">#</a></h3>\n<p>The orphan object scanner has been updated with several fixes: it now uses a trailing slash in S3 prefixes to prevent false-positive matches (for example, <code>images</code> no longer matches <code>images2</code>), supports multiple buckets via comma-delimited IDs, and adds a configurable <code>DELETE_LIMIT</code> for batch control. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/830\">GitHub</a></p>\n<h3 id=\"opentelemetry-metrics\">OpenTelemetry metrics<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#opentelemetry-metrics\">#</a></h3>\n<p>Storage now uses OpenTelemetry for metrics instead of prom-client. Metrics can be pushed to any OTel-compatible backend. Prometheus scraping is still available at <code>/metrics</code> via the OTel Prometheus exporter. This release also includes a revamped Grafana dashboard and an OTel Collector config. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/819\">GitHub</a></p>\n<h3 id=\"server-execution-time-in-logs\">Server execution time in logs<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-storage-performance-security-reliability-updates#server-execution-time-in-logs\">#</a></h3>\n<p>Request logs now include server-side execution time. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/831\">GitHub</a></p>\n<ul>\n<li><strong>Duplicate slash in TUS upload URLs:</strong> TUS resumable upload URLs were generated with a double slash. This is fixed. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/801\">GitHub</a></li>\n<li><strong>PutVector body limit:</strong> The body size limit for the PutVector endpoint has been raised from 1.6 MB to 20 MB. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/820\">GitHub</a></li>\n<li><strong>Invalid S3 response header overrides:</strong> Invalid values in <code>response-content-type</code> and similar overrides no longer crash requests. They are silently dropped. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/839\">GitHub</a></li>\n<li><strong>Missing content-type fallback:</strong> When S3 returned no Content-Type, the adapter was returning the misspelled <code>application/octa-stream</code>. It now correctly falls back to <code>application/octet-stream</code>. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/840\">GitHub</a></li>\n<li><strong>Linux file backend xattr collision:</strong> On Linux, the file backend was using the same extended attribute for both content-type and etag. Multipart uploads were overwriting the content-type with the ETag value. Each property now uses a distinct xattr name. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/842\">GitHub</a></li>\n<li><strong>Migration type ordering:</strong> Generated <code>migration_types.ts</code> now always sorts migrations by ID. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/845\">GitHub</a></li>\n<li><strong>AWS stream buffer fix:</strong> Fixes a stream buffering issue in the S3 adapter during multipart uploads, required for the AWS SDK upgrade. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/850\">GitHub</a></li>\n<li><strong>Case preservation in list v1:</strong> A regression introduced in the search optimization was returning all prefixes in lower case. Original case is now preserved. <a target=\"_blank\" href=\"https://github.com/supabase/storage/pull/851\">GitHub</a></li>\n</ul>\n<p>These changes are live for all projects. No code changes are required.</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/storage\">Storage documentation</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/dashboard\">Start a new project</a></li>\n<li><a target=\"_blank\" href=\"https://supabase.com/docs/guides/self-hosting/storage\">Self-hosting Storage</a></li>\n</ul></div></article>"
