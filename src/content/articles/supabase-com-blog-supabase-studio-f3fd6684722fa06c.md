contentHtml: "<article><div><p>Today we're releasing <a target=\"_blank\" href=\"https://github.com/supabase/supabase/tree/master/apps/studio\">Supabase Studio</a>.\nThe same Dashboard that you're using on our Platform is now available for <a target=\"_blank\" href=\"https://supabase.com/docs/guides/local-development\">Local Development</a>\nand <a target=\"_blank\" href=\"https://supabase.com/docs/guides/hosting/overview\">Self-Hosting</a>.</p>\n<p>Let's get the obvious question out of the way - why wasn't it already open source?</p>\n<p>When Ant and I started Supabase the codebase was one large monorepo which contained everything from the dashboard to cloud infrastructure code to experimental code.\nThis is our preferred development setup - we like to keep all code in one place so that we have a single source of truth and tightly coupled CI workflows.</p>\n<p>The original Dashboard really wasn't much except a couple of buttons which allowed our Alpha users to start and stop a Supabase project - back then only a PostgreSQL connection string.</p>\n<p>Then time went on, and we started gaining traction - a lot faster than expected.\nThe nice thing about building for developers is that they are very vocal about the features they want to see next.\nAnd so we kept shipping - a SQL editor, a Table view, User management, auto-generated Docs, and everything else you can find on the Dashboard today.</p>\n<p>We've been planning to make the Dashboard public for a long time now, starting with <a target=\"_blank\" href=\"https://ui.supabase.com/\">Supabase UI</a>,\n<a target=\"_blank\" href=\"https://github.com/supabase/grid\"><code>supabase/grid</code></a>, and a standalone <a target=\"_blank\" href=\"https://github.com/supabase/supabase/pull/2281\">PR</a> for Supabase Studio.\nBut as feature requests kept rolling in it became a Sisyphean task to maintain separate code bases.</p>\n<p>After the last Launch Week, we decided to prioritize the Studio.</p>\n<p>We investigated a few different approaches used in the open source world. There are three popular strategies that we found amongst OSS projects and some of our YC alum:</p>\n<ul>\n<li>Maintain separate code bases. Pluck changes from one to another.</li>\n<li>Keep two repos in sync using some mixture of git submodules or a tool like <a target=\"_blank\" href=\"https://github.com/atomix/copycat\">copycat</a></li>\n<li>Use the same codebase, abstracting platform-specific code behind an API and feature flags.</li>\n</ul>\n<p>Our frontend <a target=\"_blank\" href=\"https://github.com/orgs/supabase/teams/frontend/members\">team</a> experimented with the first two approaches where they plucked (injected, merged, and wrangled) code for our Platform.\nTime-to-production become a lot slower, an unacceptable outcome at Supabase.</p>\n<p>Eventually we decided to open source all the frontend code, a shared codebase for both the Platform and Self Hosting.</p>\n<details><summary><a>Special shout out</a></summary><p>Sentry do a fantastic job of<!-- --> <!-- -->\n<a target=\"_blank\" href=\"https://develop.sentry.dev/sentry-vs-getsentry/\">documenting their strategy</a> for\nmanaging a shared codebase and served as a great model for Supabase.</p></details>\n<p>For the past week, the dashboard you've been using on the Platform has been deployed from our <a target=\"_blank\" href=\"https://github.com/supabase/supabase/tree/master/apps/studio\">main repository</a>.</p>\n<p>This fits one of our core philosophies at Supabase: do less. Less code to manage means less bugs. Fewer codebases means faster shipping.</p>\n<p>It also fits the development philosophy of every other part of Supabase: building in public, \"warts and all\".</p>\n<p>This is a huge step forward for the community. Supabase users can now spot a bug, fix it in the open source repository,\nand have it shipped to both the Platform and Self-Hosted environments - all in a few hours.</p>\n<p>Let's jump into some of the technical implementation for Supabase Studio.</p>\n<h3 id=\"tech-stack\">Tech stack<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-studio#tech-stack\">#</a></h3>\n<p>Studio is a Javascript application with a few key pieces of technology:</p>\n<ul>\n<li><a target=\"_blank\" href=\"https://nextjs.org/\">Next.js</a> - A frontend Javascript framework built with React.</li>\n<li><a target=\"_blank\" href=\"https://tailwindcss.com/\">Tailwind</a> - A utility-first CSS framework.</li>\n<li><a target=\"_blank\" href=\"https://ui.supabase.com/\">Supabase UI</a> - Our own component library.</li>\n<li><a target=\"_blank\" href=\"https://www.mobxjs.com/\">MobX</a> - A state management library.</li>\n<li>A host of other <a target=\"_blank\" href=\"https://github.com/supabase/supabase/blob/master/apps/studio/package.json\">useful libraries</a>, including <a target=\"_blank\" href=\"https://www.radix-ui.com/\">Radix UI</a>, <a target=\"_blank\" href=\"https://lottiefiles.com/\">Lottiefiles</a>, <a target=\"_blank\" href=\"https://github.com/react-grid-layout/react-grid-layout\">react-grid-layout</a>, and <a target=\"_blank\" href=\"https://github.com/dropbox/zxcvbn\">zxcvbn</a>.</li>\n</ul>\n<h3 id=\"whats-included\">What's included<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-studio#whats-included\">#</a></h3>\n<p>Studio is designed to work with existing deployments - either the local hosted, docker setup, or our CLI.\nIt is not intended for managing the deployment and administration of projects - that's out of scope.</p>\n<p>The features exposed on Studio for existing deployments are limited to those which manage your database:</p>\n<ul>\n<li>Table &amp; SQL editors.</li>\n<li>Database management: Policies, roles, extensions, replication.</li>\n<li>API documentation.</li>\n</ul>\n<p>Check out the full instructions in our <a target=\"_blank\" href=\"https://github.com/supabase/supabase/tree/master/apps/studio\">Studio Readme</a>.</p>\n<h3 id=\"we-are-live-and-launched-on-product-hunt\">We are live and launched on Product Hunt<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-studio#we-are-live-and-launched-on-product-hunt\">#</a></h3>\n<p>Our new open source Studio is also on Product Hunt right now. If you like what you see, please give it an upvote and a review.</p>\n</div></article>"
