It reduces data transfer between the database and the application, enabling faster execution and improved performance.</p>\n<!-- -->\n<h3 id=\"how-to-use-query-pushdown-in-wrappers\">How to Use Query Pushdown in Wrappers<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-wrappers-v02#how-to-use-query-pushdown-in-wrappers\">#</a></h3>\n<p>In Wrappers, the pushdown logic is integrated into each extension. You don’t need to modify your queries to benefit from this feature. For example, the <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/stripe\">Stripe FDW</a> automatically applies query pushdown for <code>id</code> within the <code>customer</code> object:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select *</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from stripe.customers</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>where id = 'cus_N5WMk7pvQPkY3B';</span></p></div><br></code></p></div>\n<p>This approach contrasts with fetching and filtering all customers locally, which is less efficient. Query pushdown translates this into a single API call, significantly speeding up the process:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>https://api.stripe.com/v1/customers/cus_N5WMk7pvQPkY3B</span></p></div><br></code></p></div>\n<p>We can use push down criteria and other query parameters too. For example, <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/clickhouse\">ClickHouse FDW</a> supports <code>order by</code> and <code>limit</code> pushdown:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select *</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from clickhouse.people</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>order by name</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>limit 20;</span></p></div><br></code></p></div>\n<p>This query executes <code>order by name limit 20</code> on ClickHouse before transferring the result to Postgres.</p>\n<p>For details on where pushdown is supported, consult each FDW's documentation in the <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/overview\">Wrappers Documentation</a>.</p>\n<p>Remote subqueries enable the use of prepared data on a remote server, which is beneficial for complex queries or sensitive data protection.</p>\n<h3 id=\"static-subqueries\">Static Subqueries<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-wrappers-v02#static-subqueries\">#</a></h3>\n<p>In its most basic form, you can map a query on the remote server into a foreign table in Postgres. For instance:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>create foreign table clickhouse.people (</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  id bigint,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  name text,</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  age bigint</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>)</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>server clickhouse_server</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>options (</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>  table '(select * from people where age &lt; 25)'</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>);</span></p></div><br></code></p></div>\n<p>In this example, the foreign table <code>clickhouse.people</code> data is read from the result of the subquery <code>select * from people where age &lt; 25</code> which runs on ClickHouse server.</p>\n<h3 id=\"dynamic-subqueries\">Dynamic Subqueries<a target=\"_blank\" href=\"https://supabase.com/blog/supabase-wrappers-v02#dynamic-subqueries\">#</a></h3>\n<p>What if the query is not fixed and needs to be dynamic? For example, ClickHouse provides <a target=\"_blank\" href=\"https://clickhouse.com/docs/en/sql-reference/statements/create/view#parameterized-view\">Parameterized Views</a> which can accept parameters for a view. Wrappers v0.2 supports this by defining a column for each parameter. Let's take a look at an example:</p>\n<div><p><code><br><div><p><span>_<!-- -->11</span></p><p><span>create foreign table clickhouse.my_table (</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  id bigint,</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  col1 text,</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  col2 bigint,</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  _param1 text,</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  _param2 bigint</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>)</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>server clickhouse_server</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>options (</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  table '(select * from my_view(column1=${_param1}, column2=${_param2}))'</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>);</span></p></div><br></code></p></div>\n<p>You can then pass values to these parameters in your query:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select id, col1, col2</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from clickhouse.my_table</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>where _param1 = 'abc' and _param2 = 42;</span></p></div><br></code></p></div>\n<p>Currently, this feature is supported by <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/clickhouse\">ClickHouse FDW</a> and <a target=\"_blank\" href=\"https://supabase.com/docs/guides/database/extensions/wrappers/bigquery\">BigQuery FDW</a>, with plans to expand support in the future.</p>\n<p>Quantitative metrics play a pivotal role when working with Postgres FDWs because of their impact on performance optimisation, monitoring, and query planning across distributed databases. We introduced a FDW usage statistics table <code>wrappers_fdw_stats</code> in Wrappers v0.2, storing:</p>\n<ul>\n<li><code>create_times</code> - number of times the FDW instance has been created</li>\n<li><code>rows_in</code> - number of rows transferred from source</li>\n<li><code>rows_out</code> - number of rows transferred to source</li>\n<li><code>bytes_in</code> - number of bytes transferred from source</li>\n<li><code>bytes_out</code> - number of bytes transferred to source</li>\n<li><code>metadata</code> - additional usage statistics specific to a FDW</li>\n</ul>\n<p>We can use these to identify bottlenecks, latency issues, and inefficiencies in data retrieval. Access this table on the Supabase platform using the following:</p>\n<div><p><code><br><div><p><span>_<!-- -->10</span></p><p><span>select *</span></p></div><div><p><span>_<!-- -->10</span></p><p><span>from extensions.wrappers_fdw_stats;</span></p></div><br></code></p></div>\n<p>We couldn't build Wrappers v0.2 without our community and we'd like to thank all the following people for their contributions:</p>\n<p><a target=\"_blank\" href=\"https://github.com/jocubeit\">Dom Jocubeit,</a> <a target=\"_blank\" href=\"https://github.com/0xflotus\">0xflotus,</a> <a target=\"_blank\" href=\"https://github.com/zer0eXploit\">Glitch,</a> <a target=\"_blank\" href=\"https://github.com/ibotty\">Tobias Florek,</a> <a target=\"_blank\" href=\"https://github.com/workingjubilee\">Jubilee,</a> <a target=\"_blank\" href=\"https://github.com/glarrain-cdd\">Germán Larraín,</a> <a target=\"_blank\" href=\"https://github.com/kav\">Kavanaugh Latiolais,</a> <a target=\"_blank\" href=\"https://github.com/tedverse\">tedverse</a>.</p>\n<p>A separate shout-out belongs to the <a target=\"_blank\" href=\"https://github.com/pgcentralfoundation/pgrx\">pgrx</a> team, which allows us to write Wrappers with Rust.</p>\n<p>Want to join the Supabase Wrappers community contributors? <a target=\"_blank\" href=\"https://supabase.github.io/wrappers/contributing/\">Check out our contribution docs</a>.
