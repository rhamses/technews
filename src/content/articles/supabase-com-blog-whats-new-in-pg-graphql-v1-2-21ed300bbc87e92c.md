You might use these to migrate underlying tables while maintaining backwards compatibility with previous API versions.</p>\n<p>Filtering in SQL is endlessly flexible. <code>null</code>.</p>\n<h3 id=\"like-ilike-and-startswith\"><strong><code>like</code></strong>, <strong><code>ilike</code></strong>, and <strong><code>startsWith</code></strong><a target=\"_blank\" checks. href=\"https://supabase.com/blog/whats-new-in-pg-graphql-v1-2#graphql-directives-skip-and-include\">#</a></h3>\n<p>The GraphQL spec has evolved over time. Although the spec is clear, it is common for GraphQL servers to selectively omit some chunks of functionality. For example, some frameworks intentionally do not expose an introspection schema as a form of security through obscurity.</p>\n<p><code>pg_graphql</code> aims to be unopinionated and adhere exactly to the spec. The <code>@skip</code> and <code>@include</code> directives are part of the <a target=\"_blank\" href=\"https://spec.graphql.org/October2021/#sec--skip\">GraphQL core specification</a> and are now functional.</p>\n<p>The <strong><code>@skip</code></strong> directive in GraphQL is used to conditionally skip a field or fragment during query execution based on a Boolean variable. It can be used to make the query more efficient by reducing the amount of data retrieved from the server.</p>\n<p>The <strong><code>@include</code></strong> directive is the mirror of <strong><code>@skip</code></strong> where a field or fragment is conditionally included depending on the value of a Boolean variable.</p>\n<p>Here's an example of how the <strong><code>@skip</code></strong> directive can be used in a GraphQL query:</p>\n<div><p><code><br><div><p><span>_<!-- -->11</span></p><p><span>query getBooks($includeDetails: Boolean!) }</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>    }</span></p></div><div><p><span>_<!-- -->11</span></p><p><span>  }</span></p></div><div><p><span>_<!--
