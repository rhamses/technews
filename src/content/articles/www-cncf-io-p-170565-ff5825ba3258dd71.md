With this release, a single <code>`limactl`</code> workflow can now boot Linux, macOS, FreeBSD&#160; and Windows virtual machines. Lima v2.2 also introduces <strong>emulated TPM (Trusted Platform Module) 2.0</strong>, a foundational building block for modern guest operating systems and for disk-encryption workflows.</p>\n<h2>What is Lima ?</h2>\n<p><a target=\"_blank\" href=\"https://lima-vm.io/\">Lima</a> (Linux Machines) is a command-line tool to launch local virtual machines. Originally focused on running containers on a laptop and promoting containerd to Mac users, Lima joined the CNCF as a Sandbox project in September 2022 and was promoted to Incubating in October 2025. Today, Lima supports a wide variety of non-container workloads, non-macOS hosts, non-Linux guests and robust AI sandboxing.</p>\n<p>If you are using Homebrew, Lima can be installed using:</p>\n<pre><code>brew install lima</code></pre>\n<p>For other installation methods, see <a target=\"_blank\" href=\"https://lima-vm.io/docs/installation/\">https://lima-vm.io/docs/installation/</a>.</p>\n<h2>Updates in v2.2</h2>\n<h2>Windows guests (experimental)</h2>\n<p>Lima v2.2 introduces experimental support for <strong>Windows Server 2025</strong> and <strong>Windows 11</strong> guests. With v2.1 adding macOS and FreeBSD, Windows was the natural next step toward making Lima an OS-agnostic VM launcher.</p>\n<p>To create and start a Windows Server 2025 guest:</p>\n<pre><code>limactl start template:windows-2025</code></pre>\n<p>Once the VM is up,</p>\n<pre><code>limactl shell windows-2025</code></pre>\n<figure><img src=\"https://www.cncf.io/wp-content/uploads/2026/07/image-17.png\" alt=\"A screenshost of the Windows System Info\" srcset=\"https://www.cncf.io/wp-content/uploads/2026/07/image-17.png 2048w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-300x261.png 300w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-1024x891.png 1024w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-768x668.png 768w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-900x783.png 900w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-1800x1565.png 1800w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-230x200.png 230w, https://www.cncf.io/wp-content/uploads/2026/07/image-17-460x400.png 460w\"></figure>\n<p>Under the hood, Lima now knows how to:</p>\n<ul>\n<li>Drive an unattended Windows installation from a generated&#160; <code>`autounattend.xml`</code> answer file, packaged into an ISO that QEMU attaches alongside the install media. This handles disk partitioning, driver loading, and user creation without any manual clicks.</li>\n<li>Download and mount the <a target=\"_blank\" href=\"https://github.com/virtio-win/virtio-win-pkg-scripts\">virtio-win</a> driver ISO so that Windows can use virtio block, network, and other paravirtualized devices for good performance.</li>\n<li>On first logon, a PowerShell script generates a random password (replacing the initial one from <code>`autounattend.xml`</code>), installs OpenSSH Server, opens the Windows Firewall for port 22, and injects the SSH public key into <code>`C:\\ProgramData\\ssh\\administrators_authorized_keys` </code>so that <code>`limactl shell`</code> works out of the box.</li>\n</ul>\n<h3>Current limitations</h3>\n<ul>\n<li>Only the <strong>QEMU</strong> driver is supported.&#160;</li>\n<li>The Windows template requires <code>`plain: true`</code>. File mounts, port forwarding via the guest agent, and other Lima conveniences that rely on the Linux guest agent are not available yet.</li>\n</ul>\n<h3>What’s next for Windows guests</h3>\n<ul>\n<li>File sharing into the guest (likely via <strong>virtio-fs, </strong>or maybe<strong> </strong><a target=\"_blank\" href=\"https://learn.microsoft.com/en-us/windows/win32/fileio/microsoft-smb-protocol-and-cifs-protocol-overview\"><strong>SMB (Server Message Block)</strong></a>).</li>\n<li>A Windows-side <strong>guest agent</strong> so that port forwarding, environment propagation, and provisioning scripts behave the same as on Linux guests.</li>\n<li>Broader architecture and image coverage (Windows 11 ARM64, more languages beyond <code>`en-us`</code>, etc.)</li>\n<li>Eventually, a native <strong>Windows Host Compute System (HCS)</strong> backend driver for users running Lima on Windows, which would give first-class vTPM.</li>\n</ul>\n<h2>TPM 2.0 emulation (experimental)</h2>\n<p><a target=\"_blank\" href=\"https://www.intel.com/content/www/us/en/learn/what-is-a-trusted-platform-module.html\"><strong>TPM (Trusted Platform Module) 2.0</strong></a> is a dedicated microchip built into your computer’s motherboard designed to secure hardware using cryptographic keys. To make Windows 11 guests possible at all, Lima v2.2 also adds <strong>emulated TPM </strong>via <a target=\"_blank\" href=\"https://github.com/stefanberger/swtpm\"><code>swtpm</code></a> (a software emulator that acts like a physical TPM) on the QEMU driver.</p>\n<p>When `tpm: true`, Lima:</p>\n<ul>\n<li>Spawns a <code>`swtpm`</code> process per instance, with its own state directory under the instance directory.</li>\n<li>Communicates with <code>`swtpm`</code> over a Unix domain socket.</li>\n<li>Picks the right QEMU TPM device as per the architecture Cleans up the <code>`swtpm` </code>process when the instance stops.</li>\n</ul>\n<h2>LFX Mentorship 2026</h2>\n<p>This year Lima participated in the <a target=\"_blank\" href=\"https://mentorship.lfx.linuxfoundation.org/\">LFX Mentorship 2026 Term 2</a> program (June – August 2026), and this term is currently under progress. The work is tracked under the umbrella issue <a target=\"_blank\" href=\"https://github.com/lima-vm/lima/issues/4907\">#4907</a>. We are thrilled to announce Mie Tokunaga (<a target=\"_blank\" href=\"https://github.com/mie313\">@mie313</a> on GitHub) as our selected mentee for this term. Huge thanks to her for driving the Windows guests development. Also many thanks to Arnav Sharma (<a target=\"_blank\" href=\"https://github.com/Shardz4\">@Shardz4</a> on GitHub) whose earlier proof of concept for <code>`swtpm`</code> integration <a target=\"_blank\" href=\"https://github.com/lima-vm/lima/pull/5079\">#5079</a> laid the groundwork for the TPM feature.</p>\n<p>The main goal of the mentorship program was to add Windows Guest support. Now that our mentee has successfully implemented this, their focus has shifted to ensuring a seamless Lima experience on Windows hosts. This includes automating Windows host configurations and eliminating dependencies so that Lima “just works” out of the box. A key deliverable is the complete removal of the <code>`cygpath.exe`</code> dependency, so that Lima on Windows no longer requires Cygwin, MSYS2, or Git for Windows to be installed. The secondary phase aims to explore and evaluate native virtualization support for Windows hosts.
