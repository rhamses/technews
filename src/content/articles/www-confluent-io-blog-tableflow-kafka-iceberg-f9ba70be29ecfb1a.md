contentHtml: "<div><p>TL;DR<b>:</b> Tableflow is a Confluent Cloud feature that materializes Apache Kafka topics as Apache Iceberg or Delta Lake tables, eliminating custom data pipelines by automatically handling schematization, type conversions, schema evolution, CDC stream materialization, catalog publishing, and table maintenance.</p><h2><b>What Is Tableflow?</b></h2><p><a target=\"_blank\" href=\"https://docs.confluent.io/cloud/current/topics/tableflow/overview.html\"><b><u>Tableflow</u></b></a> is a managed feature in <a target=\"_blank\" href=\"https://www.confluent.io/\"><b><u>Confluent Cloud</u></b></a> that continuously converts Kafka topics into open table formats (Apache Iceberg or Delta Lake) so analytics engines can query streaming data as tables—without writing or maintaining ETL pipelines.\nThe core problem it solves is familiar: operational data lives in Apache Kafka, while analysts and BI tools expect data in data lakes or warehouses. Traditionally, teams bridge this gap with custom connectors, scheduled ETL jobs, and schema handholding—an approach that is brittle under schema evolution and expensive to operate at scale.</p><!--$--><!--/$--><h2><b>How Tableflow Works</b></h2><p>Tableflow uses Confluent’s Kora storage layer to transform Kafka topic data in Avro, JSON Schema, or Protobuf into structured Parquet files, then generates Iceberg metadata or Delta Lake metadata and exposes those tables through the built-in Iceberg REST Catalog or supported external catalog integrations. Schema Registry is the source of truth for schema mapping and schema evolution.</p><p><b>Step-by-step:</b></p><ol><li><p><b>Kafka topic ingestion</b> — Tableflow consumes committed Kafka segments.</p></li><li><p><b>Kora storage layer</b> — Segments are staged and prepared for columnar conversion.</p></li><li><p><b>Parquet conversion</b> — Records are written as Parquet files optimized for analytics.</p></li><li><p><b>Table metadata</b> — Iceberg (GA) or Delta Lake (GA) metadata is generated.</p></li><li><p><b>Catalog publish</b> — Tables are registered in an Iceberg REST catalog (or external catalogs).</p></li><li><p><b>Schema governance</b> — Schema Registry governs compatibility and evolution.</p></li></ol><p>Supported table formats:</p><ul><li><p>Apache Iceberg (GA)</p></li><li><p>Delta Lake (GA)</p></li></ul><p><b>Architecture Flow&#160;</b></p><!--$--><p><span></span><span>End-to-end Tableflow pipeline converting Kafka topic data into Parquet and publishing Iceberg/Delta metadata to a REST catalog for analytics queries.</span></p><!--/$--><h2><b>What Can You Query Tableflow Tables With?</b></h2><p>You can query Tableflow-materialized tables using common analytics engines and warehouses, including:</p><ul><li><p>Snowflake</p></li><li><p>Databricks</p></li><li><p>AWS Athena</p></li><li><p>Amazon Redshift</p></li><li><p>Trino</p></li><li><p>BigQuery</p></li></ul><p><b>Catalog options:</b></p><ul><li><p>Built-in Iceberg REST catalog (managed)</p></li><li><p>AWS Glue</p></li><li><p>Unity Catalog</p></li></ul><h2><b>Tutorial: Enable Tableflow on a Kafka Topic</b></h2><h3><b>Prerequisites</b></h3><p>1.
