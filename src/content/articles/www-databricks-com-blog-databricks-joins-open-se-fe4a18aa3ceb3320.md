Both require openness because critical security intelligence locked inside a small number of closed systems leaves the broader ecosystem exposed. Databricks supports both mission sides: open frameworks for securing AI systems, and open data via <a target=\"_blank\" href=\"https://www.databricks.com/product/lakewatch\"><strong>Lakewatch</strong></a>, the Open Security Lakehouse powering agentic threat detection and response at scale.</p><p>That's why Databricks is proud to be a founding member of the <a href=\"https://blogs.nvidia.com/blog/open-secure-ai-alliance/?ncid=so-twit-957725\" target=\"_blank\"><strong>Open Secure AI Alliance</strong></a>, alongside NVIDIA and other industry leaders. It's a complex system built from models, harnesses, and guardrails that govern what the agent is allowed to do. While much attention has focused on securing open-weight models within enterprise boundaries, model weights are only one layer. Security in the agentic era requires an <strong>open execution stack</strong>: from the runtime and guardrails underneath, to the harness that orchestrates agents and their tools, to the frameworks that define risks and controls, to the governance layer that ensures enterprise security, auditability and accountability.</p><p>Open systems allow the broadest community of defenders to study, test, and strengthen every component of this stack. The result is trust built on assurances, visibility, evidence, participation, and choice.</p><h2>What Databricks brings to the alliance</h2><p>The alliance spans more than 75 organizations across chips, models, security, and infrastructure. Omnigent gives developers choice of harness and model, allowing composition and secure sharing, while enforcing policies, spend caps, and sandbox isolation across 13+ harnesses, both open and closed.</p><p><a target=\"_blank\" href=\"https://www.databricks.com/blog/contextual-policies-omnigent-using-session-state-better-govern-ai-agents\">Omnigent's contextual policies</a> enable agent behavior governance by tracking session state, <a target=\"_blank\" href=\"https://www.databricks.com/blog/blocking-slow-burn-attacks-contextual-policies-omnigent\">blocking slow-burn attacks</a>, and <a target=\"_blank\" href=\"https://www.databricks.com/blog/permission-isnt-purpose-intent-based-authorization-omnigent\">enforcing intent-based authorization</a>. Leaving that layer proprietary while everything above it is open would put the most security-critical control point beyond inspection.
