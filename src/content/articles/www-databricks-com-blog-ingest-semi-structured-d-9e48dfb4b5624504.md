contentHtml: "<div><p>For years, ingesting semi-structured data like JSON, XML, or CSV meant a difficult tradeoff. Data teams could build ETL pipelines to schematize data for fast queries and sacrifice flexibility, or store data as strings to stay flexible and pay the cost in slow query performance. To solve this tradeoff, we collaborated with the Delta and Spark communities to introduce the <a target=\"_blank\" href=\"https://www.databricks.com/blog/introducing-open-variant-data-type-delta-lake-and-apache-spark\">Variant data type</a> and brought it to the <a target=\"_blank\" href=\"https://www.databricks.com/blog/introducing-variant-new-open-standard-semi-structured-data-apache-parquettm-delta-lake\">Parquet and Iceberg communities to unify the lakehouse</a> as a single, open standard for semi-structured data.</p><p>We are excited to announce that Variant is now <strong>Generally Available</strong> in Databricks. This launch includes Variant Shredding, also Generally Available, a performance optimization that uses Predictive Optimization to automatically improve query performance on Variant data. With Variant, teams can flexibly ingest semi-structured data without compromising downstream query performance.</p><h2>Flexible ingestion at scale</h2><p>Over 5K teams are writing Variant using Databricks. These teams most commonly use Variant to ingest events from streaming sources like Kinesis or Event Hub, JSON payloads from APIs, and schemaless data from databases like PostgreSQL and MongoDB.</p><p>Variant is particularly useful to handle schema changes from ingestion sources. For example, an upstream application may change its API types. This leaves downstream teams scrambling to update relevant pipelines, perform backfills of existing data, and handle a cutover. Even worse, most enterprises have separate data platforms and application teams, making these schema changes unpredictable. With Variant, users can ingest all of their semi-structured data flexibly into their tables.</p><p><img src=\"https://www.databricks.com/sites/default/files/blog_images/ingest-semi-structured-data-faster-and-more-blog-img-1.png\" alt=\"image3.png\"></p><p>Variant removes the upfront cost of working with semi-structured data. Building pipelines to schematize data takes time, requiring data engineers to justify their time investment. Variant flips the paradigm – teams can effortlessly land data first, and then figure out its utility for the rest of the business.</p><h2>Faster, smarter queries with Predictive Optimization</h2><p>Databricks users execute 500M+ Variant queries per month across 160+ TB of Variant data. Databricks makes reading Variant as fast as reading schematized data on managed tables. Using Shredding, Variant stores common fields as columns in the underlying Parquet files. Predictive Optimization trains on a user's unique workload and query patterns, and using machine learning, identifies the most critical shredded fields and collects statistics on them to improve file skipping. As a result, Databricks scans only the files and columns required for a query, avoiding unnecessary work and boosting performance.</p><p>Variant shredding delivers nearly <strong>4x faster reads</strong> than unshredded Variant — and <strong>30x faster reads </strong>than storing JSON as a string:</p><p><img src=\"https://www.databricks.com/sites/default/files/blog_images/ingest-semi-structured-data-faster-and-more-blog-img-2.png\" alt=\"image2.png\"></p><p>With Variant, Databricks is unlocking lightning fast performance at scale:</p><div><p><span>We need to query security logs that are not just simple flat records, but complex JSON structures that are difficult to search efficiently. Databricks' Variant support, combined with shredding, enables high-performance querying of deeply nested attributes — even at petabyte scale&#160;</span></p><div><p><img src=\"https://www.databricks.com/sites/default/files/blog_images/ingest-semi-structured-data-faster-and-more-blog-img-3.png\" alt=\"Panther\"></p><p>— Russell Leighton, Chief Architect</p></div></div><h2>Using Variant in Databricks</h2><p>With Databricks, you can use Variant across your entire data stack.</p><p>Our users commonly use two tools to ingest semi-structured data as Variant:</p><ol><li><a href=\"https://docs.databricks.com/aws/en/ingestion/cloud-object-storage/auto-loader/\" target=\"_blank\">Auto Loader</a>, a source to incrementally process semi-structured files from object storage</li></ol><!--$--><!--/$--><ol><li><a href=\"https://docs.databricks.com/aws/en/ingestion/zerobus-overview\" target=\"_blank\">Zerobus</a>, a fully managed ingestion service to write directly into tables without using a message bus</li></ol><!--$--><!--/$--><p>Both ingestion approaches write data into either Delta or Iceberg, allowing any client to interoperate with data in the lakehouse. To simplify setup, use Genie Code in the Lakeflow Pipelines Editor to easily generate Auto Loader ingestion pipelines using natural language.</p><p><img src=\"https://www.databricks.com/sites/default/files/inline-images/ingest-semi-structured-data-faster-and-more-blog-imgs-4.png\" alt=\"Delta or Iceberg\"></p><p>Teams can then directly consume Variant data in Lakehouse. Since data is intelligently shredded during the ingestion process, dashboards and reporting can query the data directly as fast as structured data.</p><!--$--><!--/$--><p>In the near future, we plan to expand Variant support even further to include Liquid Clustering by Variant fields, expanded SQL functions, and further feature integrations.</p><h2>Get started with Variant today</h2><p>With Variant, you no longer have to make a tradeoff between flexibility and performance when using semi-structured data. Databricks uses Predictive Optimization, which tracks workload and query patterns, to automatically write Variant data for the best performance across products.</p><p>Getting started with Variant is easy – try it <a href=\"https://docs.databricks.com/aws/en/sql/language-manual/data-types/variant-type\" target=\"_blank\">here</a>.</p></div>"
