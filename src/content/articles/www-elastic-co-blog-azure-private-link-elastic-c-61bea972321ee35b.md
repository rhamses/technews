With this release, you can connect your Azure workloads directly to your Serverless projects over Azure's private network backbone without exposing your Elastic endpoints to the public internet. </span><a target=\"_blank\" href=\"https://www.elastic.co/docs/deploy-manage/security/private-connectivity\"><span>AWS PrivateLink support shipped in February 2026</span></a><span>; Azure is the second cloud provider to reach GA.</span></p><div><p></p><h2 id=\"what-azure-private-link-does\">What Azure Private Link does</h2><p></p><p><span>When you associate an Azure Private connection policy with a Serverless project, traffic between your Azure Virtual Network and Elastic travels entirely within Azure's network fabric. The public Elastic endpoints remain resolvable, but once a policy is attached, any request that does not arrive through a matching private endpoint or IP filter is rejected with </span><span><span>403 Forbidden</span></span><span>. There is no separate \"private endpoint only\" toggle; the policy attachment itself enforces the access boundary.</span></p><p><span>The connection runs through an Azure private endpoint in your VNet. Elastic hosts a Private Link service on our side; you create the private endpoint in your subscription, and Elastic auto-approves it when your VNet is whitelisted by a policy you create. All data — ingestion, search, and Kibana — travels through that private path.</span></p><p><span>On Azure, a private connection policy is required (not optional). The policy carries the resource IDs of the private endpoints you want to admit, and Elastic uses it to auto-approve connection requests. This differs from AWS, where the policy is optional, and you can approve connections manually.</span></p></div><div><p><span>For the list of supported Azure regions, see </span><a target=\"_blank\" href=\"https://www.elastic.co/docs/deploy-manage/deploy/elastic-cloud/regions\"><span>Elastic Cloud Serverless regions</span></a><span>. Due to a limitation in Azure, Private Link support is not yet available in northeurope region even though Elastic Cloud Serverless is.</span></p></div><div><p></p><h2 id=\"how-to-set-it-up\">How to set it up</h2><p></p><p><span>The full configuration steps are in the </span><a target=\"_blank\" href=\"https://www.elastic.co/docs/deploy-manage/security/private-connectivity-azure\"><span>Azure private connectivity documentation</span></a><span>. At a high level:</span></p><ul><li><p><span>In Azure, create a private endpoint pointing to the Elastic Private Link service for your project.</span></p></li><li><p><span>Update your DNS to resolve the Elastic endpoint hostnames to the private IP of your endpoint.</span></p></li><li><p><span>In Elastic Cloud, create a private connection policy and add the Resource name and Resource ID of your private endpoint. Elastic uses </span><span><span>properties.resourceGUID</span></span><span> from the Azure resource — the field labeled </span><span><strong>Resource ID </strong></span><span>in the Azure portal.</span></p></li><li><span>Optionally, you can associate the policy with your Serverless project in Elastic Cloud Console.</span></li></ul></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltbf13a9baed936ac4/6a71515c75ed463df14a84f0/create-private.png\" alt=\"create private connection \"></figure></div><div><p><span>You can create up to 1,024 network security policies per organization with up to 128 sources (private endpoints or IP ranges) per policy. A single policy can be shared across multiple projects.</span></p><p><span><strong>IP filters and private endpoints can coexist.</strong></span><span> When you attach both an IP filter policy and a private connection policy to the same project, each incoming request must match at least one attached policy; it does not need to match all of them. Traffic arriving through the private endpoint matches the private connection policy. Traffic arriving from a listed IP range matches the IP filter. Any traffic that matches neither is rejected.</span></p></div><div><p></p><h2 id=\"packaging-and-availability\">Packaging and availability</h2><p></p><p><span>Private connectivity for Serverless is included in the following tiers at no additional charge and is effective August 4, 2026:</span></p><ul><li><p><span><strong>Observability Serverless projects:</strong></span><span> require </span><span><strong>Observability Complete</strong></span></p></li><li><p><span><strong>Security Serverless projects:</strong></span><span> require </span><span><strong>Security Analytics Complete</strong></span></p></li><li><p><span>For other project types, such as </span><span><strong>Elasticsearch Serverless projects</strong></span><span>, the feature is available with no tier requirement.</span></p></li></ul><p><span><strong>Projects created before August 4, 2026</strong></span><span> are grandfathered regardless of tier. Any Serverless project created before that date can use traffic filtering — both private connections and IP filters — without restriction for the project's lifetime. This applies even if the project is not currently using traffic filtering; projects created before the cutoff date can configure it at any time.</span></p><p><span>If you upgrade an observability or security project to the Complete tier after August 4, the platform automatically applies your default network security policies to the newly eligible project — no manual reconfiguration needed.</span></p><p><span>Gating is enforced in both the Elastic Cloud Console UI and the API. Projects that do not meet the tier requirement and were created on or after August 4 will not have the option to associate a private connection or IP filter policy.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt73dd5ed2e33f5893/6a7151797724f230dc044301/apply-to-resources.png\" alt=\"apply to resources\"></figure></div><div><p></p><h2 id=\"private-connectivity-across-cloud-providers\">Private connectivity across cloud providers</h2><p></p><p><span>Azure Private Link now joins </span><a target=\"_blank\" href=\"https://www.elastic.co/docs/deploy-manage/security/private-connectivity-aws\"><span>AWS PrivateLink</span></a><span>, which has been available for Serverless since February 2026, as part of Elastic's ongoing investment in network security across major cloud providers. For the current list of supported providers and regions, see the </span><a target=\"_blank\" href=\"https://www.elastic.co/docs/deploy-manage/security/private-connectivity\"><span>private connectivity documentation</span></a><span>.</span></p></div><div><p></p><h2 id=\"frequently-asked-questions\">Frequently asked questions</h2><p></p><p><span><strong>Does Azure Private Link also work for Elastic Cloud Hosted deployments?<br></strong></span><span>Azure Private Link for Hosted deployments has been available via a separate API. This release covers Elastic Cloud Serverless specifically.</span></p><p><span><strong>Can I use both an IP filter and a Private connection policy on the same project?<br></strong></span><span>Yes.
