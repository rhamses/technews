How do I repair it?&#160;</span></p><p><span>These are difficult questions to answer, but as part of </span><a href=\"https://www.elastic.co/guide/en/elasticsearch/reference/8.7/release-highlights.html\" target=\"_blank\"><span>Elasticsearch 8.7</span></a><span>, we are releasing a new </span><a href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/health-api.html\" target=\"_blank\"><span>Health API</span></a><span> to help identify and fix problems in Elasticsearch clusters.&#160;</span></p><p><span>In contrast to the existing </span><a href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/cluster-health.html\" target=\"_blank\"><span>cluster health API</span></a><span>, which looks at the health of indices and data streams, the new </span><a href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/health-api.html\" target=\"_blank\"><span>Health API</span></a><span> will also perform root cause analysis for the unhealthy indices and data streams and introduce a number of additional feature-specific health checks.&#160;</span></p><h2>Health issue anatomy and resolution</h2><p><span>Elasticsearch health issues are usually observed by checking the Elasticsearch shards status or more likely due to the higher-level functionalities being impacted (e.g., incomplete search results or slow ingestion).</span></p><p><span>Let's try to analyze an Elasticsearch health issue a bit further and introduce some terminology.</span></p><div><p><span>We will use the example of an unassigned shard to help us understand this better. An Elasticsearch health issue has a </span><span><span>symptom</span></span><span>, which is the observable lower-level Elasticsearch primitive that’s experiencing a problem — in our case, we can observe that one shard is unassigned. A </span><span><span>symptom</span></span><span> can have one or more </span><span><span>impacts</span></span><span> on the system. For example, an unassigned primary shard would be a symptom that causes the ingest and backup functionalities to be impacted.</span></p><p><span>Once a problem is observed, the next step is understanding what’s </span><span><em>causing</em></span><span> the issue and what </span><span><em>actions</em></span><span> are needed to remedy the problem. In our example, the </span><span><span>cause</span></span><span> of the shard unassignment could be that the </span><a href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/index-modules.html#index-routing-allocation-enable-setting\" target=\"_blank\"><span>allocation</span></a><span> is disabled at the index level. The </span><span><span>action</span></span><span> we’d need to take to get the shard assigned is to change the </span><span><span>index.routing.allocation.enable</span></span><span> index setting to a value of </span><span><span>all</span></span><span> as described in </span><a href=\"http://ela.st/fix-index-allocation\" target=\"_blank\"><span>this</span></a><span> step-by-step troubleshooting guide.</span></p></div></div><div><h2>Health API principles</h2><p><span>We built an API that will signal how clusters are impacted by issues in a simple and actionable way. We wanted to ensure that our users can self-perform the necessary actions to fix issues their clusters encountered.</span></p><p><span>The Health API was designed with two operating modes in mind:</span></p><ul><li><span>A very fast high-level mode that indicates the overall status of the cluster using the already established </span><span><span>red</span></span><span>, </span><span><span>yellow</span></span><span>, or </span><span><span>green</span></span><span> status.&#160;</span></li><li><span>A more detailed reporting mode that also performs a root cause analysis and reports it as part of a </span><span><span>diagnosis</span></span><span> together with the needed actions to get back to </span><span><span>green</span></span><span> health.</span></li></ul><p><span>Switching between the two operating modes is done using the </span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/health-api.html#health-api-query-params\"><span>verbose</span></a><span> query parameter. We default to detailed reporting (</span><span><span>verbose=true</span></span><span>); however, we recommend the usage of the high-level mode (</span><span><span>verbose=false</span></span><span>) for any automatic polling for health because performing the root cause analysis can be an expensive operation.&#160;</span></p><p><span>The high-level mode will report the </span><span><span>impacts</span></span><span> the detected problems have on the system. The impacts are described using terminology that’s closer to what our users would use when discussing the role Elasticsearch plays in their architecture (e.g., search, ingest, or backup).</span></p><p><span>We make use of modular health indicators to track a few metrics that usually cause health problems in Elasticsearch. The available health indicators are documented </span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/health-api.html#health-api-response-details\"><span>here</span></a><span>. The infrastructure we designed for the Health API makes it easy to add more indicators (for the intrepid engineer, implementing </span><a href=\"https://github.com/elastic/elasticsearch/blob/main/server/src/main/java/org/elasticsearch/health/HealthIndicatorService.java\" target=\"_blank\"><span>HealthIndicatorService</span></a><span> and </span><a href=\"https://github.com/elastic/elasticsearch/blob/main/server/src/main/java/org/elasticsearch/plugins/HealthPlugin.java\" target=\"_blank\"><span>HealthPlugin</span></a><span> will do the trick) and we’ll consider the feasibility of indicating health via the Health API with every new feature we design.</span></p><p><span>Each health indicator will report its own status of </span><span><span>red</span></span><span>, </span><span><span>yellow</span></span><span>, or </span><span><span>green</span></span><span>, as well as an explanation when the status is not </span><span><span>green</span></span><span>.&#160;</span></p><p><span>When we cannot determine the health status of the cluster with a high degree of certainty, we’ll signal this using the </span><span><span>unknown</span></span><span> status. The health indicators will individually return a status of </span><span><span>unknown</span></span><span> if they cannot reliably track their designated metric. For example, if a cluster doesn’t have a stable master node elected, all indicators except the </span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/health-api.html#health-api-response-details-master-is-stable\"><span>master_is_stable</span></a><span> indicator will return </span><span><span>unknown</span></span><span> as the cluster state information the indicators rely upon to evaluate the health condition is probably not up-to-date enough.</span></p><p><span>When an indicator reports the </span><span><span>red</span></span><span> status, the cluster is in a state that requires immediate intervention. It means functions like cluster stability, ingest, search, or backup are severely affected right now (e.g., an unassigned primary shard impacts ingest and search).&#160;</span></p><p><span>A status indicator of </span><span><span>yellow</span></span><span> signals a warning. The cluster functions could eventually be impacted if no action is taken (e.g., an </span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/snapshots-take-snapshot.html#automate-snapshots-slm\"><span>SLM</span></a><span> policy that hasn’t been successful for the last five consecutive executions impacts the backups and puts the deployment at risk of not having an up-to-date enough snapshot available).&#160;</span></p><p><span>The API will report an overall status for the cluster that’ll represent the worst encountered status among the health indicators (i.e., if any indicator reports </span><span><span>yellow</span></span><span>, the overall status will be
