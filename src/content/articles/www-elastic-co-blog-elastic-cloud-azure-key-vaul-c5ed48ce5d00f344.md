We’ll also show you how to validate your setup and implement additional security policies, such as encryption key rotation and revocation.</span></p></div><div><p></p><h2 id=\"the-elastic-cloud-and-azure-key-vault-integration\">The Elastic Cloud and Azure Key Vault integration</h2><p></p></div><div><p></p><h3 id=\"architecture\">Architecture</h3><p></p><p><span>The following diagram showcases how Elastic Cloud integrates with Azure Key Vault to provide your application with Hosted Stack deployments encrypted with your own Key Vault keys.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltae00e3c1325e4573/66c4a39c0388811b011eeee6/image13.png\" alt=\"architecture\"></figure></div><div><p></p><h3 id=\"prerequisites\">Prerequisites</h3><p></p><p><span><strong>1. Get your own key: </strong></span><span>To use BYOK, you need a key that you control. You set this up in your Azure Key Vault account. Create an RSA asymmetric key. The key must be available in each region you have deployments to encrypt. You can use the same key to encrypt multiple deployments, although security best practices recommend using a different one per deployment. Later, you'll need to provide the Key Vault Key URI and the key name to Elastic Cloud.</span></p><p><span><strong>2. Upgrade to Enterprise:</strong></span><span> BYOK is available for the Enterprise subscription level. This means if you're using Elastic on Azure, you can encrypt your data using your own key.&#160;&#160;</span></p><p><span>Keep in mind, i</span><span>f you're using a custom snapshot repository instead of Elastic Cloud's default one, your snapshots won't automatically be encrypted with your key. However, the file system itself will still encrypt data being stored on disk.</span></p><p><span><strong>3. Access control:</strong></span><span> Create Azure Identity and Access Management (IAM) policies to control access to the Elastic cluster.</span></p><ul><li><p><span>The following are required permissions on Azure:</span></p><ul><li><p><span>Permissions to create an RSA key in the Azure Key Vault where you want to store your key</span></p></li><li><p><span>Membership in the Application Administrator role (This is required to create a new service principal for Elastic Cloud in your Azure tenant.)</span></p></li><li><p><span>Permissions to assign roles in your Key Vault using access control (IAM) (This is required to grant the service principal access to your key.)</span></p></li></ul></li><li><p><span>The Azure Key Vault where the RSA key will be stored must have purge protection enabled to support the encryption of snapshots.</span></p></li></ul></div><div><p></p><h2 id=\"creating-and-configuring-an-azure-key-vault-key\">Creating and configuring an Azure Key Vault key</h2><p></p><p><span>1. To start the key creation process, go to the Key Vault service in the Azure portal. Click </span><span><strong>Keys</strong></span><span>.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt9624a583756c23cc/66c4a6ca5c9bfed96e0f0b6c/image5.png\" alt=\"click keys\"></figure></div><div><p><span>2. In the key creation process, select </span><span><strong>Generate/Import</strong></span><span> and specify the key type and key size.</span></p><p><span>3. Provide a name for the key and click </span><span><strong>Create</strong></span><span>.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt5f8b531747d7c2aa/66c4a6e55c9bfe37ea0f0b73/image11.png\" alt=\"create a key\"></figure></div><div><p><span>4. Add the necessary principal (Elastic service principal) to the access policy and click </span><span><strong>Save</strong></span><span>. The service principal grants Elastic Cloud access to interact with your RSA key.</span></p><p><span>In your Azure Portal, view the key that you created. In the Access control (IAM) settings for the key, grant the service principal the role </span><span><strong>Key Vault Crypto User</strong></span><span>.</span></p><p><span>5. Copy the </span><span><strong>Key Identifier</strong></span><span> and the key name from the Overview tab. Save them in a safe place for use in a later step.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt02d8909ad824da0e/66c4a721ab1b6940163ca5ee/image7.png\" alt=\"key identifier\"></figure></div><div><p></p><h2 id=\"integrating-an-azure-key-vault-key-with-elastic-cloud\">Integrating an Azure Key Vault key with Elastic Cloud</h2><p></p><p><span>1. Now you can create a new Elastic deployment that uses the Azure Key Vault key you just created. Start by signing in to the Elastic Cloud console.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltf418b39a7570da16/66c4a729ab1b6930633ca5f4/image1.png\" alt=\"Elastic Cloud console\"></figure></div><p><span>2. After you’ve signed in to the console, click the </span><span><strong>Create deployment</strong></span><span> button.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt2bb198045e5dbfc1/66c4a7323bab118481a2c150/image8.png\" alt=\"create deployment\"></figure></div><p><span>3. Enter a Name for your deployment and select </span><span><strong>Microsoft Azure</strong></span><span> as your Cloud provider. Then expand the </span><span><strong>Advanced setting</strong></span><span><strong>s</strong> section and enable the </span><span><strong>Use a customer-managed encryption key option</strong></span><span>. Paste in the Azure Key Vault RSA Key Identifier (URI) and key name that you copied in the previous step.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltd2ca2e00783c0893/66c4a5e34b8e147d10bc740d/Screenshot_2024-08-20_at_10.18.59_AM.png\" alt=\"create a deployment\"></figure></div><p><span>4. Click </span><span><strong>Create deployment</strong></span><span>. The deployment is now created and encrypted using the specified key.</span></p><div><p></p><h2 id=\"verification-and-troubleshooting\">Verification and troubleshooting</h2><p></p><p><span>1. In the Elastic Cloud Console, you can check that your hosted deployment is correctly encrypted with the key you specified. To do that, go to the deployment’s </span><span><strong>Security </strong></span><span>page by selecting </span><span><strong>Security</strong></span><span> from the left navigation menu.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt96ffbe0f4ca9f7f9/66c4a742038881cc3d1eef0a/image3.png\" alt=\"byok-demo-deployment\"></figure></div><p><span>2. Select </span><span><strong>Manage encryption key</strong></span><span> in the Encryption at rest section.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltef0c7fece5d9f172/66c4a74e13428673bac3d845/image9.png\" alt=\"manage encryption key\"></figure></div><p><span>3. You should see your Azure Key Vault URI and key name listed in the Azure </span><span><strong>Key Vault RSA key identifier </strong></span><span>field.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltefa0823ea5385c01/66c4a664dd1a36004940b7c7/image2.png\" alt=\"Key Vault RSA key identifier\"></figure></div><div><p></p><h2 id=\"key-rotation-and-revocation\">Key rotation and revocation</h2><p></p><p><span>Elastic Cloud Hosted deployments encrypted with Azure Key Vault keys benefit from Azure's security policies and features, such as key rotation and revocation. Key rotation helps reduce the risk of data breaches due to compromised keys, while key revocation ensures that access to encrypted data via a compromised key is terminated. This can be done by disabling, deleting the key, or altering the key’s access policy.</span></p><p><span>Azure Key Vault keys can be rotated manually when necessary. Elastic automatically manages these key rotations, ensuring that your Elastic Cloud deployment remains encrypted and accessible with the most current Azure Key Vault key.</span></p><p><span>If a key is compromised, you can manually revoke it in Azure Key Vault. This emergency operation, intended for security breaches, locks the deployment’s data directories within 30 minutes and prompts you to delete the deployment.
