Create a symmetric </span><a href=\"https://docs.aws.amazon.com/kms/latest/developerguide/create-keys.html\" target=\"_blank\"><span>single-region key</span></a><span> or </span><a href=\"https://docs.aws.amazon.com/kms/latest/developerguide/multi-region-keys-replicate.html\" target=\"_blank\"><span>multi-region replica key</span></a><span>. You can use the same key to encrypt multiple deployments, although security best practices recommend using a different one per deployment. Later, you will need to provide the Amazon Resource Name (ARN) of that key or key alias to Elastic Cloud. We currently support the following key material origin types:</span></p><ul><li><p><span><strong>KMS:</strong></span><span> AWS Created Key Material</span></p></li><li><p><span><strong>External:</strong></span><span> Imported Key Material</span></p></li><li><p><span><strong>External Key Store (XKS):</strong></span><span> Key Material Provided Via AWS XKS Proxy</span></p></li></ul><p><span><strong>2. Upgrade to Enterprise:</strong></span><span> BYOK is available for the Enterprise subscription level. This means if you're using Elastic on AWS, you can encrypt your data using your own key. Other cloud providers will have this feature later on.</span></p><p><span><em>Keep in mind:</em></span><span> If you're using a custom snapshot repository instead of Elastic Cloud's default one, your snapshots won't automatically be encrypted with your key. However, the file system itself will still encrypt data being stored on disk.</span></p><p><span><strong>3. Access control: </strong></span><span>Create AWS Identity and Access Management (IAM) policies to control access to the Elastic cluster.</span></p></div><div><p></p><h2 id=\"creating-and-configuring-an-aws-kms-key\">Creating and configuring an AWS KMS key</h2><p></p><p><span>To start the key creation process, go to the KMS in the AWS console. Click </span><span><strong>Switch to policy view</strong></span><span> in the Key policy</span><span><strong> </strong></span><span>section.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blta681a3746b21c49d/66ab9ac4adec835c162d2dfb/9.png\" alt=\"switch to policy view\"></figure></div><p><span>Click </span><span><strong>Edit</strong></span><span> to edit the key’s policy.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltb04af094f741fd86/66ab9addeb20b42ed72d1fd9/10.png\" alt=\"edit\"></figure></div><p><span>Copy the following code and paste it within the existing key policy.</span></p><div><pre><code>,\n{\n  \"Sid\": \"ElasticKeyAccess\",\n  \"Effect\": \"Allow\",\n  \"Principal\": {\n\t\"AWS\": \"*\"\n  },\n  \"Action\": [\n\t\"kms:Decrypt\",\n\t\"kms:Encrypt\",\n\t\"kms:GetKeyRotationStatus\",\n\t\"kms:GenerateDataKey\",\n\t\"kms:DescribeKey\"\n  ],\n  \"Resource\": \"*\",\n  \"Condition\": {\n\t\"ForAnyValue:StringLike\": {\n  \t\t\"aws:PrincipalOrgPaths\": \"o-ygducmlz12/r-e5t3/ou-e5t3-fzpdq76p/ou-e5t3-ysfcmd95/ou-e5t3-hwt05su3/\"\n   \t}\n  }\n}</code></pre></div><p><span>Your updated key policy should look something like this. Start by signing in to the Elastic Cloud console.&#160;</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt185e6fea11293233/66ab9d122b7be5789fa78b52/14.png\" alt=\"eastic cloud console\"></figure></div><p><span>After you’ve signed in to the console, click the </span><span><strong>Create deployment </strong></span><span>button.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt21f24384a33a31c1/66ab9d332fce4505a16fefae/15.png\" alt=\"create deployment\"></figure></div><div><p><span>Enter a name for your deployment and select </span><span><strong>Amazon Web Services</strong></span><span> as your Cloud provider.</span></p><p><span>Then expand the Advanced settings section and enable the </span><span><strong>Use a customer-managed encryption key </strong></span><span>option.</span><span><strong> </strong></span><span>Paste in the AWS KMS key’s </span><span><strong>Alias ARN </strong></span><span>that you copied at the end of the previous section. To do that, go to the deployment’s Security page by selecting </span><span><strong>Security</strong></span><span> from the left navigation menu.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt649a8acc0609b358/66ab9d85bb9512b27a024ee9/17.png\" alt=\"my deployment\"></figure></div><p><span>Select </span><span><strong>Manage encryption key</strong></span><span> in the Encryption at rest</span><span><strong> </strong></span><span>section.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blta12f6f543f2cee5c/66ab9da3610c41e0e24224a6/18.png\" alt=\"manage encryption key\"></figure></div><p><span>You should see your AWS KMS key Alias ARN listed in the AWS KMS key ARN field.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt02d4200888bc1fe6/66ab9dc1d141065a27557da6/19.png\" alt=\"security manage encryption key\"></figure></div><div><p></p><h2 id=\"key-rotation-and-revocation\">Key rotation and revocation</h2><p></p><p><span>Elastic Cloud Hosted deployments that have been encrypted with AWS KMS keys also support AWS KMS key security policies and features, such as key rotation and key revocation. Key rotation minimizes the risk of data leaks due to key compromise. Key revocation is an additional security measure, where access to encrypted data via a compromised key is terminated, either via disabling/deleting the key or by changing the key’s IAM policy.</span></p><p><span>AWS KMS keys are automatically rotated after one year by default, but this rotation period can be customized. KMS keys can also be manually rotated within AWS as necessary. Elastic seamlessly handles AWS KMS key rotations so the data in your Elastic Cloud deployment will remain encrypted and accessible via your most current AWS KMS key.</span></p><p><span>If the current key is ever compromised, you can manually revoke the key in AWS KMS. This is a “break-glass” operation to use in case of a security breach. No more than 30 minutes from when a key is revoked, Elastic Cloud will lock the deployment’s data directories and prompt you to delete the deployment. You can restore the key if it’s unintentionally revoked. The deployment will resume operation once the key is restored.</span></p></div><div><p></p><h2 id=\"conclusion\">Conclusion</h2><p></p><p><span>You’ve now seen the entire process of how BYOK can be used for encryption of an Elastic deployment running on AWS.
