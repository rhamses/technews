During 6.x and 7.x, we focused on removing technical debt, like moving from Angular 1 to React and migrating to Kibana’s new platform.</span></p><p><span>Now in 8.x, we’ve been adding big changes one after another. We recently introduced a new enhanced document table, field statistics, and the ability to create search threshold alerts. The screenshot below shows what has been recently added or changed:</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt6f56958227dadb3b/6345c28d8c820a10568b95a1/blog-elastic-evolution-2.jpg\" alt=\"\"></figure></div><div><h2>Document explorer — the new enhanced data table</h2><p><span>In 8.2, a significant change to our data table, powered by the EuiDataGrid of our excellent design library </span><a target=\"_blank\" href=\"https://eui.elastic.co/#/\"><span>EUI</span></a><span>, became generally available. Lots of users requested to be able to configure the widths of the table’s columns. Now, this is possible using drag and drop.</span></p><p><span>[Related article: </span><a target=\"_blank\" href=\"https://www.elastic.co/blog/whats-new-elasticsearch-kibana-cloud-8-2-0\"><span>Elasticsearch, Kibana, Elastic Cloud 8.2: Boost insights with data exploration in Discover</span></a><span>]</span></p><p><span>Optimize for best use of available screen space to reveal potential anomalies:</span></p></div><figure><img src=\"https://play.vidyard.com/7pZY9bakfsqbpZdUwtTjH9.jpg\" alt=\"Video thumbnail\"></figure><p><span>The same applies to the usage of vertical screen space. You can now choose between displaying 1–20 lines. If that’s not enough, just select </span><span><strong>Auto fit</strong></span><span> to get a bigger picture.</span></p><figure><img src=\"https://play.vidyard.com/A1vKhgafG1FLybRwCRwxwA.jpg\" alt=\"Video thumbnail\"></figure><p><span>If you wonder how to show pictures in the table, this feature has been around for quite a while. Recently we’ve added a link to the column’s context menu, so it’s much easier to access.</span></p><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/blt495315861ac0a3f4/6345c55c45693810d212db15/blog-elastic-evolution-3.png\" alt=\"\"></figure></div><div><p><span>The link opens a flyout allowing you to set a custom label and edit the formatting of the field (</span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/kibana/8.4/managing-data-views.html#managing-fields\"><span><strong>field formatters</strong></span></a><span>). When you set the format to </span><span><strong>URL,</strong></span><span> select the </span><span><strong>Image</strong></span><span> type. This transforms the URL of the actual field into a displayed image.&#160;</span></p><p><span>What’s more, we improved sorting by multiple fields. It was confusing when using the classic table, and confusion is a bug that needs to be fixed. Now you can change the order of fields to sort by with drag and drop, and remove sorting fields to sort by in a simple interface.</span></p></div><figure><img src=\"https://play.vidyard.com/iwmGjT3dirEzjoZARzhSdS.jpg\" alt=\"Video thumbnail\"></figure><p><span>Want to remove distractions to focus on your data? This is an especially better experience on a dashboard. On this flyout, you can search and pin fields and use pagination to view the previous or next document.</span></p><figure><img src=\"https://play.vidyard.com/yGW4GD2iHkF9iN72uV3PLn.jpg\" alt=\"Video thumbnail\"></figure><div><p><span>All in all, Discover is now capable of adjusting the view of data in a much better, more configurable way. Apart from this, we also offer a new tool in Discover, helping you to get your data even better.</span></p><h2>New in Discover: Field statistics!</h2><p><span>Kibana’s Machine Learning has been offering Data Visualizer for a while. In 8.1, it was added to Discover labeled </span><span><strong>Field statistics</strong></span><span>. It offers a convenient way to gain more insight into the structure of the data in Elasticsearch. Want a quick overview of a field’s top values, its cardinality, the percentage of documents containing it, and its distribution? It’s now just a single click in Discover.</span></p></div><div><figure><img src=\"https://static-www.elastic.co/v3/assets/bltefdd0b53724fa2ce/bltc1edb3a7419ea11f/6345c5d059c8ec116d140228/blog-elastic-evolution-4.png\" alt=\"\"></figure></div><div><h2>Speed is essential</h2><p><span>To deliver information about the results of your query more quickly, we split up the requests to Elasticsearch. Now there’s one request fetching the matching documents and another one fetching the aggregated data needed to show the histogram including the total number of hits. So usually, when querying a large amount of data, the matching documents are visible quicker, while it might take a bit longer to return the exact number of hits and the aggregated data. No matter which data is returned first, the information is visible more quickly.</span></p></div><figure><img src=\"https://play.vidyard.com/KB8Fp9AFjdhnDJGYcnXfZq.jpg\" alt=\"Video thumbnail\"></figure><div><p><span>Hint: If you’re not interested in the histogram, you can hide it to gain more vertical disk space. If you’re only interested in the histogram, there’s a button taking you to </span><a target=\"_blank\" href=\"https://www.elastic.co/de/kibana/kibana-lens\"><span>Lens</span></a><span>. This way, you can further explore and customize this visualization.</span></p><h2>Alerting in Discover</h2><p><span>Since 8.3, Discover supports you to no longer miss when documents of special interest are ingested in Elasticsearch. A log message of critical severance, an online order larger than a certain amount, the authentication log of your server reporting strange data — any information that matters can be turned into a notification.</span></p><p><span>For this purpose, Discover now offers an easy way to create alert rules. It is recommended to first select the data view of your choice and narrow your data by adding a query and filters. Once you submit the request and are satisfied with the results to create a new alert rule, select </span><span><strong>Alerts / Create search threshold rule</strong></span><span> in Discover’s toolbar. This action opens a flyout that provides various parameters to configure a new threshold alert.</span><span><strong> </strong></span><span>Kibana offers lots of actions to be executed when the conditions are met, including email, Slack, Pager duty, ServiceNow, and many, many more.</span></p></div><figure><img src=\"https://play.vidyard.com/pjXSbXJDyoxvVo49aKAuHx.jpg\" alt=\"Video thumbnail\"></figure><div><h2>What’s next</h2><p><span>From the start, Discover always had one requirement to start querying data: an existing data view (a.k.a. index pattern, before we recently renamed it). You always needed Kibana's Stack management before you could start. Soon this will no longer be necessary. You can go to Discover, enter a pattern matching indices of your interest, and get results even if there’s no data view available. So you can focus on what matters: getting quick answers by querying your data.</span></p><p><span><em>Disclaimer: The pictures used in the screencaps were used with friendly permission by Discover’s Elasticat Karli.</em></span></p></div></div></article></div>"
