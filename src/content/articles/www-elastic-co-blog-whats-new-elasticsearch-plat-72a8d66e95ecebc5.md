The main idea with </span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/elasticsearch/reference/8.11/data-stream-lifecycle.html\"><span>data stream lifecycle</span></a><span> is simplicity: We’ve designed this capability from the start to be easy to configure, so we removed as many implementation details as possible from the user’s concern, only exposing configuration that relates to your needs. The user wants to find the most relevant document (e.g., asset, product, or person). The Convolutional Neural Network is designed to generate a vector for each image, and the user wants to rank the docs by the most similar image and vector.</span></p></li></ol><p><span>For more information about this exciting and quite unique functionality, see the </span><a target=\"_blank\" href=\"https://www.elastic.co/blog/adding-passage-vector-search-to-lucene\"><span>Adding passage vector search to Lucene</span></a><span> blog.</span></p></div><div><p></p><h2 id=\"4096-dimension-dense-vector\">4096 dimension dense vector</h2><p></p><p><span>We have increased the number of dimensions supported for dense vector search to 4096 dimensions. If the need rises, we will raise the limit further.</span></p></div><div><p></p><h2 id=\"max-inner-product-dense-vector-similarity\">Max inner product dense vector similarity</h2><p></p><p><span>Elasticsearch now supports dense vector search using maximum inner product (</span><a href=\"https://en.wikipedia.org/wiki/Maximum_inner-product_search#:~:text=Maximum%20inner%2Dproduct%20search%20(MIPS,data%20items%20to%20be%20retrieved.\" target=\"_blank\"><span>MIPS</span></a><span>). While it is not materially different from the </span><a target=\"_blank\" href=\"https://www.elastic.co/guide/en/elasticsearch/reference/current/rank-features.html\"><span>rank_features</span></a><span> data type that ELSER has been using so far, the use case is important, popular, and different enough to merit its own data type. If nothing else, it makes it easier to understand that way.</span></p></div><div><p></p><h2 id=\"exists-query-for-sparse-vectors\">Exists query for sparse vectors</h2><p></p><p><span>The Exists query returns the documents that have a particular value in a field. The Exists query has been enhanced to include sparse vectors. We found that users sometimes ingest docs using the ELSER model and then want to rerun only a small portion of the docs that do not have a populated sparse vector. The Exists query would be handy for that.</span></p></div><div><p></p><h2 id=\"persian-language-stemmer\">Persian language stemmer</h2><p></p><p><span>Users can perform language analysis using the language analyzer plugins that Elasticsearch supports. It is however easier if Elasticsearch already comes with the plugin, and for that reason we have added support for the Persian language stemmer analyzer plugin.</span></p></div><div><p></p><h2 id=\"dense-vector-field-types-are-indexed-by-default\">Dense vector field types are indexed by default</h2><p></p><p><span>We are taking action to make the use of dense vector search simpler and easier.
