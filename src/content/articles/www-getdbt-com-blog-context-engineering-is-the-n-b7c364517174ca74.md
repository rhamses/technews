contentHtml: "<div><h2 id=\"what-is-context-engineering\">What is context engineering?</h2><p>When the idea that 2026 is \"the year of context\" started making the rounds, Joe Reis answered with a <a target=\"_blank\" title=\"send-up of context lakes, context products, and the analyst singularity\" href=\"https://joereis.substack.com/p/gartner-declares-2026-the-year-of\">send-up of context lakes, context products, and the analyst singularity</a>. Underneath the satire is a real problem: most organizations are bad at giving AI systems the context they need to reason reliably.</p><p>Context engineering is the practice of structuring information so that AI models and agents can use it accurately. It works at a different level than prompt engineering, which operates on instructions, and it's broader than retrieval-augmented generation, which is one specific implementation. Context engineering decides what information an AI system gets, in what format, and at what level of specificity, so it can reason about a domain without hallucinating or guessing.</p><p>For AI systems working with data, that discipline has a specific shape. The AI needs to know: what does this metric mean? What is the grain of this table? What does a null value in this column represent? What business rules make this metric different from that one?</p><p>Those are questions about how knowledge is encoded in the data layer. And analytics engineers have been encoding that knowledge in dbt projects for years.</p><h2 id=\"why-analytics-engineers-already-have-the-advantage\">Why analytics engineers already have the advantage</h2><p>Here's the insight this piece is built around: analytics engineers are already doing context engineering. They just don't call it that.</p><p>When you write a <a target=\"_blank\" title=\"MetricFlow\" href=\"https://docs.getdbt.com/docs/build/about-metricflow\">MetricFlow</a> metric definition, you're encoding context. You're making explicit the business logic that turns a column in a table into an answer a stakeholder can trust. When you write a model description that explains why a model exists and what it represents, you're encoding context. When you define a <a target=\"_blank\" title=\"schema contract\" href=\"https://docs.getdbt.com/docs/mesh/govern/model-contracts\">schema contract</a>, you're encoding context about what can and cannot change at this model's interface.</p><p>The difference between an AI agent that reasons reliably about your data and one that hallucinates is almost entirely a function of how well-structured that context is. Agents that query raw tables with no semantic definitions make reasonable guesses and are frequently wrong. Agents that query a governed <a target=\"_blank\" title=\"dbt Semantic Layer\" href=\"https://www.getdbt.com/product/semantic-layer\">dbt Semantic Layer</a> return answers that are consistent and defensible.</p><p>The skill analytics engineers already have, making implicit business knowledge explicit, structured, and machine-readable, is exactly the skill that makes AI systems trustworthy. Context engineering is analytics engineering pointed at a new consumer.</p><h2 id=\"how-dbt-structures-context-for-ai-agents\">How dbt structures context for AI agents</h2><p>A well-structured dbt project provides context to AI systems through four mechanisms.</p><p><strong>Model descriptions.</strong> A description field in a model's YAML does more than document for humans. When an AI agent reads the lineage graph through the <a target=\"_blank\" title=\"dbt MCP server\" href=\"https://docs.getdbt.com/docs/dbt-ai/about-mcp\">dbt MCP server</a>, model descriptions are part of the context it receives. A sparse or absent description means the agent has to guess what the model does. A precise one means it doesn't.</p><p><strong>MetricFlow metric definitions.</strong> These are the most powerful context mechanism in the dbt stack. A <a target=\"_blank\" title=\"MetricFlow\" href=\"https://docs.getdbt.com/docs/build/about-metricflow\">MetricFlow</a> definition encodes not just what to compute, but how: the entity, the measure, the filters, the grain. When an AI agent queries the <a target=\"_blank\" title=\"dbt Semantic Layer\" href=\"https://www.getdbt.com/product/semantic-layer\">dbt Semantic Layer</a>, it isn't writing SQL. It's querying against definitions that already encode the business rules. The accuracy gain is large: in an <a target=\"_blank\" title=\"early dbt experiment\" href=\"https://www.getdbt.com/blog/semantic-layer-as-the-data-interface-for-llms\">early dbt experiment</a>, LLMs answered natural language questions correctly about 83% of the time when grounded in governed MetricFlow definitions, far above raw text-to-SQL on real-world schemas. </p><p><strong>Schema contracts.</strong> <a target=\"_blank\" title=\"Contracts\" href=\"https://docs.getdbt.com/docs/mesh/govern/model-contracts\">Contracts</a> define the interface at a model boundary. They're context about what can be relied upon: which columns will always exist, what types they'll be, what constraints hold. For AI agents writing code that depends on downstream models, contracts prevent a class of errors that would otherwise need human debugging.</p><p><strong>Column-level lineage.</strong> Lineage tells an AI agent where data comes from. When an agent generates documentation or debugs an anomaly, <a target=\"_blank\" title=\"column-level lineage\" href=\"https://docs.getdbt.com/docs/explore/column-level-lineage\">column-level lineage</a> in dbt Explorer is the context that lets it reason about causality rather than just correlation.</p><h2 id=\"three-context-engineering-patterns-to-build-this-week\">Three context engineering patterns to build this week</h2><p>Three patterns analytics engineers can implement using dbt this week:</p><p><strong>Pattern 1: Metric-as-contract documentation</strong></p><p>For each of your core business metrics, write a <a target=\"_blank\" title=\"MetricFlow\" href=\"https://docs.getdbt.com/docs/build/about-metricflow\">MetricFlow</a> definition that includes the measure plus explicit documentation of what the metric excludes, what the grain means, and what edge cases apply. This is the work that keeps your AI analytics tool from returning a plausible-but-wrong answer to a CFO query. Estimated time: 2-4 hours for 5-10 core metrics.</p><p>The test: can a new team member, or an AI agent, read the definition and understand not just how to compute the metric but why it's defined this way? If not, the definition isn't doing its job as context.</p><p><strong>Pattern 2: Model-level context headers</strong></p><p>Add a structured description block to your 10 most important dbt models. Include what the model is (the grain, the purpose), what it isn't (common misuses or misinterpretations), and what changes downstream if its definition changes. This is the context an AI agent needs to reason about the model correctly without running the data.</p><p>Keep the description complete in 3-5 sentences. Shorter is better if it's precise. The goal is to write everything an AI system needs to reason about the model accurately, no more.</p><p><strong>Pattern 3: Freshness and quality metadata as context signals</strong></p><p>Configure <a target=\"_blank\" title=\"source freshness\" href=\"https://docs.getdbt.com/docs/deploy/source-freshness\">source freshness</a> checks and make the freshness metadata accessible. An AI agent that knows a source was last loaded 4 hours ago can make a better decision about whether to run a downstream pipeline. An agent with no freshness context runs regardless. Freshness metadata is context engineering at the pipeline-operations level: it gives autonomous systems the information they need to decide when to run.</p><h2 id=\"the-vocabulary-shift-that-matters\">The vocabulary shift that matters</h2><p>Context engineering is a better name for work analytics engineers have always done: making implicit business knowledge explicit, structured, and reliable. The consumers of that work have changed. The work itself has held steady.</p><p>What's changed is the leverage. In 2023, a well-documented dbt project made a human analyst's job easier. In 2026, a well-documented dbt project makes every AI agent that runs against your data stack more accurate. The context an analytics engineer builds is used by a system. That's a meaningful expansion of impact.</p><p>The year of context, whatever the analysts mean by it, is really the year analytics engineers discover that the work they've always done is worth more than they realized.</p></div>"
