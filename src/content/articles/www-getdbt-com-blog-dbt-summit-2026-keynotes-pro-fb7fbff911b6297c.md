Most dbt projects rebuild the same models every run, whether anything changed or not. <a target=\"_blank\" title=\"dbt State\" href=\"https://www.getdbt.com/product/dbt-state\">dbt State</a> checks warehouse metadata and model SQL, works out whether the result would actually change, and then builds, skips, clones, or auto-defers to production. Average compute savings run 30%. Reuben McCreanor walks through freshness SLAs, auto-cloning from prod, and the orchestration logic you get to retire, whether you run dbt Core, the dbt platform, or something in between.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/dbt-wizard-your-ai-teammate-for-data-development\"><strong>dbt Wizard: your AI teammate for data development</strong></a>. dbt Wizard is the coding agent built for data, not software. Ani Venkateshwaran and Brandon Thomson walk through its three modes—develop, analyze, and discover—the agent skills framework that makes it extensible, and a live demo of the fully autonomous analytics engineering workflows dbt’s own team has built on top of it.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/rebuilding-dbt-core-in-the-open-faster-runtime-adapters-and-docs-v2\"><strong>Rebuilding dbt Core in the open: faster runtime, adapters, and docs v2</strong></a>. Years of dbt Core v1.x left teams with a Python runtime that slowed on big projects, fragmented adapters, and a docs experience that couldn’t keep up. Hope Watson unpacks the rebuild: a Rust-based Apache 2 engine, a cleaner adapter model on ADBC and the Arrow ecosystem, and parquet-backed artifacts. You’ll see side-by-side parse speed demos and get a real migration path from v1.x through the v1.12 parser on-ramp.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/the-semantic-layer-is-dead-long-live-the-semantic-layer\"><strong>The semantic layer is dead. Long live the semantic layer!</strong></a> Semantic layers used to be a solved problem you built years ago for dashboards. Then agents showed up. Zach Mandell makes the case that your semantic layer is now the most load-bearing piece of your AI strategy, shows where MetricFlow and the dbt Semantic Layer are heading, and covers how the dbt MCP server turns governed metrics into context your agents can use. This is the session that answers the hallucination problem directly.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/product-roundtable-open-data-infrastructure-in-practice-unlock-your-dbt-projects-with-apache-iceberg-and-mesh\"><strong>Product roundtable: open data infrastructure in practice</strong></a>. Jack Lowery and Anna Lee host a working conversation on unlocking dbt projects with Apache Iceberg and mesh patterns. Roundtables are small and discussion-first, so come with the problem you’re actually stuck on.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/apache-ossie-realizing-semantic-layer-portability\"><strong>Apache Ossie: Realizing Semantic Layer Portability</strong></a>. Define a metric in one tool, redefine it in the next, and your dashboards, notebooks, and agents all end up disagreeing on what “active customer” means. Apache Ossie, the vendor-neutral, open-source semantic interchange spec co-led by dbt Labs, Snowflake, Salesforce, BlackRock, and RelationalAI, changes that contract. You’ll see how MetricFlow, now open-sourced under Apache 2.0, compiles governed metrics into a portable format so BI, conversational analytics, and AI agents finally agree on the same business logic.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/the-next-wave-of-data-infrastructure-is-in-the-lake\"><strong>The next wave of data infrastructure is in the Lake</strong></a>. The modern data stack got you here, but it won’t get you to where agents need to operate. Russell Christopher and Casey Karst lay out Open Data Infrastructure: land data in open formats like Iceberg in storage you control, then pick the right compute for any job and swap tools without rebuilding pipelines. You’ll leave with a framework for building open, portable, AI-ready infrastructure with Fivetran + dbt.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/we-said-i-do-now-were-joined-at-the-dag\"><strong>We said I do. Roxi Pourzand shows how Fivetran and dbt unify ingestion, transformation, and consumption into a single lineage graph—one that falls out of the systems doing the work instead of being stitched together after the fact—unlocking real-cost visibility tied to usage, PII that stays governed downstream, and agents that reason with the full picture.</p><p><a target=\"_blank\" title=\"[object Object]\" href=\"https://www.getdbt.com/dbt-summit/sessions/with-great-context-comes-great-autonomy-leveling-up-your-agent-context\"><strong>With great context comes great autonomy: leveling up your agent context</strong></a>.
