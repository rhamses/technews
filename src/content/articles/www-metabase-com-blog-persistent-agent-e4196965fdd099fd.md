contentHtml: "<div>  <p>Think of all the stuff you have to do every morning before you even start coding. You need to get caught up from the day before, look over your tickets, figure out which one to work on, clone the right repo, check out a branch, get up to speed on the relevant area of the code, <em>then</em> maybe you can start rolling.</p>\n<h2 id=\"what-is-a-persistent-agent\">What is a persistent agent?</h2>\n<p>Most agents are one-shot: you give them a task, they do it, and everything they learned disappears with the session. A persistent agent maintains continuity: it saves its tasks and memory to disk, so it can pick up an unfinished job, wait for your feedback, and resume without you having to re-explain anything.</p>\n<p><a target=\"_blank\" href=\"https://github.com/metabase/persistent-agent\">Persistent Agent</a>, or <code>pa</code> for short, is our lightweight memory and task system for handling chores and getting to the fun stuff faster. <code>pa</code> is inspired by the <a target=\"_blank\" href=\"https://jamon.dev/night-shift\">Night Shift Agentic Workflow</a> and note-taking systems like <a target=\"_blank\" href=\"https://obsidian.md/\">Obsidian</a>.</p>\n<h2 id=\"pa-frees-up-about-15-of-my-time-each-day\">pa frees up about 15% of my time each day</h2>\n<p>All those startup and admin tasks typically eat up between 10% and 20% of a developer’s time. Strangely, these gains get better the less normal your circumstances are: when you’re very busy, under the weather, or stressed, having <code>pa</code> consistently follow the start of day script and propose the next priority helps a lot.</p>\n<p>These gains may sound modest compared to the hype surrounding agents. But they are real, low effort, and easy to verify. All you need to do is keep a terminal open on your machine.</p>\n<h2 id=\"a-typical-day-with-pa\">A typical day with <code>pa</code></h2>\n<p>I use <code>pa</code> as a background partner that I pair with and delegate work to. Each morning when I sit down to work, I run <code>sod</code> (start of day) to pair on my start-of-day routine. It:</p>\n<ul>\n<li>pulls updates from Slack, Linear, and GitHub since the last <code>sod</code></li>\n<li>saves a daily note with a summary since the last one</li>\n<li>updates the state of tracked tasks</li>\n<li>sends my start-of-day message to my team’s Slack standup channel</li>\n</ul>\n<p>Then I pick what I’m going to work on myself, and what I want to assign to <code>pa</code> to work on autonomously in the background. Saying <code>work</code> switches <code>pa</code> to the work loop. It will work over its own tasks in <a target=\"_blank\" href=\"https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode\">auto permissions</a>, cloning repositories as needed into its own workspace, creating plans and PRs, blocking tasks when it needs input from me, waiting for CI and feedback on existing PRs, and logging everything on the task files.</p>\n<p>At around lunch time I take a break from the work I’m doing and check up on <code>pa</code>’s progress by saying <code>pair</code> to enter pairing mode. In pairing mode it will ask questions about ongoing tasks, get approval for plans, or let me know that a PR is ready for review. When I’m done pairing, I tell it to work again.</p>\n<p>Sometimes during the day I remember something I want <code>pa</code> to take a look at. I run <code>pa todo look at issue XYZ</code> to add it to the current todos, to be picked up on the next work loop. If I want to add to the backlog for later, I use <code>pa backlog</code> instead. I have Claude’s <a target=\"_blank\" href=\"https://code.claude.com/docs/en/remote-control\">remote control</a> turned on, so I can check on progress on my phone.</p>\n<h2 id=\"how-to-pick-tasks-to-delegate\">How to pick tasks to delegate</h2>\n<p>There are two broad categories of tasks that are good to delegate to <code>pa</code>: trivial tasks and boring tasks. In both cases, the task’s output should be easy to verify.</p>\n<p>There’s no shortage of trivial tasks in any real work context. These tasks don’t require a lot of attention, are usually disruptive (even if they’re not urgent), and can usually be done quickly. With <code>pa</code>, you can just say <code>please add XYZ to your todo</code>, then start a <code>work</code> loop. You don’t have to switch branches, trace code, make tests, make a PR, link it to the issue, etc. You can just check in later and see a PR ready to review.</p>\n<p>Boring tasks are usually dominated by downtime. They are tasks where you need to start processes that take a long time to finish, or monitor events over time, or make small changes to a bunch of different files and tests. These tasks need a medium amount of attention in bursts, and make it hard to switch context in the downtime.</p>\n<p>Boring and trivial tasks aren’t the only tasks you can delegate, but they’re the ones that ask the least of your attention, and your attention is <em>the</em> limited resource. More open-ended tasks often end up requiring a lot of direction and verification, which can drastically reduce the value of delegation.</p>\n<h2 id=\"how-you-get-started-with-pa\">How you get started with <code>pa</code></h2>\n<p>You’ll need to have <a target=\"_blank\" href=\"https://code.claude.com/docs/en/quickstart\">Claude Code</a> installed. Then fork <a target=\"_blank\" href=\"https://github.com/metabase/persistent-agent\">our Persistent Agent repo</a>, likely into a private repository. Now it’s your own thing to use and change, for personal use, work use, or both.</p>\n<p>Then:</p>\n<ul>\n<li>clone your fork locally</li>\n<li><code>cd</code> into it</li>\n<li>run <code>bin/install</code> to add the <code>pa</code> commands globally.</li>\n<li>call <code>pa setup &lt;your name&gt;</code> for initial setup</li>\n</ul>\n<p>The default Metabase setup uses GitHub/Slack/Linear/Notion/Figma as external tools, but setup will ask you which you want to use and update itself.</p>\n<h2 id=\"how-pa-works\">How <code>pa</code> works</h2>\n<p><code>pa</code> is mostly a file structure, a few markdown files on how to use it, and a <code>claude</code> wrapper script:</p>\n<pre><code>persistent-agent\n├── .claude\n│&#160;&#160; └── settings.json              // default plugins and permissions\n├── bin\n│&#160;&#160; ├── pa                         // start pa or call other commands\n│&#160;&#160; ├── pa-backlog                 // add new task to backlog\n│&#160;&#160; ├── pa-install                 // installs commands globally\n│&#160;&#160; ├── pa-save                    // commit tasks and daily notes\n│&#160;&#160; ├── pa-tasks                   // show all tasks\n│&#160;&#160; ├── pa-today                   // show daily note\n│&#160;&#160; └── pa-todo                    // add new task to todo\n├── daily-notes                    // saved as YYYY-MM-DD.md\n├── memory\n│&#160;&#160; ├── archive\n│&#160;&#160; ├── feedback                   // saved during interactions\n│&#160;&#160; ├── skills                     // referenced in .claude/skills/*\n│&#160;&#160; │&#160;&#160; ├── memory.md              // how to use memory\n│&#160;&#160; │&#160;&#160; ├── modes.md               // modes of operation\n│&#160;&#160; │&#160;&#160; ├── self-modification.md   // how to change pa\n│&#160;&#160; │&#160;&#160; ├── setup.md               // initial setup checklist\n│&#160;&#160; │&#160;&#160; ├── start-of-day.md        // start of day routine\n│&#160;&#160; │&#160;&#160; ├── tasks.md               // how to use tasks\n│&#160;&#160; │&#160;&#160; ├── update.md              // how to update pa\n│&#160;&#160; │&#160;&#160; └── work.md                // how to work\n│&#160;&#160; ├── user.md                    // who the user is\n│&#160;&#160; └── workspace.md               // tools and repositories\n├── tasks                          // .md with yml metadata\n│&#160;&#160; ├── archive\n│&#160;&#160; ├── backlog                    // known, but not todo\n│&#160;&#160; ├── blocked                    // blocked on user\n│&#160;&#160; ├── in-progress                // being worked on\n│&#160;&#160; ├── todo                       // ready to work on\n│&#160;&#160; └── waiting                    // waiting for someone else\n├── workspace                      // where repos are cloned\n├── CHANGELOG.md                   // used during update\n├── CLAUDE.md\n└── README.md\n</code></pre>\n<p>You can and should modify <code>pa</code> to work however suits you. The core idea is to give an agent a persistent place of its own, to work with you, in the way you like working.</p>\n<h2 id=\"your-routine\">Your routine</h2>\n<p><code>pa</code> has become a part of my day, and I hope it can support you with your own routine tasks.
