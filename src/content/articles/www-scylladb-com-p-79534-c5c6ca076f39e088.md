contentHtml: "<div>\r\n                        <p><strong>Introducing Oracle Kubernetes Engine support, stronger TLS, and a lighter dependency footprint</strong></p>\n<p>ScyllaDB Operator 1.21.0 is now available.</p>\n<p>For background, ScyllaDB Operator is <a target=\"_blank\" href=\"https://github.com/scylladb/scylla-operator\">an open-source project</a> that helps you run ScyllaDB on Kubernetes. It lets you manage ScyllaDB clusters deployed to Kubernetes and automate tasks related to operating a ScyllaDB cluster (e.g., installation, vertical and horizontal scaling, as well as rolling upgrades).</p>\n<p>ScyllaDB Operator 1.21 expands cloud platform support with OKE, adds ECDSA as an alternative key type for TLS certificates, and removes a hard dependency on Prometheus Operator.</p>\n<h2>Oracle Kubernetes Engine (OKE) support</h2>\n<p>ScyllaDB Operator 1.21 adds <a target=\"_blank\" href=\"https://www.oracle.com/cloud/cloud-native/kubernetes-engine/\">Oracle Container Engine for Kubernetes (OKE)</a> as a supported platform.</p>\n<p><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/image-68.png\"><img src=\"https://www.scylladb.com/wp-content/uploads/image-68-300x197.png\" alt=\"\" srcset=\"https://www.scylladb.com/wp-content/uploads/image-68-300x197.png 300w, https://www.scylladb.com/wp-content/uploads/image-68.png 625w\"></a></p>\n<p>The new OKE support comes with comprehensive documentation covering the entire workflow , from provisioning the underlying OCI infrastructure (VCN, subnets, gateways, and node pools with Dense I/O shapes and local NVMe storage) to deploying a 3-node ScyllaDB cluster spread across fault domains. An automated setup script is also provided for one-command infrastructure provisioning.</p>\n<p>To get started with ScyllaDB on OKE, see the <a target=\"_blank\" href=\"https://operator.docs.scylladb.com/stable/install-operator/provision-infrastructure/set-up-oke-cluster.html\">Set up an OKE cluster for ScyllaDB infrastructure</a> guide and the <a target=\"_blank\" href=\"https://operator.docs.scylladb.com/stable/deploy-scylladb/reference-deployments/reference-deployment-oke.html\">OKE reference deployment</a>.</p>\n<h2>ECDSA support for TLS certificates</h2>\n<p>ScyllaDB Operator <a target=\"_blank\" href=\"https://operator.docs.scylladb.com/stable/understand/security.html#tls-certificates\">manages TLS certificates internally</a> for securing client-to-node communication. Until now, only RSA keys were supported for certificate generation. ScyllaDB Operator 1.21 adds elliptic curve cryptography (ECDSA) as an alternative key type. This allows smaller key sizes and faster cryptographic operations with strong security.</p>\n<p>You can opt in to ECDSA by setting the –crypto-key-type=ECDSA flag on the operator, with the curve bit-size configurable via –crypto-ecdsa-key-size (defaulting to P-384). RSA remains the default key type. The RSA key size is now configured with a dedicated –crypto-rsa-key-size flag; the previous –crypto-key-size flag is deprecated and remains accepted as an alias.</p>\n<h2>Prometheus Operator is now an optional dependency</h2>\n<p>Previously, ScyllaDB Operator required Prometheus Operator CRDs (monitoring.coreos.com/v1) to be installed in the cluster, even if you did not intend to use ScyllaDBMonitoring. Missing CRDs would result in error logs at startup.</p>\n<p>With ScyllaDB Operator 1.21, Prometheus Operator becomes a purely optional dependency. The operator auto-detects whether the CRDs are present at startup using Kubernetes API discovery. When they are absent, the ScyllaDBMonitoring controller is not started and no error logs are emitted. If you install Prometheus Operator after the ScyllaDB Operator is already running, restart the operator to pick up the new CRDs.</p>\n<p>Refer to the <a target=\"_blank\" href=\"https://operator.docs.scylladb.com/stable/management/monitoring/setup.html#requirements\">monitoring setup guide</a> for details.</p>\n                    </div>"
