contentHtml: "<div>\r\n                        <p><strong>The ScyllaDB Cloud Terraform provider gives you infrastructure-as-code control over your clusters</strong></p>\n<p>The ScyllaDB Cloud <a target=\"_blank\" href=\"https://registry.terraform.io/providers/scylladb/scylladbcloud/latest\">Terraform provider</a> now supports ScyllaDB X Cloud. That means you can provision and manage elastic, autoscaling ScyllaDB clusters the same way you manage the rest of your infrastructure.</p>\n<h2>The ScyllaDB Cloud Terraform Provider</h2>\n<p>The provider lives at <code>registry.terraform.io/scylladb/scylladbcloud</code>. You need a ScyllaDB Cloud account and an API token from <a target=\"_blank\" href=\"https://cloud.scylladb.com/\">cloud.scylladb.com</a>.</p>\n<pre><code>terraform {\r\n  required_providers {\r\n    scylladbcloud = {\r\n      source  = \"registry.terraform.io/scylladb/scylladbcloud\"\r\n      version = \"~&gt; 0.3\"\r\n    }\r\n  }\r\n  required_version = \"&gt;= 0.13\"\r\n}\nprovider \"scylladbcloud\" {\r\n  token = var.scylladb_token\r\n}</code></pre>\n<p>Pass the token through a variable.</p>\n<h2>What Is ScyllaDB X Cloud?</h2>\n<p>ScyllaDB <a target=\"_blank\" href=\"https://www.scylladb.com/product/scylladb-xcloud/\">X Cloud</a> is ScyllaDB’s elastic cluster tier built on a tablets-based architecture. Traditional ScyllaDB clusters use token ranges pinned to nodes. Scaling them up or down means rebalancing large chunks of data. X Cloud uses tablets, which are smaller, independently moveable units of data. When you add or remove nodes, tablets rebalance in parallel across the cluster, which makes scaling fast and non-disruptive.</p>\n<p>In practice this means you can:</p>\n<ul>\n<li>Scale from 100K to 2M ops/sec in minutes, not hours</li>\n<li>Push storage utilization up to 90% before scaling out (no wasted headroom)</li>\n<li>Scale-in when load drops (pay for what you use)</li>\n</ul>\n<p>X Cloud also differs from standard clusters in how you configure it in Terraform: instead of choosing a fixed node type and count, you define a <strong>scaling policy</strong> and let the platform decide the right size.</p>\n<h2>Provisioning an X Cloud Cluster</h2>\n<p>Here is a complete cluster resource:</p>\n<pre><code>resource \"scylladbcloud_cluster\" \"xcloud\" {\r\n  name       = \"my-xcloud-cluster\"\r\n  cloud      = \"AWS\"\r\n  region     = \"us-east-1\"\r\n  cidr_block = \"172.31.0.0/16\"\n  scaling {\r\n    instance_families = [\"i8g\"]\n    storage_policy {\r\n      min_gb             = 500\r\n      target_utilization = 0.75\r\n    }\n    vcpu_policy {\r\n      min = 6\r\n    }\r\n  }\r\n}</code></pre>\n<p>The <code>scaling</code> block is what makes this an X Cloud cluster. It is mutually exclusive with the <code>node_type</code> and <code>min_nodes</code> fields used by standard clusters (you use one or the other).</p>\n<h2>Key Scaling Parameters</h2>\n<h3>instance_families</h3>\n<pre><code>instance_families = [\"i8g\"]</code></pre>\n<p>X Cloud scales within a single instance family. The platform picks specific instance sizes within that family as load changes. Sticking with <code>instance_families</code> rather than listing explicit <code>instance_types</code> gives the autoscaler more room to work with. If you do restrict it to specific types, allow at least three different types to give the scaler meaningful options.</p>\n<h3>storage_policy.min_gb</h3>\n<pre><code>storage_policy {\r\n  min_gb = 500\r\n}</code></pre>\n<p>The cluster will not scale below this physical storage threshold. Set it when you know your dataset has a minimum size and want to avoid scale-in churn.</p>\n<h3>storage_policy.target_utilization</h3>\n<pre><code>storage_policy {\r\n  target_utilization = 0.75\r\n}</code></pre>\n<p>This is the utilization level the autoscaler aims to maintain. The valid range is 0.7–0.9 (default: 0.8). The scaler adds capacity when utilization exceeds target by more than 5%, and removes capacity when it falls more than 5% below target. For write-heavy workloads, staying below 0.85 is a good baseline. It gives compaction and repairs room to breathe.</p>\n<h3>vcpu_policy.min</h3>\n<pre><code>vcpu_policy {\r\n  min = 6\r\n}</code></pre>\n<p>The cluster will not scale below this vCPU count, regardless of load. That’s good for latency-sensitive workloads where you want compute headroom even at low traffic.</p>\n<h2>Standard Clusters (For Comparison)</h2>\n<p>If you need a fixed-size cluster or require multi-DC deployments (which will be supported soon), use the standard configuration:</p>\n<pre><code>resource \"scylladbcloud_cluster\" \"standard\" {\r\n  name      = \"my-standard-cluster\"\r\n  cloud     = \"AWS\"\r\n  region    = \"us-east-1\"\r\n  node_type = \"i3.large\"\r\n  min_nodes = 3\r\n  cidr_block = \"172.31.0.0/16\"\r\n}</code></pre>\n<p>Standard clusters use <code>node_type</code> and <code>min_nodes</code> instead of a <code>scaling</code> block.</p>\n<h2>Outputs</h2>\n<p>After apply, the provider exposes:</p>\n<pre><code>output \"cluster_id\" {\r\n  value = scylladbcloud_cluster.xcloud.cluster_id\r\n}\noutput \"datacenter\" {\r\n  value = scylladbcloud_cluster.xcloud.datacenter\r\n}\noutput \"node_dns_names\" {\r\n  value = scylladbcloud_cluster.xcloud.node_dns_names\r\n}</code></pre>\n<p><code>node_dns_names</code> provides the hostnames to pass to your driver configuration.</p>\n<h2>Wrapping Up</h2>\n<p>The ScyllaDB Cloud Terraform provider gives you infrastructure-as-code control over your clusters. For X Cloud specifically, the <code>scaling</code> block replaces the manual node sizing decisions. You just define the baselines and the platform handles the rest. ScyllaDB’s tablets-based architecture means scale events are fast enough to respond “just-in-time” to real traffic changes – so you don’t need to overprovision for peak capacity just in case.</p>\n<p>For more details, see the full provider documentation at <a target=\"_blank\" href=\"https://registry.terraform.io/providers/scylladb/scylladbcloud/latest/docs\">registry.terraform.io/providers/scylladb/scylladbcloud</a>.</p>\n                    </div>"
