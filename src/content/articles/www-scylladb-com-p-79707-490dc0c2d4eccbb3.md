contentHtml: "<div>\r\n                        <p><strong>How to replace LangChain’s in-memory chat history with ScyllaDB — so your RAG chatbot retains context across restarts and scales across replicas</strong></p>\n<p>This post demonstrates how to integrate <a target=\"_blank\" href=\"https://www.scylladb.com/vector-search/\">ScyllaDB Vector Search</a> into your <a target=\"_blank\" href=\"https://docs.langchain.com/\">LangChain</a> project for RAG use cases, as well as how to use ScyllaDB as a durable conversation memory within LangChain.</p>\n<h2>Background</h2>\n<p><a target=\"_blank\" href=\"https://en.wikipedia.org/wiki/Large_language_model\">Large language models</a> are trained on a fixed snapshot of the world. RAG patches that gap by retrieving relevant documents at query time and injecting them into the prompt. The pipeline has two phases:</p>\n<ul>\n<li><strong>Index:</strong> load documents, split them into chunks, embed each chunk, store embeddings in a vector store.</li>\n<li><strong>Retrieve &amp; Generate:</strong> enrich and embed the user’s question, find the nearest vectors (ANN search), pass the matching chunks as context to the LLM.</li>\n</ul>\n<p>But RAG alone is not enough. You still need to keep track of all inputs provided by the user.</p>\n<h2>Persistent Chat Memory</h2>\n<p>LLMs are stateless. Every call starts with a blank slate unless you replay the conversation history. LangChain’s <code>BaseChatMessageHistory</code> abstraction lets you plug in any backend as the storage layer for that history. The default in-memory implementation vanishes on process exit. A database-backed implementation survives restarts, scales across replicas, and lets you inspect or audit conversations later.</p>\n<p>That’s where ScyllaDB comes in.</p>\n<h2>ScyllaDB + LangChain</h2>\n<p>ScyllaDB is a NoSQL database optimized for high-throughput, low-latency workloads. Combined with LangChain, you can build reliable and always-on AI applications:</p>\n<ul>\n<li><strong>High availability:</strong> data is automatically replicated across nodes, so there is no single point of failure. The cluster continues serving reads and writes even if a node goes down.</li>\n<li><strong>Predictable P99 latency:</strong> ANN queries return results fast enough that retrieval doesn’t dominate your chain’s total latency.</li>\n<li><strong>Horizontal scalability:</strong> add nodes to the cluster to increase throughput without schema changes or downtime.</li>\n<li><strong>Built-in vector search:</strong> a native <code>vector&lt;float, N&gt;</code> type and HNSW index are created automatically in ScyllaDB.</li>\n</ul>\n<p>In this example, embeddings are generated locally with sentence-transformers (<code>all-MiniLM-L6-v2</code>, 384 dimensions). For production use, you can swap in OpenAI embeddings, Cohere, or any other provider supported by LangChain.</p>\n<p>In each conversation turn, the chatbot is reading data from ScyllaDB and then writing back into it using LangChain.</p>\n<p><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/langchain_diagram.png\"><img src=\"https://www.scylladb.com/wp-content/uploads/langchain_diagram.png\" alt=\"\" srcset=\"https://www.scylladb.com/wp-content/uploads/langchain_diagram.png 567w, https://www.scylladb.com/wp-content/uploads/langchain_diagram-300x230.png 300w\"></a></p>\n<h2>Setup Example</h2>\n<p>With the release of ScyllaDB 2026.2, you can now integrate LangChain with ScyllaDB seamlessly by reusing the existing Cassandra connector.</p>\n<h3>Install Dependencies</h3>\n<pre><code>pip install langchain langchain-community \\\r\n    sentence-transformers langchain-groq \\\r\n    langchain-text-splitters cassio \\\r\n    scylla-driver python-dotenv</code></pre>\n<h3>Environment Variables</h3>\n<p>Copy <code>demo/.env.example</code> to <code>demo/.env</code> and fill in your credentials:</p>\n<pre><code># ScyllaDB Cloud\r\nSCYLLADB_CONTACT_POINTS=node-0.your-cluster.cloud.scylladb.com\r\nSCYLLADB_DATACENTER=AWS_US_EAST_1\r\nSCYLLADB_USERNAME=scylla\r\nSCYLLADB_PASSWORD=your-password-here\r\nSCYLLADB_KEYSPACE=demo\n# Groq (LLM)\r\nGROQ_API_KEY=gsk_...</code></pre>\n<p>Retrieve the contact points, datacenter name, username, and password from the <strong>Connect</strong> tab of your cluster in <a target=\"_blank\" href=\"https://cloud.scylladb.com/\">ScyllaDB Cloud</a>.</p>\n<h3>Connect to ScyllaDB Cloud</h3>\n<pre><code>from cassandra.cluster import Cluster\r\nfrom cassandra.auth import PlainTextAuthProvider\r\nfrom cassandra.policies import DCAwareRoundRobinPolicy\r\nimport cassio\ncluster = Cluster(\r\n    contact_points=[\"node-0.your-cluster.cloud.scylladb.com\"],\r\n    auth_provider=PlainTextAuthProvider(\r\n        \"scylla\", \"your-password\"\r\n    ),\r\n    load_balancing_policy=DCAwareRoundRobinPolicy(\r\n        local_dc=\"AWS_US_EAST_1\"\r\n    ),\r\n)\nsession = cluster.connect()\r\ncassio.init(session=session, keyspace=\"demo\")</code></pre>\n<p>The <code>cassio.init()</code> call registers the session and keyspace globally so all downstream integrations (the vector store and the chat history) pick it up without further configuration.</p>\n<p>Although cassio was originally built as a Cassandra integration, it is session-agnostic. It works with whatever driver session you hand it, so passing a session created by scylla-driver works just as well.</p>\n<h2>Integrating ScyllaDB with LangChain Vector Store</h2>\n<p>As an example, consider a chatbot that ingests articles, answers questions using retrieved context, and preserves conversation history in the database.</p>\n<pre><code>from langchain_community.document_loaders import WebBaseLoader\r\nfrom langchain_text_splitters import RecursiveCharacterTextSplitter\r\nfrom langchain_community.embeddings import HuggingFaceEmbeddings\r\nfrom langchain_community.vectorstores import Cassandra\nloader = WebBaseLoader([\r\n    \"https://docs.scylladb.com/stable/get-started/scylladb-basics.html\",\r\n    \"https://docs.scylladb.com/stable/get-started/data-modeling/query-design.html\",\r\n])\r\ndocs = loader.load()\nchunks = RecursiveCharacterTextSplitter(\r\n    chunk_size=500,\r\n    chunk_overlap=50,\r\n).split_documents(docs)\nembeddings = HuggingFaceEmbeddings(\r\n    model_name=\"all-MiniLM-L6-v2\"\r\n)\nvectorstore = Cassandra(\r\n    embedding=embeddings,\r\n    table_name=\"rag_docs\"\r\n)\r\nvectorstore.add_documents(chunks)\nretriever = vectorstore.as_retriever(\r\n    search_kwargs={\"k\": 4}\r\n)</code></pre>\n<p><code>WebBaseLoader</code> fetches and parses each URL into a Document.</p>\n<p><code>RecursiveCharacterTextSplitter</code> then breaks each document into 500-token chunks with a 50-token overlap so sentences are not severed at boundaries.</p>\n<p><code>Cassandra(table_name=\"rag_docs\")</code> creates the table on first use, including a <code>vector&lt;float, 384&gt;</code> column (matching all-MiniLM-L6-v2’s output dimensions) and an HNSW index. Subsequent runs reuse the existing table; you only pay the embedding cost once unless you call <code>add_documents</code> again.</p>\n<h2>Persistent Chat Memory Implementation</h2>\n<pre><code>from langchain_community.chat_message_histories import CassandraChatMessageHistory\ndef get_chat_history(session_id: str) -&gt; CassandraChatMessageHistory:\r\nreturn CassandraChatMessageHistory(\r\n    \t\tsession_id=session_id,\r\n    \t\ttable_name=\"chat_history\",\r\n\t)\r\n</code></pre>\n<p><code>CassandraChatMessageHistory</code> stores each message as a row keyed on <code>session_id</code>. Because rows are written to ScyllaDB, the history survives process crashes, server restarts, and horizontal scaling. Any replica that opens the same <code>session_id</code> sees the same history.</p>\n<p>Change <code>session_id</code> to start a fresh conversation. Keep it the same to resume where you left off — that is the entire persistence mechanism.</p>\n<h2>Putting It Together</h2>\n<pre><code>from langchain_groq import ChatGroq\r\nfrom langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder\r\nfrom langchain_core.output_parsers import StrOutputParser\r\nfrom langchain_core.runnables import RunnablePassthrough\r\nfrom langchain_core.runnables.history import RunnableWithMessageHistory\nllm = ChatGroq(model=\"llama-3.3-70b-versatile\")\nablePassthrough\r\nfrom langchain_core.runnables.history import RunnableWithMessageHistory\nllm = ChatGroq(model=\"llama-3.3-70b-versatile\")\nprompt = ChatPromptTemplate.from_messages([\r\n\t(\"system\",\r\n \t\"You are a helpful assistant. Answer the user's question using the \"\r\n \t\"retrieved context below.\\n\\nContext:\\n{context}\"),\r\n\tMessagesPlaceholder(variable_name=\"chat_history\"),\r\n\t(\"human\", \"{question}\"),\r\n])\nchain = (\r\n\tRunnablePassthrough.assign(context=lambda x: \"\\n\\n\".join(\r\n    \td.page_content for d in retriever.invoke(x[\"question\"])\r\n\t))\r\n\t| prompt\r\n\t| llm\r\n\t| StrOutputParser()\r\n)\nchain_with_history = RunnableWithMessageHistory(\r\n\tchain,\r\n\tget_chat_history,\r\n\tinput_messages_key=\"question\",\r\n\thistory_messages_key=\"chat_history\",\r\n)\nconfig = {\"configurable\": {\"session_id\": \"user-abc-session-1\"}}\nanswer1 = chain_with_history.invoke(\r\n\t{\"question\": \"What is the difference between a partition key and a clustering key in ScyllaDB?\"},\r\n\tconfig=config,\r\n)\r\nprint(answer1)\nanswer2 = chain_with_history.invoke(\r\n\t{\"question\": \"How does using both keys affect the sort order of the data within a partition?\"},\r\n\tconfig=config,\r\n)\r\nprint(answer2)  # References the prior turn via memory\r\n</code></pre>\n<p><code>RunnableWithMessageHistory </code>wraps the chain and automatically loads prior turns from <code>get_chat_history </code>before each call, then appends the new turn after. Both storage operations hit ScyllaDB.</p>\n<p>The second question drills deeper into clustering columns introduced in the first answer. Without persistent memory, the LLM would have no context for what was already explained; with it, the conversation flows naturally across turns.</p>\n<h2>ScyllaDB Schema</h2>\n<p><strong>rag_docs</strong>, the vector store:</p>\n<pre><code>CREATE TABLE demo.rag_docs (\r\n\trow_id      \ttext PRIMARY KEY,\r\n\tattributes_blob text,\r\n\tbody_blob   \ttext,\r\n\tmetadata_s  \tmap&lt;text, text&gt;,\r\n\tvector      \tvector&lt;float, 384&gt;,\r\n);\nCREATE CUSTOM INDEX idx_vector_rag_docs ON demo.rag_docs (vector)\r\n\tUSING 'vector_index';\nCREATE INDEX eidx_metadata_s_rag_docs ON demo.rag_docs (ENTRIES(metadata_s));\r\n</code></pre>\n<p><strong>chat_history</strong>, the message store:</p>\n<pre><code>CREATE TABLE demo.chat_history (\r\n    partition_id  text,\r\n    message_id    timeuuid,\r\n    body_blob     text,\r\n    PRIMARY KEY (partition_id, message_id)\r\n) WITH CLUSTERING ORDER BY (message_id DESC);\r\n</code></pre>\n<h2>Next Steps</h2>\n<p>The full demo code is <a target=\"_blank\" href=\"https://github.com/scylladb/vector-search-examples\">available on GitHub</a>.
