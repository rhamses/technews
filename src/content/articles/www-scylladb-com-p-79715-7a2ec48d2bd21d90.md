contentHtml: "<div>\r\n                        <p><strong>Combine Mem0’s memory management with ScyllaDB’s persistence features to deploy large-scale AI agents</strong></p>\n<p>Scaling AI agents to handle persistent memory for a large number of users (e.g. 500k+ DAU) introduces engineering bottlenecks. These complications generally compound across two areas: how context is filtered for the model and how that data is stored globally.</p>\n<p><a target=\"_blank\" href=\"https://mem0.ai/\">Mem0</a> addresses context efficiency by processing raw interactions into concise, entity-based facts. Instead of storing entire chat transcripts, it extracts and updates specific user preferences and historical context across sessions. This extraction method reduces the volume of data sent to the LLM, keeping prompt size manageable while retaining long-term user context.</p>\n<p>To operate at a global scale, this memory layer requires a database that handles high-throughput, low-latency vector search across multiple regions. <a target=\"_blank\" href=\"https://cloud.scylladb.com/\">ScyllaDB Cloud</a> provides this distributed database infrastructure with high availability and strict P99 guarantees. Combining Mem0’s memory management with ScyllaDB’s persistence features allows teams to deploy large-scale AI agents.</p>\n<p>This post shows you how Mem0 and ScyllaDB Cloud can be used together.</p>\n<h2>Memory: A Core Building Block of Agentic Applications</h2>\n<p>An agent might run for minutes, make dozens of tool calls, coordinate with other agents, and serve the same user across days or weeks. At each step, it needs context: what did this user say before? What facts are relevant right now? What happened earlier in this run?</p>\n<p><strong>Agent memory (semantic memory)</strong> covers facts, preferences, and learned context that persist across sessions and agents. “Tom is vegetarian.” “Nicole prefers concise answers.” This layer needs vector search so the agent can retrieve relevant memories by meaning, not just by key lookup.</p>\n<p></p>\n<p>An agent memory framework solves the application side of this problem. It extracts facts from conversations, stores them as vector embeddings, and retrieves the most relevant ones at query time. You also need a database that the framework will use to store the embeddings and memories. In the case of Mem0, you have <a target=\"_blank\" href=\"https://docs.mem0.ai/components/vectordbs/overview\">plenty</a> to choose from.</p>\n<p>Global, large-scale agentic use cases require the memory layer to be highly available, geographically distributed, and scale with the application. This is why choosing the right database backing your memory infrastructure matters as much, or even more, as the memory framework itself.</p>\n<hr>\n<p><em>Another important context layer element is <strong>agent state</strong>. Agent state covers task progress, intermediate results, checkpoints, and tool outputs. A great stack for agent state is ScyllaDB + LangGraph. You can learn more about that in <a target=\"_blank\" href=\"https://www.scylladb.com/2026/04/08/agentic-ai-state-management-with-scylladb-and-langgraph/\">this post</a>.</em></p>\n<hr>\n<p><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/mem01.png\"><img src=\"https://www.scylladb.com/wp-content/uploads/mem01.png\" alt=\"\" srcset=\"https://www.scylladb.com/wp-content/uploads/mem01.png 1549w, https://www.scylladb.com/wp-content/uploads/mem01-300x129.png 300w, https://www.scylladb.com/wp-content/uploads/mem01-1100x474.png 1100w, https://www.scylladb.com/wp-content/uploads/mem01-768x331.png 768w, https://www.scylladb.com/wp-content/uploads/mem01-1536x662.png 1536w\"></a></p>\n<h2>What Is Mem0?</h2>\n<p>Mem0 is an open-source memory layer for AI agents. It sits between your agent code and your storage backend. Mem0 handles the hard parts of agent memory:</p>\n<ul>\n<li><strong>Extraction:</strong> given a conversation or a piece of text, Mem0 calls an LLM to extract discrete facts.</li>\n<li><strong>Deduplication:</strong> before storing a new fact, Mem0 checks whether a semantically similar memory already exists and updates it instead of creating a duplicate.</li>\n<li><strong>Retrieval:</strong> <code>search()</code> embeds a query and runs an ANN lookup to return the most relevant memories for a given user or agent.</li>\n<li><strong>Lifecycle management:</strong> <code>add()</code>, <code>get()</code>, <code>get_all()</code>, <code>search()</code>, <code>update()</code>, <code>delete()</code>. A clean API that abstracts the underlying vector store.</li>\n</ul>\n<p>Mem0 supports multiple LLM providers (OpenAI, Groq, Anthropic, etc.) and multiple vector store backends. One of those backends is ScyllaDB.</p>\n<h2>What Is ScyllaDB Cloud?</h2>\n<p>ScyllaDB is a distributed high-performance database with vector support built for high-throughput, multi-region workloads. <a target=\"_blank\" href=\"https://www.scylladb.com/product/scylladb-xcloud/\">ScyllaDB Cloud</a> is a fully managed database-as-a-service. Once connected, the ScyllaDB team handles infrastructure, monitoring, autoscaling, and backups automatically.</p>\n<p>The properties that make ScyllaDB Cloud a good fit for an agent memory backend:</p>\n<ul>\n<li><strong>Vector Search:</strong> <code>vector&lt;float, N&gt;</code> is a first-class column type. HNSW indexes are created with a single <code>CREATE CUSTOM INDEX</code> statement and support multiple similarity functions.</li>\n<li><strong>Millions of ops/sec:</strong> ScyllaDB is designed to handle millions of operations per second with low and predictable latency.</li>\n<li><strong>Horizontal scalability:</strong> add new nodes or even new regions to your cluster without complexity.</li>\n<li><strong>Autoscaling capabilities:</strong> automatically scales up and down based on real-time load, ensuring consistent performance for unpredictable agentic workloads.</li>\n<li><strong>High availability:</strong> data is replicated across nodes automatically. The cluster continues to serve reads and writes even if a node goes down. There is no single point of failure.</li>\n<li><strong>Battle-tested at scale:</strong> major enterprises such as <a target=\"_blank\" href=\"https://www.scylladb.com/2019/03/20/discord-on-the-joy-of-opinionated-systems/\">Discord</a>, <a target=\"_blank\" href=\"https://www.scylladb.com/users/case-study-zillow-scales-background-and-real-time-workloads-with-scylla/\">Zillow</a>, and <a target=\"_blank\" href=\"https://www.scylladb.com/2024/07/01/freshworks-latency/\">Freshworks</a> depend on ScyllaDB for their data-intensive workloads.</li>\n<li><strong>Trusted for AI:</strong> industry leaders such as <a target=\"_blank\" href=\"https://www.scylladb.com/2025/01/30/inside-tripadvisors-real-time-personalization-with-scylladb-aws/\">Tripadvisor</a>, <a target=\"_blank\" href=\"https://www.youtube.com/watch?v=ZnZ8oqz71bw\">Tubi</a>, and <a target=\"_blank\" href=\"https://www.scylladb.com/2024/08/27/how-sharechat-scaled-their-ml-feature-store/\">ShareChat</a> rely on ScyllaDB to power their AI-driven workloads.</li>\n</ul>\n<h2>Serving Global AI Apps with Mem0 and ScyllaDB Cloud</h2>\n<p>Let’s say you are expecting thousands, hundreds of thousands, and millions of agent loops, messages, and threads daily with hundreds of thousands of concurrent sessions across multiple continents. Your database that powers the memory layer is very likely to become the bottleneck. It’s a good idea to decouple your components — application, LLM, and database — so you can scale each part individually to meet demand. Mem0 and ScyllaDB Cloud work well together to allow this kind of decoupling.</p>\n<p>ScyllaDB Cloud offers multi-region support out of the box so you can serve memories from clusters that are closest to your application instance and users.</p>\n<p>ScyllaDB Cloud also helps you optimize and scale two distinct kinds of workloads independently:</p>\n<ul>\n<li>Standard key-based lookups (get thread by id)</li>\n<li>Vector search queries (memory semantic search)</li>\n</ul>\n<p>In ScyllaDB Cloud, non-vector search queries are served by data nodes. Vector search queries are served by vector search nodes. This design allows you to optimize resources and reduce infrastructure costs.</p>\n<p>Decoupling your database from your memory layer lets you scale it on your own terms: add nodes (horizontal scaling) or CPUs (vertical scaling) to absorb load without touching application code or accepting latency regressions.</p>\n<h2>How ScyllaDB and Mem0 Work Together</h2>\n<p>Mem0 handles fact extraction, deduplication, embedding, and retrieval. ScyllaDB provides the storage: high-availability, multi-region, low-latency storage with vector search.</p>\n<p><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/mem02.png\"><img srcset=\"https://www.scylladb.com/wp-content/uploads/mem02.png 786w, https://www.scylladb.com/wp-content/uploads/mem02-300x98.png 300w, https://www.scylladb.com/wp-content/uploads/mem02-768x251.png 768w\" src=\"https://www.scylladb.com/wp-content/uploads/mem02.png\" alt=\"\"></a></p>\n<p>On <code>add()</code>, Mem0 sends the input to an LLM to pull out structured facts, embeds each fact, and writes the resulting vectors to ScyllaDB. On <code>search()</code>, Mem0 embeds the query and runs an ANN query against ScyllaDB’s vector index, returning the most semantically relevant memories.</p>\n<p>The agent does not manage embeddings or indexes directly; instead, it calls <code>add()</code> and <code>search()</code>.</p>\n<h2>Schema</h2>\n<p>The schema below creates a <code>memories</code> table with a <code>vector&lt;float, 384&gt;</code> column (matching all-MiniLM-L6-v2) and a vector index for ANN search. Secondary indexes on <code>user_id</code> support <code>get_all()</code> queries.</p>\n<pre><code>CREATE KEYSPACE mem0;\nCREATE TABLE mem0.memories (\r\n    id         UUID,\r\n    user_id    TEXT,\r\n    agent_id   TEXT,\r\n    run_id     TEXT,\r\n    hash       TEXT,\r\n    data       TEXT,\r\n    metadata   TEXT,\r\n    vector     vector&lt;float, 384&gt;,\r\n    created_at TIMESTAMP,\r\n    updated_at TIMESTAMP,\r\n    PRIMARY KEY (id)\r\n);\nCREATE CUSTOM INDEX IF NOT EXISTS memories_vector_idx\r\n    ON mem0.memories (vector)\r\n    USING 'vector_index'\r\n    WITH OPTIONS = {\r\n        'similarity_function': 'COSINE'\r\n    };\nCREATE INDEX IF NOT EXISTS memories_user_id_idx\r\n    ON mem0.memories (user_id);</code></pre>\n<h2>ScyllaDB and Mem0 Configuration</h2>\n<p>ScyllaDB is CQL (Cassandra Query Language) compatible. You can integrate ScyllaDB with Mem0 using the following configuration:</p>\n<pre><code>import os\r\nfrom dotenv import load_dotenv\r\nfrom cassandra.policies import DCAwareRoundRobinPolicy\r\nfrom mem0 import Memory\nload_dotenv()\nconfig = {\r\n    \"vector_store\": {\r\n        \"provider\": \"cassandra\",\r\n        \"config\": {\r\n            \"contact_points\": [\r\n                os.environ[\"SCYLLADB_ADDRESS\"]\r\n            ],\r\n            \"port\": 9042,\r\n            \"username\": os.environ[\"SCYLLADB_USERNAME\"],\r\n            \"password\": os.environ[\"SCYLLADB_PASSWORD\"],\r\n            \"keyspace\": \"mem0\",\r\n            \"collection_name\": \"memories\",\r\n            # DC-aware routing\r\n            \"load_balancing_policy\": DCAwareRoundRobinPolicy(\r\n                local_dc=os.environ.get(\r\n                    \"SCYLLADB_DATACENTER\",\r\n                    \"AWS_US_EAST_1\"\r\n                )\r\n            ),\r\n            # matches all-MiniLM-L6-v2\r\n            \"embedding_model_dims\": 384,\r\n        },\r\n    },\r\n    \"llm\": {\r\n        \"provider\": \"groq\",\r\n        \"config\": {\r\n            \"model\": \"mllama-3.1-70b-versatile\",\r\n            \"api_key\": os.environ[\"GROQ_API_KEY\"],\r\n        },\r\n    },\r\n    \"embedder\": {\r\n        \"provider\": \"huggingface\",\r\n        \"config\": {\r\n            \"model\": \"sentence-transformers/all-MiniLM-L6-v2\"\r\n        },\r\n    },\r\n}\nm = Memory.from_config(config)</code></pre>\n<p>After configuration, you can start using the Mem0 functions: <code>add()</code>, <code>search()</code>, <code>update()</code>, <code>delete()</code>.</p>\n<h2>Adding Memories</h2>\n<pre><code>USER_ID = \"alice\"\n# Add a single fact\r\nm.add(\r\n    \"I love hiking in the mountains, especially in autumn.\",\r\n    user_id=USER_ID,\r\n)\n# Add a conversation — Mem0 extracts facts automatically\r\nm.add(\r\n    [\r\n        {\r\n            \"role\": \"user\",\r\n            \"content\": \"What's a good pasta recipe?\",\r\n        },\r\n        {\r\n            \"role\": \"assistant\",\r\n            \"content\": (\r\n                \"Try cacio e pepe — \"\r\n                \"it only needs three ingredients.\"\r\n            ),\r\n        },\r\n        {\r\n            \"role\": \"user\",\r\n            \"content\": \"I'm vegetarian, by the way.\",\r\n        },\r\n    ],\r\n    user_id=USER_ID,\r\n)</code></pre>\n<p>Mem0 calls the LLM to extract facts from the conversation (“user is vegetarian”, “user was recommended cacio e pepe”), embeds each fact using sentence-transformers as defined in the embedder configuration, and writes them to ScyllaDB. If a semantically equivalent memory already exists for this user, Mem0 updates it instead.</p>\n<h2>Searching and Retrieving Memories</h2>\n<pre><code># Semantic search\r\nresults = m.search(\r\n    \"outdoor activities\",\r\n    filters={\"user_id\": USER_ID},\r\n    limit=3,\r\n)\r\nfor entry in results[\"results\"]:\r\n    print(f\"[{entry['score']:.3f}]  {entry['memory']}\")\r\n# [0.91]  User loves hiking in the mountains, especially in autumn.\n# List all memories for a user\r\nall_memories = m.get_all(filters={\"user_id\": USER_ID})\n# Update or delete a specific memory\r\nm.update(\r\n    all_memories[\"results\"][0][\"id\"],\r\n    \"I love hiking and trail running in the mountains.\",\r\n)\r\nm.delete(all_memories[\"results\"][-1][\"id\"])</code></pre>\n<p>In an agentic loop, call <code>m.search(user_query, filters={\"user_id\": user_id})</code> at the start of each turn to inject relevant context into the prompt, and <code>m.add(conversation_turn, user_id=user_id)</code> at the end to persist what was learned.</p>\n<h2>Try ScyllaDB + Mem0</h2>\n<p>The full example code is available in the <a target=\"_blank\" href=\"https://github.com/scylladb/vector-search-examples/tree/main/memory-mem0\">repository</a>.
