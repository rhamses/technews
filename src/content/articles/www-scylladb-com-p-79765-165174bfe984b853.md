contentHtml: "<div>\r\n                        <p>ScyllaDB 2026.2 brings a combination of GA new features, exciting experimental features, and multiple stability and external use case improvements.</p>\n<p>The updates include:</p>\n<ul>\n<li><strong>DynamoDB compatible API (Alternator) enhancements</strong>: DynamoDB compatible Streams and Vector Search extension.</li>\n<li><strong>Performance and Stability:</strong> Trie index performance improvement, and streamlining connection storm handling.</li>\n<li><strong>ScyllaDB Cloud:</strong> New Private Link connectivity feature and Vector Search integrations (LangChain, LlamaIndex, Spring AI, Agno, and more).</li>\n<li><strong>Experimental features</strong>: Strongly Consistent Tables and vNode-to-Tablet online migration.</li>\n</ul>\n<p>2026.2 is more stable, works faster, and better than any past release. You are encouraged to upgrade to it, and use it for any new deployment.</p>\n<p>For the full release notes, see <a target=\"_blank\" href=\"https://forum.scylladb.com/t/release-scylladb-2026-2/5426\">this forum post</a>.</p>\n<h2>DynamoDB compatible API (Alternator) enhancements</h2>\n<p>Alternator is a native DynamoDB-compatible API on ScyllaDB.</p>\n<p>ScyllaDB 2026.2 includes two major additions to that API: DynamoDB Streams compatibility and a Vector Search extension.</p>\n<h3>Streams are Generally Available</h3>\n<p>Alternator Streams, ScyllaDB’s DynamoDB Streams-compatible change data capture interface, is now Generally Available (GA). Applications can capture ordered item-level changes from Alternator tables for event-driven architectures, CDC pipelines, and replication workflows.</p>\n<h3>Vector Search Extension</h3>\n<p>A new extension to the Amazon DynamoDB API allows you to use Semantic <a target=\"_blank\" href=\"https://www.scylladb.com/2026/05/05/native-vector-search-dynamodb/\">Vector Search directly on your data</a>.</p>\n<p>For users in the DynamoDB environment, implementing vector search has been overly complicated. Amazon’s “Zero ETL” forces a dual-service approach (managing both DynamoDB and OpenSearch) and requires using two separate APIs just for Vector Semantic Search queries. ScyllaDB eliminated the heavy lifting by integrating vector search capabilities into Alternator, our DynamoDB-compatible API. This gives DynamoDB users high-performance similarity search within their familiar API, without the need for extra clusters or constant API context-switching.</p>\n<p>Vector Search is available in ScyllaDB Cloud.</p>\n<h2>Performance: Trie index by default</h2>\n<p>The Trie-based SSTable index format was added in ScyllaDB 2025.4. Since then it has evolved and matured to become the default index format in ScyllaDB 2026.2.</p>\n<p>The Trie index format increases throughput by up to x3 with lower latency compared to legacy index formats.</p>\n<p>To read more, see our blog post, <a target=\"_blank\" href=\"https://www.scylladb.com/2026/06/30/trie-index-3x-more-throughput/\">How ScyllaDB’s Trie-Based Index Delivers Up to 3X More Throughput</a>.</p>\n<p><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/trie.png\"><img src=\"https://www.scylladb.com/wp-content/uploads/trie.png\" alt=\"\" srcset=\"https://www.scylladb.com/wp-content/uploads/trie.png 800w, https://www.scylladb.com/wp-content/uploads/trie-300x225.png 300w, https://www.scylladb.com/wp-content/uploads/trie-768x576.png 768w\"></a></p>\n<h2>Stability: Connection Storm Mitigation</h2>\n<p>A connection storm is the result of thousands of applications reconnecting to the cluster after a node restart or a network issue. This issue is rare. But, when it happens, it’s important that it doesn’t cause latency to spike.</p>\n<p>In 2026.2, we implemented multiple mechanisms to mitigate this effect. Some of them are:</p>\n<ul>\n<li>Coordinator side connection throttling</li>\n<li>Unified authentication and authorization cache</li>\n<li>Improved password hashing</li>\n<li>Using a lower default service level</li>\n<li>Replica-Side Load Shedding</li>\n</ul>\n<p>As shown below, the effect is dramatic. From a P99 of 5 <em>seconds</em> during a connection storm (after a node restart) to 3.5 <em>milliseconds</em>.</p>\n<p><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/storm1.png\"><img srcset=\"https://www.scylladb.com/wp-content/uploads/storm1.png 391w, https://www.scylladb.com/wp-content/uploads/storm1-300x169.png 300w\" src=\"https://www.scylladb.com/wp-content/uploads/storm1.png\" alt=\"\"></a><a target=\"_blank\" href=\"https://www.scylladb.com/wp-content/uploads/storm2.png\"><img srcset=\"https://www.scylladb.com/wp-content/uploads/storm2.png 391w, https://www.scylladb.com/wp-content/uploads/storm2-300x169.png 300w\" src=\"https://www.scylladb.com/wp-content/uploads/storm2.png\" alt=\"\"></a></p>\n<p>For more details, see our blog post, <a target=\"_blank\" href=\"https://www.scylladb.com/2026/07/01/cutting-p99-during-connection-storms/\">Cutting P99 Latency 1000X During Connection Storms by Hardening ScyllaDB Admission Controls</a>.</p>\n<h2>ScyllaDB Cloud</h2>\n<p>ScyllaDB continues to expand its Vector Search capabilities with integrations to popular tools like LangChain, LlamaIndex, Spring AI, Agno and more. For more details, see our blog post, <a target=\"_blank\" href=\"https://www.scylladb.com/2026/07/14/durable-chat-memory-for-rag-scylladb-and-langchain/\">Build Durable Chat Memory for RAG Using ScyllaDB and LangChain</a>.</p>\n<h2>New experimental features</h2>\n<h3>Strong Consistency: Raft Group per Tablet</h3>\n<p>ScyllaDB has been using the Raft consensus algorithm for metadata like cluster topology and data distribution (Tablets) for years now. In this release, ScyllaDB started using Raft for data consistency as well. You can now create a <a target=\"_blank\" href=\"https://docs.scylladb.com/manual/stable/kb/consistency.html\">globally consistent Keyspace</a>, and enjoy strong consistency – with performance that’s very close to eventual consistency, and superior to the existing LWT approach.</p>\n<p>You can read more about this in <em><a target=\"_blank\" href=\"https://www.scylladb.com/2026/06/24/raft-strong-consistency/\">Riding the Raft to Strong Consistency in ScyllaDB</a></em>.</p>\n<h3>vNodes to Tablets Migration</h3>\n<p>Tablets, ScyllaDB’s new dynamic algorithm for data distribution, powers ScyllaDB’s extreme elasticity. With 2026.1, tablets achieved full feature parity and became recommended for all new clusters.</p>\n<p>But what about exiting production clusters? In 2026.2, ScyllaDB provides a zero downtime migration from legacy vNode to Tablets, with minimal resource usage.</p>\n<p>See <a target=\"_blank\" href=\"https://docs.scylladb.com/manual/branch-2026.2/operating-scylla/procedures/config-change/migrate-vnodes-to-tablets.html\">Migrate a Keyspace from Vnodes to Tablets</a> in the ScyllaDB documentation for details.</p>\n<p>Want to use one of the experimental features? See <a target=\"_blank\" href=\"https://docs.scylladb.com/stable/\">the documentation</a> for details on how to enable them, or contact the ScyllaDB Cloud support team.</p>\n                    </div>"
